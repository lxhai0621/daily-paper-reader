## 摘要
我们提出了 MemX，这是一种面向 AI 助手的本地优先长期记忆系统，采用了面向稳定性的检索设计。MemX 基于 Rust 语言实现，构建于 libSQL 和兼容 OpenAI 的嵌入（embedding）API 之上，为对话智能体提供持久化、可搜索且可解释的记忆。其检索流水线应用了向量召回、关键词召回、倒数排名融合（RRF）、四因子重排序，以及一种低置信度拒绝规则，用于在记忆库中不存在答案时抑制伪召回。我们从两个维度对 MemX 进行了评估。首先，通过两个自定义中文基准测试集（43 个查询，不超过 1,014 条记录）验证了流水线设计：在默认场景下 Hit@1 达到 91.3%，在高混淆场景下达到 100%，并具有保守的未命中查询抑制能力。其次，利用 LongMemEval 基准测试（500 个查询，最高 220,349 条记录）量化了系统在四种能力类型和三种存储粒度下的边界。在事实级粒度下，系统达到了 Hit@5=51.6% 和 MRR=0.380，是会话级性能的两倍，而时间维度和多会话推理仍具挑战性（Hit@5 <= 43.6%）。FTS5 全文索引在 10 万条记录规模下将关键词搜索延迟降低了 1,100 倍，使端到端搜索保持在 90 毫秒以内。与针对端到端智能体基准测试的 Mem0 及相关工作不同，MemX 专注于一个更窄、可复现的基准：本地优先部署、结构简单性、可解释检索以及面向稳定性的设计。

## Abstract
We present MemX, a local-first long-term memory system for AI assistants with stability-oriented retrieval design. MemX is implemented in Rust on top of libSQL and an OpenAI-compatible embedding API, providing persistent, searchable, and explainable memory for conversational agents. Its retrieval pipeline applies vector recall, keyword recall, Reciprocal Rank Fusion (RRF), four-factor re-ranking, and a low-confidence rejection rule that suppresses spurious recalls when no answer exists in the memory store.   We evaluate MemX on two axes. First, two custom Chinese-language benchmark suites (43 queries, <=1,014 records) validate pipeline design: Hit@1=91.3% on a default scenario and 100% under high confusion, with conservative miss-query suppression. Second, the LongMemEval benchmark (500 queries, up to 220,349 records) quantifies system boundaries across four ability types and three storage granularities. At fact-level granularity the system reaches Hit@5=51.6% and MRR=0.380, doubling session-level performance, while temporal and multi-session reasoning remain challenging (<=43.6% Hit@5). FTS5 full-text indexing reduces keyword search latency by 1,100x at 100k-record scale, keeping end-to-end search under 90 ms.   Unlike Mem0 and related work that targets end-to-end agent benchmarks, MemX focuses on a narrower, reproducible baseline: local-first deployment, structural simplicity, explainable retrieval, and stability-oriented design.

#### 1. 核心问题与研究背景
大语言模型（LLM）在单轮对话中表现出色，但在跨会话的长期记忆方面仍然是“无状态”的。现有的检索增强生成（RAG）系统多针对静态文档库，而非个人化、增量式的记忆。此外，用户对本地 AI 助手有隐私保护、低延迟和离线运行的诉求。
**核心问题：** 在本地部署的单用户场景下，如何构建一个结构简单、可解释且稳定的记忆系统，在保证召回率的同时，有效抑制在无相关记忆时的错误召回（Spurious Recalls）？

#### 2. 方法论：核心思想与技术细节
MemX 采用 Rust 语言开发，基于 libSQL（SQLite 的高性能分支）构建，其核心是一个**面向稳定性的混合检索流水线**：
*   **混合召回（Hybrid Recall）：** 同时运行向量搜索（基于 Qwen3-0.6B 嵌入）和关键词匹配（基于 SQLite FTS5 全文索引）。
*   **倒数排名融合（RRF）：** 使用 RRF 算法合并两路召回结果，平衡语义相关性和精确词匹配。
*   **四因子重排序（Four-Factor Re-ranking）：** 综合考虑四个维度计算最终得分：
    1.  **语义相似度（Semantic）：** 基础相关性。
    2.  **新鲜度（Recency）：** 采用指数半衰期衰减函数，优先考虑最近检索或创建的记忆。
    3.  **频率（Frequency）：** 记录检索次数，通过对数归一化处理。
    4.  **重要性（Importance）：** 用户或系统显式标注的权重。
*   **低置信度拒绝规则（Rejection Rule）：** 引入阈值 $\tau$。若关键词召回为空且最大向量相似度低于 $\tau$（推荐 0.50），系统返回空结果，从而避免“强行回答”。
*   **去重机制：** 包含内容去重和“标签签名”去重，防止同类模板生成的记忆占据所有检索位。

#### 6. 主要结论与发现
*   **存储粒度至关重要：** 在 LongMemEval 中，**事实级（Fact-level）**存储的检索效果是会话级的两倍（Hit@5 达 51.6%），证明了高语义密度记录的优越性。
*   **检索效率：** FTS5 全文索引相比传统的 LIKE 子句查询，在 10 万条记录规模下实现了 **1,100 倍的加速**，端到端搜索延迟控制在 90ms 以内。
*   **拒绝规则有效性：** 设定的 $\tau = 0.50$ 阈值能在不损害召回率的前提下，有效识别并拒绝无答案的查询。
*   **能力边界：** 系统在事实提取和知识更新方面表现强劲，但在**时间推理**和**跨会话推理**方面仍面临挑战（Hit@5 < 44%）。

#### 7. 优点与亮点
*   **本地优先（Local-First）：** 完整实现了基于 Rust 和 SQLite 的本地化方案，兼顾隐私与性能。
*   **稳定性设计：** 创新的拒绝规则和四因子重排序机制，使系统在面对模糊或不存在的记忆时表现得更加稳健。
*   **可解释性：** 检索过程透明，通过显式的访问/检索计数分离，避免了管理性操作对排序信号的污染。
*   **高性能：** 证明了在普通硬件上处理 20 万级记忆条目的可行性。

#### 8. 不足与局限
*   **多主题覆盖不足：** 当前流水线对需要同时检索多个不相关事实的复合查询（Multi-topic）处理能力较弱。
*   **推理能力限制：** 缺乏图遍历或时间索引机制，导致在处理具有时间先后顺序或复杂因果关系的记忆时效果有限。

*   **缺乏闭环反馈：** 系统目前无法记录检索到的记忆是否真正帮助智能体完成了任务（即缺乏任务级归因）。
