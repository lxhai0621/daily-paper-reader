## 摘要
检索增强生成（RAG）被广泛部署以提高语言模型的事实准确性，但目前尚不清楚参数量在 7B 或更小的模型是否能有效利用检索到的信息。为了研究这一问题，我们在四种检索条件下（包括无检索、BM25、使用 E5 large v2 的稠密检索以及保证检索段落包含答案的 Oracle 检索），评估了来自 SmolLM2、Qwen2.5 和 Llama 3.1 三个架构系列的五个模型规模（从 360M 到 8B）。我们引入了一种参数化知识划分方法，将模型已经能够回答的问题与需要外部知识的问题分开，从而能够将利用失败与检索质量失败隔离开来。我们发现了三个主要结果：首先，即使在 Oracle 检索下，7B 或更小的模型在无法独立回答的问题上，有 85% 到 100% 的情况下无法提取出正确答案，这表明存在根本性的利用瓶颈；其次，添加检索上下文会破坏模型先前已知答案的 42% 到 100%，这表明存在一种由上下文的存在而非其质量驱动的干扰效应；第三，对 2588 个 Oracle 失败案例的错误分析显示，主要的失败模式是无关生成，即模型完全忽略了提供的上下文。这些模式在多种提示词模板和检索方法中均成立。结果表明，对于 7B 参数以下的模型，RAG 的主要限制在于上下文利用而非检索质量，并且在标准评估条件下，在此规模下部署 RAG 可能会导致净负收益的权衡。

## Abstract
Retrieval augmented generation RAG is widely deployed to improve factual accuracy in language models yet it remains unclear whether smaller models of size 7B parameters or less can effectively utilize retrieved information. To investigate this question we evaluate five model sizes from 360M to 8B across three architecture families SmolLM2 Qwen2.5 and Llama 3.1 under four retrieval conditions including no retrieval BM25 dense retrieval using E5 large v2 and oracle retrieval where the retrieved passage is guaranteed to contain the answer. We introduce a parametric knowledge split that separates questions a model can already answer from those that require external knowledge which allows us to isolate utilization failure from retrieval quality failure. We find three main results. First even with oracle retrieval models of size 7B or smaller fail to extract the correct answer 85 to 100 percent of the time on questions they cannot answer alone which indicates a fundamental utilization bottleneck. Second adding retrieval context destroys 42 to 100 percent of answers the model previously knew suggesting a distraction effect driven by the presence of context rather than its quality. Third an error analysis of 2588 oracle failures shows that the dominant failure mode is irrelevant generation where the model ignores the provided context entirely. These patterns hold across multiple prompt templates and retrieval methods. The results indicate that for models below 7B parameters the main limitation of RAG is context utilization rather than retrieval quality and that deploying RAG at this scale can lead to a net negative trade off under standard evaluation conditions.

#### 1. 核心问题与整体含义
本论文探讨了**小型语言模型（SLM，参数量 $\le$ 7B）在检索增强生成（RAG）系统中的有效性**。虽然 RAG 被广泛用于减少幻觉，但现有研究多集中于大模型（>10B）。作者旨在揭示：当模型规模缩小到 7B 以下时，RAG 的性能瓶颈究竟是“检索不到相关信息”（检索质量问题），还是“模型无法有效利用检索到的信息”（利用能力问题）。

#### 2. 论文提出的方法论
为了量化“利用能力”并排除检索质量的干扰，论文提出了以下核心方法：
*   **Oracle 检索（先验检索）**：构建一种理想实验条件，确保检索到的段落中 100% 包含正确答案。通过对比 Oracle 检索与普通检索（BM25、稠密检索）的表现，将“利用失败”从“检索失败”中分离出来。
*   **参数化知识拆分（Parametric Knowledge Split）**：将（模型, 问题）对分为两类：
    *   **KNOWN（已知）**：模型在无检索情况下能答对的问题。
    *   **UNKNOWN（未知）**：模型在无检索情况下答错的问题。
    *   这种拆分允许研究者分别观察检索带来的“收益”（解决未知问题）和“损害”（干扰已知知识）。
*   **错误分类法**：将 Oracle 失败案例分为无关生成、拒绝回答、提取错误、实体错误、部分匹配和冗长正确六类。

#### 3. 实验设计
*   **模型选择**：涵盖 3 个架构系列、5 种规模：SmolLM2 (360M)、Qwen2.5 (1.5B, 3B, 7B) 和 Llama 3.1 (8B)。
*   **数据集**：Natural Questions (NQ, 单跳事实) 和 HotpotQA (多跳推理)，共 1,000 个评估问题。
*   **检索基准**：
    *   **None**：无检索（基准）。
    *   **BM25**：传统关键词检索。
    *   **Dense (E5-large-v2)**：基于向量的稠密检索。
    *   **Hybrid (RRF)**：混合检索。
    *   **Oracle**：包含答案的理想检索。
*   **评估指标**：精确匹配（EM）和 F1 分数。

#### 4. 资源与算力
*   **硬件**：实验在 **Kaggle 免费层 T4 GPU** 上运行。
*   **技术细节**：本地模型（SmolLM2, Qwen2.5）使用了 **4-bit NF4 量化**（通过 BitsAndBytes）；Llama 3.1-8B 通过 Groq API 使用 FP16 精度进行验证。
*   **语料库**：使用了 50 万个维基百科段落（约占英文维基百科的 2%）。

#### 5. 实验数量与充分性
*   **实验规模**：总计 1,000 个测试样本，涵盖了多种检索方法和模型规模。
*   **消融与稳健性实验**：
    *   进行了**提示词消融实验**（强制、许可、最小化三种模板），证明结果对提示词不敏感。
    *   进行了**跨架构验证**，证明结论在不同模型家族（Qwen vs Llama）中具有一致性。
    *   对 2,588 个失败案例进行了详细的**人工/启发式错误分析**。
*   **评价**：实验设计严谨，通过 Oracle 条件和知识拆分有效地隔离了变量，统计显著性分析（McNemar 检验）增强了结论的说服力。

#### 6. 主要结论与发现
*   **利用瓶颈严重**：即使提供 100% 包含答案的 Oracle 段落，7B 模型在处理其原本不会的问题时，提取成功率仅为 **14.6%**。360M 模型几乎完全无法利用检索信息。
*   **严重的干扰效应（Distraction Effect）**：检索上下文会“破坏”模型已掌握的知识。对于模型原本能答对的问题，加入检索后，7B 模型会丢掉约 **42%** 的正确答案，而 1.5B 模型会丢掉 **57%**。
*   **上下文存在即干扰**：对于 7B 以下模型，Oracle 检索和噪声检索带来的干扰程度相似，说明**干扰是由上下文的存在驱动的，而非上下文的质量**。
*   **净收益为负**：在标准 RAG 部署下，由于对已知知识的破坏超过了对未知知识的补全，7B 以下模型的净 EM 变化通常为负值。
*   **主导错误模式**：61%–100% 的失败源于**无关生成**（模型完全忽略上下文）。

#### 7. 优点
*   **诊断性强**：不只是报告 RAG 性能，而是通过 Oracle 实验指出了 SLM 的根本缺陷在于“利用”而非“检索”。
*   **细粒度分析**：通过 KNOWN/UNKNOWN 拆分，揭示了 RAG 对小模型知识库的负面影响。
*   **实用性高**：为开发者提供了明确的警示，即在 7B 以下规模部署 RAG 时，简单的 Prompting 可能适得其反。

#### 8. 不足与局限
*   **任务局限性**：研究仅限于**抽取式问答**（Extractive QA），未探讨摘要、推理或生成式任务。
*   **语料库覆盖**：使用的维基百科子集较小（2%），导致 Oracle 覆盖率仅为 75.6%，且无法有效评估长尾知识（如 PopQA）。
*   **量化影响**：虽然通过 FP16 接口进行了验证，但大部分本地实验基于 4-bit 量化，可能在极小模型（360M）上放大了性能退化。
*   **模型架构**：主要测试了 Decoder-only 架构，未涵盖 Encoder-Decoder 模型（如 T5 系列），后者在 RAG 任务中可能有不同的表现。
