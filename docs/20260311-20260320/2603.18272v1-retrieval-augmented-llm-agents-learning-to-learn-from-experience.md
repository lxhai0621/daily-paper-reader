## 摘要
尽管大语言模型（LLMs）推动了通用智能体的发展，但在未见任务上实现鲁棒的泛化仍是一项重大挑战。目前的方法通常依赖于微调或利用检索经验的免训练记忆增强生成，但两者均存在局限性：微调往往难以推导至新任务，而经验检索的表现通常逊于有监督基准。在本研究中，我们提出将这两种方法结合，并系统地研究如何训练检索增强型 LLM 智能体，以在上下文中有效利用检索到的轨迹。首先，我们利用 LoRA 建立了一套鲁棒的有监督微调（SFT）方案，其性能优于多种先进的智能体训练流水线。其次，我们对经验检索的关键设计选择进行了详细分析，确定了存储、查询和轨迹选择的最优策略。最后，我们提出了一种将经验检索集成到微调过程中的流水线。实验结果表明，这种结合方法显著提升了对未见任务的泛化能力，为构建能够从经验中学习的智能体提供了一个可扩展且有效的框架。

## Abstract
While large language models (LLMs) have advanced the development of general-purpose agents, achieving robust generalization to unseen tasks remains a significant challenge. Current approaches typically rely on either fine-tuning or training-free memory-augmented generation using retrieved experience; yet both have limitations: fine-tuning often fails to extrapolate to new tasks, while experience retrieval often underperforms compared to supervised baselines. In this work, we propose to combine these approaches and systematically study how to train retrieval-augmented LLM agents to effectively leverage retrieved trajectories in-context. First, we establish a robust supervised fine-tuning (SFT) recipe using LoRA that outperforms several state-of-the-art agent training pipelines. Second, we provide a detailed analysis of key design choices for experience retrieval, identifying optimal strategies for storage, querying, and trajectory selection. Finally, we propose a pipeline that integrates experience retrieval into the fine-tuning process. Our results demonstrate that this combined approach significantly improves generalization to unseen tasks, providing a scalable and effective framework for building agents that learn to learn from experience.

这篇论文《Retrieval-Augmented LLM Agents: Learning to Learn from Experience》由 NAVER LABS Europe 的研究团队撰写，系统探讨了如何通过结合经验检索与微调来提升大语言模型（LLM）智能体在未知任务上的泛化能力。

### 1. 核心问题与整体含义
*   **研究动机**：当前的 LLM 智能体在面对未见过的任务（Out-of-Distribution, OOD）时表现不佳。现有的两种主流方案各有缺陷：**监督微调（SFT）**虽然在训练任务上表现强劲，但容易过拟合，难以迁移到新任务；**免训练的检索增强生成（RAG）**虽然灵活，但其性能往往低于经过微调的基准模型。
*   **核心目标**：研究如何训练智能体，使其能够有效地从检索到的过去经验（轨迹）中进行“上下文学习”（In-context Learning），从而在不更新参数的情况下解决新环境中的新问题。

### 2. 方法论
论文提出了 **ExpRAG**（Experience Retrieval-Augmented Generation）框架，其核心思想是将智能体的历史成功/失败经验作为外部知识库。
*   **经验库构建**：离线收集智能体的交互轨迹 $\tau_i$，并使用编码器 $\phi$（如 Qwen3-Embedding）将其转化为向量索引。
*   **检索机制**：在推理的每个步骤或初始步骤，将当前任务描述和交互历史作为查询（Query），从经验库中检索 Top-K 条最相关的轨迹。
*   **ExpRAG-LoRA（核心创新）**：
    *   **训练阶段**：在对模型进行 LoRA 微调时，将检索到的经验块（Memory Block）直接注入到系统提示词中。这迫使模型在训练期间就学会如何参考外部轨迹来生成当前动作，而不仅仅是死记硬背训练数据。
    *   **序列化方式**：采用多轮对话（Multi-turn Chat）格式而非单步格式，以利用 KV 缓存加速训练和推理。
*   **检索策略**：对比了**静态检索**（仅在任务开始时检索一次）和**动态检索**（每步根据最新观察刷新检索结果）。

### 3. 实验设计
*   **数据集/场景**：
    *   **ALFWorld**：文字交互式家庭操纵任务。
    *   **ScienceWorld**：复杂的科学实验模拟环境。
*   **Benchmark 设置**：将任务分为“简单（Easy）”和“困难（Hard）”。模型仅在简单任务上微调，在困难任务（未见过的任务类型）上评估泛化能力。
*   **对比方法**：
    *   **免训练方法**：Zero-shot, ReAct, Mem0, Reflexion, 以及纯 ExpRAG。
    *   **微调方法**：NAT, ETO, SAND, 以及标准的 LoRA SFT。

### 4. 资源与算力
*   **硬件**：使用了单张 **NVIDIA A100 (80GB)** GPU。
*   **软件/库**：使用 TorchTune 进行微调，Hugging Face Transformers 进行推理。
*   **训练细节**：LoRA Rank 为 8，Alpha 为 16。论文特别提到，智能体在微调时存在“延迟泛化”现象，因此训练轮数较长（ALFWorld 9轮，ScienceWorld 29轮，部分实验甚至观察到 50 轮后 OOD 性能仍在提升）。

### 5. 实验数量与充分性
*   **实验规模**：涵盖了 4 种不同规模和家族的开源模型（Ministral 3-8B, Gemma 3-4B, Qwen 2.5-7B, Qwen 2.5-7B-1M）。
*   **消融实验**：非常详尽，包括 Top-K 数量（1, 2, 4）、检索频率（静态 vs 动态）、经验库组成（全量 vs 仅简单 vs 仅困难）、轨迹格式（JSON vs 纯文本）等。
*   **客观性**：通过 3 个随机种子评估稳定性，并设置了“索引压力测试”（如索引为空或索引不匹配），验证了方法的鲁棒性。实验设计严谨，对比了多种 SOTA 智能体流水线。

### 6. 主要结论与发现
*   **ExpRAG-LoRA 效果显著**：在未见过的 Hard 任务上，ExpRAG-LoRA 的表现远超标准 LoRA，证明了“带检索的微调”能显著提升泛化性。
*   **简单即有效**：简单的只读式经验检索（ExpRAG）在很多情况下优于复杂的自进化记忆系统。
*   **训练动力学**：发现智能体微调中存在类似“Grokking（顿悟）”的现象，即验证集损失开始上升（过拟合）后，智能体在实际环境中的成功率往往还会继续提高。
*   **动态检索的局限**：虽然动态检索能提供最新信息，但频繁更换上下文会导致“上下文抖动（Context Churn）”，在某些模型上反而不如静态检索稳定。

### 7. 优点
*   **实用性强**：提出了一套切实可行的 LoRA 微调配方，性能优于许多复杂的强化学习或反射机制。
*   **深入的分析**：对检索机制的设计选择（如 JSON 格式化、Top-K 饱和点）提供了极具参考价值的工程建议。
*   **效率优化**：通过多轮对话序列化显著降低了训练成本。

### 8. 不足与局限
*   **经验来源依赖**：实验中使用的经验库是由专家脚本生成的，尚未充分探讨当经验库包含大量 LLM 自身生成的错误轨迹时，模型的抗干扰能力。
*   **索引覆盖风险**：当检索不到任何相关经验时，ExpRAG-LoRA 的性能会退化，甚至可能低于标准 LoRA（由于训练/推理分布不一致）。
*   **长上下文挑战**：随着 Top-K 增加，提示词长度剧增，对推理算力和模型长文本处理能力提出了更高要求。
