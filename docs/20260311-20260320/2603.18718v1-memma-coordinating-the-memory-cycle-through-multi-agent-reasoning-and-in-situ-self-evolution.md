## 摘要
记忆增强型大语言模型（LLM）智能体通过维护外部记忆库来支持长程交互，但现有大多数系统将记忆的构建、检索和利用视为孤立的子程序。这带来了两个耦合的挑战：一是记忆周期前向路径上的策略盲目性，即构建和检索是由局部启发式方法而非显式策略推理驱动的；二是后向路径上的稀疏且延迟的监督，即下游任务的失败很少能转化为对记忆库的直接修复。为了应对这些挑战，我们提出了 MemMA，这是一个即插即用的多智能体框架，可在前向和后向路径上协调记忆周期。在前向路径上，元思考器（Meta-Thinker）生成结构化指导，在构建过程中引导记忆管理器（Memory Manager），并在迭代检索过程中指导查询推理器（Query Reasoner）。在后向路径上，MemMA 引入了原位自我演化记忆构建，它通过合成探测问答对、验证当前记忆，并在记忆最终确定前将失败转化为修复动作。在 LoCoMo 上的广泛实验表明，MemMA 在多个 LLM 主干网络上始终优于现有基准，并以即插即用的方式改进了三种不同的存储后端。我们的代码已在 https://github.com/ventr1c/memma 公开。

## Abstract
Memory-augmented LLM agents maintain external memory banks to support long-horizon interaction, yet most existing systems treat construction, retrieval, and utilization as isolated subroutines. This creates two coupled challenges: strategic blindness on the forward path of the memory cycle, where construction and retrieval are driven by local heuristics rather than explicit strategic reasoning, and sparse, delayed supervision on the backward path, where downstream failures rarely translate into direct repairs of the memory bank. To address these challenges, we propose MemMA, a plug-and-play multi-agent framework that coordinates the memory cycle along both the forward and backward paths. On the forward path, a Meta-Thinker produces structured guidance that steers a Memory Manager during construction and directs a Query Reasoner during iterative retrieval. On the backward path, MemMA introduces in-situ self-evolving memory construction, which synthesizes probe QA pairs, verifies the current memory, and converts failures into repair actions before the memory is finalized. Extensive experiments on LoCoMo show that MemMA consistently outperforms existing baselines across multiple LLM backbones and improves three different storage backends in a plug-and-play manner. Our code is publicly available at https://github.com/ventr1c/memma.

#### 1. 核心问题与研究动机

*   **核心痛点**：现有系统通常将记忆的**构建（Construction）**、**检索（Retrieval）**和**利用（Utilization）**视为孤立的子程序。
*   **两大挑战**：
    *   **前向路径的策略盲目性（Strategic Blindness）**：记忆构建和检索往往依赖局部启发式搜索，缺乏全局策略指导，导致记忆冗余、冲突或检索目标不明确。
    *   **后向路径的反馈稀疏与延迟（Sparse and Delayed Feedback）**：下游任务的失败（如回答错误）很难直接追溯并修复早期的记忆存储错误，导致错误信息在记忆库中持续累积。

#### 2. 方法论
MemMA 提出了一个**即插即用（Plug-and-play）的多智能体框架**，旨在协调记忆周期的正向和反向路径：
*   **前向路径：推理感知协调（Reasoning-Aware Coordination）**
    *   **Meta-Thinker（元思考器）**：作为规划层，为构建阶段提供“存什么、怎么整合”的指导，并为检索阶段诊断“还缺什么、如何优化查询”。
    *   **Memory Manager（记忆管理器）**：根据指导执行原子编辑（添加、更新、删除、跳过）。
    *   **Query Reasoner（查询推理器）**：执行迭代式的“精炼-探测”循环，通过 Meta-Thinker 的诊断引导，逐步缩小信息差距，而非盲目重写查询。
*   **后向路径：原位自进化记忆构建（In-Situ Self-Evolving Construction）**
    *   **探针生成**：在每个 Session 结束后，自动合成针对该 Session 内容的探测问答对（QA Pairs）。
    *   **原位验证与修复**：在记忆正式提交前，利用探测 QA 对当前记忆进行测试。若回答错误，则通过反射模块生成修复建议，并进行语义整合（去重、合并），从而在错误传播前完成即时修复。

#### 7. 优点
*   **闭环设计**：首次将记忆管理视为一个完整的闭环周期，同时优化正向执行和反向修复。

*   **架构解耦**：作为一种协调框架，它可以轻松集成到现有的各类记忆增强系统中。

#### 8. 不足与局限
*   **应用场景限制**：目前仅在对话类长程记忆基准上验证，对于非结构化任务或具身智能环境的适用性有待观察。
*   **Session 划分依赖**：自进化机制依赖于清晰的 Session 边界划分，在完全无界的流式交互中可能面临挑战。
*   **推理成本**：引入多智能体协同、迭代检索和合成 QA 验证会显著增加 API 调用成本和系统响应延迟。
