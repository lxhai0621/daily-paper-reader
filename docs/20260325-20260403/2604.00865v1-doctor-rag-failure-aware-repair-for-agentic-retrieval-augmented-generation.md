## 摘要
智能体检索增强生成（Agentic RAG）已成为多跳问答和复杂知识推理中广泛采用的范式，其中检索和推理在推理阶段交替进行。随着推理轨迹变长，故障变得越来越普遍。现有方法通常通过停留在诊断分析或重新运行整个检索-推理流水线来处理此类故障，这导致了巨大的计算开销和冗余推理。在本文中，我们提出了 Doctor-RAG (DR-RAG)，这是一个统一的诊断与修复框架，通过显式的错误定位和前缀重用（prefix reuse）来纠正 Agentic RAG 中的故障，从而实现最小成本的干预。DR-RAG 将故障处理分解为两个连续阶段：(i) 轨迹级故障诊断与定位，将错误归因于覆盖门控分类法（coverage-gated taxonomy），并识别推理轨迹中最早的故障点；(ii) 工具调节的局部修复，仅在诊断出的故障点进行干预，同时最大限度地重用已验证的推理前缀和检索到的证据。通过显式地将错误归因与纠正分离，DR-RAG 实现了精确的错误定位，从而避免了昂贵的完整流水线重运行，并实现了有针对性的高效修复。我们在三个多跳问答基准测试、多个 Agentic RAG 基准模型以及不同的骨干模型上对 DR-RAG 进行了评估。实验结果表明，与基于重运行的修复策略相比，DR-RAG 在显著降低推理 Token 消耗的同时，大幅提高了回答准确率。

## Abstract
Agentic Retrieval-Augmented Generation (Agentic RAG) has become a widely adopted paradigm for multi-hop question answering and complex knowledge reasoning, where retrieval and reasoning are interleaved at inference time. As reasoning trajectories grow longer, failures become increasingly common. Existing approaches typically address such failures by either stopping at diagnostic analysis or rerunning the entire retrieval-reasoning pipeline, which leads to substantial computational overhead and redundant reasoning. In this paper, we propose Doctor-RAG (DR-RAG), a unified diagnose-and-repair framework that corrects failures in Agentic RAG through explicit error localization and prefix reuse, enabling minimal-cost intervention. DR-RAG decomposes failure handling into two consecutive stages: (i) trajectory-level failure diagnosis and localization, which attributes errors to a coverage-gated taxonomy and identifies the earliest failure point in the reasoning trajectory; and (ii) tool-conditioned local repair, which intervenes only at the diagnosed failure point while maximally reusing validated reasoning prefixes and retrieved evidence. By explicitly separating error attribution from correction, DR-RAG enables precise error localization, thereby avoiding expensive full-pipeline reruns and enabling targeted, efficient repair. We evaluate DR-RAG across three multi-hop question answering benchmarks, multiple agentic RAG baselines, and different backbone models. Experimental results demonstrate that DR-RAG substantially improves answer accuracy while significantly reducing reasoning token consumption compared to rerun-based repair strategies.

*   **核心问题**：现有的故障处理方式存在两个极端：一是仅进行诊断分析而不提供自动修复；二是发现错误后直接“全量重跑”（Rerun），这导致了巨大的计算资源浪费（Token 消耗高）和推理冗余。

### 2. 方法论：Doctor-RAG (DR-RAG) 框架
DR-RAG 将故障处理建模为“诊断-定位-局部修复”的系统级过程，核心包含两个阶段：

*   **阶段一：分类法约束的错误诊断与定位**
    *   **覆盖门控分类法**：首先评估已检索文档对问题的“证据覆盖率”（Coverage）。
        *   若 **Cov=1**（证据充足）：错误归类为“格式错误”或“推理逻辑错误”。
        *   若 **Cov<1**（证据不足）：错误归类为“检索器失效”（Query 对但没搜到）或“搜索诱导错误”（推理错导致 Query 错）。
    *   **轨迹级定位**：识别推理轨迹中最早出现的失效动作索引 $k^\dagger$。$k^\dagger$ 之前的步骤被视为“验证通过的前缀”，予以保留。
*   **阶段二：工具调节的局部修复**
    *   **前缀重用（Prefix Reuse）**：截断故障点之后的轨迹，保留有效前缀。
    *   **针对性修复算子**：
        *   *格式修复*：仅重写最终答案。
        *   *推理修复*：在现有证据基础上，从故障点重新开始推理。
        *   *检索修复*：重写查询语句并增加 Top-K 检索深度。
        *   *搜索诱导修复*：重新生成高层解决方案计划，并引导后续检索。

### 6. 主要结论与发现
*   **性能提升**：DR-RAG 在所有基准测试中均显著优于全量重跑策略。例如在 Qwen3-8B + ReAct 组合下，HotpotQA 的 EM 提升了 25.8%。
*   **成本降低**：相比 Rerun 策略，DR-RAG 在提升准确率的同时，减少了约 **25%-30% 的 Token 消耗**。
*   **局部修复的优越性**：精确的错误定位能有效防止“修复引入新错误”的现象，比盲目重跑更稳健。
*   **难度差异**：证据覆盖不足（Cov<1）时的修复难度远高于证据充足（Cov=1）的情况，MuSiQue 数据集由于推理链极长，修复挑战最大。

### 7. 优点与亮点
*   **首创性**：首次将 Agentic RAG 的失效处理形式化为“最小成本干预”问题，而非简单的重试。
*   **前缀重用机制**：通过保留已验证的推理路径，极大地提高了长链推理的效率。
*   **解耦设计**：将错误归因（诊断）与纠正（修复）分离，使得修复逻辑可以针对不同错误类型进行高度定制。

### 8. 不足与局限
*   **诊断准确率瓶颈**：自动诊断模块的准确率目前在 60% 左右，若诊断错误（如将推理错误误判为检索错误），可能导致修复失败。
*   **依赖 LLM 裁判**：诊断过程本身依赖 LLM 的判断力，对于较弱的骨干模型，诊断本身的可靠性会下降。
*   **应用限制**：目前主要针对文本问答，对于涉及多模态或复杂工具调用的 Agent 场景尚未验证。
*   **数据集偏差**：实验主要集中在 Wikipedia 语料库，对于实时性极强或私有领域知识的 RAG 修复效果有待进一步观察。
