## 摘要
大型语言模型通过参数化记忆和检索证据来回答知识密集型问题，但两种来源都并非始终可靠。检索可以填补知识空白，但干扰性段落可能会覆盖正确的闭卷答案。我们将这种生成后冲突视为答案级别的来源仲裁：给定来自同一冻结模型的直接答案和RAG答案，决定信任哪个来源。我们提出TRUSTMARGIN，这是一个免训练、即插即用的仲裁层，它使用模型自身的似然度对两个现有候选答案进行评分。它结合了参数化先验边际（测试记忆是否接受检索到的答案）和证据绑定边际（折扣仅基于段落的显著性并衡量问题特定的支持度）。TRUSTMARGIN在直接生成和RAG之间进行选择，无需微调、外部评判或额外生成。在三个LLaMA规模的2WIKIMQA和CWQA数据集上，TRUSTMARGIN始终优于直接生成和BM25-RAG，恢复了直接生成/RAG oracle的部分差距，并泛化到多个免训练RAG流水线中。

## Abstract
Large language models answer knowledge-intensive questions using both parametric memory and retrieved evidence, but neither source is uniformly reliable. Retrieval can fill knowledge gaps, yet distracting passages may override correct closed-book answers. We study this post-generation conflict as answer-level source arbitration: given Direct and RAG answers from the same frozen model, decide which source to trust. We propose TRUSTMARGIN, a training-free, plug-and-play arbitration layer that scores the two existing candidates with the model's own likelihoods. It combines a parametric-prior margin, which tests whether memory accepts the retrieved answer, with an evidence-binding margin, which discounts passage-only salience and measures question-specific support. TRUSTMARGIN selects between Direct and RAG without fine-tuning, external judges, or additional generation. Across 2WIKIMQA and CWQA with three LLaMA scales, TRUSTMARGIN consistently improves over Direct generation and BM25-RAG, recovers part of the Direct/RAG oracle gap, and generalizes to multiple training-free RAG pipelines.

## 2. 方法论：核心思想、关键技术细节、公式或算法流程

- **核心思想**：仲裁应满足两个互补检验：  
  1. **参数先验兼容性**：在仅含问题的提示下，模型不应强烈偏好其直接答案而非RAG答案。  
  2. **问题-证据绑定**：答案应获得问题与检索段落交互的支持，而非仅由段落本身显着性驱动。

- **关键技术细节**：
  - **三个似然度视角**：使用冻结模型对两个候选答案（y_D, y_R）在三种提示下计算长度归一化的teacher-forced对数似然：
    - ℓ_D(y) = (1/|y|) log p_θ(y | q) （闭卷似然）
    - ℓ_R(y) = (1/|y|) log p_θ(y | q, P) （证据条件似然）
    - ℓ_C(y) = (1/|y|) log p_θ(y | P) （仅上下文似然，去除问题）
  - **参数先验边际**：M_prior = ℓ_D(y_R) - ℓ_D(y_D)。正值表示RAG答案在仅有问题时也可接受，强负值表示记忆偏好直接答案。
  - **证据绑定边际**：定义Δ(y) = ℓ_R(y) - ℓ_C(y)，比较两个候选：M_bind = Δ(y_R) - Δ(y_D)。正的大值表示RAG答案获得更多问题-证据交互支持。
  - **信任得分**：M_TrustMargin = M_prior + λ_bind * M_bind，其中λ_bind=0.5，阈值τ=-1.5（固定在所有实验）。选择规则：若M > τ，则采纳RAG答案，否则保留直接答案。

- **算法流程**（文字说明）：
  1. 使用冻结LLM分别从问题-only生成直接答案y_D，从问题+BM25 top-20段落生成RAG答案y_R。
  2. 对两个候选，分别计算三种teacher-forced似然：ℓ_D(y_D)、ℓ_D(y_R)、ℓ_R(y_D)、ℓ_R(y_R)、ℓ_C(y_D)、ℓ_C(y_R)。
  3. 计算M_prior和M_bind，加权求和得到M。
  4. 应用阈值τ决定最终答案。

- **训练-free、即插即用、无需额外生成或外部评判**。

## 7. 优点

- **训练-free**：无需微调、外部评判或额外生成，仅利用冻结模型自身似然度。
- **即插即用**：可附着于现有Direct/RAG系统或任何训练-free RAG管线，不影响原有生成流程。
- **轻量可审计**：决策由两个清晰、可解释的边际构成，便于调试和信任度评估。
- **鲁棒性**：超参数在宽范围内有效（固定λ_bind=0.5, τ=-1.5 across all settings）；对检索噪声自动保守。
- **实验设计严谨**：控制变量严格（相同BM25、提示、解码），对比多类训练-free基线，消融和诊断实验深入揭示机制。

## 8. 不足与局限

- **候选集边界**：方法无法修复两个候选均错误的情况（误例的Oracle gap未被恢复）。性能受限于Direct和RAG候选质量。
- **延迟增加**：需要额外两次生成（Direct和RAG）以及6次teacher-forced评分，端到端延迟高于简单Direct或BM25-RAG（约为BM25-RAG的3倍）。虽可缓存缓解，但实时场景中可能不理想。
- **对候选多样性敏感**：当RAG管线产生的答案与Direct高度相似时（如FLARE），仲裁无法带来增益。方法依赖候选集的多样性。
- **实验局限性**：仅使用两个数据集（2WikiMQA和CWQA），未在更广泛的QA或知识密集型任务上验证；仅使用BM25作为检索器（未测试密集检索如DPR/Contriever作为主方法）；仅测试三个LLaMA模型（未覆盖其他架构如Mistral、GPT系列等）。
- **应用限制**：在高风险领域（如医疗、法律）中，不能保证事实正确性，应配合检索评估和答案验证使用。
