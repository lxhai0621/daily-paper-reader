## 摘要
大语言模型智能体在处理长期任务时面临挑战，因其固有的无状态性，所有任务相关信息都必须编码在不断增长的输入上下文中。这导致推理质量下降、推理成本增加和延迟升高，因此需要高效的工作记忆机制。然而，现有方法要么依赖有损压缩，要么基于相似性检索，往往无法捕获多步智能体任务所需的时间结构和因果依赖。本文提出HORMA，一种层次化组织与检索记忆智能体，它将经验组织成类似文件系统的层次结构，其中摘要实体与对应的原始轨迹相连，从而在保留详细信息的同时实现高效访问。HORMA将工作记忆分解为两个阶段：结构化记忆构建和基于导航的检索。构建模块通过区分由信息缺失导致的失败和由误导或过载上下文导致的失败，迭代优化经验的结构化方式。导航模块利用轻量级智能体（通过强化学习训练）遍历层次结构来检索任务相关上下文，以选择最小但充分的上下文，从而减少关键执行路径上的延迟。在ALFWorld、LoCoMo和LongMemEval上，HORMA在受限上下文预算下提升了任务性能，同时在长对话任务中最多仅需基线标记使用量的22.17%。与现有方法相比，它始终能实现更好的效率-性能权衡，并有效泛化到未见任务。

## Abstract
Large language model (LLM) agents struggle with long-horizon tasks due to their inherent statelessness, requiring all task-relevant information to be encoded in growing input contexts. The resulting degraded reasoning quality, increased inference cost, and higher latency necessitate efficient working memory mechanisms. However, existing approaches either rely on lossy compression or similarity-based retrieval, which often fail to capture temporal structure and causal dependencies required for multi-step agentic tasks. In this work, we present HORMA, a Hierarchical Organize-and-Retrieve Memory Agent that organizes experience into a file-system-like hierarchical structure, where summarized entities are linked to the corresponding raw trajectories, enabling efficient access without losing detailed information. HORMA decomposes working memory into two stages: structured memory construction and navigation-based retrieval. The construction module iteratively refines how experiences are structured by distinguishing between failures caused by missing information and those caused by misleading or overloaded context. The navigation module retrieves task-relevant context by traversing the hierarchy using a lightweight agent trained with reinforcement learning to select minimal yet sufficient context, thereby reducing latency along the critical execution path. Across ALFWorld, LoCoMo, and LongMemEval, HORMA improves task performance under constrained context budgets while requiring at most 22.17% of the baseline token usage in long conversation tasks. Compared to existing methods, it consistently achieves better efficiency-performance trade-offs and generalizes effectively to unseen tasks.

### 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：提出 **HORMA（Hierarchical Organize-and-Retrieve Memory Agent）**，将工作记忆显式解耦为两个模块，共用一个层次化文件系统工作空间：
  1. **结构化记忆构建（Memory Manager, M_m）**：将原始轨迹组织成语义化的文件目录结构（如实体摘要、事件记录、时间戳），并与原始轨迹链接以保留来源。通过**递归技能提炼（Recursive Skill Refinement）** 迭代改进构建策略：对比成功/失败轨迹，区分信息缺失（外源性失败）与信息过载/误导（内源性失败）两类错误，生成自然语言反馈并扩充非参数化技能库。
  2. **导航检索（Retrieval Agent, M_r）**：利用 BASH 工具（`ls`, `cd`, `grep`, `cat`等）以及两个终端动作 `select` 和 `done` 在层级结构中主动导航，选择最小但充分的上下文。使用 **GRPO（Group Relative Policy Optimization）** 进行策略优化，奖励函数基于检索上下文与真实证据之间的**Jaccard重叠度**，提供细粒度的检索质量反馈。

- **关键技术细节**：
  - 记忆构建使用域无关初始提示，后续通过对比分析增强技能。
  - 检索策略独立于主智能体，在主智能体（φ参数冻结）之前执行：π = M_r(C|F,q) · M_θ(a|o,C,q)。
  - 支持**证据级检索奖励**，解决了联合优化中的信用分配问题。
  - 检索agent可学习探索、恢复失败命令、优化搜索轨迹。

### 3. 实验设计：数据集、基准、对比方法

- **数据集与场景**：
  - **ALFWorld**：文本交互式家居环境，134个任务，6个类别（Pick&Place, Clean&Place等）。评估成功率和帕累托效率（步数 vs. token）。
  - **LoCoMo**：长多轮对话记忆基准，10个对话（7个训练，3个测试共519个QA）。评估单跳、时间推理、对抗性问题。
  - **LongMemEval**：多会话长对话记忆基准，367个QA，涵盖知识更新、单会话用户/助手偏好、时间推理等，用于测试零样本泛化。

- **对比方法**：
  - **静态内部记忆**：Truncation, Sliding Window, Embedding检索。
  - **动态内部记忆**：Fold（上下文折叠）, HIAGENT, ReSum, Acon。
  - **外部动态记忆**：A-MEM, Mem0, Embedding Retrieval（基于HORMA的结构化笔记）。
  - 所有方法使用相同主智能体Claude Sonnet 4.5。

- **评估指标**：
  - ALFWorld：成功率（%）；步数、每步token。
  - LoCoMo/LongMemEval：LLM-as-Judge (L-J) 分数、F1分数；总输入token量。

### 7. 优点

- **设计创新**：
  - 首次将记忆构建与检索显式解耦，解决了端到端联合优化中的信用分配难题，使各自优化更高效。
  - 利用文件系统作为通用界面，操作可解释、可追溯，支持结构化导航。
  - 引入证据级检索奖励，提供细粒度反馈，无需依赖任务级稀疏奖励。
- **效率与性能**：
  - 在严格token预算下仍保持高成功率，帕累托前沿最优。
  - RL训练的检索agent仅4B参数，计算开销低，且具有强泛化能力。
- **可扩展性**：
  - 技能库可跨任务累积，无需重新训练。
  - 记忆管理方法可独立于检索骨干使用（如Embedding Retrieval增强）。

### 8. 不足与局限

- **实验覆盖有限**：仅评估三个基准（ALFWorld、LoCoMo、LongMemEval），未涉及更复杂的具身场景或真实部署环境。
- **依赖高性能模型**：记忆构建需要Claude Sonnet 4.5级别模型，成本较高且不开放。弱模型管理能力差，削弱了方法可推广性。
- **RL训练规模小**：检索agent仅在LoCoMo训练集（7个对话）上训练，样本量小，可能限制策略稳健性。
- **技能提炼仍需人工介入**：对比轨迹分析需要人工定义反馈指令，未实现完全自动化。
- **延迟与开销未分析**：虽然减少了主智能体上下文，但记忆管理模块本身的Bash操作和多次LLM调用（管理、检索）可能引入额外延迟，论文未量化。
- **信息丢失风险**：即使有原始轨迹链接，摘要和层次化组织仍可能丢失微妙上下文（如语气、隐含意图），影响特定任务。
