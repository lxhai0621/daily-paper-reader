## 摘要
长文档问答要求大型语言模型在分散于长文档中的证据上进行推理，答案通常依赖于事件顺序、章节级上下文以及跨片段证据连接。尽管检索增强生成通过检索相关证据减少了输入上下文，但现有的结构化检索增强生成方法仍面临三个局限：代价高昂的查询无关知识组织、对原始文档结构利用不足以及无法复用历史推理经验。为解决这些问题，我们提出了DocTrace，一个面向长文档问答的多智能体检索增强生成框架，支持查询触发的知识组织、文档结构感知和基于经验的推理。DocTrace通过轻量级文档结构树索引保留文档层次结构，在推理过程中按需构建智能体共享的超图结构工作记忆，并将成功的推理计划存储在基于图结构的经验记忆中供未来复用，从而在相关长文档问题间实现自适应探索。在四个长文档问答数据集上的实验表明，DocTrace在三个数据集上取得了最佳性能，F1分数最高超过最强基线ComoRAG 8.85%，精确匹配最高超过4.40%，同时总体计算成本降低了53.32%。

## Abstract
Long-document question answering (QA) requires large language models (LLMs) to reason over evidence scattered across lengthy documents, where answers often depend on event order, section-level context, and cross-part evidence connections. Although retrieval-augmented generation (RAG) reduces the input context by retrieving relevant evidence, existing structured RAG methods still face three limitations: costly query-agnostic knowledge organization, insufficient use of original document structure, and no reuse of historical reasoning experience. To address these limitations, we propose DocTrace, a multi-agent RAG framework for long-document QA that supports query-triggered knowledge organization, document-structure-aware and experience-guided reasoning. DocTrace preserves document hierarchy with a lightweight document structural tree index, constructs agent-shared hypergraph-structured working memory on demand during reasoning, and stores successful reasoning plans in graph-structured experience memory for future reuse, enabling adaptive exploration across related long-document questions. Experiments on four long-document QA datasets show that DocTrace achieves the best performance on three datasets, surpassing the strongest baseline, ComoRAG, by up to 8.85% in F1 and 4.40% in EM, while reducing the overall computational cost by 53.32%

# 论文总结：DocTrace

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：长文档问答中，大型语言模型需要从大量分散的证据中推理出答案，现有检索增强生成方法存在三大局限：
  - **高成本的查询无关知识组织**：预先为整个文档构建摘要树或知识图谱，无论查询是否需要，都要付出大量LLM调用和token开销。
  - **忽视文档内在结构**：将文档切分为扁平化文本块，丢失了章节边界、段落顺序、局部邻接等结构信息，而这些结构对理解事件顺序、叙事流至关重要。
  - **不重用历史推理经验**：每个问题被孤立处理，之前成功的子问题分解和推理轨迹被丢弃，无法指导后续结构相似的问题。

- **整体意义**：提出DocTrace，一种结构化、按需、可复用经验的RAG框架，旨在同时解决效率、结构感知和知识复用三大问题。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
DocTrace采用**多智能体架构**（Orchestrator + Investigator），通过**查询触发的知识组织**避免预构建全文档结构，利用**文档结构树**实现结构感知检索，并通过**图结构经验记忆**存储和复用成功的推理计划。

### 关键技术细节

**① 文档结构树索引**
- 将文档解析为四层节点（文档/章/节/段落），保留父子关系和同级顺序。
- 通过LLM识别标题模式并构建树，用spaCy抽取每个节点的命名实体。
- 树结构支持结构感知的PageRank传播（TreePPR），将种子节点的相关性沿树边扩散。

**② 按需超图工作记忆**
- **抽象视图（MA）**：自底向上构建分层摘要，仅在需要时针对选定节点区域生成摘要，支持复用已有摘要。
- **关系视图（MR）**：仅从当前子问题相关的顶部节点中提取n元关系，构建局部超图，支持多跳关系推理。
- 工作记忆随推理过程动态扩展，由多个Investigator共享，避免重复构建。

**③ 图结构经验记忆**
- 将成功的推理计划存储为有向无环图，包含子问题及其依赖关系。
- 检索路径：问题骨架相似性、签名描述相似性、推理模式/答案类型/约束的结构重叠。
- 更新时只保留高质量DAG，并限制每个骨架和推理模式的条目数量。

**④ 推理过程**
- Orchestrator负责全局控制：抽象问题 → 选择种子节点 → 检索经验DAG → 初始化计划 → 执行推理（深度优先搜索状态空间） → 聚合答案。
- Investigator负责子问题级别：分析问题 → 预测检索几何参数（范围、形状、粒度） → 执行TreePPR → 路由到合适的工作记忆工具（直接阅读、摘要、关系路径） → 返回答案。
