## 摘要
现代大型语言模型（LLM）智能体可以使用外部工具来帮助用户解决复杂任务。然而，对于需要从长期历史事件或先前的智能体-环境交互中学习的问题，LLM智能体需要使用记忆机制来存储和检索经验。虽然对话智能体存在复杂的记忆系统，但很少有研究实证检验如何通过过去的用户-智能体对话来提高智能体的工具使用能力。我们提出了MemToolAgent，一个通过记忆管理改进工具使用的框架。我们的方法包含一个记忆提取模块，将过去的经验处理成结构化的记忆条目，以及一个检索模块，动态选择存储的记忆条目的子集。这使得在无需微调LLM的情况下，能够提供更个性化和准确的响应，与用户偏好和反馈保持一致。总之，本工作有三个主要贡献：（1）统一的记忆条目格式，无需微调LLM即可改进通用和个性化工具使用；（2）基于反思的记忆提取，利用环境和用户反馈将错误执行提炼成批评存储起来；（3）一个基于记忆相似性分布选择使用多少过去经验的检索模块。MemToolAgent在WorkBench、NESTFUL和PEToolBench基准测试上分别比强基线实现了29%、80%和17%的相对改进。

## Abstract
Modern large language model (LLM) agents can use external tools to help users solve complex tasks. However, for problems that require learning from long-term historical events or from previous agent-environment interactions, LLM agents are required to use memory mechanisms to store and retrieve experiences. While sophisticated memory systems exist for dialogue agents, few studies have empirically examined how to improve agents' tool-using capabilities through past user-agent conversations. We propose MemToolAgent, a framework that improves tool use through memory management. Our approach contains a memory extraction module that processes past experiences into structured memory entries, and a retrieval module that dynamically selects a subset of the stored memory entries. This enables more personalized and accurate responses aligned with user preferences and feedback without requiring LLM fine-tuning. In summary, this work has three main contributions: (1) a unified memory entry format that improves both general-purpose and personalized tool use without LLM fine-tuning, (2) a reflection-based memory extraction that uses environment and user feedback to distill wrong executions into critiques to store, and (3) a retrieval module that chooses how many past experiences to use based on the memory similarity distribution. MemToolAgent achieves 29%, 80%, and 17% relative improvements compared to strong baselines on the WorkBench, NESTFUL, and PEToolBench benchmarks, respectively.

## 2. 论文提出的方法论

### 核心思想
- 存储过去的用户查询、代理的工具调用序列、用户二元反馈（成功/失败），对失败案例生成反思/批评，形成结构化记忆条目。
- 在推理时，基于当前查询的语义相似性动态选择相关记忆条目作为上下文（in-context learning）指导代理执行。

### 关键技术细节
1. **统一记忆条目格式**：  
   每个记忆 `m = (q, a, f, r)`，其中：
   - `q`：用户查询
   - `a`：工具调用序列（`a1, a2, ..., an`）
   - `f`：用户反馈（1=成功，0=失败）
   - `r`：反思/批评（当 `f=0` 时由记忆提取模块生成，成功时为 `∅`）

2. **记忆提取模块**（Memory Extraction Module）：
   - 基于LLM的模块，输入：当前查询、可用工具、代理响应、环境反馈、用户反馈、检索到的相似记忆。
   - 输出：对错误执行的反思（critique），而非原始复杂轨迹，使代理更容易从错误中学习。
   - 通用场景：提示分析工具顺序、参数幻觉、错误值、错误推理等。
   - 个性化场景：提取高层用户偏好（如“用户偏好 `API_X` 下的工具”）。

3. **动态Top-n检索**（Dynamic "n" Top-n Embedding-based Retrieval）：
   - 计算当前查询与所有记忆的余弦相似度，降序排列。
   - 用滑动窗口计算一阶导数估计（类似寻找“knee”点），找到相似度曲线的“峰值”（即突变点）作为检索数量 `n`。
   - 参数：半径 `R`（平滑）、prominence（峰显著性）、peak_number（选第几个峰）。
   - 与固定的 Adaptive-k 不同：Adaptive-k只找最大下降点，而动态n能处理噪声和多步下降曲线，更鲁棒。

### 算法（文字说明）
- **步骤1**：计算查询与每个记忆的余弦相似度。
- **步骤2**：降序排序相似度数组 `x`。
- **步骤3**：对每个位置 `j`（从 `R` 到 `|x|-R-1`），计算加权导数估计：`y(j) = - (∑τ=-R..R τ·x(j+τ)) / (∑τ=-R..R τ²)`。
- **步骤4**：用 `scipy.signal.find_peaks` 找 `y` 的峰值（过滤prominence）。
- **步骤5**：选取第 `peak_number` 个峰值对应的索引作为 `n`，取前 `n` 个记忆。

- MemToolAgent在通用工具使用（WorkBench总体85.06%，比无记忆57.56%提升约47.8%；NESTFUL全序列匹配30.4% vs 15.6%）和个性化工具选择（Tool Accuracy 0.820 vs 0.700）上均大幅超越强基线。

- 合成查询可缓解冷启动问题，但对复杂多域任务效果有限。
- 输出token开销较低，有利于实际部署。

## 7. 优点

- **无需微调LLM**：所有改进仅通过prompt工程和记忆管理实现，易于迁移到不同LLM。

- **动态检索**：基于相似度分布自适应确定记忆数量，避免了固定k的次优选择。
- **反思生成**：将复杂执行轨迹提炼为简单批评，降低了代理在推理时的认知负荷。
- **丰富的消融实验**：验证了每个模块的作用，并探讨了冷启动、合成数据等实际问题。
- **成本分析**：展示了token消耗权衡，输出成本低于扩展思考或ReAct。
