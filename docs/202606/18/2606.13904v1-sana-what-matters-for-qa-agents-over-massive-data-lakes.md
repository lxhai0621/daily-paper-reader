## 摘要
对数据湖进行探索性问答（EQA）需要LLM代理发现相关来源、分析检索到的数据，并根据中间结果调整其行动。仅凭端到端准确率无法区分搜索、规划、数据分析或代理的行动策略（即下一步做什么以及何时提交答案的决策）中的失败。我们提出SANA（搜索代理导航消融框架），这是一个诊断性消融框架，将EQA任务转化为包含黄金来源序列、清洗后的子问题及执行记录的运行时配置文件。SANA利用这些配置文件构建理想化的搜索、规划和数据分析工具，从而允许对每个组件进行消融；残余差距则是策略失败的诊断依据。为说明SANA作为可复用评估框架的用途，我们适配了两个近期EQA基准（LakeQA和KramaBench），并在固定提示、预算、数据湖和运行时条件下评估了轻量级和中型代理。在两个基准中，数据分析始终是瓶颈，而规划问题较小。搜索在LakeQA的大数据湖设置中是主要限制，但在规模较小的KramaBench中则不那么显著。因此，SANA将端到端任务准确率解构为对数据湖代理失败原因的诊断，并允许对搜索、规划、数据分析和代理设计方面的进展进行系统性比较。

## Abstract
Exploratory question answering (EQA) over data lakes requires an LLM agent to discover relevant sources, analyze retrieved data, and adapt its actions based on intermediate results. End-to-end accuracy alone cannot distinguish failures in search, planning, data analysis, or the agent's Action Policy: its decisions about what to do next and when to submit an answer. We present SANA (Search Agent Navigation Ablation framework), a diagnostic ablation framework that transforms EQA tasks into runtime profiles containing gold source sequence, sanitized subquestions, and execution records. SANA uses these profiles to construct idealized search, planning, and data-analysis tools, allowing each component to be ablated; the residual gap is diagnostic evidence for policy failures.   To illustrate SANA as a reusable evaluation framework, we adapted two recent EQA benchmarks, LakeQA and KramaBench, and evaluated lightweight and mid-sized agents under fixed prompts, budgets, data lakes, and runtimes. Across both benchmarks, data analysis is a consistent bottleneck while planning is less so. Search is a major limitation in LakeQA's large data-lake setting, but less so for the smaller-scale KramaBench. SANA thus deconstructs end-to-end task accuracies into a diagnosis of where data-lake agents fail, and allows for systematic comparisons of progress in search, planning, data analysis, and agent design.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究动机**：在大数据湖中进行探索性问答（Exploratory Question Answering, EQA）时，LLM代理需要自主发现相关数据源、分析检索结果，并根据中间结果动态调整下一步行动。然而，单纯依靠端到端准确率无法区分失败的具体环节——究竟是搜索、规划、数据分析，还是代理的“行动策略”（即决定下一步做什么及何时提交答案的策略）出了问题。
- **核心问题**：当EQA代理在数据湖上失败时，哪个运行时组件是根本原因？如何设计一种诊断方法，能够系统性地隔离并评估各个组件的贡献和瓶颈？
- **整体意义**：解决EQA失败原因模糊的问题，提供一种可复用的消融评估框架，帮助研究者针对性地改进搜索、规划、数据分析和代理策略，推动数据湖问答系统的进步。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：SANA（Search Agent Navigation Ablation framework）是一个诊断性消融框架。它将已解决的EQA任务转化为运行时配置文件（包含黄金源序列、清洗后的子问题、执行记录），并利用这些配置构造理想化的搜索、规划和数据分析工具。通过系统地用理想化版本替换实际组件，可以观测到性能变化，从而诊断哪些组件是瓶颈；如果所有组件都理想化后仍有性能差距，则残差归因于代理策略的失败。
- **关键技术细节**：
  - **任务配置（Task Profile）**：每个任务由三部分组成：
    - 源序列（Source Sequence）：回答每个子问题所需的黄金数据集顺序。
    - 清洗后的子问题（Sanitized Subquestions）：去除数据集名称等泄露信息的子问题文本，防止信息泄露。
    - 执行记录（Execution Records）：每个需要进行数据分析的子问题对应的数据集、正确分析意图、正确SQL/代码以及中间答案。
  - **消融条件**：框架定义三个消融轴（Planning / Search / Data Analysis），每个轴有多种模式：
    - **Planning**：Naive（无规划工具）、Standard（标准自写规划）、Ideal（接收清洗后的子问题序列）。
    - **Search**：Naive（BM25稀疏检索）、Standard（混合检索+RRF+Pneuma描述）、Ideal（仅在黄金数据集中搜索）、Preloaded（直接将黄金源放入上下文，无需搜索）。
    - **Data Analysis**：Standard（代理自行编写并执行SQL/Python）、Ideal（基于意图匹配或更强模型修复执行代码）。
  - **意图对齐（Intent-based Ablation）**：为了保证消融的公平性，框架从工具调用中提取语义意图（如搜索关键词、分析目标），然后基于意图提供理想化结果，而不是简单地替换整个工具。
  - **理想化实现**：
    - 理想搜索：用一个子代理（selector）根据搜索查询和意图从黄金源中选择匹配的源。
    - 理想数据分析：先判断当前数据集是否为黄金源、意图是否匹配执行记录中的分析意图。匹配则直接返回黄金答案；不匹配则使用更强的模型（gpt-5.4）生成并修复代码，最多两次重试。

## 6. 论文的主要结论与发现

1. **数据分析是持续瓶颈**：在两个基准中，理想化数据分析带来显著提升（LakeQA上gpt-5-mini提升+18.5%，KramaBench上gpt-5.4-nano提升+24.1%）。代理即使找到正确源并具有正确意图，仍会在实际编写SQL/Python代码时失败。
2. **搜索在大规模数据湖中是主要瓶颈**：在LakeQA（大数据湖）上，理想搜索相比BM25提升+14.1%（弱模型）和+13.3%（强模型）；预加载源进一步提高弱模型性能（+28.9%），说明弱模型在搜索导航上更吃力。而在KramaBench（数据湖较小）上，搜索影响较小（理想搜索提升仅2.4%~6.0%）。
3. **规划影响较小**：规划理想化带来的增益有限（LakeQA上弱模型+3.0%，强模型+9.6%）。代理通常能写出与黄金序列相似的计划（约80%相似），但难以可靠地遵循计划（特别是弱模型只有19%的轨迹基本遵循计划）。因此未来更需要运行时轨迹跟踪和恢复策略。
4. **残差策略失败**：即使所有组件理想化，仍有性能差距（LakeQA上弱模型37.0% SM，强模型76.3% SM）。失败审计显示弱模型问题分散（错误源选择、计划偏离、过早提交、工具阻塞），强模型主要集中在计算执行错误和最终答案合成错误。
5. **瓶颈随基准结构变化**：SANA揭示了不同数据集的结构性差异——LakeQA更强调发现能力，KramaBench更强调分析执行。

## 7. 优点

- **诊断性消融设计**：首次系统性地将EQA失败归因于搜索、规划、数据分析与代理策略四个层面，提供可分解的评估手段。
- **意图对齐的策略**：通过提取工具调用背后的语义意图，避免简单替换导致的评估偏差，更公平地比较不同实现。
- **双基准验证**：在两个规模、结构迥异的数据湖基准上检验了结论的稳健性。
- **失败审计分析**：定性归类失败事件（如计算意图错误、过早提交、工具阻塞等），为改进方向提供具体线索。
- **开源与可复现**：提供了网站和代码仓库，便于社区扩展和使用。

## 8. 不足与局限

- **理想化工具的近似性**：
  - 理想搜索仅限黄金源，可能遗漏其他有效源。
  - 理想数据分析依赖于语义匹配和LLM修复，可能产生误匹配或修复失败。
- **基准覆盖有限**：仅基于LakeQA和转换后的KramaBench，结果不能直接推广到所有EQA设置。
- **依赖LLM评判**：语义匹配、轨迹审计、失败标签均使用LLM作为评判器，可能存在假阳性/假阴性。
- **模型种类单一**：只测试了GPT系列的两个尺寸，未评估其他LLM（如Llama、Qwen等）。
- **预算固定**：30次工具调用限制可能掩盖不同组件在更大预算下的表现差异。
- **KramaBench转换可能引入偏差**：将原始一体化解决方案分解为多跳子问题并非唯一方式，可能存在设计者偏见。
