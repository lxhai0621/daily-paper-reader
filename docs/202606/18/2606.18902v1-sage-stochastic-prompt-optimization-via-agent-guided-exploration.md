## 摘要
情境工程已成为在不更新参数的情况下改进AI系统的主要手段。近期研究表明文本梯度并不像真实梯度那样起作用，这促使我们将自动提示优化视为黑盒搜索。我们提出了SPO（随机提示优化），一种在提示空间上进行随机搜索的框架，并比较了三种复杂度递增的策略：错误信息驱动的随机搜索、带有进化算子的遗传算法，以及SAGE（基于智能体引导探索的SPO），一种具有诊断代码执行的多智能体流水线。在三个基准测试中，没有单一策略占主导地位；有效性取决于景观结构与错误类型的交互作用。我们进一步在持续优化范式下将SAGE部署到一个心理健康聊天机器人上，它将八个单独噪声的A/B测试周期累积为次日留存率的统计显著提升。我们认为，将定性诊断与定量验证相结合，是使智能体优化对开放式任务导向对话有效的关键。

## Abstract
Context engineering has emerged as a primary lever for improving AI systems without parameter updates. Recent work showing that textual gradients do not function as real gradients motivates treating automatic prompt optimization (APO) as black-box search. We introduce SPO (Stochastic Prompt Optimization), a framework for stochastic search over prompt space, and compare three strategies of increasing sophistication: error-informed random search, a genetic algorithm with evolutionary operators, and SAGE (SPO via Agent-Guided Exploration), a multi-agent pipeline with diagnostic code execution. Across three benchmarks, no single strategy dominates; effectiveness depends on the interaction of landscape structure with error type. We further deploy SAGE on a mental-health chatbot under a continuous optimization paradigm, where it compounds eight cycles of individually-noisy A/B tests into a statistically robust gain in next-day retention. We argue that coupling qualitative diagnosis with quantitative validation is what makes agentic optimization effective for open-ended task-oriented dialogue.

### 方法论：核心思想、关键技术细节与算法流程

**1. 核心思想：随机爬山 + 结构化搜索**
- 将APO形式化为一个黑盒随机优化问题，目标是最大化期望奖励。
- 提出SPO（Stochastic Prompt Optimization）框架，采用**随机爬山**算法：每一轮迭代生成Q个候选提示，仅当其中最好候选的性能严格优于当前最优提示时，才进行替换。

**2. 三种搜索策略（关键技术细节）**

- **SPO-RS (误差驱动随机搜索)**：以当前提示及其误差摘要为条件，利用高温度的高维LLM采样生成Q个候选。这是一种简单的、基于随机扰动的搜索，为更复杂的策略提供了基线。
- **SPO-GA (遗传算法)**：维护一个大小为P的种群，通过LLM驱动的交叉（Crossover，结合两个父代提示的优势）和突变（Mutation，针对单一父代的错误模式进行改进）生成候选。这引入了进化算子，在探索和利用之间取得了平衡。
- **SAGE (基于智能体引导的探索)**：**本文的核心贡献**。
    - **架构**：一个多智能体流水线，包含四个角色：**分析器（Analyzer）**、**协调者（Orchestrator）**、**调查者（Investigator）** 和**生成者（Generator）**。
    - **关键技术**：区别于其他方法，SAGE的关键在于**诊断性代码执行（Diagnostic Code Execution）**。智能体被赋予计算工具（文件I/O、Shell、代码搜索），用以编写和执行代码，对全量评估数据进行**程序化分析**（如聚类错误、运行统计检验、识别过度表现的失败模式）。
    - **流程**：1）分析器对所有提示的评估结果进行初步分析，生成多个错误假设；2）协调者对这些假设进行筛选和排序；3）多个调查者并行深入验证每个假设，返回确切的错误计数和推理痕迹分析；4）生成者根据调查结果，生成改进后的提示。这种**假设驱动**的搜索方式，将提示优化从随机扰动转向了基于数据的系统性诊断。

**3. 算法流程（以SAGE为例）**
- **输入**：初始提示 p₀，数据集 D，迭代次数 K。
- **循环 K次**：
    1.  **评估**：用当前最优提示 pk 和候选池中的其他提示对数据集 D 进行评估。
    2.  **诊断（SAGE核心）**：将评估结果（包含错误样本、推理轨迹）提供给SAGE流水线。分析器、协调者、调查者协同工作，通过运行分析脚本和深度代码审查，找出最关键的、可修正的错误模式（如“模型在处理API参数时经常误解数据类型”）。
    3.  **生成候选**：生成者根据诊断出的错误模式和对应的修正策略，提出 Q 个新的候选提示。
    4.  **筛选 & 更新**：用奖励函数评估所有候选和当前最优提示 pk，选择奖励值最高的那个作为 pk₊₁。
- **输出**：优化后的最终提示 pK。

### 不足与局限

- **评估函数依赖**：SPO框架需要自动化的评估函数。对于缺乏清晰正确答案的开放域任务，使用LLM评判或人工评分会引入额外噪声和成本。在心理健康场景中，D1留存率只是临床结局（如症状改善）的代理指标，并非最终目标。
- **分布偏移风险**：持续优化假设当前数据能代表未来用户。但实际上用户群体和行为会随时间演变，性能增益可能衰减。长期运行是否会收敛、震荡或需要重新校准，仍是一个未解决的问题。
- **新颖性受限**：由于SAGE的模式发现完全基于已收集的对话数据，它本质上是**偏向于细化已有行为**，而非引入真正全新的行为。长远来看，更高阶的目标（如持久的心理健康影响）难以通过短期A/B测试验证，且新方向需要外部输入（如专家知识）。

- **伦理考量**：虽然论文指出所有生成的候选提示都经过临床专家审查，且A/B测试包含安全监控和自动回滚，但对涉及弱势用户的部署仍需保持高度警惕。数据隐私和安全协议虽已提及，但其具体实施和长期效果未详细展开。
