## 摘要
生产数据集成受限于数据所有者、工程师和分析师之间重复且有损的信息传递，他们必须协作发现、组织和查询企业数据。我们提出数据智能代理（DIA），一个由三个代理（数据解释器、模式创建器和查询生成器）组成的系统，通过将自主编码代理（ACA）视为一级抽象来压缩这一工作流：代理不再生成文本，而是生成、执行、验证和修复具体工件，利用共享内存进行经验复用，并将每个工件交给领域专家审查。DIA已在企业客户的生产环境中部署。我们深入研究了查询生成器，并在完全自主模式下，跨越四个任务类别和四种方言的七个SQL基准测试中进行了评估。它在所有七个基准测试中达到或超过了最佳已发表结果，表明基于执行、建立在ACA和共享内存之上的架构能够泛化到数据智能工作负载，仅需通过自然语言指令进行适配。

## Abstract
Production data integration is bottlenecked by repeated, lossy handoffs between data owners, engineers, and analysts who must collaboratively discover, structure, and query enterprise data. We present Data Intelligence Agents (DIA), a system of three agents (Data Interpreter, Schema Creator, and Query Generator) that compresses this workflow by treating autonomous coding agents (ACAs) as a first-class abstraction: rather than emitting text, the agents generate, execute, validate, and repair concrete artifacts, draw on a shared memory for experience reuse, and surface each for review by domain experts. DIA is deployed in production for enterprise customers. We study the Query Generator in depth and evaluate it in fully autonomous mode across seven SQL benchmarks spanning four task categories and four dialects. It matches or surpasses the best published results on all seven, demonstrating that an architecture grounded in execution, built on ACAs and a shared memory, generalizes across the data intelligence workload with adaptation confined to natural-language instructions.

## 1. 核心问题与整体含义（研究动机和背景）
- **问题**：企业数据集成过程中，数据所有者（了解字段含义）、工程师（构建和验证数据）和数据分析师（查询数据）之间反复进行**有损的信息传递**（lossy handoffs）。每次交接都会丢失上下文、增加延迟（如误读字段、隐含业务规则导致模式变更、管道重做、查询重写）。
- **动机**：现有系统只处理工作流的片段——管线式 text-to-SQL 链（handcrafted modules，面对任务变化脆弱）、强化学习训练的专用模型（锁定单一方言，需昂贵重训练）、无记忆的探索代理（每次从头开始）、有记忆的 SQL 代理（单一存储且评估狭窄）。它们都输出文本而非可执行工件，且不涉及上游数据理解和模式构建阶段。
- **整体含义**：DIA 通过将**自主编码代理（ACA）** 作为一级抽象，替代一系列专用系统，用一个通用架构覆盖从原始数据到可查询数据库再到回答问题的全流程，实现跨任务和方言的泛化。

## 2. 方法论
### 核心思想
- 以 **ACA**（在沙箱环境中由 LLM 驱动的编码器）为中心，生成、执行、验证和修复**可执行的代码工件**，而非文本。三个代理（Data Interpreter、Schema Creator、Query Generator）在**共享工作空间 W** 中工作，工件作为文件持久化，下游代理直接消费。
- **共享记忆 M**：分为三个层级：
  - **检索示例（Retrieved examples）**：从分离的训练集中嵌入并离线索引，为当前问题提供最相似的 QA 对。
  - **会话教训（Session lessons）**：同一数据库内，代理回答后反思并记录条件规则。
  - **跨会话教训（Cross-session lessons）**：那些在多个数据库上被验证为有效的会话教训被提升为长期规则。
  - 记忆是**拉取式**的，使用时通过实时探测验证前提条件后再应用，避免陈旧经验传播。

### 三个代理的流程
1. **Data Interpreter (I)**：对异构原始数据（CSV/JSON/Excel）执行分析代码，生成结构化解释 **P**（包含列名、语义类型、值分布、空值统计、候选键、连接路径、数据质量问题）。P 是代码推导出的工件，非自然语言描述。
2. **Schema Creator (S)**：根据 P 和原始数据 D，生成并执行加载/验证代码，实现数据库 **(Σ, β)**。采用“先加载后规范化”原则，对每个记录添加来源字段。验证四个维度：行数一致性、列覆盖、键有效性、加载完整性（拒绝缓冲区）。通过一组测试查询后才接受模式。
3. **Query Generator (Q)**：根据自然语言问题 q 和数据库 (Σ, β) 生成并验证 SQL。分四个阶段：
   - **形状声明**：从 q 推导出预期结果形状 κ（列列表、行粒度、排序、过滤条件）。
   - **模式探索**：执行轻量级探测查询，确认连接键、样本值格式、基数假设。
   - **生成与执行**：产生候选查询 y，执行得到结果 R。
   - **自我验证**：用自身指示函数 V(R, κ) 将 R 与声明形状逐项比较（列、行数、顺序、过滤）。若不一致则诊断、修改并重新执行。适配仅限于自然语言指令和任务类别。

## 6. 主要结论与发现
- **查询生成器**在完全自主模式下，**在所有 7 个基准上匹配或超越最佳已发布结果**。最大提升：BIRD-Interact +33.0 点、Spider2-Lite +16.1、BIRD-Critic +15.4、LiveSQLBench +12.7。
- 单一通用代理（一个 LLM，无微调）即可服务四个任务类别和四种方言，仅需自然语言指令适配。
- 结构化任务（如管理类、修改类）表现优于纯查询类，因为任务目标明确且可直接通过执行验证。
- 高难度问题（名称隐含复合指标、需要分解）是主要瓶颈。
- 错误分析表明：**失败原因主要是语义而非语法**，三大类：推理错误（最常见）、输出约定偏离、基础事实接地问题。

## 7. 优点
- **中心抽象创新**：将 ACA 而非 LLM 作为数据智能的中央抽象，生成的工件是可执行、可审查的代码，而非仅文本。
- **共享记忆机制**：三层次记忆（检索示例、会话教训、跨会话教训）使得经验可复用，且通过实时探测验证避免过期知识；记忆写入和升级是训练自由的。
- **执行接地与自验证**：每个阶段都生成并执行代码，自我验证形状声明，将执行错误转化为可修正的反馈循环。
- **广泛覆盖与通用性**：单个系统处理多种自然语言理解任务（生成、调试、对话、项目完成）和多种 SQL 方言，无需专用微调。
- **生产部署成功**：已用于企业客户，提供真实工作流程演示（附录 G 展示护理人员分析助手）。
- **详细的实验分析**：提供深度错误分类、每数据库结果、对话策略分析，透明揭示弱点。

## 8. 不足与局限
- **计算代价高**：每问题在迭代执行环境中运行数分钟，不适合高吞吐或实时交互场景；未报告 token/成本明细。
- **验证局限性**：自我验证基于自身推导的形状，若问题解读错误，查询和验证将共同继承同样的错误，无法捕获语义偏差。
- **评估范围窄**：
  - 只评估了其中一个代理（Query Generator），Data Interpreter 和 Schema Creator 的性能未定量基准。
  - 只使用一个 LLM 型号（Claude Sonnet 4.5），未测试不同模型或资源受限场景。
  - 记忆影响仅定性展示，未做消融或量化。
