## 摘要
检索增强生成系统关键依赖于文档如何被分块和搜索。细粒度分块可以提高检索精度，但会扩大搜索空间，增加延迟和成本；较大的分块减少了候选项数量，但使密集相似度变得不太可靠，因为每个分块的表示混合了多个主题并引入了更多语义噪声。这种权衡在深度研究任务中尤为受限，因为检索必须在大型异构语料库中既快速又精确。我们提出了MCompassRAG，一个元数据引导的检索框架，使用主题级信号作为选择相关证据的语义指南针。MCompassRAG不仅依赖查询与噪声分块嵌入之间的余弦相似度，而是在相同嵌入空间中用主题元数据丰富分块表示，并通过LLM教师蒸馏训练轻量级检索器。在推理时，MCompassRAG执行主题感知检索而无需额外LLM调用，提高了效率和证据质量。在六个复杂的检索基准测试中，MCompassRAG平均提高了8.24%的信息效率，延迟比最强的高效RAG基线降低了5倍以上。代码可在https://github.com/AmirAbaskohi/MCompassRAG获取。

## Abstract
Retrieval-augmented generation (RAG) systems depend critically on how documents are chunked and searched. Fine-grained chunks can improve retrieval precision but expand the search space, increasing latency and cost; larger chunks reduce the number of candidates but make dense similarity less reliable, as the representation for each chunk mixes multiple topics and introduces more semantic noise. This trade-off becomes especially limiting in deep research tasks, where retrieval must be both fast and precise across large, heterogeneous corpora. We introduce MCompassRAG, a metadata-guided retrieval framework that uses topic-level signals as a semantic compass for selecting relevant evidence. Instead of relying only on cosine similarity between queries and noisy chunk embeddings, MCompassRAG enriches chunk representations with topic metadata in the same embedding space and trains a lightweight retriever through LLM-teacher distillation. At inference time, MCompassRAG performs topic-aware retrieval without additional LLM calls, improving both efficiency and evidence quality. Across six complex retrieval benchmarks, MCompassRAG improves information efficiency (IE) by 8.24% on average with over 5 times lower latency than the strongest efficient RAG baselines. Code is available on https://github.com/AmirAbaskohi/MCompassRAG.

#### 1. 核心问题与整体含义（研究动机和背景）

**核心问题**：检索增强生成（RAG）系统的性能关键取决于文档分块和检索策略。当前存在一个难以调和的“粒度权衡”：
*   **细粒度分块**（如句子）：检索精度高，但会导致索引膨胀、搜索空间增大，从而增加延迟和成本。
*   **粗粒度分块**（如段落）：搜索空间小、效率高，但单个块常包含多个主题，其嵌入向量存在“语义噪声”，导致相似度计算不可靠，相关证据被无关内容稀释。

**研究动机**：这种权衡在面向大规模、异构语料库的“深度研究”任务中尤为突出。现有方法（如命题级检索、层级检索、LLM重排序等）虽然能提升质量，但往往增加了预处理成本、额外索引或推理时延迟，无法兼顾高效与高质。

**整体含义**：MCompassRAG 旨在打破这一权衡，通过一种新颖的、轻量级的元数据引导机制，使粗粒度分块在保持高效率的同时，具备近乎细粒度检索的精确度。

#### 2. 方法论：核心思想、关键技术细节

**核心思想**：与其不断优化分块粒度，不如让**粗粒度块更易于搜索**。通过为主题信息构建一个“语义指南针”，引导检索器在混杂的大块中精准定位相关内容。

**关键技术细节**：

1.  **主题元数据生成与索引（离线）**：
    *   使用一个主题模型（论文选用 CEMTM）将语料库中的文档和粗分块（段落级）映射到K个主题的分布向量，并获得每个主题的嵌入中心（`topic centroids`）。
    *   将每个分块的主题分布向量（`θc`）存入一个**元数据银行**，作为检索时的全局语义地图。

2.  **查询侧主题信号提取与抽象（在线推理）**：
    *   **元数据选择**：将用户查询嵌入（`eq`）与元数据银行中的每个条目（`mi`）计算兼容性得分，选出最相关的L个主题分布。
    *   **元数据抽象**：将选出的L个主题分布通过一个轻量级的Transformer编码器进行处理和均值池化，得到一个更平滑、更鲁棒的查询侧主题分布（`ˆθq`），以此减少噪声和单一选择偏差。

3.  **主题增强表示与轻量级检索器**：
    *   **表示增强**：将查询和分块的主题分布与各自的原始文本嵌入（`eq`, `ec`）拼接，形成增强后的表示（`rq`, `rc`）。
    *   **轻量级分类器**：训练一个三层MLP作为学生检索器，输入主题增强的查询-块表示对，输出相关性分数。这将检索任务转化为一个极端多标签分类问题。

4.  **训练：LLM教师蒸馏**：
    *   **数据构建**：使用LLM（GPT-4o）为训练集中的每个分块生成基础查询和扩展查询，以模拟该块是正确答案的上下文。
    *   **教师模型**：LLM根据扩展查询对候选块进行相关性判断，提供硬标签（相关/不相关）和软评分（logits）作为监督。
    *   **学生模型**：学生检索器仅接收基础查询，通过二元交叉熵损失和知识蒸馏损失的组合进行训练。这种不对称性迫使学生在推理时仅通过元数据选择来“猜测”教师所需的背景信息，从而学习到有效的主题感知检索能力。

**算法流程概要（推理时）**：
*   **输入**：用户查询q。
*   **步骤1**：学生编码器生成查询嵌入 `eq`。
*   **步骤2（元数据选择）**：在元数据银行中，为 `eq` 选择最相关的L个主题分布。
*   **步骤3（元数据抽象）**：对选中的主题分布进行抽象，得到一个紧凑的查询侧主题向量 `gq`。
*   **步骤4（表示拼接）**：将 `eq` 和 `gq` 拼接，形成查询的增强表示 `rq`。
*   **步骤5（快速评分）**：MLP分类器一次性评分所有预计算好的块增强表示 `rc`，输出top-k结果。全程无LLM调用。
