## 摘要
为了在真实家庭中长时间协助人类，具身智能体必须记住用户习惯、世界状态和过去的交互。现有的长期记忆基准主要评估以语言为中心的检索和问答，而具身基准通常关注短时域任务执行，不测试动态环境中的长期记忆使用。我们引入了WorldLines，一个面向长期具身家庭辅助的、由项目驱动的基准测试。它构建了时间上扩展的家庭追踪记录，包含对话、动作、执行反馈、物体与设备状态变化，并将其转换为用于记忆问答和具身任务规划的带有证据关联的样本。我们进一步提出了ObsMem，一个基于观察者的记忆框架，它维护可见性感知记忆和动作原生状态轨迹，以支持状态感知的决策。实验揭示了在部分可观测性、被覆盖的世界状态以及将长期记忆转化为具身规划方面持续存在的挑战，而ObsMem为此场景提供了一个更强的参考架构。

## Abstract
To assist humans over extended periods in real homes, embodied agents must remember user routines, world states, and past interactions. Existing long-term memory benchmarks mainly evaluate language-centric retrieval and question answering, while embodied benchmarks often focus on short-horizon task execution without testing long-term memory use in dynamic environments. We introduce WorldLines, a project-driven benchmark for long-horizon embodied household assistance. It constructs temporally extended household traces with dialogues, actions, execution feedback, object and device state changes, and converts them into evidence-linked samples for Memory QA and Embodied Task Planning. We further propose ObsMem, an observer-grounded memory framework that maintains visibility-aware memories and action-native state trails for state-aware decisions. Experiments reveal persistent challenges in partial observability, overwritten world states, and translating long-term memory into embodied plans, while ObsMem offers a stronger reference architecture for this setting.

## 2. 论文提出的方法论

### 2.1 核心思想
- **WorldLines 基准**：通过项目驱动的轨迹生成流水线，构建跨天的家庭活动轨迹（含对话、人类活动、机器人动作、设备操作、状态变化），并将其转换为带有证据链的样本，用于两大任务族：Memory QA（回忆历史事件、状态、偏好）和 Embodied Task Planning（基于可见历史生成与当前状态一致的执行计划）。
- **ObsMem 记忆框架**：面向具身场景，区分**观测来源**（直接观测 vs. 听说），维护四种不同类型的内存视图（事件痕迹、世界状态、信念状态、承诺状态），并在查询时根据问题类型组合证据。

### 2.2 关键技术细节

#### WorldLines 构造流程（流程图图3）
1. **世界基础化**：基于 Habitat/HSSD 家庭场景，定义可交互物体、容器、可控设备，生成语义视图与可执行场景视图。
2. **项目规划**：多天生活项目（如日常习惯、健康饮食、设备协调），指定参与者、空间、实体、时间约束。
3. **闭环轨迹模拟**：每天基于当前世界状态、活跃项目、前序笔记，生成对话、人类活动、机器人动作、设备操作。确定性执行器检查实体、可操作性和前置条件，只有有效的操作才更新状态。
4. **携带记忆**：每天结束后提取事件摘要、状态变更、偏好、未完成计划等，传递到后续天数。
5. **证据链接样本构造**：为每个样本设定截止时间（cutoff），智能体只能看到截止前的历史。问题、参考答案、证据链均由自动化+手动验证生成。

#### ObsMem 框架（图6）
1. **基于观测者的内存摄取**：只有机器人能观测到的事件才进入内存（`observer gate`）。若事件是他人话语，则创建 `reported` 原子；若机器人直接观测，则创建 `observed` 原子。不同来源分别存储。
2. **类型化更新**：
   - **事件痕迹**（Event Track）：只追加，不覆盖。
   - **世界状态**（State Track）：维护当前快照和历史记录（公式2），支持“当前在哪”和“之前在哪”两种查询。
   - **信念状态**（Belief Track）：根据是否直接观测、是否被干预等，标记为 `fresh/stale/uncertain/contradicted`（公式3）。
   - **承诺状态**（Commitment Track）：记录请求、提醒、计划等未来义务。
3. **查询时检索**：根据问题意图（当前状态、过去事件、承诺等），选择对应的内存视图进行检索。证据选择器（LLM-based）选取互补的、跨时间/实体/视图的证据。
4. **情节整合**：检测情节边界，生成情节卡片，进行可选语义合成（摘要、事实原子、关系原子等），但保留原始事件和状态轨迹。

## 6. 论文的主要结论与发现

1. **现有记忆系统在具身长期任务中存在根本缺陷**：难以处理被覆盖的状态（overwritten states）、对部分观测的不确定性建模不足、无法将检索到的长时记忆准确转化为可执行的具身计划。
2. **ObsMem 显著优于所有基线**：在 Judge 分数上比最强基线 A-mem 提升 0.138（0.713 vs 0.575），在事件级召回 Event R@5 上比 Mem0 提升 0.159（0.537 vs 0.378）。尤其是在 StateMultiHop 问题上，事件级召回差距最大（0.452 vs 0.264）。
3. **来源意识（observer-grounded）至关重要**：直接观测与听说的信息应采取不同处理方式，否则会混淆事实。信念跟踪在部分观测场景（hidden-until-observed）中极为关键（Hidden Judge 从 0.278 降至 0.0）。
4. **查询时定向检索优于单一文本相似性搜索**：根据问题类型组合不同内存视图，比泛泛地匹配所有文本更有效。
5. **WorldLines 基准有效区分了会话级召回和事件级召回**：基线在 Session Any@5 上不差，但 Event R@5 明显更低，说明检索到了广泛相关时段却未找到精确证据事件。

## 7. 优点

- **问题定义新颖**：首次将长期记忆维护与具身状态跟踪结合，提出“有状态具身代理”概念，填补了现有基准的空白。
- **基准构造严谨**：通过项目驱动流水线生成跨天轨迹，并设计截止时间、证据链、可执行约束，防止未来信息泄露。人工验证确保样本质量。
- **框架设计巧妙**：ObsMem 区分观测来源、维护类型化视图、进行信念状态更新，直接对应具身场景的核心挑战（部分可观测、状态覆盖、不确定性）。
- **实验分析深入**：不仅报告整体分数，还按问题家族分解，并分析会话级 vs 事件级召回的差异，揭示了平坦文本记忆的局限。
- **消融实验清晰**：每个组件（信念、状态、情节整合、证据选择器）的贡献被量化，尤其证据选择器最为关键（Judge 下降 0.264）。

## 8. 不足与局限

- **模拟环境局限**：WorldLines 基于 Habitat/HSSD 模拟，未包含真实感知噪声、执行误差或开放世界人类行为。证据链和状态变化由程序自动生成，缺乏真实家居中的不确定性。
- **规划样本量少**：仅 21 个规划样本，统计效力有限，可能不足以泛化。
- **ObsMem 依赖结构化信息**：需要实体标识符、可见性注释、动作模式等，实际部署需要感知、定位和基础模块提供这些信号，引入额外错误源。
- **延迟开销**：ObsMem 的检索耗时约 5.13 秒（表10），高于其他方法（3~4.5 秒），且返回记录数更少（3.4 条），可能影响实时交互。
- **未评估跨模态输入**：仅使用文本历史，未涉及视觉观察或语音指令。
- **缺乏真实用户研究**：所有评估为自动或人工评判，未在真实用户场景中测试助手行为的自然性和实用性。
