## 摘要
LLM代理积累的历史记录会超出其上下文窗口，这推动了越来越多的关于记忆系统的研究。然而，现有的大多数设计都针对单一场景（多会话聊天或单轨迹格式）进行了调整，几乎没有证据表明它们能够泛化到代理在部署中遇到的异构轨迹。我们重新审视了八个记忆系统以及一个用于搜索问题的自主工具架（agentic harness），在五个场景上进行了评估：单轮问答、多会话聊天、自主轨迹问答、记忆压力测试和长期自主任务。该工具架通过工具调用自我管理扁平文本文件存储，实现了最佳跨任务排名，这表明记忆性能的关键在于赋予代理对存储和检索的主动控制，而不是在固定管道后面设置被动存储。我们将这一见解实例化为AutoMEM，一个具有自管理工具接口的自主记忆工具架，在我们评估的系统中实现了最佳的跨场景通用性。

## Abstract
LLM agents accumulate histories that outgrow their context windows, motivating a growing literature on memory systems. Yet most existing designs are tuned to a single scenario (multi-session chat or a single trajectory format), and there is little evidence that they generalize across the heterogeneous trajectories agents encounter in deployment. We revisit eight memory systems plus an agentic harness for search problems, on five scenarios: single-turn QA, multi-session chat, agentic-trajectory QA, memory stress tests, and long-horizon agentic tasks. The harness, which self-manages flat text-file storage via tool calls, achieves the best cross-task ranking, suggesting that memory performance hinges on giving the agent active control over storage and retrieval rather than on a passive store behind a fixed pipeline. We instantiate this insight in AutoMEM, an agentic memory harness with a self-managed tool interface that achieves the best cross-scenario generality among the systems we evaluate.

- **研究动机**：大型语言模型（LLM）代理在执行任务时会积累超出上下文窗口的历史信息，因此需要记忆系统。然而，现有记忆系统大多针对单一场景（如多会话聊天或单轨迹格式）调整，缺乏在不同异构轨迹（如多会话聊天、代码交互、浏览器日志等）下的泛化能力。
- **核心问题**：现有记忆系统在跨场景部署时表现不佳，且缺乏系统性的跨场景评估。论文旨在诊断现有系统的失败原因，并探索能实现良好跨场景通用性的记忆设计原则。
- **整体含义**：记忆系统的性能关键不在于固定的被动存储结构，而在于赋予代理对存储和检索的主动控制能力。论文通过实验验证了这一观点，并提出了一个强基线方案 AutoMEM。

### 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：将记忆管理从“被动存储+固定检索管道”转变为“代理主动控制存储与检索”。代理通过工具调用（如 grep、read、dump、index_query）自主决定如何访问和利用记忆，并在查询时根据具体问题动态制定检索策略，避免构建时过早承诺存储模式。
- **关键技术细节**：
  - **DCI-Lite 工具架**：作为基线，将原始轨迹以文本文件存储，代理通过 `grep`（正则匹配）和 `read`（读取文件）工具在查询时进行检索，不预先构建索引。
  - **AutoMEM**：基于 DCI-Lite 的改进方案，采用多步“规划-执行-判断”循环。
    - **动作集**：`rg`（正则搜索记录）、`read`（按ID读取记录）、`dump`（将小型语料直接喂给回答LLM）、`index_query`（对预建索引执行类型查询，默认是基于 LightMem 摘要索引的 Cypher 图）。
    - **算法流程**：每步由规划器LLM生成动作 → 执行器执行 → 判断器LLM检查证据是否充分 → 若不足，返回提示并重新规划；若充分，则回答器生成最终答案。
    - **优化**：KV-cache 友好的聊天布局（提高前缀缓存命中率）；单次通过变体（`Kmax=1`，并行执行所有动作，跳过判断-重规划）。
- **记忆存储**：默认构建一个 Cypher 属性图，来自 LightMem 的写入时摘要索引，边类型包括 `SAID_BY`、`OF_TOPIC`、`FOLLOWS`。也可替换为 PlugMem 的标签/语义/情节存储。

### 6. 论文的主要结论与发现

- **无单方法在任何场景上占优**；DCI-Lite 工具架取得了最佳的跨任务平均排名。
- **索引方法在代理轨迹 QA 上的两种失败模式**：
  - **表示级失败**：构建时模式丢弃了步骤索引和动作标签（如 HippoRAG 的实体-关系图不保存这些信息）。
  - **检索级失败**：尽管存储保留了答案信息（如 PlugMem 的情节存储），但被动检索（基于嵌入相似性或路由）无法可靠地提取细粒度证据。
- **工具架赢在查询时决策**：DCI-Lite 让代理在查询时根据问题本身决定检索方式，避免了构建时冻结模式。
- **索引方法仅在满足两个条件时才有价值**：(1) 模式能表达问题需要的谓词（模式表达能力），(2) 高结构率（许多问题需要跨单元组合）。
- **在动态代理任务上，所有记忆方法无法显著超越长上下文基线**，因为性能瓶颈在于代理的策略（动作后验熵高、状态依赖决策），而非记忆。参数级训练（如 GRPO）才能有效提升。
- **AutoMEM 实现最佳跨场景泛化**：在 LoCoMo 上比 DCI-Lite 提升 22.3 个百分点，比长上下文提升 5.8 个百分点；在全部 12 个基准上平均排名 3.10，优于其他所有方法。

### 7. 优点

- **跨场景全面评估**：涵盖记忆系统典型部署的五大场景，且同时报告准确率、Token 成本和延迟，避免以未见的代价换泛化。
- **深入诊断失败原因**：通过 oracle 可回答性分析、结构率分析、模式表达能力分析，揭示了索引方法失效的根本原因，为后续设计提供了指导。
- **提出简洁有效的强基线**：AutoMEM 设计简单，仅通过工具接口赋予代理主动控制，不依赖复杂训练，但仍取得最佳性能，体现了“主动控制”核心价值。
- **考虑实际部署成本**：不仅关注准确率，还详细分析 Token 消耗、壁钟时间、KV-cache 利用率等，为实际应用选择提供依据。

### 8. 不足与局限

- **缺乏层级预算路由**：AutoMEM 的规划、判断、回答使用同一骨干模型（Qwen3-32B），未利用任务难度差异进行分级（如规划/判断使用小模型），导致成本存在优化空间。

- **实验覆盖有限**：每个基准使用固定子集（如 LoCoMo 200 题），未覆盖全部数据，可能导致抽样偏差。且未在真实部署环境中测试。
- **未考虑安全与隐私**：论文在学术基准上评估，未涉及用户数据安全、访问控制等实际部署问题，这是应用落地的必要前提。
