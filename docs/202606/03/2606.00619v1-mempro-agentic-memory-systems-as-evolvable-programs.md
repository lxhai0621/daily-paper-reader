## 摘要
长周期自主智能体需要记忆系统来保留历史信息、跟踪演化状态并在有限的上下文窗口之外重用相关知识。现有的智能体记忆系统通常遵循记忆构建-检索（MCR）流程，但主要是在部署后调整记忆库，而保持周围的流程固定。这种固定流程的设计难以处理异质的任务特定失败模式，并且可能随着时间的推移与规模和结构都在演化的记忆库失去对齐。为了解决这些限制，我们提出了MemPro，一个系统级演化框架，将整个MCR流程视为一个可进化的程序，而不仅仅是调整记忆库或提示文本。MemPro维护一个可运行记忆系统实现的版本树，其中演化智能体迭代地选择有前途的版本，诊断重复出现的失败，并通过失败模式引导的编辑-调试改进创建改进的子版本。在LongMemEval、LoCoMo、HotpotQA和NarrativeQA上的实验表明，MemPro在几次迭代内始终优于强静态和提示级演化基线，随演化持续改进，并实现了良好的性能-成本权衡。代码可在https://github.com/wanghai673/MemPro获取。

## Abstract
Long-horizon autonomous agents require memory systems to retain historical information, track evolving states, and reuse relevant knowledge beyond finite context windows. Existing agentic memory systems typically follow a memory construction-retrieval (MCR) pipeline, but often adapt mainly the memory bank while keeping the surrounding pipeline fixed after deployment. This fixed-pipeline design struggles to handle heterogeneous task-specific failure modes and can become misaligned with memory banks that evolve in scale and structure over time. To address these limitations, we propose MemPro, a system-level evolution framework that treats the entire MCR pipeline as an evolvable program rather than adapting only the memory bank or prompt text. MemPro maintains a version tree of runnable memory-system implementations, where an Evolving Agent iteratively selects promising versions, diagnoses recurring failures, and creates improved child versions through failure-mode-guided edit-debug refinement. Experiments on LongMemEval, LoCoMo, HotpotQA, and NarrativeQA show that MemPro consistently outperforms strong static and prompt-level evolving baselines within a few iterations, continues to improve with evolution, and achieves a favorable performance-cost trade-off. Code is available at https://github.com/wanghai673/MemPro.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题诊断**：现有智能体记忆系统通常遵循固定的“记忆构建-检索（MCR）”流水线，部署后仅调整记忆库，而保持流水线其他部分（如检索策略、整合逻辑等）不变。这种固定设计导致两个关键缺陷：
  - **任务异构性**：不同长期记忆任务（如时间推理、多会话推理）具有不同的失败模式，固定流水线无法自适应调整。
  - **记忆-流水线错位**：随着记忆库在规模和结构上演化，固定流水线可能不再匹配记忆的组织和使用方式。
- **核心动机**：要实现真正的记忆自我演化，不应只更新记忆库或提示文本，而应将整个MCR流水线视为可进化的程序，使其能够自动诊断失败模式并修改自身执行逻辑。
- **整体含义**：MemPro 提出系统级演化框架，将流水线作为优化对象，通过版本树和故障引导的编辑-调试循环，持续提升智能体记忆系统的泛化能力和鲁棒性。

## 2. 方法论：核心思想、关键技术细节与流程

- **核心思想**：将 MCR 流水线（包含记忆构建、检索、整合、反思等步骤）视为一个可运行的“程序”，通过维护版本树进行系统级演化。
- **关键技术细节**：
  1. **MCR 版本树**：
     - 每个节点 `v` 包含一个可运行流水线实现 `F_v` 及其评估日志 `L_v`（整体得分、类别得分、父节点、总体评估）。
     - 根节点为初始流水线，后续节点由演化智能体通过选择、扩展、评估步骤创建。
  2. **演化智能体（Evolving Agent）**：
     - 使用 `gpt-5.4-medium`（Codex harness），负责选择、诊断、编辑和调试。
     - 每一步有三个子步骤：
       - **选择**：根据评估日志，依据高整体得分、可泛化的改进方向、频繁失败模式等准则，选取最有潜力的父节点。
       - **扩展**：通过迭代的编辑-调试循环生成新版本。
         - **编辑**：根据诊断分析修改流水线（包括提示和可执行代码）。
         - **调试**：选择代表性的失败案例，执行当前版本获取完整轨迹，更新诊断分析（不修改流水线）。
         - **终止**：达到最大迭代次数或智能体判断完成时停止。
       - **评估**：在新版本上运行完整训练集，收集执行轨迹，生成评估日志并加入版本树。
  3. **故障模式引导**：诊断分析基于训练集上的执行轨迹，识别重复出现的失败模式（如时间推理错误、多跳证据遗漏等），指导后续编辑方向。
- **算法流程（文字说明）**：
  - 初始化根节点 `v0`（包含初始 MCR 流水线及评估日志）。
  - 对演化迭代 `ℓ = 1..T`：
    - 收集所有节点日志，选择父节点 `v⋆_ℓ` 并生成诊断分析 `R_ℓ`。
    - 从 `v⋆_ℓ` 复制流水线，进入内层扩展循环：
      - 智能体选择动作（编辑/调试/终止）。
      - 若编辑，根据 `R_ℓ` 修改流水线；若调试，选取诊断案例执行并更新 `R_ℓ`。
    - 终止后，新版本 `u_ℓ` 在训练集上评估，生成日志 `L_{uℓ}`，添加到版本树。

## 6. 主要结论与发现

1. **MemPro 在少次迭代内达到 SOTA**：仅 5 次演化迭代即超越所有非 MemPro 基线（包括静态系统和提示级演化系统）。
2. **持续改进**：随着演化迭代增加（5→10→15），性能持续提升，表明版本树和故障引导机制具有高天花板。
3. **系统级演化优于提示级演化**：去除代码编辑后（w/o Code）性能显著下降（LoCoMo 上下降约 7%），证明编辑可执行代码扩展了优化空间。
4. **版本树优于链式演化**：仅保留最新版本（w/o Version Tree）导致性能下降，分支探索允许从强历史版本继续改进。
5. **所有组件均重要**：消融实验表明代码编辑、版本树、多轮演化、迭代扩展均不可或缺。
6. **性能-成本权衡良好**：MemPro 达到最高准确率的同时，token 成本与 GAM、GEPA 相当，低于 Full Text。
7. **特定类别与骨干相关性**：在 Single-Assistant 类别上，GPT-4o-mini 下表现弱于直接上下文方法，但 Qwen 骨干下表现极佳，表明该差距是骨干特定非本质缺陷。

## 7. 优点

1. **问题定义的创新性**：首次将整个 MCR 流水线视为可演化程序，而非仅记忆库或提示，解决了固定流水线的两大局限。
2. **版本树结构**：允许从强历史版本分支探索，避免线性演化的局部最优，且可保留失败版本的诊断信息。
3. **故障引导的编辑-调试循环**：通过诊断代表性失败案例，高效定位问题，避免全数据集重复评估，降低离线成本。
4. **兼容现有系统**：MemPro 的 MCR 流水线抽象适用于大多数现有记忆系统，可作为通用优化框架。
5. **实验全面性**：覆盖记忆和 QA 两个场景，包含多种数据集、骨干和基线，消融实验设计严谨。
6. **开放性与可复现**：提供开源代码，公开训练集划分和评估协议。

1. **离线演化成本**：演化过程需要在部署前用训练集多次执行流水线，虽然可摊销，但对于大型系统可能成本较高。论文未量化总 GPU 小时数或 API 调用成本。
