## 摘要
跨不同任务部署具有多样化能力的LLM智能体分散化，激发了对跨异构智能体群体知识共享的基础设施需求。正如搜索引擎索引人类生成制品以支持人类问题解决，检索系统可以组织智能体生成制品以供跨群体重用。我们将检索增强生成（展示了人类撰写制品对单个智能体的价值）扩展到检索智能体生成制品以支持智能体群体。特别地，智能体轨迹编码了可重用的程序性知识，然而这些制品通常在使用一次后被丢弃或仅由产生它的智能体保留，迫使新实例化的智能体反复重新发现现有解决方案。我们提出多智能体交互记忆（MATM），一种用于群体级别存储和检索智能体生成轨迹的框架，其中生产者智能体将轨迹贡献到共享仓库，消费者智能体检索它们以改进任务执行。我们关注交互式环境（ALFWorld和WebArena），其中轨迹较长且编码了特别丰富的程序性结构。实验表明，从MATM中检索轨迹可提升下游任务性能并减少交互步骤，无需协调或联合训练。这些结果将MATM定位为开放智能体生态系统中群体级别经验共享的设计模式。

## Abstract
The decentralized deployment of LLM agents with diverse capabilities across diverse tasks motivates infrastructure for knowledge sharing across heterogeneous agent populations. Just as search engines index human-generated artifacts to support human problem solving, retrieval systems can organize agent-generated artifacts for reuse across agent populations. We extend retrieval-augmented generation - which demonstrates the value of human-authored artifacts to individual agents - to retrieval of agent-generated artifacts supporting a population of agents. In particular, agent trajectories encode reusable procedural knowledge, yet these artifacts are typically discarded after a single use or retained only by the producing agent, forcing newly instantiated agents to repeatedly rediscover existing solutions. We propose Multi-Agent Transactive Memory (MATM), a framework for population-level storage and retrieval of agent-generated trajectories, where producer agents contribute trajectories to a shared repository and consumer agents retrieve them to improve task execution. We focus on interactive environments (ALFWorld and WebArena), where trajectories are long and encode especially rich procedural structure. Our experiments demonstrate that retrieving trajectories from MATM improves downstream task performance and reduces interaction steps without coordination or joint training. These results position MATM as a design pattern for population-level experience sharing in open agent ecosystems.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：异构LLM智能体在多样化任务中部署时，缺乏有效的群体级知识共享机制。智能体运行时生成的轨迹（trajectories）包含丰富的程序性知识（procedural knowledge），但这些制品通常在使用一次后被丢弃，或仅由生产该轨迹的智能体本地保留，导致新实例化的智能体必须反复重新发现已有解决方案，造成计算和推理资源的浪费。
- **背景与动机**：
  - 现有检索增强生成（RAG）仅支持智能体检索人类撰写的文档，而智能体生成的制品（如交互轨迹）更适合智能体消费，但目前未被系统化复用。
  - 相关方法如推理复用（Retrieval of Thought、Buffer of Thoughts）、轨迹复用（Synapse、ExpeL）等仅限单个智能体自身，缺乏跨智能体共享；迁移学习、知识蒸馏需要源域和目标域对齐，难以适应异构、动态的智能体群体；集中式多智能体协调方法假设合作场景和共享协议，不适应开放生态。
  - 论文引用Moltbook分析（Li et al., 2026），指出共享社会记忆是智能体社会发展缺失的前提条件。
- **整体含义**：提出一种群体级别的记忆架构——多智能体交互记忆（MATM），使智能体能够贡献和检索彼此的轨迹，实现跨智能体的经验共享，无需联合训练或协调，从而提升整个生态系统的效率与有效性。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
- **MATM框架**：基于“交互记忆”（Transactive Memory, Wegner, 1987）概念，构建一个共享轨迹仓库。生产者智能体（producer agents）在执行任务后贡献轨迹；消费者智能体（consumer agents）在推理时检索相关轨迹以辅助当前任务。角色不互斥，同一智能体在不同上下文中可兼具生产和消费角色。
- **双向市场**：形成生产者-消费者双边市场，轨迹可溯源，支持后续的信任建模和个性化。

### 关键技术细节
- **索引与检索**：
  - 采用**状态条件化键值索引**：以近期交互历史（最近 l 步动作-观察对）加上任务描述作为检索键（key），后续 l 步轨迹作为文档值（value）。
  - 使用共享嵌入函数 f（实验中为E5-Base）编码键，通过密集检索获取候选轨迹片段。
  - 检索器 R 返回排序列表 π，可选择组合初检+重排序。

- **学习排序轨迹（LTRT, Learning to Rank Trajectories）**：
  - 引入轻量级学习排序模型重排初检结果，以更好对齐消费者偏好。
  - 对于每个查询-文档对 (q, d) 提取44维特征，分为六类：
    1. 生产者智能体元数据（如基准分数）
    2. 消费者智能体元数据（如智能体ID）
    3. 初检检索特征（如检索得分）
    4. 查询特征（如查询长度、当前步数）
    5. 轨迹特征（如轨迹长度、成功标志）
    6. 查询-轨迹交互特征（多种文本相似度、嵌入相似度、任务匹配等）
  - 其中生产者元数据用于信任建模，消费者元数据用于个性化。
  - 标签采用**边际效用**（marginal utility）：将该轨迹注入消费者后任务结果与无检索基线之差。
  - 训练三种重排序器：点式前馈神经网络（FFN）、成对LambdaMART、成对SVMRank。

- **记忆构建流程**：
  - **预填充阶段**：从公开轨迹来源（如官方seq2seq模型、GPT-4-Turbo、Claude-3.5-Sonnet等）构建初始索引 D₀。
  - **增量更新阶段**：将训练问题划分为多个分区，每个分区分配给一个生产者智能体（按任务类型分层轮询分配）。智能体先无检索执行任务获得基线轨迹和分数，然后在随机分支点（T个）滚动到该前缀，检索前K个候选轨迹，对选中的排名位置（I = {1,5,10,15,20}）各进行一次单次检索增强生成，记录边际效用标签。成功的轨迹（达到质量阈值）被分割、嵌入后加入索引。
  - 该过程同时产出用于LTRT训练的数据集 S： (q, d, ℓ)，其中 ℓ = s(j) - s_base。

## 3. 实验设计

### 数据集与场景
- **ALFWorld**：基于文本的家居任务环境，使用官方训练集3553集、测试集274集。任务分为6种类型（Pick & Place、Examine in Light、Clean & Place、Heat & Place、Cool & Place、Pick Two & Place）。使用官方train/test划分。
- **WebArena**：网页导航任务环境，共812个任务。论文构建自定义划分：724训练、88测试，保持任务意图分布。测试任务可能与环境布局或网站域重叠，但测试问题本身未被生产者解决过并插入语料库。

### 对比方法
- **无检索基线**：普通LLM（不带检索）
- **MATM + 单阶段密集检索**：仅用E5-Base初检，无重排序
- **MATM + LTRT重排序**：分别用FFN、LambdaMART、SVMRank三种重排序器
- 每个消费者智能体配备**RetrievalPlanner** LLM，决定每一步是否发起检索，避免盲目检索稀释上下文。

### 评价指标
- **任务性能**：成功率（SR）
- **效率**：每集交互步数（# steps）
- **联合指标**：回报配对偏好（RPP, Return-Paired Preference），衡量一个方法相对于基线的Pareto优势（成功且更高效则优先）
- 所有指标报告消费者群体平均值（消费者群体福利）。

## 6. 论文的主要结论与发现

1. **MATM检索提升效果与效率**：在ALFWorld上，单阶段检索使SR从47.1%提升至55.1%（+8%p），步数从11.77降至11.18；在WebArena上SR从18.2%提升至20.5%（+2.3%p），步数从22.0降至20.3。
2. **LTRT重排序进一步改善**：ALFWorld上SVMRank达到64.3%SR，步数降至10.35，RPP升至0.15；WebArena上FFN达到20.5%SR，步数降至19.91。
3. **检索优势分布广泛**：消费者无论从更强还是更弱的生产者处检索均能获益；能力缺口与检索优势相关性弱（相关系数0.03~0.09），表明优势不单纯由强-弱迁移驱动。
4. **跨任务泛化**：跨任务类型检索在ALFWorld上仍达59.9%SR（远高于无检索47.1%），说明轨迹包含跨任务可复用的交互模式。完全检索（全候选池）优于仅限于同任务类型，表明限制候选池会丢失有用交叉候选项。
5. **记忆规模扩展**：ALFWorld上性能随索引大小单调提升；WebArena上步数单调下降，但SR在50%大小处略有下降后回升至最高点（20.9%），表明足够大的索引才能稳定提供高质量匹配。
6. **特征重要性**：生产者基准分数（如SciCode、AAI）和轨迹长度等是重要特征，支持了信任建模的价值。

## 7. 优点

- **新颖的问题定义**：将多智能体知识共享明确为群体级轨迹检索问题，填补了现有RAG和单智能体记忆之间的空白。
- **实用且轻量**：无需联合训练或微调模型，仅通过检索和轻量级重排序提升性能，适合异构、动态的开放生态。
- **设计系统性**：索引方案考虑了状态条件化，使检索能适配当前进展；LTRT特征设计全面，涵盖了信任、个性化、内容相似度等多种信号。
- **实验充分且严谨**：进行了多种消融（检索范围、记忆规模、重排序器对比），分析了能力缺口、特征重要性，并报告了RPP联合指标。
- **开源与可复现**：论文公开了MATM轨迹数据集（HuggingFace）和代码（GitHub），便于后续研究。

## 8. 不足与局限

- **环境覆盖有限**：仅评估了两种交互环境（ALFWorld和WebArena），未涉及更复杂的真实世界任务（如软件工程、连续控制）。
- **LTRT训练偏差**：标签仅从5个固定排名位置采样，未探索所有排名，可能使重排序器对未采样位置的轨迹判别不足。
- **跨benchmark泛化未验证**：在一个环境训练的重排序器未测试在另一环境的效果，无法评估跨任务域的迁移能力。
- **WebArena改进有限**：单阶段检索SR仅有+2.3%p提升，LTRT的FFN仅与单阶段持平；LambdaMART甚至退化为无检索水平，说明该方法对任务结构敏感，鲁棒性不足。
- **未评估生产者福利和安全性**：MATM是双边市场，但论文仅分析消费者侧；未考虑恶意生产者贡献有害轨迹的风险，缺乏信任机制和归因公平性分析。
- **计算成本披露不细**：虽给出总API成本，但未详细说明LTRT训练的计算开销（训练数据量、训练时间等）。
- **未与端到端分布式算法对比**：未与强化学习、元学习等传统跨agent迁移方法对比，定位为设计模式，缺乏与基线方法在相同设定下的直接比较。
- **RetrievalPlanner设计未深入分析**：虽然引入动态检索决策，但未对决策策略进行消融或分析其对最终性能的贡献。
