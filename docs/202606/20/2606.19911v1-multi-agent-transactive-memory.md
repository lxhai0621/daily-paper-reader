## 摘要
将具有不同能力的LLM代理以去中心化方式部署到多样化任务中，促使了为异构代理群体构建知识共享基础设施的需求。正如搜索引擎索引人类生成的工件以支持人类解决问题一样，检索系统可以组织代理生成的工件，以便在代理群体中重用。我们将检索增强生成（该方法证明了人类创作的工件对单个代理的价值）扩展到对支持代理群体的代理生成工件的检索。特别地，代理轨迹编码了可重用的程序性知识，然而这些工件通常在使用一次后被丢弃，或仅由生成代理保留，迫使新实例化的代理反复重新发现现有解决方案。我们提出了多智能体交互式记忆（MATM），一个用于群体级别存储和检索代理生成轨迹的框架，其中生产代理将轨迹贡献到共享存储库，消费代理检索它们以改进任务执行。我们专注于交互环境（ALFWorld和WebArena），其中轨迹较长且编码了特别丰富的程序性结构。我们的实验表明，从MATM中检索轨迹可以提高下游任务性能，并在无需协调或联合训练的情况下减少交互步骤。这些结果将MATM定位为开放代理生态系统中群体级别经验共享的一种设计模式。

## Abstract
The decentralized deployment of LLM agents with diverse capabilities across diverse tasks motivates infrastructure for knowledge sharing across heterogeneous agent populations. Just as search engines index human-generated artifacts to support human problem solving, retrieval systems can organize agent-generated artifacts for reuse across agent populations. We extend retrieval-augmented generation - which demonstrates the value of human-authored artifacts to individual agents - to retrieval of agent-generated artifacts supporting a population of agents. In particular, agent trajectories encode reusable procedural knowledge, yet these artifacts are typically discarded after a single use or retained only by the producing agent, forcing newly instantiated agents to repeatedly rediscover existing solutions. We propose Multi-Agent Transactive Memory (MATM), a framework for population-level storage and retrieval of agent-generated trajectories, where producer agents contribute trajectories to a shared repository and consumer agents retrieve them to improve task execution. We focus on interactive environments (ALFWorld and WebArena), where trajectories are long and encode especially rich procedural structure. Our experiments demonstrate that retrieving trajectories from MATM improves downstream task performance and reduces interaction steps without coordination or joint training. These results position MATM as a design pattern for population-level experience sharing in open agent ecosystems.

## 1. 核心问题与整体含义

- **研究动机**：随着异构LLM智能体在多样化任务中的去中心化部署，群体层面的知识共享基础设施变得至关重要。现有智能体通常在执行任务时生成丰富的轨迹（action-observation序列），这些轨迹编码了可重用的程序性知识，但往往被丢弃或仅由原始智能体私有保存。这导致新智能体不断重复发现已有解决方案，造成计算和探索成本浪费。

- **整体含义**：本文提出**多智能体交互式记忆（Multi-Agent Transactive Memory, MATM）**，受人类群体中的交互式记忆理论启发，构建一个群体级别的共享存储库，让不同智能体既能贡献也能检索轨迹。MATM通过检索增强生成（RAG）范式，将人类生成的文档扩展到智能体生成的工件（如交互轨迹），实现跨智能体的经验复用，无需协调或联合训练，从而提升任务表现和效率。

## 2. 方法论：核心思想、关键技术细节、算法流程

- **核心思想**：将经验数据从私有记忆变为群体共享资源。定义两类角色：**生产者（producer）**贡献轨迹，**消费者（consumer）**检索轨迹辅助自身任务。同一智能体可兼具两种角色。MATM维护一个随时间增长的轨迹索引库，通过检索帮助消费者在当前状态下继续执行任务。

- **关键技术细节**：
  - **索引与检索**：采用状态条件键值方案。对每个交互步骤，以最近l步的历史（含任务描述）为查询键，后续l步的轨迹片段为文档值。共享嵌入函数f（本文使用E5-Base）对所有文本进行编码。
  - **学习排序轨迹（LTRT）**：在初始密集检索（如Top-20）后，引入一个轻量级学习排序（LTR）重排序器，对候选轨迹进行重排。特征设计涵盖六大类（44维）：生产者元数据、消费者元数据、第一阶段检索分、查询特征、轨迹特征、查询-轨迹交互特征。标签使用**边际效用**（注入该轨迹后任务结果减去无检索基线），在增量构建过程中自动收集。
  - **增量构建**：分两阶段：预填充（从公开轨迹初始化索引）和增量更新（处理训练数据过程中，每个问题由分配的生产者先无检索执行获得基线，然后在若干个分支点检索不同排名的轨迹，生成边际效用标签；成功的轨迹被添加回索引）。最终索引包含数万个块。

- **算法流程**（文字说明）：
  (1) 预填充：收集现有公开轨迹，分段、嵌入、构建初始索引D0。
  (2) 增量更新：对每个分区中的每个训练问题：
     - 分配生产者代理An。
     - An先无检索执行得到基线轨迹和分数sbase。
     - 随机选取T个分支点，每个分支点检索当前索引的前K个轨迹块。
     - 依次用不同排名的轨迹块进行one-shot增强生成，得到新轨迹和分数。
     - 计算边际效用s - sbase，形成标签；若轨迹成功则加入缓存。
     - 分区处理完后，将缓存中的轨迹分段、嵌入添加到索引。
  (3) LTRT训练：基于生成的标签数据集训练点级（FFN）、配对级（SVMRank、LambdaMART）重排序器。
