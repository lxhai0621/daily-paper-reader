## 摘要
对话式和使用工具的LLM代理在一个上下文窗口上运行，该窗口同时从多个方向填充。随着会话进行，代理会累积用户和助手轮次、从持久记忆存储中提取的条目，以及通常最大的部分——工具调用的逐字输出，如文件读取、搜索结果和API响应。一旦累积的上下文超过模型的令牌预算，框架必须决定保留什么。

当前的机制是最近截断，有时辅以定期摘要。这是话题盲目的：会话早期建立的事实仅仅因为旧就被丢弃，即使当前用户查询正是关于那个事实；相反，冗长但无关的近期材料却被保留。那些必须在多轮次间回忆信息的代理——记忆的定义性案例——正是最近截断失败的地方。

现有的替代方案位于代理的组装步骤之外。检索增强生成将外部文档提取到提示中，但不仲裁代理\emph{已经存在}的池化上下文。上下文压缩方法通过重写或修剪文本来减少令牌数量，但操作是查询盲目且有损的。这两种方法都没有将记忆条目、对话轮次和工具输出视为一个单一候选池，在提示组装时根据相关性进行选择。

## Abstract
Conversational and tool-using LLM agents operate over a context window that fills from several directions simultaneously. As a session proceeds, the agent accumulates user and assistant turns, entries drawn from a persistent memory store, and often largest of all, the verbatim outputs of tool calls such as file reads, search results, and API responses. Once the cumulative context exceeds the model's token budget, the framework must decide what to keep.   The prevailing mechanism is recency truncation, sometimes paired with periodic summarization. This is topic-blind: a fact established early in a session is discarded simply because it is old, even when the current user query is about exactly that fact; conversely, verbose but irrelevant recent material is retained. Agents that must recall information across many turns, the defining case for memory, are precisely where recency truncation fails.   Existing alternatives sit outside the agent's assembly step. Retrieval augmented generation fetches external documents into the prompt but does not arbitrate the agent's \emph{already-present} pooled context. Context-compression methods reduce token count by rewriting or pruning text, but operate query-blind and lossily. Neither treats memory entries, conversation turns, and tool outputs as a single candidate pool to be selected from by relevance at the moment the prompt is assembled.

## 1. 核心问题与整体含义（研究动机和背景）
- **核心问题**：长时间运行的LLM代理在对话、持久记忆和工具调用输出中积累大量上下文，常常超出模型的令牌预算。现有默认机制是**最近截断**（recency truncation），它会盲目丢弃早期但关键的旧信息，同时保留近期噪声，导致代理在需要跨轮次回忆时性能严重下降。
- **整体含义**：将上下文组装（context assembly）重新定义为**预算约束下的子模选择问题**，通过一个可插拔引擎（PACMS）在提示组装时刻根据当前查询相关性从候选池（记忆、轮次、工具输出）中选取最优子集。这为LLM代理提供了一种有原则、可观测、即时生效的上下文管理方案，显著改善了长期记忆任务的表现。

## 2. 方法论
### 核心思想
- 将候选上下文集合 \( C = \{c_1, \dots, c_n\} \) 视为一个池，结合当前查询 \( q \)、令牌预算 \( B \) 和强制保留集 \( M \)，定义一个**单调子模的设施选址目标函数** \( F(S) = \sum_i \max_{j \in S} w_{ij} \)，其中：
  - 相关性：\( \text{rel}(i,q) = \max(0, \cos(e_i, e_q)) \)
  - 覆盖权重：\( w_{ij} = \text{rel}(i,q) \cdot \max(0, \cos(e_i, e_j)) \)
  - 约束：\( \sum_{j \in S} \text{tok}(j) \le B \)，且 \( M \subseteq S \)
- **选择算法**：使用**CELF懒惰贪心**算法（cost-aware lazy greedy），有常数因子近似保证（\( 1 - 1/e \)）。

### 关键技术细节
- 与MMR的三大区别：
  1. **范围**：MMR的冗余惩罚仅关注已选集内部；PACMS的覆盖项对全池求和，奖励覆盖未覆盖区域的项。
  2. **相关性加权**：PACMS的覆盖权重乘以每个目标项的相关性，只计算覆盖相关区域；MMR的惩罚是纯相似度。
  3. **理论保证**：PACMS目标函数是单调子模，有常数因子贪心保证；MMR是启发式。

### 集成架构
- PACMS作为OpenClaw框架的**可插拔上下文引擎**，实现 `ingest()`、`assemble()`、`compact()` 钩子。assemble() 调用本地FastAPI服务（选择器基于CELF贪心），服务使用本地Ollama生成嵌入并缓存。失败时软回退到最近截断。

### Benchmark

## 6. 主要结论与发现
- **关键发现**：PACMS在**召回率上与MMR相当**（两者均优于last-𝑘，在够预算下超越top-𝑘），但在**端到端QA准确率上比MMR高+8至+12点**（GPT-5-mini: 52% vs 44%；GPT-5.4-mini: 68% vs 56%）。即使在召回率低于top-𝑘时（0.909 vs 0.933），PACMS的QA准确率仍更高（+2/+4点）。
- **含义**：设施选址覆盖目标产生的提示，比MMR的成对多样化或纯相关性排名更易于读者模型提取。召回率与QA准确率之间的背离是论文的核心结论。
- **排序**：PACMS > top-𝑘 > MMR ≥ last-𝑘 在两种读者下均成立。最近截断在强读者下依然无效。

## 7. 优点
- **系统创新**：将上下文组装形式化为有理论保证的子模优化问题，并实现为可插拔引擎，与现有框架松耦合。
- **即插即用**：PACMS上下文引擎可替换OpenClaw中的默认策略，无需修改代理逻辑；接口支持A/B测试。
- **理论与实践结合**：提供常数因子近似保证，同时通过交互式演示可视化选择结果（keep/drop网格、令牌计、预算滑块）。
- **实验设计清晰**：分别报告召回率和QA准确率，揭示两者背离，使结论有说服力。
- **开源承诺**：所有选择器、评估代码和插件开源，便于复现。

## 8. 不足与局限
- **实验覆盖有限**：QA评估只在一个预算（45%）和一个冗余级别（R=2）上进行，缺乏更系统的扫描；召回率实验中QA评估的多样性不足。
