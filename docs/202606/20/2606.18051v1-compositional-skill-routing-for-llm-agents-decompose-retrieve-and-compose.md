## 摘要
LLM代理越来越依赖外部技能——可复用的工具规范——但现实世界的任务通常需要组合多种技能，而不仅仅是选择一种。我们将此形式化为组合技能路由问题：给定一个复杂的用户查询和庞大的技能库，将查询分解为原子性子任务，为每个子任务检索合适的技能，并组合成一个可执行的计划。我们提出了SkillWeaver，一个分解-检索-组合框架，结合了LLM任务分解器、带有FAISS索引的双编码器技能检索器以及依赖感知的有向无环图规划器。为了支持评估，我们引入了CompSkillBench，一个包含300个组合查询的基准测试，这些查询涵盖来自公共MCP生态系统的2,209个真实MCP服务器技能，跨越24个功能类别。我们的实验表明，任务分解质量是主要瓶颈：标准LLM分解在步骤级别仅达到34.2%的类别召回率。为了解决这个问题，我们提出了迭代式技能感知分解（SAD），一种检索增强的反馈循环，迭代地将分解与可用技能对齐。SAD在单次迭代中将分解准确率从51.0%提升到67.7%（+32.7%，Wilcoxon p < 10^-6）；依赖感知条件分析证实，正确的粒度是有效检索的前提（当DA=1时，CatR@1从34%上升到41%）。SkillWeaver将上下文窗口消耗降低了超过99%，迁移实验证实了泛化能力（即使目标类别不在检索池中，相对DA增益也达到+35.6%）。

## Abstract
LLM agents increasingly rely on external skills -- reusable tool specifications -- but real-world tasks often require composing multiple skills, not just selecting one. We formalize this as the Compositional Skill Routing problem: given a complex user query and a large skill library, decompose the query into atomic sub-tasks, retrieve the appropriate skill for each sub-task, and compose an executable plan. We present SkillWeaver, a decompose-retrieve-compose framework combining an LLM task decomposer, a bi-encoder skill retriever with FAISS indexing, and a dependency-aware DAG planner. To support evaluation, we introduce CompSkillBench, a benchmark of 300 compositional queries over 2,209 real MCP server skills spanning 24 functional categories, sourced from the public MCP ecosystem. Our experiments reveal that task decomposition quality is the primary bottleneck: standard LLM decomposition reaches only 34.2% category recall at the step level. To address this, we propose Iterative Skill-Aware Decomposition (SAD), a retrieval-augmented feedback loop that iteratively aligns decomposition with available skills. SAD improves decomposition accuracy from 51.0% to 67.7% (+32.7%, Wilcoxon p < 10^-6) in a single iteration; DA-conditioned analysis confirms that correct granularity is the prerequisite for effective retrieval (CatR@1 rises from 34% to 41% when DA=1). SkillWeaver reduces context window consumption by over 99%, and transfer experiments confirm generalization (+35.6% relative DA gain even when target categories are absent from the retrieval pool).

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：将组合技能路由拆分为三级流水线：① 将用户查询分解为原子性子任务（每个子任务恰需一个技能）；② 对每个子任务检索候选技能；③ 考虑技能间兼容性组合成有向无环图（DAG）执行计划。关键创新在于**迭代技能感知分解（SAD）**：通过检索反馈循环，用技能库中的词汇锚定分解，纠正分解粒度。
- **关键技术细节**：
  - **Stage 1: 任务分解**：使用指令微调的 LLM（Qwen2.5-7B-Instruct）将查询输出为 JSON 字符串数组，每个字符串对应一个原子子任务。
  - **Stage 2: 技能检索**：采用双编码器（all-MiniLM-L6-v2，384 维）对每个子任务进行语义检索，使用 FAISS 索引（IndexFlatIP）在 2,209 个技能中搜索 top-k 候选。对比了仅元数据（名称+描述）和使用完整 body（额外 2000 字符）两种编码方式。
  - **Stage 3: 组合**：根据检索相关性（sim）和跨步骤兼容性（¯c_k）的加权和（α=0.5）选择最终技能，并检测依赖关系构建 DAG。
  - **迭代技能感知分解（SAD）**（算法 1）：
    1. 首轮无提示分解得 D^(0)；
    2. 为每个子任务检索 top-H（H=15）技能形成提示集 H^(i)；
    3. 将提示集加入 prompt 重新分解得 D^(i+1)；
    4. 检查 Jaccard 相似度是否 >τ 判断收敛，默认单次迭代即足够。
  - 优化目标（公式 1）：最大化子任务-技能相关性与技能间兼容性的加权和。

## 3. 实验设计：数据集、基准、对比方法

- **数据集**：构建 **CompSkillBench**，包含 300 个组合查询，技能库为来自公共 MCP 生态系统的 2,209 个真实技能（经清洗、去重、分类后归入 24 个功能类别）。查询分为三个难度级别：Easy（150 个，2 技能 2 类别）、Medium（100 个，3 技能 3 类别）、Hard（50 个，4-5 技能 4-5 类别）。每个查询标注了真值子任务描述、技能 ID、类别和顺序。
- **基准对比方法**：
  - **Vanilla**：标准 LLM 分解（无技能提示） + 双编码器检索。
  - **+SAD (H=15)**：单次迭代技能感知分解。
  - **Iterative SAD**：最多三轮迭代。
  - **LLM-Direct（天花板估计）**：使用更强模型 qwen-max 直接基于 100 个技能名选择，不经过检索。
  - **ReAct-style**：迭代思维-行动-观察代理，无显式分解。
  - 额外消融：步数受限基线（给定真值步数）、跨模型验证（Qwen2.5-14B、qwen-max）、跨数据集（200 个人类风格查询）、跨类别/跨技能迁移测试。

- **评估指标**：

- **分解是瓶颈**：标准 LLM 分解在 2209 技能池上仅达到 CatR@1=34.2%，DA=51.0%；DA 正确的条件下 CatR@1 升至 41.2%，证实步数正确是有效检索的前提。
