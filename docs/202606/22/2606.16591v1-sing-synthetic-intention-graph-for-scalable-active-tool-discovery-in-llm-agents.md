## 摘要
大型语言模型（LLM）智能体越来越依赖管理上下文、工具和多轮执行的智能体框架，使工具成为在真实数字环境中行动的核心接口。随着与框架连接的工具生态系统扩展到数百或数千个API、服务和特定任务技能，穷举式工具模式注入变得代价高昂，并施加了封闭世界假设，将智能体限制在预定义的静态清单中。检索增强的工具选择提供了一种自然的替代方案，但现有的一次性检索方法通常无法将孤立的工具描述与智能体的真实任务意图对齐，尤其是在需要能力通过分解、观察和新诱导的子目标出现的长周期任务中。我们提出SING，一种意图感知的主动工具发现框架，构建了一个连接用户意图、工具能力和工具协作模式的意图-工具图，并根据不断演化的任务状态动态检索工具。使用包含7,471个工具的统一语料库，我们在三个真实世界的工具使用基准上评估了SING。SING在全局召回率@5上相比基线提高了高达59.8%，下游成功率提高了28.9%，同时将全语料工具模式暴露减少了99.8%，证明了意图感知的图结构能够在大规模智能体生态系统中实现更准确和上下文高效的工具发现。

## Abstract
Large language model (LLM) agents increasingly rely on agent harnesses that manage context, tools, and multi-turn execution, making tools a central interface for acting in realistic digital environments. As harness-connected tool ecosystems expand to hundreds or thousands of APIs, services, and task-specific skills, exhaustive tool schema injection becomes costly and imposes a closed-world assumption that limits agents to a predefined static inventory. Retrieval-augmented tool selection offers a natural alternative, but existing one-shot retrieval methods often fail to align isolated tool descriptions with the agent's true task intention, especially in long-horizon tasks where required capabilities emerge through decomposition, observations, and newly induced subgoals. We propose SING, an intention-aware active tool discovery framework that builds an intention-tool graph linking user intentions, tool capabilities, and tool collaboration patterns, and dynamically retrieves tools according to evolving task states. Using a unified corpus of 7,471 tools, we evaluate SING on three real-world tool-use benchmarks. SING improves Global Recall@5 by up to 59.8% and downstream success rate by up to 28.9% over baselines, while reducing full-corpus tool-schema exposure by 99.8%, demonstrating that intention-aware graph structure enables more accurate and context-efficient tool discovery in large-scale agentic ecosystems.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：LLM 智能体越来越依赖外部框架（agent harnesses）来管理上下文、工具和多轮执行。工具是智能体在真实数字环境中行动的核心接口，工具生态系统已扩展到成百上千个 API 和服务。
- **问题**：
  - **穷举式工具模式注入不可持续**：将所有工具 schema 注入上下文会消耗大量预算，引入无关工具，并削弱模型对关键信息的保留（“lost in the middle”问题）。这还隐含了封闭世界假设，只能从预定义静态库存中选择，无法动态适应任务演化。
  - **现有检索方法不足**：一次性检索（one-shot retrieval）仅匹配初始用户话语与孤立工具描述，无法对齐真实任务意图。长期任务中，用户意图常模糊、合成、部分指定，所需能力通过分解、观察和新子目标逐步显现。
- **整体含义**：工具使用必须从被动选择转向主动发现（active discovery），即智能体在执行过程中动态检索相关工具。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：构建一个**意图-工具图**（Intention-Tool Graph），将用户意图、工具能力和工具协作模式显式连接起来，并通过图传播和动态 ReAct 流程实现意图感知的主动工具发现。

- **关键技术细节**：

  1. **意图图构建**（离线）：
     - **查询合成**：对每个工具，从其服务器信息、工具描述和 schema 出发，使用 LLM 生成多个自然语言指令及对应的工具调用参数。通过嵌入相似度过滤冗余，LLM-as-a-judge 过滤低质量样本。
     - **链扩展**：将单工具查询扩展为多工具链条，捕捉工具协作模式。通过类型兼容性判断和 LLM 自然扩展评估，生成更复杂的多步任务。
     - **原子意图提取**：从合成查询和 schema 中提取原子意图（动词-宾语短语），如“地理编码地址到坐标”。语义相似的意图跨工具、跨服务器合并，形成共享意图节点。
     - **图结构**：节点包括服务器、工具、意图。边包括：`has_tool`（服务器→工具）、`has_intention`（工具→意图）、`tool_next`（方向性的工具间协作）、`tool_cooccur`（无向的工具共现）；重复边按频率对数加权。

  2. **动态 ReAct 框架**（在线）：
     - 智能体交替进行推理、发现（DISCOVER）、调用（INVOKE）、响应（RESPOND）。
     - 当选择 DISCOVER 时，将当前状态（用户请求+历史）转换为状态条件的查询 q(j)，通过发现流水线检索新工具 ΔT_j，更新可访问工具集。
     - 当选择 INVOKE 时，执行指定的工具调用并记录观察。

  3. **发现层**（层级检索）：
     - **服务器级发现**：将用户请求分解为全局查询和子任务；结合直接语义匹配（最大嵌入相似度）和意图引导的图传播（PPR，种子为意图节点和语义相关工具节点）。最终服务器分数为加权组合。
     - **工具级发现**：对检索到的服务器内的工具，对每个子任务使用三个信号评分：工具描述匹配、意图匹配、图相关性（PPR 分数）。返回针对各子任务的前 N 个工具，并集为最终发现工具集。

## 6. 主要结论与发现

- **服务器发现准确性**：SING 在所有三个基准的 Global 和 Restricted 设置下均达到最佳性能。Global 设置下，相比 MCP-Zero，Recall@5 相对提升 14.2%~59.8%，MRR 提升约 0.057~0.214。
- **下游任务执行**：SING 在 MCP-Universe 上比 MCP-Zero 成功率提升 8.1~10.1 个百分点（相对 20.8%~28.9%），甚至超过仅提供真实服务器的 Default 设置，说明更聚焦的检索可减少无关工具噪音。
- **成本效率**：SING 将工具 schema 暴露从 693,574 个 token 降至 1,298 个 token（减少 99.8%），使上下文开销几乎与库大小无关。
- **意图感知结构能更好对齐子任务目标**：错误分析表明，SING 主要减少了检索失败；可视化显示工具和意图嵌入局部对齐，支持通过 PPR 进行有效传播。

## 7. 优点

1. **创新性**：提出将用户意图显式建模为图结构，并用于主动工具发现，区别于传统基于描述或命名匹配的方法。
2. **实用性**：在大规模（7k+工具）生态中显著提高检索精度和下游成功率，同时大幅节省 token 成本，有实际部署价值。
3. **动态性**：支持随任务状态演化多次检索，克服了一次性检索的局限性。
4. **层级设计**：服务器级发现→工具级发现的层级结构符合 MCP 的组织特点，降低复杂度。
5. **全面实验**：覆盖三个不同风格的基准以及 Global/Restricted 两种检索难度，并提供了错误分析和成本分析。

## 8. 不足与局限

1. **评估成本**：下游 MCP 评估需要多步智能体交互、真实工具调用和 LLM 评判，成本高昂，因此实验只使用了一组强模型，未探索不同模型家族或骨干网络的影响。
2. **执行可变性**：真实 MCP 工具输出受服务更新、可用性等影响，退一步的检索准确性可能受执行噪声影响。SING 减少了检索失败，但未消除所有变量。
3. **缺失消融实验**：未系统消融图结构组件（如移除意图节点、移除协作边、移除 PPR 等）以验证各自贡献。
