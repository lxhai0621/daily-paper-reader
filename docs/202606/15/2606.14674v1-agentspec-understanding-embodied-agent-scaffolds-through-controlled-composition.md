## 摘要
LLM智能体日益构建为脚手架系统，而非单一模型调用，这些系统结合了推理、记忆、反思、动作执行和学习。虽然此类脚手架通常能提升性能，但它们常嵌入紧耦合的流水线中，使得难以隔离组件贡献、比较替代设计方案或理解模块交互如何塑造智能体行为。我们提出AgentSpec，一个模块化规范框架，将具身智能体表示为具有标准化接口的可复用策略组件的类型化组合。AgentSpec标准化了感知、记忆、推理、反思、动作和可选学习之间的接口，使得组件能够在受控条件下被替换和重组。我们在DeliveryBench、ALFRED、MiniGrid和RoboTHOR上实例化该框架，并跨模型骨干分析推理、记忆、反思和强化学习模块。我们的结果表明，智能体性能由脚手架兼容性和交互效应主导，而非孤立模块强度。特别是，结构化多粒度记忆改进了长程状态跟踪，推理与记忆在不同环境中非均匀交互，反思在修正与成本之间权衡，而RL训练的策略在与部署时脚手架结构共同优化时组合最佳。AgentSpec为研究、比较和设计可组合LLM智能体提供了受控基础。我们的代码、基线和交互式游乐场已公开于https://agentspec-embodied.github.io。

## Abstract
LLM agents are increasingly built not as single model calls, but as scaffolded systems that combine reasoning, memory, reflection, action execution, and learning. While such scaffolds often improve performance, they are often embedded in tightly coupled pipelines, making it difficult to isolate component contributions, compare alternative designs, or understand how module interactions shape agent behavior. We introduce AgentSpec, a modular specification framework that represents embodied agents as typed compositions of reusable policy components with standardized interfaces. AgentSpec standardizes the interfaces among perception, memory, reasoning, reflection, action, and optional learning, enabling components to be swapped and recombined under controlled conditions. We instantiate this framework across DeliveryBench, ALFRED, MiniGrid, and RoboTHOR, and analyze reasoning, memory, reflection, and reinforcement-learning modules across model backbones. Our results show that agent performance is governed by scaffold compatibility and interaction effects rather than isolated module strength. In particular, structured multi-granularity memory improves long-horizon state tracking, reasoning and memory interact non-uniformly across environments, reflection trades off correction and cost, and RL-trained policies compose best when optimized with deployment-time scaffold structure. AgentSpec provides a controlled foundation for studying, comparing, and designing composable LLM agents. Our code, baselines and interactive playground are publicly available at https://agentspec-embodied.github.io.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有的LLM-based具身智能体（embodied agents）通常构建为紧耦合的脚手架系统（scaffolded systems），将推理、记忆、反思、动作执行和学习等模块嵌入同一管线。这种紧耦合设计导致难以隔离单个组件的贡献、难以比较不同设计选择、难以理解模块间的交互效应如何影响整体行为。
- **整体含义**：智能体的性能**不仅仅取决于单个模块的强度，更取决于模块间的兼容性和交互方式**。因此，需要一种受控的模块化框架来系统地研究、比较和设计可组合的LLM智能体。
- **背景**：现有框架（如CoALA、AgentSquare、AgentGym、Voyager、OpenClaw等）虽然提供了一些可复用模块，但它们通常是作为完整系统或针对高性能配置优化的，而非作为可控制的分析平台。AgentSpec旨在填补这一空白。

## 2. 论文提出的方法论：核心思想、关键技术

- **核心思想**：将具身智能体表示为**类型化的可复用策略组件的组合**，并通过**标准化接口**实现模块间的可控替换和重组。
- **关键技术**：
    - AgentSpec定义了一个**Perception–Memory–Reasoning–Reflection–Action**循环，外加可选的**Reinforcement Learning**模块。
    - **Perception**：将异构观测（符号状态、图像、文本等）转换为统一的状态表示（结构化的JSON和文本摘要），供下游模块使用。
    - **Memory**：存储和检索历史信息，包括**情节记忆**（记录具体轨迹、动作序列等）和**语义记忆**（可复用知识如地图、策略、约束）。支持多种记忆范式（检索式、持久引导如动态备忘单、代理上下文工程等）。
    - **Reasoning**：从当前状态和记忆映射到动作提议，支持直接方法（CoT）、交互方法（ReAct）、搜索方法（Tree-of-Thoughts、RAP）等。所有推理方法共享相同接口。
    - **Reflection**：在执行前批评或修订中间决策，支持步骤级反思（Self-Refine）、轨迹级口头反馈（Reflexion）、回顾性分析（Retroformer）。
    - **Action**：将最终决策转换为环境中可执行动作。
    - **RL模块**：可选，支持策略优化方法（如GRPO、SUPO），用于从环境反馈中改进策略。
- **关键设计选择**：**接口控制**——每个模块接收和发出类型化的中间对象，更换一个组件无需重写整个智能体。

## 6. 论文的主要结论与发现

1. **模块兼容性比模块强度更重要**：推理策略与记忆表示必须匹配。例如，结构化、行动导向的记忆（DynamicCheatsheet、MemoryBank）对规划型推理（ReAct、P&S）帮助大，而原始历史记忆（Base、ChatDB）收益小。
2. **受助阶段与记忆粒度相关**：多粒度记忆（MemoryBank同时包含轨迹、摘要和环境洞察）是长程任务中最稳健的默认选择。
3. **环境依赖性**：短程/符号任务（MiniGrid）更依赖单步推理；长程具身任务（DeliveryBench、ALFRED）受限于状态跟踪和轨迹连贯性，记忆贡献更大。
4. **反思是有用的修正层**：Self-Refine在弱推理-记忆组合上增益大，在强组合上增益小，且可防止局部错误累积。
5. **RL训练应与推理时脚手架对齐**：单独训练“裸”策略无法自动利用推理时添加的推理/记忆模块。SUPO（基于轨迹总结）比GRPO更好地与结构化记忆兼容，提示未来应联合优化策略和推理时脚手架。
6. **效率-性能权衡**：性能提升不一定来自更多token或更深思考，轻量但匹配的组合常优于重而不匹配的组合。
7. **模块选择应基于任务的主要失败模式**：推理改善局部决策结构，记忆支持长程状态跟踪，反思帮助修复执行错误。
