## 摘要
长上下文语言建模不仅需要扩展上下文窗口，还需维持对跨数千个token的实体状态和关系的连贯理解——这是仅靠语义相似性无法解决的挑战。KGERMAR通过在推理过程中从输入文本构建动态、上下文特定的知识图谱来解决此问题，实现了利用语义相似性和显式实体关系的领域自适应检索。该框架执行实时实体和关系提取以构建上下文知识图谱，然后通过多组件记忆架构将图结构嵌入与文本语义结合。三个记忆库——上下文、语义和结构——通过学习权重融合检索信号，以捕获表面级语义和更深层的关联模式。在SlimPajama（84.7K训练样本）、WikiText-103（4,358样本）、PG-19（100样本）和Proof-pile（46.3K样本）上评估，KGERMAR在1K到32K token的上下文长度中，与记忆增强基线相比，困惑度降低高达8.5%，记忆效率提升2-2.5倍，并在五个NLU任务中表现出更强的上下文学习能力。动态知识图谱构建方法通过适应输入上下文而非依赖固定知识库，实现了领域特定知识表示，从而推动了记忆增强语言建模的发展。

## Abstract
Long-context language modeling requires not only extending context windows but maintaining coherent understanding of entity states and relationships across thousands of tokens -- a challenge that semantic similarity alone cannot address. KGERMAR addresses this by constructing dynamic, context-specific knowledge graphs from input text during inference, enabling domain-adaptive retrieval that leverages both semantic similarity and explicit entity relationships. The framework performs real-time entity and relation extraction to build contextual knowledge graphs, then integrates graph-structural embeddings with textual semantics through a multi-component memory architecture. Three memory banks -- contextual, semantic, and structural -- are maintained with retrieval signals fused via learned weights to capture both surface-level semantics and deeper relational patterns. Evaluated on SlimPajama (84.7K training examples), WikiText-103 (4,358 examples), PG-19 (100 examples), and Proof-pile (46.3K examples), KGERMAR achieves up to 8.5\% lower perplexity and 2--2.5x better memory efficiency than memory-augmented baselines across context lengths from 1K to 32K tokens, with superior in-context learning performance across five NLU tasks. The dynamic knowledge graph construction approach advances memory-augmented language modeling by enabling domain-specific knowledge representation that adapts to input contexts rather than relying on fixed knowledge bases.

## 2. 论文提出的方法论

- **核心思想**：在推理过程中实时抽取实体和关系，构建领域自适应知识图谱，并通过多组件记忆架构整合上下文、语义和结构信号。
- **关键技术细节**：
  - **动态知识图谱构建**：使用 BERT-large（CoNLL-2003）进行 NER，BERT-base（TACRED）进行关系抽取；实体合并（Levenshtein 距离+嵌入余弦相似度，阈值 0.85/0.90），关系置信度打分（分类器置信度 0.7 + 频率 0.3），过滤低置信度三元组（阈值 0.5）。

  - **多组件记忆架构**：三个记忆库——上下文记忆（token 级键值对，容量 32,768，LRU 淘汰）、语义记忆（BGE-M3 的 256 token 块嵌入，FAISS HNSW 索引）、结构记忆（融合后的图-文本嵌入），分别进行 top-K 检索，最后将得分加权融合（权重 λ₁、λ₂、λ₃ 通过梯度下降学习）。

## 6. 论文的主要结论与发现

- KGERMAR 在困惑度上最高降低 8.5%（WikiText-103 上从 ERMAR 的 7.80 降至 7.14），内存效率提升 2–2.5×（32K token 时峰值内存 14.51 GB vs ERMAR 22.87 GB）。
- 在 ICL 中，4-shot 平均准确率 78.6%（比 ERMAR 高 2.5%），20-shot 平均 81.2%（比 MemLong 高 7.8%），尤其在 Subj、MPQA 这类依赖实体属性区分的任务上优势显著。
- 延迟可控（0.43–0.95 ms/token），且延迟增长近线性（R²=0.98），吞吐量稳定在 1,000 tokens/sec 以上，适合部署。

## 7. 优点

- **方法创新**：首次在推理中动态构建知识图谱用于记忆增强检索，无需预定义知识库，自适应领域内容。
- **记忆架构全面**：三个互补的记忆库（结构 + 语义 + 上下文）使检索信号更丰富，能区分偶然共现和真实实体关系。
- **实验设计严谨**：覆盖多种数据类型（百科全书、书籍、科学文本）、多个上下文长度（1K–32K），提供内存/延迟/吞吐量全面分析。
- **性能与效率兼顾**：相比纯扩展注意力的模型（如 Phi3-128k），KGERMAR 在同等或更低困惑度下内存需求显著更小（适合单 GPU 部署）。

## 8. 不足与局限

- **推理开销**：实时图谱构建导致延迟较高（比 ERMAR 高约 50–100%），虽具有可预测性，但对低延迟场景不友好。
- **关系抽取窗口限制**：固定窗口 W 限制了跨段落关系捕捉，虽靠 R-GCN 多跳传播部分补偿，但可能遗漏长距离结构。
- **NER/RE 模型泛化性**：使用 CoNLL-2003 和 TACRED 训练的模型，在生物医学、法律等专业领域可能降低图质量。
- **缺乏消融实验**：未量化结构记忆、语义记忆、上下文记忆各自贡献，以及不同融合权重的影响。
- **未考虑多语言**：所有实验基于英文，对多语言场景的扩展性未知。
