## 摘要
基于大语言模型构建的层级知识库（即树状结构的维基百科，其节点概括了底层语料库）已成为检索增强应用的主要基础，但其存储层仍被视为实现细节。此类工作负载具有层级性、查询密集且持续演进的特点，而现有存储模型均无法原生同时捕获这三个特性。我们提出WikiKV，一种专为此工作负载设计的路径索引键值存储模型，包含三个组件：(i) 数据驱动架构，通过意图锚定架构归纳启动层级结构，并通过持续演进算子进行优化；(ii) 路径索引存储模型的一致性协议，避免在并发离线重写时出现部分读取（无需读路径加锁）；(iii) 预算约束的导航算子，其搜索加速路由将期望的LLM辅助下降步数从d降至O(1)，同时通过逐步精炼答案保持任意时刻语义。我们通过在微信公众号AI助手上的实际部署评估WikiKV，并在AuthTrace数据集上针对多种基线进行基准测试，结果表明在四个查询算子上，与关系、图和文件系统后端相比，其实现了均衡的低延迟，端到端答案正确率达到63.2%，超过多个RAG基线，且在低扇入和高扇入多文档问题上差距扩大。消融研究进一步证实了WikiKV各组件的有效性。

## Abstract
LLM-curated hierarchical knowledge bases, namely a tree-structured wiki whose nodes summarize an underlying corpus, have become a dominant substrate for retrieval-augmented applications, yet their storage layer is still treated as an implementation detail. This workload is hierarchical, query-intensive, and continuously evolving, and no existing storage model natively captures all three properties at once. We present WikiKV, a path-indexed key-value storage model purpose-built for this workload, comprising three components: (i) a data-driven schema that bootstraps the hierarchy via Intent-Anchored Schema Induction and refines it through Continuous Evolution Operators; (ii) a consistency protocol for the path-indexed storage model that precludes partial-read observations under concurrent offline rewrites without read-path locking; and (iii) a budgeted navigation operator whose search-accelerated routing reduces the expected number of LLM-assisted descent steps from d to O(1) while preserving anytime semantics with progressively refined answers. We evaluate WikiKV through real-world deployment for the WeChat Official Account AI Assistant and benchmark it against diverse baselines on the AuthTrace dataset, where it achieves balanced low per-operator latency across four query operators against relational, graph, and FS backends, and reaches 63.2% end-to-end answer correctness, exceeding multiple RAG baselines, with the gap widening on low- and high-fan-in multi-document questions. Ablation study further confirms the effectiveness of WikiKV's components.

## 2. 论文提出的方法论

### 核心思想
将Wiki的层次结构直接编码到键空间中，使得一次目录列表等价于对目录节点的单点查找（O(1)存储往返）。在此基础上提供：数据驱动模式设计、一致性协议、预算导航算子。

### 关键技术细节

1. **路径作为键编码（Path-as-Key Encoding）**
   - 每个节点的路径π(v)作为逻辑键，物理键为哈希H(π(v))。
   - 五级层次（Index → Dimension → Entity → Digest → Document）压缩到单一自描述命名空间。
   - 目录记录内联子节点列表，使`LS(π)`只需一次点查找。
   - 值记录包含type、name、text、meta（访问计数、置信度等）供模式演化和缓存使用。

2. **数据驱动模式设计**
   - **冷启动-意图锚定模式归纳（IASI）**：从语料样本S中，通过LLM生成焦点、受众、偏置描述P，并生成目录骨架。样本非均匀采样，先滤除低信息文档。
   - **持续演化算子**：
     - `Dimension Merge`：基于互信息（MI），将访问模式高度关联的兄弟维度合并。MI由共存的访问计数估计。
     - `Page Split`：Architect-Critic-Arbiter流程，基于长度或可分离性触发，判定成本变化`fΔC`，安全约束下提交。
   - **内容级错误手册（Error Book）**：检测错误模式并注入后续摄入提示，跨批次持久化。

3. **一致性协议**
   - **写协议（父后子）**：先写子记录（PUT），再更新父目录（UPDATE）。保证读取时不会看到目录已列出但实际不存在的子节点。
   - **读协议（跳过缺失）**：LS获取目录后对每个子节点发起GET，若返回⊥则静默丢弃。
   - **乐观并发控制**：记录有版本号，写前比较，冲突则重试。
   - **多进程并行**：按作者分区，各作者子树无路径冲突，内串行外并行。

4. **预算导航查询算子（NAV(q, B)）**
   - **逐步语义**：结果按粒度递增（Index → Dimension → Entity → Digest → Document），任意前缀都是有效答案。
   - **搜索加速路由**：Phase 1用关键词/前缀搜索SEARCH获得候选路径（O(1)）；Phase 2进行点查找和可选单层展开。通过NEEDS DEEPER判断是否需要深入。
   - **预算守卫**：BUDGET EXHAUSTED在每一步前检查，超时返回已有序列。
   - **三层缓存**：L1进程内缓存（根+维度），L2共享Redis（热实体），L3持久KV。通过失效事件刷新。

### 关键公式与算法

- 模式代价函数：`C(S;W) = α|V| + β∑v depth(v)·ρ(v) − γ Q(S;W)`，约束深度≤D和扇出≤k_max。

- 算法1：NAV执行流程——分类→搜索路由→候选遍历+深度检查+预算检查。

## 6. 论文的主要结论与发现

- **存储延迟**：WikiKV在Q1-Q4四个算子上的延迟均衡，优于FS、PostgreSQL、Neo4j；虽非每个算子最快，但综合表现最好。
- **模式设计**：意图锚定冷启动+连续演化算子显著提升AC（Full 63.2% vs Static 52.5% vs Fixed 53.5%），同时不增加延迟。
- **端到端检索**：WikiKV在AuthTrace上AC达63.2%，超过所有RAG基线（第二名RAPTOR 50.0%），尤其在多文档问题上差距更大（高扇入47.7% vs 30.8%）。
- **生产部署**：平均首令牌延迟6.856秒，其中Wiki工具部分仅0.432秒；人类评分2.86/3，接近“精确命中”。
- **可扩展性**：目录数常数不变（34-35），页面数线性增长但延迟次线性（+9.2%首令牌时间）。
- **消融确认**：移除冷启动采样或搜索路由导致AC大幅下降（分别降10.9和25.4点），验证了组件必要性。
