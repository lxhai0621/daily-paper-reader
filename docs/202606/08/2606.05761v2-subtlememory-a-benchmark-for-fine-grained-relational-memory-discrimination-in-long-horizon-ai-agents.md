## 摘要
持续的AI助手，如OpenClaw，在长期交互中积累了大量相关的记忆。随着这些记忆的增长，它们可能相互加强、在不同上下文中产生分歧或直接冲突，使得正确的辅助依赖于记忆关系而非孤立的回忆。现有的长期记忆基准很少探究智能体在下游任务中如何保留和利用这些关系。为弥合这一差距，我们引入SubtleMemory，一个面向长期运行AI智能体的细粒度关系记忆判别基准。SubtleMemory构建了关系控制的潜在语义伪影，其变体实例化互补、微妙或矛盾的关系，并将它们嵌入到真实的用户-代理历史中，要求智能体在后续查询和指令中恢复分布式的关联结构。该基准包含10个长历史记录中的1,522个评估实例，基于1,090个关系控制的记忆变体集，涵盖用户相关和非用户相关的查询。评估了六个独立记忆系统、两个具有原生记忆模块的Claw式代理和三个具有插件记忆模块的Claw式代理后，我们发现当前系统在细粒度关系记忆判别上仍然薄弱。我们进一步引入诊断协议，揭示了在记忆保留、检索和下游推理阶段的不同能力特征。

## Abstract
Persistent AI assistants, such as OpenClaw, accumulate large collections of related memories over long-term interactions. As these memories grow, they may reinforce one another, diverge across contexts, or directly conflict, making correct assistance depend on memory relations rather than isolated recall. Existing long-term memory benchmarks rarely probe how agents preserve and utilize such relations during downstream tasks. To address this gap, we introduce SubtleMemory, a benchmark for fine-grained relational memory discrimination in long-running AI agents. SubtleMemory constructs relation-controlled latent semantic artifacts whose variants instantiate complementary, nuanced, or contradictory relations, and embeds them into realistic user-agent histories, requiring agents to recover distributed relational structures during later queries and instructions. The benchmark contains 1,522 evaluation instances over 10 long histories, grounded in 1,090 relation-controlled memory-variant sets and spanning user-related and non-user-related queries. Evaluating six standalone memory systems, two Claw-style agents with native memory modules, and three Claw-style agents with plugin memory modules, we find that current systems remain weak on fine-grained relational memory discrimination. We further introduce diagnostic protocols that reveal distinct capability profiles across memory preservation, retrieval, and downstream reasoning stages.

## 2. 方法论：核心思想、技术细节与流程

### 核心思想
- **关系控制的潜在语义伪影**：为每个评估实例定义一个**分辨率目标**和一个**目标条件化语义变体集**，变体之间显式控制为**互补（complementary）**、**微妙（nuanced）**或**矛盾（contradictory）**三种关系。
- 这些变体通过**潜在（latent）**方式嵌入到自然的多轮用户-代理交互会话中，分布在长历史里，要求代理在后续查询中恢复分布式关系结构并正确推理。

### 关键概念
- **语义种子与变体**：种子可以是用户相关事实或非用户事实。对每个种子构造一组语义变体（通过细节丰富、部分遮蔽、语义邻域搜索等操作）。
- **分辨率目标**：一个信息需求，其成功解决需要对累积记忆进行推理（如从先前的交互中识别用户的适用偏好）。
- **潜在语义伪影**：由分辨率目标τ、变体集Vτ和兼容关系类型r(Vτ)组成。
- **关系类型**：
  - **互补**：变体提供互相兼容的证据，应聚合使用。分两类：Multi-evidence（需整合多个）和Any-one（任一个即可）。
  - **微妙**：变体语义相似但需要细粒度区分，取决于临时/上下文线索。分Temporal和Contextual两个子类。
  - **矛盾**：变体不能同时成立，代理必须识别冲突并适当处理（如请求澄清）。

4. **评估实例构建**：生成查询qτ以及参考正确答案集A⁺和错误答案集A⁻。查询需要基于关系推理，用户相关查询使用结构化表单或资源安排任务形式。

## 5. 主要结论与发现

1. **当前系统在细粒度关系记忆判别上普遍较弱**：最强系统（如A-Mem 70.0%）仍落后Oracle（85.4%）超过15个百分点。
2. **矛盾关系最具挑战性**：即使Oracle设定下，gpt-5.4仅达到68.7%，gpt-oss-120b仅41.6%。系统与Oracle的大差距表明存储与推理均有瓶颈。
3. **记忆保留和检索共同决定性能**：瀑布分析显示，如MemoBase保留率低（39.1%）但检索相对高（75.6%），最终准确率低；OpenClaw保留率高（91.5%）但检索低（73.5%），矛盾关系检索率仅34.2%。
4. **保留原始交互有助于记忆保真度**：A-Mem和OpenClaw的高保留率与其保留原始会话的特性有关；MetaClaw偏向技能抽象，保留很差。
5. **微妙关系在检索阶段相对容易**（主要需精细匹配），而互补和矛盾关系需聚合多方证据，检索更困难。
6. **与代理上下文组织的交互并非总是有益的**：表3显示集成OpenClaw系统时，对互补关系可能提升，但对矛盾关系可能下降，且依赖基础模型强度。
