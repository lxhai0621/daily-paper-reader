## 摘要
LLM智能体在真实应用中越来越多地面临长周期任务，如网络搜索和深度研究，其中累积的上下文可能导致长上下文退化及推理失败。先前的工作通过智能体端上下文控制或固定策略（如摘要）进行上下文管理，这需要训练智能体本身以适应——使得对闭源智能体不切实际，且忽略了不同智能体可能需要不同策略。我们提出自适应上下文管理（AdaCoM），它通过灵活的修改动作和端到端强化学习训练一个外部LLM来管理冻结智能体的上下文。在多种智能体及网络搜索和深度研究基准上，AdaCoM通过保留任务约束和进展同时修剪陈旧内容，显著提升了性能。学习到的策略揭示了保真度-可靠性权衡：具有更高原始ReAct性能的智能体受益于更高保真度的上下文保留，而性能较低的智能体需要更激进的压缩以保持在可靠的推理区间内。迁移实验表明，AdaCoM在能力相近的智能体（以原始ReAct性能衡量）之间最有效地泛化，这为智能体系统提供了可复用上下文管理器的实用路径。

## Abstract
LLM agents increasingly face long-horizon tasks such as web search and deep research in real-world applications, where accumulated context can cause long-context degradation and reasoning failures. Prior work mitigates this through context management with agent-side context control or fixed strategies such as summarization, which require training the agent itself for adaptation - making it impractical for closed-source agents and ignoring that different agents may require different strategies. We introduce Adaptive Context Management (AdaCoM), which trains an external LLM to manage the context of a frozen agent through flexible modification actions and end-to-end reinforcement learning. Across diverse agents on web search and deep research benchmarks, AdaCoM substantially improves performance by preserving task constraints and progress while pruning stale content. The learned strategies reveal a Fidelity-Reliability Trade-off: agents with higher vanilla ReAct performance benefit from higher-fidelity context preservation, whereas lower-performing agents require more aggressive compression to stay within a reliable reasoning regime. Transfer experiments show that AdaCoM generalizes most effectively across agents with similar capability (measured by vanilla ReAct performance), suggesting a practical path toward reusable context managers for agent systems.

- **研究动机**：能否在不训练智能体本身的前提下，为每个智能体自动发现其偏好的上下文管理策略？
- **整体含义**：提出自适应上下文管理框架 AdaCoM，通过解耦管理者和被管理智能体，以强化学习训练一个外部 LLM 作为管理器，实现对冻结智能体上下文的灵活、个性化管理，从而提升长周期任务性能。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 核心思想
- **架构解耦**：上下文管理器与任务智能体分离，管理器通常使用较小的 LLM（如 Qwen3-4B-Instruct），智能体保持冻结（无需训练）。
- **操作级灵活性**：管理器可以自由地对上下文中的任意消息执行修改、删除、合并等操作，而不是局限于预定义的摘要操作。

### 2.2 关键技术细节
- **工作流程**（见图 1）：
  1. 在每个智能体步骤前，管理器根据当前上下文（包括问题、历史动作-观测对）生成一个结构化修改动作 `m_t`。
  2. 应用 `m_t` 得到更新后的上下文 `\tilde{c}_t`。
  3. 冻结的智能体基于 `\tilde{c}_t` 生成下一步动作 `a_{t+1}`。
  4. 环境返回观测 `o_{t+1}`，与动作一起追加到上下文，进入下一轮管理器调用。
- **动作空间**：管理器输出一个 JSON 列表，每个元素包含：
  - `ids`：要修改的消息 ID；
  - `role`：新消息的角色（system/user/assistant）；
  - `justification`：修改理由（不传递给智能体）；
  - `new_content`：新内容（空字符串表示删除）。
- **训练方法**：
  1. **SFT 预热**：使用 GPT-5 或 Claude Opus 4.6 生成编辑轨迹，让管理器学习输出格式。
  2. **强化学习（GRPO）**：对每个任务采样多个 rollout，以智能体最终答案的任务奖励作为信号。
  3. **过程奖励设计**：引入多个规则化过程奖励：
     - 超出长度限制 → token 惩罚（-0.8）；
     - 连续重复工具调用 → 冗余动作惩罚（-0.4）；
     - 格式错误 → 格式惩罚（-0.5）；
     - 在 BrowseComp-Plus 中，发现金/关键文档 → 正面奖励（0.6/0.3）。
  4. **两级优势估计**：将任务级优势（基于整体结果归一化）与步骤级优势（基于过程奖励归一化）加权组合后再归一化，提高训练稳定性。

## 6. 论文的主要结论与发现

1. **AdaCoM 显著提升多种智能体性能**：在 BrowseComp-Plus 上平均相对提升 39.0%，在 MCP-Bench-Wiki 上平均提升 15.2%。
2. **学习到的策略揭示“保真度-可靠性权衡”**：强智能体（如 GLM-4.5-Air）的 AdaCoM 保留更多原始上下文（高保真），弱智能体（如 DeepSeek-V3）的 AdaCoM 压缩更激进（高可靠）。每个智能体有一个有效上下文长度，超过则损害推理。
3. **迁移有效性与能力相近性相关**：源管理器在能力相近（以原始 ReAct 性能衡量）的目标 agent 上迁移效果最好，但风格兼容性也会影响迁移质量。
4. **固定摘要策略（SumCoM）不适应所有 agent**：对弱 agent 有帮助，但对强 agent 可能有害，因为后者需要保留更多原始信息。
5. **过程奖励提供了重要的中间监督**：去除过程奖励后两个 agent 性能下降。

## 7. 优点
