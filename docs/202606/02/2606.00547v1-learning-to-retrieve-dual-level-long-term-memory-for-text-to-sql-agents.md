## 摘要
交互式文本到SQL智能体通过多轮交互解决数据库任务，涉及模式探索、查询执行、反馈解释和决策修正。长期记忆有助于智能体重用过往经验，但现有检索方法仍存在局限。静态方法依赖固定的相似性启发式，无法优化下游效用；动态方法通常从稀疏的最终结果中学习，并在单一决策视界内检索记忆。当记忆有用性在不同交互阶段发生变化时，这种方法是无效的，因为初始规划有用的记忆可能与局部、状态条件执行所需的记忆不同。我们提出MERIT，一种动态多视界记忆检索框架。MERIT维护用于全局策略指导的片段级记忆和用于局部决策支持的轮次级记忆。两个层次均使用通过强化学习优化的学习检索策略。为了在有限中间监督下训练轮次级检索，MERIT使用轻量级过程奖励模型为局部记忆选择提供密集代理奖励。在BIRD-Interact上的实验表明，MERIT在成功率上优于无记忆、静态检索和动态检索基线，同时减少了平均交互轮次。在Spider2-Snow上的迁移结果进一步显示了无需基准特定调优即可实现跨基准正迁移。这些结果表明，多视界检索改善了交互式文本到SQL智能体中的经验重用。

## Abstract
Interactive text-to-SQL agents solve database tasks through multi-turn interactions involving schema exploration, query execution, feedback interpretation, and decision revision. Long-term memory helps agents reuse past experiences, but existing retrieval methods remain limited. Static methods rely on fixed similarity heuristics that do not optimize downstream utility, while dynamic methods often learn from sparse final outcomes and retrieve memories at a single decision horizon. This is insufficient when memory usefulness changes across interaction stages, since memories useful for initial planning may differ from those needed for local, state-conditioned execution. We propose MERIT, a dynamic multi-horizon memory retrieval framework. MERIT maintains episode-level memory for global strategic guidance and turn-level memory for local decision support. Both levels use learned retrieval policies optimized with reinforcement learning. To train turn-level retrieval despite limited intermediate supervision, MERIT uses a lightweight Process Reward Model to provide dense proxy rewards for local memory selection. Experiments on BIRD-Interact show that MERIT outperforms no-memory, static-retrieval, and dynamic-retrieval baselines in success rate while reducing average interaction turns. Transfer results on Spider2-Snow further show positive cross-benchmark transfer without benchmark-specific tuning. These results suggest that multi-horizon retrieval improves experience reuse in interactive text-to-SQL agents.

## 1. 论文的核心问题与整体含义（研究动机和背景）

交互式 Text-to-SQL 智能体需要通过多轮交互（模式探索、SQL 执行、反馈解读、决策修正）完成数据库任务，长期记忆有助于重用过往经验。但现有方法存在关键缺陷：

- **静态检索方法**（如 BM25、余弦相似度、主题覆盖）仅依赖固定的相似性启发式，不优化下游任务效用；
- **动态检索方法**（如 Memento、MemRL）虽然从最终结果中学习，但主要在**单一决策视界**（episode 级别）检索，无法适应交互过程中记忆有用性的动态变化——初始规划所需的记忆与局部状态条件下的执行所需记忆往往不同。

因此，论文提出 **MERIT（Multi-horizon mEmory Retrieval using Intermediate and Terminal rewards）**，旨在实现**多视界对齐的记忆检索**，同时提供全局策略指导和局部决策支持。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
将记忆检索问题分解为两个决策视界：
- **Episode-level（场景级）记忆**：在每轮交互开始前检索，提供全局策略指导（如成功计划、常见失败模式）。
- **Turn-level（轮次级）记忆**：在每轮交互中检索，提供基于当前状态的局部提示（如 SQL 调试模式、工具调用选择）。

### 关键技术细节

#### 双级记忆架构
- **Episode-level 记忆**：存储在完整轨迹 `(用户查询, 轨迹, 结果标签, 提炼的洞察)`，键为请求嵌入。
- **Turn-level 记忆**：存储**状态签名**（压缩的当前状态）+ 抽象化动作与观察摘要，键为状态签名嵌入。

#### 两阶段检索流水线
1. **嵌入检索阶段**：余弦相似度获取候选集（每级各 10 个候选）。
2. **学习型选择器阶段**：由 PPO 优化的策略网络从候选中选择至多 1 个记忆注入智能体上下文。

#### 训练信号
- **Episode-level 选择器**：通过终端任务奖励（最终 SQL 正确性）进行 PPO 训练。
- **Turn-level 选择器**：因中间轮次缺乏可靠环境奖励，使用**过程奖励模型（PRM）** 提供密集代理奖励。PRM 对每个状态-记忆对进行结构化效用评估（7 维度评分 + 二元决策 + 文本反馈）。

#### PRM 训练
- 用教师模型（GPT-5）标注状态-记忆对的完整评估模板（SFT + GRPO）。
- GRPO 奖励基于结构化匹配分数（维度分数 Jaccard 相似度、二元决策准确率、文本相似度、格式惩罚）。

## 6. 论文的主要结论与发现

- **MERIT 在成功率上优于所有基线**：在 BIRD-Interact Phase 1 整体成功率 33.01%（对比 No Memory 的 23.33%），Phase 2 达 22.17%（对比 13.17%）。
- **交互轮次减少**：平均轮数 7.84，低于无记忆的 8.93 和动态基线（8.44-8.59）。
- **跨基准正迁移**：在 Spider2-Snow 上成功率 69.29%（优于 No Memory 的 66.00%），平均轮数接近无记忆基线，低于其他记忆方法。
- **双级记忆均贡献显著**：消融中移除 episode 记忆导致最大性能下降（Phase 1 降至 23.50%）；移除 turn 记忆导致成功率下降且轮数增加。
- **RL 优化对 Phase 2 更关键**：移除 RL 后 Phase 2 从 22.17% 降至 19.50%，说明后续状态依赖检索更需要学习。
- **PRM 有效提供密集信号**：SFT+GRPO 训练的 PRM 在效用分数对齐上达 73.59% 准确率，MAE 0.29。

## 7. 优点：方法或实验设计上的亮点

- **多视界对齐**：首次将记忆检索分解为 episode 和 turn 两个视界，匹配交互决策的不同时间尺度。
- **学习型检索优化**：从固定相似性转化为 RL 优化的选择策略，直接最大化下游任务成功。
- **密集奖励机制**：PRM 为中间轮次分配密集代理奖励，解决了稀疏终端奖励下的信用分配难题。
- **轻量高效**：检索选择器仅需 4B 参数 LoRA 微调，token 开销可控。
- **跨基准迁移验证**：展示了所学检索行为的通用性，无需在目标基准上额外调优。
- **消融设计全面**：清晰分离双级记忆和 RL 优化的贡献。

## 8. 不足与局限

- **PRM 依赖教师标注**：训练数据来自 GPT-5 生成的模板，而非真实中间步骤效用标签，存在代理偏差。
- **仅评估强基座模型**：主要智能体为 GPT-5（专有闭源），未验证在开源或较弱推理模型上的性能保持性。
- **记忆组成策略简化为仅用正记忆**：虽在实验中表现更好（表 6），但完全排除失败轨迹可能丢失有用的负面警告信号。
- **检索大小敏感性**：注入过多记忆（>3 个）反而降低性能（图 3b），说明存在冗余/干扰，当前设计未自适应调节。
- **交互环境限制**：仅测试了特定用户模拟器（GPT-4o）和预算设置，泛化性未全面探索。
