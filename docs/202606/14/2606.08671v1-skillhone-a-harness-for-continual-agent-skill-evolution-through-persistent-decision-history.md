## 摘要
智能体技能通过任务特定的程序、脚本和参考扩展了语言模型智能体，但它们所面向的任务和环境持续变化。现有方法在有限运行中改进技能，仅保留最终产物，丢弃了后续智能体解释先前修订、评估和拒绝替代方案所需的决策历史。我们提出SkillHone，一种基于持久决策历史的持续智能体技能演化工具。SkillHone将技能修订与提供实践反馈的评估侧证据配对，记录诊断、修订、证据和结果的结构化历史。角色分离的子智能体在实践探针上运行候选技能，并采用经过编辑的报告，同时基于先前决策提出修订，实现跨会话改进而无需重新发现过去的原理。我们在原始开放网络环境中对SkillHone进行深度研究基准评估，在该环境中智能体没有集成的搜索堆栈，必须通过可移植技能组织检索。我们与由商业检索服务支持的深度研究智能体进行比较。使用Qwen3.6-35B-A3B作为评估时骨干，最终技能在GAIA上超过深度研究智能体15.8分，在WebWalkerQA-EN上超过3.2分，同时超越了先前的技能演化方法。

## Abstract
Agent skills extend language-model agents with task-specific procedures, scripts, and references, but the tasks and environments they target continually change. Existing methods improve skills in bounded runs and retain only the final artifact, discarding the decision history that later agents need to interpret prior revisions, evaluations, and rejected alternatives. We introduce SkillHone, a harness for continual agent skill evolution grounded in persistent decision history. SkillHone pairs skill revisions with evaluation-side evidence that supplies practice feedback, recording structured histories of diagnoses, revisions, evidence, and outcomes. Role-separated subagents run candidate skills on practice probes with redacted reporting and propose revisions informed by prior decisions, enabling cross-session refinement without rediscovering past rationale. We evaluate SkillHone on deep-research benchmarks in a raw open-web setting, where agents are not given an integrated search stack and must organize retrieval through portable skills. We compare against a deep-research agent backed by commercial retrieval services. With Qwen3.6-35B-A3B as the evaluation-time backbone, the resulting skills outperform the deep-research agent by 15.8 points on GAIA and 3.2 points on WebWalkerQA-EN, while also exceeding prior skill-evolution methods.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有智能体技能（skill）进化方法通常将技能视为一次性优化产物（artifact-centered），仅保留最终版本，丢弃了迭代过程中的**决策历史**（包括诊断、候选修订、评估证据、拒绝的替代方案等）。当任务环境变化时，后续智能体无法理解先前修订的动机和依据，容易重复旧修复、撤销有用更改或丢失优化方向。
- **整体含义**：作者指出，长寿命技能需要**持续的维护**，而不仅仅是单轮优化。为此，他们提出 SkillHone 框架，将技能修订与评估证据作为“决策承载单元”持久保存，使后续智能体能够继承完整的演进上下文，实现跨会话的连续改进。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
- **基于持久决策历史的持续技能进化**：将技能开发过程中的每一个步骤记录为结构化决策记录 `h_t = (q_t, r_t, e_t, o_t)`，其中 `q_t` 是诊断，`r_t` 是候选修订，`e_t` 是经过编辑的评估证据，`o_t` 是结果（接受/修订/拒绝/延迟）。所有记录累积形成历史 `H_t = {h_1, ..., h_t}`。
- **角色分离**：优化子智能体（Optimization Subagents）和评估子智能体（Evaluation Subagents）由运行时调度器动态创建，权限分离。优化侧可修改技能仓库，但不能访问未编辑的探针目标、验证器或执行轨迹；评估侧可运行技能并产生编辑报告，但不能修改技能仓库。这防止了评估反馈的直接记忆化。

### 关键技术细节
- **两个仓库**：技能仓库（存储当前技能包 `SKILL.md`、脚本、参考等）和技能评估仓库（存储练习探针、Oracle 目标、验证器、轨迹、编辑报告等）。
- **算法流程（SkillHone）**：
  1. 初始化：初始技能 `S_0`，空决策历史 `H_0`。
  2. 循环迭代（`t = 0` 到 `T-1`）：
     - **评估调度**：运行当前技能 `A(·; S_t)` 在评估仓库上，输出编辑报告 `Ẽ_t`。
     - **优化调度**：检索历史 `H_t`，提出诊断 `q_t` 和修订 `r_t`。
     - **评估调度**：返回针对修订 `r_t` 的证据 `e_t`。
     - **决策**：决定 `o_t ∈ {ACCEPT, REVISE, REJECT, DEFER}`。
     - 若接受，更新技能 `S_{t+1} = APPLY(S_t, r_t)`；否则保持。
     - 记录决策历史 `H_{t+1} = H_t ∪ {(q_t, r_t, e_t, o_t)}`。
  3. 返回最终技能 `S_T` 和完整历史 `H_T`。
