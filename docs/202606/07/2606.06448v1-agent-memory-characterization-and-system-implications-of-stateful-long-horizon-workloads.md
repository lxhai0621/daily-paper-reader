## 摘要
LLM智能体越来越多地部署于需要跨长时间交互历史进行持续推理的长期任务上。规模化实现这一目标要求智能体能够在会话之间持久地存储、检索并更新自身记忆。一个丰富的智能体记忆系统生态系统已经出现，涵盖平面检索、LLM中介抽取、事实存储整合以及自主控制流。然而，其系统级行为尚未得到特征化描述。我们首次对智能体记忆进行系统特征化研究。首先，我们引入一种面向系统的分类法，沿四个轴对智能体记忆系统进行分类。其次，我们构建了一个阶段感知的性能分析框架，将成本归因于构建、检索和生成阶段。第三，我们在两个基准测试套件上对十个代表性系统进行特征化分析，揭示了设计选择如何在写入和读取路径上转移成本。最后，我们推导出10条系统建议，涵盖构建调度、能力下限、通过查询量实现摊销、新鲜度-延迟权衡以及集群规模管理。

## Abstract
LLM agents are increasingly deployed on long-horizon tasks requiring sustained reasoning over extended interaction histories. Realizing this at scale requires agents to persistently store, retrieve, and update their own memory across sessions. A rich ecosystem of agent memory systems has emerged spanning flat retrieval, LLM-mediated extraction, consolidating fact stores, and agentic control flows. Yet, their system-level behavior remains uncharacterized. We present the first systems characterization of agent memory. First, we introduce a system-oriented taxonomy classifying agent memory systems along four axes. Second, we build a phase-aware profiling harness attributing cost to construction, retrieval, and generation. Third, we characterize ten representative systems across two benchmark suites, uncovering how design choices shift cost across the write and read paths. Finally, we derive 10 system recommendations covering construction scheduling, capability floors, amortization via query volume, freshness-latency tradeoffs, and fleet-scale management.

- **核心思想**：通过将智能体记忆执行流水线分解为七个阶段（摄取、记忆构造、存储、检索、提示组装、生成、维护），并沿四个轴（构造机制、存储组织、检索策略、可变性）对系统进行分类，构造**阶段感知分析框架**，将成本归因于三个逻辑阶段：**记忆构造（write path）**、**检索（read path）**、**生成（answer generation）**。
- **关键技术细节**：
  - **四轴分类法**：根据构造方式（无/确定性/LLM中介/自主）、存储格式（原始文本/倒排索引/稠密向量/知识图谱/混合）、检索流水线（单次/多阶段/LLM控制）、可变性（追加/整合/变异）将系统分为四种范式：

## 3. 实验设计：数据集、基准、对比方法
- **基准套件**：
  - **MemoryAgentBench (MAB)**：包含4类任务（准确检索、测试时学习、长距离理解、选择性遗忘），涵盖多个数据集（LongMemEval_S_*, EventQA, BANKING77, InfiniteBench-Sum, FactConsolidation等）。每个样本以4096 token块递增提供，总历史约360K token，60个查询。

- **对比方法**：共10个系统（加上长上下文基线），覆盖所有范式：

## 6. 主要结论与发现
1. **构造成本主导智能体生命周期**：对于LLM中介的记忆系统，构造能耗超过300次查询的总能耗；每正确答案能耗差异达47倍。
2. **构造是预填充和嵌入密集型工作负载**：构造阶段反复读取长块/窗口，输出紧凑记录；中位解码token仅占构造总token的4.6%。嵌入流量按范式分为大批次离线索引（III.a）和顺序逐事件写入（III.b/IV）。
3. **构造LLM选择受算法输出契约约束**：无硬性输出契约的系统（Mem0, SimpleMem, A-Mem）可平滑降级；有严格输出契约的系统（MIRIX）在弱小模型上完全失效。
4. **无单一系统在三轴（构造时间、查询延迟、准确性）同时最优**：BM25在所有MAB数据集上达到最高准确率（55.8%），但查询延迟高于Mem0等。不同范式占据构造-服务-准确率前沿的不同位置。
5. **会话间构造产生新鲜度-延迟权衡**：慢构造系统在异步调度下会累积陈旧记忆，累积构造时间跨五个数量级，是会话间系统选择的主导因素。
6. **存储和token成本增长斜率因范式而异**：自主控制流系统（Letta等）的构造token成本随存储规模超线性增长；整合型系统（Mem0）可压缩存储，但所有系统默认单调增长，需加上遗忘策略。
7. **延迟尾部分布受算法是否由LLM驱动影响**：确定性算法（BM25, embedRAG）的p95/p50约1.3×；LLM绑定系统（GraphRAG, Letta）可达5.9×/3.9×。
