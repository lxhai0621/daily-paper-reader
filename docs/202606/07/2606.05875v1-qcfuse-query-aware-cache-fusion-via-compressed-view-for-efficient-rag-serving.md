## 摘要
检索增强生成（RAG）通过将生成过程基于外部证据来提高大语言模型（LLM）答案质量，但处理检索到的上下文使得预填充阶段成为主要服务成本。RAG缓存融合通过重用已检索块的预计算键值（KV）缓存，并在当前提示下选择性地重新计算令牌来降低这一成本。然而，现有的选择器在质量与效率之间面临困境：快速的查询无关或最终层查询到上下文选择器可能会错过与请求相关的证据，而全视图查询感知选择器要求在重新计算之前具有广泛的上下文和层可见性，从而阻碍了逐层缓存融合管道。我们提出QCFuse，一种用于RAG缓存融合的压缩视图查询感知选择器。QCFuse使用块锚点查询探测来将用户查询状态条件化在紧凑的每块锚点上，并使用关键层剖析来识别重新计算令牌，而无需检查所有层。我们在SGLang中实现了QCFuse，并在六个数据集上对四个开放权重的大语言模型进行了评估。QCFuse达到了完全预填充级别的质量。在匹配质量下，QCFuse实现了平均1.7倍的预填充时间加速，与最强保质量基线ProphetKV相比实现了1.5倍加速。

## Abstract
Retrieval-augmented generation (RAG) improves large language model (LLM) answer quality by grounding generation in external evidence, but processing retrieved contexts makes the prefill stage a dominant serving cost. RAG cache fusion reduces this cost by reusing precomputed key-value (KV) caches for retrieved chunks and selectively recomputing tokens under the current prompt. Existing selectors, however, face a dilemma between quality and efficiency: fast query-agnostic or final-layer query-to-context selectors can miss request-relevant evidence, whereas full-view query-aware selectors require broad context and layer visibility before recomputation and therefore stall the layer-wise cache-fusion pipeline. We present QCFuse, a compressed-view query-aware selector for RAG cache fusion. QCFuse uses chunk-anchor query probing to condition user-query states on compact per-chunk anchors and critical-layer profiling to identify recomputation tokens without all-layer inspection. We implement QCFuse in SGLang and evaluate it on four open-weight LLMs across six datasets. QCFuse reaches full-prefill-level quality. At matched quality, QCFuse achieves an average prefill-time speedup of 1.7x over full prefill and 1.5x over ProphetKV, the strongest quality-preserving baseline.

# QCFuse: 通过压缩视图的查询感知缓存融合实现高效RAG服务

## 1. 论文的核心问题与整体含义

**研究背景与动机**  
在检索增强生成（RAG）系统中，LLM需要处理检索到的外部证据，这导致预填充（prefill）阶段成为主要的服务成本。RAG缓存融合（cache fusion）通过重用预计算的键值（KV）缓存，并选择性地重新计算当前提示下的部分令牌来降低开销。然而，现有选择器面临质量与效率的根本矛盾：
- **查询无关或最终层查询感知选择器**（如CacheBlend、EPIC、FusionRAG）速度快，但容易遗漏请求相关证据，生成质量下降。
- **全视图查询感知选择器**（如ProphetKV）能提供高质量信号，但需要在重计算前加载完整的上下文和所有层的KV缓存，这阻塞了逐层缓存融合流水线，导致延迟增加。

**核心问题**  
如何设计一个既能保持查询感知的高质量令牌选择，又能与流水线缓存融合兼容、不阻塞预填充的高效选择器。

## 2. 论文提出的方法论

**核心思想**  
QCFuse采用**压缩视图**的方式实现查询感知选择，避免全视图带来的加载瓶颈。它通过两个关键技术压缩选择器所需的证据视图：
1. **块锚点查询探测（Chunk-Anchor Query Probing）**：压缩令牌视图。在离线阶段，对每个可重用的语料块选择代表性锚点令牌（如用KVzip方法保留10%锚点），构建紧凑的每块锚点集合。在线服务时，用户查询只在这些锚点上进行条件化（而非全部上下文），从而计算查询感知的注意力分数。
2. **关键层剖析（Critical-Layer Profiling）**：压缩层视图。离线时通过诊断找出最能定位查询相关上下文令牌的关键层（实验中取Top-3中间层）。在线选择时仅使用这些层的注意力信号，避免全层扫描。

**关键技术细节**  
- **选择目标**：给定查询U和检索上下文C，选择一组重计算令牌位置P，使得其覆盖查询相关证据，且满足重计算预算ρ（|P|/N），同时选择器的令牌视图|C_A|和层视图|L*|要足够小，使得选择时间T_select小于全视图选择时间。
- **锚点构建**：对每个块c_i，用KVzip规则（基于自监督重建注意力）在块内选择top-10%的令牌作为锚点。在线拼接成锚点上下文C_A。
- **查询条件化**：用户查询在锚点KV缓存上进行前向传播，得到查询状态Q_U(C_A)，而非在完整上下文上。
- **关键层选择**：用证据导向的校准（Recall@10%指标，覆盖答案跨度）离线选出各模型最关键的top-3层。在线仅加载这些层的全上下文键进行注意力评分，从而得到每个上下文令牌的重要性分数。
- **流水线集成**：选择阶段仅需加载锚点缓存和关键层键，之后进入正常的逐层缓存融合流水线：稀疏重计算（用Triton优化内核）与剩余KV缓存加载重叠进行。

**公式与算法流程（文字说明）**  
- 离线准备：计算每个块的独立KV缓存（PIC）；对每个块用KVzip选择锚点；用SQuAD等跨度标注数据校准，确定关键层集L* = Top-3层。
- 在线执行：
  1. 加载检索块的锚点缓存，拼接成C_A，计算查询状态Q_U(C_A)（仅到关键层中最深一层）。
  2. 加载关键层L*的全上下文键K_PIC，计算注意力分数 I(t) = sum_{l in L*} Attn_l(Q_U(C_A), K_PIC_l)[t]。
  3. 选择top-ρN个令牌构成P。
  4. 进入逐层缓存融合：对每层，加载该层的PIC缓存，用Triton内核只重计算P位置的K/V，与后续层加载重叠。
