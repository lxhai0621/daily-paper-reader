## 摘要
大多数表现最佳的自治数据科学代理依赖于前沿的云模型，并且缺乏持久化的跨会话记忆。本文解决了两个开放空白：（1）形式结构化、质量控制的案例推理（CBR）案例库在耦合符号案例记录与可执行代码工件方面的未充分探索；（2）小型语言模型（SLM）作为本地可部署代理骨干网络的未经测试的可行性。我们提出了CBR增强的研发代理，将持久化CBR层集成到微软的研发代理框架中，并为Gemma 4 31B密集模型提供自定义后端——这是首个公开发表的关于Gemma 4作为自治数据科学代理骨干的端到端评估。CBR层通过一个单一环境变量切换的手术性子类覆盖了研发循环的三个阶段。案例存储为结构化记录，包含可执行代码快照和质量元数据；一个五门质量过滤器和启发式重用检测机制通过组合嵌入相似性、代码指纹重叠和注入来源来评估知识迁移。在两个Kaggle比赛（NOMAD 2018, Spaceship Titanic）上进行了评估，每个比赛使用四个随机种子，每个进行八次改进循环，CBR在Spaceship Titanic上实现了方向性更高的准确性（0.8147对比0.8098，d = -1.41），且方差显著更低。跨108个检索事件的启发式重用检测显示了高语义相关性（平均嵌入相似性0.882）以及可变的结构接近度（平均代码指纹相似性0.305），与概念指导而非逐字代码复制一致。

## Abstract
Most top-performing autonomous data-science agents rely on frontier cloud models and lack persistent, cross-session memory. This paper addresses two open gaps: (1) the underexplored use of formally structured, quality-controlled Case-Based Reasoning (CBR) case bases coupling symbolic case records with executable code artefacts; and (2) the untested viability of Small Language Models (SLMs) as locally deployable agent backbones. We present CBR-augmented R&D-Agent, integrating a persistent CBR layer into Microsoft's R&D-Agent framework with a custom backend for Gemma 4 31B Dense -- the first published end-to-end evaluation of Gemma 4 as an autonomous data-science agent backbone. The CBR layer overrides three R&D loop phases via a surgical subclass toggled by a single environment variable. Cases are stored as structured records with executable code snapshots and quality metadata; a five-gate quality filter and a heuristic reuse-detection mechanism assess knowledge transfer by combining embedding similarity, code-fingerprint overlap, and injection provenance. Evaluated on two Kaggle competitions (NOMAD 2018, Spaceship Titanic) with four seeds over eight improvement loops each, CBR achieves directionally higher accuracy than the CBR-disabled baseline on Spaceship Titanic (0.8147 vs. 0.8098, d = -1.41) with substantially lower variance. Heuristic reuse detection across 108 retrieval events shows high semantic relevance (mean embedding similarity 0.882) alongside variable structural proximity (mean code-fingerprint similarity 0.305), consistent with conceptual guidance rather than verbatim code copying.

- **核心主张**：通过结构化持久案例记忆与本地可部署开放权重模型的组合，可以构建一种透明、可审计、可维护的代理，适合中小型工程团队，而不必依赖前沿云API。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 整体架构
- **基础框架**：采用微软开源的R&D-Agent框架，该框架将一次改进运行组织为迭代的R&D循环（假设生成→代码合成→执行→反馈→隐式保留）。
- **CBR集成方式**：通过一个**手术性子类**覆盖R&D循环的三个阶段（假设生成、代码合成、案例保留），通过单一环境变量即可切换开启/关闭。其余逻辑保持不变。
- **知识库（KB）结构**：每个案例（Case）为结构化记录，包含三部分：
  - **问题签名**：任务类型、数据类型、评估指标与方向、竞赛上下文。
  - **解决方案签名**：假设文本、计划摘要、推断模型族、关键技术、完整代码快照。
  - **案例度量记录**：主度量值、基线值、计算出的改进量。另带有来源字段和每次重用计数器。
- **持久化**：KB持久化为三个磁盘工件：案例元数据文件、代码快照目录（每个案例一个py文件）、序列化向量索引。初始化时进行一致性检查。

### 2.2 检索与上下文注入
- **两阶段检索**：
  - （a）**预检索**：在假设生成前，基于当前场景描述检索以预热嵌入缓存。
  - （b）**后检索**：父级生成假设后，结合假设全文与场景元数据进行第二次检索，得到最多可配置数量的相似案例（嵌入相似度高于阈值）。
- **上下文注入点**：
  - 假设阶段：将检索到的案例和失败模式格式化为结构化Markdown块，写入假设的附录字段。
  - 编码阶段：为每个实验的任务描述追加格式化代码参考部分，包含完整代码快照和元数据头部。同时将CBR参考文档写入实验工作区供CoSTEER子循环访问。

### 2.3 五门质量过滤器（Five-Gate Quality Filter）
决定实验是否保留到KB中：
- **G1**：执行成功检查（扫描日志无运行时错误）。
- **G2**：数值主度量可提取（通过正则别名解析）。
- **G3**：结果优于当前SOTA基线（方向感知）；首次运行时跳过。
- **G4**：新颖性检查——与KB中最邻近案例的嵌入相似度低于去重阈值，除非候选严格优于最邻近。
- **G5**：LLM调用提取模型类型和关键技术，无条件丰富元数据（不拒绝）。

通过G1/G2失败的视为硬失败，转发至失败跟踪器（Failure Tracker）供后续检索警告。G3/G4失败的静默丢弃。

### 2.4 启发式重用检测
每次成功保留后执行：
- **条件**：① 新案例与源案例的嵌入相似度超过检索阈值；② 代码指纹相似度（归一化Jaccard三元组重叠）超过结构阈值。
- **信用归属**：仅对实际注入编码提示的案例计数，排除未注入案例的巧合相似性。
- **结果**：每个案例的重用率存储在KB中，并在检索提示头部显示，给模型提供案例质量信号。

### 2.5 针对Gemma 4 31B的自定义后端
Google AI Studio后端实现了R&D-Agent的LLM接口契约，针对模型缺陷做了两项工程适配：
- **结构化输出支持**：Gemma 4缺乏原生模式约束的结构化输出。补偿方法包括：提示模板注入JSON模式、状态机JSON修复管道（处理转义错误）、原位修复循环、正则去除偶发的思考通道标签。
- **挂起检测与自适应超时**：长上下文编码提示可能引发非终止生成循环。后端通过尾部窗口扫描检测退化输出（连续相同单词），健康注册表维护滚动统计，动态设置有效超时，并设置无活动守卫中止静默挂起。

### 2.6 算法流程（文字说明）
算法1给出单次循环伪代码：
- 输入：场景S、轨迹T、KB、失败跟踪器FT、预算L。
- 输出：更新后的KB、最佳度量m*。
- 循环ℓ从1到L：
  1. **假设生成（CBR覆盖）**：预检索→生成假设→后检索→用上下文丰富假设。
  2. **代码生成（CBR覆盖）**：基于假设和检索到的案例生成实验代码（CoSTEER调试迭代子循环）。
  3. **执行与反馈（不变）**：执行代码，收集结果，LLM质量评判。
  4. **保留（CBR覆盖）**：构建案例→通过质量门→若通过则加入KB并更新重用计数器；否则记录到FT。

## 6. 论文的主要结论与发现

1. **CBR对最终性能的影响竞争依赖**：

## 7. 优点

- **设计目标明确**：针对本地可部署、透明、可审计的代理场景，与前沿云端范式差异化。架构选择（开源模型、磁盘案例存储、最小化CBR集成）均服务于这一目标。
- **工程适配细致**：针对Gemma 4缺乏原生结构化输出的问题，设计了提示模板+状态机修复+原位修复的多级管道；针对SLM长上下文挂起问题，设计了自适应超时和死机检测。这些适配具有实用价值。
- **CBR集成手术化**：通过子类仅覆盖三个阶段，依赖单一环境变量切换，便于A/B对比且不影响上游框架。
- **五门质量过滤器**：系统性地防止低质量、冗余、失败案例污染知识库，同时保留失败模式作为负面引导。
- **启发式重用检测**：从嵌入相似度、代码指纹、注入来源三个维度评估知识转移，尽管非因果，但提供了可解释的代理指标。
- **外部验证**：同时提供了Kaggle公共排行榜和MLE-Bench评分两种外部锚定，增强内部评估可信度。
- **开源**：代码公开在GitHub，支持复现和扩展。

- **可复现性**：虽开源代码，但依赖Google AI Studio API（可能需密钥、配额限制）和Gemma 4模型特定行为，第三方完全复现可能存在障碍。
- **应用限制**：系统设计针对中小型工程团队，不适合大规模组织构建集成化代理管线。论文声明这不是目的。
