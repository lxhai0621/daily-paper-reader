## 摘要
调用外部工具的智能体 AI 系统功能强大但成本高昂，导致开发者默认使用大模型并超支推理预算。模型路由可以缓解这一问题，但现有的路由器是为聊天补全而非工具使用设计的。我们提出了 Switchcraft，据我们所知，这是首个针对智能体工具调用优化的模型路由器。Switchcraft 以内联方式运行，在保证正确性的前提下选择成本最低的模型。我们在五个函数调用基准测试上构建了一个评估框架，并训练了一个在延迟预算下部署的基于 DistilBERT 的分类器。Switchcraft 实现了 82.9% 的准确率——达到或超过了最佳的单个模型——同时将推理成本降低了 84%，每百万次查询可节省超过 3,600 美元。我们发现，在工具使用任务中，大模型并不总是优于小模型，且名义上更便宜的模型由于推理过程中的 Token 密集型计算，可能会产生更高的总成本。我们的工作实现了在不牺牲正确性的情况下进行成本感知的智能体 AI 部署。

## Abstract
Agentic AI systems that invoke external tools are powerful but costly, leading developers to default to large models and overspend inference budgets. Model routing can mitigate this, but existing routers are designed for chat completion rather than tool use. We present Switchcraft, the first (to the best of our knowledge) model router optimized for agentic tool calling. Switchcraft operates inline, selecting the lowest-cost model subject to correctness. We construct an evaluation framework on five function-calling benchmarks and train a DistilBERT-based classifier, deployed under a latency budget. Switchcraft achieves 82.9% accuracy -- matching or exceeding the best individual model -- while reducing inference cost by 84%, saving over $3,600 per million queries. We find that larger models do not consistently outperform smaller ones on tool-use tasks, and that nominally cheaper models can incur higher total cost due to token-intensive reasoning. Our work enables cost-aware agentic AI deployment without sacrificing correctness.

*   **整体含义**：本文提出了 **Switchcraft**，这是首个专门为智能体工具调用优化的模型路由系统。它在保证正确性的前提下，动态地将查询分发给成本最低的模型，从而在不牺牲性能的情况下大幅降低企业级部署成本。

### 2. 方法论
*   **核心思想**：采用“预测-选择”两阶段架构。首先预测哪些模型能正确处理当前查询，然后在预测正确的模型集合中选择成本最低的一个。
*   **关键技术细节**：
    *   **输入表示（Token Packing）**：为了在 DistilBERT 的 512-token 窗口内保留关键信息，系统优先打包：最新用户指令、精简后的工具签名（去除冗余 JSON 描述）、历史对话轮次（逆序排列）以及元数据（对话轮数、工具数量等）。
    *   **改进的 AST 评测框架**：针对现有评测工具（如 BFCL）的偏差，开发了更鲁棒的抽象语法树（AST）检查器。它解决了数组顺序敏感、默认参数缺失、字符串匹配脆弱（如日期格式）以及嵌套结构处理等问题。
    *   **路由逻辑**：
        1.  **多标签分类**：基于 DistilBERT 的分类器为每个候选模型输出正确概率。
        2.  **成本感知选择**：利用“画像成本（Profiled Cost）”模型，根据模型实际产生的 Token 数量（包括推理过程中的 CoT Token）和单价，选择最省钱的正确模型。
    *   **多模型池**：支持包括 GPT-5 系列、Qwen、Kimi 等在内的 8 个不同梯队的模型。

### 3. 实验设计
*   **数据集**：整合了 5 个主流函数调用基准测试：Berkeley Function Calling Leaderboard (BFCL v3)、AWS ConFETTI、Salesforce xLAM-60K、Glaive Function Calling 和 Hermes。总计约 15.7 万条数据。
*   **对比方法（Baselines）**：
    *   **单个 LLM**：8 个候选模型独立运行的表现。
    *   **启发式路由**：基于输入长度、工具数量或对话轮数的简单规则。
    *   **Oracle（先知）**：假设完美预测，始终选择最便宜且正确的模型，作为性能上限。
    *   **聊天路由器**：使用通用聊天数据训练的同架构路由器。

### 4. 资源与算力
*   **训练算力**：使用了 **4 张 NVIDIA A100 (80GB) GPU**。
*   **训练时长**：
    *   DistilBERT：约 50 分钟/种子。
    *   DeBERTa-v3：约 4.5 小时/种子。
    *   ModernBERT：约 6 小时/种子。
    *   总计约 **550 A100 GPU 小时**（用于完成 3 种架构、20 个随机种子的实验）。
*   **推理延迟**：在廉价的 **NVIDIA T4 GPU** 上，DistilBERT 的推理延迟仅为 **3-17ms**，远低于 LLM 的生成延迟。

### 5. 实验数量与充分性
*   **实验规模**：测试集包含 12,282 个样本，涵盖单轮、多轮、并行调用等 14 个子类别。
*   **充分性**：
    *   **稳定性测试**：每个模型运行了 20 个随机种子，证明了结果的鲁棒性。
    *   **消融实验**：验证了 Token Packing 策略（提升 1.66% 准确率）和不同编码器架构的影响。
    *   **数据清洗**：对 ConFETTI 等数据集进行了人工+LLM 辅助的纠错（修正了 27% 的条目），确保了评估的公平性。
    *   **跨模型池验证**：在不同的模型组合（旧版 OpenAI 模型池）上重复实验，结论一致。

### 6. 主要结论与发现
*   **成本效益**：Switchcraft 达到了 **82.9%** 的准确率，匹配了最强单模型（GPT-5.3-chat）的水平，但**成本降低了 84%**（每百万次查询节省约 3630 美元）。
*   **模型悖论**：发现更新、更贵的模型在工具调用上并不总是更好（例如 GPT-5.4 表现不如 GPT-5.3-chat，因为前者更易产生冗余的 CoT 干扰输出）。
*   **“话痨”成本（Chattiness）**：名义单价低的模型如果输出冗余（如 Kimi-K2.5），其实际单次查询成本可能高于单价稍高但输出简洁的模型。
*   **开源差距**：在工具调用任务中，开源模型（Qwen、Kimi）与闭源指令微调模型仍存在明显差距，主要体现在格式违规和拒绝调用上。

### 7. 优点
*   **领域填补**：首次解决了智能体工具调用场景下的模型路由问题。
*   **评测严谨**：改进了 AST 检查器，解决了行业内长期存在的评测偏差问题，对后续研究有重要参考价值。
*   **生产就绪**：路由模型极小（66M 参数），推理延迟极低，非常适合集成到实时生产系统中。
*   **数据质量**：对现有基准测试进行了深度清洗和标准化，实验结果客观可信。

### 8. 不足与局限
*   **Oracle 差距**：距离完美路由（Oracle）仍有约 6.45% 的准确率差距，存在进一步优化空间。
*   **静态模型池**：如果候选模型发生版本更新或新增模型，Switchcraft 需要重新收集数据进行微调。
*   **分布内偏差**：实验主要在已知基准测试的分布内进行，对于完全未知的全新工具集的泛化能力有待进一步验证。
*   **未考虑缓存**：目前的路由逻辑是逐轮进行的，未充分考虑多轮对话中 Prompt Caching 对成本的影响。
