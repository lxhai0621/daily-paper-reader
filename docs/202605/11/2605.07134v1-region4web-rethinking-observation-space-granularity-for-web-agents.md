## 摘要
Web 智能体通过观测空间感知网页，但其粒度一直是一个未被充分研究的设计选择。现有工作将观测处理为与动作空间相同的元素级粒度，使得页面的功能组织保持隐式，并迫使智能体在每一步都从元素级信号中进行推断。我们认为，观测应该在功能区域（即页面中各自服务于不同目的的部分）的粒度上运行。我们提出了 Region4Web 框架，通过层次化分解和语义抽象将 AXTree 重新组织为功能区域，将页面的功能组织作为页面状态理解的基础。此外，我们提出了 PageDigest，这是一种针对 Web 的推理流水线，它将这种区域级观测以紧凑的、跨步骤持久化的每页摘要形式传递给执行智能体。在 WebArena 基准测试中，PageDigest 显著减少了观测长度，同时在各种骨干大语言模型（LLMs）和成熟的智能体方法中提高了整体任务成功率，且与骨干模型的能力无关。这些结果表明，相比于单纯的元素级处理，在功能区域粒度上运行能为执行智能体提供更紧凑且信息更丰富的基础。

## Abstract
Web agents perceive web pages through an observation space, yet its granularity has remained an underexamined design choice. Existing work treats observation at the same element-level granularity as the action space, leaving the page's functional organization implicit and forcing the agent to infer it from element-level signals at every step. We argue observation should instead operate at the granularity of functional regions, parts of the page that each serve a distinct purpose. We propose Region4Web, a framework that reorganizes the AXTree into functional regions through hierarchical decomposition and semantic abstraction, exposing the page's functional organization as the basis for page state understanding. Moreover, we propose PageDigest, a web-specific inference pipeline that delivers this region-level observation to the actor agent as a compact per-page digest that persists across steps. On the WebArena benchmark, PageDigest substantially reduces observation length while improving overall task success rate across diverse backbone large language models (LLMs) and established agent methods, regardless of backbone capacity. These results show that operating at the granularity of functional regions delivers a more compact and informative basis for the actor agent than element-level processing alone.

#### 1. 核心问题与整体含义（研究动机和背景）
现有的 Web 智能体（Web Agents）在感知网页时，通常采用与动作空间相同的**元素级（Element-level）**粒度。这种设计存在两个主要缺陷：
*   **信息隐式化**：网页的功能组织（如导航栏、产品列表、评论区）隐藏在成千上万个底层 HTML/AXTree 元素中，迫使智能体在每一步都要重新推断这些元素之间的逻辑关系。
*   **观测冗余**：完整的页面树通常包含数千个节点，导致上下文窗口压力巨大，且大部分元素与当前任务无关。
论文提出，观测空间应以**功能区域（Functional Regions）**为粒度，将具有共同目的的元素组合在一起，使页面组织显性化，从而提高智能体的理解效率和任务成功率。

#### 2. 方法论：核心思想与关键技术
论文提出了 **Region4Web** 框架及其推理流水线 **PageDigest**：

*   **Region4Web 框架（两阶段处理）**：
    1.  **层次化分解（Hierarchical Decomposition）**：在可访问性树（AXTree）上进行单次自底向上的遍历。通过一个轻量级的边分类器（Edge Classifier）决定父子节点之间是“合并（Merge）”还是“切割（Cut）”。被合并的子树形成独立的功能区域。
    2.  **语义抽象（Semantic Abstraction）**：使用微调的小语言模型（SLM）为每个区域生成两个维度的描述：**目的（Purpose）**（该区域是干什么的）和**状态摘要（State Summary）**（当前区域包含哪些关键信息和可操作上下文）。
*   **PageDigest 推理流水线**：
    *   **任务相关区域选择**：在进入新页面时，利用骨干 LLM 根据区域抽象描述选择与任务相关的区域。
    *   **观测转换管理**：由于网页在操作过程中变化通常很小（分析显示 52.9% 的步骤无变化），PageDigest 仅跟踪增量变化（添加、删除、修改的节点），而不是每步都重新构建完整观测，从而保持观测的紧凑性和连贯性。

*   **兼容性强**：作为观测空间的优化方案，可以无缝接入任何基于文本/AXTree 的 Web Agent。

*   **动态性挑战**：虽然有增量更新机制，但在处理单页应用（SPA）中大规模 DOM 替换时，仍需重新触发完整的 Region4Web 流程。
