Abstract 

The exponential growth of academic publications has created an urgent need for automated tools capable of extracting structured knowledge from unstructured scientific texts. While large language models (LLMs) have demonstrated remarkable capabilities in natural language under-standing and information extraction, existing solutions often require specialized infrastructure, programming expertise, or fine-tuned domain-specific models that create barriers for researchers in specialized fields. This paper presents TCMIIES (Traditional Chinese Medicine Information Intelligent Extraction System), a browser-based, zero-installation platform that leverages com-mercial LLM APIs to perform structured information extraction from academic literature. The system employs a novel schema-guided prompting framework with automatic system prompt generation, enabling researchers to define custom extraction schemas through an intuitive graph-ical interface without any programming. TCMIIES features a pure front-end architecture that ensures data privacy by processing all information locally in the browser, supports five major LLM providers (DeepSeek, OpenAI, Qwen, Zhipu AI, and custom OpenAI-compatible end-points), implements concurrent batch processing with automatic retry mechanisms, and pro-vides intelligent field mapping for Chinese academic databases including CNKI and Wanfang. We demonstrate the system’s effectiveness through comprehensive evaluation across multiple extraction scenarios in Traditional Chinese Medicine research, achieving structured output com-pliance rates exceeding 94% and information extraction accuracy comparable to domain-expert annotation. The system represents a practical, accessible solution that bridges the gap be-tween advanced LLM capabilities and domain-specific academic information extraction needs, particularly for researchers in specialized fields who require flexible, privacy-preserving, and cost-effective extraction tools. 

Keywords: Information Extraction, Large Language Models, Traditional Chinese Medicine, Browser-Based Architecture, Schema-Guided Prompting, Academic Literature Mining 

# 1 Introduction 

The volume of published academic literature continues to grow at an unprecedented rate. As of 2025, major academic databases index over 200 million articles, with approximately 5 million new papers published annually [1]. For researchers conducting systematic reviews, meta-analyses, or domain-wide literature surveys, manually extracting structured information from this vast cor-pus has become increasingly infeasible. This challenge is particularly acute in interdisciplinary fields such as Traditional Chinese Medicine (TCM) informatics, where researchers must synthesize 1

> arXiv:2605.07507v1 [cs.CL] 8 May 2026

evidence spanning classical medical texts, modern clinical studies, pharmacological research, and bioinformatics analyses [2]. Recent advances in large language models (LLMs) have opened new possibilities for automated information extraction from scientific texts. Models such as GPT-4, DeepSeek, Qwen, and GLM-4 have demonstrated strong zero-shot and few-shot capabilities in named entity recognition (NER), relation extraction (RE), and structured data extraction tasks [3,4]. Studies have shown that LLM-based extraction can achieve accuracy approaching that of domain-specific fine-tuned models while maintaining flexibility across diverse extraction schemas and domains [5]. However, significant barriers remain between LLM capabilities and practical adoption by do-main researchers. First, most existing LLM-based extraction tools require programming expertise to set up pipelines, engineer prompts, and process outputs [21]. Second, many solutions involve sending sensitive research data through third-party cloud services or require maintaining backend infrastructure [22]. Third, domain-specific extraction needs vary widely—a pharmacologist extract-ing drug-target interactions has fundamentally different requirements from a clinician extracting treatment outcomes [17]. Finally, researchers in specialized fields such as TCM face additional challenges including non-standardized terminology and the need to process literature from Chinese academic databases with distinct metadata schemas [14]. To address these challenges, we present TCMIIES (Traditional Chinese Medicine Information Intelligent Extraction System), a browser-based, zero-installation platform that democratizes LLM-powered information extraction for academic researchers. The system’s key contributions include: 1. Pure Front-End Architecture: All data processing occurs locally in the browser, eliminating the need for backend servers, software installation, or data transfer through intermediary services. This design ensures data privacy and enables immediate deployment by simply opening an HTML file. 2. Schema-Guided Prompting with Auto-Generation: The system introduces a novel schema-guided prompting framework where researchers define extraction fields through a graphical in-terface, and the system automatically generates optimized system prompts with JSON output constraints, field descriptions, and type specifications. 3. Multi-Provider Support with Provider-Specific Optimizations: TCMIIES supports five major LLM providers with automatic model-specific parameter optimization, including reasoning effort settings for DeepSeek’s advanced models and thinking budget configuration for Qwen models. 4. Intelligent Chinese Database Field Mapping: The system incorporates rule-based column name recognition specifically designed for exports from CNKI (China National Knowledge Infras-tructure) and Wanfang databases, automatically mapping Chinese and English column headers to semantic field categories. 5. Robust Batch Processing: A configurable concurrent processing engine with exponential backoff retry logic, progress persistence via session storage, and real-time progress monitoring enables reliable processing of large literature datasets. The system has been deployed and validated in the TCM Informatics Laboratory at Hebei University, demonstrating practical utility for systematic literature surveys and meta-research in Traditional Chinese Medicine. 22 Related Work 

## 2.1 LLM-Based Information Extraction from Scientific Texts 

The application of LLMs to information extraction (IE) from scientific literature has emerged as a rapidly growing research area. Wei et al. [3] demonstrated that reformulating IE tasks as multi-turn dialogues with ChatGPT achieved competitive performance against fully supervised baselines on standard NER and RE benchmarks. Dagdelen et al. [4] showed that fine-tuned LLMs (GPT-3, Llama-2) could jointly perform NER and RE on materials science texts, outputting structured JSON records from single sentences or entire paragraphs, achieving flexible extraction without task-specific model architectures. Recent work has explored various prompting strategies for improving extraction quality. Wang et al. [5] proposed schema-guided prompting, where explicit field names, types, descriptions, and constraints are provided in the prompt, reducing hallucination by 40% and improving structured output compliance from 82% to 97%. Ho et al. [6] demonstrated that chain-of-thought (CoT) prompting improved accuracy by 8–15% on complex IE tasks requiring multi-step reasoning. White et al. [7] catalogued 12 prompt design patterns for scientific text extraction and found that combining JSON schema specification with few-shot examples and output validation instructions improved F1 scores by 15–20% over naive zero-shot prompting. Multi-agent and hybrid approaches have also shown promise. Park et al. [8] proposed a multi-agent framework where specialized LLM agents handle different aspects of extraction, achieving 91.3% F1 on complex scientific IE benchmarks. Phi et al. [9] demonstrated a hybrid pipeline combining LLM table-to-text conversion with specialized text-based extraction models, significantly outperforming direct LLM extraction approaches. 

## 2.2 Automated Literature Review and Evidence Synthesis 

The automation of systematic literature reviews has received substantial attention. Wallace et al. [10] developed an end-to-end pipeline for automated systematic reviews, where LLM-based screening achieved 95.2% sensitivity for study inclusion, comparable to human reviewers. Van Dijk et al. [11] demonstrated that multi-step extraction pipelines (identify relevant sections, ex-tract target information, validate) improved accuracy from 76% to 89% compared to single-prompt approaches, while reducing hallucination rates from 12% to 3% through self-consistency checking. For literature mapping and knowledge graph construction, Zhang et al. [12] proposed KG-LLM, a framework achieving 84.7% precision on biomedical knowledge graph construction through entity recognition, relation extraction, and multi-source fact verification. Baek et al. [13] combined citation network analysis with LLM-based summarization to generate structured literature reviews rated as “good” or “excellent” by domain experts 72% of the time. 

## 2.3 Domain-Specific IE in Traditional Chinese Medicine 

Information extraction for TCM presents unique challenges due to specialized terminology, classical Chinese language patterns, and conceptual frameworks that differ from Western medicine [2]. Wang et al. [14] developed TCM-NER using a BERT-BiLSTM-CRF architecture fine-tuned on annotated TCM corpora, achieving 89.3% F1 on entity recognition tasks including herbal medicines, prescrip-tions, symptoms, and acupoints. Li et al. [15] created BERT4TCM through continued pre-training on a 200M-character TCM corpus, outperforming general Chinese BERT by 6–12% on downstream TCM tasks. 3Zhang et al. [16] evaluated GPT-4, Claude, and Qwen on TCM-specific extraction tasks, finding 83% accuracy on herb-property extraction but only 61% on complex syndrome-pattern reasoning, highlighting the difficulty of TCM clinical reasoning. Chen et al. [17] developed a pipeline for extracting structured clinical information from TCM case reports, achieving 86% accuracy on treat-ment formula extraction but noting high variability in how practitioners describe similar clinical concepts. Yang et al. [18] fine-tuned Qwen-14B on TCM texts, achieving 78.4% accuracy on a TCM professional examination benchmark compared to 62.1% for the base model. 

## 2.4 Browser-Based and Privacy-Preserving NLP Tools 

The concept of browser-based NLP tools has gained traction as a means of democratizing access to AI capabilities. Client-side processing ensures data never leaves the user’s device, addressing privacy concerns that are particularly relevant for unpublished research data and proprietary literature collections [1]. Existing browser-based tools have primarily focused on simpler tasks such as text classification and named entity recognition using smaller models. TCMIIES extends this paradigm to complex LLM-powered extraction by leveraging browser-based HTTP requests to LLM APIs while processing all data and prompt construction entirely client-side. 

# 3 System Design and Methodology 

## 3.1 System Architecture Overview 

TCMIIES adopts a single-page application (SPA) architecture implemented as a self-contained HTML file combining Vue.js 3 for reactive UI management, SheetJS for spreadsheet parsing and generation, and the Fetch API for LLM communication. The system operates through a sequential five-stage pipeline, as illustrated in Figure 1:

## 3.2 API Configuration Layer 

The API configuration module manages connections to multiple LLM providers through a unified OpenAI-compatible chat completions interface. The system maintains a provider registry containing base URLs and default model lists for five providers: DeepSeek, OpenAI, Qwen (Tongyi Qianwen), Zhipu AI (GLM), and a customizable provider for any OpenAI-compatible endpoint. Provider-specific optimizations are implemented to maximize extraction quality for each model family. For DeepSeek’s V4 and Reasoner models, the system enables the “reasoning effort” parameter and thinking mode, disabling the temperature parameter which is incompatible with these models’ internal reasoning mechanisms. For Qwen models, the system configures an extended thinking budget of 81,920 tokens to leverage the models’ native reasoning capabilities. These optimizations are expressed as conditional request body modifications:      

> DeepSeek V4/Reasoner: reasoning_effort = "max" ,thinking = {type: "enabled"}
> Qwen: enable_thinking = true ,thinking_budget = 81920

## 3.4 Schema-Guided Prompting Framework 

The core innovation of TCMIIES is its schema-guided prompting framework, which transforms user-defined extraction requirements into optimized LLM prompts without requiring manual prompt engineering. 

3.4.1 Field Configuration 

Researchers define extraction fields through a graphical interface, specifying for each field: (1) a human-readable name (e.g., 研究主题 for Research Topic), (2) a natural language description (e.g., 研究的核心问题是什么 for “What is the core problem being studied?”), (3) a data type 5(text, number, list, or boolean), and (4) a required/optional flag. The system provides two preset templates for common extraction scenarios: 

• Paper Information Extraction: Research Topic, Methodology, Dataset, Main Conclusions, Innovation Points, Research Limitations (6 fields) 

• Literature Review Analysis: Research Domain, Technical Approach, Baseline Methods, Eval-uation Metrics, Experimental Results, Future Directions (6 fields) 

3.4.2 Automatic System Prompt Generation 

Based on the defined fields, the system automatically generates a system prompt with three criti-cal components: (1) a role specification establishing the model as an academic paper information extraction assistant, (2) an explicit JSON output schema with field names as keys and type anno-tations, and (3) a fallback instruction for handling missing information. The generation algorithm is formalized in Algorithm 2.

This auto-generation mechanism achieves two critical objectives identified in the prompt engi-neering literature [5, 7]: it enforces strict JSON output formatting to maximize parseability, and it provides field-level schema specification to reduce hallucination and improve extraction complete-ness. 

3.4.3 Template-Based User Prompt Construction 

The user prompt is constructed using a template system that supports variable interpolation. Re-searchers write a natural language prompt template where column names from the uploaded dataset are referenced using double-curly-brace syntax (e.g., {{ 摘要}} for the Abstract column). During extraction, these placeholders are replaced with actual cell values from each row. This design sepa-rates prompt logic from data binding, enabling reuse across different datasets with varying column structures. 

## 3.5 Concurrent Batch Processing Engine 

The task execution module implements a configurable concurrent processing engine designed for reliability and efficiency when processing large batches of papers. The engine’s architecture includes several key mechanisms: 63.5.1 Concurrency Control 

Researchers configure the degree of concurrency (1–10 simultaneous requests) and inter-request interval (0–10,000 ms). The engine maintains a fixed-size execution pool, launching new requests as existing ones complete while respecting the configured concurrency limit. This design enables efficient utilization of API rate limits while preventing overload. 

3.5.2 Pause/Resume and Cancellation 

Long-running extraction tasks support pausing, resuming, and cancellation through reactive state flags. When paused, in-progress requests complete normally, but new requests are deferred through a polling mechanism (200 ms interval) until the pause flag is cleared. The cancellation flag immediately stops all pending requests and prevents new ones from being initiated. 

3.5.3 Automatic Retry with Error Resilience 

Each extraction attempt includes up to three automatic retries on failure, with a one-second delay between attempts. This exponential backoff-like mechanism handles transient API errors (rate limiting, temporary service unavailability) without requiring manual intervention. Failed records are marked with error information and can be individually retried through the results interface. 

3.5.4 Progress Tracking and Persistence 

Real-time progress tracking includes: processed count, success count, failure count, estimated token usage (calculated as input_chars

## 3.6 JSON Parsing and Validation 

Extracted LLM responses are parsed using a robust JSON extraction strategy. Since LLMs may occasionally include explanatory text before or after the JSON output, the system employs regular expression matching ( \{[\s\S]*\} ) to extract the first JSON object from the response string before standard JSON parsing. This approach significantly improves parsing success rates compared to direct JSON.parse, particularly for models that tend to produce verbose outputs despite explicit formatting instructions. 

## 3.7 Multi-Format Export 

The results module supports three export formats through the SheetJS library: Excel (.xlsx) with styled worksheets, CSV with UTF-8 BOM encoding for Chinese character compatibility, and JSON with pretty-printed formatting. Researchers can choose between exporting all original columns plus extracted fields, or extracted fields only. 74 Implementation 

## 4.1 Technology Stack 

TCMIIES is implemented as a self-contained HTML file (approximately 1,028 lines, 45 KB) with zero build dependencies. The technology stack comprises: 

• Vue.js 3.4 (CDN): Reactive UI framework for component state management, computed proper-ties, and event handling 

• SheetJS (XLSX) 0.18.5 (CDN): Excel/CSV parsing and generation 

• Fetch API : Browser-native HTTP client for OpenAI-compatible API communication 

• localStorage/sessionStorage : Web Storage API for configuration persistence and result caching External dependencies are loaded from the jsDelivr CDN at runtime, enabling the system to function immediately upon opening the HTML file in any modern browser (Chrome 90+, Edge 90+, Firefox 90+, Safari 14+). 

## 4.2 Data Flow and State Management 

The system maintains a centralized reactive state object managed by Vue.js, containing: API configuration (provider, base URL, API key, model, concurrency settings), file data (columns, rows, filename), mapped fields, extraction fields, prompt templates, task progress, and extraction results. State transitions follow a unidirectional data flow pattern: user interactions trigger Vue.js methods, which update the reactive state, which in turn triggers UI re-rendering through Vue’s reactivity system. 

## 4.3 Security and Privacy Design 

TCMIIES implements a privacy-by-design architecture: 1. Local Processing: All file parsing, data transformation, and prompt construction execute entirely in the browser. Research data never leaves the user’s device except when sent directly to the chosen LLM provider’s API endpoint. 2. Credential Protection: API keys are stored in localStorage using Base64 encoding. While this is not encryption, it prevents casual exposure of credentials in plain-text storage inspection. 3. No Intermediary Servers: The system has no backend infrastructure. There is no data collection, no analytics, and no logging of user activity. The complete source code is transparent and auditable as a single HTML file. 4. One-Click Data Clearing: All stored data (API configuration, cached results) can be cleared through a single button, removing all traces from localStorage and sessionStorage. 

## 4.4 User Interface Design 

The interface follows a tab-based navigation pattern with five sequential tabs corresponding to the pipeline stages. Visual design employs a blue gradient theme with card-based layout, responsive grid systems, and contextual color coding (green for success, red for failure, yellow for warnings). # 5 Evaluation 

## 5.1 Experimental Setup 

We evaluated TCMIIES across three dimensions: (1) structured output compliance—the system’s ability to produce valid, parseable JSON output; (2) extraction accuracy—the quality of extracted information compared to human expert annotation; and (3) system reliability—the robustness of the batch processing engine under various conditions. Evaluation was conducted using a corpus of 500 TCM research papers exported from CNKI, spanning five sub-disciplines: herbal pharmacology (100 papers), acupuncture clinical trials (100 papers), formula composition studies (100 papers), TCM syndrome research (100 papers), and integrative medicine reviews (100 papers). Each paper record contained title ( 篇名), abstract ( 摘

要), keywords ( 关键词), authors ( 作者), source journal ( 来源), and publication date ( 发表时间). We tested extraction across three LLM providers: DeepSeek (deepseek-v4-flash), Qwen (qwen-turbo), and GLM-4 (glm-4-flash), using two extraction templates: Paper Information Extraction (6 fields) and Literature Review Analysis (6 fields).

# 6 Discussion 

## 6.1 Comparison with Existing Approaches 

TCMIIES occupies a distinct position in the landscape of LLM-based information extraction tools. Unlike code-level frameworks such as DSPy [21] or LangChain, which require programming exper-tise, TCMIIES provides a graphical interface accessible to domain researchers without technical backgrounds. Unlike cloud-based platforms, the browser-based architecture ensures data privacy by design. Unlike domain-specific fine-tuned models [15, 18], TCMIIES leverages commercial LLM APIs, trading some domain-specific accuracy for flexibility across extraction tasks and continuous improvement as underlying models advance. The system’s schema-guided prompting approach aligns with established best practices in the literature while adding the novel capability of automatic prompt generation from user-defined fields. This automation eliminates the need for manual prompt engineering, which has been identified as a significant barrier to LLM adoption in specialized domains [23]. 

## 6.2 Limitations 

Several limitations of the current system warrant discussion: 

API Dependency: The system requires active API subscriptions, creating a dependency on commercial LLM providers. While the multi-provider support mitigates vendor lock-in, the system cannot function without network access and valid API credentials. 

JSON Parsing Robustness: Despite the 94.2% compliance rate, approximately 5–8% of responses fail to parse as valid JSON. The regex-based extraction fallback helps, but fundamentally depends on the model’s adherence to formatting instructions. Advances in structured output modes (e.g., OpenAI’s JSON mode, function calling) could further improve reliability [26]. 

Limited Context Handling: The system sends each paper as a single prompt, which may exceed context window limits for very long abstracts or full-text papers. A chunking strategy or hierarchical extraction approach could address this limitation. 11 Accuracy Ceiling: The zero-shot extraction accuracy of approximately 82% suggests that for high-stakes applications requiring near-perfect accuracy, human verification or domain-specific fine-tuning remains necessary. This aligns with the TCM literature’s emphasis on human-in-the-loop verification [19]. 

Lack of Full-Text Processing: Currently, the system primarily processes metadata (title, abstract, keywords). Extending to full-text PDF parsing would significantly expand the system’s capabilities but would introduce additional complexity in document structure understanding. 

## 6.3 Future Work 

Several directions for future development emerge from this work: 1. Multi-Step Extraction Pipelines: Implementing staged extraction where the LLM first iden-tifies relevant text passages, then extracts targeted information, and finally validates outputs through self-consistency checking. Research suggests this approach can improve accuracy by 10–15% [11]. 2. Integration with TCM Knowledge Bases: Linking extracted information to structured TCM knowledge bases such as TCMID [19] and SymMap [20] for entity normalization and validation. 3. Active Learning for Prompt Optimization: Implementing the DSPy-inspired [21] automatic prompt optimization based on user corrections, enabling the system to learn from manual edits to improve future extractions. 4. PDF Parsing Support: Integrating browser-based PDF parsing (e.g., PDF.js) to enable ex-traction from full-text papers rather than database export metadata. 5. Cross-Database Normalization: Extending the intelligent field mapping to support exports from additional databases such as PubMed, Web of Science, and Scopus. 

# 7 Conclusion 

This paper presented TCMIIES, a browser-based, LLM-powered information extraction system designed to democratize access to advanced NLP capabilities for academic researchers, particularly in specialized domains such as Traditional Chinese Medicine informatics. The system contributes a novel schema-guided prompting framework with automatic prompt generation, a pure front-end architecture ensuring data privacy, intelligent field mapping for Chinese academic databases, and a robust concurrent batch processing engine. Experimental evaluation demonstrated structured output compliance rates exceeding 94% and extraction accuracy averaging 81.6% across six extraction fields and three LLM providers, with the cost-effective DeepSeek v4-flash model achieving the best accuracy-cost trade-off. The system’s reliability features—automatic retry, pause/resume, and session persistence—ensured 100% task completion rates even under adverse conditions. TCMIIES represents a practical bridge between cutting-edge LLM capabilities and the real-world needs of domain researchers. By eliminating barriers of programming expertise, infrastructure setup, and data privacy concerns, the system enables researchers to focus on their core scientific work while leveraging AI for efficient literature mining and knowledge synthesis. The system is actively deployed at the TCM Informatics Laboratory of Hebei University and is available as open-source software. 12 Acknowledgments
