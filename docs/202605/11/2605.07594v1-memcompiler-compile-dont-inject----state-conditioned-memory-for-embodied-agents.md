## 摘要
现有的具身智能体记忆系统通常在回合开始时将检索到的记忆作为静态上下文注入，我们将这一范式称为“提前单体记忆注入”（Ahead-of-time Monolithic Memory Injection, AMMI）。然而，这种静态设计很快就会与智能体不断演化的状态失配，并可能导致轻量级执行器的性能降至无记忆基准线以下。为解决这一问题，我们提出了 MemCompiler，它将记忆利用重新定义为“状态条件化记忆编译”。一个经过学习的记忆编译器（Memory Compiler）读取捕获智能体当前执行状态的结构化简要状态（Brief State），并动态选择仅相关的记忆，将其编译为可执行的指导。这种指导通过文本通道和潜在的 Soft-Mem 通道传递，后者保留了文本无法表达的感知信息。在 Alf World、EmbodiedBench 和 ScienceWorld 上的实验表明，MemCompiler 在各种开源骨干网络上均一致优于无记忆基准（提升高达 129%），达到或接近前沿闭源系统的水平，并将每步延迟降低了 60%，证明了状态感知记忆编译能够同时提高有效性和效率。

## Abstract
Existing memory systems for embodied agents typically inject retrieved memory as static context at episode start, a paradigm we term Ahead-of-time Monolithic Memory Injection (AMMI). However, this static design quickly becomes misaligned with the agent's evolving state and may degrade lightweight executors below the no-memory baseline. To address this, we propose MemCompiler, which reframes memory utilization as State-Conditioned Memory Compilation. A learned Memory Compiler reads a structured Brief State capturing the agent's current execution state and dynamically selects and compiles only relevant memory into executable guidance. This guidance is delivered through a text channel and a latent Soft-Mem channel that preserves perceptual information not expressible in text. Across Alf World, EmbodiedBench, and ScienceWorld, MemCompiler consistently improves over no-memory across open-source backbones (up to +129%), matches or approaches frontier closed-source systems, and reduces per-step latency by 60%, demonstrating that state-aware memory compilation improves both effectiveness and efficiency.

### MemCompiler: 编译而非注入——面向具身智能体的状态条件化记忆

#### 1. 核心问题与整体含义
具身智能体（Embodied Agents）在执行长程任务时依赖记忆来克服部分可观测性并积累经验。然而，现有的记忆系统普遍采用**提前单体内存注入（AMMI）**范式，即在任务开始前将所有检索到的记忆一次性塞入上下文。
*   **研究动机**：作者发现 AMMI 存在“注意力稀释”问题。随着任务推进，静态注入的记忆与智能体不断演化的执行状态逐渐失配，导致执行器对记忆 token 的注意力大幅下降（实验显示下降达 86.7%）。对于轻量级开源模型，这种无关信息的干扰甚至会导致性能低于“无记忆”基准。
*   **核心含义**：论文提出将记忆利用从“静态注入”转变为“动态编译”，即根据当前状态实时生成最相关的指导信息。

#### 2. 方法论：状态条件化记忆编译（SCMC）
MemCompiler 的核心思想是模仿编译器：将任务记忆视为“源代码”，将当前执行状态视为“运行时上下文”，通过**记忆编译器（Memory Compiler）**动态生成“可执行指导”。
*   **简要状态（Brief State, $b_t$）**：不同于原始观测，这是一种结构化的运行时上下文，包含：
    *   **任务进度状态**：目标、已完成/当前/待办子目标。
    *   **环境信念**：物体位置、智能体状态及环境事实。
*   **记忆编译器（Memory Compiler）**：一个轻量级模型，每步决策时读取 $b_t$ 和原始记忆库 $M$，决定四种输出之一：仅经验指导、仅状态更新、混合输出或无动作（不干预）。
*   **双通道传递机制**：
    *   **文本通道**：提供可解释的策略指导。
    *   **Soft-Mem 通道（潜空间通道）**：通过投影层将记忆中的感知和空间信息转化为“软 token”直接注入执行器的嵌入空间，绕过文本描述的瓶颈。
*   **训练流程**：
    1.  **SFT 阶段**：利用强模型（如 GPT-5）生成轨迹数据，联合优化文本生成、动作预测和潜空间正交约束（防止软 token 变成文本的冗余副本）。
    2.  **RL 阶段**：采用 **GRPO（群组相对策略优化）** 算法，以任务成功率为奖励信号，进一步微调编译器的决策策略。

#### 3. 实验设计
*   **数据集/场景**：
    *   **AlfWorld**：文本交互式家庭任务。
    *   **EmbodiedBench (EB-ALFRED, EB-Habitat)**：多模态具身规划，涉及视觉识别、空间推理等 6 个维度。
    *   **ScienceWorld**：复杂的科学实验模拟。
*   **基准（Benchmark）**：对比了 No Mem（无记忆）以及四种主流记忆系统：G-Mem、A-Mem、Mem0、LangMem，以及潜空间基准 MemGen。
*   **模型骨干**：闭源模型（GPT-5.2, Gemini-3-flash）；开源模型（Qwen-2.5/3/3.5 系列，规模从 14B 到 32B）。

#### 4. 资源与算力
*   **训练算力**：使用了 **8 × NVIDIA H20 (96GB)** GPU 集群。
    *   **SFT 阶段**：训练 5 个 epoch。
    *   **RL 阶段**：使用 FSDP 插件，4 卡用于 Actor 训练，3 卡用于 Rollout，1 卡用于环境交互，总计 500 个训练步。
*   **推理算力**：效率分析实验在 **NVIDIA A100** 上进行，使用 vLLM 加速推理。

#### 5. 实验数量与充分性
*   **实验规模**：涵盖了 3 个大类基准测试，涉及数千个任务实例。
*   **消融实验**：针对 Soft-Mem 通道、Brief State 的必要性、软 token 数量、正交约束等进行了详细消融。
*   **客观性与公平性**：
    *   采用了严格的“零泄露”机制，确保训练集和测试集在场景、物体和指令上完全隔离。
    *   在对比实验中，所有方法使用相同的原始记忆条目，仅改变交付范式，确保了对比的公正性。

#### 6. 主要结论与发现
*   **性能飞跃**：MemCompiler 在所有开源骨干网络上均显著优于无记忆基准，在 ScienceWorld 上提升高达 **129%**。
*   **缩小开源/闭源差距**：搭载 MemCompiler 的 Qwen-3.5-27B 在 AlfWorld 上达到了 Gemini-3-flash 的水平，在 EB-Habitat 上甚至超过了 GPT-5。
*   **高效率**：相比 AMMI，MemCompiler 将执行器的输入 token 减少了 **60%**，每步延迟从 0.30s 降至 0.12s，实现了“又快又准”。
*   **注意力对齐**：可视化证明 SCMC 能让执行器在整个任务周期内保持对记忆 token 的高效关注。

#### 7. 优点
*   **范式创新**：首次明确提出并解决了具身智能体中记忆交付的“时间”和“方式”问题，而非仅仅关注存储内容。
*   **双模态融合**：Soft-Mem 设计巧妙地解决了文本难以描述空间/感知信息的问题，且通过正交约束保证了信息的互补性。
*   **实用性强**：显著降低了推理成本，使中等规模的开源模型具备了挑战前沿闭源模型的能力。

#### 8. 不足与局限
*   **数据依赖**：SFT 阶段高度依赖强模型（如 GPT-5）生成的教师轨迹，这可能限制了其在完全未知领域或缺乏强教师模型时的表现。
*   **状态维护风险**：Brief State 的维护依赖于编译器的准确操作（Create/Update 等），若在长程任务中发生一步错误，可能导致后续状态累积偏差。
*   **环境局限**：实验主要在模拟器（AI2-THOR, Habitat）中完成，尚未在复杂的真实物理世界机器人上进行大规模验证。
