## 摘要
基于大语言模型的知识图谱问答（KGQA）将图遍历委托给语言模型，将每个问题转化为一系列在波束和跳数上重复的局部关系选择决策。一种常见但未经测试的默认做法是将完整的部分路径序列化到每个路由提示中，尽管控制器已经以精确的符号状态维护了该路径。有界路径上下文（BPC）将这两个角色解耦：控制器在符号记忆中保留完整路径以供答案提取和审计，而关系选择提示仅暴露问题、当前实体、出方向关系候选以及至多最后K跳。对K进行的受控扫描——固定图邻域、波束预算、深度、解码和答案提取格式——表明，在完整的WebQSP和CWQ测试集上，使用Qwen3.5-9B-AWQ模型，有界历史匹配或超过全历史提示：K=1在WebQSP上达到0.487的答案集F1值，而全历史为0.472；K=0在CWQ上达到0.287，而全历史为0.274，输入token分别减少了9.7%和12.1%。在4B规模下，K=1仍然是两个基准上的最强设置。逐示例分析表明，71-84%的示例不受历史长度影响，而受影响的示例揭示了先前跳数何时起到消歧而非干扰作用。这些结果表明，在基于LLM的图控制器中，路径序列化长度更适合作为可调的接口变量，而非默认假设。

## Abstract
LLM-based knowledge-graph question answering (KGQA) delegates graph traversal to language models, turning each question into a sequence of local relation-selection decisions repeated across beams and hops. A common but untested default is to serialize the complete partial path into every routing prompt, even though the controller already maintains this path as exact symbolic state. Bounded Path Context (BPC) decouples these two roles: the controller retains full paths in symbolic memory for answer extraction and audit, while the relation-selection prompt exposes only the question, the current entity, outgoing relation candidates, and at most the last K hops. A controlled sweep over K -- fixing graph neighborhoods, beam budget, depth, decoding, and answer-extraction format -- shows that bounded histories match or exceed full-history prompting on complete WebQSP and CWQ test sets with Qwen3.5-9B-AWQ: K=1 achieves 0.487 answer-set F1 on WebQSP versus 0.472 for full history, and K=0 reaches 0.287 on CWQ versus 0.274, with 9.7% and 12.1% fewer input tokens respectively. At the 4B scale, K=1 remains the strongest setting on both benchmarks. Per-example analysis reveals that 71-84% of examples are unaffected by history length, while the affected cases expose when prior hops disambiguate versus distract. These results suggest that path serialization length is better treated as a tunable interface variable than as a default assumption in LLM-based graph controllers.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题背景**：在基于大语言模型（LLM）的知识图谱问答（KGQA）中，通常的做法是将每一步搜索的完整部分路径序列化到路由提示（routing prompt）中，让LLM决定下一步选择哪个关系。然而，图控制器（controller）已经在符号记忆中精确维护了这些路径。这种重复序列化不仅增加了输入token数量，占用KV-cache内存，还可能与当前候选关系争夺注意力，甚至引入过时或干扰信息。
- **核心问题**：LLM在进行局部关系选择时，是否真的需要看到完整的路径历史？路径历史长度对决策质量和系统效率有何影响？
- **研究意义**：将路径序列化长度从默认假设转变为可测量的接口变量，有助于设计更高效、更准确的LLM图控制器。

## 2. 方法论：核心思想、关键技术细节、算法流程

- **核心思想**：提出**有界路径上下文（Bounded Path Context, BPC）**，解耦控制器的符号记忆与模型可见的路径文本。
  - 控制器在符号记忆中保留完整路径，用于最终答案提取和审计。
  - 关系选择提示仅暴露：问题（q）、当前实体（τ(p_t)）、出方向关系候选（C_c(e)）以及**至多最近K跳**的历史（h_K(p_t)）。
- **关键设计**：
  - K=0：不显示任何历史，用显式“无历史标记”占位。
  - 0<K<t：只显示最后K跳（suffix_K(p_t)）。
  - K≥t 或 K=full：显示完整路径。
  - 关系候选上限c=50，波束宽度w=3，最大深度D=5，最大保留波束B=16。
  - 关系选择后，控制器扩展最多w个尾实体，然后按预算保留路径（优先保留开放路径再保留完成路径）。
  - 答案提取阶段：使用保留的完整路径（最多8条）进行答案提取，不受关系选择时K的影响。
- **算法流程**（文字描述）：
  1. 初始化波束集P为所有主题实体（标记为开放）。
  2. 循环t=0到D-1：
     - 对每个开放路径p（且其当前实体有非空候选关系），批量构建关系选择提示（含h_K(p)、当前实体、候选关系）。
     - 解析LLM响应，得到最多w个关系名（或STOP）。
     - 若候选空 / 返回STOP / 解析失败，标记为完成。
     - 否则，对每个选定关系，扩展最多w个尾实体，形成新路径加入P'。
     - 从P'中保留最多B条路径，优先保留开放路径。
  3. 搜索结束后，将保留的完整路径渲染到答案提取提示中，由LLM输出逗号分隔的答案实体。

## 6. 主要结论与发现

- **核心发现**：**有界历史（小K）匹配或超过全历史提示**，同时减少输入token。
  - 9B WebQSP：K=1最佳（F1 0.487），K=0次佳（0.485），full为0.472；K=1节省9.7%输入token。
  - 9B CWQ：K=0最佳（F1 0.287），full为0.274；节省12.1%输入token。
  - 4B规模：K=1在两项基准上均优于K=0和full。
  - **大多数示例（71-84%）不受历史长度影响**，受影响的示例中K=1 wins > losses。
- **模型规模交互**：9B模型在零历史（K=0）下表现强；4B模型需要1跳历史辅助消歧。
- **消融控制表明**：随机关系性能远低于BPC（WebQSP F1 0.186 vs 0.485），说明图锚定和语义关系选择均重要；ToG结果相近但未超过。
- **建议**：K=1是跨模型规模最一致的候选默认值。

## 7. 优点

- **问题聚焦**：精准切入LLM-KGQA中一个常见但未被检验的默认做法，提出清晰解耦思路。
- **受控实验设计严格**：所有非变量因子固定，仅变可见历史长度，确保比较公平。
- **分析深入**：不仅报告聚合指标，还进行逐示例win/loss/tie分析、答案基数交互、路由失败模式、定性模式分析，有助于理解机制。
- **效率提升有实际意义**：输入token减少约10-12%，可降低延迟和内存占用，且不牺牲（甚至提升）性能。
- **模型规模维度的探索**：4B和9B的对比揭示了不同容量模型对历史依赖的差异。
- **开源代码**：提供了复现和进一步研究的便利。

## 8. 不足与局限

- **数据集覆盖有限**：仅使用Freebase风格的WebQSP和CWQ，未在更多KG（如Wikidata、DBpedia）或非英语数据集上验证。
- **模型系列单一**：仅使用Qwen3.5-AWQ（一个模型家族），未扩展到GPT、Llama、Mistral等广泛使用的模型，通用性未知。
- **CWQ全历史配置不一致**：因token长度限制，full-history设置使用max_model_len=4096，而其他K使用2048，这可能导致KV-cache分配和调度差异，成为潜在混淆。
- **未评估自适应K**：目前只测试固定K，未探索根据实体/问题动态调整可见历史长度的策略。
- **未与prompt压缩方法对比**：如Selective Context、LongLLMLingua等，无法直接说明BPC相比通用的上下文压缩有何优势。
- **确定性子解码限制**：温度0消除方差但可能掩盖不同历史长度下的决策多样性；在非确定性设置中结论是否鲁棒未知。
- **答案提取依赖LLM**：最终答案提取仍调用LLM，可能引入幻觉和错误；虽然保留了完整路径，但审计功能不能保证事实正确性。
- **图不完整问题**：BPC不能解决图邻域缺失或主题实体歧义问题，这些属于更底层挑战。
