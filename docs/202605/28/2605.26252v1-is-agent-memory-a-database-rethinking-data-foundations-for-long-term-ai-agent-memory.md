## 摘要
长期运行的AI智能体需要持久记忆。记忆支持跨会话学习，减少重复上下文注入，并能够审计过去的决策。当前的智能体记忆系统和数据库范式将记忆视为存储。它们将正确性定位在记录、嵌入或边上。每一种方案仅提供了长期记忆所需的部分能力。结果是四种反复出现的失败模式：无节制的增长、缺失语义修订、容量驱动的遗忘和只读检索。在我们的愿景中，长期智能体记忆是一种新的数据管理工作负载。其正确性是状态轨迹的属性，而非单个记录的属性。我们将其形式化为受控演化记忆（GEM）。GEM用四个状态级操作符取代记录级数据库操作：摄取、修订、遗忘和检索。六个正确性条件控制状态如何演化。三个结构观察表明，无论存储模型如何，没有任何记录级系统能够满足这些条件。我们在属性图后端原型MemState中实现了该抽象。MemState验证了可行性，并揭示了与原生引擎之间的差距。我们概述了三个研究方向，将记忆中心的数据管理定义为一个工作负载。

## Abstract
Long-running AI agents need persistent memory. Memory supports learning across sessions, reduces repeated context injection, and enables auditing of past decisions. Current agent memory systems and database paradigms treat memory as storage. They localize correctness at records, embeddings, or edges. Each supplies only some of the capabilities that long-term memory requires. The result is four recurring failure modes: unregulated growth, missing semantic revision, capacity-driven forgetting, and read-only retrieval. In our vision, long-term agent memory is a new data-management workload. Its correctness is a property of the state trajectory, not of individual records. We formalize this as Governed Evolving Memory (GEM). GEM replaces record-level database operations with four state-level operators: ingestion, revision, forgetting, and retrieval. Six correctness conditions govern how the state evolves. Three structural observations establish that no record-level system can satisfy these conditions, regardless of the storage model. We realize the abstraction in MemState, a prototype on a property-graph backend. MemState validates feasibility and exposes the gap to a native engine. We outline three research directions that define memory-centric data management as a workload.

# 论文详细总结

## 1. 核心问题与整体含义（研究动机和背景）

- **问题背景**：长期运行的AI智能体（如ChatGPT、Claude、Cursor等）需要持久记忆来支持跨会话学习、减少重复上下文注入、审计过去决策。当前绝大多数智能体记忆系统和数据库范式（关系型、键值、图、向量等）都将记忆视为静态的“存储”，正确性定位在单个记录、嵌入或边上。
- **四个失败模式**：
  1. **无节制增长**：追加式存储导致冗余和低相关条目堆积。
  2. **缺失语义修订**：更新被追加而非整合，新旧事实共存，检索可能返回过时值。
  3. **容量驱动遗忘**：遗忘由年龄或容量驱动，而非用户相关重要性。
  4. **只读检索**：检索不改变记忆状态，高频访问的事实与低频事实以同等条件竞争。
- **核心立意**：论文将长期智能体记忆重新定义为一种**新的数据管理工作负载**，其正确性应属于**状态轨迹**（state trajectory）而非单个记录。现有系统基于CRUD的记录级抽象无法满足需求。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：提出**受控演化记忆（GEM, Governed Evolving Memory）** 抽象，用四个状态级算子取代记录级CRUD，并定义六个正确性条件。
- **GEM形式化**：
  - 记忆状态定义为三元组 \( M_t = (D_t, S_t, P_t) \)：
    - \( D_t \)：存储内容，组织为语义单元（semantic unit），每个单元包含值历史（value history）和显著性信号（salience signal）。
    - \( S_t \)：结构组织，即语义单元间的类型化边（如扩展边、关联边）。
    - \( P_t \)：演化策略，为一组 `<事件, 条件, 动作>` 规则，声明式控制状态变迁。
  - 演化函数：\( M_{t+1} = U(M_t, I_t, R_t) \)，其中 \( I_t \) 为外部输入，\( R_t \) 为内部操作。
- **四个状态级算子**：
  - **摄取（Ingestion）**：将新输入整合进现有状态，更新已有语义单元的值历史，保留旧值作为证据。
  - **修订（Revision）**：根据内部证据合并冲突、沿结构边传播更新，保留被取代值的来源。
  - **遗忘（Forgetting）**：基于显著性信号进行分级衰减（压缩→隐藏→归档），非二进制删除，且可恢复。
  - **检索（Retrieval）**：返回输出并同时更新访问单元的显著性（读变成写操作）。
- **六个正确性条件（C1–C6）**：
  - C1：查询准确性（返回最新未归档值）
  - C2：变迁准确性（每个变迁遵守策略，不返回被取代值）
  - C3：依赖一致性（沿扩展边传播更新）
  - C4：来源保留（遗忘和修订保留可达单元的来源链）
  - C5：有界活跃状态（活跃部分大小受策略约束，归档内容可恢复）
  - C6：检索诱导适应（每次检索更新显著性，重复检索降低被遗忘概率）
- **三个结构观察**（证明记录级CRUD系统无法满足GEM）：
  - 纯函数检索无法满足C6（检索必须引起状态变迁）。
  - C5与C6在CRUD引擎上联合不可实现（只读检索无法驱动相关遗忘）。
  - 追加存储无语义单元无法满足C2，无类型传播无法满足C3。
- **MemState原型**：基于Kuzu嵌入式属性图引擎实现GEM，支持主题（topic）作为语义单元、字段值历史、类型化边、声明式策略检查。

## 6. 主要结论与发现

- **结论1**：长期智能体记忆不是数据库问题，而是一种新数据管理工作负载，其正确性应由状态轨迹定义。
- **结论2**：现有任何记录级系统（无论数据库范式或智能体记忆系统）都无法满足GEM的六个正确性条件。
- **结论3**：通过MemState原型在属性图上可以有限实现GEM，但暴露出与原生引擎的差距。
- **结论4**：未来需要三个研究方向：原生引擎设计（存储布局、统一索引、检索即写）、轨迹级正确性评估（轨迹基准、策略语言、受控学习）、多租户隐私与遗忘（检索诱导信息泄漏、可验证擦除）。
