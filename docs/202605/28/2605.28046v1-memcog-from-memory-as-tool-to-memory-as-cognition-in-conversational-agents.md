## 摘要
现有的代理记忆系统普遍遵循我们称之为“记忆即工具”的范式，其中单个查询触发扁平段落列表的一次性检索，存在被动调用、推理-检索解耦以及检索到的片段与代理导航需求之间的结构不匹配等问题。我们提出MemCog，一个“记忆即认知”系统，使记忆访问成为推理过程不可或缺的一部分。MemCog将用户知识组织为具有关联链接图的可导航记忆存储，提供跨维度导航接口以实现多步推理驱动的遍历，并采用主动推理协议，驱动代理从对话上下文中自发启动记忆探索。此外，我们构建了ProactiveMemBench，这是第一个用于评估主动记忆触发的基准。实验表明，MemCog在被动QA基准（LoCoMo上92.98，LongMemEval上95.8）上达到了最先进的性能，同时在ProactiveMemBench上大幅超越基线，展示了“记忆即认知”的优势。

## Abstract
Existing agent memory systems universally follow what we term a Memory-as-Tool paradigm where a single query triggers one-shot retrieval of flat passage lists, suffering from passive invocation, reasoning-retrieval decoupling, and structural mismatch between retrieved fragments and the agent's navigational needs. We propose MemCog, a Memory-as-Cognition system that makes memory access an integral part of the reasoning process. MemCog organizes user knowledge as Navigable Memory Store with associative link graphs, exposes Cross-Dimensional Navigation Interface for multi-step reasoning-driven traversal, and employs Proactive Reasoning Protocol that drives agents to spontaneously initiate memory exploration from conversational context. We additionally construct ProactiveMemBench, the first benchmark for evaluating proactive memory triggering. Experiments show that MemCog achieves state-of-the-art on passive QA benchmarks (92.98 on LoCoMo, 95.8 on LongMemEval) while substantially outperforming baselines on ProactiveMemBench, demonstrating the advantage of Memory-as-Cognition.

# MemCog: 从记忆作为工具到记忆作为认知 — 论文详细总结

## 1. 核心问题与整体含义（研究动机和背景）

- **现有范式局限**：当前对话代理的记忆系统普遍遵循 **Memory-as-Tool（记忆即工具）** 范式，即一次查询触发一次性的扁平段落检索。这带来三大根本问题：
  - **调用瓶颈**：记忆系统仅在代理显式发出工具调用时被激活，是“被动响应”而非“主动触发”。
  - **推理-检索解耦**：检索是单次调用，代理的推理能力无法干预检索过程，导致两个模块独立优化，难以协同进化。
  - **结构不匹配**：即使记忆有层次组织，返回的 top-k 片段缺乏结构导航信息，代理无法基于当前结果推理出下一步最优检索路径。
- **研究含义**：本文提出 **Memory-as-Cognition（记忆即认知）** 范式，将记忆访问从被动的预处理步骤转变为代理推理过程不可分割的一部分，旨在消除上述三大限制。

## 2. 方法论：核心思想、关键技术细节

- **整体框架**：MemCog 由三个紧密耦合的组件构成：
  1. **Navigable Memory Store（可导航记忆存储）**
  2. **Cross-Dimensional Navigation Interface（跨维度导航接口）**
  3. **Proactive Reasoning Protocol（主动推理协议）**

- **Navigable Memory Store**：
  - **层次化组织**：三维粒度——**维度**（顶层分类，如个人偏好、工作）、**页面**（每个维度下的知识单元）、**片段**（页面内细粒度信息块，包含标题、摘要、结构化事实、相关页面、时间上下文、置信度）。
  - **跨维度关联链接**：定义四种类型：`related_to`（语义关联）、`temporal_next`（时间继起）、`caused_by`（因果）、`contrasts_with`（对比）。这些链接作为显式导航线索，引导代理进行多步遍历。
  - **构建与演化**：初始构建通过 LLM 从对话历史提取事实、聚类生成页面和链接；增量更新在每次对话后更新或创建页面，并检测矛盾、更新置信度。

- **Cross-Dimensional Navigation Interface**：
  - 提供四种多粒度导航动作，替代单次检索工具：
    - `list_dimensions()`：返回所有顶层维度及描述。
    - `browse_dimension(dim)`：返回指定维度的页面标题和摘要。
    - `read_page(page_id)`：返回页面的完整内容、所有片段及出链。
    - `follow_link(link)`：沿超链接导航到目标页面，实现跨维度遍历。
  - 每个动作返回的内容不仅包括请求信息，还包含结构上下文（可用的链接、兄弟页面、维度位置），供代理推理下一步动作。

- **Proactive Reasoning Protocol**：
  - 以系统提示形式定义两种记忆互动模式：
    - **主动关联**：当对话上下文提及人、地点、话题等可能连接已有知识时，代理主动启动记忆导航；当对话可从历史背景获益时；当用户陈述与存储信息矛盾时。
    - **被动响应**：代理响应显式用户问题而导航记忆。
  - 协议还规定跨维度导航、跟随链接构建完整画面、选择性展示信息（根据相关性、时效性、敏感性、冗余度四维度评估）。
  - **选择性展示**：代理在 Think 阶段由 LLM 自身判断是否展示召回信息，无需额外门控模块。

- **整体流程**：代理在 ReAct 循环中执行：Think（评估当前信息是否充分，规划下一步导航）→ Act（调用一个导航工具）→ Observe（接收结构化结果，反馈给推理），实现检索与推理的紧密耦合。

## 3. 实验设计

## 6. 主要结论与发现

- **被动 QA 性能**：MemCog 在 LoCoMo 上达到 92.98（GPT-4.1-mini），在 LongMemEval 上达到 95.8，超越所有基线，表明 Memory-as-Cognition 不影响被动检索质量。
- **主动记忆触发**：在 ProactiveMemBench 上 Recall@5 达 59.51，LLM 判定 Precision 87.58，人工判定 Precision 91.02，大幅优于基线，验证了协议与结构组合的有效性。
- **消融结论**：
  - 移除主动推理协议后，主动触发 Recall 下降 14.63，但被动 QA 几乎不变，证明协议专门解决调用瓶颈。
  - 移除关联链接或层次结构对两个任务均有明显下降，说明导航结构不可或缺。
  - 全部组件组合才达到最佳性能，验证了协议-结构的互补协同。
- **内存访问是一个谱系**：从无记忆→单次搜索→多步导航→自发回忆，MemCog 实现在谱系上的重要推进。
- **可扩展性**：页面增长呈次线性趋势（早期快速建立核心维度，后期增量的约 30% 衰减），增量更新为 O(1) 摊销成本。

## 8. 不足与局限

- **Token 开销**：多步导航比单次检索消耗更多 Token，在严格时延或成本约束下可能不适用。
- **依赖 LLM 指令跟随能力**：主动推理协议依赖强指令跟随能力，弱模型表现差异大。
- **页面构建质量瓶颈**：如果 LLM 提取的事实不准确或链接缺失，整个系统性能会下降。
- **早期对话稀疏**：在对话初期，记忆网络欠连接，导航优势有限。
- **实验覆盖不足**：
  - 仅在一个骨干（GLM-5.1）上进行消融，未在其他骨干上重复验证。
