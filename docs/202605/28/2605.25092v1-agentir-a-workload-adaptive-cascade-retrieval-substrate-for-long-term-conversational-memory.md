## 摘要
长期对话记忆是一种经典信息检索未设计应对的检索工作负载：索引在查询流中增长，查询类型在会话内变化，每次检索的延迟预算低于10毫秒。Lucene类引擎将索引视为静态，将查询视为无状态，未能利用工作负载的结构。AgentIR将融合视为沿两个轴的每查询决策：应用哪种融合（BM25、Dense、RRF或智能体感知的RRF），以及约52毫秒的稠密通道是否值得运行。第二个轴是一个置信度触发的级联路由器，仅根据BM25 top-k余量做出决策，并在不同工作负载间重新调整而无需重新训练。在LongMemEval（n=500）上，稠密通道确实增加了信息，级联在LLM判断准确率相当的情况下跳过了63%的查询（在两名评判者下加速2.67倍，配对bootstrap p>=0.88）；按查询类型阈值在5折交叉验证下将其扩展到5.76倍。在LoCoMo（n=1,982）上，单独BM25已经是最强的单一系统，相同的触发器自动调整到100%跳过率（加速132倍，Hit@5提高0.089）。共享8核虚拟机上的容量从约154个并发智能体增加到约1,400个（9倍）。在级联之下，时间分区索引的工作量为O(log 1/epsilon)，与语料库大小无关：1234倍语料库增长仅带来3.6倍延迟代价，最终在5M记录上达到1769倍于顺序扫描，p50低于100微秒。在与Lucene质量相当的9个BEIR数据集（最多880万文档）上，该底层系统在Pyserini 8T上的几何平均速度提升10倍，在PISA-1T BlockMax-WAND上提升11倍；A100相比Pyserini 8T达到1.8-39倍；分块索引构建在MS MARCO上维持每秒56.8K文档。记录并修复了三个可导致nDCG@10无声退化6-8倍的细微BM25/GPU正确性陷阱；修复后，CPU和GPU在适合单个A100的所有八个数据集上的nDCG@10差异在0.0002以内。

## Abstract
Long-term conversational memory is a retrieval workload classical IR was not built for: the index grows during the query stream, query types shift intra-session, and the latency budget per retrieval is sub-10 ms. Lucene-class engines treat the index as static and the query as stateless, leaving the workload's structure unexploited.   AgentIR treats fusion as a per-query decision along two axes: which fusion to apply (BM25, Dense, RRF, or agent-aware RRF), and whether the ~52 ms dense channel is worth running at all. The second axis is a confidence-triggered cascade router that decides from the BM25 top-k margin alone and re-tunes across workloads without retraining. On LongMemEval (n=500), where the dense channel does add information, the cascade skips 63% of queries at parity LLM-judged accuracy (2.67x faster under two judges, paired bootstrap p>=0.88); per-qtype thresholds extend this to 5.76x under 5-fold cross-validation. On LoCoMo (n=1,982), where BM25 alone is already the strongest single system, the same trigger auto-tunes to a 100% skip rate (132x faster, +0.089 Hit@5). Capacity on a shared 8-core VM rises from ~154 to ~1,400 concurrent agents (9x).   Underneath the cascade, a time-partitioned index does O(log 1/epsilon) work independent of corpus size: 1234x corpus growth costs only 3.6x latency, ending in 1769x over sequential at sub-100 us p50 on 5M records. At parity quality with Lucene on 9 BEIR datasets up to 8.8M docs, the substrate runs 10x geo-mean over Pyserini 8T and 11x over PISA-1T BlockMax-WAND; an A100 reaches 1.8-39x over Pyserini 8T; chunked index build sustains 56.8K docs/sec on MS MARCO. Three subtle BM25/GPU correctness pitfalls that silently regress nDCG@10 by 6-8x are documented and fixed; post-fix CPU and GPU agree within 0.0002 nDCG@10 on all eight datasets that fit a single A100.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
- 将检索融合视为 **逐查询的两轴决策**：
  - **轴一**：选用哪种融合策略（BM25、Dense、RRF、智能体感知的 RRF）。
  - **轴二**：是否值得运行昂贵的稠密通道（约 52 ms）。
- 通过一个 **置信度触发的级联路由器**（Cascade Router）仅凭 BM25 top‑k 分数差距（margin）决定是否跳过稠密通道，且无需重新训练即可自动适应不同工作负载。

### 关键技术细节
1. **时间分区索引（Temporal Partitioned Index）**：
   - 将文档按时间窗口（7 天）分区，查询时仅搜索最近的分区，利用指数级时效性偏差实现 **O(log 1/ε)** 期望工作量（定理 4.1），与总语料库大小解耦。
   - 实证结果：语料从 4K 增长到 5M 记录（1234 倍），时间分区延迟仅增长 3.6 倍，最终达到 1769 倍加速；搜索 <0.1% 的倒排列表。

2. **SIMD 加速 BM25**：
   - 使用 AVX2（8 路 FMA）和 NEON（ARM）向量化内循环，将单线程延迟从 1.89 ms 降至 0.38 ms（5 倍）。

3. **MaxScore 剪枝**：
   - 对所有术语预计算最大贡献，按 IDF 降序处理，当当前 top‑k 分数超过剩余术语总分时提前终止，在大数据集上跳过 40–60% 的倒排列表。

4. **GPU 加速两核管道**：
   - **Kernel 1（BM25 评分）**：将倒排索引展平为 CSR 格式上传到 GPU，每个 CUDA block 处理一个 (查询, 术语) 对，使用原子加累积分数。
   - **Kernel 2（Top‑k 选择）**：每个 block 处理一个查询，在线程内构建局部排序缓冲区，然后块级合并（支持两种合并策略：朴素序列和 warp 协同）。
   - 异构调度：计算密集型 BM25 在 GPU 运行，内存密集型 HNSW 在 CPU运行，利用互补架构优势。

5. **工作负载条件融合**：
   - 轻量级查询类型分类器（TF‑IDF 或 TF‑IDF+BGE‑small 嵌入，<1 ms）预测查询类型，路由到该类型对应的最佳静态系统。
   - **软路由器**：使用分类器后验概率作为权重，将多个系统的排序列表通过权重预乘 RRF 融合，在 LongMemEval 上显著优于所有静态系统（p<0.05）。
   - **级联路由器**：首先运行 BM25，若 BM25 的置信度（(s₁‑s₂)/s₁）超过阈值则直接返回 BM25 结果（跳过稠密通道）；否则执行完整的混合路径。同一阈值可自动适应不同工作负载（LongMemEval 跳过 63%，LoCoMo 跳过 100%）。

6. **智能体感知融合公式**：
   - 在 RRF 基础上添加加性时效性奖励和重要性权重：`score(d,q) = RRF(r_s, r_d) + α·e^(-Δt/τ) + β·w_d`，其中 α 远小于最大 RRF，确保只作为平局打破者。τ 全局默认 30 天，对多会话问题建议 ≥120 天。

7. **SPLADE 桥接**：
   - 将 SPLADE 的学习权重（tf 替换为权重）直接放入 CSR 布局，bit‑perfect 匹配 scipy.sparse 输出，从而在 SPLADE 质量的语料库上获得 AgentIR 速度。

### 算法流程（文字描述）
- 级联路由器流程：
  1. 运行 BM25 获得 top‑k 列表。
  2. 计算置信度 c = (top1_score - top2_score) / top1_score。
  3. 如果提供了查询类型分类器，则使用对应的按类型阈值；否则使用全局阈值。
  4. 若 c ≥ 阈值，直接返回 BM25 top‑k（跳过稠密通道）。
  5. 否则，运行稠密通道（编码 + ANN），执行 RRF + 时效性和重要性融合，返回最终 top‑k。

- **LongMemEval**：500 个问题 × 4 个系统（BM25、Dense、RRF、agent_rrf），每个问题运行 LLM 回答和评判（500×4×2 次 LLM 调用），生成大量指标。
- **LoCoMo**：1,982 QA 问题，同样 ×4 系统。
- **可扩展性**：合成语料扫 4K → 5M 共 7 个规模点，每个点 200 个查询。
- **消融实验**：组件消融（1T 标量 → +SIMD → +MaxScore → +8T）在 8 个 BEIR 数据集上；线程缩放（1T/4T/8T）；GPU 内核比较（朴素 vs. warp 协同）；路由器类型与阈值扫描；5 折交叉验证验证级联路由器。
- **正确性验证**：GPU 与 CPU 的 nDCG@10 对比在 8 个数据集上；三处正确性陷阱的回归实验（预归一化 TF 等）。

### 充分性 & 公平性
- **充分**：覆盖了多种代理记忆场景（短期 QA、长期多会话、通用检索），评估了质量、延迟、吞吐量、扩展性、多租户、路由器鲁棒性、参数敏感性等。
- **公平**：
  - 与 Pyserini/PISA 在同一硬件、相同 qrels 和超参数（k1=1.2, b=0.75）下对比。
  - Pyserini 是社区标准化基线；PISA 是 SOTA CPU BM25 引擎，直接从源码构建并运行官方 `queries` 二进制。
  - 使用指数增益 nDCG 公式，与 pytrec_eval 一致。
  - LLM 评判在相同种子和温度下运行，并报告配对 bootstrap p 值以衡量统计显著性。
  - 级联路由器的延迟为确定性推导（基于实测阶段延迟和跳过率），非模拟。
- **不足**：5M 缩放实验使用合成语料，虽依据 LongMemEval 实测分布，但非真实生产轨迹。文中已在“威胁有效性”中指出。

## 6. 论文的主要结论与发现

1. **质量**：
   - 在 BEIR 上，AgentIR CPU 8T+SIMD 在 9 个数据集中有 5 个超过 Pyserini Lucene（nDCG@10 最高 +0.051），其余差距在 0.003–0.020 以内；几何平均延迟比 Pyserini 8T 快 10 倍，比 PISA 1T 快 11 倍。
   - 混合 RRF+bge‑small 在 BEIR 上比单独 BM25 提升平均 nDCG@10 0.033。
   - 在 LongMemEval 上，agent_rrf（RRF+时效性和重要性奖励）在 LLM 判断准确率上优于所有静态系统（0.254 vs. BM25 0.246）。
   - 在 LoCoMo 上，BM25 单独检测最优（Hit@10=0.945），稠密通道反而有害。

2. **速度**：
   - 时间分区索引实现亚线性缩放：5M 记录时 p50 延迟 <100 μs，比顺序扫描快 1769 倍。
   - GPU A100 在 NQ 上比 Pyserini 8T 快 3.4 倍（k=100），若优化 top‑k 内核可进一步提升至 8.4 倍（k=32）。
   - 多租户实验显示，8 核 VM 可服务至少 5 个并发智能体（每个 QPS >2600），且 p50 延迟不变（~0.38 ms）；级联路由器将并发容量从 ~154 提升至 ~1400（9 倍）。

3. **自适应级联路由器**：
   - 单阈值版本在 LongMemEval 上以同等 LLM 准确率跳过 63% 稠密通道，实现 2.67 倍加速；在 LoCoMo 上自动调整为 100% 跳过（132 倍加速，Hit@5 +0.089）。
   - 按查询类型阈值 + 5 折交叉验证将加速提升至 5.76 倍，准确率保持在噪声范围。
   - 软路由器（后验加权 RRF）在 gpt‑4o‑mini 评判下显著优于所有静态系统（p<0.05），并达到离散最优的 37% 上限收益。
   - 仅需约 50 个标注查询即可使路由器达到接近最优性能。

4. **正确性**：
   - 修复三个陷阱（预归一化 TF、线性增益 nDCG、GPU 共享内存脏数据）后，CPU 和 GPU 的 nDCG@10 差异 <0.0002，top‑1 匹配率 89.7–100%。

5. **SPLADE 兼容性**：
   - 在 7 个 BEIR 数据集上实现 bit‑perfect 匹配，SPLADE 质量增益（0.002–0.105 nDCG@10）可在 AgentIR 速度下获得。

## 7. 优点

- **创新性**：将代理记忆检索从静态 IR 问题重新定义为工作负载自适应问题，提出统一的两轴控制表面和两级级联路由器，自动适应语料库大小、查询类型和 LLM 评判器的强弱。
- **高效性**：时间分区索引实现 O(log 1/ε) 复杂度，混合 CPU/GPU 调度最大化资源利用，整体速度比业界标准快 1–2 个数量级。
- **实用性**：系统设计为可直接嵌入现有代理栈（如 Mem0、MemGPT），提供 SPLADE 兼容性，且只需要极少的标注数据（50 样本）即可完成部署调优。
- **正确性**：详细记录并修复三个容易忽视但严重退化指标的错误，提供可复现的正确性验证。
- **实验充分性**：涵盖质量、速度、扩展性、多租户、参数敏感性、鲁棒性（字符噪声、LLM 评判器变化）等方面，统计显著性的配对 bootstrap 检验增强了结论的可靠性。

## 8. 不足与局限

- **实验覆盖**：
  - 5M 缩放实验使用合成语料（80/20 时效偏差），虽然基于 LongMemEval 真实分布，但非真实生产轨迹。真实大型代理记忆轨迹尚未公开。
  - 仅测试了英文语料，多语言或跨语言场景未涉及。
- **系统局限**：
  - 多租户实验仅在 CPU 上做了（无 GPU 共享），且没有测量跨租户的写竞争。
  - 主要评估读路径，写路径（增量添加）虽提及（时间分区适合 log‑structured merge）但未基准测试。
  - GPU top‑k 内核在 k=100 时效率下降（因共享内存容量限制），作者指出通过 bitonic sort 可改善但未实现。
- **评估偏差**：
  - LLM 评判仅使用 gpt‑4o‑mini 和 gpt‑4o，不同评判家族（Anthropic、Llama）可能产生不同排名。
  - 级联路由器延迟为解析计算而非端到端壁钟测量，虽然机制确定但仍缺少尾延迟特性评估。
- **应用限制**：
  - 需要约 50 个标注查询来训练路由器分类器，对完全没有标注数据的新部署需要初期手动标注或使用默认静态配置。
  - 当稠密通道已免费（如查询嵌入预先计算）时，级联路由器不再提供延迟收益。
- **与其他系统比较**：未与商业向量数据库（Pinecone、Milvus）直接进行端到端对比，仅引用其公开数字。
