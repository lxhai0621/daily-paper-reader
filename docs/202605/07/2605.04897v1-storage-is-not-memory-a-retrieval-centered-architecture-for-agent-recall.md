## 摘要
在摄入时进行提取是智能体记忆的错误原语：在查询已知之前丢弃的内容无法在检索时恢复。我们提出了 True Memory，这是一种六层架构，它将系统中心从存储模式转向了在逐字保留的事件上运行的多阶段检索流水线。整个系统作为单个 SQLite 文件在通用 CPU 上运行，无需外部数据库、向量索引、图存储或 GPU。在 LoCoMo（涵盖 10 个多会话对话的 1,540 个问题）上，在使用匹配的 gpt-4.1-mini 回答模型时，True Memory Pro 达到了 93.0% 的准确率（3 次运行均值），而 Mem0 为 61.4%，Supermemory 为 65.4%，Zep 约为 71%，EverMemOS 为 94.5%。在 LongMemEval（500 个问题）上，True Memory Pro 达到了 87.8%（3 次运行均值）。在 BEAM-1M（100 万 token 规模下的 700 个问题）上，True Memory Pro 达到了 76.6%（3 次运行均值），高于 Hindsight 此前发表的 73.9% 的结果。一项包含 56 种配置的消融实验显示，在性能最佳的配置族中，准确率差异仅为 1.3 个百分点。

## Abstract
Extraction at ingestion is the wrong primitive for agent memory: content discarded before the query is known cannot be recovered at retrieval time. We propose True Memory, a six-layer architecture that shifts the center of the system from a storage schema to a multi-stage retrieval pipeline operating over events preserved verbatim. The full system runs as a single SQLite file on commodity CPU with no external database, vector index, graph store, or GPU. On LoCoMo (1,540 questions across 10 multi-session conversations), True Memory Pro reaches 93.0% accuracy (3-run mean) against 61.4% for Mem0, 65.4% for Supermemory, approximately 71% for Zep, and 94.5% for EverMemOS under a matched gpt-4.1-mini answer model. On LongMemEval (500 questions), True Memory Pro reaches 87.8% (3-run mean). On BEAM-1M (700 questions at the 1-million-token scale), True Memory Pro reaches 76.6% (3-run mean), above the prior published result of 73.9% for Hindsight. A 56-configuration ablation shows a 1.3-percentage-point spread within the top-performing configuration family.

### 1. 核心问题与整体含义
*   **研究动机**：当前的智能体（Agent）记忆系统（如 Mem0, Zep 等）普遍采用“摄入时提取（Extraction at Ingestion）”的模式，即在存入信息时就将其解析为事实、知识图谱或摘要。
*   **核心矛盾**：作者认为这种模式是错误的。因为在查询（Query）发生之前，系统无法预知哪些信息是重要的。一旦在摄入阶段丢弃了细节，检索时就无法恢复。
*   **整体含义**：论文提出了 **True Memory** 架构，主张“存储不等于记忆”。它将重心从复杂的存储模式转向多阶段的检索流水线，通过**逐字保留（Verbatim Preservation）**原始对话事件，在检索时刻再进行重构和推理。

### 2. 方法论
True Memory 采用六层架构（L0-L5），分为三个时间阶段：
*   **摄入阶段（Ingestion）**：
    *   **编码门控（Encoding Gate）**：通过三个信号（新颖性 Novelty、显著性 Salience、预测误差 Prediction Error）决定是否存入事件。
    *   **逐字存储**：通过 SQLite 的 FTS5（全文搜索）和 `sqlite-vec`（向量搜索）插件，将原始文本存入 L1 消息表。
*   **后摄入批处理阶段（Post-ingestion）**：
    *   **L4 整合器**：在后台生成摘要、检测矛盾、构建时间线。
    *   **L0 记忆痕迹（Engram）**：更新用户画像和风格向量。
    *   **L5 预测编码**：计算“惊讶值（Surprise Score）”作为检索增强信号。
*   **检索阶段（Query-time）**：
    *   **混合检索**：结合 L1 词法检索和 L2 稠密向量检索。
    *   **RRF 融合**：使用加权倒数排名融合（Reciprocal Rank Fusion）合并结果。
    *   **L3 显著性重加权**：根据查询意图和用户画像调整候选权重。
    *   **交叉编码重排序（Cross-encoder Reranking）**：对前 N 个候选进行最终精排。

*   **性能领先**：True Memory Pro 在 LoCoMo 上达到 93.0% 的准确率，几乎触及了模型处理全量上下文的上限（92.99%），显著超过 Mem0 (61.4%) 和 Zep (71%)。

### 7. 优点
*   **架构创新**：挑战了主流的“摄入即提取”范式，回归认知心理学的“重构式记忆”理论。
*   **部署极其简便**：单文件 SQLite 方案，无外部数据库依赖，适合边缘计算和隐私敏感场景。
*   **可回溯性**：由于保留了原始文本，未来可以根据新需求重新计算所有评分和索引，而无需重新摄入数据。

### 8. 不足与局限
*   **门控未评测**：虽然设计了精巧的编码门控（过滤无用信息），但由于现有基准测试奖励“全量召回”，作者在实验中禁用了该功能，其在生产环境中的实际收益尚未量化。

*   **评测偏差**：使用了语义匹配裁判而非严格匹配，虽然对所有系统公平，但绝对分值可能偏高。
