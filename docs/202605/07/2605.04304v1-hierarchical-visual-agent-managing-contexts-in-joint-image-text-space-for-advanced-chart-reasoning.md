## 摘要
高级图表问答既需要对微小视觉元素的精确感知，也需要跨多个子图的多步推理。虽然现有的多模态大语言模型（MLLM）在理解单张图表方面表现出色，但在跨多个子图的多步推理中往往面临困难。我们提出了 HierVA，这是一种用于图表推理的层级化视觉智能体框架，它在图文联合空间中迭代地构建和更新工作上下文。高层管理器负责生成计划并维护仅包含关键信息的紧凑上下文，而专门的工作器则执行推理、收集证据并返回结果。特别地，该智能体维护独立的视觉和文本上下文，并使用放大工具来限制视觉上下文。在 CharXiv 推理子集上的实验表明，该方法相比强大的多模态基准模型有持续的提升，消融研究验证了层级化架构、限定范围的视觉上下文以及蒸馏后的上下文均贡献了互补的增益。

## Abstract
Advanced chart question answering requires both precise perception of small visual elements and multi-step reasoning across several subplots. While existing MLLMs are strong at understanding single plots, they often struggle with multi-step reasoning across multiple subplots. We propose HierVA, a hierarchical visual agent framework for chart reasoning that iteratively constructs and updates a working context in a joint image--text space. A high-level manager generates plans and maintains a compact context containing only key information, while specialized workers perform reasoning, gather evidence, and return results. In particular, the agent maintains separate visual and textual contexts, using a zoom-in tool to restrict the visual context. Experiments on the CharXiv reasoning subset demonstrate consistent improvements over strong multimodal baselines, and ablation studies verify that hierarchical architecture, scoped visual context, and distilled context contribute complementary gains.

### 1. 核心问题与整体含义（研究动机和背景）
论文关注的核心问题是**多模态大模型（MLLM）在处理复杂图表推理时的局限性**。
*   **研究背景**：现有的 MLLM 在理解单张简单图表上表现良好，但在面对包含多个子图（Subplots）或需要多步逻辑推理（如比较、计算差值、寻找极值）的复杂任务时效果不佳。
*   **核心挑战**：
    1.  **感知精度不足**：在全局视角下，图表中的微小元素（刻度标签、图例、密集标记）难以被准确识别。
    2.  **上下文单调增长（Monotonic Context Growth）**：现有的“带图思考”模式会不断将缩放后的局部图和中间推理文本堆叠在对话历史中，导致上下文冗余、关键信息被稀释或模型产生“遗忘”。
*   **研究动机**：提出一种像管理文本推理轨迹一样管理“图文联合空间”的机制，通过层级化架构实现证据的获取、范围限定和信息蒸馏。

### 2. 方法论：HierVA 框架
HierVA 采用**管理者-工作者（Manager-Worker）**的层级化架构，核心思想是“获取、限定范围并蒸馏证据”。

*   **层级化管理**：
    *   **管理者（Manager）**：负责全局规划。它维护一个精简的全局上下文（CM），包含原始问题、精炼后的计划以及工作者返回的**蒸馏后**的结果。
    *   **工作者（Worker）**：负责执行具体子任务。每个工作者在独立的局部上下文（CW）中运行，只接收当前步骤所需的特定图像（原图或缩放图）和指令。
*   **关键技术细节**：
    *   **两阶段规划与蒸馏**：管理者先生成高层计划，再细化为步骤列表，且仅保留最终计划，丢弃中间草稿。
    *   **自适应缩放（Adaptive Zoom）**：管理者可调用缩放工具，获取高分辨率的局部裁剪图交给工作者处理。
    *   **即时技能路由（Just-in-Time Skill Routing）**：建立技能库（如 ReadValue, FindExtremum 等），管理者根据任务动态地将技能描述注入工作者的系统提示词中，而非全部堆叠在全局上下文中。
    *   **封装与蒸馏**：工作者的详细推理过程对管理者不可见，仅返回最终的精简结论（如一个数值或一个裁剪图句柄），有效控制了 Token 消耗。

### 6. 主要结论与发现
*   **性能提升**：在 CharXiv 推理子集上，HierVA 达到 **64.2%** 的准确率，比最强的非层级化基线（Thinking w/ Images）高出 **5.3%**，比 CoT-Plan 高出 **1.8%**。
*   **视觉管理的重要性**：随着子图数量增加，所有模型性能均下降，但具备缩放和上下文管理能力的 HierVA 下降最慢。

*   **复杂任务优势**：在“寻找极值”、“比较”和“频率计数”等需要多步证据管理的任务中，HierVA 的领先优势最为明显。

### 7. 优点（亮点）
*   **架构优雅**：通过“抽象屏障”解决了多模态推理中常见的上下文爆炸问题。
*   **无需训练**：作为一种插件式的智能体框架，可以轻松适配不同的底层 MLLM。
*   **图文协同管理**：不仅管理文本轨迹，还将视觉裁剪图作为一种受控资源进行管理，这在当前研究中具有前瞻性。
*   **即时技能注入**：避免了长 System Prompt 带来的干扰，提高了工具调用的准确性。

### 8. 不足与局限
*   **底层感知依赖**：如果底层模型（如 Qwen3VL）本身无法识别缩放后的微小刻度，HierVA 的层级架构也无法挽回错误。
*   **推理延迟**：由于涉及多轮管理者与工作者的交互，且包含缩放、代码执行等步骤，其实时性（Latency）会显著低于单次推理。
*   **技能库限制**：目前的技能库（5 种）相对较小，面对更广泛的科学领域图表可能需要更复杂的技能工程。
*   **复杂性成本**：相比简单的 CoT，该框架的工程实现和 Prompt 调试复杂度更高。
