## 摘要
教语言模型使用搜索工具不仅在于它们是否进行搜索，还在于它们是否能发出高质量的查询。这在开放域问答中尤为重要，因为宽泛或复制的查询往往会浪费检索预算并干扰后续推理。我们提出了 SearchSkill，这是一个通过可重用搜索技能使查询规划显式化的框架。在每一步中，模型首先选择一项技能，然后根据所选技能卡生成搜索或回答动作。技能清单本身并非固定不变：SearchSkill 维护一个不断演进的技能库（SkillBank），根据反复出现的失败模式对其进行扩展或优化，并在监督训练前重构受影响的轨迹。由此产生的两阶段监督微调（SFT）方案将训练与推理时的协议（即先选择技能，再进行基于技能的执行）对齐。在开源和闭源模型上，SearchSkill 提高了知识密集型问答基准测试中的精确匹配率，并产生了更好的检索行为，包括更少的复制式首个查询、更多聚焦于原子跳跃（atomic hop）的查询，以及在较小搜索预算内获得更多正确答案。这些结果表明，显式的基于技能条件的查询规划是替代将搜索视为无差别动作的一种轻量化方案。

## Abstract
Teaching language models to use search tools is not only a question of whether they search, but also of whether they issue good queries. This is especially important in open-domain question answering, where broad or copied queries often waste retrieval budget and derail later reasoning. We propose \Ours, a framework that makes query planning explicit through reusable search skills. At each step, the model first selects a skill, then generates a search or answer action conditioned on the selected skill card. The skill inventory itself is not fixed: SearchSkill maintains an evolving SkillBank, expands or refines it from recurrent failure patterns, and reconstructs affected trajectories before supervised training. The resulting two-stage SFT recipe aligns training with the inference-time protocol of skill selection followed by skill-grounded execution. Across open-source and closed-source models, SearchSkill improves exact match on knowledge-intensive QA benchmarks and yields better retrieval behavior, including fewer copied first queries, more atomic hop-focused queries, and more correct answers within a small search budget. These results suggest that explicit skill-conditioned query planning is a lightweight alternative to treating search as an undifferentiated action.

### 1. 核心问题与整体含义
*   **研究动机**：虽然大语言模型（LLM）已具备使用搜索工具的能力，但现有的方法（如 RAG 或 ReAct）往往只关注模型“是否”搜索，而忽略了“如何”生成高质量查询。在多跳问答（Multi-hop QA）中，模型常因生成过于宽泛、直接复制原问题或冗余的查询，导致检索效率低下、浪费 Token 预算并干扰后续推理。
*   **核心问题**：如何通过显式的查询规划（Query Planning）和可重用的技能库，教模型更聪明地使用搜索工具，从而在复杂的知识密集型任务中实现精准检索。

### 2. 方法论
SearchSkill 框架的核心思想是将搜索过程分解为“选择-阅读-执行”的显式步骤，并引入一个动态演进的技能库（SkillBank）。

*   **核心流程（Select-Read-Act）**：
    1.  **技能选择**：模型首先输出 `<select_skill>` 标签，从技能库索引中选择一个或多个技能 ID。
    2.  **技能阅读**：系统将所选技能的详细说明（技能卡）注入上下文。
    3.  **技能执行**：模型根据技能卡指导，生成具体的 `<search>` 查询或 `<answer>` 回答。
*   **技能库演进（SkillBank Evolution）**：
    *   技能库并非静态，而是通过“失败驱动”的循环进行优化。
    *   从基础种子库（B0）开始，针对不同难度的任务（单跳到多跳）进行四轮迭代（B1-B4），通过分析模型在训练集上的失败模式，利用强模型（如 GPT-5.4）添加或精炼技能（如：桥接实体搜索、并行属性比较、时间范围提取等）。
*   **两阶段监督微调（SFT）**：
    *   **阶段 I（格式学习）**：训练模型掌握基本的 `<skill>` 声明和动作执行格式。
    *   **阶段 II（技能库对齐）**：训练模型根据技能库索引进行路由，并根据注入的技能卡内容调整后续动作。

*   **泛化性测试**：除了微调开源模型，作者还将冻结的技能库作为 Prompt 插件应用于闭源模型（GPT-4o-mini, Claude Haiku 4.5, Gemini 2.5 Flash），均取得了显著提升。

### 6. 主要结论与发现
*   **性能领先**：SearchSkill 在 7B 和 3B 模型上均刷新了平均 EM 分数，尤其在多跳任务（如 2Wiki）上大幅领先于基于强化学习的方法（Search-R1）。
*   **检索质量提升**：模型生成的查询更具“原子性”（聚焦于单一子目标），显著减少了直接复制原问题的行为。
*   **效率更高**：在更小的搜索预算（≤3 次搜索）内，SearchSkill 能够获得更多的正确答案。
*   **RL 的作用**：实验发现，在 SFT 基础上加入 GRPO 强化学习虽然对 EM 提升有限，但能显著优化模型的停止行为和证据利用率。

### 7. 优点
*   **显式规划**：将模糊的搜索动作转化为可解释的技能选择，增强了模型处理复杂问题的逻辑性。
*   **轻量高效**：相比于大规模强化学习，两阶段 SFT 方案训练成本更低，且效果更稳定。
*   **可移植性**：演进出的技能库（SkillBank）可以作为一种通用的“搜索策略手册”，直接应用于其他冻结的模型。

### 8. 不足与局限
*   **依赖强教师模型**：技能库的演进和高质量轨迹的合成高度依赖于极强模型（GPT-5.4）的指导，这可能限制了该框架在完全脱离闭源 API 环境下的自我进化。
*   **领域局限性**：目前主要集中在百科类问答任务，对于需要实时编程、多模态检索或极长文档分析的场景尚未验证。
*   **技能库规模**：随着技能数量增加，如何在有限的上下文窗口中高效组织和检索最相关的技能卡仍是一个挑战。
