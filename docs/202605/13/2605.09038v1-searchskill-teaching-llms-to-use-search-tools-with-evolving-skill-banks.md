## 摘要
教语言模型使用搜索工具不仅在于它们是否进行搜索，还在于它们是否发出了高质量的查询。这在开放域问答中尤为重要，因为宽泛或复制的查询往往会浪费检索预算并干扰后续推理。我们提出了 SearchSkill，这是一个通过可重用的搜索技能使查询规划显式化的框架。在每一步中，模型首先选择一项技能，然后根据所选的技能卡生成搜索或回答动作。技能清单本身并非固定不变：SearchSkill 维护一个不断演进的技能库（SkillBank），根据反复出现的失败模式对其进行扩展或优化，并在监督训练前重构受影响的轨迹。由此产生的两阶段监督微调（SFT）方案使训练与推理时的协议（即先选择技能，再进行基于技能的执行）保持一致。在开源和闭源模型上，SearchSkill 提高了知识密集型问答基准测试中的精确匹配率，并带来了更好的检索行为，包括更少的复制式首个查询、更多聚焦于原子跳跃（atomic hop）的查询，以及在较小搜索预算内获得更多正确答案。这些结果表明，显式的基于技能条件的查询规划是替代将搜索视为无差别动作的一种轻量化方案。

## Abstract
Teaching language models to use search tools is not only a question of whether they search, but also of whether they issue good queries. This is especially important in open-domain question answering, where broad or copied queries often waste retrieval budget and derail later reasoning. We propose \Ours, a framework that makes query planning explicit through reusable search skills. At each step, the model first selects a skill, then generates a search or answer action conditioned on the selected skill card. The skill inventory itself is not fixed: SearchSkill maintains an evolving SkillBank, expands or refines it from recurrent failure patterns, and reconstructs affected trajectories before supervised training. The resulting two-stage SFT recipe aligns training with the inference-time protocol of skill selection followed by skill-grounded execution. Across open-source and closed-source models, SearchSkill improves exact match on knowledge-intensive QA benchmarks and yields better retrieval behavior, including fewer copied first queries, more atomic hop-focused queries, and more correct answers within a small search budget. These results suggest that explicit skill-conditioned query planning is a lightweight alternative to treating search as an undifferentiated action.

### 1. 核心问题与整体含义
论文针对大语言模型（LLM）在开放域问答（Open-domain QA）中**“会搜索但搜不好”**的问题展开研究。现有的检索增强生成（RAG）或工具使用方法往往让模型直接生成查询，导致出现查询过于宽泛、直接复制原问题、检索路径冗余等现象，浪费了检索预算并干扰了后续推理。
**核心含义：** 论文提出将搜索行为从“无差别动作”转变为“显式的技能规划”。通过构建一个可演进的**技能库（SkillBank）**，让模型在搜索前先选择特定的搜索策略（如桥接实体搜索、属性对比等），从而提高检索的精准度和多步推理的效率。

### 2. 方法论
SearchSkill 框架的核心是 **“选择-阅读-执行”（Select-Read-Act）** 协议，主要包含以下关键环节：
*   **演进式技能库（Evolving SkillBank）：** 技能库并非静态，而是通过四个阶段（B0到B4）从简单到复杂逐步演进。利用 GPT-5.4 分析模型在不同难度数据集（如 NQ 到 MuSiQue）上的失败模式，不断添加或精炼技能卡片（如“桥接实体搜索”、“时间范围提取”等）。
*   **显式技能条件规划：** 模型在每一步交互时，必须先输出 `<select_skill>` 标签选择技能 ID，随后读取对应的技能卡片说明，最后再生成具体的 `<search>` 查询或 `<answer>` 回答。
*   **两阶段监督微调（SFT）方案：**
    1.  **格式学习阶段：** 教模型掌握 `<skill>` 标签和基本的搜索/回答动作格式。
    2.  **技能库对齐阶段：** 训练模型根据技能库索引进行路由，并根据选定的技能卡片内容来约束后续动作。
*   **轨迹重构：** 在技能库更新后，利用教师模型（GPT-5.4）根据新技能重构高质量的训练轨迹，确保数据的一致性。

    *   **多跳（Multi-hop）：** HotpotQA, 2WikiMultiHopQA, MuSiQue, Bamboogle。
*   **对比方法（Baselines）：**
    *   基础推理：直接推理、Chain-of-Thought (CoT)。
    *   检索增强：标准 RAG。

*   **实验模型：** 开源模型使用 Qwen2.5-3B/7B（Base 和 Instruct 版本）；闭源模型测试了 GPT-4o-mini, Gemini 2.5 Flash Lite, Claude Haiku 4.5 的迁移能力。

*   **实验规模：** 论文在 7 个主流数据集上进行了全面测试，并针对 3B 和 7B 两种参数规模的模型验证了有效性。
*   **消融实验：** 进行了多项深度消融，包括：

*   **客观性：** 实验采用了统一的检索环境（E5 检索器）和固定的搜索预算，对比了最新的强化学习（RL）搜索智能体，结果具有较高的说服力和公平性。

### 6. 主要结论与发现
*   **性能提升：** SearchSkill 在多跳问答上表现尤为出色，在 2Wiki 数据集上比强力基线（GRPO 训练的模型）高出 6.5-10.5 个百分点。
*   **检索效率：** 模型生成的查询更具“原子性”（聚焦于单一子目标），显著减少了直接复制原问题的行为，且在 3 次搜索以内的正确率（Correct@≤3）大幅提升。
*   **通用性：** 即使不进行微调，将演进后的技能库作为 Prompt 引导闭源模型，也能显著提升其搜索规划能力。
*   **RL 的作用：** 辅助的强化学习（GRPO）虽然在准确率上提升有限，但能显著优化模型的停止行为和证据利用习惯。

### 7. 优点
*   **规划显式化：** 将复杂的搜索策略拆解为可理解、可维护的“技能卡片”，增强了模型行为的可解释性。
*   **轻量高效：** 相比于大规模强化学习（如 Search-R1），SearchSkill 主要依赖 SFT，训练成本更低，效果却能持平甚至超越 RL 方法。
*   **演进机制：** 提出了一种基于失败模式自动迭代工具使用策略的闭环，具有很强的工程参考价值。

### 8. 不足与局限
*   **技能发现依赖强模型：** 技能库的演进高度依赖于更高级别的教师模型（如 GPT-5.4）进行分析和提炼，自动化程度仍有提升空间。
*   **任务局限：** 目前主要集中在问答任务，对于更复杂的长程任务（如开放式研究报告撰写）尚未验证。
*   **RL 稳定性：** 论文提到在 Base 模型上进行强化学习时存在奖励崩溃的风险，说明在技能空间内的 RL 优化仍具有挑战性。
