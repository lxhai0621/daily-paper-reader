## 摘要
随着大语言模型（LLM）应用日益复杂，开发者越来越多地采用多智能体架构，将工作流分解为专门的协作组件，从而引入了约束智能体行为并揭示有用语义可预测性的结构。与在高度动态和不确定条件下运行的传统 LLM 服务不同，这种结构化拓扑提供了减少运行时不确定性的机会——然而，现有系统未能利用这一点，将智能体工作负载视为通用流量，导致了严重的效率低下。我们对来自智能体服务平台和内部编程助手的生产轨迹分析揭示了关键瓶颈，包括低前缀缓存命中率、长上下文请求导致的严重资源争用，以及由于扩展性不佳导致的显著排队延迟。为了应对这些挑战，我们提出了 Pythia，这是一个多智能体服务系统，它通过服务层的简单接口捕获工作流语义，从而开启了新的优化机会，并相比最先进的基准系统显著提高了吞吐量和作业完成时间。

## Abstract
As LLM applications grow more complex, developers are increasingly adopting multi-agent architectures to decompose workflows into specialized, collaborative components, introducing structure that constrains agent behavior and exposes useful semantic predictability. Unlike traditional LLM serving, which operates under highly dynamic and uncertain conditions, this structured topology enables opportunities to reduce runtime uncertainty -- yet existing systems fail to exploit it, treating agentic workloads as generic traffic and incurring significant inefficiencies. Our analysis of production traces from an agent-serving platform and an internal coding assistant reveals key bottlenecks, including low prefix cache hit rates, severe resource contention from long-context requests, and substantial queuing delays due to suboptimal scaling. To address these challenges, we propose Pythia, a multi-agent serving system that captures workflow semantics through a simple interface at the serving layer, unlocking new optimization opportunities and substantially improving throughput and job completion time over state-of-the-art baselines.

### 1. 核心问题与整体含义（研究动机和背景）
*   **核心问题**：传统的 LLM 推理服务系统（如 vLLM、SGLang）基于“一切皆不可预测”的假设，将所有请求视为独立、随机的流量。然而，现代 AI 应用正转向**多智能体（Multi-Agent）架构**，这些应用具有高度的结构化特征。
*   **瓶颈分析**：研究者通过分析生产环境发现，现有系统在处理智能体负载时存在三大问题：
    1.  **缓存效率低**：不同智能体使用不同 Prompt 且调用间隔长，导致前缀缓存（Prefix Cache）频繁失效。
    2.  **资源竞争严重**：异构请求（长短不一）混合导致负载不均、内存挤兑和频繁的请求抢占。
    3.  **排队延迟高**：智能体工作流常有结构化爆发（如一个 Planner 触发多个 Executor），现有反应式扩容（Autoscaling）滞后于需求。
*   **核心思想**：利用多智能体工作流在**结构（图拓扑）**和**负载（输出长度）**上的**可预测性**，将推理服务从“被动反应”转变为“主动规划”。

### 2. 方法论：核心思想与关键技术
Pythia 通过一个轻量级接口捕获工作流语义，并实施三项主动优化：
*   **预测信息生成（Workflow Profiler）**：
    *   通过 API 扩展（`extra_body`）收集智能体身份元数据。
    *   利用**示例驱动的程序合成**技术，将执行轨迹建模为**正则表达式**，预测未来的执行路径。
    *   通过历史数据预测各智能体角色的输出长度分布。
*   **投机性缓存管理（Speculative Cache Management）**：
    *   **主动剔除**：根据预测路径，立即释放不再需要的“死亡 Token”。
    *   **前向预热**：在当前智能体生成时，提前在后台组装并预热下一个智能体所需的 KV Cache（从 L3 存储移至 L2 内存或 L1 显存）。
*   **前瞻性请求调度（Lookahead Request Scheduler）**：
    *   **统计容量路由**：利用预测长度的置信区间进行路由，在最大化利用率的同时将 OOM（显存溢出）风险控制在极低概率内。
    *   **全局优先级分配**：优先处理接近完成的工作流，或能解除下游模型阻塞的请求。
*   **相位自适应扩容（Phase-Adaptive Autoscaling）**：
    *   根据工作流图预测即将到来的负载爆发（如 Fan-out 阶段），在流量到达前提前拉起模型副本，避免冷启动延迟。

*   **实验规模**：涵盖了端到端性能对比、消融实验、敏感性分析（对负载波动性的反应）以及预测器准确性验证。

### 6. 主要结论与发现
*   **性能提升**：相比 SGLang 和 vLLM，Pythia 将平均 JCT 降低了 **1.38–2.9 倍**，吞吐量提升了 **1.12–1.96 倍**。

*   **缓存有效性**：通过投机性预热，首字延迟（TTFT）在某些场景下降低了 **25.5 倍**。
*   **预测准确性**：基于正则表达式和统计区间的预测能有效覆盖绝大多数实际运行情况，仅有极少数离群值。

### 7. 优点
*   **范式转移**：打破了 LLM 服务完全不可知的传统假设，首次系统性地利用了智能体工作流的程序化语义。
*   **全栈优化**：从网关层（预测）、引擎层（缓存/调度）到集群层（扩容）进行了协同设计。
*   **低侵入性**：通过简单的 API 扩展实现，不需要开发者重写复杂的智能体逻辑。

### 8. 不足与局限
*   **冷启动依赖**：系统依赖历史轨迹进行预测，对于全新的、从未见过的智能体工作流，初期优化效果有限（需要“影子分析”阶段）。
*   **对抗性工作流**：如果智能体行为完全随机或具有对抗性（如死循环、随机跳转），Pythia 的预测机制可能会失效甚至导致资源浪费。
*   **模型规模限制**：实验主要在中小规模模型（3B-14B）上完成，在超大规模模型（如 70B+）或极长上下文下的表现仍需进一步验证。
