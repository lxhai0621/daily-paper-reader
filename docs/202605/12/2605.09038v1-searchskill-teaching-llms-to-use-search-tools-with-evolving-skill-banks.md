## 摘要
教语言模型使用搜索工具不仅在于它们是否进行搜索，还在于它们是否发出了高质量的查询。这在开放域问答中尤为重要，因为宽泛或复制的查询往往会浪费检索预算并干扰后续推理。我们提出了 SearchSkill，这是一个通过可重用的搜索技能使查询规划显式化的框架。在每一步中，模型首先选择一项技能，然后根据所选的技能卡生成搜索或回答动作。技能清单本身并非固定不变：SearchSkill 维护一个不断演进的技能库（SkillBank），根据反复出现的失败模式对其进行扩展或优化，并在监督训练前重构受影响的轨迹。由此产生的两阶段监督微调（SFT）方案使训练与推理时的协议（即先选择技能，再进行基于技能的执行）保持一致。在开源和闭源模型上，SearchSkill 提高了知识密集型问答基准测试中的精确匹配率，并带来了更好的检索行为，包括更少的复制式首个查询、更多聚焦于原子跳跃（atomic hop）的查询，以及在较小搜索预算内获得更多正确答案。这些结果表明，显式的基于技能条件的查询规划是替代将搜索视为无差别动作的一种轻量化方案。

## Abstract
Teaching language models to use search tools is not only a question of whether they search, but also of whether they issue good queries. This is especially important in open-domain question answering, where broad or copied queries often waste retrieval budget and derail later reasoning. We propose \Ours, a framework that makes query planning explicit through reusable search skills. At each step, the model first selects a skill, then generates a search or answer action conditioned on the selected skill card. The skill inventory itself is not fixed: SearchSkill maintains an evolving SkillBank, expands or refines it from recurrent failure patterns, and reconstructs affected trajectories before supervised training. The resulting two-stage SFT recipe aligns training with the inference-time protocol of skill selection followed by skill-grounded execution. Across open-source and closed-source models, SearchSkill improves exact match on knowledge-intensive QA benchmarks and yields better retrieval behavior, including fewer copied first queries, more atomic hop-focused queries, and more correct answers within a small search budget. These results suggest that explicit skill-conditioned query planning is a lightweight alternative to treating search as an undifferentiated action.

### 1. 核心问题与研究动机
*   **核心问题**：大语言模型（LLM）在利用搜索工具解决复杂问答（QA）时，瓶颈往往不在于“是否搜索”，而在于“如何搜索”。现有模型常生成过于宽泛或直接复制问题的低质量查询，导致检索效率低下、噪声多且推理失败。
*   **研究动机**：现有的检索增强生成（RAG）或工具调用方法（如 ReAct）将搜索视为单一动作，缺乏显式的查询规划。作者希望通过引入一套可重用的“技能库”，让模型在搜索前先思考策略，从而提高多跳推理和知识获取的精准度。

### 2. 方法论
SearchSkill 框架的核心思想是将搜索过程分解为“选择-阅读-执行”三个阶段：
*   **演进式技能库（Evolving SkillBank）**：
    *   构建一个包含多种搜索技能（如：桥接实体搜索、并行属性对比、时间范围提取等）的技能库。
    *   **演进机制**：从基础种子库（B0）开始，根据模型在不同难度数据集（单跳到多跳）上的失败模式，利用 GPT-5.4 迭代地添加或精炼技能，最终形成成熟的 B4 库。
*   **Select-Read-Act 协议**：
    *   **选择（Select）**：模型首先输出 `<select_skill>` 标签，从索引中选择合适的技能 ID。
    *   **阅读（Read）**：系统将所选技能的详细说明（技能卡）反馈给模型。
    *   **执行（Act）**：模型根据技能指导，生成具体的搜索查询 `<search>` 或最终答案 `<answer>`。
*   **两阶段监督微调（SFT）**：
    *   **第一阶段**：学习基础的动作格式和基于技能的查询生成。
    *   **第二阶段**：训练模型根据技能库索引进行路由选择，并根据技能卡内容调整后续动作。

### 3. 实验设计
*   **数据集**：涵盖 7 个知识密集型问答基准。
    *   **单跳 QA**：Natural Questions (NQ), TriviaQA, PopQA。
    *   **多跳 QA**：HotpotQA, 2WikiMultiHopQA, MuSiQue, Bamboogle。
*   **对比方法**：
    *   基础方法：直接推理、Chain-of-Thought (CoT)、标准 RAG。
    *   前沿搜索智能体：Search-o1, Search-R1 (基于 RL), ZeroSearch。
*   **实验模型**：开源模型 Qwen2.5-3B/7B（Base 和 Instruct 版）；闭源模型（用于迁移测试）GPT-4o-mini, Gemini 2.5 Flash Lite, Claude Haiku 4.5。

### 4. 资源与算力
*   **硬件环境**：使用了 H20 GPU 集群。
*   **训练时长**：
    *   **SFT 阶段**：相对轻量。7B-Instruct 模型的两个阶段总计约 1.21 小时。
    *   **RL 阶段（辅助测试）**：耗时较长。7B-Instruct 的 GRPO 训练约 10.39 小时，3B 模型约 3 小时。
*   **API 开销**：数据合成阶段消耗较大，使用了约 1 亿个 GPT-5.4 token，成本约 416 美元。

### 5. 实验数量与充分性
*   **实验规模**：在 7 个主流数据集上进行了全面测试，涵盖了从 3B 到 7B 不同规模的模型，实验设置较为充分。
*   **消融实验**：进行了多项关键消融，包括“空技能库对比”、“无技能卡内容对比”、“技能类别贡献分析”，验证了技能库演进和显式引导的必要性。
*   **客观性**：通过与基于强化学习（RL）的强基准（如 Search-R1）对比，证明了 SearchSkill 仅通过 SFT 就能达到甚至超越 RL 方法的效果，且检索行为更具可解释性。

### 6. 主要结论与发现
*   **性能提升**：SearchSkill 在多跳问答上表现优异，显著超过了现有的搜索智能体。在 2Wiki 数据集上，相比 GRPO 基准提升了 6.5-10.5 个百分点。
*   **检索行为优化**：模型生成的查询更具“原子性”（聚焦于单一子目标），减少了对原始问题的盲目复制，且在更少的搜索次数内能获得正确答案。
*   **通用性**：即使不进行微调，将演进出的技能库作为 Prompt 引导闭源模型，也能显著提升它们的搜索规划能力。

### 7. 优点
*   **显式规划**：将模糊的搜索动作转化为结构化的技能选择，增强了模型处理复杂问题的逻辑性。
*   **轻量高效**：相比于昂贵的强化学习训练，该方法主要依赖高质量的 SFT 轨迹，训练成本更低。
*   **可解释性**：通过技能标签，开发者可以清晰地看到模型在搜索每一步的意图。

### 8. 不足与局限
*   **数据依赖**：技能库的演进高度依赖于强大的教师模型（如 GPT-5.4）来分析失败模式和合成轨迹。
*   **领域局限**：目前的技能库主要针对百科类问答优化，对于需要实时金融数据、代码调试或极度垂直领域的搜索技能可能覆盖不足。
*   **RL 潜力未完全挖掘**：文中提到辅助的 RL 实验并未带来巨大的准确率增益，说明在技能空间下的强化学习优化仍需更精细的奖励函数设计。
