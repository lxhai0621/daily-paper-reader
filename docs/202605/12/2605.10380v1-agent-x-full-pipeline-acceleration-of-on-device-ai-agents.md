## 摘要
基于大语言模型（LLM）的智能体在各项任务中表现出最先进的性能，但在边缘设备上会产生较高的端到端延迟。我们推出了 Agent-X，这是一个纯软件、保持准确性的框架，可加速端侧智能体工作负载的预填充（prefill）和解码（decode）阶段。Agent-X 的两个关键组件通过重写提示词来利用针对智能体特定输入 token 模式定制的前缀缓存（prefix caching），并实现无 LLM 的投机解码（speculative decoding），从而以极低的开销实现快速 token 生成。在代表性的智能体工作负载上，Agent-X 在真实系统中实现了 1.61 倍的端到端加速，且无准确率损失，并可无缝集成到现有的端侧 AI 智能体中。据我们所知，这是首个系统性地表征并消除端侧智能体延迟瓶颈的工作。

## Abstract
LLM-based agents deliver state-of-the-art performance across tasks but incur high end-to-end latency on edge devices. We introduce Agent-X, a software-only, accuracy-preserving framework that accelerates both the prefill and decode stages of on-device agent workloads. Agent-X's two key components rewrite prompts to leverage prefix caching tailored to agent-specific input-token patterns and enable LLM-free speculative decoding for fast token generation with minimal overhead. On representative agentic workloads, Agent-X achieves a 1.61x end-to-end speedup in real systems with no accuracy loss and can be seamlessly integrated into existing on-device AI agents. To the best of our knowledge, ours is the first to systematically characterize and eliminate latency bottlenecks in on-device agents.

### 2. 方法论：核心思想与关键技术
Agent-X 由两个核心组件组成，旨在不损失准确性的前提下实现加速：

*   **PromptWeaver（加速预填充阶段）**：
    *   **提示词重构**：将动态检索的工具描述改为“全包含式”的静态描述，使前缀缓存（Prefix Caching）能够覆盖更多内容。
    *   **工具共激活聚类**：利用工具调用的局部性（例如“邮件”和“联系人”常一起调用），将工具使用示例进行聚类，并离线预计算这些聚类组合的 KV 缓存存储在 SSD 中。
    *   **动态补偿**：在静态前缀后添加极少量的动态示例，以确保模型推理的准确性。
*   **ExSpec（加速解码阶段）**：
    *   **无 LLM 投机解码**：不使用额外的草稿模型（Draft Model），而是根据当前提示词和示例在线构建一个轻量级的 **n-gram 查找表（LUT）**。
    *   **选择性解码**：针对端侧框架存在的“多 token 验证税”（验证多个 token 可能比逐个生成更慢）问题，ExSpec 仅在 LUT 命中时才进行投机，否则回退到标准解码，从而规避无效开销。

*   **实验规模**：在 1,022 个测试用例上进行了端到端评估。
*   **消融实验**：针对 n-gram 的阶数（n=2,3,4）、KV 缓存的预算大小、追加动态示例的数量（K=0~4）以及 LUT 提取区域的影响进行了详细测试。
*   **充分性**：实验覆盖了准确性验证、延迟分解、存储开销分析以及在不同规模模型（如 1.1B 模型）上的泛化性测试，结果较为客观、公平。

### 6. 主要结论与发现
*   **加速效果**：Agent-X 实现了 **1.61倍** 的端到端加速。其中预填充阶段加速 **1.97倍**，解码阶段加速 **1.73倍**。
*   **准确性**：通过动态示例补偿，Agent-X 的任务执行准确率（DAG 匹配度）甚至略高于 Baseline（从 0.836 提升至 0.841）。
*   **投机解码洞察**：在端侧设备上，使用传统的小 LLM 作为草稿模型往往会因为“多 token 验证税”和模型切换开销导致减速，而基于 n-gram 的方案更具优势。

### 7. 优点
*   **全流水线优化**：不只是优化单一阶段，而是解决了端侧智能体特有的双重瓶颈。
*   **纯软件且无损**：无需硬件改动或模型重训，且不牺牲智能体的任务处理能力。
*   **系统性表征**：首次深入分析了端侧智能体 token 模式（如工具共激活局部性），为后续研究提供了数据支持。

### 8. 不足与局限
*   **存储开销**：虽然 SSD 空间相对廉价，但 6GB+ 的额外存储对于存储空间紧张的移动设备仍有一定压力。
*   **架构依赖**：该方法主要针对“先规划后执行”（Plan-out）类型的智能体架构，对于每一步都需要多次 LLM 交互的 ReAct 架构加速效果可能有所不同。
*   **工具规模**：实验主要基于 16 个工具的场景，若工具数量增加到成百上千，KV 缓存的管理和检索复杂度会进一步上升。
