## 摘要
上下文蒸馏将上下文信息压缩到模型参数中，然而现有方法往往忽略了在非预言机设置下如何存储、检索和安全激活多个蒸馏后的潜在记忆。我们将上下文蒸馏形式化为一个潜在记忆管理问题。我们将每个上下文蒸馏为一个独立的LoRA适配器，形成一个模块化的记忆库，从而实现显式的记忆选择。给定一个查询，我们的框架检索候选记忆，将查询路由到最合适的适配器，并使用自门控机制决定是否应该激活潜在记忆。为了提高效率，我们进一步引入缓存共享以减少推理过程中的管理开销。实验表明，我们的方法在检索方面显著优于基线，而自门控通过停用不必要的潜在记忆提高了鲁棒性。

## Abstract
Context distillation compresses contextual information into model parameters, yet existing methods often ignore how multiple distilled latent memories should be stored, retrieved, and safely activated in non-oracle settings. We formulate context distillation as a latent memory management problem. We distill each context into an independent LoRA adapter, forming a modular memory bank that enables explicit memory selection. Given a query, our framework retrieves candidate memories, routes the query to the most suitable adapter, and uses a Self-Gating mechanism to decide whether latent memory should be activated. To improve efficiency, we further introduce cache sharing to reduce management overhead during inference. Experiments show that our method substantially outperforms baselines with retrieval, while Self-Gating improves robustness by deactivate unnecessary latent memories.

# 论文总结：Context Distillation as Latent Memory Management

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：大型语言模型（LLM）通过将上下文放入输入窗口来实现适应，但这具有临时性，每次查询都需要重新读取上下文，长提示导致高延迟、内存消耗和生成不稳定性。上下文蒸馏（Context Distillation, CD）将上下文信息压缩到模型参数中，使模型在未来查询中无需显式上下文即可使用该信息。
- **问题**：现有上下文蒸馏方法主要关注单上下文的内部化，而忽略了如何存储、检索和安全激活多个蒸馏后的潜在记忆。实际部署不仅需要将上下文写入参数，还需要管理一组参数化记忆。目前的CD方法要么假设可以预言地访问相关蒸馏记忆（oracle setting），要么采用累积式（cumulative paradigm）将所有新上下文连续写入单个适配器。
- **累积式范式的缺陷**：
  - **严重遗忘**：新蒸馏的上下文会覆盖旧上下文，在非预言机设置下性能急剧下降。
  - **性能上限受限**：累积上下文长度和噪声累积使蒸馏模型继承教师模型对不相关累积上下文的敏感性，即使预言机设置下性能也弱于独立蒸馏。
  - **缺乏显式选择机制**：无法在多个记忆之间选择，也无法在查询不需要上下文知识时停用记忆。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
- 将上下文蒸馏重新定义为**潜在记忆管理问题**。每个上下文独立蒸馏为一个LoRA适配器，形成模块化记忆库（memory bank）。通过外部检索和内部路由选择最合适的适配器，并使用**自门控（Self-Gating）**机制决定是否激活潜在记忆，否则回退到基础模型。引入**缓存共享（Cache-Sharing）**提高训练和推理效率。

### 关键技术细节

#### 2.1 缓存共享上下文蒸馏（Cache-Sharing Context Distillation）
- 冻结基础模型 \( f_\theta \)，为每个上下文 \( c_i \) 训练一个独立的LoRA模块 \( \Delta\theta_i \)。
- 蒸馏目标：最小化教师模型（基础模型+上下文）与学生模型（基础模型+LoRA）之间的KL散度。
- **教师缓存**：预计算上下文的KV-cache并复用，避免每次训练都重新计算长上下文。
- **学生缓存**：计算查询前缀的KV-cache时只用基础模型（不加LoRA），只在生成响应时激活LoRA，实现“热插拔”（Hot-swap）——切换适配器时无需重新计算前缀缓存。

#### 2.2 自门控系统（Self-Gating）
- 观察到：当提供上下文时，ICL模型在第一个token的预测熵上对上下文相关查询和上下文无关查询存在清晰分布差距；而基础模型无此差距。
- 蒸馏后的LoRA模型继承了此熵间隙。
- 通过缓存共享可高效计算第一个token熵：
  1. 仅用基础模型处理前缀得到共享KV-cache。
  2. 临时激活LoRA模块生成第一个token的概率分布 \( p_1 \)。
  3. 计算熵 \( H(p_1) \)。
  4. 若 \( H(p_1) < \lambda \)（低熵，高置信度），则继续用LoRA生成；否则回退到基础模型（重用已计算的KV-cache）。
- 额外计算仅为一个token的LoRA前向传播，开销极小。

#### 2.3 潜在记忆检索系统（Latent Memory Retrieval）
- 采用两阶段检索：
  - **外部检索（粗粒度）**：使用现成嵌入模型编码上下文和查询，余弦相似度选出Top-K候选适配器。
  - **内部路由（细粒度）**：对每个候选适配器，计算第一个token的隐藏状态和熵，结合外部相似度，通过轻量级前馈网络（FFN）选择最终适配器。所有候选共享同一查询前缀KV-cache，评估多个LoRA的额外开销极小。

## 7. 优点
