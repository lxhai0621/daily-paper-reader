## 摘要
随着客户服务和个人助手等一系列下游应用的发展，对智能体 AI 技术的需求日益增长。对于需要智能体与人交互的应用，实时低延迟响应至关重要；例如，在语音控制应用中，通常需要低于 1 秒的延迟才能保证交互的无缝感。然而，如果要求大语言模型（LLM）进行推理并执行包含工具调用的智能体工作流，这可能会增加数秒甚至更长的延迟，这对于实时延迟敏感型应用来说是难以接受的。在本研究中，我们的目标是使具有复杂多轮工具调用的智能体也能实现实时交互。我们提出了异步 I/O（Asynchronous I/O），它将智能体核心的“推理-行动”线程与等待来自用户或环境的额外信息解耦，从而允许在等待外部延迟时重叠进行智能体处理。我们还提出了投机性工具调用（Speculative Tool Calling），作为一种在智能体尚不确定是否已接收到完整信息，或者后续是否会提供额外用户信息时管理任务执行的方法。对于强大的云端模型，我们的方法可以开箱即用地应用于现有的实时云端 API，在精度损失极小的情况下提供 1.3-1.7 倍的加速。为了在小型边缘级模型上实现实时交互，我们还提出了一种基于时钟的训练方法，使模型能够处理流式输入和异步响应，并展示了一种用于有监督微调（SFT）的合成数据生成策略。总之，该方法在多个工具调用基准测试中，使 Qwen2.5-3B-Instruct 和 Llama-3.2-3B-Instruct 模型获得了 1.6-2.2 倍的加速。

## Abstract
There is a growing demand for agentic AI technologies for a range of downstream applications like customer service and personal assistants. For applications where the agent needs to interact with a person, real-time low-latency responsiveness is required; for example, with voice-controlled applications, under 1 second of latency is typically required for the interaction to feel seamless. However, if we want the LLM to reason and execute an agentic workflow with tool calling, this can add can add several seconds or more of latency, which is prohibitive for real-time latency-sensitive applications. In our work, we aim to enable real-time interaction even for agents with complex multi-turn tool calling. We propose Asynchronous I/O, which decouples the core agent reason-and-act thread from waiting for additional information from either the user or environment, thereby allowing for overlapping agentic processing while waiting on external delays. We also propose Speculative Tool Calling as a method to manage task execution when the agent is still unsure if it has received the full information or if additional user information may later be provided. For strong cloud models, our method can be applied out-of-the-box to existing real-time cloud APIs, providing 1.3-1.7$\times$ speedups with minor accuracy loss. To enable real-time interaction with small edge-scale models, we also present a clock-based training methodology that adapts the model to handle streaming inputs and asynchronous responses, and demonstrate a synthetic data generation strategy for SFT. Altogether, this approach provides 1.6-2.2$\times$ speedups with the Qwen2.5-3B-Instruct and Llama-3.2-3B-Instruct models across multiple tool calling benchmarks.

### 1. 核心问题与研究动机
*   **研究背景**：实时交互应用（尤其是语音交互）要求亚秒级（<1s）的响应延迟。
*   **核心问题**：传统的智能体工作流是同步的，必须等待用户输入完毕才能开始推理，且在工具执行期间推理线程处于阻塞状态。复杂的“推理-行动”循环和长耗时的工具调用往往会增加数秒延迟，严重破坏交互的流畅性。
*   **研究动机**：通过技术手段实现推理、用户输入和环境反馈的并行化，使智能体能够在用户说话的同时开始思考和行动。

### 2. 论文提出的方法论
论文提出了 **AsyncIO** 框架，包含以下核心技术：
*   **异步 I/O (Asynchronous I/O)**：
    *   将智能体的推理线程与外部输入（用户流式语音、工具执行结果）解耦。
    *   引入中断机制：当新信息到达时，立即中断当前生成，将新信息注入上下文（使用 `<think interrupted>` 等标签），然后让模型继续推理。
*   **投机性工具调用 (Speculative Tool Calling)**：
    *   **早期触发**：在用户尚未说完话时，基于部分信息预先发起工具调用。
    *   **读写分离**：将工具分为“只读”（如搜索，可立即投机执行）和“写入”（如发送短信，需等待最终确认信号后执行），确保系统状态的安全性。
    *   **动态修正**：允许模型通过特定的 ID 标签修改或删除已发出的投机性工具指令。
*   **时钟感知训练 (Clock-based Training)**：
    *   为了让小型边缘模型（如 3B 参数量）掌握异步处理能力，设计了基于“时钟”（以 Token 数量衡量时间）的 SFT 训练方案。
    *   使用 TTS（语音合成）和强制对齐技术生成带有精确时间戳的合成轨迹数据，模拟真实的流式交互过程。

*   **客观性**：通过模拟真实的流式语音输入延迟和工具执行延迟，实验环境较为贴近实际应用。

### 6. 主要结论与发现
*   **显著加速**：在云端 API 上实现了 **1.3-1.7 倍** 的加速；在边缘模型上实现了 **1.6-2.2 倍** 的加速。
*   **精度保持**：在实现大幅加速的同时，模型在 HotpotQA 和 TinyAgent 上的准确率损失非常微小。
*   **训练必要性**：对于小型模型，如果不经过 Async-SFT 训练，直接使用异步推理会导致严重的格式错误或逻辑混乱。

### 7. 优点
*   **系统性创新**：不仅提出了算法，还设计了完整的一套支持依赖跟踪和任务管理的事件驱动推理框架。
*   **安全性考量**：通过“读写分离”和“提交点（Commit Point）”机制，解决了投机执行可能带来的副作用问题。
*   **端到端方案**：提供了从合成数据生成、模型训练到推理引擎优化的全栈解决方案。

### 8. 不足与局限
*   **真实口语挑战**：在处理包含大量语气词、自我纠错的自然人类指令（Human Instructions 数据集）时，准确率相比标准数据集有明显下降，且容易出现重复动作。
*   **计算浪费风险**：如果投机调用的准确率较低，频繁的撤回和修改可能会造成额外的计算资源浪费。
*   **应用限制**：目前主要针对文本/语音流，对于多模态视频流等更复杂的异步场景尚未深入探讨。
