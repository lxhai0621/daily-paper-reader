## 摘要
长期运行的自主 AI 智能体面临着一个已被广泛记录的记忆一致性问题：由于现有扁平文件记忆系统中的四种复合故障模式，在 72 小时的运行窗口内，工具执行成功率下降了 14 个百分点。我们提出了 MEMTIER，这是一种用于 OpenClaw 智能体运行时的三部分记忆架构，它引入了结构化情境 JSONL 存储、五信号加权检索引擎、注意力归因认知权重更新循环、将情境事实提升至语义层的异步整合守护进程，以及用于调整检索权重的基于 PPO 的策略框架（基础设施已验证；性能提升待定）。在包含 500 个问题的完整 LongMemEval-S 基准测试（Wu 等人，2025）中，MEMTIER 在消费级 6GB GPU 上配合 Qwen2.5-7B 实现了 Acc=0.382 和 F1=0.412，相比全上下文基线（0.050 -> 0.382，即 5% -> 38%）提升了 33 个百分点。通过 DeepSeek-V4-Flash 事实预填充，单会话召回率达到 0.686-0.714，在这些类别上超过了论文中 RAG BM25 GPT-4o 的基线（0.560）。时间推理能力提升至 0.323，多会话综合能力提升至 0.173，证明了结构化语义预填充从定性上改变了轻量级检索所能达到的效果。所有阶段均在配备 6GB GPU 的消费级笔记本电脑上本地运行。

## Abstract
Long-running autonomous AI agents suffer from a well-documented memory coherence problem: tool-execution success rates degrade 14 percentage points over 72-hour operation windows due to four compounding failure modes in existing flat-file memory systems. We present MEMTIER, a tripartite memory architecture for the OpenClaw agent runtime that introduces a structured episodic JSONL store, a five-signal weighted retrieval engine, an attention-attributed cognitive weight update loop, an asynchronous consolidation daemon promoting episodic facts to a semantic tier, and a PPO-based policy framework for adapting retrieval weights (infrastructure validated; performance gains pending camera-ready). On the full 500-question LongMemEval-S benchmark (Wu et al., 2025), MEMTIER achieves Acc=0.382, F1=0.412 with Qwen2.5-7B on a consumer 6GB GPU - a +33 percentage point improvement over the full-context baseline (0.050 -> 0.382, i.e., 5% -> 38%). With DeepSeek-V4-Flash fact pre-population, single-session recall reaches 0.686-0.714, exceeding the paper's RAG BM25 GPT-4o baseline (0.560) on those categories. Temporal reasoning rises to 0.323 and multi-session synthesis to 0.173, demonstrating that structured semantic pre-population qualitatively changes what lightweight retrieval can achieve. All phases run locally on a consumer laptop with a 6GB GPU.

## 论文详细总结（自动生成）

这篇论文介绍了一种名为 **MEMTIER** 的分层记忆架构，旨在解决长期运行的自主 AI 智能体（Agents）在记忆检索和状态保持方面的失效问题。

### 1. 核心问题与研究背景
*   **研究动机**：现有的 AI 智能体（如 OpenClaw）通常使用扁平的 Markdown 文件存储记忆。随着运行时间增加（如超过 72 小时），这种系统会出现“上下文崩溃”、压缩导致的行为中断、无法区分实体关系以及缺乏反馈闭环等问题，导致工具执行成功率下降约 14%。
*   **核心问题**：如何在受限的硬件资源下，为长期运行的智能体构建一个能够持续积累、提炼并高效检索知识的记忆系统。

### 2. 方法论
MEMTIER 提出了一个三层记忆架构及配套的优化机制：
*   **三层存储结构**：
    *   **情节层 (Episodic)**：存储原始会话日志（JSONL 格式），属于智能体私有。
    *   **语义层 (Semantic)**：通过异步守护进程提炼出的事实知识，可在项目内跨智能体共享。
    *   **程序层 (Procedural)**：存储操作流程。
*   **五信号加权检索引擎**：检索评分综合了 BM25 相关性、指数时间衰减（优先近期记忆）、认知权重（CW）、层级提升（Tier Boost）等五个维度。
*   **认知权重 (Cognitive Weight, CW) 更新**：这是一个反馈循环，根据工具执行的成功或失败，通过归因分析（如 Jaccard 相似度或 Logprob）自动增加或减少相关记忆条目的权重。
*   **两阶段检索流程**：第一阶段在语义层定位相关会话，第二阶段在特定会话的情节层进行精细检索，以减少上下文冗余。
*   **PPO 策略优化**：利用近端策略优化（PPO）算法，根据任务成功与否作为奖励信号，动态调整检索公式中各信号的权重。

### 3. 实验设计
*   **数据集/基准测试**：
    *   **LongMemEval-S**：核心基准，包含 500 个手动构建的问题，测试单会话召回、多会话综合、时间推理、知识更新等能力。
    *   **LoCoMo**：辅助基准，用于测试长对话的上下文理解。
*   **对比方法**：
    *   **Full-context 基线**：将所有历史直接塞入上下文。
    *   **RAG BM25 GPT-4o**：原论文中基于 GPT-4o 的标准检索增强生成基线。
    *   **OpenClaw 默认系统**：基于扁平文件的存储系统。

### 4. 资源与算力
*   **硬件环境**：所有实验均在**一台消费级笔记本电脑**上完成，配备单张 **6 GB 显存的 GPU**。
*   **模型使用**：主要生成模型为 **Qwen2.5-7B**；事实提炼和预填充使用了 **DeepSeek-V4-Flash**。
*   **成本**：500 个问题的处理成本极低，API 调用总费用约为 0.05 美元。

### 5. 实验数量与充分性
*   **实验规模**：针对 LongMemEval-S 的 500 个问题进行了全量测试，并进行了详细的分类统计。
*   **消融实验**：非常充分。研究者逐一移除了时间衰减、认知权重、层级提升、两阶段检索等组件，并测试了不同的检索条目数（$k$）和 Token 预算。
*   **客观性**：论文诚实地报告了在 LoCoMo 基准上“零提升”的结果，并解释了这是因为该基准测试的是上下文理解而非存储检索，体现了评价的客观性。

### 6. 主要结论与发现
*   **性能显著提升**：在 7B 模型上，MEMTIER 将准确率从 5% 提升至 38.2%，在单会话召回任务上甚至超过了使用 GPT-4o 的基线。
*   **三层不变性（核心诊断发现）**：研究发现，无论是升级更强大的生成模型（如 284B MoE），还是通过 PPO 微调检索权重，性能提升都遇到了瓶颈。这证明了**BM25 检索架构本身是当前的性能天花板**，而非模型大小或权重分配。
*   **压缩效率**：通过 LLM 提取事实，将语义层的数据量压缩了 164 倍，同时显著提升了检索的 F1 分数。

### 7. 优点
*   **架构优雅**：情节层与语义层的分离既保证了隐私，又实现了跨 Agent 的知识共享。
*   **闭环进化**：引入认知权重（CW），使记忆系统能根据实际行动的结果进行自我优化。
*   **落地性强**：证明了在极低算力（6GB 显存）下，通过精细的记忆管理，小模型也能处理长程记忆任务。

### 8. 不足与局限
*   **检索瓶颈**：线性加权检索容易被 BM25 的高分值主导，导致强化学习（PPO）调整权重的效果被掩盖。
*   **归因精度**：受限于本地硬件，未能完全发挥 Logprob 归因的潜力，目前使用的 Jaccard 相似度归因较为粗糙。
*   **复杂推理薄弱**：在需要跨多会话综合信息（0.180）和处理绝对时间推理（0.316）的任务上，得分依然较低，显示出传统检索方法的局限。
