## 摘要
随着大语言模型（LLM）智能体从孤立的工具使用者演变为协同团队，强化学习（RL）不仅必须优化单个动作，还必须优化工作的产生、委派、通信、聚合和停止方式。本文通过编排轨迹（orchestration traces）研究基于 LLM 的多智能体系统强化学习：编排轨迹是时间交互图，其事件包括子智能体产生、委派、通信、工具使用、返回、聚合和停止决策。通过这一视角，我们确定了三个技术轴。首先，奖励设计涵盖八个系列，包括针对并行加速、拆分正确性和聚合质量的编排奖励。其次，奖励和信用信号附着在从标记（token）到团队的八个信用或信号承载单元上；在我们的精选池中，显式的反事实消息级信用分配尤其稀缺。第三，编排学习分解为五个子决策：何时产生、委派给谁、如何通信、如何聚合以及何时停止。在截至 2026 年 5 月 4 日的精选池中，我们没有发现针对停止决策的显式强化学习训练方法。我们将学术方法与来自 Kimi Agent Swarm、OpenAI Codex 和 Anthropic Claude Code 的公开工业证据联系起来。由此产生的规模差距是公开报告的部署范围与开放学术评估体系之间的差距，而非对工业训练轨迹的独立验证。我们在 https://github.com/xxzcc/awesome-llm-mas-rl 发布了研究成果，包括一个包含 84 篇带标签论文的池、一个包含 32 条记录的排除日志、脚本化的语料库统计数据以及一个用于可重放编排轨迹的最小 JSON 模式。

## Abstract
As large language model (LLM) agents evolve from isolated tool users into coordinated teams, reinforcement learning (RL) must optimize not only individual actions but also how work is spawned, delegated, communicated, aggregated, and stopped. This paper studies RL for LLM-based multi-agent systems through orchestration traces: temporal interaction graphs whose events include sub-agent spawning, delegation, communication, tool use, return, aggregation, and stopping decisions.   Using this lens, we identify three technical axes. First, reward design spans eight families, including orchestration rewards for parallelism speedup, split correctness, and aggregation quality. Second, reward and credit signals attach to eight credit- or signal-bearing units from token to team; explicit counterfactual message-level credit remains especially sparse in our curated pool. Third, orchestration learning decomposes into five sub-decisions: when to spawn, whom to delegate to, how to communicate, how to aggregate, and when to stop. In our curated pool as of May 4, 2026, we found no explicit RL training method for the stopping decision.   We connect academic methods to public industrial evidence from Kimi Agent Swarm, OpenAI Codex, and Anthropic Claude Code. The resulting scale gap is a gap between publicly reported deployment envelopes and open academic evaluation regimes, not independent verification of industrial training traces. We release the artifact at https://github.com/xxzcc/awesome-llm-mas-rl, including an 84-entry tagged paper pool, a 32-record exclusion log, scripted corpus statistics, and a minimal JSON schema for replayable orchestration traces.

核心技术细节分为三个维度：
*   **奖励设计（8大系列，R1-R8）**：从团队共享结果（R1）到角色特定奖励（R3），再到新增的“编排奖励”（R7，如并行加速比、完成率）。论文指出，编排奖励在训练早期作为“脚手架”，后期需退火至零。
*   **信用分配（8个层级单元）**：信用信号从粗到细依次为：团队 $\rightarrow$ 编排者 $\rightarrow$ 角色 $\rightarrow$ 智能体 $\rightarrow$ 轮次 $\rightarrow$ 消息 $\rightarrow$ 工具调用 $\rightarrow$ Token。论文强调了“反事实消息级信用分配”的稀缺性。
*   **编排学习（5个子决策，O1-O5）**：
    *   O1：何时产生（Spawn）子智能体。
    *   O2：委派给谁（Delegate）。
    *   O3：如何通信（Communicate）。
    *   O4：如何聚合（Aggregate）结果。
    *   O5：何时停止（Stop）。
*   **数学扩展**：将传统的 Dec-POMDP 扩展为 **Dynamic-Dec-POMDP**，以适应智能体数量动态变化（产生/销毁）的场景。

### 3. 实验设计
由于这是一篇综述/分类论文，其“实验”表现为对现有文献和工业系统的深度审计：
*   **数据集/场景**：分析了包括代码生成（SWE-Bench）、Web 浏览（WebArena）、科学搜索（GAIA）、工具使用（ToolBench）等场景。
*   **Benchmark 审计**：论文提出了 MAS 原生评估的四个维度（E1-E4）：任务成功率、并行效率、协作质量、协议开销。
*   **对比对象**：对比了 84 篇核心文献（如 M-GRPO, Dr. MAS, MALT 等）以及工业界案例（Kimi K2.5/2.6, OpenAI Codex, Claude Code）。

### 4. 资源与算力
*   **论文自身**：未进行大规模模型训练，主要工作是构建了一个包含 116 条记录（84 篇保留）的精选论文池。
*   **引用的工业算力**：论文引用了 Kimi K2.5 的数据，其支持多达 100 个子智能体和 1500 个协调步骤；K2.6 扩展到 300 个智能体和 4000 个步骤。
*   **算力成本分析**：论文给出了一个 Rollout 成本公式，指出多智能体训练的壁垒在于 Rollout 成本（Token 消耗 + 工具调用延迟）远超单智能体。

### 5. 实验数量与充分性
*   **样本量**：审计了 116 项研究记录，最终保留 84 篇，涵盖了从 2024 年 Q4 到 2026 年 Q2 的几乎所有重要进展。
*   **充分性**：论文通过脚本化的元分析（Scripted Meta-analysis）生成统计数据，并提供了排除日志（Exclusion Log），体现了研究的客观性和透明度。
*   **公平性**：论文明确区分了“学术方法”与“工业证据”，指出工业界数据多来自技术博客，不可直接作为可复现的算法对比，这种区分非常严谨。

### 6. 主要结论与发现
*   **编排决策空白**：在所有调研的论文中，**没有一项研究显式地使用强化学习来训练“停止决策”（O5）**，这通常由硬编码或外部信号控制。
*   **规模差距（Scale Gap）**：学术界评估通常在 10-100 步轨迹，而工业界已达到 1000-4000 步。这种差距导致学术界可能低估了长轨迹下的“信用扩散”风险。
*   **信用分配趋势**：智能体级和角色级信用分配研究较多，但消息级和编排者级的显式信用分配仍然非常稀缺。
*   **奖励-信用对偶性**：稠密的奖励设计可以减轻信用分配的压力，反之亦然。

### 7. 优点
*   **结构化严谨**：将零散的 Agent 论文拆解为奖励、信用、决策三个清晰的分类轴。
*   **工业前瞻性**：紧密结合了 Kimi、Claude Code 等最新工业动态，使理论研究不脱离实际应用。
*   **开源贡献**：发布了包含 18 个字段的结构化论文池、JSON 模式的编排轨迹定义及验证工具，极具实用价值。

### 8. 不足与局限
*   **非穷尽性综述**：论文声明其为“精选”而非“穷尽”综述，可能存在幸存者偏差。
*   **单人标注风险**：分类标签由作者手工标注，缺乏多标注者的一致性校验。
*   **工业黑盒**：由于 OpenAI 和 Anthropic 未公开训练细节，论文对工业界的分析仅限于“部署形态”而非“训练算法”。
*   **理论深度限制**：提出的 Dynamic-Dec-POMDP 更多是作为分类工具，尚未给出严谨的收敛性证明或最优性理论。
