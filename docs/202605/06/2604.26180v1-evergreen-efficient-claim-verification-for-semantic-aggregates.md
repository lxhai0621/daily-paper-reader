## 摘要
随着近期语义查询处理引擎的发展，语义聚合已成为一种原语操作，能够利用大语言模型（LLM）将关系数据缩减为自然语言聚合结果。然而，生成的语义聚合可能包含未在底层关系中得到证实的断言。验证此类断言具有挑战性：它们通常涉及对远超 LLM 上下文窗口的关系进行量化、分组和比较，且需要结合语义与符号处理，成本高昂。我们提出了 Evergreen 系统，它将断言验证重构为一项语义查询处理任务，并配备了定制优化和溯源捕获机制。Evergreen 将每个断言编译为声明式语义验证查询，并在生成该聚合的同一引擎上执行。为了降低成本和延迟，Evergreen 通过验证感知优化（提前停止、相关性排序和基于置信序列的估计）以及语义查询的通用优化（算子融合、相似度过滤和提示词缓存）来避免不必要的 LLM 调用。每个判定结果都附带引用，用于识别证明该结果的最小元组集，其语义基于一阶逻辑的半环溯源（semiring provenance）。在反映生产环境负载的真实餐厅评论数据集基准测试中，Evergreen 在使用强 LLM 时实现了极佳的验证质量（F1 = 1.00），同时与未优化的验证相比，成本降低了 3.2 倍，延迟降低了 4.0 倍。即使使用性能显著较弱的 LLM，Evergreen 在 F1 分数上也优于强 LLM-as-a-judge 基准，且成本降低了 48 倍，延迟降低了 2.3 倍。相对于检索增强智能体，当两者都使用强 LLM 时，Evergreen 在 F1 和延迟方面表现相当且成本相近；然而，在使用弱得多的 LLM 时，它以 63 倍低的成本和 4.2 倍低的延迟实现了相同的 F1 分数。

## Abstract
With recent semantic query processing engines, semantic aggregation has become a primitive operator, enabling the reduction of a relation into a natural language aggregate using an LLM. However, the resulting semantic aggregate may contain claims that are not grounded in the underlying relation. Verifying such claims is challenging: they often involve quantifiers, groupings, and comparisons over relations that far exceed LLM context windows and require a costly combination of semantic and symbolic processing.   We present Evergreen, a system that recasts claim verification as a semantic query processing task with tailored optimizations and provenance capture. Evergreen compiles each claim into a declarative semantic verification query and executes it on the same engine that produced the aggregate. To reduce cost and latency, Evergreen avoids unnecessary LLM calls through verification-aware optimizations (early stopping, relevance sorting, and estimation with confidence sequences) and general-purpose optimizations for semantic queries (operator fusion, similarity filtering, and prompt caching). Each verdict is accompanied by citations that identify a minimal set of tuples justifying the result, with semantics based on semiring provenance for first-order logic.   On a benchmark of real-world restaurant review datasets reflecting production-inspired workloads, Evergreen achieves excellent verification quality (F1 = 1.00) with a strong LLM while reducing cost by 3.2x and latency by 4.0x compared to unoptimized verification. Even with a significantly weaker LLM, Evergreen outperforms a strong LLM-as-a-judge baseline in F1 at 48x lower cost and 2.3x lower latency. Relative to a retrieval-augmented agent, Evergreen compares favorably in F1 and latency with similar cost when both use a strong LLM; yet, with a much weaker LLM, it achieves the same F1 at 63x lower cost and 4.2x lower latency.

#### 1. 核心问题与整体含义
随着语义查询引擎（如 Snowflake Cortex）的兴起，**语义聚合（Semantic Aggregation）**已成为一种核心操作，允许用户利用大语言模型（LLM）对大规模关系数据进行总结或比较。然而，LLM 生成的聚合结果（如摘要、排名）往往包含**幻觉断言**（即未被底层数据支持的陈述）。
*   **研究动机**：验证这些断言极其困难，因为数据量通常远超 LLM 的上下文窗口，且断言往往涉及复杂的逻辑（如全称量化、分组比较和排名），单纯依靠 LLM 既昂贵又不可靠。
*   **核心目标**：开发一个既能保证验证质量，又能显著降低计算成本和延迟的系统。

#### 2. 方法论
Evergreen 的核心思想是将断言验证重构为**语义查询处理任务**，利用数据库引擎的符号处理能力结合 LLM 的语义理解能力。
*   **声明式查询编译**：系统将自然语言断言分解并编译为由标准关系算子（`filter`, `aggregate`, `join`）和语义算子（`prompt` 驱动的 `map` 和 `filter`）组成的查询计划。
*   **验证感知优化（核心技术）**：
    *   **早停机制（Early Stopping）**：对于存在性断言（找到一个证据即可）或全称断言（找到一个反例即可），一旦满足条件立即停止处理后续元组。
    *   **相关性排序（Relevance Sorting）**：利用向量嵌入和关键词搜索对元组进行预排序，使支持或反驳断言的证据尽早出现，从而触发早停。
    *   **置信序列估计（Estimation with Confidence Sequences）**：对于比例或计数断言，利用统计学中的“随时有效置信序列”进行采样估计，在达到预设置信度（如 95%）且判定结果明确时提前终止。
*   **通用语义优化**：包括算子融合（合并多个 LLM 调用）、相似度过滤（利用嵌入模型预过滤无关元组）和提示词缓存。
*   **溯源捕获（Provenance）**：基于一阶逻辑的半环溯源理论，为每个判定结果提供“最小证据集”（引用），解释为何断言成立或不成立。

*   **数据集**：使用了 Yelp 真实餐厅评论数据集的三个子集（每个约 1600 条评论，总计约 25-30 万 token）。
*   **Benchmark**：构建了一个包含 16 个多样化断言的基准测试，涵盖存在性、全称、基数（数量）、比例、序数（排名）和嵌套断言。

*   **实验规模**：针对 16 个断言在不同模型组合下进行了多次重复实验（每组 3 次试验取平均）。
*   **消融实验**：进行了详尽的“留一法”消融实验，分别验证了早停、相关性排序、置信序列、算子融合等 6 种优化手段对成本和延迟的贡献。
*   **充分性评价**：实验设计较为客观，对比了不同参数（如相似度阈值）对结果的影响，并跨越了从顶级闭源模型到轻量级开源模型的多个梯度，证明了系统的鲁棒性。虽然断言总数（16个）不算巨大，但覆盖了复杂的逻辑类型。

#### 6. 主要结论与发现
*   **高性能与低成本**：在使用强模型时，Evergreen 达到了 **1.00 的 F1 分数**，且比未优化版本成本降低 **3.2 倍**，延迟降低 **4.0 倍**。
*   **以弱胜强**：Evergreen 使用极弱的模型（如 Llama 8B）时，其验证质量仍优于使用顶级模型（如 Claude Opus）的传统 LLM-as-a-judge 方法，且成本降低了 **48 倍**。
*   **优化效果**：早停机制是性能提升的最大功臣（带来约 6.7 倍的加速），而置信序列估计在处理比例断言时表现优异。

#### 7. 优点
*   **神经符号结合**：将 LLM 限制在微观语义判断上，而将宏观逻辑和规模化处理交给优化的数据库引擎，解决了上下文窗口限制。
*   **统计学严谨性**：引入置信序列（Confidence Sequences）避免了在线聚合中的“偷看问题”（Peeking Problem），保证了统计判定的可靠性。
*   **可解释性**：通过形式化的溯源机制提供引用，增强了用户对自动验证结果的信任。

#### 8. 不足与局限
*   **断言编译依赖**：系统假设 LLM 能准确将自然语言断言编译为语义查询，虽然文中提到 16 个断言均编译正确，但在更复杂或模糊的工业场景下，编译错误可能成为瓶颈。
*   **启发式策略风险**：优化器在选择“相关性排序”还是“置信估计”时基于“断言大概率为真”的假设，如果断言为假，某些优化路径可能反而导致全表扫描。
*   **数据集规模**：实验数据集虽然超过了上下文窗口，但仍处于数千条记录的量级，对于数百万条记录的超大规模关系，其延迟表现尚待进一步验证。
