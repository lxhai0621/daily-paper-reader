## 摘要
大语言模型（LLMs）正越来越多地被探索作为信息物理系统（CPS）的高级推理引擎，然而，由于异构接口、有限的具身落地（grounding）以及对长期闭环执行的需求，其在实时无人机（UAV）集群管理中的应用仍面临挑战。本文提出了一种任务无关的、基于智能体增强的 LLM 框架用于无人机集群控制，用户以自然语言表达任务目标，系统通过具身的实时交互自主执行任务。该架构将基于 LLM 的智能体核心与模型上下文协议（MCP）网关以及基于 W3C 物联网（WoT）标准的无人机群联网抽象相结合。通过将无人机、传感器和服务暴露为标准化的 WoT 物件（Things），该框架实现了结构化的基于工具的交互、持续的状态观测和安全的动作执行，且无需依赖代码生成。我们使用基于 ArduPilot 的仿真，在四个集群任务和六个最先进的 LLM 上对该框架进行了评估。结果表明，尽管具有强大的推理能力，但在没有明确的具身落地和执行支持的情况下，当前的通用 LLM 即使在执行简单的集群任务时也难以实现可靠执行。特定任务的规划工具和运行时护栏显著提高了鲁棒性，而 Token 消耗量本身并不能反映执行质量或可靠性。

## Abstract
Large Language Models (LLMs) are increasingly explored as high-level reasoning engines for cyber-physical systems, yet their application to real-time UAV swarm management remains challenging due to heterogeneous interfaces, limited grounding, and the need for long-running closed-loop execution. This paper presents a mission-agnostic, agent-enhanced LLM framework for UAV swarm control, where users express mission objectives in natural language and the system autonomously executes them through grounded, real-time interactions. The proposed architecture combines an LLM-based Agent Core with a Model Context Protocol (MCP) gateway and a Web-of-Drones abstraction based on W3C Web of Things (WoT) standards. By exposing drones, sensors, and services as standardized WoT Things, the framework enables structured tool-based interaction, continuous state observation, and safe actuation without relying on code generation. We evaluate the framework using ArduPilot-based simulation across four swarm missions and six state-of-the-art LLMs. Results show that, despite strong reasoning abilities, current general-purpose LLMs still struggle to achieve reliable execution - even for simple swarm tasks - when operating without explicit grounding and execution support. Task-specific planning tools and runtime guardrails substantially improve robustness, while token consumption alone is not indicative of execution quality or reliability.

*   **核心问题**：现有的 LLM 机器人控制方案多依赖于一次性的“代码生成”，缺乏实时状态反馈和闭环调整能力。论文旨在探索：如何构建一个任务无关的架构，让 LLM 能够直接通过自然语言指令，在无需生成代码的情况下，实时、自主地指挥异构无人机群完成复杂任务。

### 2. 方法论：核心思想与技术细节
论文提出了一种**基于智能体增强（Agent-Enhanced）的闭环架构**，其核心组件包括：
*   **W3C 物联网（WoT）抽象层**：利用 W3C WoT 标准将每台无人机、传感器和服务抽象为“物件（Thing）”。通过“物件描述（TD）”定义其属性（如位置）、动作（如起飞）和事件，解决了硬件异构性问题。
*   **MCP（模型上下文协议）网关**：作为 LLM 与物理世界之间的唯一桥梁。它将 WoT 的能力暴露为 LLM 可调用的“工具（Tools）”，使模型能通过函数调用（Function Calling）直接操控硬件。
*   **智能体核心（Agent Core）执行循环**：
    *   **推理-执行-监测循环**：LLM 不生成代码，而是生成工具调用请求。Agent Core 执行调用并实时反馈结果（如传感器数据、执行成功与否）给模型。
    *   **运行时护栏（Guardrails）**：动态注入提示词，防止模型在任务未完成时提前终止，或在无人机未降落时尝试关闭系统。
    *   **辅助工具（Helper Tools）**：提供如“同步等待所有无人机到达”等高级封装，减轻模型的推理负担。

### 6. 主要结论与发现
*   **具身落地（Grounding）是关键**：通用 LLM 在没有标准化接口（WoT）和实时反馈的情况下，即使是简单任务也难以可靠执行。
*   **规划工具的必要性**：大多数模型在配备特定任务规划工具（如覆盖路径算法）时表现显著提升，但 GPT-5.2 在无工具时反而表现更好，显示出极强的原生几何推理能力。
*   **Token 消耗与质量无关**：实验发现 Token 消耗量（成本）与任务成功率之间没有直接正相关关系。高效的模型（如 GLM 4.7）能以更少的 Token 达成更高的成功率。
*   **模型差异**：GLM 4.7 在综合任务中表现最稳健；小规模模型（如 Qwen3 8B）在长流程任务中容易崩溃。

### 7. 优点
*   **标准化程度高**：引入 W3C WoT 和 MCP 协议，为 LLM 接入物理设备提供了一套可扩展、工业级的标准框架。
*   **无需代码生成**：通过实时函数调用避免了代码生成带来的语法错误和安全性风险，支持动态调整。
*   **安全性设计**：引入运行时护栏（Guardrails），有效解决了 LLM 容易“提前幻觉任务已完成”的顽疾。

### 8. 不足与局限
*   **仿真局限**：所有实验均在仿真环境（SITL）中完成，未在真实户外环境进行风力、通信延迟等物理干扰测试。
*   **规模限制**：实验仅针对 10 台无人机的小规模集群，未探讨更大规模（如百台级）下的 Token 窗口限制和通信拥塞问题。
*   **依赖闭源模型**：表现优秀的模型多为闭源 API，对于断网环境下的边缘侧部署（如军事或偏远地区应用）支持有限。
