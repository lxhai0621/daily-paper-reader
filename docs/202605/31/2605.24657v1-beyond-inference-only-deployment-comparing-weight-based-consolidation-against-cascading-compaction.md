## 摘要
主流的大语言模型平台以仅推理配置部署模型：模型提供服务请求，但从不更新每个用户的权重。用户必须反复重新教授偏好、修正和项目上下文，基于上下文的变通方案会消耗上下文窗口空间，并在级联压缩下性能下降。我们评估了一种替代方案：通过反思、合成以及在单个消费级GPU上进行低秩适配（LoRA）微调，将交互知识在夜间整合到模型权重中。在十次真实的软件开发对话（n = 10，三种记忆类型共1,146个测试问题）中，三轮级联压缩保留了36.8 +/- 3.0%的知识（介于11.8%的无上下文下限和90.1%的全上下文上限之间），而整合保留了80.4 +/- 1.3%——提升了43.6个百分点（配对t检验t(9) = 14.8, p < 0.001），这是压缩所保留知识的两倍以上，其中程序性修正（36.3% -> 74.6%）和情景性项目事实（31.5% -> 78.2%）的增益最大。作为方法论的附带发现，平均每令牌验证交叉熵与LLM判断的准确率呈负相关（r = -0.51），而中位数每令牌验证交叉熵几乎完全跟踪准确率（r = +0.99）：在容忍表面形式变化的评估器下，平均值具有误导性，而稳健的重尾统计量才是真实的信号。持续的个性化需要超越仅推理部署，转向将知识整合到权重中的架构。

## Abstract
Major LLM platforms deploy models in an inference-only configuration: the model serves requests but never updates per-user weights. Users must repeatedly re-teach preferences, corrections, and project context, and context-based workarounds consume context-window space and degrade under cascading compaction. We evaluate an alternative: nightly consolidation of interaction knowledge into model weights via reflection, synthesis, and Low-Rank Adaptation (LoRA) fine-tuning on a single consumer GPU. Across ten realistic software development conversations (n = 10, 1,146 test questions across three memory types), three cycles of cascading compaction retain 36.8 +/- 3.0% of knowledge (between an 11.8% no-context floor and a 90.1% full-context ceiling), while consolidation retains 80.4 +/- 1.3% -- a 43.6 pp gain (paired t(9) = 14.8, p < 0.001) that more than doubles what compaction preserves, with the largest gains on procedural corrections (36.3% -> 74.6%) and episodic project facts (31.5% -> 78.2%). As a methodological aside, mean per-token validation cross-entropy is negatively correlated with LLM-judged accuracy (r = -0.51) while median per-token validation cross-entropy tracks accuracy almost exactly (r = +0.99): under evaluators that tolerate surface-form variation, the mean is misleading and a heavy-tail-robust statistic is the faithful signal. Persistent personalization requires moving beyond inference-only deployment toward architectures that consolidate knowledge into weights.

## 1. 论文的核心问题与整体含义

- **研究动机**：主流大语言模型（LLM）平台采用“仅推理部署”模式——模型提供服务但从不更新用户权重。用户必须反复重新教授偏好、修正和项目上下文，而基于上下文的变通方案（如级联压缩）消耗上下文窗口空间且随压缩次数增加知识严重退化。长此以往，大量相关项目知识远超任何上下文窗口容量，导致模型无法持续适应用户。
- **核心挑战**：如何在不依赖上下文窗口的情况下，将每日交互中累积的事实、修正和偏好持久地存入模型参数，避免反复教学和上下文丢失。
- **整体含义**：论文主张“个性化需超越仅推理部署”，采用夜间权重整合（weight-based consolidation）替代级联压缩（cascading compaction），从而在单次对话中无需上下文也能高精度回忆用户特有知识，实现真正的持续学习。

## 2. 论文提出的方法论

### 核心思想
借鉴互补学习系统（CLS）理论：注意力机制充当快速编码系统（类似海马体），模型权重充当慢速持久存储（类似新皮层）。通过夜间三阶段管线将交互知识从上下文窗口转移到权重中，类似睡眠-觉醒周期。

### 三阶段管线
1. **反思（Reflection）**：对每段对话日志，用 Claude Sonnet 4 进行三次独立提取，按程序性、语义、情景三种记忆类型分类，得到结构化事实；三次结果合并去重。
2. **合成（Synthesis）**：对每个事实，用同一模型生成 20 种不同风格（直接、如何做、回忆、场景、否定、任务导向等）的简短用户-助手对话，形成多样化演练数据。每个底层概念最终覆盖约 40-60 组对话。
3. **训练（Training）**：在合成数据上使用 LoRA（rank=16, alpha=32）对 Qwen2.5-7B-Instruct 进行微调，训练 8 个 epoch（通过 epoch 扫描确定最优步数）。仅更新注意力投影矩阵，基础模型权重保持不变，保持预训练能力。

### 关键设计
- 使用低秩适配隔离新知识，避免灾难性遗忘。
- 训练数据为短对话形式而非原样转录，以提高泛化能力。
- 测试时模型不接收任何系统提示，完全依赖权重中的知识。

## 3. 实验设计

### 数据集/场景
- 生成 10 个真实的软件开发对话，每个约 50,000-65,000 token，涵盖 CLI 工具、数据管道、ML 框架、监控面板、Web 前端、游戏开发、DevOps、科学计算、安全扫描、分布式系统等多样项目。
- 每个对话自然包含三种记忆类型：语义（编码惯例、偏好）、程序性（bug 修正经验）、情景性（项目特有事实如端口号、配置文件路径）。

### 测试问题
- 从每个对话中提取 1,146 个可验证的测试问题（115±9 个/对话）：语义 184、程序性 154、情景性 808。
- 测试问题保持恒定，用于所有条件评估。

### 对比条件
1. **无上下文（floor）**：基础 Qwen2.5-7B-Instruct，无系统提示、无 LoRA 适配器。
2. **全上下文（ceiling）**：基础模型以原始完整对话作为系统提示。
3. **级联压缩（Compaction）**：模拟 Claude Code 实际行为，按 6:1 比例对前一轮上下文进行总结，并追加新对话（延续对话），重复三轮。测试时使用每轮压缩后的总结作为系统提示。
4. **权重整合（Consolidated）**：根据原始对话+三轮延续对话提取事实并合成训练数据，训练 LoRA 适配器，测试时无任何上下文。

### 评估方式
- 贪心解码（temperature=0），LLM 评判（Claude Sonnet 4，temperature=0）判断回答是否包含预期信息，对措辞宽松但对事实严格。

## 4. 资源与算力

- **训练耗时**：每个对话（包括所有延续）在 A100 上约 1.5 小时，在 RTX 5090 上约 8.2 小时。
- **API 调用**：事实提取和对话合成使用 Claude Sonnet 4 API。
- **总体成本估计**：若使用云端 A100 + Claude API，约 5 美元/用户-夜；若用户自有 GPU 则仅需合成 API 费用。

## 6. 论文的主要结论与发现

1. **级联压缩严重退化**：三轮压缩后仅保留 36.8% 的知识（首次压缩最破坏性，从 90.1% 降至 43.2%）。
2. **权重整合显著优势**：在无测试上下文情况下保留 80.4%，恢复 floor-ceiling 差距的 87%，是压缩保留知识的两倍以上（提升 43.6 pp）。
3. **记忆类型梯度差异**：
   - 语义知识最抗压缩（62.0%），整合几乎完全保留（94.3%）。
   - 程序性修正（36.3% -> 74.6%）、情景性事实（31.5% -> 78.2%）在压缩下损失最大，整合显著缓解。
4. **训练信号的方法论发现**：中位数每 token 验证交叉熵与 LLM 评判准确率高度正相关（r=+0.99），而均值交叉熵因受重尾 token 影响产生误导性负相关（r=-0.51），提示在容忍表面形式变化的评估器下应使用稳健统计量。
