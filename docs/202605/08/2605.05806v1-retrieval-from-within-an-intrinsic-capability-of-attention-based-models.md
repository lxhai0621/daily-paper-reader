## 摘要
检索增强生成（RAG）通常将检索和生成视为独立的系统。我们探讨了基于注意力的编码器-解码器是否可以直接从其内部表示中进行检索。我们引入了 INTRA（通过注意力的内在检索），这是一个解码器注意力查询对预编码的证据块进行评分，并将其直接重用为生成上下文的框架。通过这种构建方式，INTRA 统一了检索和生成，消除了 RAG 流水线中典型的检索器-生成器不匹配问题。该设计还通过在不同查询中重用预计算的编码器状态，分摊了上下文编码的开销。在问答基准测试中，INTRA 在证据召回率和端到端回答质量上均优于强大的工程化检索流水线。我们的结果表明，基于注意力的模型已经具备了可以被激发的检索机制，而无需作为外部模块添加。

## Abstract
Retrieval-augmented generation (RAG) typically treats retrieval and generation as separate systems. We ask whether an attention-based encoder-decoder can instead retrieve directly from its own internal representations. We introduce INTRA (INTrinsic Retrieval via Attention), a framework where decoder attention queries score pre-encoded evidence chunks that are then directly reused as context for generation. By construction, INTRA unifies retrieval and generation, eliminating the retriever-generator mismatch typical of RAG pipelines. This design also amortizes context encoding by reusing precomputed encoder states across queries. On question-answering benchmarks, INTRA outperforms strong engineered retrieval pipelines on both evidence recall and end-to-end answer quality. Our results demonstrate that attention-based models already possess a retrieval mechanism that can be elicited, rather than added as an external module.

### 1. 核心问题与整体含义（研究动机和背景）
传统的检索增强生成（RAG）架构通常将**检索器（Retriever）**和**生成器（Generator）**视为两个独立的模块。这种分离导致了两个主要问题：
*   **表示不匹配（Mismatch）**：检索器使用的向量空间（如文本嵌入）与生成器处理信息的内部表示空间不一致。
*   **计算冗余**：在标准 RAG 中，检索到的文本需要被生成器重新编码，这在处理大规模上下文时非常耗时。

本研究的核心问题是：**基于注意力的模型是否具备内在的检索能力？** 作者提出，注意力机制本质上就是一种查询驱动的信息选择机制，因此可以利用模型自身的内部表示直接进行检索，从而实现检索与生成的深度统一。

### 2. 方法论：INTRA 框架
作者提出了 **INTRA (INTrinsic Retrieval via Attention)** 框架，其核心思想是让解码器的交叉注意力查询直接对预编码的证据块（Evidence Chunks）进行评分。

*   **核心流程**：
    1.  **预编码（Encoding）**：使用冻结的编码器将语料库预先处理为 token 级别的向量表示并存储。
    2.  **检索查询（Retrieval Queries）**：在解码器输入中加入可学习的“检索标记”（Retrieval Tokens），通过解码器的前向传播生成查询向量。
    3.  **相似度评分（Late Interaction）**：采用类似 ColBERT 的 **MaxSim** 算子，计算解码器查询向量与编码器块向量之间的相似度，从而筛选出最相关的证据块。
    4.  **直接复用与生成**：被选中的块向量直接作为解码器交叉注意力的上下文，无需重新编码文本，直接生成答案。

*   **关键技术细节 (Reverse-QWK)**：
    为了解决 Transformer 各层 Key 投影矩阵不同的问题，作者发明了**反向查询-键投影（Reverse-QWK）**技术。通过将 Key 侧的线性投影转移到 Query 侧，使得所有解码层可以共享同一个标准化的编码器表示池，极大地节省了存储并允许使用高效的向量搜索索引（ANN）。

*   **语料库规模**：构建了一个包含约 75.9 万个文本块、总计 1 亿个 token 的共享检索池。

*   **存储**：10 亿 token 语料库在 8 位量化下约需 2.5 TB 存储空间（可存放在单个 NVMe SSD 上）。

### 5. 实验数量与充分性
*   **实验规模**：论文在 4 个主流数据集上进行了详尽测试，并提供了完整的召回率（Recall@k）和端到端问答指标。
*   **消融实验**：非常充分。作者测试了初始上下文选择（S0）、检索标记数量（从 1 到 64）、池化块长度（Lp）以及不同生成器兼容性对结果的影响。

### 6. 主要结论与发现
*   **性能领先**：INTRA 在多跳问答任务上表现尤为出色，其证据召回率和端到端答案质量均优于经过大规模检索数据训练的工程化流水线。
*   **内在能力**：证明了预训练的编码器-解码器模型本身就蕴含了强大的检索逻辑，只需通过极少量的参数（检索标记）即可激发。
*   **效率优势**：由于省去了检索后的文本重编码过程，INTRA 的**首字延迟（TTFT）**随检索块数量增加的增长速度远低于传统 RAG。
*   **模型对齐**：当检索器和生成器共享同一个解码器时，性能提升最明显，这说明检索过程学习到了生成器特定的“注意力偏好”。

### 7. 优点与亮点
*   **架构优雅**：消除了 RAG 中检索器和生成器之间的“表示鸿沟”，实现了真正的端到端统一。
*   **KV 缓存复用**：将静态语料库视为一种可复用的长期记忆（KV Cache），在长文本处理和高并发查询场景下具有巨大的潜力。
*   **Reverse-QWK 创新**：这是一个非常实用的工程创新，解决了 Transformer 跨层共享表示的数学障碍。

### 8. 不足与局限
*   **架构限制**：该方法依赖于编码器-解码器（Encoder-Decoder）架构，无法直接应用于目前主流的纯解码器（Decoder-only）大模型（如 Llama, GPT 系列）。
*   **存储成本**：存储 token 级别的向量表示（Embedding）比存储原始文本或压缩索引需要更多的空间。
*   **规模验证**：实验主要在亿级 token 规模上进行，尚未在万亿级（Web-scale）超大规模检索场景下验证其索引效率和冲突率。
*   **任务局限**：主要集中在短答案问答，对于长文本生成或摘要任务的检索表现尚待观察。
