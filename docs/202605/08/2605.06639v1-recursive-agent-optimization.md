## 摘要
我们引入了递归智能体优化（Recursive Agent Optimization, RAO），这是一种用于训练递归智能体的强化学习方法：递归智能体可以递归地生成自身的新实例并向其委派子任务。递归智能体实现了一种推理时扩展算法，该算法自然地允许智能体通过分而治之的方式扩展到更长的上下文，并泛化到更困难的问题。RAO 提供了一种训练模型以充分利用此类递归推理的方法，教导智能体何时以及如何进行委派和通信。我们发现，以这种方式训练的递归智能体具有更好的训练效率，能够扩展到超出模型上下文窗口的任务，泛化到比训练任务困难得多的任务，并且与单智能体系统相比，可以缩短实际运行时间。

## Abstract
We introduce Recursive Agent Optimization (RAO), a reinforcement learning approach for training recursive agents: agents that can spawn and delegate sub-tasks to new instantiations of themselves recursively. Recursive agents implement an inference-time scaling algorithm that naturally allows agents to scale to longer contexts and generalize to more difficult problems via divide-and-conquer. RAO provides a method to train models to best take advantage of such recursive inference, teaching agents when and how to delegate and communicate. We find that recursive agents trained in this way enjoy better training efficiency, can scale to tasks that go beyond the model's context window, generalize to tasks much harder than the ones the agent was trained on, and can enjoy reduced wall-clock time compared to single-agent systems.

### 2. 方法论
RAO 的核心思想是将递归执行过程建模为一个动态生成的执行树，并对树中的所有节点进行联合优化。
*   **递归智能体构建**：在 Python REPL 环境中扩展了智能体的动作空间，引入了异步函数 `launch_subagent(goal, ...)`。智能体可以像调用普通函数一样启动自身的副本。
*   **局部节点奖励（Local Node Reward）**：
    *   每个节点（智能体实例）的奖励由两部分组成：**自身任务的成功信号** + **委派奖金（Delegation Bonus）**。
    *   公式表示为：$R = \text{Success}(X) + \lambda \cdot (\text{子节点平均成功率})$。这种设计提供了密集的信用分配（Credit Assignment），鼓励有效的委派而非盲目增加子智能体数量。
*   **策略优化 objective**：
    *   **联合训练**：在递归生成的执行树的所有深度上训练同一个共享策略。
    *   **留一法基准（Leave-one-out Baseline）**：为了降低方差，使用同一根任务下不同 rollout 的根节点奖励平均值作为基准来计算优势（Advantage）。
    *   **深度频率加权**：为了防止执行树中数量较多的深层节点主导梯度更新，根据深度的出现频率进行逆频率加权。

### 6. 主要结论与发现
*   **突破上下文限制**：递归智能体即使在训练上下文很短（8K）的情况下，也能通过分块委派处理极长任务。
*   **更强的泛化能力**：递归策略比单智能体更容易泛化到比训练时更难的任务（通过增加递归深度）。

*   **训练效率**：递归结构提供了天然的课程学习（Curriculum Learning），使得模型在训练初期就能获得更有效的监督信号。

### 7. 优点
*   **端到端训练**：不同于以往的硬编码框架，RAO 真正让模型“学会”了如何组织和管理子任务。
*   **推理时扩展**：提供了一种通过增加计算量（深度和并行度）来换取性能的清晰路径。
*   **灵活性**：支持异步并行委派，能够充分利用现代计算资源的并发特性。

### 8. 不足与局限
*   **推理成本**：虽然运行时间可能缩短，但递归调用会显著增加 Token 的总消耗（尤其是在 DeepDive 这种顺序依赖的任务中）。
*   **任务异质性**：目前的实验主要集中在子任务与父任务性质相似的场景，对于需要委派给完全不同功能（如专门的验证器或检索器）的异质多智能体协作研究较少。
*   **训练开销**：在强化学习循环中进行完整的递归 rollout 成本极高，论文也提到未来需要研究更高效的代理采样程序。
