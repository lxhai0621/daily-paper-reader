## 摘要
随着大语言模型（LLM）智能体从孤立的工具使用者演变为协同团队，强化学习（RL）不仅必须优化单个动作，还必须优化工作的产生、委派、通信、聚合和停止方式。本文通过编排轨迹（orchestration traces）研究基于 LLM 的多智能体系统强化学习：编排轨迹是时间交互图，其事件包括子智能体产生、委派、通信、工具使用、返回、聚合和停止决策。通过这一视角，我们确定了三个技术轴。首先，奖励设计涵盖八个系列，包括针对并行加速、拆分正确性和聚合质量的编排奖励。其次，奖励和信用信号附着在从标记（token）到团队的八个信用或信号承载单元上；在我们的精选池中，显式的反事实消息级信用分配仍然特别稀缺。第三，编排学习分解为五个子决策：何时产生、委派给谁、如何通信、如何聚合以及何时停止。在截至 2026 年 5 月 4 日的精选池中，我们没有发现针对停止决策的显式强化学习训练方法。我们将学术方法与来自 Kimi Agent Swarm、OpenAI Codex 和 Anthropic Claude Code 的公开工业证据联系起来。由此产生的规模差距是公开报告的部署范围与开放学术评估体系之间的差距，而非对工业训练轨迹的独立验证。我们在 https://github.com/xxzcc/awesome-llm-mas-rl 发布了研究成果，包括一个包含 84 篇标注论文的池、一个包含 32 条记录的排除日志、脚本化的语料库统计数据以及一个用于可重放编排轨迹的最小 JSON 模式。

## Abstract
As large language model (LLM) agents evolve from isolated tool users into coordinated teams, reinforcement learning (RL) must optimize not only individual actions but also how work is spawned, delegated, communicated, aggregated, and stopped. This paper studies RL for LLM-based multi-agent systems through orchestration traces: temporal interaction graphs whose events include sub-agent spawning, delegation, communication, tool use, return, aggregation, and stopping decisions.   Using this lens, we identify three technical axes. First, reward design spans eight families, including orchestration rewards for parallelism speedup, split correctness, and aggregation quality. Second, reward and credit signals attach to eight credit- or signal-bearing units from token to team; explicit counterfactual message-level credit remains especially sparse in our curated pool. Third, orchestration learning decomposes into five sub-decisions: when to spawn, whom to delegate to, how to communicate, how to aggregate, and when to stop. In our curated pool as of May 4, 2026, we found no explicit RL training method for the stopping decision.   We connect academic methods to public industrial evidence from Kimi Agent Swarm, OpenAI Codex, and Anthropic Claude Code. The resulting scale gap is a gap between publicly reported deployment envelopes and open academic evaluation regimes, not independent verification of industrial training traces. We release the artifact at https://github.com/xxzcc/awesome-llm-mas-rl, including an 84-entry tagged paper pool, a 32-record exclusion log, scripted corpus statistics, and a minimal JSON schema for replayable orchestration traces.

        1.  **奖励设计（8大族群）**：从团队共享奖励（R1）到细粒度的编排奖励（R7，如并行加速比、完成率）和混合奖励（R8）。
        2.  **信用分配（8个层级）**：构建了从团队、编排器、角色、智能体、轮次、消息、工具到 Token 的信用层级。
        3.  **编排学习（5个子决策）**：明确了编排器需学习的五个核心动作：何时生成（O1）、委派给谁（O2）、如何通信（O3）、如何聚合（O4）、何时停止（O5）。
*   **算法流程**：通过编排轨迹捕捉所有交互事件，利用图结构进行价值函数估计和信用分配，解决长轨迹下的信号稀疏和“搭便车”问题。

### 3. 实验设计
该论文主要是一篇**综述与分类学研究**，其“实验”体现为对现有文献和工业系统的系统性审计。
*   **数据集 / 场景**：分析了涵盖代码生成（SWE-Bench）、Web 浏览（WebArena）、科学研究（GAIA）和工具使用（ToolBench）等领域的基准测试。
*   **Benchmark 分析**：评估了现有基准是否具备“MAS 原生性”，即是否测量了并行效率、协作质量和协议开销，而非仅仅是任务成功率。
*   **对比对象**：对比了 51 篇核心 LLM-MAS RL 论文以及 Kimi K2.5/2.6、OpenAI Codex、Anthropic Claude Code 等工业级系统。

### 4. 资源与算力
*   **算力说明**：由于本文是综述和分类学论文，**未进行大规模的模型训练**，因此未提供具体的 GPU 型号、数量或训练时长。
*   **成本分析**：论文从理论上推导了 MAS 训练的成本公式，指出多智能体 Rollout 的成本远高于单智能体，且受最慢子智能体的延迟限制。

### 5. 实验数量与充分性
*   **样本量**：论文构建了一个包含 **84 篇精选论文** 的语料库（从 116 篇候选记录中筛选），并记录了 32 条排除日志。
*   **分析维度**：对每篇论文进行了 18 个维度的标注（如奖励类型、信用粒度、编排形式等）。
*   **充分性**：通过脚本化的元分析（Meta-analysis）生成了统计数据，揭示了消息级信用分配和停止决策训练的缺失。这种基于广泛文献审计的方法对于综述类论文而言是非常充分且客观的。

### 6. 主要结论与发现
*   **信用扩散风险**：在长达 1500-4000 步的工业级轨迹中，简单的团队奖励会导致学习信号极其微弱（SNR 极低）。
*   **编排决策缺失**：在所有调研的学术方法中，**没有一个显式地通过 RL 训练“何时停止”的决策**，通常依赖硬编码或外部信号。
*   **规模鸿沟**：工业界已报告支持 300 个智能体协同，而学术界主流实验仍集中在 10 步以内的短轨迹和少量智能体。
*   **奖励与信用的对偶性**：密集的奖励设计可以减轻信用分配的压力，反之亦然。

### 7. 优点（亮点）
*   **统一的抽象**：提出的“编排轨迹”图模型为理解复杂的智能体交互提供了清晰的数学和逻辑基础。
*   **工业与学术的桥梁**：首次系统性地将 Kimi PARL 等工业技术细节与学术方法论进行对比分析。
*   **开源贡献**：发布了完整的标注论文池、排除日志以及可机器读取的 JSON Trace Schema，极具实用价值。
*   **前瞻性**：识别了 15 个开放研究问题，为后续研究指明了方向。

### 8. 不足与局限
*   **工业数据不透明**：由于工业界（如 OpenAI, Anthropic）不公开训练细节，论文对这些系统的分析仅基于公开文档和部署形态，存在推测成分。
*   **单人标注偏差**：论文由独立研究者完成，标注过程缺乏多专家交叉验证（Inter-annotator agreement）。
*   **动态性挑战**：虽然提出了 Dynamic-Dec-POMDP，但对于如何高效处理变长、变宽的图结构 Replay Buffer，文中未给出成熟的工程解决方案。
