## 摘要
AI Agent 在每个任务中执行数十到数百个链式 LLM 调用，然而目前的 GPU 调度器将每个调用视为独立的，丢弃了步骤之间数 GB 的中间状态，使端到端延迟增加了 3-8 倍。我们认为这种请求级抽象与复合 AI 工作负载根本不匹配，并提出转向程序级调度：将整个 Agent 工作流（而非单个推理调用）视为第一类可调度单元。我们提出了 SAGA，这是一种通过三种机制实现该抽象的分布式调度器：(1) Agent 执行图，用于捕获工作流结构以预测跨工具调用边界的 KV 缓存重用，其表现达到 Bélády 离线最优策略的 1.31 倍以内；(2) 带有工作窃取（work stealing）的会话亲和性批处理，在保持全局负载均衡的同时协同定位相关请求；(3) Agent 公平份额（Agent Fair Share），一种具有可证明的有界偏差保证的任务完成时间公平性指标。在运行 SWE-bench 编码 Agent 和 WebArena 浏览器任务的 64-GPU 集群上，与配备前缀缓存和亲和性路由的 vLLM v0.15.1 相比，SAGA 将任务完成时间缩短了 1.64 倍（几何平均值，p < 0.001），同时将 GPU 显存利用率提高了 1.22 倍，并在多租户干扰下实现了 99.2% 的 SLO 达成率。这些延迟收益具有量化的成本：峰值吞吐量比吞吐量最优的批处理调度低约 30%，这种权衡适用于主导复合 AI 使用的延迟敏感型交互式部署。我们的结果表明，工作流感知调度对于高效的复合 AI 服务至关重要。

## Abstract
AI agents execute tens to hundreds of chained LLM calls per task, yet GPU schedulers treat each call as independent, discarding gigabytes of intermediate state between steps and inflating end-to-end latency by 3-8x. We argue that this request-level abstraction is fundamentally mismatched to compound AI workloads, and propose a shift to program-level scheduling: treating the entire agent workflow (not individual inference calls) as the first-class schedulable unit. We present SAGA, a distributed scheduler that implements this abstraction through three mechanisms: (1) Agent Execution Graphs that capture workflow structure to predict KV cache reuse across tool-call boundaries, achieving within 1.31x of Bélády's optimal offline policy; (2) session-affinity batching with work stealing that co-locates correlated requests while maintaining global load balance; and (3) Agent Fair Share, a task-completion-time fairness metric with provable bounded-deviation guarantees. On a 64-GPU cluster serving SWE-bench coding agents and WebArena browser tasks, SAGA reduces task completion time by 1.64x (geometric mean, p < 0.001) over vLLM v0.15.1 with prefix caching and affinity routing, while improving GPU memory utilization by 1.22x and achieving 99.2% SLO attainment under multi-tenant interference. These latency gains come at a quantified cost: approximately 30% lower peak throughput than throughput-optimal batch scheduling, a tradeoff appropriate for the latency-sensitive interactive deployments that dominate compound AI usage. Our results demonstrate that workflow-aware scheduling is essential for efficient compound AI serving.

### 论文总结：SAGA：GPU 集群上 AI Agent 推理的工作流原子调度

#### 1. 核心问题与整体含义（研究动机和背景）
随着 AI Agent（如编码助手、自动化浏览器）的兴起，GPU 集群的工作负载正从“单次推理”转向“多步推理工作流”。
*   **研究动机**：现有的 LLM 推理系统（如 vLLM、Orca）采用**请求级调度**，将 Agent 的每一步调用视为独立请求。这导致在 Agent 调用外部工具（如执行代码、查询数据库）的空闲期间，系统会丢弃数 GB 的 KV 缓存。
*   **核心痛点**：当 Agent 返回下一步推理时，系统必须重新生成缓存，导致端到端延迟增加 3-8 倍，显存利用率低下。
*   **整体含义**：本文提出将调度单位从“请求”提升到“程序/工作流”级别，通过感知 Agent 的执行结构来优化资源留存。

#### 2. 方法论：核心思想与关键技术
SAGA 的核心思想是**工作流原子调度（Workflow-Atomic Scheduling）**，将整个 Agent 任务视为一个不可分割的调度单元。

*   **Agent 执行图 (AEG)**：通过框架接口或模式推理捕获 Agent 的 Thought-Action-Observation 循环结构，预测未来步骤对 KV 缓存的重用概率。
*   **工作流感知驱逐策略 (WA-LRU)**：改进传统的 LRU 算法，结合归一化的访问近期性、预测重用概率和缓存大小来决定驱逐优先级。其目标是逼近离线最优的 Bélády 算法。
*   **工具调用感知的 TTL (Time-to-Live)**：针对不同工具（代码执行、网页访问等）的延迟分布，动态设置缓存保留时间。在显存压力大时自动缩短 TTL。
*   **会话亲和性批处理与工作窃取**：全局调度器将同一会话的请求路由到同一 Worker 以复用缓存；当负载不均时，通过“工作窃取”机制和 KV 缓存迁移实现集群平衡。
*   **Agent 公平份额 (AFS)**：提出一种基于任务完成紧急程度的公平性指标，并利用 Lyapunov 漂移分析证明了其在多租户环境下的有界偏差保证。

#### 3. 实验设计
*   **数据集/场景**：
    *   **SWE-bench**：500 个真实的 GitHub 问题解决任务（编码 Agent）。
    *   **WebArena**：812 个浏览器自动化任务。
    *   **BurstGPT 衍生负载**：基于真实生产轨迹合成的多租户并发负载。
*   **对比方法 (Baselines)**：
    *   **vLLM (v0.6.0 & v0.15.1)**：包括开启了自动前缀缓存 (APC) 和亲和性路由的最强配置。
    *   **SGLang**：具有 RadixAttention 的高效推理引擎。
    *   **Llumnix**：支持动态迁移的分布式推理系统。
    *   **KVFlow**：另一种工作流感知的缓存管理系统。

#### 4. 资源与算力
*   **硬件环境**：使用了 8 个节点，每个节点配备 8 张 **NVIDIA A100-80GB GPU**，总计 **64 张 GPU**。
*   **网络连接**：节点内通过 NVLink 连接，节点间通过 200Gbps InfiniBand (GPUDirect RDMA) 连接。
*   **模型**：主要使用 **Llama-3-70B-Instruct**，采用 4 路张量并行 (TP=4)。

#### 5. 实验数量与充分性
*   **实验规模**：所有实验均重复 **10 次**并报告均值和标准差，排除了前 3 次预热运行。
*   **统计显著性**：使用了双尾 Welch's t-检验，结果显示 p < 0.001，具有极高的统计显著性。
*   **消融实验**：详细分析了会话亲和性、WA-LRU、TTL、预取、工作窃取和 AFS 各组件的贡献。
*   **敏感性分析**：对 10 多个超参数（如权重系数、阈值、TTL 上限等）进行了鲁棒性测试。
*   **充分性评价**：实验覆盖了从单任务性能到多租户公平性、从系统开销到扩展性的全方位评估，设计严谨且客观。

#### 6. 主要结论与发现
*   **延迟降低**：在 SWE-bench 和 WebArena 上，SAGA 相比 vLLM+APC 分别实现了 **1.73x** 和 **1.55x** 的任务完成时间 (TCT) 缩短（几何平均 1.64x）。
*   **显存优化**：显存利用率提升了 **1.22x**，显著减少了缓存重新生成的计算浪费。
*   **公平性保证**：在多租户干扰下，SLO 达成率高达 **99.2%**，远超基准系统的 67.3%。
*   **理论验证**：WA-LRU 的表现达到了 Bélády 离线最优策略的 **1.31x** 左右，证明了工作流感知预测的有效性。
*   **吞吐量权衡**：为了优化延迟，SAGA 的峰值吞吐量比纯吞吐量优化策略低约 **30%**，这在交互式 Agent 场景中是合理的权衡。

#### 7. 优点
*   **抽象层创新**：打破了传统的请求级调度思维，提出了“工作流原子性”这一更符合 Agent 特性的抽象。
*   **理论与工程结合**：不仅有扎实的系统实现，还提供了竞争比分析和公平性证明（Lyapunov 漂移分析）。
*   **显著的性能提升**：在 64 卡规模的真实集群上验证了大幅度的延迟削减。
*   **兼容性**：能够通过模式推理处理未标注的工作流，不强制要求修改 Agent 代码。

#### 8. 不足与局限
*   **工作流观测性依赖**：虽然有模式推理，但在完全无提示的情况下性能会下降约 12-18%；对于动态生成的复杂多 Agent 对话，预测难度较大。
*   **吞吐量代价**：不适用于非交互式的离线批处理任务，因为其核心目标是降低端到端延迟而非最大化每秒 Token 数。
*   **模型覆盖面**：实验主要集中在 Llama-3 家族，对于混合专家模型 (MoE) 或超大规模模型（如 405B）的路由和迁移开销讨论较少。
*   **单数据中心限制**：尚未解决跨数据中心或地理分布式的缓存迁移挑战。
