## 摘要
长期对话智能体必须决定将哪些对话轮次存储在外部内存中，然而最近的系统在每一轮都依赖自回归大语言模型（LLM）生成来做出该决策。我们提出了 MemRouter，这是一种写端内存路由器，它将内存准入与下游回答骨干网络解耦，并用基于嵌入的路由策略取代了逐轮的内存管理解码。MemRouter 将每一轮对话与近期上下文一起编码，通过冻结的 LLM 骨干网络投影生成的嵌入，并使用轻量级分类头预测是否应存储该轮次，仅需训练 1200 万个参数。在 LoCoMo 上的受控匹配测试对比中，在检索流水线、回答提示词和问答骨干网络（Qwen2.5-7B）保持一致的情况下，MemRouter 在每个问题类别上的表现均优于基于 LLM 的内存管理器（总 F1 分数为 52.0 对比 45.6，95% 置信区间不重叠），同时将内存管理的 p50 延迟从 970 毫秒降低到 58 毫秒。描述性析因平均进一步表明，学习到的准入机制比随机存储使平均 F1 提升了 +10.3，特定类别的提示词比通用提示词提升了 +5.2，而检索贡献了 +0.7。这些结果表明，写端内存准入可以由一个小型监督路由器学习，而回答生成在长程对话问答中仍然是一个独立的下游组件。

## Abstract
Long-term conversational agents must decide which turns to store in external memory, yet recent systems rely on autoregressive LLM generation at every turn to make that decision. We present MemRouter, a write-side memory router that decouples memory admission from the downstream answer backbone and replaces per-turn memory-management decoding with an embedding-based routing policy. MemRouter encodes each turn together with recent context, projects the resulting embeddings through a frozen LLM backbone, and predicts whether the turn should be stored using lightweight classification heads while training only 12M parameters. Under a controlled matched-harness comparison on LoCoMo, where the retrieval pipeline, answer prompts, and QA backbone (Qwen2.5-7B) are held identical, MemRouter outperforms an LLM-based memory manager on every question category (overall F1 52.0 vs 45.6, non-overlapping 95% CIs) while reducing memory-management p50 latency from 970ms to 58ms. Descriptive factorial averaging further shows that learned admission improves mean F1 by +10.3 over random storage, category-specific prompting adds +5.2 over a generic prompt, and retrieval contributes +0.7. These results suggest that write-side memory admission can be learned by a small supervised router, while answer generation remains a separate downstream component in long-horizon conversational QA.

#### 1. 核心问题与整体含义（研究动机和背景）
长期对话智能体（Long-term Conversational Agents）需要决定哪些对话轮次（Turns）值得存入外部存储器，以便后续检索。
*   **现有瓶颈**：目前的系统（如 Memory-R1, MemGPT）通常依赖 LLM 在每一轮对话中通过**自回归生成**（Autoregressive Generation）来做出存储决策（如生成 "ADD" 或 "NOOP" 指令）。这种方式导致了极高的计算开销和延迟（每一轮都要调用一次或多次 LLM 生成），且内存管理策略往往与特定的下游模型深度耦合。
*   **核心目标**：提出一种高效、解耦的“写端”内存路由器，在不牺牲准确性的前提下，将内存准入决策从昂贵的文本生成转变为廉价的嵌入空间分类。

#### 2. 方法论：核心思想与关键技术
MemRouter 的核心思想是**将内存准入视为嵌入空间的路由任务**，而非文本生成任务。其架构分为三个阶段：
*   **上下文嵌入与投影（Stage 1）**：将当前对话轮次及其历史背景划分为固定大小的块（Chunks），使用 Sentence Transformer（如 BGE）提取嵌入。通过一个两层的 MLP 投影层（约 8M 参数）将这些嵌入映射到冻结 LLM 的隐藏维度空间。
*   **骨干网络上下文处理（Stage 2）**：将投影后的嵌入序列直接输入到**冻结的 LLM 骨干网络**（如 Qwen2.5-7B）中。通过一次前向传播（Forward Pass）利用预训练模型的表征能力来捕捉对话深层语义，而无需进行逐 Token 的解码生成。
*   **操作分类（Stage 3）**：在骨干网络的输出端连接轻量级分类头（约 4M 参数），预测两个目标：
    1.  **操作类型**：ADD（存储）或 NOOP（忽略）。
    2.  **内容类型**：如事实、偏好、计划等（用于辅助训练）。
*   **训练策略**：采用监督学习（SL），利用更强大的教师模型（如 Qwen3.5-35B）自动生成轮次级别的标签。

*   **受控实验（Matched-harness）**：为了公平对比准入策略，作者设计了受控实验，使 MemRouter 与基于 LLM 的管理器在相同的检索算法、提示词和问答骨干（Qwen2.5-7B）下运行。
