## 摘要
回答大型文档集合上的复杂问题需要跨章节和文档汇集互补证据。GraphRAG提供结构化检索，但通常使用固定遍历，而智能体RAG在弱结构化接口上操作。我们的关键见解是，智能体应在文档内部和跨文档之间导航文档结构，而不是反复从头搜索。我们提出DocNavRAG，它将文档层次结构和跨区域关系组织为可导航图，暴露用于定位、导航、扩展和获取的图操作，并维护不断演化的证据状态以指导检索，直到收集到足够的证据。在四个长文档和多文档问答基准上，DocNavRAG相较于最强基线，答案质量和上下文充分性平均分别提升了7.8%和17.7%。

## Abstract
Answering complex questions over large document collections requires assembling complementary evidence across sections and documents. GraphRAG offers structured retrieval but typically uses fixed traversal, while agentic RAG operates over weakly structured interfaces. Our key insight is that agents should navigate document structure within and across documents rather than repeatedly search from scratch. We introduce DocNavRAG, which organizes document hierarchies and cross-region relations into a navigable graph, exposes graph operations for locating, navigating, expanding, and fetching, and maintains an evolving evidence state to guide retrieval until sufficient evidence is collected. Across four long- and multi-document QA benchmarks, DocNavRAG improves answer quality and context sufficiency over the strongest baseline by 7.8\% and 17.7\% on average.

## 1. 核心问题与整体含义（研究动机与背景）

- **问题定义**：复杂文档问答（Complex Document QA, CDQA）要求回答覆盖大型文档集合（如科学论文、技术手册、政府报告）的复杂问题，所需证据往往分散于多个章节和多个文档中。
- **现有方法的不足**：
  - 基础 RAG 依赖扁平化、单轮检索，检索到的片段"单独相关但集体不充分"。
  - 图 RAG（GraphRAG）虽组织文档结构，但依赖预定义的固定图遍历策略，难以根据问题的动态信息需求自适应调整证据选择。
  - 智能体 RAG（Agentic RAG）具备迭代检索能力，但其底层语料接口结构有限——要么是缺乏导航提示的扁平段落集合，要么是脆弱的 LLM 抽取知识图谱，导致代理反复进行全局查询，而非"从宽泛文档区域移动到精确证据"。
- **核心洞察**：智能体应**在文档内部及文档之间导航文档结构**，而非每次从头搜索。据此提出 DocNavRAG，将文档层次结构与跨区域关系组织为可导航图，供检索代理自适应探索。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 整体框架

DocNavRAG 为两阶段、免训练（training-free）框架：
- **离线阶段**：将源文档组织为多粒度文档图。
- **查询阶段**：检索代理通过受限的图操作接口与图交互，迭代更新检索状态，最终累积证据生成答案。

形式化流程为：

```
y = Generate(q, Select(q, Φ(D)))
```

其中 Φ 为语料组织（文档图构建），Select 为基于代理的证据构建，Generate 为答案生成。

### 2.2 文档图构建（三步骤）

**（1）文档层次恢复**
- 利用文档的布局、标题、阅读顺序恢复每篇文档的根有序层次树 T_d。
- 节点分为**段落节点**（叶子，对应源文本段落，作为证据单元）和**结构节点**（内部节点，代表章节、文档等嵌套范围）。

**（2）分级条件化节点画像（Level-conditioned Profiling）**
- 区分高层路由范围（routing scopes）与局部范围：满足子树高度 h(u) ≥ τ_h 或覆盖长度 ℓ(u) ≥ τ_ℓ 的结构节点（含文档根节点）被选为路由范围 R_d。
- 段落节点保留原文本、嵌入、结构位置；结构节点自底向上聚合子节点信号（嵌入用最大池化）。
- 仅对路由范围节点附加 LLM 生成的摘要（summary、key concepts、major subtopics），兼顾路由能力与构建成本。

**（3）图关系构建**
- **结构边** E_struct：层次边（父子关系）+ 局部邻接边（阅读顺序/结构相邻性）。
- **横向边** E_lat 四类：
  | 关系类型 | 信号 | 连接规则 |
  |---|---|---|
  | E_cite | 引用 | 引用段落及其结构祖先 → 被引文档节点 |
  | E_ent | 实体重叠 | 共享显著实体的匹配粒度节点 |
  | E_sim | 语义相似性 | 高语义相似度的匹配粒度节点 |
  | E_comm | 社区隶属 | 同一主题社区内的高层结构节点 |
- 最终图：G = (V, E)，其中 V = P ∪ S，E = E_struct ∪ E_lat。

### 2.3 基于图基质的智能体检索

**（1）四个图访问操作**：
| 操作 | 访问的图组件 | 返回 |
|---|---|---|
| LOCATE | 节点画像 | 选定粒度下的相关节点 |
| NAVIGATE | 层次边 | 更广/更窄文档范围内的节点 |
| EXPAND | 横向边 | 文档内或跨文档的相关节点 |
| FETCH | 节点-源关联 | 关联的源段落节点 |

**（2）检索状态**（每轮维护）：
```
s_t = (E_t, C_t, M_t, F_t)
```
- E_t：已保留为源证据的段落节点
- C_t：供后续探索的候选图节点
- M_t：剩余证据需求
- F_t：下一轮局部图交互所选节点（∅ 表示全图搜索）

**（3）多轮自适应图交互**（每轮三个步骤）：
1. **动作调用**：代理根据问题 q 和前一轮状态 s_{t-1} 选择动作 a_t = R(q, s_{t-1}; A)，在当前焦点范围内执行。
2. **状态更新**：
   - **结果筛选**（Screen）：与当前证据需求直接相关的段落节点纳入新证据 ΔE_t；可能支持进一步探索的节点保留为候选 ΔC_t。
   - **需求修订**（UpdateNeed）：对比问题与更新后的证据，移除已满足的需求、保留或细化未满足的需求，形成 M_t。
   - **焦点选择**（SelectFocus）：根据 M_t 从 C_t 中选择单个节点作为下一轮焦点 F_t。
3. **完成评估**：当剩余需求 M_t = ∅ 或步数预算 B 耗尽时终止，最终生成 y = Generate(q, E_T)。

## 6. 主要结论与发现

1. **整体效果**：DocNavRAG 在所有四个基准上同时超过答案质量与上下文充分性的最强基线（A-RAG），平均提升 **+7.8%**（答案质量）与 **+17.7%**（上下文充分性）。尤其 ScholarQA 的 Sufficient Context 达 0.970，大幅领先 A-RAG 的 0.818。
2. **图结构单独不总是带来收益**：对比各组最强基线，图 RAG 仅在 ScholarQA Correctness 上领先 0.1 个百分点，基础检索在多数数据集反而领先——结构本身不等于质量，关键在于如何使用。
3. **检索接口比查询自适应更重要**：从 IRCoT（迭代查询更新）→ A-RAG（层次搜索操作）→ DocNavRAG（动态图导航），性能逐步提升，代理能力受底层接口结构制约。
4. **消融的互补性**：多文档场景中层次搜索（Hierarchy Search）贡献最大（覆盖范围广的语料定位是主要挑战）；长文档场景中状态控制（State Control）与证据获取（Evidence Fetch）更关键（深度区域间的证据完整性为主）；跨源异构的 Gov 场景中横向导航（Lateral Navigation）重要性显著上升。
5. **主干泛化性**：19/24 组 Correctness 对比优于 A-RAG，平均 +2.42 点；在较弱后端（DeepSeek、Qwen-Flash、GPT-5.4-mini）上增益更大，说明检索代理的稳健性不依赖强 LLM。
6. **成本区间居中**：DocNavRAG 的 LLM 开销低于语义图构建（LightRAG）但高于轻量检索，属于"质量导向"的中间档位。

## 7. 优点

1. **核心思想新颖且务实**：将"文档原生结构"作为可导航搜索空间，而非用 LLM 抽取脆弱的知识图谱，既保留了源结构又避免了昂贵且易错的语义图构建。
2. **免训练设计**：无需训练即可部署，适配任意 LLM 后端，实用性强。
3. **状态化证据构建**：通过显式的检索状态 s_t = (E_t, C_t, M_t, F_t) 跟踪证据积累与需求缺失，实现从粗粒度路由到细粒度证据的渐进式聚焦，而非盲目的多次全局搜索。
4. **操作接口设计清晰**：四个互补图操作（定位、导航、展开、获取）覆盖了从发现到提取的完整检索周期，且动作与底层执行细节解耦。
5. **证据边界严格**：仅 FETCH 获取的源文本进入最终生成依据，防止导航性信息（如概要、轮廓）污染答案，增强可审计性。
6. **分级画像节省成本**：仅对高层路由节点生成 LLM 摘要，低层节点保持源贴近的轻量画像，在路由能力与构建成本之间取得平衡。
7. **实验分析系统全面**：消融、主干、成本三个维度均有系统分析，揭示不同语料设置下各组件的相对贡献，而非仅报整体数字。

## 8. 不足与局限

1. **适用语料范围有限**：依赖可恢复的文档原生结构（标题、布局、阅读顺序、引用），对缺乏清晰组织的动态内容、纯对话或多模态（图、表格密集型）文档支持不足（作者在 Limitations 中承认）。
2. **非完整语义知识图谱**：图本质上是"轻量检索基质"，缺少对跨文档深层语义关系的完整建模，对需要复杂推理链的问题可能力不从心。
3. **查询时开销较高**：代理式图检索增加了查询时 LLM 调用次数（总计 4118 次调用、9437 万输入 token），虽低于最贵的图构建方法但仍显著高于基础 RAG；作者未提供端到端延迟数据。
