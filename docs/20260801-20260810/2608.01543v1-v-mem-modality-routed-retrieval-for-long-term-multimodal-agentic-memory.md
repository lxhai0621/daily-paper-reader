## 摘要
用户与LLM智能体之间的交互日益多模态：对话将文本与图像交织在一起，后续问题可能针对其中任何一种。然而，大多数智能体记忆都是围绕文本设计的，即使是少数支持多模态对话的记忆系统，在面对与视觉相关的问题时仍然会失败。我们将这种失败归因于它们所依赖的相似性搜索背后的一个假设：在索引空间中，查询与能够回答该查询的相关证据在位置上接近。在多模态设置中，这种假设被两个差距打破。其一是模态差距：即使在经过训练的联合嵌入空间中，查询也与其自身模态的记忆内容更接近，而不是与另一个模态的证据更接近。其二是相似性-相关性差距：与查询最相似的内容往往不是回答该查询的证据，最明显的情况是当查询同时包含文本和图像，而它的证据与二者单独来看都不相似。我们提出了V-Mem，一个多模态智能体记忆系统，它根据查询的模态和目标证据的模态来路由检索，而这两种模态都仅从查询本身进行识别。为了跨越模态差距，V-Mem将对话组织成多轮，并从匹配的同一轮中返回目标模态的内容，而不进行跨模态比较。为了弥合相似性-相关性差距，它使用一个由LLM生成的锚点进行搜索，该锚点比查询更接近相关证据：对于寻求图像的纯文本查询，使用一个假设性标题；当证据只能通过结合文本和图像才能获得时，使用一个增强的搜索锚点，即查询文本加上从查询图像中提取的相关关键词。在Mem-Gallery上，V-Mem的LLM评判得分为0.82，而第二名仅为0.56，在包含图像的问题上差距最大（0.87，而基线均未超过0.47）；在LoCoMo上，它的得分为0.69，对比0.58。

## Abstract
Interaction between users and LLM agents is increasingly multimodal: conversations interleave text with images, and a later question may target either. Yet most agent memories are designed around text, and even the few that support multimodal conversations still fail on vision-related questions. We trace this failure to an assumption behind the similarity search they rely on: in the index space, a query lies close to the relevant evidence that answers it. In multimodal settings, two gaps break it. By the modality gap, a query lies closer to memory content of its own modality than to evidence in another, even in a trained joint embedding space. By the similarity-relevance gap, the content most similar to a query is often not the evidence that answers it, most acutely when a query carries both text and image and its evidence resembles neither part alone. We present V-Mem, a multimodal agentic memory system that routes retrieval by the modality of the query and that of the target evidence, both recognized from the query alone. To cross the modality gap, V-Mem organizes the conversation into rounds and returns the target-modality content from the same round as the match, without comparing across modalities. To close the similarity-relevance gap, it searches with an LLM-generated anchor that sits closer to the relevant evidence than the query does: a hypothetical caption for a text-only query seeking an image, and an enriched search anchor, the query text plus relevant keywords extracted from the query image, when the evidence is reachable only by combining the two. On Mem-Gallery, V-Mem reaches an LLM-judge score of 0.82 versus 0.56 for the second best, with the largest margin on questions carrying an image (0.87, no baseline above 0.47); on LoCoMo it scores 0.69 versus 0.58.

- **研究背景**：LLM 智能体在长期运行中积累了大量用户交互历史，其中文本与图像高度交织。现有 Memory-Augmented Generation（MAG）系统大多仅支持文本召回，即便少数系统声称支持多模态记忆（如 MemVerse、Omni-SimpleMem、M2A），在面对视觉相关问题（如图像检索、基于图像的事实问答）时依然失效。
- **核心问题**：论文将失败根源归结为相似性检索背后的隐含假设——在索引空间中，查询（query）与能回答它的相关证据（relevant evidence）在嵌入表示上应彼此接近。该假设在多模态场景下被两个“鸿沟”打破：
  - **模态鸿沟（Modality Gap）**：查询在嵌入空间中更接近与其同模态的记忆内容，而非异模态的证据，甚至在 CLIP/SigLIP 等联合嵌入空间中依然存在；
  - **相似性-相关性鸿沟（Similarity-Relevance Gap）**：与查询最相似的内容，往往并非能回答查询的证据，尤其在查询同时携带文本与图像、而证据与两者单独都不相似时最为突出。
- **整体含义**：长期多模态智能体记忆的难点不是缺少更强的编码器，而是检索范式的假设本身有缺陷。V-Mem 通过“按模态路由检索”重新设计了检索流程，为多模态长期记忆提供了一套无需跨模态嵌入对齐的替代方案。

## 2. 方法论

### 2.1 核心思想

V-Mem 的基本策略是：**不直接进行跨模态相似性比较**，而是借助“轮次（round）”作为跨模态纽带，并用 LLM 生成的“锚点（anchor）”替代原始查询、使其更贴近目标证据，从而分别弥合模态鸿沟与相似性-相关性鸿沟。

### 2.2 记忆表示：轮次、单元与通道

- 对话历史按轮次组织，每一轮是一个 user-assistant 交换；
- 每个文本片段或图像是一个独立的**单元（unit）**，按模态存入各自的**通道（lane）**：
  - 文本通道：稠密文本嵌入（all-MiniLM-L6-v2）+ BM25 稀疏索引（包括图像标题文本）；
  - 图像通道：原始图像的视觉嵌入（SigLIP）。
- 音频通过转写以文本形式存储；所有内容不做摘要或重写，构建成本极低。

### 2.3 路由检索（Routed Retrieval）

根据查询本身的模态（是否附带了图像）和推断出的目标模态，分为四种情况：

| 查询模态 → 目标模态 | 激活的通道 | 搜索锚点 |
|---|---|---|
| text → text | 仅文本通道 | 原始查询文本 |
| image+text → image | 仅图像通道 | 查询图像本身 |
| text → image | 限制在含图像的轮次内激活文本通道 + 图像标题通道 | LLM 生成的**假设性标题（hypo-caption）** |
| image+text → text | 文本通道 + 图像通道 | **增强锚点**：查询文本 + 从查询图像中提取的关键词 |

### 2.4 两大核心机制

- **跨轮匹配（Matching through Shared Rounds）**：避免跨模态比较的一种途径。当目标证据与查询不同模态时，V-Mem 只在查询自身模态的通道内匹配，找到最佳匹配轮次后，从同一轮中返回目标模态内容。同一轮内的文本与图像天然相关，因此无须学习任何跨模态对齐。两个跨模态情况均如此处理：
  - text → image：在文本通道内（限定为有图像的轮次）匹配，返回匹配轮中的图像；
  - image+text → text：用查询图像匹配存储图像，返回匹配轮中的文本。
- **LLM 生成锚点（Generated Anchor）**：
  - text → image 时，用 LLM 生成目标图像“应有”的假设性标题，替代原始查询与存储图像的标题匹配；计数类问题则跳过此步骤（因为无单一图像可描述）；
  - image+text → text 时，用视觉 LLM 从查询图像中提取最可能出现在答案中的关键词（最多 8 个），追加到查询文本之后形成增强锚点，从而找到与图像和文本单独都不相似、但两者结合才能命中的证据。

### 2.5 排序、融合与上下文组装

- 每个信号（稠密、稀疏、视觉）按余弦相似度或 BM25 对单元打分；
- 轮次得分取该轮下最高单元分；跨信号融合采用**倒数排名融合（Reciprocal Rank Fusion, RRF）**，避免不同量纲信号失衡；
- 返回每轮时附上其 ±1 相邻轮，合并为时间有序的连续块（相邻轮通常延续同一主题，补充证据）；
- 聚合类问题（如“讨论过多少次/哪些内容”，LoCoMo 上启用）则放弃邻轮并扩大返回轮数（k=12 → 30）。

### 2.6 算法流程（文字版）

输入查询后，先由关键字规则识别（查询模态，目标模态）对 → 决定激活哪些通道（Lc）、在哪些单元上搜索（Uc,ℓ）、用什么锚点搜索（ac,ℓ(q)）→ 每个通道对候选单元打分 → RRF 将各通道排名融合 → 每轮取最高分 → 返回 top-k 轮及其邻轮（聚合问题除外）。整个过程除锚点生成外，路由决策均由无 LLM 调用的关键字规则完成。

## 6. 主要结论与发现

- **V-Mem 在多模态与文本基准上均显著领先**：Mem-Gallery 总分 0.825，远超 Omni 的 0.561；LoCoMo 上 0.690 vs 0.583。32B 主干下结论稳定（0.829 vs 0.628），视觉类差距扩大至 0.912。
- **图像查询是最大优势区**：TTL 类目（携带新图像的问题）上 V-Mem 达 0.872，所有基线均低于 0.472；VR 类 0.575 对比次好的 0.273。
- **机制有效性定位明确**：跨轮匹配是整个设计贡献最大的步骤（总体 +0.129，TTL +0.182、VR +0.181、VS +0.154）；路由与生成锚点各自在类别层面起作用，而非总体均值层面。
- **零 LLM token 构建**：不做摘要/抽取的记忆构建方式不仅成本极低，而且保持历史原貌，让检索期选择成为可能。
- **文本检索不因多模态设计而受损**：V-Mem 在纯文本 LoCoMo 上超过纯文本的 A-Mem，多跳推理（multi-hop）与图式记忆系统打平（0.550 vs 0.555），无需构建图结构。

## 7. 优点

- **问题诊断深刻**：将视觉问答失败明确定位为相似性检索的两个假设盲点（模态鸿沟 + 相似性-相关性鸿沟），而非简单归因于编码器不够强，为后续研究提供了清晰的概念框架。
- **设计简洁且可解释**：跨轮匹配无需训练跨模态对齐；路由决策全由关键词规则完成（零 LLM 调用）；每个设计决策都有针对性实验支撑。
- **构建路径极高效**：提取式基线花费数百万至数十亿 token 构建记忆，V-Mem 保持原始对话、本地编码、零 LLM 调用，秒级完成，且构建成本不随历史增长而累积。
- **实验规范性强**：统一主干/编码器/评判模型、官方评判提示、固定超参数、paired bootstrap + 置换检验、如实呈现失败场景（小主干实验、误差审计），可信度高。
- **诚实报告局限**：包括 LLM-judge 与词法指标在 LoCoMo 上方向相反、7B 下的排名倒转、生成锚点的额外推理成本等，均被明确讨论而非回避。

## 8. 不足与局限

- **对主干模型能力高度依赖**：V-Mem 返回的是“证据周围的上下文”而非经过压缩的单元摘要，需要回答模型从上下文自行定位答案；在 7B 小模型上，额外上下文反成噪声，导致其被 Omni 反超。这限制了 V-Mem 在弱模型场景下的适用性。
- **生成锚点的成本非零**：每个视觉问题都需要视觉 LLM 调用（提取关键词），每次 text →image 问题也需额外生成假设性标题——虽然少于基线的构建成本，但增加了回答延迟和 token 消耗。
- **在 LoCoMo 的词法指标上不占优**：V-Mem 的回答更简洁，在 F1/BLEU/EM 上落后于 Omni（虽然 LLM 判断语义正确性时更占优）；开放域类目下优于所有基线之外的 M2A 仍领先。
- **统计显著性的边界**：整体得分的优势来自“共享轮次”一环，路由与锚点生成在总体均值上不显著；其价值主要在特定类别层面体现，严格来说这两步的泛化收益需要更大规模验证。
- **范围限制**：仅覆盖图像+文本的会话记忆；音频仅作转写文本处理，视频完全未涉及；多模态检索的额外模态（音视频作为一等检索对象）尚无实验。
- **图像嵌入选择未验证专用模型**：SigLIP 与 DINOv2 交换差异仅 -0.003，结论是“通用对比编码器够用”，但该结论只在当前基准规模下成立。
- **应用限制**：路由的关键词规则依赖具体语言表述（如 counting cues、image 识别词），对不同语言与表述风格的泛化性未测试；所依赖的 gpt-4o-mini 为 API 模型，评判与生成可能受模型更新影响。
