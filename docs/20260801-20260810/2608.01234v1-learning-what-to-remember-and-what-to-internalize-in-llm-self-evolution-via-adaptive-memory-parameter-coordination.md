## 摘要
大语言模型智能体越来越多地在动态环境中运行，其中工具接口、API和用户需求在部署后会发生变化。现有的自我进化方法主要遵循两种范式：基于框架的方法，将反馈外部化为可编辑的记忆或技能以快速适应；以及基于参数的方法，将经验内化为模型参数以实现更深层次的能力提升。然而，单独使用任一机制都会在灵活性和性能之间产生权衡。本文探讨智能体如何协调两个渠道以实现稳健的自我进化。我们提出了COVE，一个统一的智能体自我进化框架，通过任务感知路由、阶段感知调度和知识优化，将基于框架和基于参数的学习相结合。通过这种设计，COVE将自我进化视为一个协调过程，而非经验的 indiscriminate 积累，该过程将任务和知识类型与适当的学习机制相匹配。跨多个任务类别的实验表明，COVE优于单通道进化策略，在变化环境下展现出更稳健和高效的改进。

## Abstract
Large language model agents increasingly operate in dynamic environments where tool interfaces, APIs, and user requirements change after deployment. Existing self-evolution methods mainly follow two paradigms: harness-based approaches, which externalize feedback into editable memories or skills for rapid adaptation, and parameter-based approaches, which internalize experience into model parameters for deeper capability improvement. However, using either mechanism alone creates a trade-off between flexibility and performance. This paper asks how an agent can coordinate both channels to achieve robust self-evolution. We present COVE, a unified agent self-evolution framework that combines harness-based and parameter-based learning through task-aware routing, stage-aware scheduling, and knowledge optimization. Through this design, COVE treats self-evolution not as indiscriminate accumulation of experience, but as a coordinated process that matches tasks and knowledge types to appropriate learning mechanisms. Experiments across multiple task categories show that COVE outperforms single-channel evolution strategies, demonstrating more robust and efficient improvement under changing environments.

## 1. 核心问题与整体含义

- **背景与动机**：LLM 智能体已从被动文本生成器发展为能够规划、调用工具、编写代码和执行多步推理的交互式系统。然而部署后外部环境持续变化——API 更新、数据库 schema 改变、新库出现、领域惯例变化、用户引入未预见的任务——导致智能体需要频繁重新配置或重训练，成本高昂。
- **现有两类自进化范式各有不足**：
  - **基于框架（Harness-based）**：如 Evo-Memory、Reflexion、Voyager，将反馈外部化为可编辑的记忆或技能，推理时检索注入。优点是快速、适应变化的任务表面；缺点是当基础模型缺乏解释反馈的能力时，会产生误导性或不可用的经验，且无法形成深层操作能力（如 Lean 定理证明中语法错误不降反增）。
  - **基于参数（Parameter-based）**：如 WizardLM、Self-Challenging，通过 SFT 或 RL 将经验内化为模型权重。优点是能内化深层策略和领域推理模式；缺点是成本高、适应慢，对常规的表面知识更新（如 API 名称）属于“杀鸡用牛刀”，且会导致模型对变化的接口变得脆弱。
- **核心研究问题**：智能体如何协调两种通道——什么经验应该“记住”（留在外部记忆），什么经验应该“内化”（写入参数）——以实现稳健的自进化。
- **论文的关键洞察**：自进化不是经验的 indiscriminate 积累，而是一个需要按**任务类型**、**学习阶段**和**知识波动性**来匹配学习机制的协调过程。

## 2. 方法论：COVE 框架

论文提出 **COVE（Channel Orchestrated Volatility-aware Evolution）**，一个统一的自进化框架，包含三个核心机制：

- **任务感知路由（Task-aware Router）**：
  - 将每个任务路由到合适的进化通道，决策基于任务描述和反馈（结果状态、标量分数、诊断信息）。
  - 使用受约束的 judge 模型输出结构化决策记录 \(d_i = (m_i, s_i, r_i)\)，其中通道 \(m_i \in \{\text{harness\_only}, \text{parametric\_candidate}, \text{hybrid}\}\)，\(s_i\) 为短描述符（如 `dynamic_tool`、`logical_rigor`），\(r_i\) 为单句理由。
  - 关键发现：路由不是按任务标签硬分类，而是按知识类型。例如 MATH 中已有模型能推理的样本被路由到 harness 通道，避免参数训练浪费；TableQA 则因表格操作模式可复用而获得较大参数侧份额，但列名/schema 波动部分留在 harness 侧。

- **阶段感知调度（Stage-aware Scheduler）**：
  - 动态决定何时从 harness 探索转向参数训练，由三条件触发：
    - **性能平台期**：窗口 \(w\) 内奖励改进低于阈值 \(\epsilon\)；
    - **数据充分性**：高质量轨迹数 \(|\mathcal{D}_q| \ge N\)；
    - **冷启动失败**：任务族前 \(k\) 个任务成功率低于阈值 \(\tau_c\)，此时需先参数更新建立基础能力。
  - 支持两条路径：harness-first（先探索积累数据再参数化内化）和 param-first（冷启动时先参数训练让 harness 探索变得有效）。

- **KnowledgePO：双模态知识优化**：
  - 为每条知识条目标注波动性标签 \(\ell(c) \in \{\text{volatile}, \text{stable}, \text{strategic}\}\)；反复修正的条目会被升级为 `volatile`。
  - **记忆辅助参数训练（Memory-aware Rollout）**：volatile 知识用 `<volatile>...</volatile>` 标记，rollout 时检索 top-k 记忆注入上下文，提高轨迹质量；训练时对 volatile 条目施加**反背诵奖励（Anti-Recitation Reward）**，将 volatile 名称随机重命名，若模型调用过时或未观察到的 volatile 名称则惩罚：\(R = R_{\text{task}} - \lambda \cdot \mathbb{I}[\text{uses stale or unobserved volatile name}]\)，迫使模型“读当前条目再行动”而非“记住并重复”。
  - **记忆释放（Memory Release）**：训练后对 stable 记忆进行 A/B 测试，若移除后性能下降低于阈值则标记为已内化，从在线检索集释放；volatile 记忆永不释放。这保持知识库精简，避免上下文膨胀和检索噪声。

## 6. 主要结论与发现

- **单一通道进化不可靠**：
  - Lean 定理证明中，harness 记忆累积再多，成功率提升不足 3%，编译器错误类型无一致下降；
  - TableQA 参数化进化在 API 重命名后成功率从 40.5% 降至 16.5%，API 调用正确率从 96.5% 降至 54.0%。
- **通道选择依赖任务与阶段**：
  - 任务层面：易变任务（API 变化）需要 harness 侧灵活记忆；能力受限任务（Lean 形式证明）需要参数侧学习。
  - 阶段层面：平台期触发的参数更新优于持续参数训练和仅 harness 进化，说明“何时训练”本身是关键决策。
- **知识波动性是存储位置的关键判据**：
  - 高频但易变的接口知识不应内化；稳定原则（如可复用证明策略）应参数化内化。
  - 反背诵奖励显著提升 rename 下的 API 正确率（92.5%），且不损害原分布表现；错误分解显示标准微调模型失败主要在 API 选择步骤，而抗背诵模型失败主要在任务推理之后。
- **COVE 的总体效果**：
  - 在 Lean4、APPS、HotpotQA、MATH 上取得最佳成功率，TableQA 上竞争力较强（50.0 vs. Parametric-only 47.0）；
  - 相比 Parametric-only，训练 token 减少 86%；
  - 路由消融显示 COVE 用 Always-Both 的 16% token 成本达到 65.0 的平均性能，效率（28.83）远高于 Always-Both（4.89）和 Random-Route（8.82）；
  - 在 hybrid 子集上 COVE 获 24.1% 成功率，优于 Base（15.6%）和 Parametric-only（21.3%），说明双通道联合训练在路由识别出的“双通道样本”上收益最大。

## 8. 不足与局限

- **模型覆盖单一**：所有主实验基于 Qwen3-8B，未验证在更大模型（如 70B）或多系列模型（GPT、DeepSeek）上的表现；Router backbone 一致性验证用了多模型，但主进化流程未覆盖。

- **Self-Challenging 基线复现偏差风险**：原文无官方实现，论文自行复现，可能低估或高估其性能；token 平摊方式为按任务摊销，其客观性存在讨论空间。

- **抗背诵机制的依赖**：依赖对知识波动性的自动标注质量，若波动性标签判断错误（如将 stable 知识误标为 volatile），可能阻碍有用的参数内化。
