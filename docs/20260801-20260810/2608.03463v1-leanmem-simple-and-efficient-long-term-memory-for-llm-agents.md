## 摘要
长期记忆对于基于LLM的代理维持交互并可靠利用遥远历史至关重要。然而，现有记忆系统通常通过统一的摘要和检索流程处理异构对话内容，导致要么过度消耗Token，要么不可逆地丢失细粒度证据。我们认为，历史对话内容应根据其可压缩性、时间动态性和保真度要求区别处理。基于这一见解，我们提出LeanMem，一个轻量级长期记忆框架。LeanMem首先过滤掉低价值内容，然后将有信息量的片段根据信息性质存储为紧凑的档案记忆、时间结构化的事件记忆或基于来源的记录记忆。在维护期间，仅选择性地更新动态演化的事件记忆，避免对稳定的档案和不可变的记录进行冗余整合。在推理期间，LeanMem根据查询特定的证据需求动态选择记忆类型并分配检索预算，按需组装相关证据。在LoCoMo和LongMemEval-S上，使用GPT-4.1-mini和Qwen3-8B，LeanMem在每种设置下都比最强的基于记忆的基线提高了准确性，最高提升15.1个百分点，同时构建成本、推理Token和延迟均为最低或接近最低。代码和数据集包含在补充材料中。

## Abstract
Long-term memory is essential for LLM-based agents to sustain interactions and reliably leverage distant history. However, existing memory systems typically process heterogeneous dialogue content through a uniform summarization and retrieval pipeline, leading to either excessive token consumption or irreversible loss of fine-grained evidence. We argue that historical dialogue content should be handled differently according to its compressibility, temporal dynamics, and fidelity requirements. Based on this insight, we propose LeanMem, a lightweight long-term memory framework. LeanMem first filters out low-value content, then stores informative segments as compact profile memory, temporally structured event memory, or source-grounded record memory, depending on the nature of the information. During maintenance, only dynamically evolving event memories are selectively updated, avoiding redundant consolidation of stable profiles and immutable records. During inference, LeanMem dynamically selects memory types and allocates retrieval budgets according to query-specific evidence demands, assembling relevant evidence on demand. On LoCoMo and LongMemEval-S with GPT-4.1-mini and Qwen3-8B, LeanMem improves accuracy over the strongest memory-based baseline in every setting, by up to 15.1 points, at the lowest or near-lowest construction cost, inference tokens, and latency. The code and datasets are included in the supplementary materials.

## 1. 论文的核心问题与整体含义

**研究动机：**
- 基于LLM的智能体在进行长期交互时，受限于固定上下文窗口和不可靠的远期历史访问能力，需要借助**长期记忆（Long-Term Memory）**机制来维持持久状态、积累用户知识并支持未来决策。
- 现有记忆系统通常对**异构对话内容（heterogeneous dialogue content）**采用**统一的摘要和检索流水线**（uniform summarization and retrieval pipeline）处理，导致两种核心问题：
  - **效率问题**：对每个对话块反复调用LLM进行摘要和更新，消耗大量构建Token；
  - **保真度问题**：激进的压缩会不可逆地丢失日后可能需要的细粒度证据（如列表、计划、时间线等）。
- 由此形成"效率—保真度"之间的**两难困境（efficiency-fidelity trade-off）**：处理更多上下文可保留更多证据，但增加Token成本；压缩更激进可降低成本，但会丢失未来查询所需信息。

**核心论点：**
论文明确提出：**对话信息在可压缩性（compressibility）、时间动态性（temporal dynamics）和保真度要求（fidelity requirements）上存在本质差异**，不应一刀切地统一处理。因此，一个高效记忆系统应首先判断"是否值得存储"，再根据信息类型匹配合适的存储形态。

## 2. 方法论：核心思想、关键技术细节与流程

### 核心思想

LeanMem 将记忆构建视为"受控写入过程"（controlled writing process），依据信息的三项属性——**稳定性、时间依赖性、保真度要求**——将对话内容分类写入三种异构记忆，并在推理时按查询需求动态组装证据。

### 三大关键阶段

#### （1）受控记忆写入（Controlled Memory Writing）

分三个子步骤：

- **关键话语过滤（Key Utterance Filtering）**：基于规则过滤结构性低信息量的轮次（问候、确认、重述等）。由于用户话语通常承载需求、偏好和状态变化，仅以用户话语作为路由锚点，助手回复不独立保留但其语境信息仍可通过原始对话访问。
- **话题分段（Topic Segmentation）**：以语义连贯的话题段而非单轮或整会话为基本构建单元。利用相邻话语的余弦相似度计算"谷底深度"：

  \[
  d_i = \frac{1}{w}\sum_{j=1}^{w} s_{i-j} + \frac{1}{w}\sum_{j=1}^{w} s_{i+j} - 2s_i
  \]

  自适应用边界阈值 \(\tau = \mu_D + 0.05\sigma_D\)，选取局部最大值且满足阈值的谷底位置作为话题边界。

- **写调度（Write Scheduling）**：LLM调度器评估每个片段的三维属性，按预定义优先级（时间依赖优先于稳定，高保真要求覆盖压缩表示）将片段路由到四种动作之一：
  - **ignore**：无需长期存储的内容（如临时请求）；
  - **profile（档案记忆）**：稳定可结构化的用户属性和偏好，直接存储调度器提取的属性-值对，**无需额外LLM调用**；
  - **event（事件记忆）**：随时间变化的状态信息，仅保留事件主题\(e_i\)、时间锚点\(t_i\)和状态描述\(z_i\)三个字段；
  - **record（记录记忆）**：信息密集、不能安全压缩的内容，仅生成简短检索摘要\(g_i\)，用轻量GLiNER模型提取关键词/实体集\(\kappa_i\)，并保留原始对话源指针\(p_i = I_i\)，以便追溯。

#### （2）选择性记忆演化（Selective Memory Evolution）

- **仅对事件记忆进行演化**，档案记忆（稳定）和记录记忆（不可变）不参与整合，避免冗余消耗。
- 通过**延迟更新**解耦写入与演化：新事件先进入缓冲区，达到预定义容量才触发整合，将多次更新分摊为一次LLM调用。
- 演化时按主题检索相关事件记忆，按时间锚点排序，由LLM增量推断最新状态——新增证据、修正状态或扩展时间线，无需全局重建。

#### （3）自适应证据组装（Adaptive Evidence Composition）

- 推理时先用LLM规划器分析查询的证据粒度、时间依赖、保真度和聚合范围，生成检索计划：

  \[
  \pi_q = \langle C_q, d_q, M_q, w_q, k_q \rangle
  \]

  其中 \(C_q\) 为实体/属性/时间/关系约束，\(M_q\) 为所需记忆类型集合，\(w_q\) 为各类型权重（和为1），\(k_q\) 为各类型检索深度。

- 按计划从各类记忆中检索top-\(k^c_q\)候选，然后按重排公式：

  \[
  score(q, m) = w^c_q [Rel_c(q, m) + Match(C_q, m)]
  \]

  进行重排，同时考虑类型相关性、查询约束匹配度和查询对该记忆类型的依赖权重。

- 按证据角色组装：档案条目提供稳定用户上下文、事件条目按时间排序呈现状态迁移、记录指针仅在需要细粒度证据时展开到原始对话片段——而非简单拼接全局top-k列表。

## 6. 主要结论与发现

1. **联合效果—效率优势**：相比最强记忆基线，LeanMem在GPT-4.1-mini/Qwen3-8B下将LoCoMo准确率提升5.54/5.84个百分点，将LongMemEval-S准确率提升15.07/2.80个百分点，同时构建成本降低26.8%/22.2%（LoCoMo）。
2. **成本大幅削减**：在LongMemEval-S上仅需117.61K构建Token，而A-Mem消耗超过1330K Token（约11.3倍）；推理Token和延迟也保持在最低或接近最低水平。
3. **分类型获益异质**：LoCoMo上Single-Hop和Open-Domain的大幅提升验证了profile与record记忆的价值；Temporal和Multi-Hop问题的提升验证了event记忆与自适应证据组装的效果。LongMemEval-S上Multi-Session、Temporal Reasoning和Knowledge Update的显著提升直接支持"选择性事件演化"与"自适应检索"的设计。
4. **跨骨干稳健**：Qwen3-8B上呈现相同趋势，说明增益主要来自记忆设计本身而非特定骨干模型。
5. **每个组件都不可或缺**：消融中移除存储调度导致最大准确率下降（72.79 vs 84.87），验证了"最小充分表示"是证据保留与效率的核心。

## 7. 优点

1. **洞察深刻、问题切中要害**：识别出"统一压缩与异构对话内容不匹配"这一被忽视的根本性问题，并据此提出分类处理的解决思路；
