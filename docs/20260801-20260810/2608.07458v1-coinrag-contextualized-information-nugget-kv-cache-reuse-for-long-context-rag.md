## 摘要
近期关于检索增强生成（RAG）的优化研究利用块级KV缓存复用来避免处理长检索上下文以提高效率，但粗粒度块中仍存在显著的信息冗余和噪声。本文通过提出CoinRAG（面向长上下文RAG的上下文信息片段KV缓存复用），在低预填充延迟约束下优化帕累托前沿，同时最大化准确性。该名称隐喻地反映了我们的核心机制：就像组装小代币（或“硬币”）以积累更大的价值，CoinRAG组合式地复用离线计算的细粒度片段缓存，以更语义相关且紧凑的方式高效地形成学习到的上下文表示。具体而言，CoinRAG不进行全块编码，而是通过两阶段检索识别检索块中与查询相关的语义单元，并将其切片KV表示与块级上下文无缝组装。在LongBench多跳问答任务上的广泛评估表明，CoinRAG显著降低了运营成本，并在标准快速预填充延迟预算下，以新的帕累托前沿和平均5.3%的答案质量（F1）相对提升超越了其他基线。

## Abstract
Recent optimization studies on Retrieval-Augmented Generation (RAG) have exploited chunk-level KV cache reuse to avoid processing long retrieved contexts for higher efficiency, while significant information redundancy and noise still remain in the coarse-grained chunks. This paper optimizes the Pareto frontier under low prefill latency constraints while maximizing accuracy by proposing CoinRAG (Contextualized Information Nugget KV Cache Reuse for Long-Context RAG). The name metaphorically reflects our core mechanism: much like assembling small tokens (or "coins") to accumulate a larger value, CoinRAG compositionally reuses offline-computed, fine-grained nugget caches to form a learned contextual representation efficiently in a more semantically relevant but compact manner. Specifically, instead of full-chunk encoding, CoinRAG identifies query-relevant semantic units within retrieved chunks through two-stage retrieval and seamlessly assembles their sliced KV representations with a chunk-level context. Extensive evaluations on LongBench multi-hop question answering tasks demonstrate that CoinRAG significantly reduces operational costs and outperforms the other baselines with a new Pareto frontier and an average 5.3% relative improvement in answer quality (F1) under a standard fast prefill latency budget.

## 1. 核心问题与整体含义（研究动机与背景）

- 检索增强生成（RAG）通过引入外部知识提升大语言模型的回答质量，但其在线推理时需要处理长检索上下文，导致**高预填充延迟**与**大量计算冗余**。
- 已有优化（如 TurboRAG、CacheBlend、KVLink 等）利用**块级 KV 缓存复用**来避免重复编码长文本，显著提升推理效率。然而，粗粒度的文本块中仍包含大量**信息冗余与噪声**，低延迟约束下不得不缩小检索范围，从而牺牲准确率。
- 本文提出 **CoinRAG**，核心动机是：在满足标准 SLA（P99 延迟 ≤ 100 ms）的前提下，通过**更细粒度的信息单位——nugget（信息片段）**进行 KV 缓存复用，在降低延迟的同时最大化答案质量。其名称隐喻“用零散硬币累积大价值”——将若干小片段缓存组合为紧凑且语义丰富的上下文表示。

## 2. 方法论：核心思想、关键技术细节与流程

### 核心思想
- 将传统的“整块编码”转化为**离线的信息片段提取 + 在线轻量组装**：文档块在离线阶段编码为全上下文 KV 缓存；在线推理时，仅选取与查询相关的小片段，对其 KV 表示进行切片并拼接，避免重新编码整块文本。

### 关键技术细节

1. **离线 nugget 提取（Offline Nugget Extraction）**
   - 使用 LLM（GPT-4o-mini）从每个 512-token 的文本块中提取候选 nuggest，作为**原始文档中的连续文本片段**（用起止 token 索引标记）。
   - 提取流程分三阶段匹配：Stage A 精确子串匹配；Stage B 基于相似度阈值的模糊匹配（τ = 0.7）；Stage C 放弃无法匹配的候选。
   - 通过“文本片段指针”设计，后续可直接对源块的完整 KV 缓存按索引切片，获得**保留整块语义上下文的 nugget KV 表示**。

2. **两阶段在线检索（Two-Stage Online Retrieval）**
   - 第一阶段：用稠密检索器（BGE-M3）从大规模语料中召回 top-$k_c$ 个候选文本块；
   - 第二阶段：仅在这 $k_c$ 个块内对预提取的 nuggest 按查询相似度排序，选 top-$k$ 个。
   - 这种“先定位块、再筛选片段”的级联策略在降低检索噪声的同时减少了在线计算量。

3. **上下文化 KV 缓存组合与位置对齐（Contextualized KV Cache Composition with Position Alignment）**
   - 从离线缓存中切取所选 nuggest 对应的 KV 张量（$C_{b_i}[s_i:e_i]$），这些张量继承了整块编码时的上下文信息。
   - 由于各 nuggest 来自不同块、不同位置，利用 **RoPE 位置旋转操作** $\text{Rot}(C;\Delta)$ 统一位置编码，按原始文档顺序连续排列，公式为：
$$\Delta_i = |p| + \sum_{j<i}(e_j - s_j + 1)$$
   - 最终上下文缓存：$C_{ctx} = C_p \oplus \text{Rot}(C_{b_1}[s_1:e_1];\Delta_1) \oplus \cdots \oplus \text{Rot}(C_{b_k}[s_k:e_k];\Delta_k)$，再拼接在线计算的查询 KV，形成完整的 KV 上下文。

4. **Nugget 感知微调（Nugget-Aware Fine-tuning）**
   - 为弥合“非连续片段拼接”与“原始连续序列训练”之间的结构差距，构建与测试期操作一致的训练数据（混合真实证据与干扰项的文档集合），用标准交叉熵在答案 token 上微调模型。

- 在 **P99 100 ms 延迟预算**下，CoinRAG 在 3 个数据集上 F1 均高于所有基线，比最强基线 TurboRAG **平均提高 5.3%**（41.7 vs. 39.6），同时上下文 token 长度是 TurboRAG 的 **1.84 倍**更短。

- 消融分析显示：
  - 上下文化 KV 切片比隔离编码峰值 F1 高 3.9–6.3 点；
  - 两阶段检索优于单阶段检索（相对提升 9.6–17.5%）；
  - 位置对齐在 75 ms 紧预算下尤为有效（F1 提升 3.0–8.5%）；
  - nugget 感知微调增益最大（峰值 F1 提升 6.3–11.3 点）。

## 7. 优点

- **粒度创新**：首次将 KV 缓存复用的单位从“块”推进到“信息片段”，兼顾效率与准确性，大幅去除噪声。
- **上下文保留机制**：基于文本跨度指针的 KV 切片设计，在复用片段的同时保留整块编码的语义环境，优于隔离片段再编码。
- **两阶段级联检索**：以块为候选池再做片段筛选，有效缩小搜索空间、提升检索精度。
- **训练-推理一致性校准**：nugget 感知微调针对非连续拼接带来的分布偏移进行针对性优化，体现出工程细节的严谨性。
- **系统层面的考量**：包括磁盘 I/O 优化（按块独立存储、异步加载）、离线缓存构建成本分析、多请求吞吐提升的讨论等，落地性较强。
- 低延迟预算下优势显著，对于真实 SLA 驱动的 Web 服务具有实用价值。

## 8. 不足与局限

- **离线成本不可忽略**：每份语料和每个模型骨架都需要一次性提取 nugget、构建 KV 缓存并完成微调；语料动态更新频繁的场景不适用。
- **与模型强耦合**：预计算 KV 与特定模型权重和位置编码绑定，更换模型需要完全重新编码。
- **受检索召回上限约束**：若两阶段检索漏掉关键证据片段，下游生成无法恢复，准确率存在“天花板”。
- **跨块交互缺失**：来自不同块的 nuggest 在编码时互不关注，与 TurboRAG 等块级缓存方法存在相同局限；虽与 CacheBlend 作了对比，但尚未将跨块注意力恢复技术整合进 CoinRAG。
- **实验覆盖有限**：仅使用 3 个多跳 QA 数据集、单一大模型（Qwen2-7B-Instruct），未覆盖对话式、单跳或多轮场景，未在更大规模模型上验证；安全方面也未系统研究缓存片段被注入恶意内容的可能性。
- **评测假设限制**：假设在线缓存容量有限，未考虑多查询间共享文档的缓存复用机会，可能低估标准 RAG 在真实流量模式下的竞争力。
