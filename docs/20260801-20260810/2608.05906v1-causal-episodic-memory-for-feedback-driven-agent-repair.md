## 摘要
修复失败的LLM智能体常常丢弃成功的纠正，导致后续情节重新发现类似解决方案。我们研究最终修复结果能否在不更新参数的情况下改进后续的Text-to-SQL情节。我们引入MERIT，一种无需训练智能体，维护经Oracle验证的纠正和观察到的失败方向在线双极性记忆。在Oracle辅助基准反馈下，仅早期最终确定的情节中的记忆有资格用于检索。一个确定性分类器分配粗略失败类型，该类型在冻结模型生成每次修订之前调节混合词汇-稠密检索器。使用Qwen2.5-7B-Instruct且初始预测和修复预算相同，MERIT在Spider上将执行准确率从66.34%提高到69.79%，在BIRD上从47.35%提高到48.44%。配对分析为Spider的增益提供了清晰证据，但对BIRD的证据较弱。在两个基准上，MERIT与无类型动态检索没有可靠区分，而Reflexion风格记忆在BIRD上达到51.24%，但推理成本显著更高。消融实验表明，负记忆贡献有限，类型条件和词汇-稠密排序的价值依赖于数据集，而模式局部经验提供最一致的收益。这些结果澄清了因果跨查询记忆何时改进修复，以及何时更广泛的记忆表示仍然更可取。

## Abstract
LLM agents that repair failures often discard successful corrections, forcing later episodes to rediscover similar solutions. We study whether finalized repair outcomes can improve subsequent Text-to-SQL episodes without parameter updates. We introduce MERIT, a training-free agent that maintains an online dual-polarity memory of oracle-verified corrections and observed unsuccessful directions. Under oracle-assisted benchmark feedback, only memories from earlier finalized episodes are eligible for retrieval. A deterministic classifier assigns a coarse failure type, which conditions a hybrid lexical-dense retriever before the frozen model generates each revision. Using Qwen2.5-7B-Instruct with identical initial predictions and repair budgets, MERIT improves execution accuracy over stateless iterative repair from \(66.34\%\) to \(69.79\%\) on Spider and from \(47.35\%\) to \(48.44\%\) on BIRD. Paired analyses provide clear evidence for the Spider gain but weaker evidence on BIRD. MERIT is not reliably separated from untyped dynamic retrieval on either benchmark, while Reflexion-style memory reaches \(51.24\%\) on BIRD at substantially higher inference cost. Ablations show that negative memory contributes modestly, the value of type conditioning and lexical--dense ranking is dataset dependent, and schema-local experience provides the most consistent benefit. These results clarify when causal cross-query memory improves repair and when broader memory representations remain preferable.

### 2. 论文提出的方法论

论文提出 **MERIT（Memory-Augmented Error-Typed Retrieval for Iterative Text-to-SQL repair）**，一种无需训练的在线修复智能体，核心组成如下：

- **因果式在线修复框架**：
  - 每个查询为一个“情节”（episode），初始SQL预测由冻结模型用贪心解码生成，所有方法共享同一初始预测，以隔离修复策略的差异。
  - 修复预算K=7，即最多生成7次修订。只有成功（Oracle确认正确）或预算耗尽时情节才终结，记忆才对外可见。
  - “因果”（causal）指时间上的记忆可用性约束：当前查询只能访问此前已完结情节产生的记忆，不能访问自己未完结的轨迹或未来经验。

- **确定性错误分类器**：
  - 将失败分类为：RESULT MISMATCH、SCHEMA LINKING、AGGREGATION、FILTER/VALUE、EXECUTION、SYNTAX、UNKNOWN。
  - 仅基于执行状态和DBMS报错文本，通过有序规则匹配确定标签；不检查SQL AST，不推断语义错误。

- **在线双极性记忆**：
  - 记忆分为正记忆 \(M^+\) 和负记忆 \(M^-\) 两个池。
  - 正记忆：Oracle确认的“失败→正确”转换（\(y^- \to y^+\)），记录源问题、模式、失败SQL、转换描述等。
  - 负记忆：未解决情节中最后尝试的方向，仅表示该方向在源上下文中失败，不声称其普遍无效。
  - 每个已终结情节最多贡献一条记忆条目，形式为 \(x = \langle c, \tau, \Delta, o, \rho \rangle\)。

- **类型条件混合检索**：
  - 候选池构建：优先选择与当前失败类型相同的记忆；若同类型条目少于3条，则回退到同极性全部合法池：
    \[
    C_{t,p} = \begin{cases}
    T_{t,p}, & |T_{t,p}| \ge 3, \\
    L_{t,p}, & \text{otherwise}.
    \end{cases}
    \]
  - 混合排序：对候选记忆分别计算dense（bge-large-en-v1.5编码，余弦相似度）和BM25分数，各自在池内做min-max归一化后加权组合：
    \[
    r(x,u) = 0.75\,b_{\text{dense}}(x,u) + 0.25\,b_{\text{BM25}}(x,u)
    \]
  - 每次检索最多取3条正记忆和1条负记忆。

- **修复生成**：
  - 将当前问题、模式、当前SQL、反馈状态、DBMS错误、失败类型、局部历史和检索到的正负记忆拼入提示词，送入冻结LLM生成一次修订，Oracle评估后循环。

- **类型可靠性感知变体（MERIT Type-Realiability-Aware）**：
  - 对SYNTAX、SCHEMA LINKING、EXECUTION三类“高可靠性”类型采用硬过滤；对其他类型仅对同类型条目施加0.10的软加分。

### 6. 论文的主要结论与发现

- **跨查询记忆有效**：MERIT使Spider执行准确率从66.34%提升至69.79%（+3.45个百分点，95% CI [1.97, 4.96]），证据明确；BIRD上从47.35%到48.44%（+1.09个百分点，CI [0.00, 2.17]），证据较弱。
- **与Dynamic RAG无显著差异**：在Spider上并列（69.79%），BIRD上仅领先0.28个百分点，置信区间均过零。MERIT的极性分离与硬类型条件化未带来可验证的聚合优势。
- **Reflexion-style在BIRD上最强**：达51.24%，显著超过MERIT 2.80个百分点，但推理成本约为MERIT的1.3倍token和1.85倍调用次数。
- **记忆主要提升“可修复失败数”**：MERIT在Spider上平均修复112.7个初始失败，远高于Iterative的77.0；但轨迹长度和振荡差异较小。
- **消融结论**：
  - 负记忆贡献有限（±0.1点左右）。
  - 类型过滤在Spider上略有帮助（+0.58），在BIRD上无益甚至略降。
  - dense重排在Spider上重要（移除掉1.12点），BM25在BIRD上更有用。
  - **模式局部经验最一致地重要**：跨数据库记忆限制在BIRD上降低2.74个百分点，Spider上降0.93。

### 7. 优点

- **设计严谨且公平**：共享初始预测、同一模型、相同预算，隔离了“修复策略”变量；因果记忆协议保证记忆来源时间合法性。
- **统计检验规范**：使用query-cluster bootstrap保持查询内跨流相关性，置信区间报告增强了结果的可解释性。

- **结论诚实**：不夸大增益，明确报告MERIT与更简单基线无显著差异，并指出Reflexion-style在一些条件下更优。
- **成本透明化**：明确报告token和调用次数，指出MERIT并非低成本方案。

### 8. 不足与局限

- **依赖Oracle级正确性信号**：需要基准评估器返回denotation-level正确性，部署环境中往往只有部分执行反馈或延迟的人工确认，适用性受限。
- **模型和数据覆盖有限**：仅用Qwen2.5-7B-Instruct，未验证其他模型家族；仅Spider/BIRD开发集，未包含训练集、跨语言或对话式场景。
- **记忆顺序敏感性**：结果依赖查询流顺序，3种顺序只能捕捉有限的变化范围。
- **错误分类器准确性低**：验证准确率仅约48%，Macro-F1约0.32–0.36，粗粒度标签限制了硬类型过滤的实际收益。
- **未做超参数敏感性研究**：检索权重（0.75/0.25）、阈值（3条）、正负记忆配额均固定，未探索其影响。
- **推理成本偏高**：不是比无状态修复更便宜；检索记忆增加提示长度，token消耗显著上升（Spider约2倍，BIRD约1.9倍），仅调用次数略减。
- **未对比最新专项Text-to-SQL系统**：与DAIL-SQL、CHASE-SQL等SOTA方法不在同一赛道上比较，不能声称整体SOTA。
