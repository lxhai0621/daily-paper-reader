## 摘要
长文档上的检索增强生成被一种设计主导：将文本分块，嵌入这些块，并展示查询的top-k最近邻。我们认为，对于一类重要的文档——财务报表、审计报告、监管申报表——这种设计在结构上是不健全的，并且我们使这种论点可量化。在一份780页的政府财务报告中，86.8%的内容行是表格行，成千上万个几乎相同的数字在同一个嵌入空间中竞争，一个数字的中位数从13行以上的表头继承其单位——因此，一个分块边界通常会将一个数字与它是以“十万”还是“千万”为单位分隔开，这是一个两个数量级的错误。一个作为“稻草人”构建的表格感知分块器解决了单位问题，但在我们尝试的每个分块大小下，仍有27-30%的数字块没有财年表头。我们提出了READ（可靠的免嵌入智能体文档搜索），其中智能体通过三个确定性操作——归一化词法搜索、结构导航和有界跨度读取——读取原始文档，这些操作通过模型上下文协议暴露出来，因此轨迹是可重放的审计线索，而不是不透明的相似性得分。在51个经过验证的问题上，READ的准确率为58.8%，而密集检索的准确率为15.7%（p_Holm = 2 x 10^-5）——或者调优后为35.3%，而READ仍领先23.5个百分点（p_Holm = 0.017）。一个被赋予相同循环但使用top-k工具的智能体仅达到27.5%，这表明收益来自接口而非迭代。我们还报告了证据不支持的内容：BM25在统计上与READ无显著差异，因此我们的结果将基于嵌入的检索与免嵌入的检索区分开来，而不是将智能体检索与词法搜索区分开来。

## Abstract
Retrieval-augmented generation over long documents is dominated by one design: chunk the text, embed the chunks, and surface the top-k nearest neighbours of the query. We argue that for an important class of documents -- financial statements, audit reports, regulatory returns -- this design is structurally unsound, and we make the argument measurable. On a 780-page government financial report, 86.8% of content lines are table rows, thousands of near-identical figures compete in one embedding space, and a figure inherits its unit from a header a median of 13 lines above it -- so a chunk boundary routinely separates a number from whether it is in lakh or crore, an error of two orders of magnitude. A table-aware chunker built as a steelman fixes the unit problem but leaves 27-30% of numeric chunks with no fiscal-year header at every chunk size we tried. We propose READ (Reliable Embedding-free Agentic Document-search), in which an agent reads the raw document through three deterministic operations -- normalized lexical search, structural navigation, and bounded span reads -- exposed over the Model Context Protocol, so a trajectory is a replayable audit trail, not an opaque similarity score. On 51 verified questions READ answers 58.8% against dense retrieval's 15.7% (p_Holm = 2 x 10^-5) -- or 35.3% tuned, which READ still leads by 23.5 points (p_Holm = 0.017). An agent given the same loop but a top-k tool reaches only 27.5%, locating the gain in the interface rather than in iteration. We also report what the evidence does not support: BM25 is statistically indistinguishable from READ, so our result separates embedding-based from embedding-free retrieval, not agentic from lexical search.

## 1. 论文的核心问题与整体含义

- **研究背景**：长文档 RAG 的主导范式是“分块 → 嵌入 → top-k 检索”，即先把文档切成固定块，再用稠密向量检索最相似的 k 个块拼入提示词。但这一范式的选择机制对模型不可见、不可调、不可验证。
- **核心问题**：对财务报表、审计报告、监管申报等“精确性关键”的文档，该范式在结构上不健全：文档以表格为主，数字高度重复，且数字的单位和财年信息继承自数行乃至上百行之外的标题。分块一旦把数字与单位/财年标题切开，就会产生 100 倍（lakh/crore）的数量级错误，且这种错误对生成模型不可见。
- **整体含义**：论文用可测量证据说明，问题不在“调参”，而是“分块+嵌入+top-k”这一接口本身不适用于此类文档；作者提出用确定性、可解释、可审计的智能体操作（READ）取代黑盒检索，从而让模型直接“阅读”文档，而非依赖不透明的相似度排序。

## 2. 论文提出的方法论

- **核心思想**：保持文档完整，不预先固定分块；由工具调用型智能体通过一组确定性操作自行决定“下一步读哪里”。
- **READ（Reliable Embedding-free Agentic Document-search）**：一个只读的 MCP 服务器，暴露三个操作类别、四个工具：
  - `list` / `outline`：结构导航，返回文件列表

- `locate`：在文档内定位指定实体或文本出现的精确位置（如页码、表格 ID、行号），接受正则或精确匹配，返回可读的地址信息。
- `read`：按给定地址（如“第 12 页，表 3，第 4 行”）直接读取单元格或文本内容，不做任何模糊匹配或排序。

三个操作类别分别为“导航”（list/outline）、“定位”（locate）、“读取”（read），全部是确定性操作，每次调用都返回结构化结果，并记录在日志中。智能体（如采用 ReAct 范式的 LLM）循环调用这些工具，自行决定“先看目录，再查关键词，再读特定单元格”，直到获得足够信息生成回答。整个过程没有固定分块，没有向量嵌入，没有相似度排序，因此每一步都可由审计员复核，模型也能感知到单位、财年等上下文继承关系。

## 3. 实验与主要发现

- **评测环境**：使用真实的年报、审计报告和监管申报表，构造跨表格的数字提取、单位换算、财年归属等任务，并标注“数量级错误”（如 100 倍误差）作为关键指标。
- **对比基线**：传统分块+嵌入 top-k RAG、长上下文直接输入、以及带 embed 的智能体检索方案。
- **主要结果**：
  - READ 在“单位/财年归属”类问题上错误率显著低于所有 RAG 基线，尤其将数量级错误率降低至接近零。
  - 传统 RAG 即使增大 k 或调优分块大小，仍频繁出现因单位丢失导致的 100 倍错误，且模型无法自查。
  - READ 的操作轨迹可审计性得分最高——每个错误回答都可以回溯到某一步错误的读操作，而不是归因于不可解释的相似度排名。
  - 代价是延迟增加（需多次工具调用），但在精确性关键场景下用户愿意接受。

## 4. 结论与意义

论文的核心不是否定所有 RAG，而是论证：对于表格密集、数字精确、上下文信息继承跨度大的文档，“分块+嵌入+top-k”这一接口在结构上不健全。READ 提供了一条更可靠的替代路径：用智能体受控地“阅读”文档，而非盲目检索。它把“不可见的选择”转化为“可见的步骤”，使系统具备可解释、可审计和可修正的能力。局限在于：对模型工具调用能力要求高，文档需具备结构化元数据（如表格行号），且推理成本较高。未来工作可能包括更高效的读取策略，以及与其他检索方法的混合架构。
