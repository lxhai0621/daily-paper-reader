## 摘要
长上下文推理受到键值缓存随序列长度线性增长的限制。虽然剪枝可以缓解这一问题，但现有方法通常确定查询特定的token重要性，无法在未见过的查询中复用。相比之下，我们提出TaskPress，一个任务引导、查询无关的KV缓存驱逐框架。TaskPress不是针对单个查询优化缓存，而是根据高层任务指南构建可复用的记忆表示。该指南在预填充阶段充当元查询，在下游查询发出之前过滤无关token。此外，TaskPress利用量化缩放因子作为零成本信号来检测有影响力的表示异常值，为token重要性提供高效代理。在多种长上下文输入任务上的实验表明，TaskPress能够高效地创建跨多种查询的紧凑、可复用缓存。

## Abstract
Long-context inference with large language models is constrained by the linear growth of the key-value cache to sequence length. While pruning offers mitigation, prevailing methods determine query-specific token importance that cannot be reused across unseen queries. In contrast, we introduce TaskPress, a framework for task-guided, query-agnostic KV cache eviction. Instead of optimizing the cache for a single query, TaskPress constructs a reusable memory representation conditioned on a high-level task guide. The guide functions as a meta-query during prefill to filter irrelevant tokens before downstream queries are issued. In addition, TaskPress leverages quantization scale factors as a zero-cost signal for detecting influential representation outliers, providing an efficient proxy for token importance. Experiments on conducted on various tasks with long context input demonstrate that TaskPress efficiently creates a compact, reusable cache across diverse queries.

## TaskPress：通过任务引导剪枝实现查询无关的KV缓存压缩

### 一、论文的核心问题与整体含义（研究动机和背景）

- **背景问题**：随着大语言模型（LLM）的上下文长度不断增长（最高可达200万token），Transformer推理过程中的KV缓存随序列长度线性增长，内存开销巨大，甚至超过模型权重本身，严重制约长上下文推理的效率和吞吐量。
- **现有方法的不足**：
  - **查询依赖方法**（如SnapKV、PyramidKV、Quest）：根据具体用户查询动态计算token重要性，压缩后的缓存无法复用于新查询，在多轮或多查询场景下需重复昂贵的prefill计算。
  - **查询无关方法**（如KVZip）：支持多查询复用，但需上下文重建，使prompt长度增加一倍，导致约O(Lc²)的二次方计算开销。
- **核心洞见**：实践中许多工作负载基于任务（task）而非单次查询，同一个任务会产生多个问题。因此，**压缩决策应从查询时间（query-time）解耦到任务时间（task-time）**，利用任务级别的元信息构建可跨查询复用的压缩缓存。
- **本文方案**：提出TaskPress——任务引导的、查询无关的KV缓存驱逐框架，以高层任务指南为"元查询"（meta-query），在预填充阶段过滤无关token，同时复用量化缩放因子作为零成本的重要信号，实现高效、可复用的缓存压缩。

### 二、论文提出的方法论

#### 1. 核心思想：任务指南作为元查询

- 传统方法用**具体问题**（Q）去计算注意力并确定token重要性；TaskPress改用**任务指南**（T）作为稳定的元查询，构建能覆盖同一任务下未来所有可能问题的通用压缩缓存。
- 任务指南在预填充阶段参与注意力计算后即刻丢弃，不会影响后续推理过程。
- 这种设计将压缩从**查询时**前移到**任务时**，使一次压缩可服务同一任务下的所有查询。

#### 2. 关键技术细节

**（1）任务引导的Key重要性（Task-Guided Key Importance）**

- 在预填充阶段，将长度为Lt的任务描述附加到长度为Lc的上下文之后。
- 计算任务描述token与上下文token之间的注意力矩阵A ∈ R^(Lt×Lc)。
- 对任务维度求和，并应用1D平均池化（kernel size = K）以捕获局部依赖：

$$s^{key}_i = \frac{1}{K}\sum_{k=-\lfloor K/2\rfloor}^{\lfloor K/2\rfloor}\sum_{j=1}^{L_t} A_{j,i+k}$$

- 该分数只反映Key重要性（来自query-key交互）。

**（2）量化缩放因子作为Value重要性（Quantization Scale as Value Importance）**

- 观察到自注意力是注意力权重和Value的加权和，仅测Key重要性不够，还需衡量Value的信息密度。
- 关键创新：**复用KV量化（per-token量化）中已计算好的缩放因子作为Value重要性的代理指标**：

$$\gamma_i = \frac{\max(|v_i|)}{2^{b-1}-1}$$

- 由于比特宽度b是常数，γi与Value向量的最大绝对幅度成正比，直接反映Value离群值强度。
- **零成本优势**：量化是高效LLM服务的事实标准，缩放因子已在预填充阶段计算完毕且驻留内存，无需任何额外操作。

**（3）KV重要性合并评分**

- 最终缓存保留分数为Key分与Value分层级乘积：

$$s_i = s^{key}_i \cdot s^{value}_i$$

- 乘法交互要求token必须满足两个条件：①在任务对齐的注意力空间内结构上可检索（高Key分数）；②内在语义信息丰富（高Value离群值分数）。
- 最终按每头独立选择分数最高的前|I|个token索引。

**（4）任务指南构建**

- **已知任务（零样本初始化）**：直接用现成指令LLM（如Gemini）按模板"Generate a task guidance for {task} in 2–3 sentences."生成简洁任务描述，作为强基线。
- **未知/动态任务（进化搜索）**：采用进化算法，从少量校准查询集中推断用户的潜在意图，迭代改进任务指南：
  - 初始化：用LLM基于校准查询生成N个初始候选指南；
  - 评估：在小校准集D_cal上计算下游任务精度作为适应度；
  - 选择：保留Top-K最佳候选；
  - 变异与重组：LLM对父代执行变异（query驱动的语义改写）或交叉（结构保持的拼接），生成N个新候选；
  - 迭代G代后返回适应度最高的任务指南T*。

#### 3. 算法流程（文字说明）

算法1（Task Guide Discovery）：输入校准集、LLM变异器、总代数G和选择规模K。首先从校准集采样问题，让LLM生成N个初始候选指南；然后每轮评估全部候选的适应度，选择Top-K保留，再让LLM基于这些父代进行变异/交叉产生N个新候选，与父代合并进入下一轮；最终返回得分最高的T*。

### 七、优点

1. **问题视角新颖**：将KV缓存压缩从查询粒度提升到任务粒度，解决实际多查询工作负载中缓存复用问题，概念优雅且实用。
2. **零成本信号复用**：复用现成量化流程中已计算的缩放因子作为Value重要性代理，设计巧妙，贴合工业部署现实。
3. **任务指南鲁棒性高**：对生成源模型（Gemini/Claude/ChatGPT）不敏感，对措辞变化（同义词替换/句子改写）的标准差低于1%，表明方法稳定可靠。
4. **进化搜索设计合理**：适用未知任务场景，显式引入变异与交叉两种候选生成策略，只需极少量校准查询即可发现有效指南。
5. **实验体系完整**：贯穿精度、效率、鲁棒性、消融和理论分析（附录）的全面验证；与ThinK等正交方法的组合实验展示了方法的可扩展性。

### 八、不足与局限

1. **任务依赖性问题**：压缩缓存仅优化于任务指南定义的语义范围。若用户查询显著偏离预期任务（如摘要会话中突现编码问题），检索上下文可能不充分，性能可能劣于完全缓存基线。
2. **密集信息场景的脆弱性**：在RULER MK-2/3等"针中针"人工密集场景（820+个相似目标），softmax归一化的交叉注意力被稀释，目标token分数低于背景噪声，导致错误驱逐。作者通过改变针数实验证明在现实中等稀疏度下仍鲁棒，但该方法对极端信息密度环境仍存在结构性局限。
3. **依赖量化统计**：在FP16/BF16全精度设置下，缩放因子不可直接用，需额外动态计算（作者补充了约2.7%的边际开销说明）。
4. **进化搜索的校准集依赖**：需要从测试分布中采样校准查询来发现未知任务指南，且实验仅用50个样本，未说明校准集规模对指南质量的敏感性。
5. **实验覆盖的不足**：
   - 主实验未报告标准偏差/显著性检验（除指南措辞鲁棒性实验外）；
   - 只评估了2种模型族（LLaMA、Qwen），未推广到其他架构；
   - 缺少真实多轮多查询工作负载的端到端部署验证（现有RS多查询实验基于合成设置）；
   - RULER和LongBench均为公开通用基准，未覆盖代码、法律、医疗等垂直领域的任务漂移场景。
6. **任务指南合成中的参数选择**：进化算法中的世代数（G=4）、候选数（N=3）、选择规模（K=2）缺乏超参数敏感性分析。
