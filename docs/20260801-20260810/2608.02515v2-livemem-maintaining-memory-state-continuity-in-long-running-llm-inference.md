## 摘要
长期运行的助手和智能体会消耗交互流，这些交互流最终会超出上下文限制。现有的上下文保留、摘要和检索方法可以保留对选定历史的访问，但在工作上下文发生变化时，无法提供覆盖整个生命周期的持久状态。我们将这种缺失的推理能力表述为“上下文更替下的状态连续性”：通过一个固定容量的记忆状态来推进计算，该状态的寿命独立于活动上下文。我们提出了一种内在记忆方法——LiveMem，它通过一个记忆状态增强预训练的全注意力LLM，该记忆状态在整个生命周期内保留历史信息，同时主注意力路径保持一个有界KV窗口。上下文更替与记忆状态维护、面向记忆的后训练以及状态感知的服务共同使得该记忆状态在其源token被释放后仍能承担实际功能。实验表明，LiveMem在评估的系统和其他内在记忆方法中取得了领先的整体性能。在LongMemEval上的实验表明，即使支持性证据已从当前上下文中移除，LiveMem仍能基于记忆状态回答问题，且证据距离分析显示有用信息持续存在于活动窗口之外。因此，LiveMem将状态连续性确立为持续LLM推理的一种独特且互补的抽象。

## Abstract
Long-running assistants and agents consume interaction streams that eventually outgrow the context. Existing context retention, summarization, and retrieval preserve access to selected history, but do not provide a persistent state over the full lifecycle when working context changes. We formulate this missing inference capability as \emph{state continuity under context turnover}: carrying computation forward through a fixed-capacity memory state whose lifetime is independent of the active context. We introduce an intrinsic memory method, \textbf{LiveMem}, which augments a pretrained full-attention LLM with a memory state that preserves the historical information over the whole lifecycle while the main attention path retains a bounded KV window. Context turnover and memory state maintaining, memory-oriented post-training, and state-aware serving jointly make this memory state load bearing after its originating tokens are released. Our experiments show that LiveMem achieves leading overall performance among evaluated systems and other intrinsic memory methods. Experiments on LongMemEval show that LiveMem is able to answer the question based on the memory state, even when the supporting evidence has been removed from the current context, and evidence-distance analysis shows that useful information persists beyond the active window. LiveMem thus establishes state continuity as a distinct and complementary abstraction for continual LLM inference.

### 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：长期运行的 LLM 助手/智能体与环境的交互历史最终会超出模型上下文窗口的限制。现有技术（如上下文保留、摘要、RAG 检索）只能提供对“选定历史”的访问，而无法在**工作上下文不断更换**的情况下，维持一个覆盖整个交互生命周期的持久、连续的状态。
- **提出新概念**：论文将这一缺失能力定义为“上下文更替下的状态连续性（state continuity under context turnover）”——即通过一个**固定容量、独立于活动上下文、随输入在线更新**的记忆状态，将计算从过去持续“携带”到未来。
- **关键区分**：作者将“记忆存取/检索”（如 RAG，类似于外部“记事本”）与“状态连续性”（模型内部的高维循环记忆）明确区分为**正交且互补**的两个维度。现有工作的空白在于缺乏后者。
- **深层挑战**：仅仅添加一个名义上的循环模块（如 RNN 状态）并不足以构成有效记忆——模型可能绕过记忆状态、只依赖注意力。必须通过**上下文轮换训练**迫使模型在信息离开注意力后仍能依赖记忆状态进行推理。

### 2. 方法论

**核心思想**：在预训练全注意力 LLM 上并行添加一个循环记忆分支，形成“注意力提供近期精确访问 + 记忆状态提供生命周期级连续性”的双路径架构。

**关键技术细节**：

- **架构**：在每个解码器层，主路径为原注意力（有界 KV 窗口）；侧路径使用 **Gated DeltaNet-2（GDN2）** 作为循环骨干，维护一个固定大小的记忆状态（张量形状为 32×128×128 per layer）。侧路径输出直接加回到注意力输出。
- **GDN2 状态更新公式（核心）**：
  - 遗忘：`S_t = Diag(exp(g_t)) S_{t-1}`
  - 擦除与写入：`S_t = S_t + k_t (w_t ⊙ v_t - S_t^T (b_t ⊙ k_t))^T`
  - 读取：`r_t = S_t^T q_t`
  - 其中 `g_t` 为对数衰减，`b_t` 为擦除门，`w_t` 为写入门，均在训练中学习。
- **上下文轮换机制**：输入按块（chunk）处理，系统提示词作为“注意力锚点（attention sink）”始终保留；其余块通过 FIFO 队列管理，当块数或 token 数超阈值时，最旧的 KV 页被逐出注意力路径，但其信息已写入记忆状态。训练和推理采用完全一致的轮换策略。
- **记忆导向后训练**（两阶段）：
  - **SFT 阶段**：先使用长文本 QA 数据冷启动以“激活”侧路径，再用重新平衡的数据混合训练（含多跳 QA、对话 QA、分类等）；损失只作用于答案 token。
  - **RL 阶段**：使用 GRPO 算法，融合 DAPO 技巧（clip-higher、token-level loss、动态采样、去除 KL），奖励函数结合准确率、全对奖励和格式惩罚。
- **状态感知服务**：采用分页 KV 管理，逐出旧 KV 页时不影响记忆状态槽位；预填充/解码过程均维护和更新循环状态，且保证不同请求之间状态不串扰。

### 3. 实验设计

- **四大任务套件（benchmark）**：
  - **Wiki QA**（知识型多跳 QA）：2WikiMultiHopQA、HotpotQA、MuSiQue（各含单问和多问 MQ 变体；MQ 将多个样本打包后要求同时回答）
  - **Conversation**（对话记忆）：LoCoMo、LongMemEval、MAB-FactConsolidation
  - **TTL**（测试时学习）：Banking77、CLINC150、NLU、TREC-coarse/fine、ReDial（来自 MemoryAgentBench）
  - **Long QA**（长文本问答）：∞Bench-QA、MAB-EventQA、NarrativeQA
- **评价设置**：全部基于 **Qwen3-4B-Instruct-2507**；主实验限制上下文 32k tokens（短数据集为 8k）；另有 256k 上下文的对照实验。
- **对比方法**：Qwen3-4B 直接基线、RAG、Recurrent（仿 MemAgent 的文本记忆循环）、Context2LoRA（参数化记忆）、δ-Mem（侧路径状态）、LiveMem-SFT、LiveMem-RL。

### 6. 主要结论与发现

- **总体性能**：LiveMem 在 Wiki QA 和 Long QA 上取得 SOTA，在 Conversation 和 TTL 上位列第二，整体成绩（Overall 0.519）显著优于所有基线。
- **记忆状态确实携带了被逐出窗口的证据**：在 LongMemEval 上，当证据被完全移出窗口时，LiveMem 比无记忆模型高 10+ 个百分点（LiveMem-RL 16.5% vs Qwen 3.1%）；部分移出时同样领先。
- **证据距离影响有限**：随证据逐步远离窗口，准确率仅呈轻微下降趋势，说明 GDN2 的更新/遗忘机制能在多个轮换周期后仍保留关键信息。
- **多问任务优势明显**：在 2Wiki-MQ、Hotpot-MQ、MuSiQue-MQ 上，LiveMem 大幅领先所有基线（如 2Wiki-MQ 0.587 vs δ-Mem 0.009）；说明记忆状态能同时承载多条推理链。
- **消融结论**：侧路径全参数训练优于 LoRA；加入主路径 LoRA 无增益；长文本数据冷启动“激活”侧路径 + 再平衡数据精调是最优训练课程。

### 7. 优点

- **问题定义清晰**：将“状态连续性”从“历史访问（检索）”中独立出来，提出了一套完整的形式化（公式 2-3）和“活记忆状态三要素”判据（在线更新、跨上下文持久、影响后续行为）。
- **训练-推理一致性设计**：上下文轮换机制在训练（动态注意力掩码）与推理（物理释放 KV 页）中完全一致，避免了训练/推理失配。
- **归零初始化**：侧路径输出投影初始化为零，确保引入记忆分支初始等价于原模型，训练稳定性好。
- **有说服力的验证设计**：通过“证据是否在窗口内”的对比实验和证据距离分析，直接检验记忆状态是否真的承载了被逐出的信息，而非仅仅依赖注意力。
- **消融完备**：对可训练容量、数据混合、课程顺序均做了系统消融，结论可操作性强。

### 8. 不足与局限

- **有损记忆 ≠ 精确档案**：在针尖查找（NIAH）测试中，LiveMem 无法从记忆状态可靠恢复任意细粒度字符串，无法替代检索系统实现无损归档；对于需要精确回放的场景，需与外部检索联合使用。
- **位置编码有限制**：Qwen3 骨干的 RoPE 最大位置为 262,144，超过后需外推，因此本系统并非真正“无限上下文”；作者承认需采用无位置编码（NoPE）骨干才能突破这一架构天花板。
- **实验覆盖有限**：仅在 4B 规模单骨干上验证；未报告训练总耗时/成本估算；某些任务子集采样量较小。
- **部分对比公平性存疑**：Context2LoRA 在 TTL 上极强可能是因为按其假设直接用文本-标签对训练 LoRA（而其他方法无此定制）；RAG 在多问任务中缺测。
- **RL 训练复杂度高**：需要多节点（训练+rollout+judge）联动，工程成本较大，可能限制其可复现性。
- **无法证明“必需品”性**：论文未定量证明“记忆状态”相比“将更多历史保留在注意力中”在相同 token 预算下的优势边界（NIAH 已显示不是无损的）。
