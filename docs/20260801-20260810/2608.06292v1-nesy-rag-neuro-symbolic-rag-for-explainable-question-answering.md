## 摘要
检索增强生成（RAG）通过将大语言模型（LLMs）锚定在外部知识（如文本语料库）中来改进问答。然而，其推理过程在很大程度上仍是不透明的：中间推理步骤难以验证，且无法可靠地归因于特定证据。此外，用户特定上下文的缺失很少被系统性地检测到，常常导致不完整或错误的输出。我们提出了NeSy-RAG，一个模块化的神经符号RAG框架，它从检索到的文本块中综合出可归因的Prolog模块。对于每个文本块，系统生成语义上有意义的谓词，编码布尔声明，这些声明可能依赖于用户事实。利用联合自然语言-代码嵌入，谓词被检索并组合成Prolog查询。为了解决不完整的用户上下文，我们引入了一种符号性知识缺口检测机制，该机制识别缺失的用户事实，其真值影响查询结果，并自动触发后续交互。执行生成的Prolog查询产生确定性答案以及透明的执行轨迹，将每个推理步骤连接到其来源。在ShARC基准上，无需领域特定训练，NeSy-RAG达到了61.1%的准确率，优于同模型RAG基线的42.8%准确率。

## Abstract
Retrieval-augmented generation (RAG) improves question answering by grounding large language models (LLMs) in external knowledge such as text corpora. However, its reasoning process remains largely opaque: intermediate reasoning steps are difficult to verify and cannot be reliably attributed to specific evidence. Moreover, missing user-specific context is rarely detected systematically, often leading to incomplete or incorrect output.   We propose NeSy-RAG, a modular neuro-symbolic RAG framework that synthesizes attributable Prolog modules from retrieved text chunks. For each chunk, the system generates semantically meaningful predicates that encode Boolean claims, which may depend on user facts. Using joint natural language-code embeddings, predicates are retrieved and composed into Prolog queries. To address incomplete user context, we introduce a symbolic knowledge-gap detection mechanism that identifies missing user facts whose truth values affect the query outcome and automatically triggers follow-up interactions.   Executing the resulting Prolog queries yields deterministic answers together with transparent execution traces that link each reasoning step to its originating source. On the ShARC benchmark, without domain-specific training, NeSy-RAG achieves 61.1% accuracy, outperforming a same-model RAG baseline that achieves 42.8% accuracy.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：检索增强生成（RAG）通过引入外部知识提升了 LLM 回答的事实准确性，但其推理过程仍不透明：链式思考（CoT）不可验证，答案难以可靠归因到具体证据，且缺乏对用户特定上下文缺失的系统性检测，导致输出可能不完整或错误。
- **问题**：
  - 推理过程无法为用户提供可信、可复核的解释；
  - 大规模知识库下，将自然语言问题转换为符号查询困难且易出错；
  - 缺少用户关键信息时，系统往往盲目作答而不是主动询问。
- **整体目标**：构建一个模块化的神经符号 RAG 框架，将检索文本转化为可执行、可归因的 Prolog 模块，从而提供确定性、透明且可交互追问的问答系统。

## 2. 方法论

### 核心思想
- 将 RAG 检索到的每个文本块（chunk）用 LLM 独立合成一个 Prolog 模块（事实 + 规则），形成模块化、可归因的符号知识库；
- 通过“0-arity 谓词抽象”将规则封装为布尔声明，利用联合自然语言-代码嵌入检索与用户问题最相关的谓词，再由 LLM 组合成 Prolog 查询；
- 执行 Prolog 查询时，通过“动态谓词”自动识别缺失的用户事实，并触发追问；执行过程产生可追溯到源文本的确定性推理轨迹。

### 关键技术细节
1. **可归因 Prolog 合成**  
   - 每个检索到的文本块 `c_m` 独立生成 Prolog 模块 `p_m = (R_m, F_m)`；  
   - 每条事实/规则均可唯一映射回来源 chunk，推理轨迹也携带模块来源信息，实现细粒度溯源。

2. **0-arity 谓词抽象**  
   - LLM 在合成模块时额外生成 0-arity 规则，如 `could_claim_married_couples_allowance`；  
   - 将复杂规则抽象为无参数布尔谓词，便于查询构建和检索。

3. **两阶段层次检索**  
   - 阶段一：基于向量检索相关文本块；  
   - 阶段二：用联合 NL–PL 嵌入模型（jina-code-embeddings-1.5b）计算用户问题与 0-arity 规则的余弦相似度，取 top-k 规则，再由 LLM 仅基于这些规则构建 Prolog 查询。  
   - 显著减小查询生成的搜索空间，避免直接加载整个知识库。

4. **知识缺口检测（Knowledge-Gap Detection）**  
   - 事实分为“通用事实”（universal facts，知识文本中完全确定）和“动态事实”（dynamic facts，含推理时才能确定的值，如用户布尔属性）；  
   - 动态事实执行时通过 foreign Python 函数向用户（或模拟用户）提问；  
   - 若用户无法回答，则尝试两种布尔赋值，若查询结果一致则返回一致答案，否则返回 `more`。

5. **答案生成与解释**  
   - 执行 Prolog 查询得到确定性答案和完整执行轨迹；  
   - 轨迹中每个规则/事实都带有来源 chunk 标注，可用于验证和生成自然语言解释。

## 3. 实验设计

### 数据集
- **ShARC benchmark**（Saeidi et al., 2018）：对话式机器阅读理解数据集，基于英国政府网站的法律文本构建。  
- 每个实例包含文本片段（snippet）、问题、用户情境（scenario）、历史对话、证据和标准答案（yes/no/irrelevant/more）。  
- 实验采用测试集（8,276 条），并将 scenario + evidence + history 合并为上下文，但初始不提供给系统，系统需通过追问主动获取信息。

### 实验设置
- 模拟检索：每个实例由目标 snippet 与随机采样的 distractor snippets 组成（共 3 个），要求系统先判断相关性。  
- 如果无相关 snippet 则输出 `irrelevant`；  
- 模拟用户：另一个 LLM 基于隐藏上下文回答系统的追问；  
- 无法回答且结果不确定时输出 `more`。

### 对比方法
| 方法 | 说明 |
|------|------|
| LLM RAG Baseline | 与 NeSy-RAG 相同的设置，但用纯 LLM 推理替代 Prolog；若预测为 `more` 则生成追问，再综合回答。使用 gpt-oss:20b 和 gpt-5-mini。 |
| LLM Upper Baseline | 拥有完整用户上下文，直接预测最终标签，等价于无追问情况下的近似上界。 |
| NeSy-RAG | 本框架，使用 gpt-oss:20b 进行模块/查询生成，jina-code-embeddings-1.5b 进行 0-arity 谓词检索，测试不同 top-k（3/10/20）。 |
| BiAE (Luo et al., 2023) | 领域训练后的 SOTA 方法，直接输入 scenario 和 history，作为训练方法的上界参考。 |

### 主要结果
- NeSy-RAG（k=10）准确率 **61.1%**，平均耗时 **7.4s**；  
- LLM RAG Baseline：gpt-oss:20b 为 **42.8%**（11.4s），gpt-5-mini 为 **53.7%**（25.1s）；  
- LLM Upper Baseline：gpt-oss:20b 为 **64.1%**（2.7s），gpt-5-mini 为 **69.9%**（5.2s）；  
- BiAE：**77.9%**（无耗时报告）。  
- NeSy-RAG 正确识别 61% 的 `more` 实例，而 LLM RAG 仅 19%、LLM Upper 仅 23%，显示其知识缺口检测有效性显著；  
- NeSy-RAG 的主要错误模式是将本可回答的 yes 误判为 `more`（31%），源于过度生成动态谓词。

## 6. 主要结论与发现

- NeSy-RAG 在无需领域训练的情况下，以 61.1% 准确率显著超过同模型的 LLM RAG 基线（42.8%），同时降低平均推理时间；  
- 符号化知识缺口检测能有效识别缺失用户信息并触发追问，对 `more` 标签的召回率远高于纯 LLM 方法；  
- 模块化 Prolog 合成与 0-arity 谓词抽象使查询构建可扩展、可归因，执行轨迹提供了透明度；  
- 主要局限是动态谓词过度生成导致保守偏差（将部分可答问题判为 `more`），但在高风险场景下这种保守性优于错误确定。

## 7. 优点

- **可解释性与归因**：每条推理步骤都能映射到源文本，比纯 LLM 的链式思考更可靠；  
- **模块化可扩展**：Prolog 模块与文本块绑定，支持选择性推理，避免庞大单体知识库；  
- **高效性**：模块可复用、查询上下文小、追问由程序化触发，平均耗时低于 RAG 基线；  
- **无训练依赖**：直接适用于任意文本领域，无需领域微调；  
- **知识缺口主动检测**：通过动态谓词自动发现缺失用户信息，弥补 LLM 不主动追问的短板；  
- **约束式查询生成**：利用 0-arity 谓词和 NL–PL 嵌入检索，减少 LLM 幻觉，提升查询精确度。

## 8. 不足与局限

- **实验覆盖有限**：仅在 ShARC 单一基准上评估，未测试多跳推理、跨 chunk 推理、开放域等更复杂场景；  
- **动态谓词生成质量不佳**：过度生成导致 31% 的 yes 实例被误判为 `more`，显著拉低准确率；  
- **依赖检索质量**：论文承认系统性能依赖于底层检索机制，而实验中采用了合成检索设置，未检验真实检索错误的影响；  
- **问题类型受限**：当前仅支持布尔问答，动态谓词也限定为单布尔参数，扩展性受限；  
- **模型规模未消融**：NeSy-RAG 仅用 gpt-oss:20b，未验证更大模型（如 gpt-5-mini）是否能进一步提升效果；  
- **安全性评估不足**：虽然文中讨论了保守偏差，但没有对答案潜在风险进行严格分析；
