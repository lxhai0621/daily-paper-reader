## 摘要
长期记忆对于LVLM智能体在多模态长时间交互中保持一致性并整合信息至关重要。然而，现有的智能体记忆系统通常将视觉经验简化为文本摘要，或依赖静态的检索-然后-推理流水线，这在查询时效率低下，并且在问题需要图像-文本绑定、时间更新或视觉细节时表现脆弱。我们提出了前瞻性多模态记忆编译框架，该框架将部分记忆推理过程从查询时间转移到记忆巩固时间。给定累积的多模态交互，一个提问者预测未来可能的问题候选，一个规划者编译基于问题条件的多模态记忆程序，一个怀疑者验证规划的证据路径是否能支持预测的答案。经过验证的问题-程序对形成一个结构化问题库，用于高效的查询时路由和证据检索。在多模态长期记忆基准上的实验表明，我们的方法在提高答案质量和视觉证据召回率的同时，降低了查询时的令牌和延迟成本。广泛的消融实验分析了自我反馈、动态规划、原始图像访问和问题库覆盖率的影响。

## Abstract
Long-term memory is essential for LVLM agents to maintain consistency and integrate information across extended multimodal interactions. Existing agent memory systems, however, often reduce visual experiences into textual summaries or rely on static retrieve-then-reason pipelines, which are inefficient at query time and brittle when questions require image-text binding, temporal updates, or visual details. We propose Prospective Multimodal Memory Compilation, a framework that shifts part of the memory reasoning process from query time to memory consolidation time. Given accumulated multimodal interactions, a Questioner predicts future question candidates, a Planner compiles question-conditioned multimodal memory programs, and a Doubter verifies whether the planned evidence path can support the predicted answer. The verified question-program pairs form a structured question bank for efficient query-time routing and evidence retrieval. Experiments on multimodal long-term memory benchmarks show that our method improves answer quality and visual evidence recall while reducing query-time token and latency costs. Extensive ablations analyze the effects of self-feedback, dynamic planning, raw-image access, and question bank coverage.

## 2. 方法论：PMMC框架

### 2.1 核心思想
将记忆访问规划从**查询时（query time）**前移至**记忆巩固时（memory consolidation time）**。系统在吸收新记忆时就为未来可能的问题"编译"好可执行的多模态记忆访问程序，经执行验证后存入**Question Bank（问题库）**；真实查询到来时直接路由到对应程序，以最小在线开销获取经过验证的证据路径。

### 2.2 总体流程（四阶段）
设多模态交互历史为 H = {m₁, ..., m_N}，其中每条记忆 m_i = (x_i, I_i, c_i, s_i, ℓ_i, b_i, μ_i) 包含对话文本、源图像、可选标题、会话/时序信息、可见边界和元数据。

1. **编译单元构建**：对每个新巩固的锚点，从互补关系（时间邻近、实体/词法重叠、共享图像、画像/偏好关联）中选择支持记忆，构成有界编译单元 U_t；确定性分析器识别证据机会 Ω_t（如视觉属性、图像-文本绑定、时间更新、冲突、多证据关系）。
2. **前瞻性提问（Questioner）**：条件于 (U_t, Ω_t)，生成有界数量的规范问题、改写和源支持主张：eQ_t = Q_θ(U_t, Ω_t)。编译器验证grounding与截止一致性、去重，推导每个候选问题的类型、推理模式、所需模态和最小证据数量。构建**编译器私有**的临时答案 bâ_j 和源支持 bÊ_j（禁止使用benchmark标注）。
3. **计划编译（Planner）**：对每个候选问题 bq_j，构造需求契约 R_j（模态、能力、证据多样性）；Planner只观察 (bq_j, R_j) 和类型化修订指令（看不到私有答案和源标识），选择受约束策略并确定性降级为类型化程序：z_j^(r)=P_ϕ(bq_j, R_j, Δ_j^(r−1))，π_j^(r)=Lower(z_j^(r), R_j)。程序使用冻结的算子内核（词法/稠密文本检索、跨模态图像检索、图像-文本扩展、时间扩展、原始图像物化、证据控制算子），禁止任意代码、SQL、路径和不受限工具调用。
4. **执行验证（Doubter）**：使用与在线相同的算子内核实际执行程序：(T_j^(r), E_j^(r)) = Exec(π_j^(r), H≤t; bq_j)。就绪检查要求：执行成功、非空证据、达到所有必需模态和能力、满足源多样性：Ready(E,T;R)=ExecOK(T) ∧ |E|>0 ∧ M_req(R)⊆M(E) ∧ K_req(R)⊆K(T) ∧ N(E)≥g(R)。Doubter返回 pass/revise/reject，可修订失败转为类型化指令（如添加视觉检索、扩展时间上下文、物化原始图像等），至多 r_max 轮修订。

### 2.3 在线路由与回答
- 真实查询 q 到来时，按会话、快照和截止兼容性过滤Question Bank条目，通过词法/稠密文本/多模态匹配 + 加权倒数秩融合（RRF）排序，仅当置信度与top-2间隔均超过阈值时接受编译路由。
- 选中的程序在 H≤tq 上**重新执行**（程序冻结的是访问策略和检索表示，而非固定证据标识，因此能检索到编译后新出现的合法记忆）。
- 通过就绪检查后，将检索到的引用物化为原始对话文本、标题、上下文和源图像，仅将这些程序发出的证据交给答案LVLM；否则触发**Native Multimodal-RAG回退**：
  A(q) = G(q, I_q, Materialize(E_q))（若路由和就绪通过）或 G_MMRAG(q, I_q, H≤tq)（否则）。
- 私有临时答案、源支持、Planner理由和Doubter反馈全部不会进入Question Bank——它只存"如何访问"，不存"答案"。
- 摊还成本：C_PMMC(n) = C_compile/n + C_online。

## 6. 主要结论

- **性能领先**：PMMC在8个配置中6个第一，总体宏平均HJ从最强baseline的46.7提升至**49.9**（MemLens上50.4 vs 48.1、Mem-Gallery上49.4 vs 45.4，各领先2.3/4.0分）；在Mem-Gallery上对每个backbone均第一。
- **多模态记忆访问规划可以前置**：执行验证过的、问题条件化的记忆程序，比统一的长上下文或固定检索策略更稳健。
- **各组件均有贡献**：移除Doubter使HJ降约3分且程序成功率降至82.7；移除动态Planner是最大单项退化（证据召回−8.3、程序成功率−15.2）；移除原始图像访问在视觉密集的Mem-Gallery上HJ降4.9分。
- **有界自反馈是关键**：r=0→r=2使HJ从54.0提升至57.0、回退率从22.4降至12.6、查询token下降15.8%；第三轮收益收敛（HJ仅+0.2）而写入成本大增21.1%。
- **覆盖非穷尽、路由成瓶颈**：QBank Cover@5达82.1%，Oracle选择可达到65.4 HJ（比部署版高8.4分），说明候选排序与路由仍有优化空间；仅12.6%查询触发回退。
- **摊还成本优势**：虽然编译成本最高，但更低在线成本使其相对M3-Agent/M2A约2次查询即回本、相对Native MM-RAG约12次、相对Caption-Text RAG约18次。

## 7. 优点与亮点

1. **范式创新**：将"何时、如何规划记忆访问"从查询时决策改为巩固时决策（"prospective compilation"），问题库是**路由与程序索引**而非答案缓存，从机制上可无缝应对新出现的记忆，避免缓存过期。
2. **执行验证闭环**：Planner生成的程序必须通过真实执行和准备好的检查（Eq. 5）才能入库；Doubter的修订指令总是绑定到具体执行失败，避免了无约束self-refinement的失控。
3. **信息隔离设计严谨**：Planner看不到私有答案和源标识、Doubter反馈被过滤、Question Bank不含临时答案——防止了编译阶段无意中"作弊"或泄露标注信息。
4. **证据形式可编程**：程序是**类型化算子序列**而非固定检索top-k，能按问题类型（文本/图像/时序/多跳）自然生成不同访问策略，而非单一策略服务所有查询。
5. **成本-质量的显式权衡**：以摊还成本公式和分析（图4、表3）明确展示了编译开销如何随使用频次摊薄，决策有据可依。
6. **多级评估体系**：从Harmonized Judge主指标，到细粒度F1/证据召回/图像命中，再到程序成功率/覆盖/回退等机制级诊断，形成"结果-机制-成本"三层验证。

## 8. 不足与局限

1. **覆盖率的固有上限**：前瞻性提问无法保证全覆盖；Cover@5仅82.1%，相当一部分查询依赖RAG回退兜底，未来信息需求高度不可预测的场景下优势会缩小且编译成本可能"沉没"。论文明确承认这是主要局限。
2. **写入时开销大**：编译阶段需要Questioner（b=8问题）+ Planner（最多8算子程序）+ Doubter（至多2轮执行验证）的多次模型调用；对一次性/低频查询场景，编译成本远高于查询节省。
3. **额外计算资源未透明**：未披露编译阶段的GPU数量、总推理时间和能源成本；对实际部署的硬件需求评估不足。
4. **单backbone消融验证**：主要消融与诊断仅基于Qwen3.5-9B，组件贡献和超参设置的**跨模型通用性**缺乏证据；不同规模/能力的模型在"提问质量"和"程序生成"表现上可能有显著差异。
5. **评估过滤了关键能力子集**：排除了拒答、冲突检测实例（Mem-Gallery共265个样本），而这些恰是长期记忆智能体（尤其涉及错误修正与"知道何时不知道"）的重要能力维度。
6. **路由作为瓶颈尚未解决**：Oracle-higher（+8.4分）暴露了候选排序缺陷，论文将其归为未来工作的"持续维护与学习策略"，而非当前方案闭环解决的部分。
7. **领域与模态局限**：仅验证于对话记忆/家庭相册类benchmark（文本+静态图像），未覆盖视频、音频、交互式环境或工具使用场景；中文等多语言场景也未验证。
