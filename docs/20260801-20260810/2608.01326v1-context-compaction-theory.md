## 摘要
大型语言模型（LLM）具有有界的上下文窗口。上下文窗口是LLM在单次推理中能消耗的最大输入大小。AI代理依赖一种称为上下文压缩的过程，以便在调用LLM时将其状态适配到上下文窗口内。尽管其普遍存在，上下文压缩几乎没有得到任何形式化的分析。在本文中，我们启动了对上下文压缩的形式化研究。我们首先引入一个框架，包含两个博弈，它们捕捉了当代AI代理在实践中使用的两种上下文压缩算法策略。上下文选择博弈模拟了上下文压缩算法，该算法选择代理累积状态的一个子集进行保留。上下文生成博弈模拟了上下文压缩算法，该算法通过有界长度的任意消息总结代理状态。然后我们证明了上下文生成博弈与单向通信复杂性之间的等价性。在目标误差内回答一组查询所需的最小上下文压缩预算等于诱导通信问题在相同误差下的单向通信复杂性。因此，通信复杂性的已知界限直接转移到上下文压缩。我们还表明，上下文选择博弈对应于单向通信协议的一个受限类别。选择与生成之间的任何差距因此也是两类通信协议之间的差距。我们证明了存在一组查询，使得生成所需的预算严格少于选择。上下文生成博弈与单向通信之间的等价性还使我们能够衡量部署的上下文压缩算法在查询上的表现相对于最优策略如何。作为一个例子，我们提供了一个案例研究，评估Anthropic的上下文压缩端点在集合成员查询上的表现。

## Abstract
Large Language Models (LLMs) have a bounded context window. The context window is the maximum input size an LLM can consume for a single inference. AI agents rely on a process called context compaction to fit their state within the context window when calling an LLM. Despite its ubiquity, context compaction has received essentially no formal analysis. In this paper, we initiate a formal study of context compaction. We first introduce a framework consisting of two games that capture the two algorithmic strategies for context compaction used by contemporary AI agents in practice. The Context Selection Game models context compaction algorithms that select a subset of an agent's accumulated state to retain. The Context Generation Game models context compaction algorithms that summarize an agent's state by an arbitrary message of bounded length. We then prove an equivalence between the Context Generation Game and one-way communication complexity. The minimum context compaction budget for answering a set of queries within a target error is equal to the one-way communication complexity of the induced communication problem at the same error. Known bounds from communication complexity therefore transfer directly to context compaction. We also show that the Context Selection Game corresponds to a restricted class of one-way communication protocols. Any gap between selection and generation is therefore a gap between two classes of communication protocols. We prove that there exists a set of queries for which generation needs strictly less budget than selection. The equivalence between the Context Generation Game and one-way communication also lets us measure how well a deployed context compaction algorithm performs on a query relative to the optimal strategy. As an example, we present a case study that evaluates Anthropic's context compaction endpoint on set membership queries.

### 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：大型语言模型（LLM）具有硬性的上下文窗口限制（context window），即单次推理能处理的最大输入 token 数。AI 代理（agent）在长会话中会持续累积内部状态（用户消息、模型响应、工具执行结果等），一旦状态超出上下文窗口，就必须通过**上下文压缩（Context Compaction）**将状态压缩到窗口大小以内。

- **核心问题**：上下文压缩在当代 AI 代理系统中已被广泛使用（如 Claude Code、Cursor、Codex 等），但**缺乏任何形式化的理论分析**。现有的工作主要是经验性的评测，无法回答"压缩后哪些信息必然保留或丢失"这一根本问题。

- **整体含义**：本文首次为上下文压缩建立了形式化理论框架，将其与通信复杂性理论建立等价关系，使得通信复杂性中的大量已知结果能够直接迁移到上下文压缩领域，并为衡量部署算法的实际性能提供了理论基准。

### 2. 方法论：核心思想、关键技术细节与公式

#### 2.1 两个博弈框架

- **核心思想**：将上下文压缩建模为压缩算法（玩家）与代表未来信息需求的对手（adversary）之间的二人博弈。

- **上下文选择博弈（Context Selection Game）**：
  - 模拟"从累积状态中选择子集保留"的压缩策略。
  - 博弈过程：对手确定条目宇宙 X → 选择器选择子集 S ⊆ X（满足预算约束 Σs(xᵢ) ≤ B）→ 按查询机制选择查询 q → 根据价值函数 v_q(S) 计算误差。
  - 定义了两种查询机制：**随机查询机制**（期望误差）和** oblivious adversary 查询机制**（最坏情况误差）。

- **上下文生成博弈（Context Generation Game）**：
  - 模拟"通过任意有界长度消息总结状态"的压缩策略（如 LLM 归纳摘要）。
  - 生成器使用"冷凝器–解释器"配对（condenser–interpreter pair）：冷凝器将条目宇宙映射为有界长度消息 Cond(X) ∈ Σ≤B，解释器根据消息和查询输出答案 Int(Cond(X), q)。
  - 生成博弈是选择博弈的超类（SELECT ⊆ GEN），去除了"输出必须是子集""不能利用顺序编码""输出大小为条目大小之和"三项限制。

#### 2.2 与通信复杂性的等价性（定理1）

- **核心定理**（Theorem 1）：上下文生成博弈 ≡ 单向通信复杂性（one-way communication complexity）。
  - Property 1（随机机制）：最小预算（期望误差 ≤ ε）等于 μ-分布单向通信复杂性 R^→_{μ,ε}(Π_G)。
  - Property 2（oblivious 对手机制）：最小预算（所有输入期望误差 ≤ ε）等于最坏情况单向通信复杂性 R^→_ε(Π_G)。
  - **证明思路**：冷凝器等价于 Alice 的编码函数，解释器等价于 Bob 的解码函数；随机化算法与公共硬币（public-coin）协议一一对应。

#### 2.3 选择作为受限通信（推论2与定理3）

- **推论（Corollary 2）**：选择算法精确对应"消息识别子集、输出仅依赖于子集和查询"的受限单向协议。SELECT 与 GEN 之间的任何差距 = 子集编码协议与无限制单向协议之间的差距。

- **分离定理（Theorem 3）**：存在查询集（精确表示 X ⊆ Y，n = 2^k）使得：
  - GEN 只需 n 比特预算（发送指示向量）；
  - SELECT 至少需要 n·log₂n 比特（因为子集 S(X) 必须能唯一确定 X，迫使 S(Y) = Y，即保留全部 n 个条目）。
  - 差距为 Θ(log n) 因子。

#### 2.4 现有算法分类

- 论文将生产环境中的压缩算法分类为 SELECT 或 GEN：
  - **GEN**：Codex、Gemini CLI（LLM 摘要）
  - **SELECT+GEN**：Claude Code、OpenCode（工具结果粒度）
  - **SELECT**：OpenAI Assistants API（消息）、LangChain trim_messages（消息）、Aider repo map（代码符号）、LLMLingua（token）、Selective Context（token）

### 3. 实验设计

- **案例研究设置**：
  - **数据集**：Malicious URLs 数据集（Kaggle），从中均匀采样 15,000 个 URL。
  - **被测系统**：Anthropic Claude API 的上下文压缩端点（使用 Opus 4.8 作为 LLM）。
  - **任务**：集合成员查询（set membership queries）——询问某个 URL 是否在记录集合中。
  - **提示设计**：明确告知压缩端点其输出仅用于成员查询（模拟 Bloom filter 已知工作负载的场景）。
  - **查询方式**：200 个查询（50% 真阳性条目测试假阴性，50% 未记录条目测试假阳性），每个查询单独发送压缩后的上下文。
  - **对照组**：不做压缩，将全部 15,000 个 URL 保留在上下文中。

- **性能基准对比**：
  - 同大小的 Bloom filter（理论最优近似成员查询器，达到信息论下界在常数因子内）；
  - 信息论下界曲线（½·2^(−B/N)）；
  - 随机猜测基线（误差率 0.5）。

- **充分性评估**：

### 6. 主要结论与发现

- **理论发现**：
  1. 上下文生成博弈的最优预算 = 对应单向通信问题的通信复杂性（定理1），通信复杂性的下界直接适用于上下文压缩；
  2. 选择博弈是受限单向协议，二者差距为协议类的差距；
  3. 存在查询族使 GEN 比 SELECT 严格更省预算（Θ(log n) 因子）；
  4. set disjointness 查询示例表明：正确回答所有此类查询所需预算与原始存储相同（Ω(Nm) 比特），表明某些任务压缩收益有限。

- **实证发现**：
  1. Anthropic 的压缩端点（Opus 4.8）在约 14 Kbits 预算下，集合成员查询误差率为 0.505–0.555，**接近随机猜测**；
  2. 同大小 Bloom filter 的误差约 1/3，信息论下界更低；
  3. 对照组（无压缩）误差仅 0.02，证明错误源于压缩过程的信息丢失；
  4. 压缩摘要文本显示模型坦言无法无损存储，退化为基于模式匹配的启发式猜测；
  5. 假阳性/假阴性比例因种子而异，但总误差接近 0.5，表明压缩后几乎没有保留成员信息。

- **理论贡献显著**：首次为上下文压缩建立形式化理论框架，定义了清晰的博弈模型（SELECT 与 GEN），并将问题映射到成熟的通信复杂性理论上，使大量已有结果可直接复用。
- **等价性证明简洁有力**：通过识别冷凝器/解释器与 Alice/Bob 的函数一致性，给出干净的双向映射，覆盖确定性与随机化情形。
- **分类体系实用**：对现有生产系统的压缩算法进行了系统分类（表1），使理论框架与实际系统对接。
- **SELECT ⊊ GEN 的证明**：通过构造性论证揭示了选择策略的固有限制，为代理设计者选择压缩策略提供理论指引。
- **案例研究展示了理论的应用价值**：说明如何用理论下界量化实际部署算法的性能差距——这是"测量原本无法测量的东西"。

### 8. 不足与局限

- **信息论而非计算论（核心局限）**：定理上下界衡量的是比特数，即"需要多少信息"，而非"计算这些信息需要多少计算量"。一个可达的预算可能无法被实际的 LLM 摘要器实现。下界对所有算法成立（无论计算量），但上界不保证实际可实现。
- **自适应对手未覆盖**：定理仅适用于随机和 oblivious 查询机制；若对手在观察压缩输出后再选择查询，等价性不成立（留作公开问题）。
- **单次压缩模型**：只分析单次压缩调用，而真实代理会多次压缩并无情地丢弃信息。多次压缩的累积误差增长未被刻画。
- **生成算法的定义过于宽泛**：GEN 允许任何形式的任意消息，包括了现实中无法构造的抽象算法（如理论最优草图），实用性受限。
- **案例研究局限性**：仅一个提供商、一个模型、一个数据集；未与其他压缩方法做系统对比；样本量小；作者明确承认这是快照式测量。
- **SELECT/GEN 差距仅证明了一个特定构造**：对于哪些查询族普遍存在差距、差距最大能达到多大，论文仅给出一个 Θ(log n) 的例子，未给出完整刻画。
- **零误差假设的强限制**：定理3的分离仅针对零误差情形，对于允许误差的情况是否仍有差距未给出证明。
