## Abstract
Knowledge Base Question Answering (KBQA) aims to retrieve accurate answers to natural language queries by retrieving and reasoning over large-scale structured knowledge bases (KBs). Advanced semantic parsing-based methods promoted by large language models (LLMs) demonstrate superior performance by transforming questions into structured queries, i.e., logical forms (LFs). However, LFs generated by LLMs could be non-executable due to the inherent semantic hallucination issue of LLMs and the complex graph retrieval characteristics of the KBQA task. To address this challenge, we propose a novel "generate-verify-refine" framework, termed Action-Reflection-Integrated KBQA (ARI-KBQA) for reliable LF generation. ARI-KBQA introduces a dual-module cooperative architecture: First, an action generator is trained to produce initial query paths based on a hop-by-hop reasoning strategy. Then a reflection verifier dynamically validates path feasibility by interacting with the KBs. Consequently, ARI-KBQA filters out invalid LFs and provides semantic correction feedback to the action generator for iteratively refining LFs. Evaluations on standard KBQA benchmarks show that the proposed ARI-KBQA significantly enhances model performance with a reduced search space, especially in complex multi-hop query scenarios.

## 2. 方法论

### 2.1 核心思想

- ARI-KBQA 采用双模块架构：
  - **动作生成器（Action Generator）**：基于逐跳推理策略生成初步查询路径，降低一次性生成完整 LF 的复杂度。
  - **反思验证器（Reflection Verifier）**：与知识库实时交互，验证当前路径可行性，过滤无效 LF，并向动作生成器提供语义纠正反馈。
- 整体流程：**逐跳生成 LF → 执行验证 → 若不可执行则反思替换关系 → 继续生成/终止 → 聚合成最终 LF → 执行得到答案**。
- 训练分两阶段：先分别微调动作生成器与反思验证器；推理阶段再进行双模块协同。

### 2.2 动作生成器：逐跳 LF 生成

- 对问题 \(q\) 的第 \(i\) 个主题实体 \(e_i^q\)，第 \(j\) 跳 LF 的生成依赖：
  - 问题 \(q\)
  - 当前主题实体 \(e_i^q\)
  - 前 \(j-1\) 跳已生成 LF \(l_i^{j-1}\)
  - 知识图 \(G\)
- 目标为最大化逐跳生成概率：
  - \(P_\theta(L_p|q,G)=\prod_{i=1}^{|E_q|}P_\theta(l_i^j|q,e_i^q,l_i^{j-1},G)\)
- 引入 `[CLS]` 表示生成开始，`[EOS]` 表示终止。
- 生成各主题实体的初步逻辑形式（PLF）后，动作生成器再综合所有 PLF，生成最终精炼逻辑形式（RLF）：
  - \(P_\theta(l_r|q,G)=P_\theta(l_r|L_{PLF})P_\theta(L_{PLF}|q,G)\)
- 最终目标：
  - \(L_a=\log P_\theta(L_p|q,G)+\log P_\theta(l_r|q,G)\)

### 2.3 反思验证器：动态验证与关系替换

- 当动作生成器生成第 \(j\) 跳 LF 后，反思验证器根据 LF 结构判断检索方向：
  - 前向搜索：`(JOIN (R r) e)`
  - 后向搜索：`(JOIN r e)`
- 为减少噪声，从 KB 中按加权相似度选择 top-k 候选关系：
  - \(\Phi(r_c)=\arg topk_{r_c\in C}(\sum_{i=1}^n p_i \cdot sim(r_i,r_c))\)
  - 其中 \(p_i\) 是第 \(i\) 个 LF 的概率，\(sim\) 计算生成关系与候选关系的相似度。
- 反思验证器输入问题、主题实体、前 \(j-1\) 跳 LF、候选关系集 \(C\) 和知识图 \(G\)，输出第 \(j\) 跳最可能关系：
  - \(L_r=\log P_\theta(r|q,e_i,l_i^{j-1},C,G)\)

### 2.4 LoRA 微调

- 使用 LoRA 进行参数高效微调。给定训练集 \(Z=\{(x_i,y_i)\}\)，优化：
  - \(\max_{\Delta\Phi}\sum_{(x,y)\in Z}\sum_{t=1}^{|y|}\log P_{\Phi+\Delta\Phi}(y_t|x,y_{<t})\)
- 其中 \(\Phi\) 为预训练权重，\(\Delta\Phi\) 为额外可训练参数，\(\theta=\Phi+\Delta\Phi\)。

### 2.5 推理算法流程

- 对每个主题实体：
  - 从 `[CLS]` 开始，按 beam search 生成第 \(j\) 跳 LF 候选。
  - 若当前跳存在可执行 LF，则认为与事实一致，直接生成下一跳。
  - 若当前跳所有 LF 均不可执行，则调用反思验证器替换关系，再继续生成。
  - 若所有 LF 包含 `[EOS]`，用 softmax 归一化概率；若 \(1-P([EOS])>P([EOS])\) 则继续生成，否则终止。
- 生成所有主题实体的 PLF 后，聚合为最终 RLF。
- 若最终 RLF 可执行，则返回执行结果；否则返回无答案。
