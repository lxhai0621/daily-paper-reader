## 摘要
我们提出上下文语言模型（Context Language Models，CLMs），一种原生管理自身上下文的语言模型。我们通过将上下文视为一个文件，并允许模型对该文件进行不受限制的更新来实现这一点。这使模型能够学习哪些内容对在上下文中保持最为重要，并自然扩展到多智能体系统，其中多个智能体上下文作为文件共存。用现有模型零样本构建 CLMs，在多种任务上优于 SOTA 上下文管理策略：在 BrowseComp-Plus 上准确率提高 11.4%，FLOPs 减少 21.5%；在 12 小时 EdgeBench 上得分提高 5%，FLOPs 减少 59%；在 24 小时多仓库智能体集群任务上，在相同计算量下改进幅度高出 65%。此外，通过将上下文管理从外部框架控制转变为模型内在行为，CLMs 自然支持上下文管理策略的上下文内学习和参数化学习。我们表明，CLMs 可以通过标准技能优化循环演化出的自然语言指令进行引导，在上下文管理任务上将留出准确率提高最多 35.9 个百分点，同时减少计算量。我们还为 CLMs 引入了一种在线强化学习方法，在 BrowseComp-Plus 上将 Qwen3.5-9B 性能提高 47.6%，同时 FLOPs 减少 12%。最后，我们为 CLM 服务协同设计了 Suffix Cache Reuse，在性能匹配的情况下，相对于标准 SGLang 进一步将服务器端计算量减少 35%。

## Abstract
We introduce Context Language Models (CLMs), language models that natively manage their own context. We implement this by treating the context as a file and allowing the model to make unrestricted updates to this file. This allows the model to learn what is most important to maintain in context, and naturally extends to multi-agent systems where multiple agent contexts coexist as files. Building CLMs zero-shot with existing models outperforms SOTA context management strategies across a variety of tasks: 11.4% higher accuracy with 21.5% fewer FLOPs on BrowseComp-Plus, 5% higher scores with 59% fewer FLOPs on 12-hour EdgeBench, and 65% greater improvement with the same compute on a 24-hour multi-repository agent-swarm task. Moreover, by shifting context management from external harness control to intrinsic model behavior, CLMs naturally enable both in-context and parametric learning of context-management strategies. We show that CLMs can be steered with natural-language instructions evolved through a standard skill-optimization loop, improving held-out accuracy by up to 35.9 points on a context-management task while reducing compute. We also introduce an online reinforcement learning method for CLMs, improving Qwen3.5-9B performance on BrowseComp-Plus by 47.6% while using 12% fewer FLOPs. Finally, we co-design Suffix Cache Reuse for CLM serving, further reducing server-side compute by 35% relative to standard SGLang at matched performance.

# 论文总结：Context Language Models（上下文语言模型）

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：上下文是语言模型处理与保留跨时间信息的基石，但传统上**上下文管理并非 LM 的原生能力**。已有工作依赖外部“harness”（框架）进行管理：
  - **手工设计的固定策略**：如 Cursor、Codex、Terminus2 在预设长度阈值触发压缩；MEM1 每轮更新上下文。
  - **受限动作空间的工具化方法**：如 Self-Compact、AutoCompact（模型决定何时压缩）、Context-as-a-Tool（受控压缩）、ACM（增加卸载与检索）、Sculptor（片段级操作）。
  - 这些方法的**自主性逐渐提高，但仍被限制在人类预定义的动作空间内**。
- **核心洞察**：作者援引 Sutton 的“The Bitter Lesson”，主张应让 LM 自行搜索并学习优于人类先验的上下文管理策略，而非依赖手工框架。
- **研究问题**：能否让语言模型**原生地、不受限制地**管理自己的上下文？这样做是否能同时提升效果与计算效率，并支持多智能体场景？
- **整体含义**：将上下文管理从**外部框架控制**转为**模型内在行为**，使上下文管理策略可像其他技能一样被学习（上下文内学习与参数化学习）。

## 2. 方法论

### 2.1 核心思想：上下文即文件（Context-as-a-File）

- **形式化定义**：
  - 标准 LM 为追加式上下文转移：`c_{t+1} = c_t ⊕ f^LM_θ(c_t)`（⊕ 表示拼接）。
  - CLM 将上下文维护的全部责任交给模型自身：`c_{t+1} = f^CLM_θ(c_t)`，其中 `f^CLM_θ` 是模型控制的**任意函数**。
  - 式 (2) 在形式上包含所有先前的工具化方法，区别在于 CLM 让模型**自己定义**这些上下文管理函数（作为元能力），而非在框架中预定义。
- **实现方式**：
  - 将 LM 的实时上下文镜像为一个**可直接编辑的文件**，在系统提示中给出路径。
  - 模型可用通用 Bash 命令自由编辑该文件（如 `open(...,"w").write(...)`、正则替换、循环压缩等）。
  - 对该文件的修改会**自动同步到 LM 的实时上下文**并发送至推理服务器继续生成；若模型不编辑，则默认追加生成 token。该设计在**上下文复用**与**编辑灵活性**之间取得平衡。
- **多智能体扩展**：允许多个上下文文件共存并分别同步至各自的 LLM 服务器；智能体集群可通过初始化多个上下文文件实现，子智能体可通过创建/删除上下文文件来初始化与终止。

### 2.2 上下文内学习与强化学习

- **自然语言引导**：`c_{t+1} = f^CLM_θ(c_t; s)`，通过附加一句自然语言指令 `s`（如“超过 Y token 后压缩到约 4K”“在子问题边界压缩”“压缩前先备份”）即可改变上下文管理策略，无需改动框架或参数。
- **技能演化优化循环**：`s* = argmax_s E_{x~D}[R(τ(x; s))]`。采用 prompt-evolution 循环（Agrawal et al., 2026）：每轮在训练集 rollout，由 proposer 模型基于轨迹生成候选技能，在开发集评估并选择进入下一轮。可为**辅助演化**（更强外部模型作 proposer）或**自演化**（智能体模型自身作 proposer）。
- **在线强化学习**：
  - 由于上下文编辑打破追加式轨迹，采用 **stepwise GRPO**：采样一组完整轨迹，计算轨迹级结果奖励的 GRPO 优势，并将其分配给所有组成片段。
  - 引入 **成功门控效率优势（success-gated efficiency advantage）**：
    - 令 `c_i` 为轨迹 `τ_i` 的 prefix-reuse FLOPs，`𝒢⁺_g` 为组 `g` 中成功的轨迹集合，`c̄_g` 为其平均 FLOPs。
    - `A^eff_i = clip((c̄_g − c_i)/c̄_g, −1, 1)`（当 `i ∈ 𝒢⁺_g`），否则为 0；若组内成功轨迹少于 2 条则全部置 0。
    - 最终优势 `A_i = A^out_i + w_eff · A^eff_i`，鼓励**既正确又高效**的轨迹，且效率信号只在成功子集内重排序，避免失败轨迹获得效率奖励或通过频繁编辑“刷分”。
- **效率度量：prefix-reuse FLOPs**：`FLOPs_prefix-reuse = FLOPs_prefill(未匹配上下文后缀) + FLOPs_decode(生成 token)`，捕捉解码、预填充以及编辑后重预填充的轨迹级推理成本。
- **Suffix Cache Reuse（SCR）服务协同设计**：
  - 当 `B` 被 `B'` 替换后，SCR **复用所有存活 token（包括后缀 `C`）的缓存状态**，仅重预填充新插入/追加的 `B'`；标准 prefix-cache 则需重预填充首个不匹配点之后的所有 token。
  - 存活后缀保留编码旧前缀的“陈旧”缓存状态，有时反而有益（保留更丰富的过往信息）。
  - 对全注意力层：diff 新提示与旧提示，找出存活 span，按长度降序重定位最多 `K`（主文取 6）个 span，复用其 KV、重旋转 RoPE 到新位置后拼接；缓存槽为会话私有，分配失败则回退到标准重预填充。
  - 对线性注意力层（如 Qwen3.6-27B 的 48/64 层 Gated DeltaNet）：在编辑前快照循环状态并从快照继续，编辑仅反映在 16 个全注意力层。
  - 还适用于聊天端点中**剥离历史推理 token** 导致的重复预填充场景。

## 6. 主要结论与发现

- **零样本 CLM 在效果与效率上均优于 SOTA 上下文管理策略**：
  - BrowseComp-Plus：59.4%（Qwen3.6-27B，32K），相对最强基线（Codex 风格摘要）准确率高 **11.4%**，prefix-reuse FLOPs 少 **21.5%**（对 MEM1 少 28.9%）。
  - TerminalBench 2.1：与最强基线持平，FLOPs 仅为其 **70%**；TBLite：73.7% vs 67.0%，FLOPs 为 91%。
  - EdgeBench-10（12 小时）：44.6 vs 摘要的 42.3，FLOPs 179 vs 437（**少 59%**）；Claude 4.6 Sonnet 下达 51.0 vs 42.3。
  - Software World（24 小时多仓库集群）：相同算力下下游加速比提升 **65%**。
  - 数学优化：在全部 4 个问题上取得最高 best-of-run 分数（如圆填充 2.618 vs OpenEvolve 2.541；Heilbronn 0.03653 vs 0.03127）。
- **涌现的创造性行为**：定义并维护多智能体编排用的 in-context 记分板/追踪器（163 次就地编辑，上下文仅 6–8K token）；为内部笔记引入新聊天角色“notes”；定义并复用上下文管理函数（如 `compact_turns` 调用 37 次）；用循环移除无关搜索结果、压缩冗长输出。
- **可学习性**：
  - 一句自然语言指令即可改变压缩时机、语义边界、备份行为。
  - 技能演化在 ContextBench 上最多提升留出准确率 **35.9 个百分点**（如 KV Store 开发集 22.3%→83.8%，留出测试 38.3%→74.2%），同时降低成本、扩展 Pareto 前沿。
  - RL 使 Qwen3.5-9B 在 BrowseComp-Plus 上从 28.8% 提升至 **42.5%（+47.6%）**，匹配训练后的摘要框架且 FLOPs 从 2.19 降至 1.34（**少 38.8%**）。
- **服务效率**：SCR 在性能匹配下将服务器端计算降至标准 SGLang 的 **65%**（相对再减少约 35%）；其中 5.3 个百分点收益来自推理 token 剥离，2.5 个百分点来自上下文编辑。
- **上下文长度感知**：现有 LM 在长上下文下估计能力有限，倾向于输出分桶值（如 6.2K、9.8K）；环境提示可显著改善估计，Claude-4.6-Sonnet 倾向低估，GPT-5.4 校准最好。

## 7. 优点

- **思想简洁而统一**：将“上下文即文件”作为唯一原语，`c_{t+1} = f^CLM_θ(c_t)` 在形式上涵盖并超越所有既有工具化方法，避免为每种策略设计专用接口。
- **优雅的“少即是多”设计**：尽可能少地在框架层硬编码，工具以 in-context 技能形式灵活定义/添加/修改（如搜索工具）。
- **效率度量严谨**：提出 prefix-reuse FLOPs，显式计入编辑引发的重预填充，避免只统计生成长度而忽略真实推理成本。
- **学习路径完整**：从自然语言引导 → 技能演化 → 在线 RL，展示上下文管理可像技能一样被学习并内化到权重。
- **服务协同设计**：SCR 与 SGLang 集成，并扩展到混合注意力架构；还发现其对标准聊天服务的推理 token 剥离同样有效，具有独立价值。
- **实验对照公平**：为每个基线提供同等详细度的技能文档，统一基座模型、预算与评分器；报告 Pareto 前沿而非单点指标
