## 摘要
记忆自进化利用任务反馈来迭代改进可执行记忆程序，这些程序负责存储和检索来自过去交互的信息。现有方法通常采用整体式进化，从混合反馈中推导修正方向，并通过整体性能判断进展。这可能模糊优化方向，并掩盖被其他方面退步所抵消的特定能力收益，使有前景的方向未得到充分探索。我们引入能力驱动的进化，它将搜索引导从整体性能扩展到单个能力维度，保留有前景的修正，并将探索扩展到整体式进化的边界之外。我们提出 PrisMem，它使用依赖感知的能力选择来优先考虑具有潜在跨能力收益的目标，并使用历史引导的诊断来改进能力专家。轨迹引导的整合在成对差分案例上比较已评估的程序，利用它们的行为差异将互补收益整合为一个统一的记忆程序。实验表明，PrisMem 在 BEAM-1M 和 LongMemEval-M 上分别以 10.54 和 7.83 个百分点的优势优于最强基线，证明了其在百万 token 历史上的有效性。

## Abstract
Memory self-evolution uses task feedback to iteratively improve executable memory programs that store and retrieve information from past interactions. Existing approaches typically adopt holistic evolution, deriving revision directions from mixed feedback and judging progress by overall performance. This can obscure optimization directions and hide capability-specific gains offset by regressions elsewhere, leaving promising directions underexplored. We introduce capability-driven evolution, which extends search guidance from overall performance to individual capability dimensions, preserving promising revisions and expanding exploration beyond the boundaries of holistic evolution. We propose PrisMem, which uses dependency-aware capability selection to prioritize targets with potential cross-capability benefits and history-guided diagnosis to refine capability specialists. Trace-guided integration compares evaluated programs on paired differential cases, using their behavioral differences to consolidate complementary gains into a unified memory program. Experiments show that PrisMem outperforms the strongest baselines by 10.54 and 7.83 percentage points on BEAM-1M and LongMemEval-M, respectively, demonstrating its effectiveness on million-token histories.

# 论文总结：Capability-Driven Self-Evolution of Agent Memory（PrisMem）

## 1. 核心问题与研究动机

- **背景**：记忆已成为 LLM 智能体的关键组件，用于存储和复用历史交互信息。真实交互包含显式事实、隐式偏好、动态变化状态等多样信息，且不同请求要求不同能力（事实检索、时序追踪、偏好提取、跨会话综合、对抗性处理等）。因此记忆本质上是**多维度**的，一个记忆程序需同时支撑多种相互关联的能力。
- **现有方法的局限**：以 M⋆、EvolveMem、MemEvolve、MemPro 为代表的自进化记忆方法普遍采用**整体式进化（holistic evolution）**——从混合反馈中推导修正方向，并以整体任务性能判断进展。
- **由此产生的两个核心问题**：
  - **优化方向模糊**：混合反馈把不同能力任务的失败混在一起，同一记忆组件可能对应多种效果相反的修改方向（如扩大检索可改善多会话推理，却加剧过度个性化）。
  - **能力增益被掩盖**：某一能力的提升常被其他能力的退步抵消，导致整体分数不变甚至下降。论文分析显示，**80.5% 没有整体增益的修订仍至少提升了一项能力**，这些有用机制因此被忽视。
- **核心洞察**：将进化空间从"单一整体性能维度"提升到"多个能力维度"，即**能力驱动进化（capability-driven evolution）**，用能力级反馈明确诊断方向、用能力级评估保留有潜力的修订，从而扩展探索边界。

## 2. 方法论：PrisMem

### 2.1 核心思想与基础设定

- **问题形式化**：任务实例 $x=(H,q,y,E)$（历史、问题、参考答案、参考证据），记忆程序 $P$ 从 $H$ 构建记忆并检索内容回答问题，得分 $s(P;x)\in[0,1]$。数据集分为 $S_{train}$、$S_{valid}$、$S_{test}$。
- **细粒度记忆接口**：将记忆程序分解为五个可局部修改的组件——**Extraction、Indexing、Planning、Retrieval、Answer**，比传统"add/retrieve"抽象提供更精确的修改边界。
- **能力集合**：五个代表能力——事实检索（F）、时序追踪（T）、偏好提取（P）、多会话综合（M）、对抗性（A）。离线用 LLM 为每个任务标注 1 个主能力 $\ell(x)$ 和最多 2 个次能力 $\sigma(x)$；**标签仅用于组织反馈，绝不在评估时提供给记忆程序**。

### 2.2 三阶段进化流程

- **Stage I：冷启动（T₁=5 轮）**
  - 从极简种子程序 $P_0$ 出发，联合考虑所有能力的反馈，快速建立均衡基础程序。
  - 构建**基于证据的诊断度量表**：用语义相似度衡量参考证据与 (i) 抽取的记忆单元、(ii) 以证据为查询检索到的内容、(iii) 针对实际问题检索到的内容之间的匹配度，分别对应信息保留、索引可达性、检索有效性，帮助定位 Extraction/Indexing/Planning/Retrieval 的弱点。

- **Stage II：能力精炼（T₂=12 轮）**
  - **依赖感知能力选择**：量化某能力对另一能力的"潜在错误压力"。
    - 结构基率先验 $D(c_p\!\to\!c_s)$：主 $c_p$ 任务中同时需要 $c_s$ 的比例。
    - 集中度 $F^{t,c_s}_t(c_p\!\to\!c_s)$：$c_s$ 专家在 $c_p$ 任务上的错误中，需要 $c_s$ 的任务所占比例。
    - 传入错误压力 $I_t(c_p\!\to\!c_s)=\bar e^{t,c_s}(c_p)\,[F-D]_+$。
    - 紧迫度 $U_t(c)=\bar e^{t,c}(c)+\max_{c_p\neq c} I_t(c_p\!\to\!c)$（用 max 而非 sum 避免度中心性偏差）。
    - 折扣后优先级 $\rho_t(c)=U_t(c)/(1+n_t(c))$，避免反复投入已停滞能力；$c_t=\arg\max_c \rho_t(c)$。
  - **历史引导诊断**：从目标能力任务中筛选得分低于 $\delta=0.8$ 的失败案例，按优先级权重 $w_t(i)$ 排序——历史得分高（回归见证）但当前失败者优先，同时对反复选中的案例和重复覆盖的次能力组合做折扣，选 $K=5$ 个多样且可操作的案例。
  - 每次精炼从该能力的**专家程序 $P^\star_t(c)$** 出发，允许局部增益在整体分数被掩盖时仍能发展。

- **Stage III：轨迹引导整合（T₃=3 轮）**
  - 从整体最优程序出发，按血统拓扑顺序（由近及远）逐步整合各能力专家。
  - **成对差分案例（paired differential cases）**：为每个能力选出基程序与专家得分差距最大的训练案例，对比二者执行结果，暴露行为差异，指导规划模型判断如何纳入增益与副作用。
  - 若整合未提升整体分数或任一能力下降超过 $\theta$，将失败实现与差分案例执行结果返回编码模型重试。

### 2.3 高效进化

- **紧凑诊断上下文**：去除冗余、标记省略、保留与问答相关片段，诊断案例 token 成本平均降低 **44%**（16,776→9,428 tokens）。
- **修订感知执行复用**：比较候选与其父程序的组件差异，从最早受影响阶段开始重执行（如仅改检索可复用已构建记忆），减少冗余处理。

## 3. 实验设计

## 6. 主要结论与发现

- **性能**：PrisMem 在 BEAM-1M 与 LongMemEval-M 上整体分数分别比最强静态基线高 8.17–11.53 pp、比最强自进化基线高 7.83–10.54 pp；在几乎所有能力维度上均为最佳。GPT-5.5 上也领先基线 6.17–20.41 pp。
- **效率**：token 使用与其他方法相当；进化成本比 M⋆ 降低 4%–30%。
- **消融结论**：移除能力驱动进化导致 **−10.15 pp**（最大来源）；移除轨迹引导整合 **−3.16 pp**；round-robin 替代依赖感知选择 **−2.55 pp**；随机案例选择 **−5.26 pp**。
- **轨迹分析**：Stage II 中能力分数间歇性提升，精炼一个能力可同时更新其他能力的专家（反映能力依赖）；最终整合程序接近进化中达到的能力峰值。
- **路由 vs 整合**：整合优于问题级路由 5.65 pp、优于 oracle 标签路由 1.12 pp，说明单一统一程序比按能力分派专家更优。
- **泛化性**：进化程序可跨模型、跨数据集迁移而无需再优化，仍保持强性能。

## 7. 优点

- **范式创新**：首次明确提出"能力驱动进化"，把搜索引导从标量整体分数提升到能力维度，直面整体式进化的两大失效模式。
- **方法设计系统性强**：
  - 依赖感知选择用"结构基率 vs. 集中度"的偏差量化潜在瓶颈，兼顾直接缺陷与跨能力影响。
  - 历史引导诊断引入"回归见证"概念（历史好、当前差）并做重复折扣，兼顾信息量与多样性。
  - 轨迹引导整合基于同一任务集上的成对差分案例，让互补机制的合并有据可依。
- **工程优化务实**：紧凑诊断上下文（−44% token）与修订感知执行复用，降低了自进化的高推理成本。
- **实验严谨性**：进化集与测试集内容不同、长度不同，检验真实泛化；能力标签严格隔离；3 次运行报告方差；跨模型/跨数据集迁移验证鲁棒性。
- **可复现性**：附录提供完整 prompt 模板、种子程序、最终进化程序代码、伪代码与超参数。
