## 摘要
现代语言模型智能体越来越多地在长时程、多步轨迹中与外部环境交互，其中累积的交互历史会迅速超出实际可用的上下文预算。为确保可靠性，智能体必须在长时程中保持事实信息、记住执行错误和纠正反馈，并跟踪跨动作的进展。已有若干方法被提出，用于在无需将完整执行历史保留在上下文中的情况下实现这一目标，例如使用推理与动作历史、通过学习通过覆写机制维护固定大小的记忆，以及周期性摘要。尽管覆写式记忆原则上可以保留仅追加式记忆所能保留的任何内容，但它必须学会在每一次后续重写中携带每个事实，而这很难从稀疏的结果奖励中学习；对于 Web 智能体等交互式应用，我们发现训练后的覆写式记忆会删除轨迹所需的关键信息，以及从环境收到的纠正反馈。我们提出 AMBER（Append-only Memory Bank for Evidence Retention，用于证据保留的仅追加记忆库）——一个简单且可扩展的框架，其中智能体联合学习推理、行动和写入自由形式记忆，而仅追加规则从构造上保证保留。这使得 AMBER 可以端到端地通过基于结果奖励的强化学习进行训练，而无需大量精心整理的 SFT 数据。在 WebArena Lite 上，AMBER 将平均成功率较基于覆写式记忆的方法提升了 4.09 个百分点，将在五次重复运行中解决的任务比例提升了 4.8 个百分点，并匹配了使用昂贵得多的精心整理监督训练的覆写式基线。AMBER 在保持实用 token 预算的同时实现了这些改进，在上下文效率、任务性能和可靠的长时程执行之间提供了良好的平衡。

## Abstract
Modern language-model agents increasingly interact with external environments over long-horizon, multi-step trajectories, where the accumulated interaction history can quickly exceed practical context budgets. To ensure reliability, agents must maintain factual information over long horizons, remember execution errors and corrective feedback, and track progress across actions. Several approaches have been proposed to achieve this without the need for maintaining the entire execution history in context, such as using the reasoning and action history, learning to maintain a fixed-size memory through an overwrite mechanism, and periodic summarization. Although overwrite memory can in principle retain anything an append-only memory can, it must learn to carry each fact through every subsequent rewrite, which is difficult to learn from sparse outcome rewards; for interactive applications like web agents, we find that trained overwrite memories delete key information required by the trajectory, as well as corrective feedback received from the environment. We introduce AMBER (Append-only Memory Bank for Evidence Retention) - a simple and scalable framework where an agent jointly learns to reason, act, and write free-form memory, while an append-only rule guarantees retention by construction. This allows AMBER to be trained end-to-end with reinforcement learning from outcome rewards without the need for extensive curated SFT data. On WebArena Lite, AMBER improves average success over overwrite-based memory by 4.09 percentage points, increases the fraction of tasks solved in five repeated runs by 4.8 percentage points, and matches an overwrite baseline trained on substantially more expensive curated supervision. AMBER achieves these improvements while maintaining a practical token budget, providing a strong balance between context efficiency, task performance, and reliable long-horizon execution.

## 1. 核心问题与整体含义

- **研究背景**：LLM 智能体越来越多用于长时程、多步交互任务（网页导航、深度研究、工具使用等）。这些任务中，关键信息往往通过逐步探索才能发现，完整交互历史会迅速超出上下文预算。
- **核心问题**：一旦智能体识别出值得记住的信息，应如何在后续交互中可靠保留？现有方法包括：
  - 保留完整历史：上下文爆炸，且长上下文检索不可靠。
  - 保留推理与动作历史：丢失观察事实，难以恢复错误。
  - 覆写式记忆：通过递归重写维护固定大小记忆，但每次重写都需“学会”把旧事实带到新记忆中。
  - 摘要/外部记忆：增加策略学习负担，且常依赖稀疏结果奖励。
- **关键发现**：覆写式记忆在结果奖励 RL 下容易丢失两类关键信息：
  - 轨迹所需的事实证据；
  - 环境返回的纠错反馈。
  这会导致任务失败和重复错误。
- **整体含义**：论文主张记忆的“保留决策”不应完全交给学习策略，而应通过结构先验保证持久性。AMBER 将“写什么”交给策略学习，将“保留什么”交给确定性的仅追加规则，从而提升长时程网页智能体的成功率、可靠性和监督效率。

## 2. 方法论

- **核心思想**：AMBER（Append-only Memory Bank for Evidence Retention）让智能体联合学习推理、行动和自由文本记忆写入；记忆一旦写入便只追加、不覆写、不删除，从构造上保证信息持久性。
- **问题建模**：将网页交互建模为 POMDP。完整历史为 \(H_t=(o_0,a_0,\dots,o_t)\)。由于完整历史昂贵，智能体使用压缩保留上下文 \(C_t\)，并通过更新规则 \(U\) 维护：\(C_{t+1}=U(x,C_t,o_t,r_t,a_t)\)。
- **保留上下文需满足三性质**：
  - **进度跟踪**：记录已完成/待完成子目标、失败尝试。
  - **信息识别**：识别哪些信息未来有用。
  - **持久性**：已识别的重要信息必须保留到未来需要时。
- **AMBER 的两轮生成流程**：
  - 第 \(t\) 步开始时，构造新对话，输入任务 \(x\)、当前观察 \(o_t\)、记忆库 \(C_t\)。
  - 第一轮生成推理 \(r_t\) 和动作 \(a_t\)：\((r_t,a_t)\sim \pi_\theta(\cdot|x,o_t,C_t)\)。
  - 第二轮继续同一对话，要求模型生成自由文本记忆条目 \(m_t\)：\(m_t\sim \pi_\theta(\cdot|x,o_t,C_t,r_t,a_t)\)。
  - 环境执行 \(a_t\)，得到下一观察 \(o_{t+1}\)。
  - 记忆追加：\(C_{t+1}=C_t\parallel[m_t]\)，即 \(C_t=[m_0,\dots,m_{t-1}]\)，初始为空。
  - 步内对话随后丢弃；下一步只使用 \(x,o_{t+1},C_{t+1}\)，不重放旧观察、旧推理或旧动作。
- **训练方式**：
  - 先使用离线轨迹做少量 SFT 初始化，再用 GRPO 进行端到端 RL。
  - 每个任务生成一组 \(G\) 条多步 rollout，每条 rollout 只有终端结果奖励 \(R_g\in\{0,1\}\)。
  - 组相对优势：\(A_g=(R_g-\text{mean}(R))/(\text{std}(R)+\delta)\)，每个交互步共享同一优势。
  - 同一交互步中，推理、动作和记忆 token 均被优化；模板和用户消息 token 被 mask。
  - 使用重要性采样比、clip 和 KL 惩罚到 SFT 参考策略。**没有记忆专用奖励**，记忆写入行为由任务结果奖励自然涌现。
- ** rollout 基础设施**：
  - 分离模型推理、浏览器执行和网站服务。
  - 每个 rollout 有独立浏览器 session 和网站容器，避免状态泄漏。
  - 使用 Ray 管理并发浏览器 session，FastAPI 环境服务器，SGLang 推理服务器。
