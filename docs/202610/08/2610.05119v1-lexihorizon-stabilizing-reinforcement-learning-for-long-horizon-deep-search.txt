# LEARNING FOR LONG -H ORIZON DEEP SEARCH 

Zhiqing Nong Liang Wen ∗ Chao-Hsuan Liu 

ABSTRACT 

Deep search agents tackle complex knowledge tasks through iterative retrieval, multi-hop reasoning, and evidence synthesis across multiple sources. Existing approaches typically assume relatively stable retrieval systems and operate over short-horizon tool interaction. However, when retrieval is sensitive to query for-mulation, even a semantically appropriate query may fail to surface critical ev-idence because of mismatched entity names, aliases, or keyword combinations. Recovering from such failures requires repeated query reformulation and longer interaction trajectories. This setting poses a distinct training challenge, as the pol-icy must sustain long-horizon query exploration while managing an expanding volume of retrieved content. We propose L EXI HORIZON , a framework for train-ing search agents over long horizons that expands the trajectory context budget, manages accumulated retrieval content using a window over recent tool obser-vations while preserving the reasoning history, and introduces an outcome-gated search-effort reward that provides a bounded bonus for tool invocations to trajec-tories with nonzero answer reward. Experiments on XBench, WebWalkerQA, and BrowseComp-ZH show that the resulting 9B model consistently outperforms both its base model and MiroThinker-1.7-mini, with maximum absolute gains of 8.7 and 23.8 percentage points, respectively. These results suggest that combining an extended context budget with reasoning-preserving context management benefits long-horizon deep search agents. 

1 INTRODUCTION 

Large language models (LLMs) have demonstrated strong capabilities on complex reasoning tasks (Guo et al., 2025; Yang et al., 2025). While these models possess substantial knowledge acquired during training, their reliance on parametric knowledge limits access to recent or task orianted in-formation and does not inherently provide provenance (Vu et al., 2024). Deep search agents address these limitations by integrating language model reasoning with web search, enabling models to re-trieve information, examine evidence from multiple sources, and synthesize relevant findings during inference (OpenAI, 2025). Retrieval can be unreliable when search engines are sensitive to query wording. Differences in entity names, aliases, terminology, or keyword combinations may prevent an otherwise appropriate query from retrieving relevant evidence. The agent must therefore inspect noisy results and repeatedly reformulate its queries based on previous retrieval outcomes (Sun et al., 2025), making deep search an iterative process that can produce long trajectories. As search becomes more iterative, successful trajectories can extend well beyond typical tool use horizons, creating a training challenge that cannot be addressed simply by allowing more tool calls. With a limited context budget, a trajectory may reach the context boundary before collecting suffi-cient evidence or producing a final answer, thereby preventing outcome-based reinforcement learn-ing from receiving a successful terminal signal. Increasing the context budget alleviates this capacity constraint, but a larger context does not guarantee that information will be used effectively through-out the trajectory. Models can struggle to retrieve relevant information from long contexts even when it remains within the supported context length (Modarressi et al., 2025), and reasoning quality can further deteriorate as the reasoning horizon grows (Lu et al., 2026). Each interaction adds new tool outputs, while earlier observations persist in the trajectory beyond their immediate utility. Retaining the full retrieval history can therefore consume substantial context and interfere with subsequent query formulation. The central challenge is to sustain extended search while retaining information that remains useful for future decisions. Motivated by these observations, we propose L EXI HORIZON , a long-horizon training framework for deep search agents operating under noisy, query-sensitive retrieval feedback. The framework ex-pands the trajectory context budget to support sustained query exploration. At its core, a reasoning-preserving context window retains the complete reasoning and observation history while keeping only the most recent tool observations in full. Earlier observations are replaced with markers, while information recorded in the preserved reasoning history remains available to the policy. This de-sign limits context redundancy without interrupting the trajectory. An outcome-gated search-effort reward further provides a bounded bonus for tool interactions only on trajectories with nonzero an-swer reward. The policy is then optimized with GSPO over the resulting trajectories, jointly learning evidence selection and query adaptation. The resulting model, LEXI HORIZON -9B, is evaluated on XBench, WebWalkerQA, and BrowseComp-ZH. Across all three benchmarks, it consistently outperforms both the initial Qwen3.5-9B model and MiroThinker-1.7-mini, with maximum absolute improvements of 8.7 and 23.8 percentage points, respectively. Controlled ablations show that expanding the context budget from 64K to 128K produces more stable training dynamics and increases the valid answer rate from 66.97% to 99.88%. Under the 128K budget, introducing the context window changes an otherwise flat reward curve into sustained improvement. The main contributions are: • Long-horizon search reinforcement learning is formulated as a training stability problem arising from premature context exhaustion, interference from accumulated retrieval con-tent, and weak incentives for sustained exploration. • L EXI HORIZON addresses these coupled sources of instability with an extended context budget, an context window that preserves reasoning while managing raw tool outputs, and an outcome-gated reward that encourages sustained exploration. • The resulting 9B policy improves over its base model and MiroThinker-1.7-mini across XBench, WebWalkerQA, and BrowseComp-ZH. Controlled ablations further reveal the complementary roles of context capacity and context management in training dynamics and search behavior. 

2 RELATED WORK 

Deep Search Systems. Proprietary systems, including OpenAI Deep Research, Claude Research, Kimi-Researcher, Grok DeepSearch, and Gemini Deep Research, have showcased strong capabili-ties in autonomous multi-step research (OpenAI, 2025; Anthropic, 2025b;a; Moonshot AI, 2025; xAI, 2025; Google, 2025). These systems iteratively retrieve information from heterogeneous sources, synthesize evidence, and produce comprehensive research reports. However, their underly-ing models, training procedures, and mechanisms for handling extended search trajectories remain largely inaccessible. Open research agents have explored how to structure and train deep search behavior. Existing ap-proaches address different aspects of the search process, including explicit question decomposition and parallel search, search augmented reasoning, and iterative search-and-draft workflows (Chen et al., 2025; Li et al., 2025b; 2026). Beyond search execution, recent work has shifted attention toward constructing training resources for research agents, including open training data, trajectory construction pipelines, and supervised trajectories that cover broader research workflows (Du et al., 2026; Dong et al., 2026). Despite these advances, existing systems primarily focus on enabling re-search capabilities and constructing training trajectories; the challenges of scaling search agents to longer interaction horizons remain underexplored. 

Reinforcement Learning for Deep Search Agents. Recent studies have demonstrated that rein-forcement learning can induce autonomous search behaviors from task-level outcomes. Search-R1 2and R1-Searcher show that models can learn when to search, how to formulate queries, and how to incorporate retrieval feedback through outcome-based reinforcement learning, while ARTIST extends this paradigm to multi-tool reasoning (Jin et al., 2025; Song et al., 2025; Singh et al., 2025). To improve credit assignment beyond terminal outcomes, subsequent works introduce denser supervision through path-centric and hierarchical process rewards (Xia et al., 2026; Wu et al., 2026b). Beyond reward design, recent work has extended agentic reinforcement learning to realistic information-seeking environments. DeepResearcher, WebDancer, WebSailor, and Tongyi Deep-Research combine reinforcement learning with authentic web interaction and end-to-end training pipelines, enabling agents to learn multi-step information seeking under dynamic retrieval feedback (Zheng et al., 2025b; Wu et al., 2026a; Li et al., 2025a; Team et al., 2025b). Other approaches further scale search interaction through deeper sequential exploration or parallel evidence acquisition (Team et al., 2025a; 2026; Chen et al., 2026). Extending search trajectories, however, introduces additional challenges for reinforcement learning (Laban et al., 2026). As trajectories become longer, rein-forcement learning becomes increasingly unstable, manifested in rising reward variance, gradient spikes, and degraded multi-turn learning dynamics (Wang et al., 2025). At the same time, growing interaction histories place increasing pressure on context management, motivating trajectory sum-marization and compression for long-horizon agents (Wu et al., 2025b). In search environments, these difficulties are further compounded by noisy and query-sensitive retrieval feedback, which has motivated the use of controllable simulated search during training (Sun et al., 2025). However, how reinforcement learning scales to substantially longer search trajectories while maintaining sustained and stable optimization under real retrieval feedback remains insufficiently understood. 

3 METHOD 

3.1 OVERVIEW AND PROBLEM FORMULATION 

We adopt ReAct (Yao et al., 2022) as the interaction framework for our deepearch agent. The policy model interleaves reasoning with tool invocation throughout the search process. Given an input question x, the policy πθ interacts with a tool-augmented web environment E until it produces a final answer. The environment provides tools for web search, webpage extraction, PDF parsing, and Python execution. At interaction step t, the policy generates a thought τt and an action at conditioned on the current interaction context ht:

(τt, a t) ∼ πθ (· | ht). (1) The action either invokes an external tool or terminates the interaction by producing a final answer. If at is a tool invocation, the environment returns an observation ot, and the interaction context is updated as 

ot = E(at), ht+1 = ht ⊕ τt ⊕ at ⊕ ot, (2) where ⊕ denotes sequence concatenation. A complete search trajectory is represented as 

ξ = ( x, τ 1, a 1, o 1, . . . , τ T −1, a T −1, o T −1, τ T , a T ) , (3) where T denotes the number of interaction steps and aT is the final answer. We consider a lexically sensitive retrieval environment, in which semantically similar queries may return substantially different search results. Consequently, identifying the correct semantic direction does not necessarily lead to immediate retrieval of the target evidence. The agent may need to ex-plore entity aliases, alternative descriptions, attribute combinations, temporal constraints, and query decompositions over an extended interaction horizon. Query reformulation is not implemented as a separate module, but is learned jointly with search planning through end-to-end policy optimization. The learning objective is to maximize the expected trajectory reward under finite interaction and context budgets:

Training an agent to conduct long-horizon search introduces several coupled sources of instability. A limited context budget may terminate trajectories before sufficient evidence is collected or a final answer is produced, preventing the policy from receiving terminal feedback. Meanwhile, accumu-lated tool observations can fill the context with outdated, redundant, or noisy content and interfere with the current search state. Answer reward alone also provides only limited incentive for sustained exploration among successful trajectories. LEXI HORIZON addresses these issues through a context architecture and a complementary reward mechanism. An extended context budget reduces premature truncation, while a context window preserves the complete reasoning and action trace but retains only recent tool outputs in full. Mean-while, outcome-gated reward provides a bounded tool call bonus only to trajectories with nonzero answer reward. Trajectory reset is additionally introduced as an auxiliary mechanism for pathologi-cal tail trajectories, with further details provided in Appendix A.3. 3.2.1 REASONING -P RESERVING CONTEXT WINDOW 

Long-horizon search trajectories may contain a large number of tool interactions. Although each search result may provide useful evidence when first retrieved, different query variants often return overlapping, weakly relevant, or noisy results. Retaining all such observations causes redundant retrieval content to accumulate in the active context. As the trajectory grows, outdated search results may compete with more recent evidence for the model’s attention and interfere with subsequent query formulation and reasoning. To control this accumulation, the window preserves the complete history of reasoning and tool actions while retaining the full observations from only the K most recent tool interactions. For earlier interactions, the reasoning segment τt and tool action at remain in their original positions, while the raw observation ot is removed from the active context. Information already incorporated into the reasoning history therefore remains available, while redundant historical search results no longer occupy the context. The reward follows a correctness first design. Rewarding tool use unconditionally could encourage redundant search or reward hacking, as a trajectory might receive additional reward simply by mak-ing more calls. We therefore condition the search-effort bonus on answer quality, so that additional 4tool use is rewarded only after a trajectory obtains a nonzero answer reward. The final reward com-bines the accuracy reward, the gated and bounded search-effort bonus, and penalties for malformed or repetitive trajectories: 

R(ξ) = clip [Rmin ,R max ] (Racc + Reffort − Pfmt − Prep ) . (7) 

Answer Correctness. An LLM judge evaluates the semantic correctness of the final answer using a fixed ordinal rubric. It assigns 

y ∈ { 0, 0.25 , 0.5, 0.75 , 1}, (8) corresponding to incorrect, minimally correct, partially correct, mostly correct, and fully correct, re-spectively. We use discrete levels to provide consistent partial credit without relying on fine grained numerical calibration by the judge. We set Racc = 0 .9y, leaving a limited margin for the outcome-gated tool bonus. The complete evaluation rubric and judge prompt are provided in Appendix A.2. 

Bounded Search-Effort Bonus. Keyword-sensitive retrieval may require the agent to explore multiple query formulations before retrieving the target evidence. We therefore provide a bounded bonus based on the number of executed tool calls: 

Reffort = min (0 .005 Ntool , 0.15) Racc , (9) where Ntool denotes the number of tool calls in the retained trajectory. The bonus saturates after 

30 tool calls. Importantly, Reffort is multiplicatively gated by Racc ; therefore, the bonus is nonzero only for trajectories receiving nonzero answer reward. This gating ties the bonus to answer quality rather than rewarding tool use independently, preventing trajectories with zero accuracy reward from receiving a positive tool bonus. 

Format and Repetition Penalties. The format penalty is defined as 

Pfmt = 0 .1Ino -boxed + 0 .1Iinvalid -tool + 0 .2Iunclosed -think ,

where Ino -boxed indicates the absence of the required boxed final-answer format, Iinvalid -tool indi-cates an invalid tool invocation, and Iunclosed -think indicates an unclosed reasoning block. The repetition penalty is 

Prep = min(0 .05 Crep , 0.5) , (10) where Crep is the number of detected content repetitions. 3.2.3 TRAINING OBJECTIVE

4 EXPERIMENTS 

4.1 EXPERIMENTAL SETUP 

Base Model and Benchmarks. We use Qwen3.5-9B as the base policy and train the result-ing agent, denoted L EXI HORIZON -9B, with the long-horizon search framework described in Sec-tion 3.2. The agent has access to four tools: SEARCH returns ranked results with titles, snippets, and URLs; HTML READER and PDF READER extract text from webpages and PDF documents, respectively; and PYTHON supports numerical computation, structured data processing, and in-termediate verification. All training and evaluation runs use the same tool implementations and search backend. We compare L EXI HORIZON -9B with its base model, a larger scale model, and a specialized search agent on three benchmarks: xbench-DeepSearch (Xbench Team, 2025), Web-WalkerQA (Wu et al., 2025a), and BrowseComp-ZH (Zhou et al., 2025). Answer correctness is judged by DeepSeek-V4 Flash (Xu et al., 2026). 

Baselines. Our baselines cover model initialization, parameter scaling, and specialized deep search training. Qwen3.5-9B is the initialization of our policy and serves as the base model baseline for measuring the gains from agentic reinforcement learning. Qwen3.5-27B provides a larger scale comparison for assessing whether long-horizon training helps a 9B model narrow the performance gap associated with model scale. We also compare with MiroThinker-1.7-mini (Team et al., 2025a), an open-source research agent trained for long-horizon reasoning and tool interaction. Unless other-wise specified, all models are evaluated with the same search engine, tool environment, interaction budget, decoding configuration, and answer evaluator. 4.2 MAIN RESULTS

We conduct controlled ablations to examine the effects of the extended search horizon and the reasoning-preserving context window. The full configuration, L EXI HORIZON -9B, uses a 128K con-text budget together with the context window. The w/o Extended Horizon variant reduces the context budget from 128K to 64K while retaining the window. The w/o Context Window variant retains the 128K context budget and keeps all tool observations in full. All other settings are fixed within each comparison. Reducing the context budget from 128K to 64K causes the larger degradation in Table 3, including a drop in valid-answer rate from 99.88% to 66.97%. Removing the context window also reduces accuracy consistently across all three benchmarks. 4.3.1 EFFECT OF THE SEARCH HORIZON 

The sharp drop in valid answer rate under 64K indicates that the available context budget is insuffi-cient for a substantial fraction of long-horizon search trajectories. 

Training Dynamics. Figure 1 compares search behavior under 64K and 128K context budgets. Under 64K, persistent length clipping is followed by sharp declines in response length and tool usage, together with a substantially lower valid answer rate and worse benchmark performance. This pattern is consistent with premature termination under context pressure rather than improved efficiency. In contrast, the 128K configuration sustains longer responses while tool usage gradually increases and stabilizes, indicating more persistent multi-step search without uncontrolled growth in tool calls. The behavioral divergence is accompanied by different optimization dynamics. Figure 2 shows that the reward and actor entropy of the 64K policy both decline to near zero, coinciding with its shift toward short and incomplete trajectories. Under 128K, reward remains informative and generally improves, while actor entropy avoids the same abrupt and sustained decline. The degradation without the context window suggests that an extended context budget alone is in-sufficient. As search trajectories grow, verbose historical observations accumulate and may interfere with the agent’s current search state. The window controls this accumulation by retaining only recent observations in full while preserving the complete reasoning and action history. 

Test-Time Mechanism and Search Behavior. To quantify the actual context reduction, we re-construct the corresponding uncompressed context before each generation step and compare it with the retained context produced by the context window. Aggregating token counts across evaluation trajectories, we find that the window is activated in more than 80% of cases and reduces the overall active context by 79.1%. For trajectories in which the window is activated, we identify candidate removed observations using normalized answer keywords and aliases. An LLM judge then verifies whether each candidate contains valid evidence and whether that evidence was incorporated into the preserved reasoning history before removal. As shown in Table 4, the reasoning history retains the relevant evidence in 44 of the 55 trajectories whose removed observations contain valid answer evidence, corresponding to an 80% retention rate. All 11 retention failures occur in trajectories with more than 40 tool calls, indicating that retention is lower in the longest trajectories. Beyond evidence preservation, Table 5 compares the test-time search behavior of policies trained with and without the context window. The policy trained with windowed context performs substan-tially more tool interactions while maintaining much shorter active contexts. In particular, its higher tool usage is accompanied by a 76.6% reduction in the 95th percentile of active context length. This result suggests that the window supports deeper tool interaction while controlling extreme context growth. 

Training Dynamics. After characterizing the window’s context reduction and evidence retention, we examine its relationship with policy learning. Figure 3a shows a clear difference in reward dynamics. Without the context window, rollout reward remains largely flat and exhibits no sustained improvement. In contrast, enabling the window produces a steady increase in reward throughout training. This comparison suggests that reducing accumulated tool content helps the policy make more effective use of the available learning signal. As shown in Figure 3b, the number of tool calls increases during window-enabled training and gradually converges to a stable level. 5 CONCLUSION 

Long-horizon deep search under query-sensitive retrieval poses the joint challenge of sustaining exploration while managing a growing interaction history. To address this challenge, L EXI HORIZON 

combines an extended context budget, a reasoning-preserving context window, and an outcome-gated search-effort reward. Across XBench, WebWalkerQA, and BrowseComp-ZH, the resulting 9B policy consistently outperforms both its base model and MiroThinker-1.7-mini. Controlled ablations further indicate that context capacity and context management provide complementary benefits for long search trajectories. A.3.1 RESET MECHANISM 

The context window limits the accumulation of raw tool observations but preserves the complete reasoning trace. Consequently, an agent that repeatedly reformulates ineffective queries may still produce an excessively long trajectory. Such cases are particularly common in lexically sensitive re-trieval environments, where the agent cannot directly determine whether a retrieval failure is caused by an incorrect search hypothesis or an inadequate query formulation.
