Abstract. Memory-augmented agents typically integrate procedural knowledge by injecting re-trieved skills directly into text prompts. This approach dangerously equates readable text with reliable execution. To bridge this gap, we introduce From Memory to Guide , a novel paradigm that transitions procedural memory from passive text delivery to active, inference-time policy adaptation. We instantiate this paradigm through the Spatio-Temporal Composer, an active policy compiler that explicitly manages exactly how and when retrieved knowledge should be applied. Rather than treating skills as plug-and-play modules, Composer dynamically aligns historical knowledge with current environmental constraints ( spatial adaptation ) and precisely dictates its applicable lifecycle ( temporal orchestration ). It actively transforms static memories into strictly bounded Runtime Guides —equipping the agent with localized objectives and behavioral guardrails without requiring a single parameter update. Extensive evaluations on 13 demanding, long-horizon software engineering tasks in EngramBench demonstrate the clear advantages of this architecture. Composer not only robustly prevents context mismatch but drives an absolute pass-rate increase of 7.2 percentage points on the most complex tasks, while simultaneously slashing the main agent’s token usage by 32.2%. 

Keywords agent memory, skill evolution, recursive self-improvement 

# 1 Introduction 

LLMs are rapidly evolving from passive chatbots into autonomous agents executing complex real-world workflows. A fundamental bottleneck in this shift is the gap between general knowledge and practical execution. While LLMs possess vast amounts of pre-trained knowledge, their static weights struggle to capture the dynamic, hands-on experience required for lengthy tasks like software engineering. To bridge this gap, procedural memory has emerged as a critical infrastructure. By enabling agents to accumulate step-by-step procedures, decision rules, and debugging experience as reusable Skills , procedural memory empowers agents to continuously learn and reuse know-how without the prohibitive costs of retraining. Consequently, equipping agents with reusable skills has become a standard practice, driving recent successes in autonomous execution (e.g., ReMe (Cao

et al. 2026), Mem 𝑝 (Fang et al. 2026), and SkillRL (Xia et al. 2026)). However, simply accumulating experience exposes a critical vulnerability: the illusion of direct applicability. In long-horizon environments, directly injecting retrieved skills without contextual adaptation is not merely suboptimal—it is frequently catastrophic. When a retrieved skill encodes assumptions from a mismatched source context, blindly executing this static guidance introduces severe regressions. Consider a spatial mismatch: if a static Skill explicitly dictates using npm 

commands, but the target project strictly enforces yarn , a direct application will instantly corrupt the lockfile and crash the entire build system. Similarly, consider a temporal mismatch: because software engineering tasks are highly sequential, executing the right Skill at the wrong time triggers severe cascading consequences. For example, if an architectural Skill is triggered during a simple bug fix, the agent might rewrite working code instead of just patching the error. Consider a Skill that correctly guides architectural refactoring during initial scaffolding. If this exact same Skill is retrieved during late-stage debugging, it becomes actively destructive—prompting the agent to dismantle working code rather than fixing a simple localized bug. These spatial and temporal mismatches completely derail the agent’s reasoning trajectory, triggering cascading errors and trapping it in irreversible debugging loops. Why do current memory-augmented agents struggle to generalize? State-of-the-art frame-works—like AtomMem (Huo et al. 2026), MemAgent (Yu et al. 2025), and Mem-𝛼 (Y. Wang et al. 2025)—still treat procedural memory as a static text repository. Their reliance on basic semantic retrieval exposes a critical conceptual flaw: treating retrieved memories as plug-and-play modules rather than raw materials that require adaptation. In reality, procedural memory originates from specific source contexts (e.g., tool configurations and task domains) that often clash with the target environment. By merely injecting static text into the prompt, these methods delegate the complex burden of adaptation to the agent’s implicit reasoning. This exposes a critical gap between human intuition and model execution. When a human developer reads a retrieved skill, they naturally mentally adapt its logic to fit a new scenario. We mistakenly assume the LLM will do the same. However, expecting a text prompt to act as an adaptable policy is structurally flawed. In traditional machine learning, policy adaptation (Jiang et al. 2026) works because parameters are continuous and can be mathematically optimized to fit new environments. In contrast, prompt injection forces the agent to rely on a rigid, discrete text space. Because we cannot continuously optimize static text to align with a dynamic execution state, we have no real guarantee that the skill will generalize safely. Ultimately, what is semantically readable to humans does not equal executable generalization for the model. To bridge this generalization gap, we must fundamentally shift our conceptualization of proce-dural memory. Rather than treating the Skill Bank as a static text database, we argue it should be viewed as a repository of encoded behavioral policies, each shaped by its original environment. Once a retrieved skill is understood as an external policy, the challenge of experience reuse natu-rally transforms into a rigorous problem of policy adaptation . In long-horizon tasks like software engineering—which span hours of planning, implementation, testing, and repair—the execution context is inherently dynamic. Code states, local goals, and validation feedback continuously evolve. A policy that provides crucial guidance during the initial scaffolding phase might become actively destructive if applied during late-stage debugging. Therefore, effective experience reuse requires dynamically adapting these encoded policies to fit both specific project configurations and the shifting execution lifecycle. Ultimately, long-horizon engineering execution calls for a paradigm shift: from static, rigidly injected skills to dynamically managed, lifecycle-aware guides. 

Motivated by this insight, we introduce From Memory to Guide —a paradigm shift that funda-mentally decouples long-term knowledge storage from stage-specific action guidance. To power this transition, we propose the Spatio-Temporal Composer for Procedural Coding Memory

(Composer) . Instead of acting as a passive retrieval pipeline, Composer serves as an active policy compiler, transforming rigid, static skills into dynamic, context-aware execution strategies. This dynamic transformation operates across two complementary dimensions: • Spatial Adaptation (The Environmental Adapter): Composer aggressively tailors generic skills to the specific configuration of the target workspace, guaranteeing that historical knowledge never clashes with local constraints. • Temporal Adaptation (The Lifecycle Orchestrator): Composer synchronizes guidance with the evolving execution phase, precisely dictating not only when a skill is triggered, but crucially,

Synthesizing these dimensions, Composer compiles the raw experience into a Runtime Guide —a highly constrained action space equipped with local goals and strict behavioral boundaries. The theoretical implication is profound: Composer morphs static memory into dynamically shifting action trajectories. Finally, ablation studies empirically validate our dual-axis design: dynamically incorporating spatial execution evidence and explicit temporal lifecycle boundaries independently yield pass-rate gains of 7.03 and 10.09 percentage points, confirming that our policy adaptation mechanism is both highly effective and architecturally necessary. To overcome the rigidity of standard prompt injection, Composer evaluates both environmental constraints (spatial adaptation) and current execution stages (temporal orchestration). It dynamically compiles retrieved experiences into localized Runtime Guides , achieving precise, context-aware policy adaptation without a single parameter update. 3. We demonstrate significant gains in both generalization and execution efficiency on demanding long-horizon benchmarks. Extensive evaluations on 13 complex software engi-neering tasks in EngramBench reveal that Composer drives an absolute pass-rate increase of 7.2 percentage points on the most challenging subsets. Simultaneously, it slashes the main agent’s cumulative token consumption by 32.2%. Comprehensive ablations further validate the critical necessity and independent performance gains of our dual-axis spatial and temporal design.

Both approaches use generated guidance to adapt execution without updating the executor. Composer organizes this interface around an explicit separation between persistent procedural knowledge and stage-specific guidance: selected Skills are composed around the current local objective, execution evidence, and previous guidance, while termination and requirement re-entry define the guidance’s temporal scope. 

Utility-optimized experience generation. SEAM generates structured experience for a frozen executor, comprising problem analysis, experience highlights, and a reference plan (Li et al. 2026). It encodes executor-specific experience in a lightweight generator and optimizes guidance through executor rollouts and GRPO, with optional deployment-time supervised fine-tuning on logged successful experience. SEAM and Composer differ in how they organize experience: SEAM inter-nalizes its experience library in generator parameters, whereas Composer retains an explicit Skill Bank as a stable external policy resource. Composer instantiates selected knowledge as a Runtime Guide whose actions, behavioral boundaries, and termination conditions are tied to a local stage of software development. 

Procedural memory and runtime policy adaptation. ExpeL extracts reusable insights from agent experience (Zhao et al. 2023), while Agent Workflow Memory induces workflows and selectively provides them during subsequent interaction in both offline and online settings (Z. Z. Wang et al. 2024). These approaches establish experience abstraction and reuse as important components of agent adaptation. From Memory to Guide connects procedural memory with guidance-based adaptation of frozen executors by making the transformation from selected policy knowledge to state-conditioned action guidance explicit. Its central contribution is the joint organization of guidance content and temporal scope: which experience should inform the current objective, how it should be translated into actions, and when its local guiding role should end. 

Runtime skill interfaces and stage-aware execution. SWE-agent demonstrates the importance of agent-computer interfaces for software engineering (Yang et al. 2024). SkVM uses model– harness capability profiles to compile Skills and adapts their execution at runtime (Chen et al. 2026), while SkillSmith compiles Skill packages into boundary-guided executable interfaces (Xu et al. 2026). Hierarchical Memory Tree organizes reusable web-task knowledge into goals, stages with pre- and post-conditions, and action patterns (Y. Tan et al. 2026). Composer focuses on state-conditioned natural-language policy instantiation from a persistent Skill Bank, with explicit local goals, behavioral boundaries, and guidance lifecycles. 

Learning experience utility and evolving contexts. Memento formalizes memory-augmented decision making with a case-selection policy (Zhou et al. 2025), while MemRL uses environmental feedback to identify high-utility memories (S. Zhang et al. 2026). Agentic Context Engineering evolves contextual playbooks through generation, reflection, and curation (Q. Zhang et al. 2025). These approaches develop the selection and organization of experience; Composer makes the subsequent transformation of selected knowledge into local, time-bounded action guidance explicit.

3.2 Spatio-Temporal Composer Architecture 

To realize the runtime adapter C𝜙 defined above, we propose the Spatio-Temporal Composer for Procedural Coding Memory (Composer). Composer acts as an explicit interface that transforms static skills into dynamic action guidance, separating the selection of reusable knowledge from its instantiation as state-conditioned actions. At request step 𝜏 , Composer synthesizes three complementary sources of information: 1. Task profile ( 𝑝 𝑇 ): Project objectives, business rules, interface constraints, and tool conditions. 2. Execution evidence ( 𝑜 𝜏 ): The agent’s description of current work, session context, reported validation results, and blockers. 3. Previous Guide ( 𝑔 prev ): The earlier local goal and recommendations, allowing Composer to assess how previous guidance relates to completed work and current gaps.

3.3 Context-Conditioned Skill Selection 

The Selector turns a guidance request into a concrete composition directive. It evaluates the available Skills in K against 𝑝 𝑇 , 𝑜 𝜏 , and 𝑔 prev , returning three structured fields: 

Guidance decision ( decision ): Specifies whether to generate a new Guide. The Selector considers current goals against outcomes reported for earlier guidance. If new guidance is warranted, the request proceeds; otherwise, existing guidance remains governed by its own termination conditions. 

Skill references ( skillRefs ): Identifies the specific Skills in K to use for the current request. Multiple Skills can be selected when their rules contribute complementary components of the required guidance. 

Rationale-preserving handoff ( whyNow ): Records the exact reason for the guidance decision, identifying the current execution gap and the intended contribution of the newly selected Skills relative to the previous Guide. This structure strictly separates which experience to use ( skillRefs ) from why it is needed now (whyNow ), bridging selection and composition without information loss.

Each task requires sustained implementation, testing, and repair against its project requirements. The execution agent is Codex with GPT-5.5 at

Final project artifacts are assessed by task-specific evaluators. Runtime guidance uses development-time requirements and execution evidence; final hidden-test outcomes are reserved for evaluation.

4.3 Evaluation Metrics 

Task quality. We report each task’s mean confirmed-pass rate across three runs. The rate is the number of confirmed passed outcomes divided by all scheduled test executions, including 

excluded and diagnostic instances. Excluded executions remain in the denominator without being classified as observed implementation failures. Aggregate rates pool counts across the stated tasks and runs under the same rule for all conditions; we distinguish relative count improvements from percentage-point changes in rate. 

Execution-side token efficiency. We measure the main Coding Agent’s cumulative input and output tokens across development. This execution-side metric quantifies the token usage associated with the submitted implementations and is distinct from auxiliary-model orchestration costs. 

Development time. We report per-run development duration and cumulative time across runs, including tool execution and Guide waiting. Final hidden-test evaluation is excluded. Cumulative time is computed by summing individual run durations and characterizes the execution horizon independently of experiment parallelism.

# 6 Toward Self-Evolving Procedural Policies 

Runtime Guides make it easier for the system to learn from its own actions because each Guide clearly defines a goal, boundaries, and when to stop. In future work, we can use these well-defined steps to test different ways of applying the same skill and compare the results side-by-side. To make this work, we can borrow ideas from recent research on memory credit assignment (Liao et al. 2026) and text-based feedback (Pryzant et al. 2023; Yuksekgonul et al. 2024). In simple terms, we can take successful task outcomes and text feedback and turn them into training data. We can then use this data to fine-tune the Composer. This means the Composer itself can be continuously improved and optimized, even while the Skill Bank and the main agent remain completely fixed. This setup paves the way for true recursive self-improvement (RSI). The system can form a complete learning loop: it generates a guide, tests it in the environment, and uses the feedback to update the Composer. This allows the system to issue better guides over time, automatically adjusting how strict or detailed it needs to be as the main agent’s abilities improve. Ultimately, our goal is to build a self-evolving memory system—one that not only stores useful skills but constantly learns the best way to apply them.

# 7 Conclusion 

In this work, we introduced From Memory to Guide , a new paradigm that fundamentally separates persistent procedural knowledge from context-specific action guidance. We realized this through the Spatio-Temporal Composer, which treats the Skill Bank not as a static text repository, but as an adaptable policy resource. By actively aligning past experiences with current environmental constraints (spatial adaptation) and strictly defining when that guidance applies (temporal adapta-tion), Composer dynamically compiles raw skills into bounded Runtime Guides . Together, these mechanisms achieve true inference-time policy adaptation without requiring any updates to the execution model’s parameters. Extensive evaluations on demanding, long-horizon software engineering tasks in EngramBench demonstrate the clear advantages of this architecture. Composer consistently outperformed the native Codex + Skills baseline across all evaluated tasks. Most notably, on the most complex subset of tasks, it increased the aggregate confirmed-pass rate by 7.2 percentage points while simultaneously slashing the main agent’s token usage by 32.2%. Comprehensive ablations further confirmed that both spatial grounding and temporal lifecycles are indispensable for reliable execution. Ultimately, From Memory to Guide advances procedural memory from passive experience delivery to active runtime policy adaptation: Memory preserves reusable policy knowledge, while Guide gives that knowledge its actionable form and stage-specific scope.
