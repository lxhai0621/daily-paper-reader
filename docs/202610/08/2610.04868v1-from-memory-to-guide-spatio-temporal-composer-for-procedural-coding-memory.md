## 摘要
记忆增强智能体通常通过将检索到的技能直接注入文本提示来整合程序性知识。这种做法危险地将可读文本等同于可靠执行。为弥合这一鸿沟，我们提出“从记忆到指南”（From Memory to Guide），一种新范式，将程序性记忆从被动文本传递转变为主动的、推理时的策略自适应。我们通过 Spatio-Temporal Composer 实例化该范式，这是一种主动策略编译器，显式管理检索到的知识应如何以及何时被应用。Composer 不将技能视为即插即用模块，而是动态地将历史知识与当前环境约束对齐（空间自适应），并精确规定其适用的生命周期（时间编排）。它主动将静态记忆转化为严格受限的运行时指南（Runtime Guides）——无需任何参数更新，即可为智能体配备局部化目标和行为护栏。在 EngramBench 的 13 个高难度、长时程软件工程任务上的广泛评估表明，该架构具有明显优势。Composer 不仅能稳健地防止上下文不匹配，还在最复杂任务上推动绝对通过率提升 7.2 个百分点，同时将主智能体的 token 使用量削减 32.2%。

## Abstract
Memory-augmented agents typically integrate procedural knowledge by injecting retrieved skills directly into text prompts. This approach dangerously equates readable text with reliable execution. To bridge this gap, we introduce From Memory to Guide, a novel paradigm that transitions procedural memory from passive text delivery to active, inference-time policy adaptation. We instantiate this paradigm through the Spatio-Temporal Composer, an active policy compiler that explicitly manages exactly how and when retrieved knowledge should be applied. Rather than treating skills as plug-and-play modules, Composer dynamically aligns historical knowledge with current environmental constraints (spatial adaptation) and precisely dictates its applicable lifecycle (temporal orchestration). It actively transforms static memories into strictly bounded Runtime Guides---equipping the agent with localized objectives and behavioral guardrails without requiring a single parameter update. Extensive evaluations on 13 demanding, long-horizon software engineering tasks in EngramBench demonstrate the clear advantages of this architecture. Composer not only robustly prevents context mismatch but drives an absolute pass-rate increase of 7.2 percentage points on the most complex tasks, while simultaneously slashing the main agent's token usage by 32.2%.

- **两类失配风险**：
  - **空间失配**：技能要求使用 `npm`，但目标项目强制使用 `yarn`，直接执行会破坏锁文件、导致构建崩溃。
  - **时间失配**：架构重构类技能在初期脚手架阶段有效，但若在后期调试阶段被检索触发，会促使智能体重写正常代码而非修补局部 bug，导致级联错误与不可逆的调试循环。
- **根本原因**：现有方法把检索到的记忆当作即插即用模块，而非需要适配的原材料；将复杂的适配负担推给智能体的隐式推理。文本空间的离散性使得无法像传统策略适配那样对参数进行连续优化，因此无法保证技能安全泛化。
- **整体含义**：论文主张将程序性记忆从"静态文本仓库"重新概念化为"编码的行为策略库"，并提出 **"从记忆到指南"（From Memory to Guide）** 新范式——将长期知识存储与阶段特定行动指导解耦，实现无需参数更新的推理时策略自适应。

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想

- 提出 **Spatio-Temporal Composer（时空组合器）**，作为主动策略编译器，将静态技能转化为动态、上下文感知的执行策略。
- 两个互补维度：
  - **空间适配（环境适配器）**：将通用技能裁剪到目标工作区的具体配置，保证历史知识与本地约束不冲突。
  - **时间适配（生命周期编排器）**：同步指导与演进中的执行阶段，明确技能**何时触发**以及**何时必须失效**。
- 最终产物是 **Runtime Guide（运行时指南）**：带有局部目标与严格行为边界的受限行动空间。

### 2.2 问题形式化

- 任务 $T$ 具有 profile $p_T$（目标、规则、工具条件）；步骤 $t$ 的动作 $a_t$ 基于动态交互上下文 $h_t$ 生成。
- 原生技能使用下：$a_t \sim \pi_\theta(\cdot \mid p_T, h_t, \mathcal{D}(\mathcal{K}, p_T, h_t))$，其中 $\mathcal{D}$ 为检索机制。
- 新范式中引入运行时适配器 $C_\phi$，在请求步骤 $\tau$ 生成 Guide：
  - $g_\tau = C_\phi(p_T, \mathcal{K}, o_\tau, g_{\text{prev}})$，$g_\tau \in \mathcal{G} \cup \{\emptyset\}$
- 每个 Guide 是结构化策略接口：
  - $g_\tau = (\ell_\tau, r_\tau, b_\tau, e_\tau)$
  - $\ell_\tau$：局部目标；$r_\tau$：状态条件推荐动作；$b_\tau$：行为边界与适用前提；$e_\tau$：终止条件。
- 执行策略变为：$a_t \sim \pi_\theta(\cdot \mid p_T, h_t, g_t^{\text{act}})$，实现适配（$C_\phi$）与执行（$\pi_\theta$）的解耦。

### 2.3 架构与算法流程

- **Catalog**：向 Coding Agent 暴露技能库 $\mathcal{K}$ 中可复用的能力。
- **Coding Agent**：基于局部目标、进展与阻塞同步发起指导请求。
- **Selector（上下文条件技能选择）**：综合三类信息——任务 profile $p_T$、执行证据 $o_\tau$、前一 Guide $g_{\text{prev}}$，输出三个结构化字段：
  - `decision`：是否生成新 Guide；
  - `skillRefs`：从 $\mathcal{K}$ 中选择的具体技能（可多选）；
  - `whyNow`：记录指导决策的确切理由，分离"用哪些经验"与"为何现在需要"。
- **Spatial Composition（空间组合）**：由 `whyNow` 驱动，将抽象经验映射到具体项目实体，把通用规则实例化为围绕局部目标的"情境化行动"，同时执行 $p_T$ 规定的行为边界。
- **Temporal Adaptation（时间适配）**：通过 $e_\tau$ 与 $b_\tau$ 中的适用前提限定 Guide 生命周期。执行智能体依据 `Applies When`、`Verification`、`Termination` 子句独立判断指导是否继续。目标完成、阶段变化或不可逾越的阻塞会触发重新评估（requirement re-entry）。
- **Algorithm 1 流程**：
  1. 初始化 $t \leftarrow 0$，$g_0^{\text{act}} \leftarrow \emptyset$，$g_{\text{prev}} \leftarrow \emptyset$，向 Agent 提供 Catalog；
  2. 循环：Agent 识别当前局部目标；若请求指导，记录 $\tau \leftarrow t$，提取证据 $o_\tau$，Selector 输出 $(d_\tau, R_\tau, w_\tau)$；
  3. 若 $d_\tau = \text{Generate}$，Composer 生成 $g_\tau$ 并设为活跃 Guide；否则保持原有指导；
  4. Agent 执行动作，更新上下文；
  5. 若活跃 Guide 终止，则将其记为 $g_{\text{prev}}$，清空活跃 Guide，执行 requirement re-entry；
  6. $t \leftarrow t+1$，继续循环。

### 2.4 实例说明（DockChain）

- 当目标转向 Port Call 创建时，Guide 将通用一致性/幂等性技能翻译为具体的 PostgreSQL 事务（分配资源、写状态、持久化响应），并明确 V1 与 two-movement 输入的接口语义，防止空间上下文失配。
- Port Call 实现与验证完成后，局部指导终止；Agent 重读需求，识别下一局部目标（清关与租约处理），携带最新执行证据发起新请求。

## 6. 主要结论与发现

- **主对比结果**：
  - Composer 在所有 13 个任务上一致优于 `Codex + Skills`。
  - 在最复杂子集（平均 8.48 小时/次运行）上，聚合确认通过率从 **29.9% 提升至 37.1%**，绝对提升 **7.2 个百分点**；主 Agent 累计 token 使用量减少 **32.2%**。

  - 其余 9 个任务上同样保持质量—效率模式：累计确认通过从 **458 增至 563**（相对提升 **22.9%**），主 Agent token 减少 **6.86%**。
- **组件对比结果**：
  - Composer 累计确认通过从 173 增至 229（相对提升 **32.37%**）。

- **消融结果**：
  - 动态执行证据：通过率从 34.23% 升至 41.26%，增益 **+7.03 个百分点**（四个任务中三个提升）。

- **总体结论**：将程序性记忆从被动经验投递转变为主动运行时策略适配，无需参数更新即可显著提升长时程软件工程任务的可靠性与执行效率；空间落地与时间生命周期两者缺一不可。

- **失败案例缺乏定性分析**：结果以聚合通过率与 token 数为主，未提供未通过任务（或改进幅度较小任务）的轨迹级分析，难以定位剩余瓶颈究竟来自技能覆盖、组合质量还是执行智能体自身能力。
- **技能库构建与维护成本未讨论**：18 个技能由人工预先构建并全程固定，其构建成本、技能粒度选择、技能间冗余与冲突处理、以及技能库扩展后的可维护性均未涉及。
- **生命周期终止判断的主观性**：`Applies When`、`Verification`、`Termination` 子句由执行智能体自行解释并决定是否重入需求，可能引入判断偏差；论文未报告终止判断的准确率、误终止率或"该终止而未终止"的案例分析。
- **可复现性细节不足**：提示词模板、Guide 的具体文本格式与字段渲染方式、辅助模型的具体身份与解码参数、随机种子控制策略等关键实现细节未充分披露，增加了外部复现难度。
- **与参数级适配方法的对比缺失**：论文强调"无需参数更新"的推理时适配优势，但未与微调、LoRA、策略蒸馏等参数级方案进行实证对比，因此"免训练"的相对收益幅度仍属推断而非实测。
- **安全与鲁棒性维度未评估**：行为边界 $b_\tau$ 被设计为约束行动空间，但论文未测试在对抗性需求、模糊规则或工具异常情况下，Runtime Guide 是否能真正阻止危险操作，安全性主张尚缺乏实验支撑。

## 9. 总体评价与适用建议

- **理论贡献层面**：论文的核心价值在于概念重构——把程序性记忆的复用问题从"检索与注入"提升为"推理时策略编译"，并用空间/时间双轴刻画失配来源。这一视角对记忆增强智能体、长时程智能体、工具使用智能体等方向均具有迁移价值，即便不采用其具体实现，$(\ell_\tau, r_\tau, b_\tau, e_\tau)$ 的结构化指导接口与"选择—组合"解耦也提供了可借鉴的设计范式。
- **实证贡献层面**：13 个任务、78 次开发运行、超过 335 小时的执行规模在同类研究中属于较大体量，且"质量提升 + token 下降"的双赢结果具有较强的说服力；组件控制与双轴消融也基本支撑了"空间与时间缺一不可"的核心主张。
- **适用场景建议**：最适合技能来源与目标环境存在系统性差异、任务跨越多个执行阶段、且执行器不可微调（或微调成本过高）的长时程工程任务；对于短任务、单一环境或技能与目标高度一致的场景，引入 Selector/Composer 的编排开销可能得不偿失。
- **改进优先级建议**：优先补充（1）多 benchmark、多执行器的泛化验证；（2）辅助模型成本的完整披露与延迟拆分；（3）全任务消融与统计显著性检验；（4）失败轨迹的定性归因。这四类工作将显著提升结论的外部效度与工程可信度。
