## 摘要
AI编程智能体的性能高度依赖于其底层编码规则。然而，现有编码规则通常是手工设计且固定的，导致过程劳动密集且往往次优。在这项工作中，我们提出RuleEvolve，一种用于编码规则的自演化框架。RuleEvolve维护一个候选编码规则池，并迭代地改进它们。在每次迭代中，它采用由LLM驱动的变异器模块从现有候选中生成变体，然后使用评判器模块评估这些变体，并用表现最佳的变体更新规则池。在两种编码智能体框架、四种骨干LLM和三个基准上的广泛评估表明，RuleEvolve在生成代码的功能正确性、代码长度和/或生成成本（例如使用的token数）方面，优于人工工程和现有提示优化基线。

## Abstract
The performance of AI coding agents is highly dependent on their underlying coding rules. However, existing coding rules are typically hand-crafted and fixed, making the process labor-intensive and often suboptimal. In this work, we propose RuleEvolve, a self-evolving framework for coding rules. RuleEvolve maintains a pool of candidate coding rules and iteratively improves them. In each iteration, it employs an LLM-powered mutator module to generate variants from existing candidates, and then uses a judge module to evaluate these variants and update the pool with the best-performing ones. Extensive evaluations across two coding-agent frameworks, four backbone LLMs, and three benchmarks demonstrate that RuleEvolve outperforms both manual engineering and existing prompt optimization baselines in terms of functional correctness of the generated code, code length, and/or generation cost (e.g., tokens used).

  - 现有编码规则几乎完全由人类开发者手工编写（如 awesome-cursorrules 仓库），劳动密集且往往缺乏任务针对性，甚至可能**降低**智能体性能。
  - 现有自动提示优化技术（如 Prompt-Ops、DSPy）主要面向"几句短指令"，而编码规则是长篇、结构化、文档化的指导文本，搜索空间大得多。
  - 编程智能体的执行涉及多轮交互与外部工具调用，流程不可微，且每次规则评估都需完整运行智能体与验证，资源消耗极高，使随机变异策略在计算上不可行。
- **整体含义**：论文主张将编码规则从"静态手工资产"转变为"可自动进化的优化对象"，提出自演化框架 **RuleEvolve**，在保持功能正确性的前提下，自动演化出更简洁、更省 token 的编码规则。

## 2. 方法论

### 2.1 核心思想
维护一个固定大小 $m$ 的候选编码规则池，通过"**变异—评估—剪枝**"的迭代循环逼近最优规则：每轮由 LLM 变异器生成 $N$ 个新变体，由评判模块在真实任务上打分，保留 top-$m$ 进入下一轮。

### 2.2 问题形式化
- 编码智能体 $A_\theta$ 按 $y \sim p_\theta(\cdot \mid x, r)$ 生成代码，$x$ 为任务、$r$ 为规则。
- **约束优化目标**：
  - 正确性约束：$\frac{1}{|X|}\sum_{x} \mathbb{E}[V(x,y)] \ge \tau$（$V$ 为代码验证器，$\tau$ 为可接受正确率阈值）；
  - 优化目标：最大化 $\mathbb{E}[E(y) + C(A_\theta, x, r)]$，即最大化代码简洁度与降低推理成本。
- **评判分数**（式 5）：
  $$S = -|A_\theta(x,r)| - \lambda \cdot \mathbb{E}_{x\in X}\big[V(x,A_\theta(x,\varnothing)) - V(x,A_\theta(x,r))\big]_+$$
  其中第一项以**生成代码字符数**近似代码长度与推理成本（论文验证字符数与 token 用量高度相关），第二项是对"规则导致正确率低于无规则基线"的惩罚，$\lambda$ 平衡二者。

### 2.3 三大组件
- **变异器模块 M**：LLM 驱动，输入当前规则 $r$ 与自然语言变异指令 $g$（如改进措辞、重排/合并步骤、改变风格），输出变体 $r_m = M(r,g)$。
- **评判模块 J**：在任务集 $X$ 上执行智能体、运行生成代码、按正确性/长度/成本打分，输出 $S = J(r, A_\theta, X)$。
- **规则池与剪枝**：池容量固定为 $m$，每轮合并 $m+N$ 个候选后保留 top-$m$；$T$ 轮后返回平均分最高的规则。

### 2.4 关键技术：战略变异分配（基于 OCBA）
- **动机**：均分或按平均分比例分配 $N$ 个变异会产生次优结果。
- **做法**：借鉴 Optimal Computing Budget Allocation，以最大化"正确选择最优候选的概率（PCS）"为目标分配预算。
  - 每个候选维护历史分数集 $S_i$；**新变异体继承父代的分数集**以解决冷启动问题并保证各候选观测数一致。
  - 对非最优候选 $i \ne b$，权重 $w_i \propto \left(\frac{\hat\sigma_i}{\hat\mu_b - \hat\mu_i}\right)^2$——**方差越大、与当前最优差距越小，分配越多变异**。
  - 最优候选权重 $w_b = \hat\sigma_b\sqrt{\sum_{i\ne b} w_i^2/\hat\sigma_i^2}$，保证比较的统计稳定性。
  - 归一化后取整得到各候选的离散变异数 $n_i$，$\sum n_i = N$。
- **算法流程（Algorithm 1）**：初始化池（$m$ 个变异）→ 评分 → 循环 $T$ 轮{战略分配 $N$ → 逐候选生成变异 → 评估新候选 → 更新分数 → 剪枝保留 top-$m$} → 返回最优规则。

## 6. 主要结论与发现

- **正确性不降甚至提升**：RuleEvolve 在所有基准上取得最高或持平 Pass Rate。例如 OpenHands + gpt-5.3-codex 在 BCB 上 PR 从 0.49（No rule）提升至 **0.52**；OpenAI SDK + gpt-5.3-codex 在 BCB 上从 0.45（Manual rule）提升至 **0.49**。
- **代码长度与成本显著下降**：OpenAI SDK + gpt-5.3-codex 在 BigCodeBench 上**代码长度降低超过 60%**且不牺牲 pass rate（CC 从 2372 降至 453.1，Tok 从 1022 降至 544.5）；OpenHands 的 HumanEval 上代码行数从 21.7 降至 12.7。
- **人工规则往往无益甚至有害**：Manual Rule 常比 No Rule 产生更长代码且 pass rate 更低，与已有研究（Gloaguen 等）一致。
- **Prompt-Ops 以正确性换取简洁**：其偶尔在长度/成本上优于 RuleEvolve，但正确性明显下滑（如 OpenHands BCB 降至 0.43；Qwen-Coder-30B 的 HumanEval 仅 0.67）。论文强调 PR 是最关键指标，代码错误则长度优化无意义。
- **战略变异分配有效**：在 pass rate 同为 0.500 时，战略分配得到最简洁代码（22.6 行 / 736.2 字符）与最低成本（15.48 s / 975.2 tokens），优于 Even 与 Proportional。
- **收敛特性**：正确率在 20 轮迭代中保持稳定，代码行数、字符数、token 用量持续下降，主要改进集中在前 5 轮，约 20 轮后趋于收敛；生成时间因 API 延迟与自回归随机性而波动较大。
- **鲁棒性**：10 seed 下 PR 为 0.502 ± 0.026，CLn 24.3 ± 0.4，CC 794.4 ± 14，稳定性好；Pass@k 随 $k$ 单调上升。
- **仓库级场景可迁移**：SWE-Bench Lite 上 PR 达 **0.340**（最高），代码行数从 8.5 降至 5.7，字符数从 380 降至 254。
- **规则归因**：约束代码形式的"输出格式/自包含性"指令影响最大（153 字符），"简洁风格"单节效率最高（61.6 字符/节），而"流程/预算"类指令净效应为负（-5.0）。
- **代码质量权衡**：圈复杂度 5.37→3.95、Halstead 体积降低 47%、重复块比例降至 0%，可维护性指数仍为 Grade A（85.1→78.3）；但每 SLOC 复杂度上升 22%，docstring 覆盖率从 47% 降至 1%。

## 7. 优点

- **问题切入新颖且实用**：首次系统性地将编码规则（AGENTS.md 类长文本资产）作为自演化优化对象，填补了自演化智能体研究中"规则"维度的空白。
- **多目标约束建模清晰**：以正确率为硬约束、以长度/成本为优化目标，并巧妙用代码字符数近似 token 成本（有相关性图支撑），避免了昂贵的在线成本测量。
- **分配策略有理论支撑**：基于 OCBA 的概率正确选择（PCS）框架推导权重公式，并给出直观解释（方差大、接近最优者获得更多预算），比均分/比例分配更有原则性。
- **评分继承机制**：新变异体继承父代分数集，解决冷启动并保证统计可比性，是工程上简洁有效的设计。
- **实验矩阵庞大且多维**：2 框架 × 4 骨干 × 3 基准 + SWE-Bench Lite + 10 seed + 4 组消融 + Pass@k + 规则归因 + 代码质量指标，证据链完整。
- **诚实呈现反面结果**：明确指出人工规则可能有害、Prompt-Ops 在某些成本指标上可胜出、规则演化会牺牲 docstring 与代码密度，论证客观。

- **评估域的语言与任务单一性**：主实验基准 BigCodeBench、BigCodeBench-Hard、HumanEval 均为 **Python 函数级任务**，SWE-Bench Lite 亦以 Python 仓库为主。规则演化的收益是否能迁移到多语言、前端/系统级、数据科学等异构场景，论文未做验证。
- **成本度量的近似性**：以**生成代码字符数**作为长度与 token 成本的代理，虽给出字符数与 token 用量的相关性图，但字符数并不等价于输入侧规则长度、推理步数或 API 计费 token；规则本身对上下文长度的占用（即规则 token）未直接计入优化目标，可能出现"规则变长但生成代码变短"的净收益误判。
- **训练—测试同源偏差**：演化训练集与主测试基准均采样自 BigCodeBench，尽管样本严格不重叠，仍存在**分布同源的乐观偏差**风险；跨数据集（如仅用 HumanEval 演化、在 BCB 测试）的泛化实验缺失。
- **规则可解释性与过拟合**：论文未分析演化出的规则文本是否可读、是否包含对训练任务过拟合的特定指令（如针对某类题目的技巧性提示），也未评估规则在**未见任务类型**上的行为；自演化规则可能生成规避性指令（例如弱化测试要求），这类对齐与安全风险未被讨论。
- **超参与预算的敏感性**：$T$、$N$、$m$、$B$ 虽各有消融，但**组合效应**与"演化总预算固定时如何分配轮数/变异数/池大小"的权衡未系统研究；OCBA 分配假设各候选方差可估，在候选数 $m=1$ 或 $N$ 极小时其优势可能退化（论文池大小消融中 $m=1$ 即为该边界情形）。

## 9. 总体评价与启示

- **总体定位**：这是一篇**问题定义清晰、方法有原则、证据链较完整**的工作，把"编码规则"这一长期被当作手工配置的静态资产，正式纳入智能体自演化的优化闭环，并用约束优化 + OCBA 预算分配给出了可操作的解法。其最大价值不仅在于 RuleEvolve 本身，更在于揭示了一个反直觉但重要的经验事实：**人工精心编写的规则常常无益甚至有害，而自动演化可以在不牺牲（甚至提升）正确率的前提下大幅压缩代码长度与推理成本。**
- **对实践者的直接启示**：
  - 不要默认"规则越多越好"；`AGENTS.md` 类文件应被视为需要持续测量与迭代的**性能变量**，而非一次性写就的文档。
  - 高杠杆的规则内容集中在**输出格式约束与自包含性要求**（归因分析中影响最大），而"流程/预算"类指令净效应为负，说明规则应聚焦"产出形态"而非"过程指挥"。
  - 简洁化需以正确率为硬门槛，否则会滑向 Prompt-Ops 式"以正确性换长度"的陷阱。
- **未来研究方向**：
  - 将**规则 token 成本**显式纳入目标函数，实现端到端的上下文预算优化。
  - 把**变异指令集**、评判标准乃至评判器本身一并纳入搜索或元学习，突破人工算子设定的上限。
  - 引入**多目标/帕累托优化**（正确性、成本、可维护性、文档覆盖率），避免 docstring 归零这类单目标副作用。
  - 探索**跨语言、跨仓库、持续在线演化**的设定，并研究演化规则的过拟合、可解释性与安全对齐问题。
  - 补充**算力与费用报告**（API 调用次数、token 总消耗、墙钟时间），使复现与成本—收益评估成为可能。
- **一句话结论**：RuleEvolve 证明了编码规则可以被自动"进化"得更短、更省、且不更差，为自演化编程智能体补上了"规则层"这一关键拼图；但其在文档质量、跨域泛化与演化成本透明度上的空白，也界定了下一阶段研究的明确着力点。
