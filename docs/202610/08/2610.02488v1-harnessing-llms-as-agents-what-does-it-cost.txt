Harnessing LLMs as Agents: What Does It Cost? 

Zelin Zhao 1, Xinyu Guo 1, Jingyuan Zhang 1, Yuxuan Zhang 2, Yongxin Chen 1

1Georgia Institute of Technology,  2Etude AI 

Language-model agents increasingly rely on harnesses that manage bounded context, persistent memory, tools, verification, 

and repeated execution, but existing notions of model capability do not quantify the computational resources these mechanisms 

consume. We develop a theory of these costs through the  Language Model Agent Machine  (lam ), a resource-bounded model that 

fixes the underlying semantic model while explicitly charging harness-level resources. Our theory yields four classes of results. 

Communication:  lam  execution and red–blue pebbling are instancewise equivalent at the level of simultaneous call–transfer 

budgets, yielding the full discrete resource frontier and transferring classical I/O lower bounds to context–memory traffic. 

Access:  memory interface changes asymptotic cost, including a  Θ(𝑛 ) separation between random and non-speculative sequential 

access on pointer chasing and an exact single-stack FIFO frontier.  Recomputation:  bit-reversal DAGs require  Θ(𝑛 2/(𝐶  + 𝑆 ) +

𝑛 ) model calls with context capacity  𝐶  and persistent-memory capacity  𝑆 , quantifying when stored intermediate state avoids 

repeated semantic computation.  Reliability:  we derive tight stage-local sampling bounds, exact imperfect-verification costs, 

and a Young–Daly-type checkpoint law with a closed-form optimal verification interval. Controlled experiments and held-out 

evaluations on GPT-6 Astra  [1]  compare development-derived communication and reliability predictions with measurements, 

including checkpoint optima and a held-out policy-selection tournament conditional on a programmatic segment check; held-

out chained MATH additionally exposes an observed tradeoff between whole-task call granularity, logical input traffic, and 

reliability. Prescribed-schedule runs are reported separately as implementation checks. Together, these results provide a resource 

theory for the computational cost of language-model agent harnesses.

11. Introduction 

Modern language-model agents are computational systems 

built around a model, not isolated model calls: a harness 

manages context, persistent state, tools, verification, and 

repeated execution  [2] , [3] , [4] , [5] . Existing theory largely 

characterizes what models or agentic extensions can com -

pute: additional reasoning steps, external memory, tool ac -

cess, and verifier interaction can all change computational 

power  [6] , [7] , [8] , [9] , [10] . What it does not characterize 

is the resource cost of realizing that computation through 

a harness. 

Harness architecture is itself a source of computational 

complexity. Two agents using the same underlying model 

can have the same semantic capability yet require asymp -

totically different numbers of model calls, context–memory 

transfers, memory operations, or verification steps. We 

therefore ask a different theoretical question: holding se -

mantic capability fixed, what resources must a harness 

spend to execute a computation, and what is the optimal 

tradeoff among model calls, context, persistent storage, 

communication, and verification? 

We introduce the  Language Model Agent Machine  (lam ), a 

resource theory for model–harness execution.  lam  fixes se -

mantic-oracle power and makes context, persistent storage, 

state movement, model calls, tools, and verification explicit 

computational resources. Its value-provenance principle 

allows the harness to move, store, and reuse semantic state 

but prevents it from creating task-relevant content for free. 

This separation is essential: it lets us attribute differences in 

execution cost to harness design rather than to a stronger 

underlying model. 

This viewpoint exposes resource questions that are in -

visible to computability alone. How much communication 

is forced by bounded context? Does the interface to the 

same amount of memory change complexity? When can 

persistent state replace repeated semantic computation? 

How expensive is correctness when model transitions are 

imperfect? Classical complexity theory provides important 

ingredients for each question, but harness executions intro -

duce complications absent from the classical abstractions: 

values may be copied or recomputed, only active-context 

values can directly enter a model call, the controller must 

not store semantic information for free, and an incorrect 

model transition may be committed before its error can be 

detected. We resolve these complications in four resource 

laws: 

• Communication is exactly characterized by peb 

bling ( Section 4 ).  Red–blue pebbling provides the 

classical abstraction for fast–slow memory communi -

cation, but a harness execution contains physical block 

copies, recomputation, and controller-managed state 

that do not correspond one-to-one with graph vertices. 

Using value provenance, we quotient block occurrences 

by computational origin and prove an instancewise, 

resource-preserving correspondence: for every  𝐿 -real -

isable DAG, memory-initialized vertex-granular  lam 

evaluations and red–blue pebblings have exactly the 

same feasible call–transfer budgets. The result therefore 

preserves the full discrete Pareto frontier, not only 

an asymptotic I/O lower bound or a single weighted 

optimum ( Theorem 1 , Corollary 9  and  Corollary 10 ). 

Classical pebbling lower bounds consequently become 

harness-communication lower bounds. On a sequential 

chain, dependency-only prompting uses  Θ(𝑛 𝑏 ) logical 

input symbols, versus  Θ(𝑛 2𝑏 ) for full-history replay 

(Proposition 12 ). 

• The memory interface changes computational 

complexity ( Section 5 ).  Memory capacity alone does 

not determine harness cost. For FIFO retrieval through 

a single stack, arbitrary buffering and copying defeat 

the usual stack-order argument; we prove a single-

copy normal form that removes this freedom without 

increasing context, and from it derive the exact context– 

storage–traffic frontier, including the precise feasibility 

region and optimal transfer cost ( Theorem 17 , Corol -

lary 19 ). Random access solves the same routing task 

with constant active context. On pointer chasing, ran -

dom access follows  𝑘  pointers in  𝑘  reads, whereas 

every always-correct non-speculative sequential execu -

tion requires  Ω(𝑘 𝑛 ) expected head movements; even 

unrestricted always-correct read-only sequential execu -

tion retains an  Ω(𝑛 ) lower bound ( Theorem 2 , Proposi -

tion 14 ). 

• Persistent state trades directly against semantic 

recomputation ( Section 6 ).  The classical bit-reversal 

graph has a known call–space tradeoff, but the  lam 

setting separates active context from persistent storage: 

only context participates directly in a model call, while 

stored values must be explicitly recovered, and the 

input source is delivered only once. We lift the classi -

cal tradeoff to this asymmetric execution model and 

obtain a complete harness-level characterization: opti -

mal model-call complexity  Θ(𝑛 2/(𝐶  + 𝑆 ) + 𝑛 ), explicit 

two-sided constants, the exact feasibility region, and a 

matching schedule with linear context–memory traffic 

(Theorem 3 ). In particular, linear model-call complexity 

is achievable if and only if total semantic capacity  𝐶  + 𝑆 

is linear in  𝑛 ; without persistence, the same computation 

incurs a  Θ(𝑛 /𝐶 ) multiplicative recomputation overhead 

when  𝐶  = 𝑜 (𝑛 ).

• Correctness feedback changes the cost of reliable 

execution ( Section 7 ).  Classical noisy-query bounds 

describe the cost of distinguishing a correct answer 

locally, but an agent commits to a sequence of depen -

dent states. We construct a hidden-tree family in which 

an erroneous commitment produces no later diagnostic 

signal, allowing adaptive within-stage stopping while

## 2. Related Work 

Agent computability and harness complexity.  Prior 

theory largely asks what language models and agentic 

extensions can compute, including the effects of additional 

reasoning, external memory, tools, and verification  [2] ,

[3] , [4] , [6] , [7] , [8] , [10] , [11] . Closest in spirit, MemGPT 

[12]  manages a bounded context window by paging state 

to external storage, an operating-system analogy that our 

active context  𝑋  and persistent memory  𝑀  formalize. 

Differently,  lam  asks a question: holding semantic-oracle 

power fixed, what resources must the harness spend to 

realize a computation? This makes model calls, context, 

persistent storage, memory traffic, and verification explicit 

computational resources, and exposes complexity differ -

ences between harnesses with the same semantic capability. 

Structured procedures handed to a model, such as program-

guided transformers  [13]  or routines discovered from a 

single demonstration  [14] , are harness-level objects in this 

sense: they change the execution schedule without chang -

ing the model. Research-level mathematics agents such as 

RMA  [15] , with persistent proof state, bounded per-call 

context, and verifier feedback, are concrete harnesses of the 

kind  lam  is designed to account for. 

Communication, access, and recomputation.  Red– 

blue pebbling  [16]  and classical bit-reversal tradeoffs  [17] 

provide lower-bound machinery for abstract computations. 

lam  establishes the bridge to harness execution: the 

pebbling correspondence preserves simultaneous call and 

transfer budgets and therefore the full discrete Pareto 

frontier, while the bit-reversal theorem gives the joint 

law  Θ(𝑛 2/(𝐶  + 𝑆 ) + 𝑛 ) for active context and persistent 

memory, including explicit constants and the exact feasi -

bility region. Our access results further show that memory 

capacity alone is insufficient: the access interface itself can 

change asymptotic complexity. 

Reliability and cost  aware execution.  Noisy-query 

theory, reliable computation, verifier-assisted generation, 

and checkpointing study different aspects of computation 

under uncertainty  [10] , [18] , [19] , [20] , [21] , [22] , [23] .

lam  treats correctness feedback as a priced computational 

resource, yielding tight sampling bounds without feedback, 

exact error–cost laws for imperfect verification, and a 

closed-form checkpoint optimum under rollback. Empirical 

work measures deployment-specific accuracy–cost trade -

offs  [24] , [25] ; our theory instead predicts feasible resource 

tradeoffs and harness choices before execution, which we 

test prospectively in  Section 8 .

## 3. Language Model Agent Machines 

The  lam  is designed to separate two quantities that exist -

ing agent abstractions often conflate: semantic capability 

and the resources required to orchestrate that capability 

(Figure 1 a). It models the harness-level execution around 

a fixed semantic interface—context construction, persistent 

state, memory access, tools, verification, and repeated calls 

—rather than the model’s internal computation. 

Semantic block.  Fix an input size  𝑛  and a finite alpha -

bet  Σ. A  semantic block , a fixed-width unit of task-relevant 

information, is an element of  ℬ︀  𝑛  ≔ Σ𝑏 (𝑛 ), where  𝑏 (𝑛 ) is the 

block width. 

Machine model.  A lam  is a tuple  Λ =

(𝐿 , ctrl, 𝑋  , 𝑀 , 𝑂 tool, 𝑂 ver), drawn in  Figure 1 b, where  𝐿  is 

the model interface,  ctrl is the harness controller,  𝑋  is the 

active context,  𝑀  is the persistent memory, and  𝑂 tool and 

𝑂 ver are the tool and verifier interfaces. The active context 

𝑋  holds at most  𝐶  blocks available to the next model call; 

the persistent memory  𝑀  holds at most  𝑆  blocks across 

calls outside  𝑋  , and a stored block must be retrieved into  𝑋 

before a call can use it, the persistent copy staying in place. 

A call to  𝐿  consumes blocks in  𝑋  and inserts its output as 

a new block of  𝑋  , so a call takes at most  𝐶  − 1 argument 

blocks. A tool returns a semantic block through an explic -

itly charged operation. A verifier returns a tag (e.g. accept/ 

reject in  Section 7 ), inserts no block, and may inspect all  𝐶 

resident blocks. Each of  𝐿 , 𝑂 tool and  𝑂 ver is a fixed map of 

its opcode and argument blocks alone (the  interface clause ): 

no interface sees the input,  𝑀 , or a block not passed to 

it. The controller is a finite control with tag and address 

registers that see block contents only through returned tags 

and decoded addresses, plus the occupancy pattern of  𝑋 

and public step counters;  Definition 3  (Appendix A ) fixes 

the step rule and the operation set that every lower bound 

below quantifies over. 

Definition 1  (Value provenance) . A lam  execution satis -

fies  value provenance  (vpa ) if every semantic block origi -

nates from an input, a declared constant, or a charged model 

or tool call. Copying, movement, and storage preserve this 

origin, while recomputation creates a new occurrence of 

the same computational value. The controller cannot create 

semantic blocks otherwise.

Computation graph.  We represent dependencies

Red–blue pebbling.  The red–blue pebble game  [16] 

represents block movement between  𝑋  and  𝑀  (Figure 1 d): 

a red pebble on  𝑣  means its block is in  𝑋  , a blue pebble 

that a copy is in  𝑀 , and a vertex may carry both. A  load

a blue pebble to a red-pebbled vertex, a  compute  places a

bounded by  𝐶 , blue pebbles by  𝑆 , and each load or store adds 

one to  𝑄 blk. A pebbling starts with a blue pebble on every

of loads and stores of such a pebbling ( IO𝐶  (𝐺 ) when  𝑆  is 

not binding). The analogy is not yet an equivalence: a  lam 

execution may copy and recompute semantic values, so 

physical block occurrences do not correspond one-to-one 

with DAG vertices. Value provenance lets us quotient these 

occurrences by computational origin while preserving both 

model-call and transfer budgets. 

Definition 2  (Vertex-granular  𝐺 -evaluation) . A vertex-

8.1. Held  out MATH: traffic, success, and granu 

larity 

From the  207 eligible MATH-500 problems  [26] , [27]  we 

build  100 depth-16 answer-dependent chains following 

Compositional GSM  [28] : chains 1–30 form the devel -

opment set and 31–100 the held-out compositions. We 

evaluate GPT-6 Astra under four harness configurations: 

Direct, using one whole-chain call; full-history replay; de -

pendency-only prompting; and dependency-only prompt -

ing with an  accept /reject  verifier. The routing protocol, 

traffic intervals, and success forecasts are determined from 

the development chains and held fixed on the held-out 

compositions. 

On the held-out compositions, dependency-only prompt -

ing with verification solves  70/70 chains with every link 

correct, whereas Direct solves  65/70 final answers and has 

64/70 chains with every link correct. Replay solves  67/70

final answers and has  65/70 chains with every link correct 

(Figure 2 (a)). Replay uses  35, 124 input tokens per chain, 

versus  3, 217 for dependency-only prompting with verifica -

tion, a  10.9 × reduction, while Direct uses only  1, 311 input 

tokens in a single whole-chain call. Thus dependency-

aware routing sharply reduces logical input traffic within 

stepwise execution, while Direct exposes a complementary 

granularity tradeoff: one model call can realize many logical 

steps with still lower input traffic, but here with lower 

observed held-out reliability. The vertex-granular theory 

therefore characterizes the resource frontier of stepwise 

execution rather than unrestricted whole-task calls. 

Execution granularity is itself a resource choice. 

The Direct condition highlights a distinction that is not 

visible in a vertex-granular cost model. A sufficiently capa -

ble model may compress many logical dependencies into 

one semantic call, simultaneously reducing both call count 

and input traffic. This does not contradict the vertex-gran -

ular frontier: it changes the computational primitive being 

priced. Conversely, the stepwise conditions expose inter -

mediate state to memory management and verification, 

yielding higher all-link reliability in the held-out GPT-6 As -

tra evaluation. Thus the choice of semantic-call granularity 

determines which communication–reliability tradeoffs are 

available to the harness.

## 9. Conclusion 

lam  makes agent-harness architecture a mathematical 

object whose resource requirements can be bounded, com -

pared, and optimized while semantic capability is held 

fixed. Across communication, memory access, recomputa -

tion, and reliability, the framework yields exact feasible 

regions, lower bounds, and closed-form resource tradeoffs. 

The experiments compare frozen predictions with mea -

surements while also exposing the scope of the theory: 

dependency-aware routing sharply reduces logical input 

traffic within stepwise execution, whereas held-out chained 

MATH shows that a whole-task call can use still less input 

traffic at lower observed reliability, outside the vertex-

granular frontier. Together, these results separate semantic 

capability from the resource cost of realizing that capabil -

ity through an agent harness.  lam  therefore provides a 

resource theory of agent execution: harness architecture 

determines which call, memory, communication, and reli -

ability tradeoffs are achievable even when the underlying 

semantic model is held fixed.

## Reproducibility statement 

All theoretical results in the paper are stated with their 

assumptions and proved in the appendices. We release the 

simulation code, frontier-model harness, theorem-target 

problem set, figure-generation scripts, raw request logs, 

frozen experimental configurations, and result files used 

in the paper. The supplementary material also records the 

experimental protocols, prompts, model settings, datasets, 

seeds, and other parameters needed to reproduce the re -

ported experiments. 

Ethics Statement 

This work develops a theoretical framework for analysing 

the resource requirements of language-model agents and 

their harnesses. It does not involve human-subject research 

or the collection of personally identifiable or sensitive data. 

The empirical components are limited to controlled simu -

lations and model-based experiments on a synthetic task 

and on public benchmark problems, intended to test the 

accounting and the assumptions of the theoretical model 

rather than to evaluate or deploy an agent in a high-stakes 

setting. 

The framework may inform the design of more efficient 

and reliable agentic systems. As with general improve -

ments in language-model agents, such advances could 

have both beneficial and potentially harmful downstream 

applications. Our work does not introduce methods specif -

ically intended to facilitate harmful behavior, bypass safety 

mechanisms, compromise privacy or security, or enable 

autonomous operation in high-stakes domains. Moreover, 

many of the results rely on explicitly stated abstractions 

and assumptions and should not be interpreted as guaran -

tees about the safety or reliability of deployed agents.

## B. Context–memory communication 

B.1. Proof of  Theorem 1 

We use the red–blue convention of  Section 4 . Red pebbles model the active semantic store of capacity  𝐶 , and blue pebbles

Charged controller computation.  Strict  vpa  can be relaxed by representing value-producing controller operations

## F. Controlled execution checks 

We use controlled simulators to check that the constructive schedules in  Section 4 –Section 6  respect the stated context and 

memory capacities and reproduce their analytical resource accounting. Communication, access, and recomputation checks 

use deterministic semantic transitions; reliability checks use stochastic transitions with prescribed error laws. 

These experiments are implementation and scaling checks for the stated constructions. They are not treated as empirical 

evidence for the lower bounds themselves. 

F.1. Communication and access checks 

Bounded  context communication.  On grid DAGs, we compare row-major execution with a tiled schedule under the 

formal context bound. The tiled construction exhibits the  Θ(𝑛 2/𝐶 ) communication scaling predicted by  Corollary 11 ,

whereas row-major execution remains quadratic until a live row fits in context. On sequential chains, full-history replay 

and dependency-only prompting reproduce the quadratic and linear input-accounting laws of  Proposition 12 .

Memory access.  For pointer chasing, we compare random access with the demand-following, non-speculative sequen -

tial execution class of  Theorem 2 . Random access incurs one block read per pointer, while sequential access pays for the 

intervening head movement. The observed scaling is consistent with the separation proved in  Theorem 2 .

F.2. Reliability checks 

The reliability simulator implements the execution classes used in  Section 7 . Sampling-only policies commit stage by stage 

without correctness feedback, whereas verification and checkpoint policies receive the corresponding feedback and pay 

the stated verifier costs. 

For checkpointing, simulated retry costs closely follow the exact objective  𝑇  (𝑘 ) of  Theorem 6 , and the observed optimum 

tracks its closed-form minimizer. The square-root approximation is accurate only in its stated asymptotic regime; outside 

that regime the exact expression is the appropriate prediction. 

F.3. Recomputation implementation check 

The simulator executes the constructive schedules from the proof of  Theorem 3  while explicitly enforcing the context and 

persistent-memory capacities. Every model call requires its arguments to be resident, and an execution terminates on any 

context or storage overflow.

## G. GPT-6 Astra evaluation details 

Prompts and evaluation artifacts are provided with the released code. 

Common protocol.  All experiments use GPT-6 Astra  [1] , accessed through the OpenAI API with reasoning effort set 

to  medium , and a common harness. We record model and verifier calls, input and output traffic, cached input traffic, external-

memory transfers, and peak prompt length. Calls producing semantic state are counted as model calls; verdict-only calls 

are counted as verifier calls. 

The controller performs deterministic parsing, normalisation, and routing, but does not receive credit for semantic 

computation. Development or calibration data and held-out evaluation data are disjoint; forecast parameters and policy-

selection rules determined from the former remain fixed on the latter. Success rates use Wilson  95% intervals, token means 

use chain-level bootstrap intervals, and paired comparisons use exact McNemar tests.

G.2. Reliability 

Calibration and controlled checks.  We evaluate reliability policies on modular-affine chains whose transitions are 

executed by the model. A disjoint calibration split estimates the candidate error rate together with the error rates and 

relative cost of the learned verifier. These quantities parameterize the sampling, local- verification, and checkpoint policies 

evaluated in  Section 8.2 . Controlled checkpoint experiments additionally use a perfect segment verifier at stipulated costs 

to isolate the prediction of  Theorem 6  from verifier error. 

Dependence diagnostics.  Repeated sampling reveals substantial variation in error rates across chain states, so a pooled 

homogeneous i.i.d. model does not adequately describe the observed sampling process. The predeclared  𝑚 ⋆ = 15 voting 

policy nevertheless solved  6/6 chains with  0/96 wrong plurality decisions. 

Verifier errors are likewise candidate dependent: naturally wrong, correct, and synthetically corrupted candidates exhibit 

different acceptance behaviour. This observation motivates the candidate-dependent formulation of imperfect verification 

in  Appendix D , rather than a single candidate-independent false-accept probability. 

Held  out checkpoint  policy tournament.  The tournament compares the principal reliability mechanisms studied in 

Section 7 : unverified execution, sampling, local verification, segment rollback, and a joint local-verification–rollback policy. 

Calibration and held-out evaluation use disjoint chains. Forecast parameters and the policy-selection rule are determined 

from the calibration split and remain fixed on the held-out split. The resulting arm-level success and cost measurements 

are reported in  Section 8.2  and  Figure 2 .

For segment rollback, the verifier checks the affine map obtained by composing the public transition constants within a 

segment. This composition is controller-side arithmetic rather than a charged semantic call. The tournament therefore tests 

prospective checkpoint-policy selection conditional on this implemented segment-check interface, rather than an end-to-

end realization of the  vpa  restriction. 

The sampling results additionally confirm that state heterogeneity materially affects reliability prediction: a model 

that preserves the observed state-dependent error structure describes held-out failures substantially better than a pooled 

homogeneous i.i.d. approximation.
