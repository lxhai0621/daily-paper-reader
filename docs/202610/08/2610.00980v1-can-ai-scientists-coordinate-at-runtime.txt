## ABSTRACT 

Multi-agent AI scientists have shown improving performance across a diverse range of tasks. Yet a common approach is design-time agentic orchestration, which typically relies on fixed workflows. In contrast, human scientists coor-dinate and adjust their division of labor at runtime. We therefore ask: can AI scientists also coordinate at runtime? To this end, we introduce Runtime Agent Coordination (RAC), which selects agents from existing AI-scientist hosts dur-ing execution, assigns scoped work contracts, and provides artifact-grounded verification. Verification informs subsequent agents without blocking transi-tions or discarding artifacts. We conduct a single-seed exploratory evaluation across Agent Laboratory, EvoScientist, and ARK on ResearchClawBench, pre-serving host models, tools, and permissions under host-calibrated budgets. Four cumulative conditions separate native execution, runtime communication, run-time selection, and the combined addition of contracts and verification. Run-time selection yields the highest observed mean score for each host; adding con-tracts and verification reduces these means, with host-dependent outcomes rel-ative to native execution. These results motivate runtime coordination while exposing the limits of additional coordination mechanisms under constrained budgets. Code is available at https://github.com/systemind-team/ Runtime-AI-Scientist .

## 1 INTRODUCTION 

AI scientists automate increasingly large parts of the research lifecycle, including idea generation, literature synthesis, experiment design, implementation, analysis, and paper writing (Lu et al., 2024; Yamada et al., 2025; Schmidgall et al., 2025; Goel et al., 2025; Gottweis et al., 2025; Yang et al., 2026). Multi-agent systems distribute these activities across specialized roles that exchange prompts, critiques, code, and research artifacts. This communication determines what agents share. Coordi-nation is a separate decision: which agent should act next, what it should produce, whether its output is valid, and how the run should continue. Many prominent AI-scientist systems organize agent interactions through predefined stages, loops, and fallback rules (Lu et al., 2024; Yamada et al., 2025; Tang et al., 2025; Schmidgall et al., 2025; Xin et al., 2026). Search, repair, and debate add flexibility within these workflows, but do not necessarily let the system select the most relevant agent across stages (Yamada et al., 2025; Liu et al., 2026). Other systems, such as EvoScientist (Lyu et al., 2026), incorporate persistent memory and self-evolution. These differences motivate us to investigate whether a shared runtime coordination approach can improve research performance across hosts with varying degrees of native flexibility. Selecting the next agent based on the current research state matters because long-horizon scientific failures are state dependent. A missing result calls for an experimenter, a broken bibliography calls for a deterministic check or writer, or a contradictory figure may require code rather than another prose revision. Recent evaluations locate substantial AI-scientist failures in experimental design, grounding, and scientific reasoning rather than only in software crashes (Xu et al., 2026; Fei et al.,

We therefore ask whether runtime coordination is a useful alternative to fixed workflows for multi-agent AI scientists (Wang, 2026). To address this question, we propose Runtime Agent Coordination (RAC), illustrated in Figure 1, which uses current artifacts, open problems, execution history, and remaining budget to select an authorized existing agent. Scoped contracts define what each selected agent should accomplish, while artifact-grounded verification provides feedback on its output for subsequent work. Every verdict retains the workspace and host transition. We apply the same framework across different hosts under matched budgets, keeping their underlying agents and tools fixed to assess the benefits of communication and coordination. Our core contributions are threefold. First, we formally study runtime coordination in multi-agent AI scientists and formulate next-agent selection as a state-dependent decision, distinguishing it from communication under native workflow control. Second, we instantiate the RAC framework in multi-agent AI scientists such as Agent Laboratory, EvoScientist, and ARK without replacing their native agents, tools, or permissions. Third, we empirically test whether runtime coordination improves research performance under matched budgets, reporting research scores, token usage, and estimated inference costs across a range of tasks. ## 2 RELATED WORK 

2.1 AI S CIENTISTS 

AI scientists aim to automate research activities ranging from idea generation and experimentation to analysis and scientific writing (Lu et al., 2024; Schmidgall et al., 2025; Tang et al., 2025). The 2Systemind Research 

AI Scientist organizes these activities into an end-to-end workflow, while AI Scientist-v2 introduces agentic tree search within experimentation (Lu et al., 2024; Yamada et al., 2025). Agent Laboratory assigns specialized agents to research phases, AI-Researcher combines literature exploration with experimental development, and ARK provides a human-steered research harness (Schmidgall et al., 2025; Tang et al., 2025; Xin et al., 2026). These systems demonstrate different ways to organize specialized capabilities across the research lifecycle. Other systems emphasize iterative feedback and adaptation. Co-scientist combines hypothesis gen-eration, debate, and ranking (Gottweis et al., 2025); AutoResearchClaw integrates multi-agent de-bate, execution repair, and verifiable reporting (Liu et al., 2026); and ARIS uses cross-model re-view and evidence checks to assess research claims (Yang et al., 2026). EvoScientist accumulates reusable research experience through persistent memory and self-evolution (Lyu et al., 2026). Mov-ing beyond predefined pipelines, freephdlabor supports workflows determined by real-time agent reasoning, while AutoScientists organizes decentralized teams around evolving experimental evi-dence (Li et al., 2025; Gao et al., 2026). Our work examines whether a shared runtime coordination approach can improve existing hosts with different native control mechanisms. Scientific output also requires evaluation beyond successful execution. ResearchClawBench eval-uates end-to-end research on real-paper-derived tasks, while diagnostic studies examine failures in experimental design, grounding, and scientific reasoning (Xu et al., 2026; Fei et al., 2026). Auto-mated review introduces further uncertainty because assessments can vary across evaluator mod-els (Ravideshik & Kejriwal, 2026). We therefore distinguish feedback used during research from external benchmark evaluation of the final outputs. 2.2 MULTI -A GENT COORDINATION 

Multi-agent systems combine specialized roles through communication and structured collaboration. AutoGen supports programmable agent conversations, MetaGPT combines role-specific workflows with shared structured messages, and multi-agent debate iteratively exchanges candidate answers and critiques (Wu et al., 2023; Hong et al., 2023; Du et al., 2023). These mechanisms shape the information available to agents, while coordination determines how their contributions are organized and which agent acts next. Several approaches explicitly optimize or adapt this organization. GPTSwarm represents agents as computational graphs and optimizes prompts and inter-agent connectivity (Zhuge et al., 2024). Dy-LAN selects agent teams and supports dynamic interactions during task solving (Liu et al., 2023). In scientific applications, freephdlabor and AutoScientists further demonstrate reasoning-driven work-flows and self-organizing collaboration (Li et al., 2025; Gao et al., 2026). Building on these di-rections, RAC studies runtime selection across existing AI-scientist hosts while preserving their underlying agents, tools, and permissions. Its cumulative conditions distinguish communication under native control from runtime selection and the combined addition of contracts and verification. Feedback and resource use are integral to this comparison. MetaGPT incorporates executable feed-back, while analyses of multi-agent failures identify inter-agent misalignment and verification or termination problems (Hong et al., 2023; Cemri et al., 2025). In RAC, scoped contracts define the selected agent’s task, and artifact-grounded verification informs subsequent work without veto-ing transitions. Because additional coordination can increase inference costs, we follow cost-aware agent evaluation principles (Kapoor et al., 2024; 2025) and compare research scores, token usage, and estimated costs under matched run-level budgets.

## 4 EXPERIMENTAL SETUP 

4.1 BASELINES 

We evaluated RAC with Agent Laboratory (Schmidgall et al., 2025), EvoScientist (Lyu et al., 2026), and ARK (Xin et al., 2026). These hosts span predefined control loops, fixed research phases, and native adaptation, allowing us to examine runtime coordination across different native control mechanisms. Each host’s native lifecycle serves as its N0 baseline. 4.2 BENCHMARK AND CONDITIONS 

ResearchClawBench provides real-paper-derived tasks across scientific domains. Each task supplies a research question, related literature, raw data, and an executable environment while withholding the target paper (Xu et al., 2026). Our evaluation covers mathematics, neuroscience, information science, energy, life science, and physics. We evaluate Agent Laboratory and EvoScientist on ten tasks each and ARK on five tasks. All runs use seed 0. Table 1 defines the cumulative conditions used to examine communication, runtime selection, and contracts with verification. R3 versus N0 compares the full framework with native execution; R2–R3 treats contracts and verification as a joint addition rather than isolating their individual effects. Table 1: Four cumulative conditions. R1 preserves native successors, R2 adds shared runtime selec-tion, and R3 jointly adds scoped contracts and verification.

4.3 CONTROLS AND ANALYSIS 

Within each host, we hold base models, native role prompts, tools, permissions, artifact interfaces, and task inputs fixed across conditions. Hop ceilings are calibrated to the corresponding host’s N0 hop count rather than set uniformly across hosts. The budget-matching design concerns config-ured resource ceilings, not equal realized consumption; routing and verification are charged to the run’s budget. Budget accounting is described in Appendix B.2. Cross-run memory and evolution stores are reset before each run to isolate within-run coordination. Model choices and inference-cost accounting are detailed in Appendix B. The primary outcome is the official ResearchClawBench weighted final score. We report input and output token usage and estimated inference costs separately. Each task–host–condition contributes one final score from the consolidated results record, including numeric zeros. A zero is an evaluator 5Systemind Research 

outcome, not an encoding of a missing report or a failed evaluation. Within-task differences from N0 are averaged over the same evaluated tasks within each host. Table 4 provides task-level scores; all summaries use unrounded values before display rounding.

Points in (a) show descriptive means, and connecting lines are visual guides. 5.4 TRACE -LEVEL ANALYSIS : THREE COORDINATION EFFECTS 

We inspected 1,181 hop excerpts and 180 external scoring receipts from the 60 cells covering five shared tasks, three hosts, and N0–R3. Selected trajectories illustrate coordination mechanisms and failure modes, not their prevalence or the causes of aggregate score differences. The excerpts are incomplete, scientific claims were not independently recomputed, and hop indices are zero-based. 

Evidence–action closure effect. In Physics-002 with EvoScientist R2, the native reviewer re-ported at hop 6 that the report contained only 39 bytes despite existing code, analyses, and figures. At hop 7, the selected debug capability reported producing a 337-line report of approximately 22 KB. Ten recorded scientific-artifact changes and the final inventory support the conclusion that a report was produced. This handoff connected a specific defect to corrective work, although subsequent debug calls made no recorded scientific-artifact changes before the hop limit. The feedback came from the host reviewer, not R3’s verifier; delivery repair does not establish scientific correctness. 

Planning stagnation after diagnosis. In Physics-002 with EvoScientist R3, the reviewer iden-tified a standard-error discrepancy: 0.011 in the report versus 0.015 in the data. At hop 8, the planner attributed it to duplicated observations and proposed code changes followed by regeneration of results. However, hops 8–13 remained planner calls with no recorded scientific-artifact changes, ending at the 14-hop limit. The trajectory illustrates a failure to move from diagnosis to imple-mentation. Claims of repeated verification appeared in agent messages but were not independently confirmed from verifier events. 8Systemind Research Self-consistent drift effect. In Neuroscience-000 with EvoScientist R3, the native reviewer re-ported that numerical and code–report consistency checks passed and assigned a score of 8/10. External evaluation nevertheless identified missing cross-laboratory, sex, and environment SHAP comparisons, yielding a final score of 13.6. The two scores use different criteria and scales and are not directly comparable. Similarly, Life-001 with Agent Laboratory R2 analyzed ten synthetic patients rather than the supplied seven-patient dataset. These cases distinguish internal consistency from coverage of the research objective, without identifying whether divergence originated in task interpretation, data limitations, or coordination. Appendix D provides detailed trajectories and evidence boundaries, including additional Math cases outside the shared-task subset. 

## 6 DISCUSSION 

Runtime selection achieved the highest observed means on ResearchClawBench, whereas contracts and verification produced the largest aggregate gain on the exploratory DiscoveryBench subset. This contrast suggests that the benefits of additional coordination depend on the host and research setting, rather than increasing uniformly with each mechanism. Under matched budgets, communication and verification add context and inference costs that may displace useful research work. Runtime selection can offset this overhead by directing work to-ward relevant agents, but R2’s lower recorded costs in ARK and Agent Laboratory did not extend to EvoScientist. Additional budget might accommodate R3’s overhead, yet the repeated planning trajectory in Section 5.4 shows that diagnosis need not lead to implementation. Distracting context or inaccurate verifier feedback could also weaken outcomes. Budget sweeps with per-hop usage and artifact changes would help distinguish resource constraints from ineffective delegation. Host structure may further shape these trade-offs. Agent Laboratory’s fixed phases may benefit from information carried between stages, whereas EvoScientist already incorporates native adaptation. Differences in native prompts and token consumption may also affect how effectively hosts use additional context. These remain hypotheses: aggregate scores and usage do not establish why individual runs improve or decline. Our single-seed evaluation does not measure variability across independent runs, and bounded benchmark tasks do not establish performance in open-ended discovery. Costs are standardized token-based estimates rather than provider invoices. R3 jointly adds contracts and verification, so their individual effects remain unresolved. 

## 7 CONCLUSION 

We presented RAC as an alternative coordination approach for multi-agent AI scientists. It selects existing agents from current state and, in R3, adds scoped contracts and artifact-grounded verifica-tion feedback. Across all available ResearchClawBench scores, R2 had the highest task-weighted mean for each host, whereas R3’s performance relative to N0 varied across hosts. These rankings are descriptive and do not establish robustness across independent runs. Standardized token-based costs describe resource use without establishing a general performance or cost advantage. ETHICS AND REPRODUCIBILITY STATEMENT 

Adaptive scientific workflows may accelerate research but can also amplify unsupported claims or optimize for fallible reviewer signals. This appendix specifies the records that RAC writes during a run and the boundary between RAC and each host. All conditions share the same RAC package and condition configuration; only the host bridge differs across hosts. A.1 COORDINATION RECORDS

A.2 HOST BRIDGES AND TERMINATION 

Each host bridge serializes native state, invokes an existing capability, and returns artifacts and usage records through a shared interface. Bridges contain no host-specific runtime selection rules, verifica-tion criteria, or benchmark hints, so each host keeps its agents, tools, and permissions. Verification feedback enters the next selected agent’s prompt rather than directly triggering retries, rerouting, rollback, or stopping. Runs terminate on budget exhaustion, hard hop limits, terminal provider errors, or native host completion. Communication state is isolated between runs, and cross-run memory and evolution stores are reset before each run. 

## B EXPERIMENTAL DETAILS 

This appendix gives the models, budget calibration, cost accounting, and evaluation protocol used for all reported comparisons. B.1 MODELS 

We use DeepSeek V4 Pro as the execution model for the AI-scientist hosts and GPT-5.5 as the external ResearchClawBench judge. External judging is separate from the in-loop verifier and does not control agent selection or host transitions. B.2 BUDGET CALIBRATION AND ACCOUNTING 

Hop ceilings are tailored to each host using its N0 hop count as the calibration reference. They are not a common cross-host constant: a native phase may itself contain many model or tool calls. 13 Systemind Research 

Configured limits and realized usage must therefore be distinguished. Token and call accounting includes coordination and verification, while external judging is excluded. Limits checked after an agent returns can be exceeded by that completed call; the excess is retained in usage totals, and subsequent work is stopped. The archived configurations contain multiple ceiling settings, and the consolidated score table alone does not identify every final configuration. We therefore do not infer a single numerical budget vector for an entire host or equate the standardized USD estimates with an enforced provider-spend limit. Budget matching describes the intended comparison design, not an independently verified equality of every archived resource ceiling. The results should be read as exploratory comparisons rather than exact compute-equated effects. B.3 COST ACCOUNTING 

We estimate inference costs from recorded input and output token usage using a common DeepSeek V4 Pro tariff. We apply the official peak rates of US$1.32 per million non-cached input tokens and US$3.96 per million output tokens, as listed in the DeepSeek API pricing documentation on 23 September 2026. For each episode, the estimated cost is (1 .32 Tin + 3 .96 Tout )/10 6 USD. Here, Tin 

and Tout are its recorded input and output token counts. We apply no cache-hit or off-peak discounts. Table entries average episode estimates before rounding. These are standardized inference-cost estimates, not Azure invoices, and exclude external GPT-5.5 judging charges. B.4 EVALUATION PROTOCOL 

The primary comparison is R3 versus N0 under matched budgets. Condition means equally weight final task–host–condition scores. For each host and each of R1–R3, we subtract the N0 score on the same task and average these differences over the same evaluated task set within that host. Figure 3 reports these descriptive paired means. The bars do not measure variability across independent runs. Adjacent conditions are compared on the same tasks, but R2–R3 does not separate contracts from verification.
