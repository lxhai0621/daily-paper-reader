## 摘要
个性化 LLM 助手必须从长对话历史中，针对复杂度各异的查询恢复稀疏证据。我们提出 APDMem（Agent-Controlled Progressive Disclosure Memory，智能体控制的渐进式披露记忆），一种将渐进式披露应用于记忆检索的分层长期记忆架构。APDMem 不依赖扁平记忆存储或固定检索粒度，而是将对话历史表示为四个逐步细化的层级：主题摘要、个性化关键事实、轮次级证据笔记和原始消息。在推理时，控制器对记忆层级应用渐进式披露：它首先读取高层摘要，仅在需要时才深入更细粒度的证据。这形成了一种自适应的成本—保真度权衡：简单查询可以提前终止，而复杂的时间、多跳或精确证据查询会触发更深入的检查。笔记合成器将检索到的证据转换为以查询为中心的结构，在生成最终答案之前整合事实、排序事件并标记矛盾。在 LongMemEval 上的实验表明，APDMem 在长上下文记忆推理中取得了强劲性能，同时仅访问总对话的 8%。

## Abstract
Personalized LLM assistants must recover sparse evidence from long conversation histories across queries of varying complexity. We introduce APDMem (Agent-controlled Progressive Disclosure Memory), a hierarchical long-term memory architecture that applies progressive disclosure to memory retrieval. Rather than relying on a flat memory store or fixed retrieval granularity, APDMem represents conversation history as four progressively detailed layers: thematic summaries, personalized key facts, turn-level evidence notes, and raw messages. At inference time, a controller applies progressive disclosure to the memory hierarchy: it first reads high-level summaries and drills into finer evidence only when needed. This creates an adaptive cost-fidelity trade-off: simple queries can terminate early, while complex temporal, multi-hop, or exact-evidence queries trigger deeper inspection. A note synthesizer converts retrieved evidence into a query-focused structure that consolidates facts, orders events, and flags contradictions before final answer generation. Experiments on LongMemEval show that APDMem achieves strong performance for long-context memory reasoning while accessing only 8% of the total conversations.

## 一、核心问题与研究动机

- **背景痛点**：个性化 LLM 助手需要在长期、多会话交互中记住用户偏好、事实细节、时间序列与反复出现的主题。缺乏有效记忆会导致"上下文失忆"（contextual amnesia）——无法回忆先前事实、丢失演进中的目标、忽略跨会话联系。
- **现有方法的两难**：
  - 一类系统（MemoryBank、MemGPT、A-MEM、Zep）通过专用记忆对象、图节点、外部存储提升召回，但引入了额外的记忆机制与工程复杂度。
  - 另一类系统（LightMem、SimpleMem）通过压缩/整合降低检索成本，但固定了检索表示与粒度，可能丢弃细粒度细节。
- **核心矛盾**：扁平记忆存储或固定检索粒度无法同时满足"成本"与"证据保真度"，而真实查询复杂度差异巨大（简单事实查询 vs. 时间推理、多跳、逐字证据查询）。
- **论文主张**：将长期记忆访问重构为**查询自适应的披露问题**（query-adaptive disclosure problem），而非一次性检索问题；借鉴 Nielsen (1993) 的渐进式披露（progressive disclosure）理念，先暴露粗粒度信息，按需揭示更细证据。
- **作者自述定位**：APDMem 是首个将渐进式披露作为智能体记忆**显式架构原则**、并由智能体通过工具调用控制披露深度的系统。

## 二、方法论

### 2.1 总体架构（三大组件）

1. **多分辨率记忆基底（Multi-Resolution Memory Substrate）**：将每次会话表示为四层元组 $S_i=(L_0,L_1,L_2,L_3)$。
2. **渐进式披露控制器（Progressive Disclosure Controller）**：以工具调用方式搜索、下钻、反思记忆层级。
3. **组织化笔记合成器（Organized Notes Synthesizer）**：将证据结构化为面向查询的接地上下文，供答案生成使用。

### 2.2 多分辨率记忆基底（四层设计）

- **L0 主题摘要**：带指代消解、绝对日期归一化、关键词与标签的逐轮摘要，是**主索引层**；摄入时即物化。
- **L1 个性化关键事实**：会话级的用户信息、推荐、计划、偏好、约束等要点（5–25 条）。
- **L2 轮级证据笔记**：按轮次组织的原子化事实要点，保留时间顺序，供细粒度证据推理。
- **L3 原始消息**：逐字保留的用户–助手消息，用于精确证据恢复；摄入时即物化。
- **惰性物化（Lazy materialization）**：仅 L0 与 L3 在摄入时生成，L1/L2 在被控制器首次请求时按需生成并缓存，以降低写入成本。
- **构建规则**：所有构建提示均强制语义消歧——禁止代词（改用具体实体名）、禁止相对时间（以会话时间戳为锚转换为绝对日期）；L2 要求"一事实一 bullet，不合并"。

### 2.3 渐进式披露控制器

- **动作空间**：$A=\{\text{search, read\_facts, read\_turns, read\_raw, interpret\_dates, decompose, reflect}\}$。
- **成本–保真度权衡**：$c(L_0)<c(L_1)<c(L_2)<c(L_3)$，$f(L_0)<f(L_1)<f(L_2)<f(L_3)$；控制器视为求解

$$\min_{a_{1:T}}\sum_{t=1}^{T}c(a_t)\quad \text{s.t.}\quad \text{sufficient}(V_T,q)=1$$

其中 $V_t$ 为第 $t$ 步的证据集合，充分性由证据反思估计并由收敛准则约束。与扁平检索不同，APDMem 同时选择**相关记忆区域**与**所需证据分辨率**。

- **工作流三阶段**：
  - **查询准备**：用 `interpret_dates` 将相对日期（如"去年夏天"）按提问时间戳归一化；用 `decompose` 拆分多跳/复合查询。
  - **渐进式披露**：`search` 在 L0 上做混合词法+稠密检索（RRF 融合）取 Top-K 会话；自动下钻（auto-drill）选择最有前景的未探索会话，`read_facts` 读 L1；不足则 `read_turns` 读 L2（按时间顺序）、`read_raw` 读 L3（限定最相关轮次）。
  - **反思与起草**：`reflect` 总结证据、识别缺失、判断继续检索是否有益；需要时提出后续查询重入披露阶段；收敛后由控制器生成草稿答案 $a_{\text{draft}}$。
- **收敛控制**：满足以下任一即终止——(1) 反思未发现新证据，$|V_t|=|V_{t-1}|$；(2) 达到步数预算 $T_{\max}$（实验中设 20，作为最坏情况成本/时延上界）。算法 1 还包含"nudge"机制（在证据增长但未反思时注入提示，最多 2 次）。

### 2.4 组织化笔记合成器

- 受 Chain-of-Note 启发，将查询 $q$、证据集 $V$ 与草稿 $a_{\text{draft}}$ 转换为紧凑中间表示，包含五部分：**相关事实**（按相关性排序并标注来源会话与日期）、**时间排序**（标出最新项）、**矛盾/更新**（列出所有版本，最新日期为当前真相）、**枚举**（计数/列举类查询去重列举）、**答案提示**（非最终答案）。
- **先合成再生成**：答案生成器接收组织化笔记与草稿，被要求独立扫描全部上下文、不得盲信智能体初稿，可纠正控制器遗漏或错误。

### 2.5 混合检索器（附录 G）

- 词法索引（带词干化的 BM25，关键词字段单独索引）+ 稠密索引（Nomic-v1.5，768 维，L2 归一化）。
- RRF 融合：$\text{rrf}(q,c_t)=\sum_{j\in\{lex,dense\}}\frac{w_j}{k+r_j(c_t)}$，$k=60$。
- 会话得分取最佳匹配轮次：$s(q,S_i)=\max_{t\in S_i}\text{rrf}(q,c_t)$；再加关键词精确匹配增益 $s'(q,S_i)=s(q,S_i)+\alpha\cdot s_{\max}\cdot n_i$（$\alpha=0.1$）。
- 多查询融合：对分解后的查询集取各会话的最优得分。
