## 摘要
语言模型在一次二次方前向传播中读取长文本，在上下文窗口处停止，并在尚未达到该窗口时就随长度增加而损失准确率。我们追问：当需要在有限集合上做出判断时——哪篇文档相关、哪个选项得到支持、哪段文字是证据——这种读取是否可以分解？Periscope 是一种免训练的推理方法，它将文本的 N 个块排列在 K×K 网格上，其中 K=⌈√N⌉，并针对 K 个由连续块组成的局部片段和 K 个采样整篇文本的跨步片段，向冻结模型提出同一个问题，在单个 token 处读取每个答案的对数几率。每个答案取其最佳局部得分和跨步得分；用每个块的两个片段对其打分，即可在不增加额外成本的情况下得到一张证据图，其峰值就是答案所依据的块。对于长度为 s 个 token 的文本和块大小 c，每次探测约为 √(sc) 个 token，因此一个 W 个 token 的窗口以 s^1.5 的代价可覆盖 W^2/c 个 token。该证据图取代了长文本读取。在 LongBench v2 上，仅读取证据图排名最高的 K 个块（9k 个 token），即可匹配同一模型在 32k 到 1M 个 token 的各种窗口下的最佳窗口读取；而在中位上下文为 150k 个 token 的 InfiniteBench 上，它领先最佳窗口读取 5 个百分点。同一张图对 BRIGHT 的长文档语料库进行排序，取得六种方法中最高的 NDCG@10。每次调用只缓存一个探测，因此一个 27B 模型可在单张 80GB GPU 上读取 4.5M 个 token 的上下文，而单次前向传播将需要 296GB 的缓存。于是，长文本读取需要的是一张能容纳模型的 GPU，而不是一张能容纳文本的 GPU。

## Abstract
A language model reads long text in one quadratic forward pass, stops at the context window, and loses accuracy with length before reaching it. We ask whether the read can be factorized when deciding over a finite set: which document is relevant, which option is supported, which passage is the evidence. Periscope, a training-free inference method, arranges the $N$ chunks of a text on a $K{\times}K$ grid with $K{=}\lceil\sqrt{N}\rceil$ and asks a frozen model the same question about $K$ local spans of consecutive chunks and $K$ strided spans that sample the whole text, reading the log-odds of every answer at one token. Each answer takes its best local and strided score, and scoring every chunk by its two spans gives an evidence map at no further cost, whose peak is the chunk behind the answer. Every probe is about $\sqrt{sc}$ tokens for a text of $s$ tokens and chunk size $c$, so a window of $W$ tokens reaches $W^{2}/c$ tokens at $s^{1.5}$ cost. The map replaces the long read. On LongBench v2, reading only the $K$ chunks the map ranks highest, 9k tokens, matches the same model's best window read across windows from 32k to 1M tokens, and on InfiniteBench, where the median context is 150k tokens, it leads the best window read by 5 points. The same map ranks BRIGHT's long-document corpora with the best NDCG@10 of six methods. Each call caches only one probe, so a 27B model reads 4.5M-token contexts on one 80GB GPU, where a single pass would need 296GB of cache. A long read then needs a GPU that holds the model, not one that holds the text.

# Periscope 论文结构化总结

## 1. 核心问题与研究动机

- **长读的三重瓶颈**：语言模型以单次二次方前向读取长文本，(1) 注意力成本随输入平方增长；(2) 在上下文窗口处被硬性截断；(3) 在抵达窗口之前精度就已下降——多数长上下文模型远早于宣称长度就跌破质量阈值，13 个宣称 128k 的模型中 11 个在 32k 时已跌到短上下文准确率的一半以下，且即使检索完美、长度本身也会损害表现，中间位置内容被利用得更少。
- **三条既有路线的结构性局限**：
  - **扩窗**（位置插值、YaRN、LongRoPE、稀疏/线性注意力混合）只是移动墙壁，保留二次成本与单体式显存；且属架构改造，不适用于既有模型。
  - **少读**（RAG 检索、prompt 压缩、KV 记忆检索）由读者之外的固定规则决定读什么，漏掉的内容无法被后续读取挽回；训练型稠密检索器在需要推理而非表面匹配时表现差。
  - **分片读**（FirstP/MaxP、Chain of Agents、LongAgent）每次调用有界，但要么每块孤立（无跨块视野），要么依赖前序生成的有损摘要，最终答案与"对全文的读取"没有明确关系。
- **核心洞察**：许多长上下文读取本质上是**有限答案集上的判定**（哪篇文档相关、哪个选项被支持、哪段是证据）。此类判定只需**一处**支持性片段，而冻结模型恰好在其有界窗口内最可靠。因此可以用有界窗口覆盖全文、用 max 组合答案（不引入额外近似），并顺带把答案分布转化为**证据位置图**。
- **整体含义**：长文本读取需要的是一块"装得下模型的 GPU"，而不是一块"装得下文本的 GPU"。

## 2. 方法论

### 2.1 探针（Probe）
- 一次前向传播，读第一个答案 token 的 log-odds，衡量该跨度单独支持某答案的强度。
- 多选题在选项外增加一个 **abstain 选项 ȳ（E. Unsure）**：`ℓ(y|S,q) = log p_θ(y|S,q) − log p_θ(ȳ|S,q)`。abstain 让无证据跨度对所有选项都低分，从而使不同跨度的分数**可比**。
- 检索任务把问题改为"该文档是否与查询相关"，取 Yes 对 No 的对数几率。

### 2.2 局部与跨步跨度（可分离网格）
- 文本切为 `N=⌈s/c⌉` 个 c-token 块，`K=⌈√N⌉`，按 K×K 网格索引，空块补齐。
- **局部跨度** `Lᵢ`：连续 K 个块（一个邻域）；**跨步跨度** `Sⱼ`：每隔 K 取一块，共 K 块（全篇的均匀采样）。
- 每块恰属于一个局部跨度与一个跨步跨度，故被读两次；共 **2K 次独立调用**，每次约 `√(sc)` token。

### 2.3 组合、证据图与读出
- **组合规则**：`score(y) = max_i Lᵢ(y) + max_j Sⱼ(y)`——只有某局部与某跨步跨度同时支持某答案时才得高分。
- **证据图**：`M[i,j] = max_{y≠ȳ}(Lᵢ(y) + Sⱼ(y))`，无需额外调用；最大单元即 `score(y)`，故**地图峰值就是产生答案的块**。
- **四种固定读出**（探针不变）：
  - *排序*：Yes/No 给出每篇文档一个分数，用于语料排序；
  - *直接回答*：`argmax_{y≠ȳ} score(y)`，不再额外调用；
  - *定位*：地图峰值即证据块；
  - *选择式读取*：取地图最高的 K 块按原序拼接，再用一次调用作答（共 2K+1 次调用，读取长度约等于一次探针）。

### 2.4 可达长度、成本与显存
- **可达长度**：`s_max ≈ W²/c`（W 为窗口）。c=500 时，32k 窗口可达约 2M token，128k 窗口可达约 33M token——是窗口自身的 W/c 倍。
- **计算成本**：单次全文读 `F_full = as + bs²`；探针 `F_probe = 2as + 2b√c·s^1.5`。探针每 token 做两倍工作，但注意力项从 s² 降到 s^1.5。交叉点 `s* ≈ a/b`（实测：4B 为 119k、27B 为 278k，c=500）；短文本整读更便宜，长文本探测更便宜。
- **显存**：单次读缓存全部 s token；探针只缓存 `√(sc)` token，且**永不超出一个窗口**。因此长读的显存由模型权重决定，而非文本长度。

## 3. 实验设计

- **问答基准**：
  - **LongBench v2**：503 道四选一，上下文 8k–2M 词，分短(180)/中(215)/长(108)。
  - **InfiniteBench En.MC**：229 题整本小说，中位上下文 150k token。
- **检索基准**：
  - **BRIGHT 长文档语料**：3,792 篇文档，350 条跨 7 个领域的查询，**无候选池**（对整域全语料打分），报告 NDCG@10、MRR、R@1、R@10。
- **模型**：Qwen3.5-4B、Qwen3.5-27B、Gemma-4-26B-A4B-it（MoE），全部冻结，vLLM bf16，单张 A100 80GB；同一模型的各 arm 跑在同一实例上。
- **窗口读基线**：4B 跑 32k/64k/131k/262k 原生 + 1M YaRN；27B 跑 131k/262k（1M 放不下）；Gemma 跑 262k。窗口读取"能放进窗口的最长前缀"。
- **同预算选择基线**（替换第二阶段的选块）：前 K 块、随机 K 块、Qwen3-Embedding-4B 余弦相似度 top-K。
- **检索基线**：BM25、Qwen3-Embed-4B、Embed chunk-max、FirstP、16k 窗口读。
- **消融与分析**：
  - 局部探针 vs 局部+跨步探针（LongBench v2 + BRIGHT）；
  - 与 Chain of Agents 对比（相同 K 个局部跨度、相同模型，K+1 次串行调用）；
  - 块大小 500 vs 1000；
  - **跨模型迁移**：用 4B 建图、交给 27B 读；
  - 分域/分长度档表现、胜负题数、与整读的一致率（Agree%、Pearson r、Spearman ρ）；
  - 附录 B：OBLIQ Congress 100 篇人工标注文档上的块级定位。

## 4. 资源与算力

- **硬件**：全程单张 **A100 80GB**；vLLM bf16 服务，4B 32 并发、27B 8 并发。所有 arm（含窗口读）在同一 GPU、同一实例上运行，无 arm 获得额外算力。
- **训练算力**：**无**——方法是免训练（training-free）的纯推理方法，因此没有训练时长/GPU 小时的报告。
- **显存实测**：27B 权重 54GB，vLLM 分配 356k token 缓存；4B 分配 2.1M token。最长上下文 4.5M token 时，单次读需 **296GB（27B）/148GB（4B）** 缓存，而一个探针只需 **3.1GB/1.6GB**。
- **延迟实测**（4B，1M 服务）：1M token 时探针批 108s vs 单次读 457s；262k 时 26s vs 40s；131k 以下探针更慢（约 1.1 倍）。
