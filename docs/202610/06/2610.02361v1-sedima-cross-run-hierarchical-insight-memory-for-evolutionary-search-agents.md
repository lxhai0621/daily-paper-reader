## 摘要
大型语言模型（LLM）驱动的进化搜索是自动化程序和算法发现的一种强大范式，但现有系统大多没有记忆：每次运行都从头探索，因此智能体会反复重新发现相同的改进，并再次遇到相同的死胡同。我们提出 SEDIMA，一种用于进化搜索智能体的持久分层洞察记忆。SEDIMA 将原始轨迹蒸馏为自然语言洞察，使用注意力加权质心按语义相似度对其进行聚类，并检索相关指导以调节未来变异，从而跨运行和问题积累可迁移知识，而非仅在单条轨迹内积累。作为一个即插即用模块，且不修改搜索算子，在评估 100 个候选的固定预算下，SEDIMA 在 AlgoTune 上平均最终性能提升 5.5%，在 ALE-Bench LITE 上提升 6.6%。在 OpenEvolve 下，SEDIMA 在五个所评估的骨干模型上达到基线最佳性能平均所需迭代次数减少 32.3%。

## Abstract
Large language model (LLM)-driven evolutionary search is a powerful paradigm for automated program and algorithm discovery, yet existing systems are largely memoryless: each run explores from scratch, so agents repeatedly rediscover the same improvements and re-encounter the same dead ends. We introduce SEDIMA, a persistent hierarchical insight memory for evolutionary search agents. SEDIMA distills raw traces into natural-language insights, clusters them by semantic similarity using attention-weighted centroids, and retrieves relevant guidance to condition future mutations, accumulating transferable knowledge across runs and problems rather than within a single trajectory. As a drop-in module that leaves the search operators unmodified, SEDIMA improves average final performance by 5.5% on AlgoTune and 6.6% on ALE-Bench LITE under a fixed budget of 100 evaluated candidates. Under OpenEvolve, SEDIMA requires 32.3% fewer iterations on average to reach baseline-best performance across the five evaluated backbones.

## 1. 核心问题与研究动机

- **背景**：LLM 已从一次性代码生成器演变为迭代式搜索算子。以 Romera-Paredes 等（2023）、AlphaEvolve（2025）为代表的系统，会反复挑选候选解、让 LLM 提出语义上有依据的修改、评估结果并保留更优变体，已推动数学发现、算法设计与启发式合成等方向的进展；OpenEvolve、ShinkaEvolve、LLM4AD 等开源框架进一步降低了使用门槛。
- **核心痛点**：这些系统**本质上没有记忆**——每次运行都从零开始，运行结束后即丢弃产生成功与失败的推理过程。这带来两方面浪费：
  - **跨运行**：面对新任务时，智能体会重新推导已经发现的修改、重新探索此前已被证明无用或中性的方向。
  - **单次运行内**：搜索轨迹不稳定，解质量随迭代剧烈波动，缺少持续信号来巩固哪些做法有效。
- **已有工作的局限**：ReEvo、LoongFlow、DeltaEvolve 等虽引入反思/摘要记忆，但记忆**局限于单条进化轨迹**，运行结束即重置；CORAL、PRISM 虽提供持久记忆，却需要把搜索循环改造为长时运行的多智能体系统。
- **整体含义**：论文提出 SEDIMA，试图以**单智能体、即插即用**的方式，为进化搜索智能体提供跨运行、跨问题的持久分层洞察记忆，在不改动搜索算子的前提下实现可迁移知识的积累。

## 2. 方法论

### 2.1 核心思想
SEDIMA 通过两个接口与底层进化搜索耦合：**评估后写入（write）** 与 **变异前读取（read）**，选择、种群管理、变异算子均保持不变。记忆采用三级层次结构，把原始轨迹逐步抽象为可复用的自然语言洞察，并按语义相似度组织与检索。

### 2.2 三级记忆结构
- **Level 1 原始轨迹**：每次评估后存储步骤索引、父/子适应度、适应度差值、事件来源、原始评估报告。不做任何解释，作为高层记忆的证据来源，保证检索到的建议可回溯到具体评估事件。
- **Level 2 蒸馏洞察**：由 LLM 将轨迹转写为紧凑的自然语言洞察，并链接回 Level 1 证据。
  - 问题的**首次评估**生成"问题级洞察"，描述主要算法/架构瓶颈；
  - 后续每次父子评估生成"变更级洞察"，结合父适应度、子适应度、适应度增量、变更摘要与评估报告，描述修改类型及其性能影响；
  - 抽象过程刻意剥离实现细节，保留缓存、剪枝、向量化、数据结构替换、减少冗余计算等可复用经验。每条洞察被嵌入向量化以便语义组织与检索。
- **Level 3 语义聚类**：按嵌入相似度分组，新洞察若与最近聚类代表相似度超过阈值则并入，否则新建聚类；聚类代表随成员增加而刷新，可选地由 LLM 生成聚类摘要以概括反复出现的优化模式。

### 2.3 关键技术细节与公式（文字说明）
- **聚类分配**：计算新洞察嵌入 $e_i$ 与各聚类代表 $c_k$ 的余弦相似度，取最大者 $k^*$；若 $\cos(e_i, c_{k^*}) \ge \tau_{\text{cluster}}$ 则加入该聚类，否则新建聚类。问题级与变更级洞察遵循同一流程。
- **注意力加权质心**（替代简单均值）：
  - 先计算成员 $i$ 的**语义中心性** $s_i$，即其与聚类内其他成员余弦相似度的平均值；
  - 再通过 softmax 转换为**非参数注意力权重** $w_i = \exp(s_i/\tau) / \sum_j \exp(s_j/\tau)$；
  - 聚类代表为 $c = \sum_i w_i e_i$。温度 $\tau$ 越低越强调语义中心、原型化的高价值洞察；$\tau \to \infty$ 时退化为均值池化；单元素聚类直接取 $c = e_1$。
- **分层检索**：给定查询嵌入 $e_q$，先按 $\cos(e_q, c_k) \ge \tau_{\text{ret}}$ 排序聚类，保留前 $K_c$ 个；再在每个聚类内按 $\cos(e_q, e_i)$ 选出前 $K_i$ 条洞察。聚类相似度与洞察相似度**分开保留**，不合并为单一分数。
- **证据与建议合成**：每条检索洞察可选地附带最多 2 条 Level 1 轨迹；合成提示接收当前查询、洞察文本、聚类相似度、洞察相似度与原始证据，返回 **3 条可操作建议**，注入 diff 或全文重写提示中。
- **预算与回退**：检索受聚类数、洞察数与提示长度上限约束，因此上下文开销不随记忆规模增长；若无聚类超过阈值，则跳过合成、沿用原始变异提示。
- **在线更新**：记忆以磁盘持久化，同一次运行内后续变异可检索本次早期写入的洞察，也可复用此前运行留下的洞察。

## 3. 实验设计

- **Benchmark**：
  - **AlgoTune**：数值编程任务，报告各任务加速比的**调和平均**；
  - **ALE-Bench LITE**：AtCoder 启发式竞赛十题子集，报告问题无关的**平均性能分**，并分别报告 5 道短赛题与 5 道长赛题结果。
- **搜索框架**：将同一份 SEDIMA 模块**不做修改**地接入 **OpenEvolve** 与 **ShinkaEvolve** 两个开源 harness，保持其选择、岛屿式种群管理、评估与变异逻辑不变。
- **评估协议**：搜索仅使用公开的本地评测分数作为适应度，最终结果来自**私有评测**且从不对搜索过程暴露；每次运行最多 100 个进化步、每步评估一个子代，按**评估候选数**而非 LLM 调用数或 token 数对齐比较。
- **对比方法**：与**匹配的无记忆基线**（Base）对比；另设**随机检索**对照、**冷启动 vs 暖启动**、**同基准 vs 跨基准记忆来源**等条件；消融覆盖记忆组件与嵌入模型。
- **骨干模型**：GPT-5.4、DeepSeek V4 Pro、Gemini 3 Pro、Qwen 3.7 Max、Qwen 3 Coder，共 5 个；同一次运行内所有 LLM 调用（变异、蒸馏、聚类摘要、建议合成）使用同一骨干，防止记忆辅助条件获得更强模型。
- **实现配置**：变异温度 0.7，蒸馏/聚类摘要/建议合成温度 0.2；嵌入统一使用 Qwen-Embedding-4B；$\tau_{\text{cluster}}=0.8$、$\tau_{\text{ret}}=0.6$、质心温度 $\tau=0.1$、$K_c=3$、$K_i=3$、检索证据上限 2500 token；聚类摘要最多使用 10 条成员洞察。
- **记忆隔离**：记忆在部署前由**不相交的问题集**构建，确保任何评估问题都不会贡献用于求解自身的记忆；评测期间记忆在线更新。

## 6. 主要结论与发现

- **性能提升**：在固定 100 个评估候选的预算下，跨 harness 平均，AlgoTune 最终性能提升 **5.5%**，ALE-Bench LITE 提升 **6.6%**；所有 5 个骨干、2 个 harness 均一致受益。
- **弱模型获益更大**：Qwen 3 Coder 在 ALE-Bench 上提升最大（OpenEvolve 下 +11.0%，ShinkaEvolve 下 +9.0%），说明持续指导对较弱的底层搜索尤其有价值。
- **收敛更快**：OpenEvolve 下达到基线最优性能所需迭代平均减少 **32.3%**（GPT-5.4 从 78 步降至 55 步，DeepSeek 76→50，Gemini 71→54，Qwen 3.7 Max 84→52，Qwen 3 Coder 90→58）。作者强调这是按进化步数衡量的加速，不能解读为总算力等比例下降。
- **跨运行与跨问题迁移有效**：同基准暖启动比冷启动提升 4.8%（AlgoTune）与 6.7%（ALE-Bench）；来自另一基准的记忆仍带来 1.8% 与 2.9% 的增益，说明优化知识可跨问题族迁移，但域内经验更有效。
- **增益来自相关性而非文本**：随机检索仅略高于无记忆（AlgoTune-20 上 1.62 vs 1.61，ALE-Bench 上 1102.6 vs 1094.3），而完整 SEDIMA 达 1.69 与 1173.6。
- **组件与嵌入的贡献**：均值质心替代注意力加权质心会小幅下降（1.67 / 1157.4），去掉语义聚类、仅用 Level 2 下降更大（1.65 / 1138.9），说明分层组织的价值；嵌入模型方面 Qwen3-Embedding-4B 最佳，8B 与 GTE-Qwen2-7B 接近，BGE-M3 与 0.6B 较弱，但所有嵌入配置均优于无记忆基线。
- **赛制差异**：短赛题增益更大（OpenEvolve 下 +8.1%，ShinkaEvolve 下 +6.9%），长赛题仍有稳定提升（+6.2% / +5.1%），表明反复出现的优化模式更易迁移。
- **定性案例**：容量设施选址任务中，SEDIMA 从 2.36× 的 CBC 中间候选出发，检索到"布尔占优模型宜用 CP-SAT、应原生暴露基数约束、需转整型系数"的跨问题经验，产出 3.99× 的 CP-SAT 候选（相对中间候选再快 1.69×）。

## 7. 优点

- **即插即用的极简接口**：仅需"评估后写入 + 变异前读取"两个钩子，同一模块不改一行搜索逻辑地接入两个独立开源 harness，工程可用性强、迁移成本低。
- **分层抽象设计合理**：Level 1 保留可追溯证据、Level 2 剥离实现细节保留可复用经验、Level 3 按语义组织，兼顾可解释性、可复用性与检索效率。
- **注意力加权质心**：用非参数 softmax 权重强调语义中心、原型化的高价值洞察，比简单均值更能让优质经验主导检索，且温度可平滑调节（高温退化为均值池化）。
- **语义检索而非谱系检索**：使知识能跨问题、跨基准族迁移，突破了以往记忆绑定单条进化轨迹的限制。
- **上下文成本受控**：检索受 $K_c$、$K_i$ 与固定 token 预算约束，提示长度不随记忆规模膨胀；无匹配时回退原始提示，风险可控。
- **实验设计中的几个亮点**：记忆用不相交问题构建、评测用私有分数、同一骨干贯穿运行、设置随机检索对照以排除"加文本即有效"的平凡解释、报告完整逐任务与逐题结果、公开全部提示模板。
- **诚实的报告风格**：明确区分"进化步数减少"与"总算力减少"，明确说明主表单次运行的局限，并在定性案例中指出 3.99× 候选的增益可能混合了求解器替换与终止策略变更两种因素。
