## ABSTRACT 

Search agents adapt their queries, yet fixed search interfaces leave candidate pro-cessing and evidence presentation outside the agent’s direct control. Our trajec-tory analysis shows that supporting passages can be retrieved yet never delivered to the agent; a same-page oracle intervention shows that changing the returned ev-idence can reduce subsequent search. We introduce Programmatic Search Agent (PSA), which makes a local executable computation over candidates the unit of a search action. PSA unifies a persistent candidate workspace, flexible primitive composition, and selective evidence presentation. It incrementally generates pro-gram cells that reuse candidates, execute dependent operations, and select what the agent inspects next. The runtime resolves specified data dependencies within each cell, while the agent adapts its search strategy across cells as new evidence arrives. We compare PSA with the Query-based Agent and Tool-based Agent on InfoSeek-Eval and BrowseComp-Plus using five policy backbones without task-specific training. All three interfaces share the search substrate, and the Tool-based Agent also shares PSA’s primitives and persistent workspace. Relative to the Query-based Agent, PSA improves macro-averaged task success by 4.00 and 7.56 percentage points on the two benchmarks, respectively; within-backbone re-ductions in final-step tokens average 28.3% and 33.9%. These results support extending agent control beyond query reformulation to the processing and presen-tation of retrieved evidence. Code will be released subject to approval. 

## 1 INTRODUCTION 

Effective search requires more than finding relevant pages: an agent must also identify and use the evidence they contain. Large language model agents interleave reasoning and retrieval, reformulat-ing queries to follow leads, resolve relations, and verify candidate answers (Jin et al., 2025b; Li et al., 2026). Yet a fixed search(query) interface leaves candidate processing outside the agent’s di-rect control: the pipeline decides which candidates to retain, how to rank them, and which passages to return. The agent can revise its query, but cannot directly revisit those processing choices. This raises our central question: Should agents only reformulate queries, or also control how retrieved candidates are processed and presented? 

Our motivating analysis shows why this distinction matters. In natural Query-based Agent tra-jectories on BrowseComp-Plus (Chen et al., 2026), supporting passages can reach the extraction stage without ever appearing in the agent’s observations; later search recovers only some of these omissions (Section 2). A controlled oracle intervention reveals the downstream consequences: for complete omissions, substituting a supporting passage from the same retrieved page improves task success and reduces subsequent search decisions in the analyzed cohort. The bottleneck can there-fore lie not only in finding evidence, but also in processing and presenting evidence already retrieved. These findings motivate giving the agent control over this part of the search process. Exposing individual search operations as tools provides finer control, but leaves open the appro-priate unit of interaction. Building on composable retrieval pipelines (Macdonald & Tonellotto, 2020), executable agent actions (Wang et al., 2024), and tool planning (Kim et al., 2024), we make a local computation over candidates the unit of a search action (Figure 1). Inspired by Perplexity’s Search as Code architecture (Perplexity, 2026), we introduce Program-matic Search Agent (PSA) . Conditioned on the task, interaction history, and a compact description of retained state, PSA incrementally generates executable program cells. Three mechanisms orga-nize this control: a persistent candidate workspace retains objects for later reuse; flexible primitive composition combines retrieval, filtering, reranking, extraction, and deduplication through variables, collection operations, and bounded control flow; and selective evidence presentation determines which results become the next observation. For example, a cell can filter and re-extract from a retained pool without another query, then return selected source notes while keeping the underly-ing candidates available. Each new observation guides the next cell, so the search strategy evolves with the evidence. A cell may contain a single operation when immediate feedback is needed, or a dependent chain when its processing logic can already be specified. We evaluate PSA against the Query-based Agent and Tool-based Agent on InfoSeek-Eval and BrowseComp-Plus with five policy backbones and no task-specific parameter training. All three interfaces share the same search substrate; the Tool-based Agent also shares PSA’s primitives and persistent candidate workspace. PSA achieves the highest task success for all five backbones on InfoSeek-Eval and four of five on BrowseComp-Plus, while using the fewest final-step tokens in ev-ery backbone–dataset comparison. Relative to the Query-based Agent, macro-averaged task success improves by 4.00 and 7.56 percentage points on the two benchmarks, respectively; within-backbone reductions in final-step tokens average 28.3% and 33.9%. PSA also improves macro-averaged suc-cess over the Tool-based Agent, which shares its primitives and persistent workspace. Our contributions are threefold: (i) an empirical analysis of evidence-delivery limitations in fixed search pipelines, using natural trajectories and a same-page oracle intervention; (ii) PSA, a search interface that unifies persistent candidate reuse, flexible primitive composition, and selective evi-dence presentation within executable cells; and (iii) a cross-model evaluation of task success and final-step tokens, complemented by controlled feedback and decision-budget experiments.

We trace supporting passages from extraction candidates to agent observations. For benchmark-annotated supporting webpages, an LLM labeling and verification procedure identifies passages that support the reference answer or a factual constraint in the question. A substantial fraction of available support never reaches the agent. Final passage-delivery re-call ranges from no verified support delivered to complete delivery across tasks (Figure 2a). At the passage level, 42.7% of verified supporting passages are never delivered, although they entered the extraction candidate set; later search recovers only a minority of the initial omissions (Figure 2b). The gap therefore extends beyond page retrieval: useful passages can be present among the candi-dates yet excluded from the returned evidence. 2.2 INTERVENING ON EVIDENCE PRESENTATION 

A same-page oracle intervention tests whether omitted evidence matters downstream. We replay saved tool calls to the first extraction event with verified support and construct paired con-tinuations when that event omits supporting passages. From the same replayed prefix, the control receives the original response; the oracle replaces a selected passage with omitted verified support from the same retrieved webpage . Both arms use the same backbone and preserve the query, re-trieved pages, pipeline, and returned item count at the intervention point. We distinguish complete omissions , where the target response returns no verified support, from partial omissions , where it returns some but omits other supporting passages. 

Repairing complete omissions improves task success and reduces subsequent search in this cohort. Oracle delivery raises judge-based task success by 16.7 percentage points and reduces mean subsequent search decisions by 64.0% for complete omissions (Figure 2c–d). The cumulative curves show more oracle continuations ending after only a few additional searches. Partial omissions show no net success gain, suggesting that changing presentation is most useful when the target response otherwise exposes no verified support. ## 3 METHOD 

Building on executable code actions (Wang et al., 2024), PSA makes local computation over can-didates the unit of search. The policy generates an executable program cell that specifies search operations, their data dependencies, and the output to inspect. The runtime executes the cell over a persistent workspace, then returns control to the policy to interpret the result and choose the next ac-tion (Figure 3). The interface separates three choices: what candidate state to retain, how to process it, and what evidence to expose for the next decision. This also separates data dependencies , which the runtime can resolve within a cell, from decisions that require new model judgment. PSA uses a fixed policy backbone without task-specific parameter updates. 3.1 PERSISTENT CANDIDATE WORKSPACE 

Candidate collections persist as addressable objects, not only as text in the interaction history. The policy can revisit, combine, or reprocess them in later cells without retrieving them again. It selects each action from the history and a compact description of this retained state. Given a question x and a fixed corpus D, its state before interaction t is

The projection σ describes available variable names, object types, and collection sizes, making stored objects addressable without exposing all of their contents. Conditioned on this state, the policy selects either a new cell or a terminal answer:

A Finish action terminates the interaction; an Execute action updates the workspace and returns an observation. Cells are generated incrementally, so each new observation can change the next search target, can-didate collection, or sequence of operations. For example, a cell can store a merged evidence pool, and the next cell can select sources from that pool for a different extraction instruction. The source objects remain available even when their full contents were not shown in the preceding observation. 3.2 FLEXIBLE PRIMITIVE COMPOSITION

Following the compositional view of retrieval (Macdonald & Tonellotto, 2020), cells specify opera-tion graphs rather than invoke a mandatory pipeline. A cell may acquire new candidates, reprocess retained candidates, or combine both, expressing dependencies and local transformations within one action. Variable assignment connects primitive outputs to later inputs, while list operations, bounded loops, and conditionals specify how collections are processed. Variables can reference results from the current cell or previous cells. Local collection operations and deduplication require no additional retrieval or model calls. ## 4 EXPERIMENTS 

We evaluate agent control over candidate processing and evidence presentation using task success and final-step tokens under shared search components. The main results compare the three inter-faces across policy backbones. A controlled feedback experiment isolates the effect of exposing ad-ditional extracted evidence, and a decision-budget sweep examines sensitivity to interaction limits. Appendix D illustrates candidate reuse, primitive composition, and selective evidence presentation in a trajectory example. Primitive-level resource accounting is reported separately in Appendix C. 4.1 EXPERIMENTAL SETUP 

Datasets and evaluation. We use the full evaluation sets of two complementary deep-search benchmarks: BrowseComp-Plus (830 questions), which pairs search-intensive questions with a fixed webpage corpus and supporting-document annotations (Chen et al., 2026), and InfoSeek-Eval (300 questions), the held-out InfoSeek split whose questions are synthesized from hierarchi-cal research trees and require resolving interdependent constraints (Xia et al., 2026). For both benchmarks, we assess answer correctness using the respective official evaluation prompt with 

GLM-5.3-Flash as the judge model, and report the resulting task success rate. We report final-step tokens as the complete input messages and output tokens of the last decision call, averaged over tasks, with the accounting convention specified in Appendix C. On BrowseComp-Plus, we additionally report Recall using its supporting-document annotations. 

Models and search substrate. We evaluate all three interfaces with five policy backbones: 

DeepSeek-V4.1-Flash , Hunyuan-4-Preview , GLM-5.3-Flash , Qwen3.8-Flash ,and GPT-5.6-Luna , using the same task set for each backbone–dataset combination. 

Hunyuan-4-Preview uses non think mode, and GPT-5.6-Luna uses low reasoning ef-fort. The policy chooses search actions and produces the final answer, while all interfaces share a frozen search substrate: Qwen3-Embedding-0.6B retrieval with an exact inner-product index, Qwen3-Reranker-0.6B reranking, and deterministic passage-level extraction with Qwen3.5-0.8B . Corpora and indices are dataset-specific; component models and primitive implementations are shared across interfaces. GLM-5.3-Flash also serves as the answer judge. Nei-ther policy nor search-component models receive task-specific parameter training. 

Interfaces and budgets. The Query-based Agent supports multiple parallel search(query) 

calls per decision, each executing the fixed funnel for one query. The Tool-based Agent exposes PSA’s five primitives and persistent alias workspace, allowing independent calls within one primary stage (retrieve, rerank, or extract) to be batched with filter and dedupe in a turn; dependent primary stages require separate turns to consume previously returned aliases. PSA expresses these depen-dencies, local collection operations, loops, and conditionals within one restricted-Python cell. All interfaces use the same runtime-enforced 20/10/10 per-call limits: retrieval returns at most 20 documents, reranking retains at most 10, and extraction selects at most 10 passages from the first 10 input candidates; smaller sets are permitted. Bench, BrowseComp-Plus, and DelegSearchBench (Wei et al., 2025; Du et al., 2026; Chen et al., 2026; Yao et al., 2026). PSA complements these advances by studying the search interface with fixed backbones and shared operators, without task-specific training. 

Candidate processing and evidence management. PyTerrier makes retrieval pipelines compos-able (Macdonald & Tonellotto, 2020), while RankGPT and pairwise ranking prompting use LLMs as ranking operators (Sun et al., 2023; Qin et al., 2024). Question’s Gambit pools and reranks searches before the agent loop (Rad et al., 2026). Beyond ranking, WebResearcher consolidates findings into reports, SLIM summarizes long search trajectories, and Argus coordinates searchers through an ev-idence graph (Qiao et al., 2025; Yen et al., 2025; Zhang et al., 2026b). AgentFold learns multi-scale folding of historical trajectories for proactive context management (Ye et al., 2025). ACE maintains an evolving strategy playbook through generation, reflection, and curation, using execution feedback to update context without changing model parameters (Zhang et al., 2026a). The Context Gather-ing Decision Process motivates explicit belief states and stopping criteria; LENS localizes evidence under a budget; AnySearch learns budget-adaptive search policies (Kausik et al., 2026; Wang et al., 2026; Sun et al., 2026). PSA focuses on agent-controlled composition of candidate-processing op-erations: retained candidates can be revisited without placing every intermediate result in context. Its motivating analysis distinguishes evidence available to the pipeline from evidence delivered to the agent. 

Tool use and programmatic search. Toolformer learns API use (Schick et al., 2023), CodeAct represents actions as executable code (Wang et al., 2024), and ReWOO and LLMCompiler separate planning from tool execution (Xu et al., 2023; Kim et al., 2024). Recursive Language Models ex-tend programmatic execution to long-context reasoning: the model treats input text as an external environment, inspects it through code, and issues recursive model calls on selected portions (Zhang et al., 2025). Separating stored context from observed context is particularly relevant to search, where candidates accumulate across queries and the evidence needed for the next decision changes as the task unfolds. Most directly related, Perplexity’s Search as Code exposes search primitives through an SDK that agents compose using generated Python, with control over intermediate re-sults (Perplexity, 2026). PSA uses local executable cells over persistent candidate collections, with new observations guiding subsequent computation. Our Tool-based Agent shares the workspace and candidate references, allowing an interface-level comparison under shared persistent state. 

## 6 CONCLUSION AND FUTURE WORK 

Programmatic Search Agent makes executable computations over persistent candidates the unit of search, giving the agent control over primitive composition and evidence presentation. Persistent candidates remain available across cells, allowing new observations to guide their reuse and process-ing. Our motivating analysis shows that fixed processing can omit useful evidence and that changing its presentation can affect downstream outcomes. Under a shared search substrate, PSA achieves the highest task success for all five backbones on InfoSeek-Eval and four of five on BrowseComp-Plus, with the lowest final-step token counts for all five on both benchmarks. PSA also improves supporting-document Recall over the Query-based Agent for all five backbones. These results sup-port extending agent control beyond query reformulation to candidate processing and evidence pre-sentation. A promising next step is to improve search-program generation through trajectory-based self-distillation. Self-Distillation Policy Optimization (SDPO) offers a relevant learning principle: use a feedback-conditioned version of the model to supervise its policy (H¨ ubotter et al., 2026). The agent could reflect on completed trajectories, identify effective candidate-processing strategies, and distill them into reusable search programs. These retrospective summaries and refined programs could serve as privileged information during training, guiding the policy to generate effective cells from the context available at each decision. Candidate programs could be replayed to check executability and task utility before being used as training targets. A teacher conditioned on the retrospective guidance could then supervise a student conditioned only on the corresponding decision-time con-text. Distilling this guidance back into the policy would aim to improve primitive composition and evidence selection without requiring retrospective information at inference time. 9Tencent Yuanbao
