## 摘要
记忆增强型智能体通常通过将检索到的技能直接注入文本提示来整合程序性知识。这种做法危险地将可读文本等同于可靠执行。为弥合这一差距，我们提出“从记忆到指南”这一新范式，将程序性记忆从被动的文本传递转变为主动的、推理时策略适配。我们通过时空合成器实例化该范式，这是一种主动策略编译器，明确管理检索到的知识应如何以及何时被应用。Composer 不将技能视为即插即用模块，而是动态地将历史知识与当前环境约束对齐（空间适配），并精确规定其适用的生命周期（时间编排）。它主动将静态记忆转化为严格受限的运行时指南——为智能体配备局部化目标和行为护栏，且无需任何参数更新。在 EngramBench 中 13 项高难度、长时程软件工程任务上的广泛评估证明了该架构的明显优势。Composer 不仅能稳健地防止上下文不匹配，还在最复杂任务上推动绝对通过率提升 7.2 个百分点，同时将主智能体的 token 使用量削减 32.2%。

## Abstract
Memory-augmented agents typically integrate procedural knowledge by injecting retrieved skills directly into text prompts. This approach dangerously equates readable text with reliable execution. To bridge this gap, we introduce From Memory to Guide, a novel paradigm that transitions procedural memory from passive text delivery to active, inference-time policy adaptation. We instantiate this paradigm through the Spatio-Temporal Composer, an active policy compiler that explicitly manages exactly how and when retrieved knowledge should be applied. Rather than treating skills as plug-and-play modules, Composer dynamically aligns historical knowledge with current environmental constraints (spatial adaptation) and precisely dictates its applicable lifecycle (temporal orchestration). It actively transforms static memories into strictly bounded Runtime Guides---equipping the agent with localized objectives and behavioral guardrails without requiring a single parameter update. Extensive evaluations on 13 demanding, long-horizon software engineering tasks in EngramBench demonstrate the clear advantages of this architecture. Composer not only robustly prevents context mismatch but drives an absolute pass-rate increase of 7.2 percentage points on the most complex tasks, while simultaneously slashing the main agent's token usage by 32.2%.

## 2. 方法论

### 2.1 核心思想

- 提出 **"From Memory to Guide"** 新范式，将长期知识存储与阶段特定的行动指导**解耦**。
- 提出 **Spatio-Temporal Composer（时空合成器）**，作为**主动策略编译器**，无需任何参数更新即可实现推理时策略适配。
- 两大互补维度：
  - **空间适配（环境适配器）**：将通用技能裁剪至目标工作区的具体配置，保证历史知识不与本地约束冲突。
  - **时间适配（生命周期编排器）**：将指导与演化中的执行阶段同步，精确规定技能何时触发、何时必须**过期**。

### 2.2 形式化建模

- **原生技能使用**（式1）：`a_t ∼ π_θ(· | p_T, h_t, D(K, p_T, h_t))`，检索机制 D 直接注入文本，迫使基础模型隐式适配。
- **运行时适配**（式2）：`g_τ = C_φ(p_T, K, o_τ, g_prev)`，`g_τ ∈ G ∪ {∅}`，其中 `∅` 表示无需新指导。
- **结构化策略接口**（式3）：`g_τ = (ℓ_τ, r_τ, b_τ, e_τ)`：
  - `ℓ_τ`：局部目标（local goal）
  - `r_τ`：状态条件化的推荐动作
  - `b_τ`：行为边界与适用前提
  - `e_τ`：终止条件
- **新执行策略**（式4）：`a_t ∼ π_θ(· | p_T, h_t, g^act_t)`，通过解耦适配（C_φ）与执行（π_θ），将隐式经验投递转变为显式的、阶段特定的执行。

### 2.3 架构组件

- **Catalog**：向编码智能体暴露 K 中可用的复用能力。
- **三类输入信息**：任务画像 `p_T`（项目目标、业务规则、接口约束、工具条件）、执行证据 `o_τ`（当前工作描述、会话上下文、验证结果、阻塞项）、前序指南 `g_prev`。
- **上下文条件化技能选择（Selector）**，返回三个结构化字段：
  - `decision`：是否生成新 Guide（结合当前目标与先前指导的结果）。
  - `skillRefs`：具体使用哪些 Skill（可多选，规则互补时）。
  - `whyNow`：记录决策原因，严格分离"用哪些经验"与"为何现在需要"。
- **空间合成**：由 `whyNow` 驱动，将抽象经验映射到具体项目实体，对齐相关规则为连贯的推荐动作 `r_τ`，同时强制执行 `p_T` 规定的行为边界 `b_τ`（如 DockChain 案例中，将通用一致性与幂等性技能转化为具体的 PostgreSQL 事务，明确 V1 与双移动输入的接口语义）。
- **时间适配**：通过 `e_τ` 与 `b_τ` 中的适用前提限定生命周期，智能体依据 **Applies When / Verification / Termination** 三类子句独立判断指导是否继续；目标完成、阶段变化或不可逾越阻塞时触发重新评估。
- **算法流程（Algorithm 1）**：维护活跃指南 `g^act_t`；当智能体请求指导时，提取证据 `o_τ`，调用 Selector 得到 `(d_τ, R_τ, w_τ)`；若决定生成则调用 Composer 得到 `g_τ` 并激活；执行一步后若当前 Guide 终止，则将其设为 `g_prev`、清空活跃 Guide 并执行**需求重入（requirement re-entry）**。请求步 τ 是执行步 t 的子集，`g_τ`（请求输出）与 `g^act_t`（当前活跃）是不同概念。

## 6. 主要结论与发现

- **主结果**：Composer 在全部 13 项 EngramBench 任务上一致优于原生 Codex + Skills。
- **最复杂子集（4 项任务，平均 8.48 小时/次）**：
  - 聚合确认通过率从 **29.9% → 37.1%**，绝对提升 **+7.2 个百分点**。
  - 主编码智能体累计 token 用量**削减 32.2%**。
  - 单项提升包括 AccessSentinel +9.4pp、CreatorRightsExchange +9.3pp。
- **全部 13 项任务**：累计确认通过数从 458 增至 563（相对提升 **22.9%**），主智能体 token 用量下降 **6.86%**。
- **超越选择与通用建议**：在 4 项任务上，Composer 累计确认通过 229 次，相对 Codex + Skills 的 173 次提升 **32.37%**；比 Selector-only（149 次）多 80 次，比 Generic Advisor（157 次）多 72 次，且在每个任务上均胜出。
- **消融结论**：
  - 动态执行证据贡献 **+7.03pp**（34.23% → 41.26%，4 任务中 3 个改善）。
  - 显式指导生命周期贡献 **+10.09pp**（31.17% → 41.26%，4 个任务全部改善）。
  - 两轴设计均为"高效且架构上必要"。
- **整体结论**：程序记忆应从被动文本投递转向推理时主动策略适配；**Memory 保留可复用策略知识，Guide 赋予其可执行形态与阶段特定作用域**。

## 7. 优点

- **范式创新性强**：明确指出现有方法"把可读文本等同于可靠执行"的隐含假设，将程序记忆重新定义为需适配的策略资源，视角清晰且具说服力。
- **双轴设计正交且可解释**：空间适配（内容对齐环境约束）与时间适配（生命周期管理）职责分明，消融实验独立验证了两者的增量价值。

- **评估器与任务覆盖的边界**：全部结论基于 EngramBench 的 13 项迁移任务，任务领域虽多样但仍属特定基准族；对开放式、需求模糊或需跨会话长期记忆的真实工业场景，外推性未知。
- **"无参数更新"的代价被淡化**：推理时适配虽免于微调，但把适配负担转移到了每次运行的推理开销上，对超长任务（单次 >12 小时）而言，重复调用编排模型的机会成本可能高于一次性微调，论文未做此权衡分析。
- **缺少与更强基线的对照**：对比集中在"原生 Skills / Selector-only / Generic Advisor / 自身消融"，未与检索增强的替代方案（如重排序检索、多轮自反思、Reflexion 类方法、计划分解式 Agent）比较，难以判断增益是否来自方法本身还是来自"额外一次模型调用"。

## 9. 启发与展望

- **"记忆即策略，而非文本"应成为记忆增强智能体的默认设计哲学**：本文最有价值之处在于把程序记忆从"检索-拼接"的工程直觉，提升为"策略适配"的形式化问题，提示后续工作应在**接口层面**（结构化 Guide）而非**提示层面**（拼接文本）解决经验复用。
- **生命周期管理是被长期忽视的维度**：显式终止条件与需求重入带来的 +10.09pp 增益说明，多数失败并非"技能不对"，而是"技能在该阶段不该用"。这提示任何长程 Agent 系统都应把**失效判定**作为一等公民设计，而非依赖模型自行察觉。
- **可探索的方向**：
  - 将 Composer 与技能**自动发现/自动精炼**闭环，形成 Skill Bank 的自演进生态；
  - 用轻量模型蒸馏 Composer 的编排能力，降低推理开销，使"时空合成"从辅助调用变为常驻能力；
  - 引入不确定性与冲突检测，在空间对齐置信度低时主动向用户澄清，而非静默裁剪；
  - 把双轴框架扩展到多智能体协作场景，处理"同一技能在不同 Agent 角色下的空间/时间作用域差异"。
- **评估范式的启示**：论文采用"隐藏测试 + 确认通过率 + token 效率 + 开发时长"的多维指标，比单一成功率更能反映真实工程价值，值得作为长程 Agent 基准的参考模板。

## 10. 一句话总结

本文指出现有记忆增强智能体"把可读文本等同于可靠执行"的根本误区，提出 **Spatio-Temporal Composer** 这一零参数更新的推理时策略编译器，通过**空间适配**（将通用技能对齐目标环境约束）与**时间适配**（为技能赋予显式生命周期与终止条件）双轴机制，把静态记忆仓库转化为动态、阶段感知的行动指南；在 EngramBench 全部 13 项任务上一致优于原生技能注入，最复杂子集确认通过率 +7.2pp、主智能体 token 消耗 -32.2%，消融验证了动态执行证据（+7.03pp）与显式生命周期（+10.09pp）均为架构上必要的设计，为程序性经验的可靠复用提供了从"投递"到"编译"的范式转变。
