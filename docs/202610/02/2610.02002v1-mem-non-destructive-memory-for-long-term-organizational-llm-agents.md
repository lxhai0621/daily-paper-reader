## 摘要
大语言模型（LLM）智能体如今已参与组织性工作，在这些工作中，许多作者会在数月间通过多份文档记录决策。由于修订后的决策是以新文档而非编辑的形式出现，回答问题时需要知道在某一给定时间点哪一版本有效。然而，大多数记忆系统会在写入时对记录进行压缩。这些方法将每份文档蒸馏为事实、笔记或图边，从而在任何问题被提出之前就已固定了可回答的范围。为解决这一问题，我们提出 Mem++，一个非破坏性记忆框架，将范式从写入时蒸馏转向读取时选择。Mem++ 完整存储每份文档及其日期与作者，且在写入时不调用任何生成模型。在读取时，它仅检索日期不晚于问题所询问时间点的文档，并融合词法与语义排序。与覆盖旧版本的系统不同，Mem++ 保留旧版本，将选择权交给作答模型。在组织类基准 OrgMemBench 上的评估表明，Mem++ 在两个作答模型上均以 8.0 至 13.1 分的优势超越最强的记忆系统基线。在使用 gpt-4.1-mini 时，它还取得了最佳总体得分，比 RAG 高出 2.6 分。此外，Mem++ 在 LoCoMo 上取得最佳平均 LLM 评判得分，在 LongMemEval-S 上排名第二，仅次于其实体图变体。基准评估代码见 https://github.com/AIDAChip-Inc/mem-plus-plus。

## Abstract
Large Language Model (LLM) agents now take part in organizational work, where many authors record decisions across documents over months. Because a revised decision arrives as a new document rather than an edit, answering a question requires knowing which version held at a given time. However, most memory systems compress the record at write time. By distilling each document into facts, notes or graph edges, these methods fix what can be answered before any question is asked. To address this, we propose Mem++, a non-destructive memory framework shifting from write-time distillation to read-time selection. Mem++ stores every document whole with its date and author, and it calls no generative model at write time. At read time, it retrieves only documents dated up to the time a question asks about and fuses lexical and semantic rankings. Unlike systems that overwrite older versions, Mem++ keeps them and leaves the choice to the answering model. Evaluations on the organizational benchmark OrgMemBench demonstrate that Mem++ surpasses the strongest memory system baseline by 8.0 to 13.1 points across two answering models. With gpt-4.1-mini, it also achieves the best overall score, 2.6 points above RAG. In addition, Mem++ achieves the best average LLM-judge score on LoCoMo and ranks second on LongMemEval-S, behind only its entity-graph variant. Code for benchmark evaluation is available at https://github.com/AIDAChip-Inc/mem-plus-plus.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景转变**：LLM 智能体已进入组织性工作场景，需要跨数月、跨团队回忆"已决定了什么"。组织记忆由多人通过邮件、工单、会议记录、共享文档等渠道独立写入，且**决策修订以"新文档"而非"编辑旧文档"的形式出现**——一份 3 月制定、6 月修订、9 月推翻的政策会以三份文档同时存在，且无人删除旧版本。
- **与对话记忆的本质差异**：对话记忆是单一叙述者、陈述累积而非竞争，后一句被读作前一句的更新；组织记忆是多作者、多权威并存，提问既可能问"现在有效的是什么"，也可能问"某历史时点有效的是什么""是谁改的""为什么改"。
- **现有系统的根本缺陷**：主流记忆系统在**写入时压缩**——Mem0 蒸馏为事实并在冲突时覆盖；Zep 存为带有效期的图边；HippoRAG/GraphRAG 存实体图；A-Mem/Nemori/LightMem 等改写为笔记或情节。这些方法在**任何问题被提出之前就已固定了可回答的范围**，文档原文（及其理由、条件、审批信息）在摄取后即不可达。
- **权衡困境**：传统 RAG 保留原文但不组织，无法区分已被取代的值与仍有效的值；结构化系统获得结构却丢失原文。两者都是在摄取时一次性解决"保留 vs 结构化"的权衡。
- **核心主张**：应将"什么重要"的决策从**写入时**推迟到**读取时**（write-time distillation → read-time selection），让文档完整保留、由作答模型在读到证据时自行判断版本关系。

## 2. 方法论

### 2.1 核心思想

- Mem++ 由**一个存储 + 两个算子**构成：`Mem++ = ⟨R, C, Φ⟩`，其中 R 为记忆存储，C 为可选的合并（consolidation）算子，Φ 为读取算子。
- 三条设计原则：
  1. 每份文档**整体存储**，并作为检索的基本单元；
  2. 结构只能作为**可选叠加层**，不能替代原文；
  3. 版本选择推迟到问题到达时，在全量记录上做选择，而非在预先剪枝的事实集上。

### 2.2 存储结构（写入路径）

- 每份文档存为一行记录：`r = ⟨x, a, t, e, σ⟩`
  - `x`：完整原文；`a`：作者；`t`：事件日期；`e = h(x)`：句向量；`σ`：状态（是否 active、被哪一行 supersede）。
- **写入时不做任何生成式模型调用**，只做一次嵌入；文本同时建全文索引（词法）与向量索引。
- 超长文档**仅在嵌入时截断**，`x` 与词法索引保留全文。
- **追加式增量更新**：新文档不与旧行交互；仅跳过空文档或在同作者范围内与 active 行完全重复的文档，因此重放同一数据流不会产生重复行。
- **时间与来源锚定**：有日期则记入 `t`；有作者则作为 tag 入索引。在 OrgMemBench 上基准不传作者字段，故 tag 实际为空。

### 2.3 检索（读取路径）

- 给定问题 `q` 与可选 as-of 日期 `θ`，先在**共享时间作用域**内取候选：
  - `Sθ = { r ∈ R | active(σr), tr ≤ θ }`；无 θ 时去掉时间条件。
  - **时间过滤先于排序**，保证 k 个槽位全部落在合法行上；无日期的行在有 as-of 问题时不可达。
- 三路检索，各自在 `Sθ` 内返回至多 C 个候选：
  - **词法路**：按覆盖密度匹配查询实词，恢复精确标识符；
  - **标签路**：匹配作者 tag（实际很少触发，作为消融评估）；
  - **语义路**：按 `h(q)` 与 `e` 的余弦相似度排序，恢复同义改写。
- **加权 RRF 融合**（无需分数归一化）：
  - `RRF(r) = Σℓ wℓ / (γ + rankℓ(r))`，γ 为平滑常数，缺席某列表则不贡献该路分数。
  - 平票按**摄取时间新近度**打破。
- **新近度保留槽（recency reserve）**：k 个结果中 k−3 个按融合分数排序，另外 **3 个留给剩余匹配行中事件日期最新的行**（无日期则回退到摄取时间）；若匹配不足则用最近摄取但未匹配的行补齐。
- 读取算子 Φ **不读取 σ 中的取代链接**，被取代行与普通 active 行同等竞争。

### 2.4 可选合并算子 C（默认关闭）

- 在两写与查询之间运行，先按余弦相似度 ≥ τ 对 current 行做贪心分组，再让 LLM 为每组打标签：
  - `y(B) ∈ {CONFLICT, RESTATEMENT, DISTINCT}`
  - **CONFLICT**：保留最新事件日期行，旧行原文与日期保留、在 σ 中标记为被取代（仍可检索）；
  - **RESTATEMENT**：生成至多 220 token 的合并行（取组内最早日期、列出全部作者），原行标记 archived 并从检索中移除——**这是全库中唯一由模型撰写文本的行**；
  - **DISTINCT**：不动；标签调用失败也不动。
- 成本约为每组至多 2 次模型调用，而非每文档 1 次。

### 2.5 证据呈现

- 按排名顺序渲染每行：**事件日期 +（若记录）作者 tag + 原文**，使模型能按撰写时间比较同一事实的不同版本。
- 对话类基准中日期与说话人已内嵌于文本，故只加排名编号。
- 设计上保持"记忆而非推理器"：**答案生成阶段不加任何自身推理步骤**。

### 2.6 图检索变体 Memg++

- 复用 Mem0g 的实体-关系图：写入时每文档 2 次 gpt-4o-mini 调用抽取三元组，查询时 1 次调用抽取实体并检索相关三元组，最多追加 5 条。
- **三元组不带日期，as-of 条件不施加于图结果**，因此有日期的问题可能被引入晚于 θ 的关系。

## 6. 主要结论与发现

- **组织记忆上显著领先**：OrgMemBench 上 Mem++ 用 gpt-4.1-mini 得 57.6，超最强基线 RAG 2.6 分；超最强"记忆系统"基线 A-Mem 达 **13.1 分**；gpt-4o-mini 下超 Zep **8.0 分**（Memg++ 与 Mem++ 分列 44.4 / 44.2，均高于 RAG 43.4）。
- **Supersession 与 Audit Replay 是主要优势区**：Supersession 两作答模型下均为最佳（67.7 / 57.0）；Audit Replay 在 gpt-4.1-mini 下达 83.0，超 Zep 6.2 分。作者归因于"保留每份原文 + 日期 + 作者"。
- **Full Context 表现最差**（总体低于 18，Supersession 与 Bi-temporal 近乎 0），说明**把全部记录放进上下文本身并不能揭示哪一版本有效**。
- **对话记忆上仍具竞争力**：LoCoMo 上取得最佳平均 LLM 分（81.5 / 77.4），Temporal Reasoning 提升最明显；LongMemEval-S 上 Memg++ 最佳（72.4 / 75.3），Mem++ 第二（72.2 / 74.7），两变体在 Knowledge Update 与 Single-session User 上包揽前二。
- **消融的核心发现**：**语义（向量）检索路是性能主引擎**（去掉后在 OrgMemBench −35.7、LongMemEval-S −76.0）；去掉词法路影响 ≤0.7 分；**合并、事实索引、实体图均无一致增益且增加成本**；整文档索引在 LoCoMo 上比事实索引高 2.6 分。
- **图收益有限**：Memg++ 在各基准总体分变化 ≤1.1 分，且跨作答模型不一致，考虑到额外 2+1 次 LLM 调用，作者认为 Mem++ 是更好的性价比选择。
- **总体论断**：保留原文、在读取时选择版本，是组织记忆的强基线范式。

## 7. 优点

- **范式层面的清晰定位**：把"保留 vs 结构化"的取舍重构为"写入时 vs 读取时"的时间点问题，论点锋利且有解释力（能直接解释对话记忆系统在 OrgMemBench 上的断崖式下跌）。
- **零生成式写入**：写入路径只做嵌入与索引，避免了摄取阶段的 LLM 幻觉、信息损失与高成本，天然可增量、可重放、可审计。
- **非破坏性与可追溯**：任何版本都不删除，σ 只做标记；时间作用域先于排序施加，保证 k 个槽位全部合法，工程细节考虑周全。
- **新近度保留槽**是一个轻量但有效的设计，用固定 3 个槽位显式保证"最新状态"类问题可答。
- **消融设计克制且有说服力**：用"去掉后大幅下降 / 加入后无增益"双向验证，明确否定自身若干复杂组件（合并、事实索引、图），学术诚实度高。
- **成本意识明确**：显式比较图检索的调用开销与收益，给出工程取舍建议。
- **公平性努力**：统一作答模型、统一判分模型、多种子多次判分、报告标准差；对标签路噪声、40K 字符截断等可能影响结论的因素主动说明。

多领域、多语言的组织语料验证；合成组织的行为模式（如文档撰写风格、冲突频率、审批链条）是否与真实企业一致，论文未做外部效度检验。作者本人也承认该基准是为本文论点量身构造的，存在"自建基准、自证优势"的潜在循环风险。
- **截断导致部分结论证据不足**：OrgMemBench 只将前 40,000 字符送入作答模型，而新近度保留槽、Memg++ 追加的三元组均落在该窗口之外。这意味着关于"新近度保留"这一特色设计的消融，实际上并未真正被评测；论文对这一点的解释也较为简略，未提供去掉截断后的对照实验。
- **Memg++ 对比不完全对等**：它在每题额外获得至多 5 条图三元组、写入与查询各多出模型调用，等于在同等 k 值下获得了更多上下文预算。作者虽已自述此点，但未做"给 Mem++ 等量额外文本"的公平对照，因此"图无增益"的结论强度有限。
- **时间与来源锚定的实现与主张不匹配**：设计上强调作者 tag 与事件日期锚定，但 OrgMemBench 基准不传作者字段，标签路实际几乎不触发，其 2.0 分差异被判为噪声。也就是说，"多作者/来源"这一组织记忆的核心维度在实验中基本未被激活，削弱了方法论中"来源可追溯"论点的实证支撑。
- **as-of 语义的边界情形处理粗放**：无日期的行在带 as-of 问题时直接不可达，而非给出"日期未知"的显式提示；Memg++ 的三元组完全不带日期，as-of 条件不施加于图结果，可能引入晚于 θ 的关系。这些在工程上可接受，但会让系统在真实语料日期缺失/不规范时出现静默失效。
- **读取算子本身不做推理**：论文强调"记忆而非推理器"，但这也意味着时间比较、版本裁决完全交给作答模型。当候选行数量大、日期格式不一致或存在多跳依赖时，性能可能显著退化；论文未给出候选行数增长下的退化曲线。
- **合并算子被否定但保留在框架内**：消融显示合并无一致增益，作者仍将其作为可选组件保留，并指出 RESTATEMENT 合并行是全库唯一由模型撰写的文本——这实际上部分回归了"写入时生成"的路线，与其核心主张存在张力，论文未充分讨论这一矛盾。
- **成本与可扩展性证据缺失**：全文未报告任何算力、token、时延或费用数据。虽然写入零生成调用是明确优势，但读取时把 k=50 个整文档（OrgMemBench 场景下截断至 40K 字符）送入作答模型，其上下文开销可能远超结构化基线，论文未做此维度的对比。
- **统计功效有限**：每个 run 判分 3 次取均值并报告标准差，方向正确，但核心基准仅 73 题、单一组织，且部分方法未跨基准运行（A-Mem/LangMem 缺 OrgMemBench，gbrain 缺对话基准），跨方法结论的可比性受限于此。
- **评测口径不完全一致**：LongMemEval-S 自评 470 题而发表基线覆盖 500 题，F1/BLEU 与 LLM-judge 混合使用，不同基准间的主指标权重不透明，读者难以横向比较绝对水平。

## 9. 启示与可改进方向

- **基准建设是当务之急**：组织记忆领域真正需要的是多组织、多语言、带真实审批链与角色权限的公开基准。当前单一合成组织难以支撑"通用范式"级别的结论，建议后续工作在真实企业语料（经脱敏）上复现。
- **补做截断对照与预算对齐实验**：应在不截断（或大幅提高窗口）条件下重跑 OrgMemBench，并给 Mem++ 与 Memg++ 配置等量上下文预算，才能真正判定图与新近度槽的边际价值。
- **激活来源维度**：在基准中恢复作者字段，让标签路、作者冲突检测、跨部门来源加权等机制获得实证机会，否则"多作者组织记忆"这一立论基础仍是悬空的。
- **量化读取成本**：报告每题的输入 token 数、检索时延、判分成本，并与 Zep/Mem0 等结构化基线做同口径对比，才能完整评估"零写入生成"换来的读取端开销是否划算。
- **加强时间语义的鲁棒性**：为无日期行提供"日期未知"降级路径，为图三元组补充时间戳或至少在 as-of 查询时屏蔽图结果，避免静默引入未来信息。
- **探索混合而非二选一**：论文的"保留 vs 结构化"二分很有力，但真实系统可能需要在两者间做分层——例如原文全量保留、结构作为可丢弃的加速索引。当前把结构定位为"可选叠加层"是正确起点，但消融显示其无增益，值得进一步研究"何种结构在何种查询分布下才有价值"。

## 10. 总体评价

Mem++ 是一篇**范式驱动、工程克制、论证诚实**的工作。其最大贡献不在于提出复杂机制，而在于把一个被忽视的时序问题——"什么重要"应在何时决定——清晰地摆上台面，并用"写入零生成、原文整体保留、读取时选择版本"这一极简设计，在组织记忆场景上取得明显且可解释的优势。Supersession 与 Audit Replay 的领先、Full Context 的失败，共同支撑了"上下文里放着全部文档 ≠ 能判断哪版有效"这一核心洞见，对当前记忆系统普遍采用的"写入即蒸馏"路线构成了有力质疑。

其局限同样清晰：核心实证建立在单一合成组织的小规模基准上，部分关键设计（新近度槽、图）因上下文截断与预算不对等而未被真正检验，来源/作者维度在实践中几乎未被激活，且全文缺乏成本数据。因此，更准确的定位是：**Mem++ 提出了一个强范式与一个可信的强基线，但"组织记忆的最优解"仍需更大规模、更真实、更公平的评测来回答**。对后续研究者而言，本文的价值既在于其方法论主张，也在于它明确划出了该领域评测基础设施的缺口。
