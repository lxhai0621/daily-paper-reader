## 摘要
智能体能够从过去的执行中学习，但让不同智能体复用并基于彼此的经验继续构建仍然具有挑战性。我们提出 EpiCon，一种用于智能体集体学习的共享多模态记忆框架，无需更新宿主模型参数。EpiCon 通过两个独立训练的 2B 模型——记忆控制器和树自组织器——将问题级记忆演化与持久经验库相连接。控制器在多次尝试中联合精炼文本指导和视觉证据，并有选择地纳入视觉记忆。自组织器分层地整合经验教训，并为新问题检索经验和规则。我们在涵盖四个多模态任务领域的十一个基准上评估 EpiCon，使用两种测试框架和多种骨干模型。即使仅进行一次求解尝试，冻结的经验库也能改进其他系统。第二种测试框架在十一个基准上将原系统的宏平均分提高了 2.6 分。在四种宿主配置下，EpiCon 相比 No Memory 将宏平均分提高了 1.7 到 4.9 分，并相对于骨干规模大小的记忆模型将记忆操作时间减少了 67% 到 74%。

## Abstract
Agents can learn from past executions, but enabling different agents to reuse and build on one another's experience remains challenging. We introduce EpiCon, a shared multimodal memory framework for agent collective learning without updating host model parameters. EpiCon links question-level memory evolution to a persistent experience bank through two independently trained 2B models: a memory controller and a tree self-organizer. The controller jointly refines textual guidance and visual evidence across attempts and selectively includes visual memory. The self-organizer consolidates lessons hierarchically and retrieves experience and rules for new problems. We evaluate EpiCon on eleven benchmarks spanning four multimodal task domains, using two harnesses and multiple backbones. A frozen bank improves other systems even with a single solving attempt. A second harness raises the original system's macro-average score by 2.6 points across eleven benchmarks. Across four host configurations, EpiCon improves macro-average scores by 1.7 to 4.9 points over No Memory and reduces memory-operation time by 67\% to 74\% relative to backbone-sized memory models.

# EpiCon 论文总结

## 1. 核心问题与整体含义

- **研究动机**：基于语言模型的多智能体系统（MAS）在推理、工具使用和协作中会产生大量关于解题流程、失败模式与证据的经验，但不同智能体/系统之间难以复用和继续积累彼此经验。
- **核心挑战**：
  - 外部记忆可让经验在不更新宿主模型参数的情况下影响后续推理，但现有工作多偏文本记忆，且跨 harness、跨 backbone 的共享与演化不足。
  - 多模态任务中，经验常依赖图像区域、图表细节或文档证据，文本指导与视觉证据需要跨尝试共同修正。
  - 经验积累后还需要组织、整合、检索，否则难以复用。
- **整体含义**：论文提出 **EpiCon（Episodic Consolidation）**，试图把“问题级多模态记忆演化”与“持久共享经验库”连接起来，实现智能体集体学习：系统可复用他人经验，也可贡献新经验，而宿主模型参数保持冻结。

## 2. 方法论：核心思想与关键技术

- **总体框架**：
  - EpiCon 由专用记忆 harness 与两个独立训练的 **2B 模型**组成：**Memory Controller Cθ** 与 **Tree Self-Organizer Sϕ**。
  - 控制器负责问题内记忆更新；自组织器负责跨问题的共享经验库维护与检索。
  - 宿主 MAS 保留自身编排与 backbone，参数不变。

- **共享多模态经验库**：
  - 维护持久经验库 \(B\)，系统可从中检索指导，也可把自身执行中的经验写入/演化库。
  - 维护更新形式为：\(B^{(k+1)} = S_\phi(B^{(k)}, U_k)\)，其中 \(U_k\) 是一批被接受的经验与修订。
  - 评估时历史经验库冻结，问题级更新仅作用于当前问题。

- **问题级文本-视觉记忆协同演化**：
  - 问题级记忆表示为 \(W_{i,t}=(M^{text}_{i,t}, M^{vis}_{i,t})\)。
  - 控制器根据上一记忆、问题与图像、最新答案和执行轨迹更新：  
    \(W_{i,t}=C^{update}_\theta(W_{i,t-1}, x_i, \hat y_{i,t}, \tau_{i,t})\)。
  - 文本记录可执行指导、适用条件与警示；视觉记忆指向源图像中的支持区域。
  - 控制器可保留、替换或删除视觉证据，并由 harness 校验与裁剪。

- **自适应视觉记忆注入**：
  - 用门控 \(g_{i,t}\in\{0,1\}\) 决定下一次输入是否包含视觉记忆。
  - 记忆输入为：若 \(g=0\)，仅文本；若 \(g=1\)，文本加视觉记忆。原始任务图像始终可用。
  - 门控只控制输入内容，不删除已存储的视觉记忆。

- **共享经验整合与复用**：
  - 经验库用树结构组织：叶节点存问题特定经验，内部节点分组、总结相关经验。
  - 自组织器可提出 **Place、Merge、Split + Lift、Consolidation** 操作。
  - 整合可把多条经验抽象为可复用规则；规则资格由支持度、失败、冲突和证据强度决定。
  - 检索先召回候选，再选择相关经验：\(R_i = S^{retrieve}_\phi(x_i, Recall(x_i,B))\)，可选择规则、具体经验或空结果。

- **训练数据构造**：
  - 教师模型：Qwen3.8-27B 生成初始记忆更新、经验与树操作；Qwen3.8-Flash-Next 选择性修订。
  - 通过回放筛选 **Repair** 与 **Compress** 变换，得到约 **25K** 记忆变换监督样本。
  - 树操作经 schema、节点引用、分区、来源等检查，保留约 **6.5K** 操作演示。
  - 两个 2B 策略用 LoRA 独立微调。

## 6. 主要结论与发现

- **共享记忆可提升单次求解**：冻结经验库即可改进其他系统，即使每个问题只求解一次。
- **跨系统经验可复用**：
  - 跨 backbone 迁移宏平均提升约 **3.2 分**。
  - 跨 harness 迁移宏平均提升约 **4.2 分**。
- **跨 harness 演化可使原贡献者受益**：
  - Codex 宏平均从 53.5 升至 55.7，DeepSeek-Harness 从 53.4 升至 56.6，提升约 **2.1–3.2 分**；摘要概括为第二套 harness 使原系统提升 **2.6 分**。
  - 但并非所有 benchmark 都提升，存在任务依赖和负迁移现象。
- **2B 紧凑模型有效且高效**：
  - 四种宿主配置下，相比 No Memory 宏平均提升 **1.7–4.9 分**。
  - 相比 backbone-sized 记忆模型，记忆操作时间降低 **67%–74%**，总时间降低约 **25%–35%**。
- **文本-视觉协同演化与自适应注入有效**：
  - 演化视觉记忆优于冻结视觉记忆；自适应注入优于始终注入，并减少执行时间。
  - 树状组织优于 flat 记忆，ParseBench 从 52.2 升至 67.3。
- **泛化到更强求解器**：Codex + GPT-5.6-Luna 上四个 benchmark 均有提升。

## 7. 优点

- **无需更新宿主模型参数**：通过外部共享多模态记忆实现集体学习，部署友好。
- **共享经验库设计完整**：同时支持复用、贡献、整合、抽象规则与检索。
- **文本与视觉证据协同演化**：不是只更新文本，而是联合修正指导与图像区域。
- **自适应视觉注入**：按需注入视觉记忆，兼顾性能与效率。
- **树状经验组织**：叶节点与内部节点分层，支持规则抽象和跨问题复用。
- **紧凑记忆模型**：两个独立 2B 模型显著降低记忆操作时间，适合作为可扩展组件。
- **实验覆盖较广**：11 个 benchmark、4 个任务域、2 个 harness、多个 backbone，并验证强 API 模型。
- **评估控制较严谨**：历史经验复用采用单次尝试，构建与评估分离，ReasonMap 按地图划分。

## 8. 不足与局限

- **跨系统经验并非总是正收益**：
  - 跨 harness 演化中，Codex 在 ParseBench 上下降，DeepSeek-Harness 在 MATH-Vision 上下降。
  - 说明共享经验可能带来任务依赖的负迁移，需要更细粒度的适用性判断。
- **部分任务提升有限或不一致**：
