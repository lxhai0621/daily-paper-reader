## 摘要
RAG 与基于检索的智能体记忆都会将检索到的内容注入 LLM 提示中，分别以文档块和召回的记忆记录的形式。同一内容可能在不同请求中、以不同的提示位置或在不同前置上下文之后重复出现，从而无法通过传统前缀缓存实现复用。我们的特征分析发现，在智能体记忆工作负载中，出现在匹配前缀之外并重复出现的记录占注入记忆 token 的 70% 以上。可组合的 KV 复用方法能够在此类情况下实现复用，但在线服务引入了一个管理问题：一个重复出现单元的 KV 状态可能尚不存在、可能已被逐出，或可能位于另一节点上。我们提出 Tessera，一种分离式服务系统，将检索作为 KV 复用的控制平面。通过在模型执行前暴露所需的上下文单元，检索使 Tessera 能够将当前需求与检索历史、KV 驻留情况和生成负载相结合，以协调缓存管理和请求路由。生成节点会并发准备本地缓存、远程缓存以及缺失的状态，同时将新计算出的状态保留在请求关键路径之外。在 RAG 和智能体记忆工作负载中，在相同请求速率下，Tessera 相比 SGLang 以及采用 EPIC 的 LMCache 将平均 TTFT 最多降低 3.6 倍，并在基线饱和的请求速率下仍能维持较低的 TTFT，同时达到与底层组合策略相当的答案质量。

## Abstract
RAG and retrieval-based agent memory both inject retrieved content into LLM prompts, as document chunks and recalled memory records, respectively. The same content can recur across requests at different prompt positions or after different preceding contexts, preventing reuse through conventional prefix caching. Our characterization finds that records recurring outside the matching prefix account for over 70% of injected memory tokens in agent-memory workloads. Composable KV-reuse methods enable reuse in such cases, but online serving introduces a management problem: a recurring unit's KV states may not yet exist, may have been evicted, or may reside on another node. We present Tessera, a disaggregated serving system that makes retrieval the control plane for KV reuse. By exposing the context units needed before model execution, retrieval allows Tessera to combine current demand with retrieval history, KV residency, and generation load to coordinate cache management and request routing. Generation nodes concurrently prepare locally cached, remotely cached, and missing states, while retaining newly computed states off the request's critical path. Across RAG and agent-memory workloads, Tessera lowers mean TTFT by up to 3.6x over SGLang and LMCache with EPIC at matched request rates, and sustains low TTFT at rates where the baselines saturate, while matching the answer quality of the underlying composition policy.

# Tessera 论文中文总结

## 1. 核心问题与整体含义

- **背景**：RAG 和基于检索的智能体记忆都会把外部内容注入 LLM 提示，分别表现为文档块和记忆记录。这些内容经常在多个请求中重复出现，但出现位置不同、前置上下文不同。
- **传统前缀缓存失效**：前缀 KV 缓存只能复用完全匹配的提示前缀。一旦同一内容出现在不同位置或不同上下文之后，其 KV 状态因位置编码和跨块因果依赖不同而无法直接复用。
- **关键量化发现**：作者对两个智能体记忆负载进行特征分析，发现匹配前缀之外重复出现的记忆记录占注入记忆 token 的 **73.9%（LoCoMo）和 76.3%（τ2）**；83.2% 的 LoCoMo 请求和 80.8% 的 τ2 请求中，至少一半注入记忆 token 属于非前缀重复。
- **在线服务管理问题**：即使可组合 KV 复用方法能在算法上复用非前缀内容，在线服务中仍面临状态可能“尚未计算、已被逐出、位于其他节点”的问题。核心挑战是把“上下文单元重复出现”转化为“实际 KV 复用”。
- **三大挑战**：
  - 缓存管理与请求路由相互耦合：保留位置影响路由，路由又影响复用价值。
  - 缓存命中与缺失必须并发执行：串行会叠加传输和预填充延迟。
  - 新状态保留与当前请求执行竞争资源，必须放在关键路径之外。
- **核心机会**：检索在模型执行前就暴露了请求所需的上下文单元，因此检索层可作为 KV 复用的控制平面，结合检索历史、KV 驻留和生成负载做决策。

## 2. 方法论

### 2.1 总体架构

Tessera 是一种分离式服务架构，将系统划分为三个独立资源池：

- **Retrieval Pool**：执行检索，识别上下文单元，维护检索历史和 KV 驻留目录，决定缓存保留与请求路由。
- **Generation Pool**：每个生成节点运行 LLM 服务引擎，在固定主机内存中维护上下文单元缓存，按计划并发准备本地命中、远程命中和缺失状态。
- **KV Pool**：提供跨生成节点的共享、RDMA 可访问 KV 存储，由 Retrieval Pool 管理驻留元数据和空间分配。

请求流程：请求先进入 Retrieval Pool，检索并识别上下文单元；Retrieval Pool 选择生成节点并生成“逐单元准备与保留计划”；生成节点从本地缓存、共享 KV Pool 或独立预填充获取状态；状态就绪后组合并继续生成；新计算状态可异步保留在本地或写回 KV Pool。

### 2.2 检索耦合的 KV 接口

- **稳定上下文单元标识**：在每个共享范围内，基于 token 序列和服务配置生成单元身份，与位置和周围上下文无关，使检索需求和缓存状态可跨请求对应。
- **逐单元计划**：计划包含两个独立字段：
  - 准备方式：使用本地状态、从共享 KV Pool 获取、或从文本计算。
  - 保留方式：本地缓存、共享 KV Pool、两者、或都不保留。
- **存储块**：单元长度不一，状态以最多 B 个 token 的固定块存储。n 个 token 的单元占 `ceil(n/B)` 个块；块可不连续，也可分布在多个内存节点。单元所有块写完后才可读。

### 2.3 检索感知缓存与路由

- **复用价值评分**：对上下文单元 u 在请求序号 t 处，评分定义为  
  `s(u,t) = w_r * f_W(u,t) + w_l * f_∞(u,t)`  
  其中 `f_W` 是最近 W 个请求中的检索次数，`f_∞` 是累计检索次数；`w_r = 1`，`w_l = 0.05`，W 由缓存容量和平均每请求单元数决定。
- **准入与逐出**：评分达到阈值 θ 才成为准入候选；默认首次检索不保留。容量不足时，按评分递增顺序考虑驻留单元，只有能释放足够空间且被逐出单元评分严格更低时才准入。逐出以整个上下文单元为单位，容量按块计算。
- **缓存感知路由**：先限制在负载不超过最低负载节点一个请求的节点集合中；再选择持有最多本地块的节点；平局时按更低负载、再轮询决定。共享缓存命中不影响排序，因为所有节点都可访问。

### 2.4 部分缓存请求执行

- **先放置后准备**：先固定提示布局并分配最终 GPU KV 槽位，本地复制、远程获取、缺失预填充可独立进行。
- **缓存命中准备**：
  - 本地命中从固定主机内存复制。
  - 远程命中通过单边 RDMA 从共享 KV Pool 获取，经有界 GPU 暂存区放入请求 KV 槽。
  - 在请求位置应用 RoPE 后标记就绪，并释放远程读租约。
- **缺失准备**：缺失单元从位置 0 独立预填充，作为内部请求加入常规 extend 批次；同一生成节点上并发请求对同一单元的缺失共享一次在途预填充；捕获 pre-RoPE 的 K/V 作为可复用形式。
- **完成预填充**：所有单元状态就绪后，按组合策略重算选定 token 范围，并处理剩余提示，最终一次 extend 完成。
- **失败回退**：缓存传输失败或超时则释放资源并从文本计算；张量并行下所有 rank 需一致决定回退。

### 2.5 非阻塞状态保留

- **保留共享条目**：缺失单元通过共享准入后，Retrieval Pool 预留块并创建带“存储 epoch”的 PENDING 条目，只有被授权写者能发布。
- **异步保留**：本地插入和共享写回独立于父请求；原型限制固定主机暂存和有界未完成写，避免无界传输资源消耗。
- **发布完整状态**：所有预留块写成功并观察到 RDMA 完成后才请求发布；Retrieval Pool 校验存储 epoch、写权限和预期块集合，再原子地将 PENDING 改为 READY。
- **保护读者与回收**：远程命中携带特定存储 epoch 的读租约，租约活跃期间块不可回收；本地准入在执行前重新验证。
- **保留失败**：失败写回不发布，取消预留；因当前请求已获得所需状态，保留失败只损失未来复用机会。
