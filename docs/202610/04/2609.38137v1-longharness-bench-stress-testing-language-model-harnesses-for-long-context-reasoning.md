## 摘要
语言模型（LM）harness 借助额外计算，使 LM 能够在长上下文上有效运行。然而，现有的长上下文评测不足以区分现代 harness，这体现为不同 harness 的准确率趋于饱和，且评测成本大体相似。本文提出一个基准，用于评估长上下文 harness 的有效性与效率。我们的任务需要多样化的检索策略，包括词法搜索与语义匹配，并结合对全局与局部上下文的策略性、自适应推理。大量上下文在语义上相关，但每一步只有一小部分有用，这既造成了具有挑战性的搜索问题，也在不同处理策略之间带来不同的准确率—成本权衡。例如，一项任务要求利用分散在文档中的证据，找出满足若干条件的每一个人；策略性地先检查最具选择性的条件，可以在验证其余条件之前缩小搜索范围。我们使用四种最先进的 harness，评估多个前沿语言模型系列。即使对于强大的模型—harness 组合，我们的基准仍然具有挑战性：最佳者在四个评测套件上达到 68% 的宏平均准确率。更重要的是，我们发现同一个底层模型在不同 harness 下可以表现出显著不同的效率。我们的结果确立了效率作为长上下文评估的重要维度，并为开发以策略性而非穷举方式处理上下文的 harness 提供了测试平台。

## Abstract
Language-model (LM) harnesses enable LMs to operate effectively over long contexts using additional compute. However, existing long-context evaluations are insufficient for distinguishing modern harnesses, reflected by saturated accuracy across harnesses and largely similar evaluation costs. In this paper, we introduce a benchmark for evaluating both the effectiveness and efficiency of long-context harnesses. Our tasks require diverse retrieval strategies, including lexical search and semantic matching, together with strategic and adaptive reasoning over global and local context. Much of the context is semantically relevant but only a small subset is useful at each step, creating both a challenging search problem and different accuracy--cost tradeoffs across processing strategies. For example, one task requires identifying every person satisfying several conditions using evidence scattered across documents; strategically checking the most selective condition first can narrow the search before verifying the remaining conditions. We evaluate multiple families of frontier language models with four state-of-the-art harnesses. Our benchmarks remain challenging even for strong model--harness combinations: the best reaches 68\% macro-average accuracy across four evaluation suites. More importantly, we find that the same underlying model can exhibit markedly different efficiency under different harnesses. Our results establish efficiency as an important axis for long-context evaluation and provide a testbed for developing harnesses that process context strategically rather than exhaustively.

# LongHarness Bench 论文总结

## 1. 核心问题与整体含义

- **研究背景**：LM harness（语言模型外部控制层，负责管理上下文、工具与交互序列）使模型能通过额外计算在长上下文上有效工作，如 OpenCode、mini-swe-agent、RLM、ReAct 等。
- **核心问题**：现有长上下文评测无法区分现代 harness，存在两个关键缺口：
  - 任务可通过简单检索或独立分段处理解决，无法检验 harness 随推理进展调整策略的能力；强模型–harness 组合在现有基准上准确率已趋饱和。
  - 仅看准确率无法反映计算成本：同一底层模型在不同 harness 下可能准确率相近，但计算量差异巨大。
- **整体含义**：需要同时衡量**有效性**与**效率**的新基准，任务应包含多样检索策略、语义易混证据、依赖中间结果的逐步推理，以及多种成本不同的解法路径。论文提出 **LongHarness Bench**，确立效率为长上下文评测的核心维度。

## 2. 方法论

### 2.1 核心思想

- 任务设计遵循五项属性：多样自适应检索需求、语义易混证据、大量推理步骤、步骤依赖型检索、多种不同成本的解法策略。
- 上下文语义高度相关，但每步仅少量信息有用，形成困难搜索问题与准确率–成本权衡。
- 所有任务答案确定性、可精确评分，支持对同一模型不同 harness 的公平比较。

### 2.2 四个任务

- **Constraint Solving Search（约束求解搜索）**
  - 约 120K tokens 文档，描述 160 人；查询含 3–5 个条件，恰好 5 人全部满足。
  - 证据分散且与近似反例混杂（如"计划坐公交"≠"有公交习惯"、"西瓜味蜡烛"≠"爱吃水果"）。
  - 高效策略：先识别满足人数最少的条件缩小候选，再逐一验证；穷举策略需检查全部 160 人 × 所有条件。

- **Equivalent Program Pair Search（等价程序对搜索）**
  - 约 100K tokens、200 个 Python 程序（改编自 APPS），需找出所有行为等价的程序对（5 对无序对，数量不公开）。
  - 正确实现被行为不同但表面相似的"变异体"包围；匹配程序可能看起来差异更大。
  - 高效策略：先推断程序用途分组，再用区分性输入排除近似变异体。

- **Program Execution Tracing（程序执行追踪）**
  - 320 条打乱的计算记录（含 ID、函数、示例调用、输出），需从 8 步查询程序中恢复最终结果并给出所引用 cell ID。
  - 前一步输出决定后一步输入，检索**步骤依赖**；存在显示样例输出相同但其他输入行为不同的易混函数。
  - 高效策略：用每步恢复的输出作为下一步搜索键，验证语义等价并复用结果，避免重复计算。

- **Outlier Memo Detection（异常备忘录检测）**
  - 700 条备忘录、2,500 条关于人/组织/对象及其关系的陈述，恰好 15 条含冲突声明，孤立看无矛盾。
  - 矛盾需通过组合多条备忘录的事实（如两跳关系推理）才能暴露；改写与近义声明使主题相似度不足为凭。
  - 高效策略：一次性阅读并构建可复用的关系表/图，复用证据检查所有派生声明。

### 2.3 数据集构建流程

- **通用原则**：先构造结构化私有数据（谓词支持集、类型化关系图、计算图、可执行程序族），由求解器/执行引擎计算金标答案与支持证据；再制造受控干扰项，渲染为公开上下文并打乱；最后用确定性规则校验答案与干扰项角色。
- **Constraint**：符号集合构造固定答案，强制一个选择性条件（≤10%）与一个宽泛条件（≥60%）。
- **Memos**：两跳规则组合边 R1(a,b)、R2(b,c) 生成派生声明，替换 15 个端点制造矛盾，保留正确端点证据。
- **Program Tracing**：采样 8 节点计算图（线性链 + 5 种非线性结构），每节点构造 20 个 cell，仅 1 个实现完整契约，其余 19 个仅在显示调用上输出相同。
- **Pairs**：APPS 问题保留 4 种结构不同的正确解，施加语法树变异体，要求变异体在测试套件上终止、至少一个测试不同且输出签名独特；金标对在相似度排序中需低于至少 12 个变异体。

## 3. 实验设计

- **Benchmark**：LongHarness Bench 四个套件（Constraint、Memos、Program、Pairs），每实例 3M token 预算（累计输入+输出）。
- **模型**：GPT-5.6-sol、Gemini 3.8 Flash、GLM-5.3、Qwen3.8-27B、Kimi-K2.6（推理努力级别不同）。
- **Harness**：直接推理（direct）、RLM、OpenCode、mini-swe-agent、ReAct（ReAct 暴露语义搜索、批量最近邻检索与文档阅读工具，嵌入模型为 BAAI/bge-m3）。
- **外部对比基准**：OOLONG-Synth（50 个 128K 样本）与 LongBench-v2（50 个 90K–128K token 子集），仅用 GPT-5.6-sol 配置对比。
- **评价指标**：任务级精确准确率（Program 需同时答对最终结果与引用 cell；Memos 需精确 15 个 ID；Constraint 需精确人员 ID 集合；Pairs 需精确 5 对无序对）；成本按 API 费率折算 USD/实例；同时报告平均输入/输出 token。
- **对比方法**：各模型 × 各 harness 的组合，以及相对直接推理的准确率变化与成本倍数。

## 6. 主要结论与发现

- **基准仍具挑战性**：最佳组合 GPT-5.6-sol + mini-swe-agent 仅达 68% 宏平均准确率；最强非 GPT 组合 GLM-5.3 + mini-swe-agent 为 42.5%；Kimi-K2.6 从未超过 1.5%。最佳任务准确率从 Outlier Memo Detection 的 100% 到 Equivalent Program Pair Search 的 52%，无配置在四个任务上全面领先。
- **相似准确率可有截然不同的成本**：Program Execution Tracing 上 GPT-5.6-sol 直接推理（94%，$0.648）与 OpenCode（96%，$1.37）；Constraint 上直接推理（58%，$0.690）优于 OpenCode（56%，$1.72）。Outlier Memo Detection 上 RLM 与 mini-swe-agent 准确率相近，但成本相差 **12.4×**（$7.23 vs $0.583）。
- **Harness 收益依赖模型与任务**：对 GPT-5.6-sol，OpenCode 在 Program 上略有提升（94%→96%），但在 Memos 上从 44% 降至 10%、Pairs 上从 44% 降至 0%；mini-swe-agent 提升 Memos 至 100% 却把 Constraint 从 58% 降至 42%。
- **较弱模型从 harness 获益更多**：Qwen3.8-27B 从 0%→38.5%，GLM-5.3 从 9.5%→42.5%，Gemini 3.8 Flash 从 10%→25%，而 GPT-5.6-sol 仅从 60%→68%。
- **更多推理不保证成功**：GPT-5.6-sol + RLM 在 Pairs 上以 $7.86 仅得 2%，远低于直接推理（44%，$0.780）。
- **机制差异**：文件与 shell 代理（OpenCode、mini-swe-agent）适合定向检索与脚本化验证；RLM 的程序化分解在 Memos 上有效但代价高，在 Pairs 上因候选空间未充分缩小而失败；ReAct 的嵌入检索在 Pairs 上有效（44%→52%），但在需跨记录组合证据的 Memos 上仅得 6%。
- **与现有基准对比**：OOLONG-Synth 上所有 harness 都优于直接推理（70–86% vs 64%），LongBench-v2 上所有配置集中在 60–68% 窄区间；而 LongHarness 上每个 harness 都有得有失，覆盖四种准确率–成本区域，更能揭示 harness 差异。

## 7. 优点

- **双轴评测设计**：同时测量准确率与计算成本（token 与美元），把效率提升为长上下文评测的一等维度。
- **任务设计精巧**：四项任务分别覆盖约束求解、程序等价、执行追踪、矛盾检测，均要求词法与语义检索结合、步骤依赖检索、跨证据组合推理。
- **支持多种解法与成本区分**：每项任务都设计了可选择性缩小搜索空间的高效路径，使不同策略的成本差异可被量化。
- **构建严谨**：先有私有结构化规范与金标求解器，再渲染公开上下文；确定性校验器独立复核答案与干扰项角色，降低标注噪声。
- **干扰项受控**：近似反例、变异体、近义改写、端点替换等设计，使表面相似度或词法匹配不足以求解。
- **对比充分**：覆盖 5 个模型家族、4 种 harness 类型，并与两个主流长上下文基准横向对比，结论具有较强说服力。
- **失败模式分析深入**：不仅报告数字，还分析了证据复用、候选验证、预算控制等具体失败机制。
