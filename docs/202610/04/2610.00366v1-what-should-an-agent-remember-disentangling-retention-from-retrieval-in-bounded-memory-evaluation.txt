# What Should an Agent Remember? Disentangling Retention from Retrieval in Bounded-Memory Evaluation

## Abstract 

A persistent agent must decide both what to retain as information arrives and what to surface once a query appears, different decisions made at different times with different information, yet memory evaluations can end up comparing methods that differ on both at once. We build a streaming-recall environment crossing a retention rule with a selection rule, scoring the same 300 seeded episodes in every cell. Holding access fixed, query-aware selection buys +15 .5 percentage points (pp) of required-fact recall (95% CI [+12 .8, +18 .2] ), whereas the mixed-cell contrast used by an earlier version of this evaluation reports +68 .7 pp [+65 .2, +72 .0] ; the extra +53 .2 pp is access. With query-aware, dense, or oracle selection, recall in every bounded retention condition then exactly equals its retention rate: a 768-dimensional dense retriever moves it by +0 .00 pp [+0 .00 , +0 .00] , in the bounded recency-retention condition all 319 observed retrieval failures are evictions rather than ranking errors, and recall there falls to 0% as the target recedes into the past. In that synthetic evaluation, incidental benchmark properties can create substantial spurious advantages; rerunning the identical grid on SQuAD reproduces the ceiling in all 25 cells, though there the dense retriever does beat the lexical one, so that particular null was a property of our generator. Bounded-memory evaluations should hold access fixed and report retention and selection separately. 

## 1 Introduction 

Long-running agents can accumulate more observations than they can keep available at once, so some must be dropped. This makes memory a control problem: given a budget of K items, which observations remain available later? Existing memory architectures each embed an assumption about what is worth keeping: that recent, repeated, or query-resembling things matter. Evaluating those assumptions is harder than it looks, because an agent makes two decisions. A 

retention decision happens online, as each observation arrives, and is necessarily query-independent :the future query has not been seen. A selection decision happens at query time and can be query-aware. A method that appears to win may be winning at either stage, or may simply have been granted access to material its competitors discarded. One accuracy number per method cannot distinguish these. This is easy to introduce accidentally. Auditing an earlier version of this evaluation, which compared five memory heuristics, we found that its strongest methods re-ranked the complete history at query time while its weakest saw only a bounded buffer; that a template defect left its queries with no token identifying the fact asked about; and that its distractors carried a literal marker any overlap scorer

Our contributions: • A streaming-recall benchmark that crosses retention rule × selection rule , evaluates every cell on the same seeded episodes, and reports recall alongside the retention rate that upper-bounds it (§3). • A decomposition showing that most of the apparent advantage of query-aware memory in the mixed-cell comparison is attributable to history access rather than query awareness, with the remainder capped by retention (§4.1). • Evidence that query-aware retrieval gives no protection against delay-induced eviction; that the retention ceiling is selection-independent, verified against a dense retriever rather than assumed; and that incidental benchmark properties can create spurious apparent gains, with the stronger retriever amplifying one such artifact (§4.2, §4.3); and that the ceiling result reproduces on real SQuAD text while the dense-versus-lexical null does not (§5). 

## 2 Related work 

Agent memory systems score stored items by a mixture of signals: Park et al. [2023] retrieve from a memory stream by weighted recency, importance, and relevance; Packer et al. [2023] page between a bounded context and external storage; Zhong et al. [2024] add a forgetting schedule. These systems couple several memory-management decisions within end-to-end evaluations, which is exactly the regime in which retention and retrieval effects become hard to separate. The selection half is classical retrieval, where lexical scorers such as BM25 [Robertson and Zaragoza, 2009] remain strong against dense retrievers [Karpukhin et al., 2020] and RAG [Lewis et al., 2020] conditions generation on retrieved evidence. But that literature assumes a fixed corpus, with nothing thrown away; bounded memory breaks that assumption. Relatedly, Liu et al. [2024] show that where evidence sits in a context changes whether a model uses it: another case in which an apparent capability difference turns out to be a property of what was made available to the model. We contribute to the evaluation layer rather than proposing a memory architecture; our object of study is what a bounded-memory benchmark measures. 

## 3 A factorial streaming-recall benchmark 

Environment. An episode is a stream of 10 facts followed by 2 queries. Every fact has the identical surface form "The slot is value ." ; slots are drawn without replacement within an episode, so a query naming a slot identifies exactly one fact. A fraction d (default 0.3) of facts are distractors, drawn from a disjoint slot vocabulary but written in the same form, so distractors are not lexically marked. Each query targets a uniformly sampled non-distractor fact. 

The two factors. A retention rule consumes the stream online under capacity K and is never shown the query: RECENCY (keep the last K), RANDOM (admit with p=0 .5, FIFO evict), FREQUENCY (evict the item whose tokens are rarest so far, FIFO on ties), TYPE -ORACLE (admit only non-distractors; this reads the generator’s ground-truth label and is therefore privileged , not implementable by an agent), and UNBOUNDED (keep everything; the no-forgetting reference). A selection rule then ranks the survivors and exposes the top k=3 : RECENCY , RANDOM , QUERY (Jaccard overlap between query and fact tokens, recency tie-break), DENSE (cosine similarity between MPNet sentence embeddings 2), and ORACLE (surface the target if present). We call the Jaccard rule query-similarity and never an embedding method; DENSE is the only rule here that uses learned vectors. 

Query informativeness. We also vary whether the query carries usable signal. An informative

Metric and statistics. We report required-fact recall : the fraction of queries whose target fact appears among the k exposed items. We report recall rather than answer accuracy because it isolates the memory pipeline; §4.4 then puts a language model at the end and shows recall predicts answer correctness up to a near-constant factor. Alongside recall we report the retention rate , the fraction of queries whose target survived retention, which upper-bounds recall for any selection rule. All cells use the same 300 seeded episodes (600 queries); confidence intervals are percentile bootstrap over 2,000 resamples of episodes , since two queries from one stream are not independent. Seed, configuration, and per-query records are saved with the results. 

## 4 Results 

4.1 RQ1: how much of the advantage is query awareness? 

Table 1 gives the full grid under informative queries. Reading it by column isolates selection; by row, retention. Two things follow. First, in every bounded row the QUERY , DENSE and ORACLE columns are exactly equal to the retention rate ( 46 .8, 46 .8, 45 .8, 70 .3): selection saturates in this environment , and every remaining failure is a retention failure. We test that with a far stronger scorer rather than asserting it: a 768-dimensional MPNet retriever changes recall by +0 .00 pp [+0 .00 , +0 .00] against both the lexical rule and an oracle selector, under bounded and unbounded retention alike, and across all 50 cells no selection rule exceeded its row’s retention rate. Saturation is a property of this generator, not a general one: §5 shows that on real text a dense retriever does improve selection, and yet still cannot pass the retention ceiling. The ceiling is the general claim; saturation is not. A better retriever is not merely unhelpful; it is arithmetically incapable of helping, the exposed set being a subset of what retention kept. Raising density from 0.1 to 0.7 leaves recency retention flat ( 47 .3 → 50 .5)but lifts type-oracle retention from 54 .0 to 100 .0 (Table 4), because discarding a larger share of the stream leaves proportionally more room for targets. Raising density therefore benefits the privileged type-oracle, because more of the stream can be filtered before capacity is consumed, while recency retention is left roughly unchanged. The rule that gains is the one that needs the answer key to do it.

4.4 RQ4: does recall predict answer correctness? 

Recall is a retrieval-side proxy. To test whether it tracks task success we place FLAN-T5-large at the end of the pipeline (greedy decoding, normalized exact match, 300 queries from the same episode set) and score its answers (Table 7). With no memory the model scores 0.0% , so the task genuinely requires memory. A bounded agent (K=5 , query selection) recalls the target for 47 .3% of queries and answers 36 .3% correctly; full context scores 73 .7% and the required fact alone 74 .7% , so nine irrelevant facts cost 1.0 pp and the bottleneck is memory, not context noise. Accuracy conditioned on the fact having reached the model spans only 70 .7–74 .7% , so under these tested conditions answer accuracy is recall scaled by a roughly constant factor, which is what licenses recall as the primary metric. The bounded agent’s 

63 .7% failure rate splits into 52 .7 pp where the fact never arrived and 12 .7 pp where it arrived and the model erred anyway: five in six failures are memory failures. 

4.5 RQ5: what explains the remaining failures? 

We classify every failure of the bounded agent (recency retention, query selection) into memory-specific categories: eviction, where the target never survived retention; displacement, where it was retained but pushed out of the top-k; and similarity confusion, where a distractor outscores the target under the query scorer itself. All 319 failures are evictions. Displacement and similarity confusion account for zero. Swapping in a query-independent selector on the same streams adds 93 displacement failures, so query awareness removes the selection-stage failure mode outright while leaving the dominant one untouched. ## 5 Does this survive real text? 

Everything so far runs on a generator we wrote, which is the obvious objection. We therefore rerun the identical grid on SQuAD v1.1 dev [Rajpurkar et al., 2016], changing only where episodes come from. For each of 300 questions we split the target paragraph into sentences, mark the sentence containing the answer span as the target, and pad the stream to ten sentences with sentences drawn from unrelated paragraphs. The distractors are ordinary English on other topics, so nothing marks them, and the query is the real SQuAD question rather than a template. The retention rules, selection rules, metric and bootstrap are imported and called unmodified. The central claim survives, and one secondary claim does not. The retention ceiling holds in all 25 cells: no selection rule anywhere exceeds its row’s retention rate (Table 8). Under a bounded recency buffer the dense retriever again lands exactly on the ceiling, +0 .00 pp [+0 .00 , +0 .00] 

against an oracle selector, and unbounded access is worth +44 .3 pp [+38 .3, +50 .3] to it. Query awareness at matched access is worth +20 .3 pp [+15 .7, +25 .0] , more than the +15 .5 pp we measured synthetically, which is what one would expect once queries stop being templates. What does not transfer is the dense-versus-lexical null. On real text the dense retriever genuinely beats Jaccard, by +6 .0 pp [+3 .0, +9 .3] with unbounded retention and +1 .7 pp [+0 .3, +3 .3] under a bounded buffer. Our synthetic finding that the two are exactly equivalent was therefore a property of that generator, where an informative query token-matches its target exactly, and not a general fact. The dense-versus-lexical equivalence observed synthetically therefore does not generalize to natural text: a better retriever does help at the selection stage there. It still cannot exceed what retention kept, which is the claim the paper actually makes. 

## 6 Limitations 

The main environment is synthetic, single-episode and small (10 facts, 2 queries), built so selection is exactly solvable under informative queries, hence the 100% ceilings; §5 rebuts the strongest form of that objection but both environments are still single-turn recall rather than multi-session agent memory. That isolates retention, but means our numbers bound what selection contributes rather than estimating it on a realistic corpus; with paraphrase, partial overlap, or multi-hop queries the matched-access query-awareness effect would likely be larger than the +15 .5 pp we measure. The main grid is retrieval-side, and the answer-accuracy check of §4.4 uses a single small model with one prompt and greedy decoding, so it establishes that recall tracks answer correctness in this setting rather than characterizing how any particular agent would behave. ## 7 Conclusion 

Retention and selection are different decisions, and one accuracy number cannot tell them apart. Hold access fixed across compared methods, and report the retention rate beside every recall number. When the required memory has been evicted a better retriever cannot recover it: retrieval performance is upper-bounded by retention.
