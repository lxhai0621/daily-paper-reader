## 摘要
基于大语言模型（LLM）的编程智能体依赖于“技能”（skills），即扩展智能体能力的预封装指令集，然而注入上下文窗口的每一 token 技能内容都会产生经济成本并导致注意力稀释。为了解这一问题的严重性，我们对 55,315 个公开可用的技能进行了大规模实证研究，并发现了系统性低效：26.4% 的技能完全缺失路由描述，超过 60% 的主体内容是不可执行的，且参考文件在每次调用时可能注入数万个 token。受这些发现启发，我们提出了 SkillReducer，一个两阶段优化框架。第一阶段通过压缩冗长的描述并利用对抗性增量调试（adversarial delta debugging）生成缺失的描述来优化路由层。第二阶段通过分类驱动的重构和渐进式披露（progressive disclosure）重组技能主体，将可执行的核心规则与按需加载的补充内容分离，并通过忠实度检查和自我修正反馈循环进行验证。在 600 个技能和 SkillsBench 基准测试上的评估结果显示，SkillReducer 实现了 48% 的描述压缩和 39% 的主体压缩，同时将功能质量提升了 2.8%，揭示了“少即是多”的效应，即移除非必要内容可减少上下文窗口中的干扰。这些优势在来自四个家族的五个模型中均可迁移，平均保留率为 0.965，并能泛化到独立的智能体框架。

## Abstract
LLM-based coding agents rely on \emph{skills}, pre-packaged instruction sets that extend agent capabilities, yet every token of skill content injected into the context window incurs both monetary cost and attention dilution. To understand the severity of this problem, we conduct a large-scale empirical study of 55,315 publicly available skills and find systemic inefficiencies: 26.4\% lack routing descriptions entirely, over 60\% of body content is non-actionable, and reference files can inject tens of thousands of tokens per invocation. Motivated by these findings, we present \textsc{SkillReducer}, a two-stage optimization framework. Stage~1 optimizes the routing layer by compressing verbose descriptions and generating missing ones via adversarial delta debugging. Stage~2 restructures skill bodies through taxonomy-driven classification and progressive disclosure, separating actionable core rules from supplementary content loaded on demand, validated by faithfulness checks and a self-correcting feedback loop. Evaluated on 600 skills and the SkillsBench benchmark, \textsc{SkillReducer} achieves 48\% description compression and 39\% body compression while improving functional quality by 2.8\%, revealing a \emph{less-is-more} effect where removing non-essential content reduces distraction in the context window. These benefits transfer across five models from four families with a mean retention of 0.965, and generalize to an independent agent framework.

### 1. 核心问题与整体含义（研究动机和背景）
论文关注的是 **LLM 编程智能体（Agent）中“技能”（Skills）的效率问题**。技能是预封装的指令集（如 Markdown 文件），用于扩展智能体的能力。
*   **研究动机**：作者发现当前的技能生态存在严重的“软件膨胀”现象。注入上下文窗口的技能 token 不仅增加了 API 调用成本，还会稀释模型的注意力（导致性能下降）。
*   **实证研究**：通过对 55,315 个公开技能的大规模分析，发现 26.4% 的技能缺失路由描述，超过 60% 的主体内容是不可执行的背景或示例，且参考文件可能一次性注入数万个 token。
*   **核心目标**：在保证（甚至提升）智能体功能质量的前提下，最大限度地减少技能占用的 token 数量。

### 2. 方法论：SkillReducer 框架
SkillReducer 是一个两阶段的优化框架，借鉴了软件工程中的“去膨胀”（Debloating）和“增量调试”思想：

*   **第一阶段：路由层优化（Stage 1: Routing Layer Optimization）**
    *   **目标**：压缩冗长的描述，补全缺失的描述。
    *   **关键技术**：采用**增量调试（Delta Debugging, DDMIN）**算法。通过一个对抗性构造的预言机（Oracle）模拟路由决策，将描述拆分为语义子句，递归剔除不影响路由正确性的部分，直到获得“1-最小化”描述。
    *   **验证**：通过真实环境（如 Claude Code CLI）进行触发测试，若压缩过度则进行选择性恢复。

*   **第二阶段：主体重构与渐进式披露（Stage 2: Body Restructuring）**
    *   **核心思想**：将技能主体从“单体架构”转变为“分层架构”。
    *   **分类驱动压缩**：利用 LLM 将内容分类为：核心规则（Core Rule）、背景（Background）、示例（Example）、模板（Template）和冗余。
    *   **渐进式披露（Progressive Disclosure）**：仅将核心规则保留在默认加载的上下文中，而将示例、背景等转化为“按需加载”的模块（通过 `read_file` 工具调用）。
    *   **反馈循环**：包含忠实度检查（Gate 1）和基于任务的评估（Gate 2）。如果压缩导致任务失败，系统会自动将必要的非核心内容“提拔”回核心规则中。

*   **实验规模**：评估了 600 个技能，生成并执行了 3,000 个评估任务，涵盖了 5 个模型家族和 1 个独立智能体框架（OpenCode）。

### 6. 主要结论与发现
*   **高效压缩**：实现了 48% 的描述压缩和 39% 的主体压缩，端到端输入 token 节省约 26.8%。
*   **“少即是多”效应（Less-is-More）**：压缩后的技能在功能质量上反而提升了 **2.8%**。这证明了移除非必要内容能显著减少模型在长上下文中的注意力分散。
*   **鲁棒性**：在 SkillsBench 上实现了 100% 的功能保留，跨模型平均保留率为 0.965。
*   **技能过时性**：发现约 10.7% 的技能在当前强模型下已不再被触发，暗示了技能生命周期管理的重要性。

### 7. 优点
*   **系统性强**：将经典的软件工程方法（增量调试、程序切片）成功应用于 LLM 提示词优化。
*   **结构化处理**：不同于传统的 token 级剪枝，SkillReducer 理解技能的内部结构（规则 vs 示例），保证了操作指令的完整性。
*   **闭环优化**：引入了自我修正的反馈循环，能够根据实际任务表现动态调整压缩力度。

### 8. 不足与局限
*   **分类依赖性**：高度依赖 LLM 对内容类型的判断。如果作者将规则隐含在示例中（Example-as-specification），分类器可能会误将其移至按需加载模块，导致初次执行失败。
*   **评估覆盖面**：虽然使用了 600 个技能，但主要针对编程和技术文档类技能，在创意写作或纯常识类技能上的表现尚未验证。
*   **工具调用开销**：虽然减少了初始 token，但如果智能体频繁调用 `read_file` 读取参考资料，可能会增加推理轮数和延迟。
