## 摘要
随着人工智能智能体（AI agents）的发展，学术界正迅速从单一的大型语言模型（LLMs）转向多智能体系统（MAS），以克服自动化研究中的认知瓶颈。然而，针对这些自主智能体的最优多智能体协作框架在很大程度上仍未得到探索。在本文中，我们提出了一项系统的实证研究，旨在调查不同多智能体结构在自动化机器学习优化中的比较效能。利用一个配备了 Git 工作树隔离和显式全局内存的、受严格控制的基于执行的测试平台，我们将单智能体基准与两种多智能体范式进行了对比：子智能体架构（具有事后整合的并行探索）和智能体团队架构（具有执行前交接的专家协作）。通过在严格固定的计算时间预算下评估这些系统，我们的研究结果揭示了运行稳定性与理论深思熟虑之间的一种根本性权衡。子智能体模式表现为一个具有高韧性、高吞吐量的搜索引擎，最适合在严格的时间限制下进行广泛且浅层的优化。相反，智能体团队拓扑结构由于多作者代码生成而表现出更高的运行脆弱性，但在计算预算充足的情况下，能够实现复杂架构重构所需的深度理论对齐。这些实证见解为设计未来的自动研究系统提供了可操作的指导方针，提倡采用能够根据实时任务复杂度调整其协作结构的动态路由架构。

## Abstract
As AI agents evolve, the community is rapidly shifting from single Large Language Models (LLMs) to Multi-Agent Systems (MAS) to overcome cognitive bottlenecks in automated research. However, the optimal multi-agent coordination framework for these autonomous agents remains largely unexplored. In this paper, we present a systematic empirical study investigating the comparative efficacy of distinct multi-agent structures for automated machine learning optimization. Utilizing a rigorously controlled, execution-based testbed equipped with Git worktree isolation and explicit global memory, we benchmark a single-agent baseline against two multi-agent paradigms: a subagent architecture (parallel exploration with post-hoc consolidation) and an agent team architecture (experts with pre-execution handoffs). By evaluating these systems under strictly fixed computational time budgets, our findings reveal a fundamental trade-off between operational stability and theoretical deliberation. The subagent mode functions as a highly resilient, high-throughput search engine optimal for broad, shallow optimizations under strict time constraints. Conversely, the agent team topology exhibits higher operational fragility due to multi-author code generation but achieves the deep theoretical alignment necessary for complex architectural refactoring given extended compute budgets. These empirical insights provide actionable guidelines for designing future autoresearch systems, advocating for dynamically routed architectures that adapt their collaborative structures to real-time task complexity.

*   **研究背景**：随着 AI 智能体从单模型向多智能体演进，虽然已有如 AI Scientist 等端到端系统，但关于“最优协作框架”的系统性对比研究仍然匮乏。本研究旨在填补这一空白，探索不同协作模式在固定计算预算下的表现。

### 2. 方法论
论文构建了一个严谨的执行测试平台，并对比了三种架构：
*   **核心技术细节**：
    *   **Git 工作树隔离**：为每个智能体分配独立的隔离环境，防止状态污染。
    *   **结构化补丁契约**：采用“搜索/替换”模式而非重写全文件，确保代码修改的精确性。
    *   **显式全局内存**：通过共享文档记录成功经验和失败教训，缓解灾难性遗忘。
*   **协作拓扑结构**：
    *   **子智能体架构（Subagents）**：采用“并行探索 + 事后整合”模式。多个 Worker 独立生成补丁并训练，由 Coordinator 尝试合并表现优异的补丁。
    *   **智能体团队架构（Agent Teams）**：采用“专家分工 + 预执行协作”模式。包含架构专家、优化专家和效率专家，通过顺序链式沟通（Group Chat）共同修改代码，并配备一名工程师智能体进行故障排除。

### 3. 实验设计
*   **任务场景**：迭代优化 `train.py` 脚本，目标是最小化验证集的每字节比特数（`val_bpb`）。
*   **Benchmark**：以 Karpathy 的 `autoresearch` 项目为基础，模拟真实的神经网络超参数和架构搜索。
*   **对比方法**：
    1.  **单智能体基准**：线性尝试-错误循环。
    2.  **子智能体模式**：强调搜索的广度和吞吐量。
    3.  **智能体团队模式**：强调深度协作和角色专业化。
*   **评估指标**：`val_bpb` 的降低程度、提案成功率、预检失败率及运行崩溃率。

### 4. 资源与算力
*   **硬件环境**：实验在 **NVIDIA RTX 3090** GPU 上运行（注：原项目基于 H100，作者进行了适配）。
*   **模型使用**：采用了 **GLM-4.7** 和 **GLM-4.6v**。

    *   团队模式：GLM-4.6v 作专家，GLM-4.7 作工程师。
*   **时间预算**：设置了 **300秒** 和 **600秒** 两种严格的墙钟时间限制。

*   **充分性与公平性**：

    *   引入了预检（Preflight）机制拦截语法错误，确保计算预算消耗在有效的训练上。
    *   对比了不同时间预算下的表现，揭示了架构性能随资源变化的趋势。
    *   **评价**：实验设计较为客观、公平，但在任务多样性上（仅限于一个 ML 优化任务）略显单一。

### 6. 主要结论与发现
*   **稳定性与深度的权衡**：
    *   **子智能体模式**：是极佳的“搜索引擎”，韧性高、吞吐量大，适合在短时间内进行广泛但浅层的优化（如单纯调整超参数）。
    *   **智能体团队模式**：具有“理论深度”，虽然由于多作者协作导致代码更易崩溃（脆弱性高），但能实现复杂的架构重构（如同时修改注意力模式、调度策略和嵌入大小），在长预算下潜力更大。
*   **搜索行为差异**：子智能体易陷入局部最优（如反复调整同一个参数），而团队模式能提出更具创造性和综合性的修改方案。

### 7. 优点
*   **工程严谨性**：引入 Git Worktree 和结构化补丁契约，解决了自主智能体评估中常见的环境污染和代码破坏问题。
*   **实证导向**：不只关注最终指标，还深入分析了不同拓扑结构导致的失败模式（如预检失败、训练崩溃等）。
*   **可操作性建议**：提出了“动态路由架构”的设想，即根据任务复杂度动态切换协作模式。

### 8. 不足与局限
*   **任务覆盖面有限**：实验仅基于一个特定的机器学习训练任务，其结论在其他科学发现领域（如化学、生物）的普适性有待验证。
*   **模型依赖性**：实验结果可能受到 GLM 系列模型特定能力的影响，若更换为 GPT-4o 或 Claude 3.5，协作动态可能发生变化。
