## 摘要
能够预测用户需求并自主执行任务的主动式智能体作为数字助手具有巨大潜力，但缺乏真实的交互用户模拟框架阻碍了其发展。现有方法将应用程序建模为扁平的工具调用 API，未能捕捉到数字环境中用户交互的有状态和顺序特性，使得真实的用户模拟变得不可行。我们推出了主动式智能体研究环境（Pare），这是一个用于在数字环境中构建和评估主动式智能体的框架。Pare 将应用程序建模为具有有状态导航和状态依赖动作空间的有限状态机，供用户模拟器使用，从而实现了活跃用户模拟。在此基础上，我们提出了 Pare-Bench，这是一个包含 143 个多样化任务的基准测试，涵盖了通信、生产力、日程安排和生活方式类应用，旨在测试上下文观察、目标推理、干预时机以及多应用编排能力。

## Abstract
Proactive agents that anticipate user needs and autonomously execute tasks hold great promise as digital assistants, yet the lack of realistic user simulation frameworks hinders their development. Existing approaches model apps as flat tool-calling APIs, failing to capture the stateful and sequential nature of user interaction in digital environments and making realistic user simulation infeasible. We introduce Proactive Agent Research Environment (Pare), a framework for building and evaluating proactive agents in digital environments. Pare models applications as finite state machines with stateful navigation and state-dependent action space for the user simulator, enabling active user simulation. Building on this foundation, we present Pare-Bench, a benchmark of 143 diverse tasks spanning communication, productivity, scheduling, and lifestyle apps, designed to test context observation, goal inference, intervention timing, and multi-app orchestration.

### 论文总结：Proactive Agent Research Environment (Pare)

#### 1. 核心问题与整体含义（研究动机和背景）
当前的语言模型（LM）智能体大多处于“被动响应”模式，即仅在接收到用户明确指令后才执行任务。然而，理想的数字助手应当是“主动式”的，能够通过观察用户行为和环境事件（如收到邮件、日历提醒）来推断用户意图并预先提供帮助。
**研究动机：** 现有的评估框架通常将应用程序简化为扁平的 API 调用，忽略了真实用户在数字界面中必须经历的有状态、序列化导航过程（如点击、翻页、填充表单）。这种简化导致无法真实模拟用户与助手的动态交互，进而难以准确评估主动式助手的有效性、干预时机及对用户自主权的尊重。

#### 2. 方法论
Pare 框架引入了**非对称模拟**的核心思想：
*   **用户模拟器（有状态 FSM）：** 将应用程序建模为有限状态机（FSM）。模拟用户不能直接调用后台 API，必须像真人一样在不同“屏幕”（状态）间导航。例如，发送邮件需要经历“打开应用 -> 搜索联系人 -> 进入写信页 -> 发送”的序列。
*   **主动式助手（扁平 API）：** 助手拥有更高的权限，可以直接访问所有应用的后台 API，以实现高效的信息检索和任务执行。
*   **Observe-Execute 架构：** 助手分为两个阶段：
    1.  **观察模式（Observe）：** 持续监测用户动作和环境通知，仅使用只读工具。此时助手需决定是“继续等待”还是“向用户发送建议”。
    2.  **执行模式（Execute）：** 仅在用户接受建议后启动，自主完成多步骤任务。
*   **数学形式化：** 将交互建模为 **Stackelberg POMDP**（领导者-跟随者部分可观测马尔可夫决策过程），其中用户是领导者，助手是观察并提供反馈的跟随者。

#### 3. 实验设计
*   **数据集/场景（Pare-Bench）：** 构建了包含 **143 个多样化任务** 的基准测试，涵盖通信（邮件、短信）、生产力（日历、笔记、提醒）、生活方式（打车、购物、公寓搜索）等 10 个应用领域。
*   **对比方法：** 评估了 7 种主流模型，包括闭源前沿模型（Claude 4.5 Sonnet, GPT-5, Gemini 3 Pro/Flash）和开源模型（Qwen 3 4B, Llama 3.2 3B, Gemma 3 4B）。
*   **评估指标：** 成功率（Success Rate）、建议接受率（Acceptance Rate）、建议频率（Proposal Rate）以及信息获取动作数量（Read Actions）。
*   **鲁棒性测试：** 引入了工具调用失败概率（0.1-0.4）和环境噪声（每分钟 2-6 个干扰事件）。

#### 5. 实验数量与充分性
*   **实验规模：** 针对 143 个场景，每个模型在每个场景下运行 4 次以减少随机性误差，并报告了标准差。
*   **消融实验：** 进行了深入的“用户模型消融”，分别测试了使用 GPT-5-mini、Claude 4.5 和 Qwen 3 作为用户模拟器时对助手表现的影响。
*   **充分性评价：** 实验设计非常充分且客观。通过引入环境噪声和工具故障，验证了模型在复杂现实情况下的稳定性；通过非对称接口设计，确保了评估过程对“主动性”这一核心能力的聚焦。

#### 6 主要结论与发现
*   **性能天花板：** 即使是最强的前沿模型（Claude 4.5 和 Gemini 3 Flash），在主动任务中的成功率也仅为 **42%** 左右，说明主动式服务仍具挑战。
*   **执行是瓶颈：** 对于小规模模型（如 Qwen 3 4B），虽然建议接受率尚可（~64%），但实际执行成功率极低（~18%），表明执行能力而非意图推理是其主要短板。
*   **观察的重要性：** 表现优秀的模型通常会执行更多的“只读”动作来收集上下文，这证实了充分的观察是准确推理的前提。
*   **鲁棒性差异：** Claude 在高噪声和高故障率环境下表现出最强的稳定性，而其他模型性能下降明显。

#### 7. 优点
*   **真实性高：** 首次引入基于 FSM 的有状态用户模拟，填补了主动智能体评估中“缺乏真实交互用户”的空白。
*   **架构合理：** Observe-Execute 架构很好地平衡了助手的自主性与用户的控制权，符合隐私和安全需求。
*   **基准全面：** Pare-Bench 覆盖场景广泛，且通过自动化流水线生成，具有良好的可扩展性。

#### 8. 不足与局限
*   **缺乏视觉感知：** 目前模型基于 API 工具调用而非视觉屏幕交互，无法评估多模态视觉定位能力。
*   **模拟偏差：** 尽管使用了 LLM 模拟用户，但仍难以完全捕捉真实人类的疲劳、情绪波动或复杂的个性化偏好。
*   **回合限制：** 实验设置了 10 个回合的上限，可能导致一些需要长期观察的长程任务被截断（Truncated）。
*   **部署假设：** 实验主要采用对称设置（观察和执行用同一模型），未深入探讨“端侧小模型观察+云端大模型执行”的非对称部署性能。
