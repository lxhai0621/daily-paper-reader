## 摘要
多模态大语言模型（MLLMs）正从被动观察者演变为主动智能体，通过视觉扩展（调用视觉工具）和知识扩展（开放网络搜索）来解决问题。然而，现有的评估方法存在不足：它们缺乏灵活的工具集成，将视觉工具和搜索工具分开测试，且主要根据最终答案进行评估。因此，这些评估无法验证工具是否被实际调用、应用是否正确以及使用是否高效。为解决这一问题，我们推出了 Agentic-MME，这是一个针对多模态智能体能力的过程验证基准测试。它包含跨 6 个领域和 3 个难度级别的 418 个真实世界任务，用于评估能力协同作用，并包含 2,000 多个分步检查点，每个任务平均耗费 10 多个小时的人工标注。每个任务都包含一个支持沙箱代码和 API 的统一评估框架，以及一条沿 S 轴和 V 轴双轴标注了分步检查点的人类参考轨迹。为了实现真正的过程级验证，我们审核细粒度的中间状态而非仅仅是最终答案，并通过相对于人类轨迹的“过度思考”指标来量化效率。实验结果显示，表现最好的模型 Gemini3-pro 达到了 56.3% 的总体准确率，但在 Level-3 任务上显著下降至 23.0%，这凸显了解决真实世界多模态智能体问题的难度。

## Abstract
Multimodal Large Language Models (MLLMs) are evolving from passive observers into active agents, solving problems through Visual Expansion (invoking visual tools) and Knowledge Expansion (open-web search). However, existing evaluations fall short: they lack flexible tool integration, test visual and search tools separately, and evaluate primarily by final answers. Consequently, they cannot verify if tools were actually invoked, applied correctly, or used efficiently. To address this, we introduce Agentic-MME, a process-verified benchmark for Multimodal Agentic Capabilities. It contains 418 real-world tasks across 6 domains and 3 difficulty levels to evaluate capability synergy, featuring over 2,000 stepwise checkpoints that average 10+ person-hours of manual annotation per task. Each task includes a unified evaluation framework supporting sandboxed code and APIs, alongside a human reference trajectory annotated with stepwise checkpoints along dual-axis: S-axis and V-axis. To enable true process-level verification, we audit fine-grained intermediate states rather than just final answers, and quantify efficiency via an overthinking metric relative to human trajectories. Experimental results show the best model, Gemini3-pro, achieves 56.3% overall accuracy, which falls significantly to 23.0% on Level-3 tasks, underscoring the difficulty of real-world multimodal agentic problem solving.

*   **工具集成缺乏灵活性**：通常将视觉工具与网络搜索隔离测试，缺乏统一框架。

#### 2. 方法论：核心思想与技术细节
论文提出了 **Agentic-MME**，一个强调过程验证（Process-Verified）的基准测试：

*   **双轴评估体系**：
    *   **S轴（策略与搜索）**：审计搜索关键词、参考 URL 和中间答案的正确性。
    *   **V轴（视觉证据）**：审计模型是否有意图调用工具，以及生成的中间图像（如裁剪出的局部）是否确实包含解题所需的关键证据。
*   **统一执行框架**：支持 **Gen模式**（模型编写 Python 代码操作图像）和 **Atm模式**（通过结构化 API 调用工具），并使用基于 AST（抽象语法树）的追踪器来标准化代码审计。
*   **效率指标（Overthink）**：通过公式 `max(0, C_agent - C_human) / (C_human + 1)` 计算模型相对于人类参考轨迹的冗余操作，量化“过度思考”程度。

#### 6. 主要结论与发现
*   **性能鸿沟**：所有模型均远低于人类水平（人类 93.8% vs 最强模型 56.3%）。在 Level 3 任务中，模型表现骤降（最强仅 33.3%）。
*   **开源差距**：开源模型在搜索规划和多步推理上显著落后于闭源模型，S 轴得分普遍较低。
*   **界面偏好**：结构化 API（Atm 模式）通常优于代码生成（Gen 模式），因为代码生成增加了模型处理 I/O 和语法的认知负担。
*   **过度思考**：强模型容易陷入冗余的工具调用循环，虽然调用次数多，但往往在错误区域浪费资源。
*   **协同必要性**：Level 3 任务证明了视觉与搜索的“超加性”效应——单独使用任一能力都无法解决，必须深度协同。

#### 7. 优点
*   **过程级审计**：不再是黑盒测试，通过 2000+ 检查点精准定位模型是死在“看不见”、“搜不到”还是“想不通”。
*   **高质量标注**：极高的人工成本投入确保了参考轨迹的权威性和细粒度。
*   **现实性强**：任务源于真实网页和高分辨率复杂图像，而非合成数据，具有极高的实用参考价值。
*   **效率量化**：首次系统性引入 Overthink 指标评估智能体的执行效率。

#### 8. 不足与局限
*   **样本规模**：418 个任务虽然深度极高，但相比于一些数万规模的自动化基准，样本量相对较小，可能存在特定领域的覆盖偏差。
*   **评判模型依赖**：虽然引入了人工校准，但中间过程的 V 轴和 S 轴验证仍部分依赖于 LLM-as-a-Judge（如 GPT-4o），可能存在评判偏见。
*   **动态性限制**：目前的网页搜索基于快照或缓存 replay，无法完全模拟互联网实时变化的动态环境。
