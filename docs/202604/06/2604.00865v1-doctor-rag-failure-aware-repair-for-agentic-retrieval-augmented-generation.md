## 摘要
智能体检索增强生成（Agentic RAG）已成为多跳问答和复杂知识推理中广泛采用的范式，其中检索和推理在推理阶段交替进行。随着推理轨迹变长，故障变得越来越普遍。现有方法通常通过停留在诊断分析或重新运行整个检索-推理流水线来处理此类故障，这导致了巨大的计算开销和冗余推理。在本文中，我们提出了 Doctor-RAG (DR-RAG)，这是一个统一的诊断与修复框架，通过显式的错误定位和前缀重用，以最小成本的干预来纠正 Agentic RAG 中的故障。DR-RAG 将故障处理分解为两个连续阶段：(i) 轨迹级故障诊断与定位，将错误归因于覆盖门控分类法，并识别推理轨迹中最早的故障点；(ii) 工具条件的局部修复，仅在诊断出的故障点进行干预，同时最大限度地重用已验证的推理前缀和检索到的证据。通过显式地将错误归因与纠正分离，DR-RAG 实现了精确的错误定位，从而避免了昂贵的完整流水线重运行，并实现了有针对性的高效修复。我们在三个多跳问答基准测试、多个 Agentic RAG 基准模型以及不同的骨干模型上对 DR-RAG 进行了评估。实验结果表明，与基于重运行的修复策略相比，DR-RAG 在显著降低推理 Token 消耗的同时，大幅提高了回答准确率。

## Abstract
Agentic Retrieval-Augmented Generation (Agentic RAG) has become a widely adopted paradigm for multi-hop question answering and complex knowledge reasoning, where retrieval and reasoning are interleaved at inference time. As reasoning trajectories grow longer, failures become increasingly common. Existing approaches typically address such failures by either stopping at diagnostic analysis or rerunning the entire retrieval-reasoning pipeline, which leads to substantial computational overhead and redundant reasoning. In this paper, we propose Doctor-RAG (DR-RAG), a unified diagnose-and-repair framework that corrects failures in Agentic RAG through explicit error localization and prefix reuse, enabling minimal-cost intervention. DR-RAG decomposes failure handling into two consecutive stages: (i) trajectory-level failure diagnosis and localization, which attributes errors to a coverage-gated taxonomy and identifies the earliest failure point in the reasoning trajectory; and (ii) tool-conditioned local repair, which intervenes only at the diagnosed failure point while maximally reusing validated reasoning prefixes and retrieved evidence. By explicitly separating error attribution from correction, DR-RAG enables precise error localization, thereby avoiding expensive full-pipeline reruns and enabling targeted, efficient repair. We evaluate DR-RAG across three multi-hop question answering benchmarks, multiple agentic RAG baselines, and different backbone models. Experimental results demonstrate that DR-RAG substantially improves answer accuracy while significantly reducing reasoning token consumption compared to rerun-based repair strategies.

智能体检索增强生成（Agentic RAG）通过交替进行推理和检索来解决复杂的多跳问答任务。然而，随着推理链条的增长，系统极易在中间环节出错。
*   **研究动机**：现有的 RAG 故障处理方法存在两个极端：要么仅停留在诊断层面（如 RAGChecker），不提供自动修复；要么采取“全量重跑（Rerun）”策略（如 RAG-Critic），即一旦出错就丢弃整个轨迹重新开始。
*   **核心痛点**：全量重跑会导致巨大的计算开销（Token 浪费），且由于没有定位错误根源，重跑仍可能在相同或不同位置再次失败。
*   **研究目标**：如何以最小的计算成本，精确地定位并修复 Agentic RAG 轨迹中的错误？

#### 2. 方法论：核心思想与技术细节
Doctor-RAG (DR-RAG) 提出了一个“诊断-定位-局部修复”的统一框架，核心流程分为两个阶段：

*   **阶段一：分类法约束的故障诊断与定位**
    *   **覆盖率门控（Coverage Gating）**：首先评估已检索文档是否足以回答问题（$Cov(y) \in \{0, 1\}$）。这作为一个门控信号，将错误空间划分为“证据充足”和“证据不足”两类。
    *   **错误分类法**：在门控约束下，将错误归因为：格式错误（Format Error）、推理逻辑错误（Reasoning Error）、检索器失效（Retriever Error）或推理诱导的搜索错误（Search Error）。
    *   **轨迹级定位**：识别轨迹中最早出现的失效动作索引 $k^\dagger$。$k^\dagger$ 之前的所有步骤被视为“验证通过的前缀”，予以保留。

*   **阶段二：工具条件的局部修复**
    *   **前缀复用**：仅从 $k^\dagger$ 处截断并重新生成后续步骤，最大化复用已有的推理和检索结果。
    *   **针对性修复算子**：
        *   **格式修复**：仅重写最终答案。
        *   **推理修复**：在证据充足时，基于已有证据重新进行逻辑推导。
        *   **检索修复**：重写查询语句并增加检索深度（Top-K）。
        *   **搜索修复**：重新生成高层解决方案计划，引导新的搜索路径。

#### 6. 主要结论与发现
*   **性能提升**：DR-RAG 在所有基准测试中均显著优于 Rerun 策略。例如，在 Qwen3-8B + ReAct + HotpotQA 上，EM（精确匹配）提升了 **25.8%**。

#### 7. 优点（亮点）
*   **系统性强**：首次将 Agentic RAG 的故障处理形式化为“诊断-定位-局部修复”的结构化问题。
*   **高效节能**：通过前缀复用机制，极大地解决了 Agentic RAG 在长轨迹推理中的计算浪费问题。
*   **即插即用**：作为一个通用的框架，可以适配不同的 Agent 架构和 LLM 骨干，具有很强的实用价值。

#### 8. 不足与局限
*   **诊断瓶颈**：自动诊断的准确率目前在 60% 左右，虽然足以支撑修复，但仍有提升空间（如 Oracle 实验所示，诊断更准则修复更强）。

*   **依赖 LLM 能力**：诊断和修复的效果高度依赖于骨干模型本身的指令遵循和自我反思能力，对于极小规模的模型可能效果受限。
