## 摘要
我们介绍了 AstraAI，这是一个用于高性能计算 (HPC) 软件开发的命令行界面 (CLI) 编程框架。AstraAI 直接在 Linux 终端中运行，并将大语言模型 (LLM) 与检索增强生成 (RAG) 以及基于抽象语法树 (AST) 的结构分析相结合，从而为复杂的科学代码库实现上下文感知的代码生成。其核心思想是构建一个高保真提示词 (prompt) 并传递给 LLM 进行推理。该提示词通过 RAG 从底层框架代码库中检索相关的代码片段，并结合从 AST 分析中提取的结构上下文来增强用户请求，为模型提供有关相关函数、数据结构和整体代码组织的精确信息。该框架旨在对源代码进行局部修改，同时保持与周围代码的结构一致性。AstraAI 既支持来自 Hugging Face 的本地托管模型，也支持通过美国科学云 (American Science Cloud) 访问的基于 API 的前沿模型，从而实现在 HPC 环境中的灵活部署。该系统生成的代码与现有的项目结构和编程模式保持一致。我们在 AMReX（一个由美国能源部支持的用于百亿亿级应用的 HPC 软件基础设施）中的代表性 HPC 代码生成任务上演示了 AstraAI。

## Abstract
We present AstraAI, a command-line interface (CLI) coding framework for high-performance computing (HPC) software development. AstraAI operates directly within a Linux terminal and integrates large language models (LLMs) with Retrieval-Augmented Generation (RAG) and Abstract Syntax Tree (AST)-based structural analysis to enable context-aware code generation for complex scientific codebases. The central idea is to construct a high-fidelity prompt that is passed to the LLM for inference. This prompt augments the user request with relevant code snippets retrieved from the underlying framework codebase via RAG and structural context extracted from AST analysis, providing the model with precise information about relevant functions, data structures, and overall code organization. The framework is designed to perform scoped modifications to source code while preserving structural consistency with the surrounding code. AstraAI supports both locally hosted models from Hugging Face and API-based frontier models accessible via the American Science Cloud, enabling flexible deployment across HPC environments. The system generates code that aligns with existing project structures and programming patterns. We demonstrate AstraAI on representative HPC code generation tasks within AMReX, a DOE-supported HPC software infrastructure for exascale applications.

*   **研究动机**：开发一种能够深入理解 HPC 代码库结构、利用现有代码模式作为参考，并能在 Linux 终端环境下直接运行的上下文感知辅助工具，以提升科学计算软件的开发效率和可靠性。

### 2. 方法论
AstraAI 是一个集成在命令行（CLI）中的框架，其核心流程如下：
*   **检索增强生成 (RAG)**：
    *   **预处理**：将代码库切分为带有元数据（任务类型、用户意图、API 关键字等）的块，并使用 `all-MiniLM` 模型生成向量嵌入。
    *   **检索**：根据用户输入的语义，从向量数据库中检索最相关的代码示例，为 LLM 提供框架特定的编程范式。
*   **抽象语法树 (AST) 引导分析**：
    *   利用 `clang-query` 工具对源代码进行静态分析，提取类成员变量、函数签名、访问权限及精确的源代码行号范围。
    *   这些结构化信息被注入提示词，确保 LLM 了解代码的上下文接口和物理位置。
*   **高保真提示词构建**：将系统指令、RAG 检索到的代码片段、AST 提取的结构信息和用户原始请求组合成一个复杂的提示词。
*   **推理与编辑**：支持通过 Ollama 运行本地模型（如 Hugging Face 的 CodeLlama）或通过 API 调用前沿模型。生成代码后，利用 AST 信息进行“安全编辑”，通过类似 GitHub 冲突标记的方式辅助开发者集成代码。

*   **实验规模**：针对 4 种不同规模和来源的模型，在 6 类典型 HPC 编程任务上进行了对比实验。
*   **充分性评价**：实验涵盖了从简单的循环转换到复杂的求解器配置，具有较好的代表性。通过变量归一化处理相似度，体现了评估的客观性。但由于任务总数较少（6 组），且主要集中在 AMReX 框架，其在其他 HPC 框架或更广泛任务上的泛化能力仍有待进一步验证。

### 6. 主要结论与发现
*   **性能提升**：AstraAI 的 RAG+AST 增强显著提升了代码生成的准确性。特别是对于较小的本地模型（如 CodeLlama-13B），相似度得分从基线的 0.3-0.6 提升到了 0.8 以上。

### 7. 优点
*   **结构化感知**：不同于纯文本检索，引入 AST 分析确保了代码生成的语法和逻辑边界。

*   **评估科学性**：采用了变量名归一化的相似度评估，有效过滤了无关干扰。
