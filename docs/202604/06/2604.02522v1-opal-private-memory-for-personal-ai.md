## 摘要
个人 AI 系统越来越多地保留用户活动的长期记忆，包括文档、电子邮件、消息、会议和环境录音。可信硬件可以保护这些数据的私密性，但难以应对不断增长的数据存储规模。这迫使数据被存储到外部，从而暴露了检索访问模式，导致隐私信息泄露给应用提供商。不经意 RAM (ORAM) 是一种可以隐藏这些模式的加密原语，但它需要固定的访问预算，这排除了智能体记忆系统为保证准确性所依赖的查询相关遍历。我们提出了 Opal，一种用于个人 AI 的私有记忆系统。我们的核心见解是将所有与数据相关的推理与海量个人数据解耦，并将其限制在可信飞地（trusted enclave）内。这样，不可信磁盘只能看到固定的、不经意的内存访问。这一驻留在飞地内的组件利用轻量级知识图谱来捕捉语义搜索所遗漏的个人上下文，并通过在每次 ORAM 访问中搭载重新索引和容量管理来处理持续的数据摄取。在基于随机通信模型驱动的综合合成个人数据流水线上的评估表明，Opal 的检索准确率比语义搜索提高了 13 个百分点，吞吐量比安全基准高出 29 倍，且基础设施成本降低了 15 倍。目前，一家主要的 AI 提供商正考虑将 Opal 部署给数百万用户。

## Abstract
Personal AI systems increasingly retain long-term memory of user activity, including documents, emails, messages, meetings, and ambient recordings. Trusted hardware can keep this data private, but struggles to scale with a growing datastore. This pushes the data to external storage, which exposes retrieval access patterns that leak private information to the application provider. Oblivious RAM (ORAM) is a cryptographic primitive that can hide these patterns, but it requires a fixed access budget, precluding the query-dependent traversals that agentic memory systems rely on for accuracy.   We present Opal, a private memory system for personal AI. Our key insight is to decouple all data-dependent reasoning from the bulk of personal data, confining it to the trusted enclave. Untrusted disk then sees only fixed, oblivious memory accesses. This enclave-resident component uses a lightweight knowledge graph to capture personal context that semantic search alone misses and handles continuous ingestion by piggybacking reindexing and capacity management on every ORAM access. Evaluated on a comprehensive synthetic personal-data pipeline driven by stochastic communication models, Opal improves retrieval accuracy by 13 percentage points over semantic search and achieves 29x higher throughput with 15x lower infrastructure cost than a secure baseline. Opal is under consideration for deployment to millions of users at a major AI provider.

以下是对该论文的深度结构化总结：

### 1. 核心问题与整体含义
*   **研究动机：** 随着个人 AI（如 Microsoft Recall, Google Gemini）的普及，系统需要记录用户长期的邮件、会议、聊天等敏感数据。
*   **技术矛盾：** 
    *   **隐私风险：** 将数据存放在云端，即便加密，服务商也能通过“访问模式”（即检索了哪些记录）推断出用户的查询意图和生活细节。
    *   **硬件限制：** 可信执行环境（TEE，如 Intel TDX）虽然安全，但其加密内存容量有限且昂贵，无法装下数年的个人数据。
    *   **现有方案缺陷：** 传统的不经意 RAM（ORAM）虽然能隐藏访问模式，但其固定的访问逻辑与 AI 智能体需要的动态、复杂的知识图谱（KG）遍历不兼容，导致检索准确率低或开销巨大。

### 2. 方法论
Opal 的核心思想是**将“数据依赖的推理逻辑”留在 TEE 飞地内，而将“海量加密数据”放在外部不可信磁盘上**，并通过 ORAM 进行访问。

*   **关键技术细节：**
    1.  **知识图谱过滤搜索（KG-filtered Search）：** 在 TEE 内部维护一个极简的、仅包含元数据（如人名、时间戳、项目标签）的知识图谱。查询时，先在 TEE 内通过 LLM 提取谓词并过滤出“准入集”，再在 ORAM 中进行固定预算的向量检索。这避免了在不可信存储上进行复杂的图遍历。
    2.  **不经意梦境（Oblivious Dreaming）：** 这是一个巧妙的维护机制。系统利用每次正常的 ORAM 访问所带回的随机数据块（Stash），在后台静默执行数据过期删除、索引重平衡和摘要生成。这些操作“寄生”在正常请求中，不会产生额外的外部 I/O 痕迹，从而隐藏了维护模式。
    3.  **三飞地架构：** 系统分为 Controller（逻辑控制）、Embedding（向量化）和 LLM（推理生成）三个相互隔离又安全通信的 TEE 飞地。
    4.  **安全性增强：** 使用单调计数器和 Merkle 树结构防止服务商进行回滚攻击（Rollback Attack）。

### 3. 实验设计
*   **数据集：** 由于真实的个人数据极度敏感且难以获取，研究者开发了一套**合成个人数据流水线**。该流水线基于 Hawkes 过程（一种随机点过程模型）模拟真实的通信爆发性，生成了包含邮件、会议、文档、消息等长达三年的多模态数据。
*   **Benchmark：** 包含单事实查询、时间敏感查询、多跳推理、人名/项目/模态过滤等 7 类任务。
*   **对比方法：**
    *   **ANN-only：** 仅使用语义搜索（向量检索）。
    *   **Graphiti：** 现有的非私有图记忆系统（作为准确率上限）。
    *   **In-Memory Opal：** 模拟将所有数据强行塞入 TEE 内存的传统安全方案（作为性能基准）。
    *   **Plaintext Opal：** 无隐私保护的明文版本（衡量系统开销）。

### 4. 资源与算力
*   **硬件环境：** 
    *   **TEE：** 使用 Intel TDX 机密虚拟机（4 vCPUs, 4GB RAM 用于控制器）。
    *   **GPU：** 使用 **NVIDIA B200 GPU**（处于机密计算模式），用于运行 LLM 和 Embedding 模型。
*   **模型：** 
    *   LLM 使用 `gpt-oss-20b`（200 亿参数开源模型）及 Google Vertex AI 的 Gemini 系列。
    *   Embedding 使用 `nomic-embed-text`。
*   **网络：** 模拟了跨区域的广域网（WAN）延迟，带宽约为 0.17 Gb/s。

### 5. 实验数量与充分性
*   **实验规模：** 模拟了 100 万用户规模下的系统表现，进行了长达三年的数据回放实验。
*   **充分性：** 实验非常充分。不仅对比了检索准确率（Accuracy），还深入分析了带宽开销、单次操作延迟、系统吞吐量（Throughput）以及基础设施成本（Cost）。此外，还通过消融实验验证了“梦境”机制对防止索引漂移的有效性。

### 6. 主要结论与发现
*   **准确率提升：** 引入 KG 过滤后，检索准确率比纯语义搜索提升了 **13 个百分点**，达到了与非私有先进系统持平的水平。
*   **性能飞跃：** 相比于将数据全部保存在 TEE 内存的方案，Opal 的吞吐量高出 **29 倍**。
*   **成本降低：** 在服务百万用户时，基础设施成本降低了 **15 倍**。
*   **实用性：** 查询延迟约为 2.32 秒，数据摄取延迟约为 0.94 秒，完全满足实时交互需求。

### 7. 优点
*   **架构优雅：** 成功解决了 ORAM 的僵硬性与 AI 记忆灵活性之间的矛盾。
*   **工程落地性强：** 考虑了云端部署的实际成本和 TEE 的物理限制，目前已被大型 AI 提供商考虑部署。
*   **评估贡献：** 提出的合成数据生成模型为隐私敏感领域的 AI 研究提供了极具价值的工具。

### 8. 不足与局限
*   **合成数据偏差：** 尽管使用了统计学模型，但合成数据可能仍无法完全覆盖人类真实行为的所有极端情况（如极度不规律的作息）。

*   **模态扩展：** 目前主要针对文本和结构化元数据，对于视频、图像等原生大文件的 ORAM 存储开销和检索效率仍有待进一步验证。
