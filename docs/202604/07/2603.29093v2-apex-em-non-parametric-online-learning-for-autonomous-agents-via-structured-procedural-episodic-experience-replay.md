## 摘要
基于大语言模型（LLM）的自主智能体缺乏持久的程序性记忆：即使之前已经解决过结构相同的任务，它们仍会从头开始重新推导解决方案。我们提出了 APEX-EM，这是一个非参数在线学习框架，它在不修改模型权重的情况下积累、检索和重用结构化程序计划。APEX-EM 引入了：(1) 一种结构化经验表示，编码了每次执行的完整程序-情境轨迹——包括规划步骤、中间产物、带有错误分析的迭代历史以及质量评分；(2) 一种带有任务验证器（Task Verifiers）的“规划-检索-生成-迭代-摄取”（PRGII）工作流，提供多维奖励信号；(3) 一种双结果经验记忆，采用结合了语义搜索、结构特征匹配和计划有向无环图（DAG）遍历的混合检索方式——从而实现在词汇无重叠但操作结构相似的任务之间进行跨领域迁移。成功的经验作为正向上下文示例；失败的经验则作为带有结构化错误标注的负面示例。我们使用 Claude Sonnet 4.5 和 Opus 4.5 在 BigCodeBench、KGQAGen-10k 和 Humanity's Last Exam 上进行了评估。在 KGQAGen-10k 上，APEX-EM 达到了 89.6% 的准确率，而无记忆时仅为 41.3%（提升了 48.3 个百分点），超过了真值检索（oracle-retrieval）的上限（84.9%）。在 BigCodeBench 上，它从 53.9% 的基准线达到了 83.3% 的成功率（SR）（提升了 29.4 个百分点），在可比的冻结骨干网络条件下，超过了 MemRL 11.0 个百分点的增益（注：我们的分析中对骨干网络的差异进行了控制）。在 HLE 上，实体图检索从 25.2% 提升至 48.0%（提升了 22.8 个百分点）。消融实验表明，各组件的价值取决于具体任务：丰富的评判反馈对代码生成的影响微乎其微，但对结构化查询至关重要（提升了 10.3 个百分点），而二元信号迭代可以部分补偿较弱的反馈。

## Abstract
LLM-based autonomous agents lack persistent procedural memory: they re-derive solutions from scratch even when structurally identical tasks have been solved before. We present APEX-EM, a non-parametric online learning framework that accumulates, retrieves, and reuses structured procedural plans without modifying model weights. APEX-EM introduces: (1) a structured experience representation encoding the full procedural-episodic trace of each execution -- planning steps, artifacts, iteration history with error analysis, and quality scores; (2) a Plan-Retrieve-Generate-Iterate-Ingest (PRGII) workflow with Task Verifiers providing multi-dimensional reward signals; and (3) a dual-outcome Experience Memory with hybrid retrieval combining semantic search, structural signature matching, and plan DAG traversal -- enabling cross-domain transfer between tasks sharing no lexical overlap but analogous operational structure. Successful experiences serve as positive in-context examples; failures as negative examples with structured error annotations.   We evaluate on BigCodeBench, KGQAGen-10k, and Humanity's Last Exam using Claude Sonnet 4.5 and Opus 4.5. On KGQAGen-10k, APEX-EM achieves 89.6% accuracy versus 41.3% without memory (+48.3pp), surpassing the oracle-retrieval upper bound (84.9%). On BigCodeBench, it reaches 83.3% SR from a 53.9% baseline (+29.4pp), exceeding MemRL's +11.0pp gain under comparable frozen-backbone conditions (noting backbone differences controlled for in our analysis). On HLE, entity graph retrieval reaches 48.0% from 25.2% (+22.8pp). Ablations show component value is task-dependent: rich judge feedback is negligible for code generation but critical for structured queries (+10.3pp), while binary-signal iteration partially compensates for weaker feedback.

### 1. 核心问题与研究动机
*   **核心问题**：当前的 LLM 智能体在程序层面是“无状态”的。即使面对结构完全相同的任务，它们每次都会从零开始推导方案，无法积累和重用过往的执行经验。
*   **研究背景**：现有的记忆机制（如 MemRL、Reflexion）大多存储非结构化的文本摘要或简单的标量效用值（Q-value），这导致了三个局限：
    1.  **缺乏结构**：丢失了规划步骤、实体发现和错误轨迹等程序化细节。
    2.  **单向学习**：未能充分利用失败经验作为负面约束。
    3.  **迁移困难**：当任务描述的表面语义不同但操作结构相似时（例如：查询体育数据 vs 查询财务数据），基于语义向量的检索往往失效。

### 2. 方法论：APEX-EM 框架
APEX-EM 是一种**非参数在线学习**框架，其核心思想是通过外部结构化存储实现智能体能力的持续进化，而无需修改模型权重。

*   **程序化知识图谱 (PKG)**：将经验存储为图节点，每个节点包含五个反射层：
    *   **目标反射 (RG)**：任务意图与约束。
    *   **程序反射 (RP)**：可重用的步骤模板。
    *   **证据反射 (RE)**：执行过程中使用的具体数据或工具输出。
    *   **错误注册 (Rerr)**：结构化的错误分类与根因分析。
    *   **补丁反射 (Rpatch)**：针对错误的具体修复逻辑。
*   **PRGII 工作流**：
    1.  **Plan (规划)**：提取任务的“结构特征签名”（Structural Signature），即抽象的操作序列（如：实体解析 $\rightarrow$ 时间过滤 $\rightarrow$ 聚合）。
    2.  **Retrieve (检索)**：结合语义搜索、结构签名匹配和图遍历。
    3.  **Generate (生成)**：同时参考成功的正例和失败的负例进行生成。
    4.  **Iterate (迭代)**：通过验证器进行自我修正循环。
    5.  **Ingest (摄取)**：经过质量门控（Quality Gate）评估后，将新经验存入 PKG。
*   **双结果学习**：成功经验作为 In-context Learning 的正向示例，失败经验则带上错误标注作为避坑指南。

### 3. 实验设计
*   **数据集与场景**：
    *   **BigCodeBench (BCB)**：复杂的 Python 代码生成，涉及多库调用。
    *   **KGQAGen-10k**：基于 Wikidata 的多步结构化查询生成（SPARQL）。
    *   **Humanity’s Last Exam (HLE)**：跨学科的专家级知识推理。
*   **对比方法**：
    *   **基准线**：No Memory（无记忆）。

*   **骨干模型**：主要使用 Claude Sonnet 4.5 和 Claude Opus 4.5。

### 5. 实验数量与充分性
*   **实验规模**：
    *   在三个大型基准上进行了测试，每个任务运行 10 个 Epoch 以观察在线学习的演进曲线。
    *   **消融实验**：设计了 A0-A5 等多组消融，分别验证了记忆组件、评判反馈（Judge Feedback）、迭代循环、检索策略（语义 vs 实体图）的贡献。
    *   **跨任务迁移测试**：在 342 个未见过的 BCB 任务和 1079 个未见过的 KGQA 任务上验证了冻结记忆后的泛化能力。
*   **客观性**：实验采用了与 MemRL 相同的划分标准和评估指标（SR, CSR），并控制了骨干模型变量，对比相对公平。

### 6. 主要结论与发现
*   **性能飞跃**：在 KGQAGen-10k 上，准确率从 41.3% 提升至 89.6%（+48.3pp），超过了真值检索的上限。在 BCB 上提升了 29.4pp。
*   **结构迁移的优越性**：在 HLE 等语义相关性低的任务中，结构签名匹配实现了有效的跨任务知识迁移，而传统 RAG 几乎无效。
*   **任务依赖性**：
    *   **代码生成**：二元（通过/失败）信号已足够，详细的评判反馈增益较小。
    *   **结构化查询**：详细的评判反馈至关重要（+10.3pp），能指导模型修正复杂的逻辑错误。
*   **效率提升**：随着记忆积累，智能体解决任务所需的平均迭代次数显著下降（KGQA 任务减少了约 40%）。

### 7. 优点与亮点
*   **结构化深度**：不同于以往的扁平化记忆，PKG 提供了因果链条清晰的程序化记录。
*   **跨领域迁移**：通过抽象“操作签名”，实现了从“查询体育”到“查询财务”的逻辑迁移，解决了语义鸿沟问题。
*   **负面经验利用**：将失败转化为结构化的“补丁”，有效防止智能体重复犯错。
*   **非参数化进化**：无需微调即可实现类似强化学习的性能提升，且具备完全的可审计性。

### 8. 不足与局限
*   **分类体系依赖**：结构化签名的分类法（Taxonomy）目前仍是人工设计的，可能无法覆盖所有复杂场景。
*   **评判噪声**：质量门控高度依赖 Judge LLM 的水平，若评判模型出错，可能引入错误的经验。
*   **缺乏理论收敛证明**：虽然实验表现优异，但作为非参数方法，缺乏像强化学习那样的收敛性理论保证。
*   **上下文压力**：随着检索到的正负例增加，Prompt 的长度会显著增加，可能导致推理成本上升或长文本注意力分散。
