## 摘要
可解释推荐有助于提高推荐系统的透明度和可信度，在个性化推荐场景中发挥着重要作用。目前，基于大语言模型（LLM）的可解释推荐方法通常考虑引入协同信息以增强模型的个性化和准确性，但忽略了推荐数据集中的多模态信息；此外，协同信息需要与 LLM 的语义空间对齐。通过检索路径引入协同信号是一个不错的选择，但现有的大多数检索路径采集方案都采用了现有的可解释图神经网络（GNN）算法。尽管这些方法有效，但它们的可解释性相对较弱，且可能不适用于推荐领域。为了应对上述挑战，我们提出了 MMP-Refer，这是一个使用多模态检索路径和检索增强 LLM 进行可解释推荐的框架。我们使用基于联合残差编码的序列推荐模型来获取多模态嵌入，并设计了一种启发式搜索算法，通过多模态嵌入获取检索路径；在生成阶段，我们集成了一个可训练的轻量级协同适配器，将交互子图的图编码映射到 LLM 的语义空间，作为软提示（soft prompts）以增强 LLM 对交互信息的理解。大量实验证明了我们方法的有效性。代码和数据可在 https://github.com/pxcstart/MMP-Refer 获取。

## Abstract
Explainable recommendations help improve the transparency and credibility of recommendation systems, and play an important role in personalized recommendation scenarios. At present, methods for explainable recommendation based on large language models(LLMs) often consider introducing collaborative information to enhance the personalization and accuracy of the model, but ignore the multimodal information in the recommendation dataset; In addition, collaborative information needs to be aligned with the semantic space of LLM. Introducing collaborative signals through retrieval paths is a good choice, but most of the existing retrieval path collection schemes use the existing Explainable GNN algorithms. Although these methods are effective, they are relatively unexplainable and not be suitable for the recommendation field.   To address the above challenges, we propose MMP-Refer, a framework using \textbf{M}ulti\textbf{M}odal Retrieval \textbf{P}aths with \textbf{Re}trieval-augmented LLM \textbf{F}or \textbf{E}xplainable \textbf{R}ecommendation. We use a sequential recommendation model based on joint residual coding to obtain multimodal embeddings, and design a heuristic search algorithm to obtain retrieval paths by multimodal embeddings; In the generation phase, we integrated a trainable lightweight collaborative adapter to map the graph encoding of interaction subgraphs to the semantic space of the LLM, as soft prompts to enhance the understanding of interaction information by the LLM. Extensive experiments have demonstrated the effectiveness of our approach. Codes and data are available at https://github.com/pxcstart/MMP-Refer.

### 1. 核心问题与整体含义（研究动机和背景）
推荐系统的可解释性对于提升用户信任度和透明度至关重要。目前基于大语言模型（LLM）的可解释推荐方法存在两个主要瓶颈：
*   **忽视多模态信息：** 现有模型多侧重于协同过滤信号（用户-物品交互），未能充分利用商品图像、文本描述等多模态特征。
*   **协同信号对齐困难：** 协同信息（图结构）与 LLM 的语义空间存在鸿沟。虽然现有方法尝试通过检索路径引入协同信号，但多依赖 GNN 解释算法，这些算法在推荐场景下的可解释性较弱且计算效率较低。

**MMP-Refer** 旨在通过结合多模态表征学习、启发式路径检索和检索增强生成（RAG）技术，为用户提供更精准、更具说服力的推荐理由。

### 2. 方法论
MMP-Refer 框架由三个核心模块组成：

*   **多模态表征学习（Multimodal Representation Learning）：**
    *   **联合残差编码（Joint Residual Encoding）：** 使用 RQ-VAE（残差量化变分自编码器）对文本（LLM2CLIP 提取）和视觉特征进行统一量化，通过 InfoNCE 损失对齐不同模态，缓解模态间的信息不平衡。
    *   **序列建模：** 利用序列编码器（如 SASRec）融合量化后的多模态特征与用户行为序列，生成个性化的用户和物品嵌入。
*   **启发式路径检索（Heuristic Search for Retrieval Paths）：**
    *   **图剪枝：** 对原始交互图进行 L-hop 邻居提取和 K-core 剪枝，去除低度数（冷门）节点以减少噪声。
    *   **启发式加权：** 设计规则函数为边分配权重。权重考虑了节点间的**多模态特征相似度**和**节点度数**（惩罚高热度节点以突出个性化），权重越低代表可解释性越强。
    *   **路径搜索：** 使用 Dijkstra 算法在加权子图中搜索 Top-K 条最短路径，作为解释的外部知识。
*   **基于 LLM 的推理生成（LLM Reasoning）：**
    *   **硬提示（Hard Prompt）：** 将检索路径转化为自然语言描述（如“用户A -> 购买 -> 商品B -> 被购买 -> 用户C”）。
    *   **软提示（Soft Prompt）：** 使用 GNN 编码检索子图，并通过 **MoE（混合专家）适配器** 将图嵌入映射到 LLM 的语义空间。
    *   **微调：** 使用 LoRA 技术对 LLM（如 Llama2-3B）进行指令微调，最小化生成文本与真实解释（由 ChatGPT 生成作为基准）之间的负对数似然损失。

*   **基准模型（Benchmarks）：**

*   **模型底座：** 序列推荐部分使用 SASRec，生成部分使用 **Llama2-3B-hf**。

### 6. 主要结论与发现
*   **性能领先：** MMP-Refer 在所有数据集上的语义解释得分均优于现有基准，尤其在 BARTscore 上提升显著（约 9.75% - 12.9%）。
*   **多模态的重要性：** 引入多模态特征能更精准地捕捉用户偏好，联合残差编码有效缓解了模态鸿沟。
*   **启发式搜索的优越性：** 相比于复杂的 GNN 解释器，基于规则的启发式搜索在推荐场景下更稳定、更高效且更具解释性。
*   **小模型大能量：** 经过微调的 3B 模型在检索路径增强下，其解释质量可媲美甚至超过未微调的 13B 模型。

### 7. 优点
*   **高效性：** 启发式路径检索大幅降低了计算开销，适合大规模推荐系统。
*   **多模态融合：** 提出了一种系统性的方法将视觉和文本特征整合进 LLM 推荐框架。
*   **对齐机制：** MoE 适配器的设计巧妙地解决了图特征与文本语义的对齐问题。
*   **稳定性：** 实验结果的标准差较低，证明模型生成的解释质量波动较小。

### 8. 不足与局限
*   **Ground-Truth 依赖：** 训练用的“标准解释”是由 ChatGPT 生成的，这可能导致模型学习到的是 ChatGPT 的风格而非真实用户的心理动机。
*   **长输入挑战：** 随着检索路径增加，输入序列变长，LLM 可能会出现注意力稀释，导致软提示的效果提升受限。
*   **模态覆盖：** 目前仅考虑了文本和图像，未涉及视频或音频等更复杂的模态。
*   **应用限制：** 依赖于高质量的商品元数据（标题、描述、图片），在数据缺失严重的场景下效果可能打折扣。
