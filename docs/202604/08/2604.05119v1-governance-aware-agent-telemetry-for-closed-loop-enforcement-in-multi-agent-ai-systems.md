## 摘要
企业级多智能体 AI 系统每小时产生数千次智能体间的交互，然而现有的可观测性工具仅捕获这些依赖关系，而不进行任何强制执行。OpenTelemetry 和 Langfuse 虽然收集遥测数据，但将治理视为下游分析关注点，而非实时执行目标。其结果是存在“只观察不行动”的鸿沟，导致策略违规行为往往在损害发生后才被检测到。我们提出了治理感知智能体遥测（GAAT），这是一种参考架构，旨在闭合多智能体系统中遥测收集与自动化策略执行之间的环路。GAAT 引入了：(1) 治理遥测模式（GTS），通过治理属性扩展了 OpenTelemetry；(2) 实时策略违规检测引擎，使用兼容 OPA 的声明式规则，延迟低于 200 毫秒；(3) 治理执行总线（GEB），支持分级干预；以及 (4) 具有加密溯源功能的受信任遥测平面。

## Abstract
Enterprise multi-agent AI systems produce thousands of inter-agent interactions per hour, yet existing observability tools capture these dependencies without enforcing anything. OpenTelemetry and Langfuse collect telemetry but treat governance as a downstream analytics concern, not a real-time enforcement target. The result is an "observe-but-do-not-act" gap where policy violations are detected only after damage is done.   We present Governance-Aware Agent Telemetry (GAAT), a reference architecture that closes the loop between telemetry collection and automated policy enforcement for multi-agent systems. GAAT introduces (1) a Governance Telemetry Schema (GTS) extending OpenTelemetry with governance attributes; (2) a real-time policy violation detection engine using OPA-compatible declarative rules under sub-200 ms latency; (3) a Governance Enforcement Bus (GEB) with graduated interventions; and (4) a Trusted Telemetry Plane with cryptographic provenance.

*   **核心问题**：现有的多智能体观测工具（如 OpenTelemetry, Langfuse）主要关注事后分析，缺乏实时干预能力。在企业级应用中，智能体间的违规行为（如违反数据驻留政策、泄露隐私 PII）往往在毫秒级发生，而现有的检测和响应机制存在显著延迟，导致“损害已造成，治理才发现”。
*   **研究背景**：随着 EU AI Act 和 NIST AI RMF 等法规的出台，对高风险 AI 系统进行持续监控和实时强制执行已成为合规的刚需。

### 2. 方法论：GAAT 架构
GAAT 引入了一个五层参考架构，核心思想是将遥测数据转化为实时的治理信号，并建立闭环反馈机制：
*   **治理遥测模式 (GTS)**：扩展了 OpenTelemetry，增加了治理属性（如数据分类、管辖权、敏感度、跨智能体血缘/Lineage）。
*   **五层架构细节**：
    1.  **智能体执行层**：执行任务的 LLM 智能体。
    2.  **治理仪表层**：使用 GTS 扩展进行插桩，为每个操作生成带加密签名（ECDSA P-256）的 Span。
    3.  **遥测聚合层**：基于 Kafka 处理流数据，包含签名验证、Bloom Filter 重放攻击检测和基于 **隐马尔可夫模型 (HMM)** 的事件遗漏检测。
    4.  **策略评估层**：使用 OPA (Open Policy Agent) 评估声明式规则，支持并行组合策略，确保决策确定性。
    5.  **治理执行总线 (GEB)**：实施**分级干预 (L0-L4)**，从简单的告警（L1）到重定向（L3）直至完全隔离/隔离（L4，撤销令牌并应用网络策略）。
*   **信任平面**：跨越所有层级，提供基于 Merkle Tree 的审计日志和硬件级（TPM/SGX）的密钥存储。
*   **数学形式化**：论文定义了策略代数，并证明了**升级终止性**（确保干预不会无限循环）和**冲突解决确定性**。

### 6. 主要结论与发现
*   **高效性**：GAAT 在合成测试中达到 **98.3% 的 VPR**，在真实轨迹中达到 **99.7% 的 VPR**。
*   **低延迟**：中位检测延迟仅 **8.4 ms**，端到端执行延迟 **127 ms**，远优于传统仪表盘方案（15 秒以上）。
*   **跨智能体优势**：GAAT 显著优于 NeMo Guardrails（VPR 78.8%），主因是 GAAT 能识别跨智能体的血缘关系，而单体边界检查无法发现多跳传递后的违规。
*   **安全性**：实现了 92.3% 的遗漏检测和 99.1% 的重放攻击拦截。

### 7. 优点
*   **闭环设计**：首次实现了从遥测到执行的亚秒级闭环，填补了行业空白。
*   **分级干预机制**：避免了非黑即白的“全有或全无”强制执行，降低了对业务可用性的影响。
*   **形式化保证**：不仅有工程实现，还提供了数学证明和模拟验证，增强了系统在极端情况下的可靠性。
*   **兼容性**：基于 OpenTelemetry 等开放标准，易于集成到现有企业技术栈。

### 8. 不足与局限
*   **规模限制**：目前的评估主要在 5 个智能体的规模下进行，虽然模拟了 50 个智能体的负载，但超大规模企业级部署（数百个智能体）的复杂性仍待验证。
*   **冷启动问题**：基于 HMM 的遗漏检测需要约 8,000 条轨迹进行预训练，无法在系统上线初期立即生效。
*   **框架依赖**：目前仅在 LangChain 上进行了验证，虽然理论上支持 AutoGen 等框架，但尚未提供跨框架的通用适配器。
*   **对抗性风险**：如果攻击者能够完全控制智能体并绕过插桩层，GAAT 的效力将受限（尽管有加密签名保护）。
