## 摘要
现代安全运营中心（SOC）正面临告警疲劳、工具碎片化以及跨源事件关联受限等难题。当前的安全信息事件管理（SIEM）和扩展检测与响应（XDR）系统仅通过碎片化的工具部分解决了这些挑战。本文提出了 LLM 辅助网络治理（LanG），这是一个用于统一安全运营的开源、治理感知型智能体 AI 平台，其贡献包括：(i) 带有关联引擎的统一事件上下文记录（F1 = 87%）；(ii) 基于 LangGraph 且具备人机回环检查点的智能体 AI 编排器；(iii) 基于四个基础模型微调的 LLM 规则生成器，可生成可部署的 Snort 2/3、Suricata 和 YARA 规则（平均采纳率 96.2%）；(iv) 结合了 Louvain 社区检测、LLM 驱动的假设生成和贝叶斯评分的三阶段攻击重构器（杀伤链准确率达 87.5%）；以及 (v) 分层的“治理-MCP-智能体 AI-安全”架构，其中所有工具均通过模型上下文协议（MCP）公开，并由具备双层护栏流水线（正则表达式 + Llama Prompt Guard 2 语义分类器，F1 分数达 98.1%，实验中实现零误报）的 AI 治理策略引擎进行管理。该平台专为托管安全服务提供商（MSSP）设计，支持多租户隔离、基于角色的访问控制以及完全本地化部署。经过微调的异常和威胁检测器在入侵检测基准测试中分别实现了 99.0% 和 91.0% 的加权 F1 分数，推理时间约为 21 毫秒，机器端平均检测时间为 1.58 秒，且规则生成器在真实 IDS 引擎上的可部署性超过 91%。与八个 SOC 平台的系统性对比证实，LanG 在单个开源工具中独特地满足了多种工业能力，同时强制执行了选定的 AI 治理策略。

## Abstract
Modern Security Operations Centers struggle with alert fatigue, fragmented tooling, and limited cross-source event correlation. Challenges that current Security Information Event Management and Extended Detection and Response systems only partially address through fragmented tools. This paper presents the LLM-assisted network Governance (LanG), an open-source, governance-aware agentic AI platform for unified security operations contributing: (i) a Unified Incident Context Record with a correlation engine (F1 = 87%), (ii) an Agentic AI Orchestrator on LangGraph with human-in-the-loop checkpoints, (iii) an LLM-based Rule Generator finetuned on four base models producing deployable Snort 2/3, Suricata, and YARA rules (average acceptance rate 96.2%), (iv) a Three-Phase Attack Reconstructor combining Louvain community detection, LLM-driven hypothesis generation, and Bayesian scoring (87.5% kill-chain accuracy), and (v) a layered Governance-MCP-Agentic AI-Security architecture where all tools are exposed via the Model Context Protocol, governed by an AI Governance Policy Engine with a two-layer guardrail pipeline (regex + Llama Prompt Guard 2 semantic classifier, achieving 98.1% F1 score with experimental zero false positives). Designed for Managed Security Service Providers, the platform supports multi-tenant isolation, role-based access, and fully local deployment. Finetuned anomaly and threat detectors achieve weighted F1 scores of 99.0% and 91.0%, respectively, in intrusion-detection benchmarks, running inferences in $\approx$21 ms with a machine-side mean time to detect of 1.58 s, and the rule generator exceeds 91% deployability on live IDS engines. A systematic comparison against eight SOC platforms confirms that LanG uniquely satisfies multiple industrial capabilities all in one open-source tool, while enforcing selected AI governance policies.

#### 1. 核心问题与整体含义（研究动机和背景）
现代安全运营中心（SOC）面临三大挑战：**告警疲劳**（分析师 99% 的时间在处理误报）、**工具碎片化**（分析师需在 5-10 个独立控制台间切换）以及**跨源事件关联受限**。虽然 LLM 在自动化安全任务方面展现了潜力，但将其引入 SOC 会带来提示词注入、权限提升、幻觉以及合规性（如欧盟 AI 法案）等新风险。
**LanG 平台**旨在通过一个开源、本地部署且具备治理意识的智能体架构，将 LLM 的推理能力与严格的治理策略相结合，实现统一的安全运营。

#### 2. 方法论：核心思想与关键技术
LanG 采用自底向上的四层架构：**安全层 -> 智能体 AI 层 -> MCP 层 -> 治理层**。
*   **统一事件上下文记录 (UICR)：** 提出一种标准化数据结构，整合 IoC、IoA、网络流、日志和机器学习特征。
*   **智能体 AI 编排器：** 基于 LangGraph 构建五节点流水线（摄取/检测 -> 分类 -> 人工审查 1 -> 日志分析 -> 规则建议 -> 人工审查 2 -> 部署），确保“人机回环”（HITL）。
*   **LLM 规则生成器：** 使用 QLoRA 微调四个基础模型，通过改进的目标函数（对规则字段加权）生成 Snort 2/3、Suricata 和 YARA 规则。
*   **三阶段攻击重构器：** 
    1.  **扫描与聚合：** 归一化异构数据。
    2.  **关联与假设：** 利用 8 种钩子（时间、IP、日志、行为等）构建图，应用 Louvain 社区检测，并结合贝叶斯后验评分生成攻击链假设。
    3.  **可视化与导出：** 生成交互式杀伤链图并导出 STIX/PDF 报告。
*   **治理与安全护栏：** 通过模型上下文协议（MCP）公开工具，并使用“正则表达式 + Llama Prompt Guard 2 语义分类器”的双层护栏强制执行 AI 治理策略。

#### 6. 主要结论与发现
*   **高性能检测：** 微调后的检测器 F1 分数达 91%-99%，推理延迟极低。
*   **规则生成可用性：** 规则生成器在真实 IDS 上的平均采纳率达 96.2%，显著降低了响应时间。
*   **治理有效性：** 双层护栏在保持零误报的同时，实现了 98.1% 的安全拦截 F1 分数。
*   **平台独特性：** LanG 是唯一一个同时满足智能体流水线、LLM 规则生成、MCP 治理和完全本地部署的开源平台。

#### 7. 优点
*   **治理优先：** 首次在安全领域为 MCP 协议引入了形式化的治理层，解决了 AI 智能体的失控风险。
*   **本地化与隐私：** 完全支持本地 LLM（通过 Ollama），无需云端 API，满足国防、医疗等敏感行业的合规需求。
*   **多租户支持：** 专为 MSSP 设计，具备严格的数据隔离和基于角色的访问控制。
*   **端到端自动化：** 从流量捕获到规则部署的完整闭环，且保留了必要的人工干预。

#### 8. 不足与局限
*   **身份验证简化：** 目前仅使用硬编码的用户目录，缺乏与企业级 IdP（如 LDAP/OIDC）的深度集成。
*   **模型能力上限：** 受限于本地算力，使用的 1.7B-8B 模型在处理极其复杂的逻辑推理时可能逊于 GPT-4 等超大规模模型。

*   **存储限制：** 目前使用 SQLite，不支持高并发的多进程写入，不适合超大规模 MSSP 环境。
