## 摘要
现代安全运营中心（SOC）正面临警报疲劳、工具碎片化以及跨源事件关联受限等挑战，而当前的安全信息事件管理（SIEM）和扩展检测与响应（XDR）系统仅能通过碎片化的工具部分解决这些问题。本文提出了 LLM 辅助网络治理（LanG），这是一个用于统一安全运营的开源、具备治理意识的智能体 AI 平台。其主要贡献包括：(i) 一个带有关联引擎的统一事件上下文记录（F1 分数为 87%）；(ii) 一个基于 LangGraph 且具备人机回环（human-in-the-loop）检查点的智能体 AI 编排器；(iii) 一个基于 LLM 的规则生成器，在四个基础模型上进行了微调，可生成可部署的 Snort 2/3、Suricata 和 YARA 规则（平均采纳率为 96.2%）；(iv) 一个三阶段攻击重构器，结合了 Louvain 社区检测、LLM 驱动的假设生成和贝叶斯评分（杀伤链准确率为 87.5%）；以及 (v) 一个分层的“治理-MCP-智能体 AI-安全”架构，其中所有工具均通过模型上下文协议（MCP）公开，并由具备双层护栏流水线（正则表达式 + Llama Prompt Guard 2 语义分类器，F1 分数达到 98.1%，实验中实现零误报）的 AI 治理策略引擎进行管理。该平台专为托管安全服务提供商（MSSP）设计，支持多租户隔离、基于角色的访问控制以及完全本地化部署。经过微调的异常和威胁检测器在入侵检测基准测试中分别实现了 99.0% 和 91.0% 的加权 F1 分数，推理时间约为 21 毫秒，机器端平均检测时间为 1.58 秒，且规则生成器在实际 IDS 引擎上的可部署性超过 91%。与八个 SOC 平台的系统性对比证实，LanG 在单个开源工具中独特地满足了多种工业级能力，同时能够强制执行选定的 AI 治理策略。

## Abstract
Modern Security Operations Centers struggle with alert fatigue, fragmented tooling, and limited cross-source event correlation. Challenges that current Security Information Event Management and Extended Detection and Response systems only partially address through fragmented tools. This paper presents the LLM-assisted network Governance (LanG), an open-source, governance-aware agentic AI platform for unified security operations contributing: (i) a Unified Incident Context Record with a correlation engine (F1 = 87%), (ii) an Agentic AI Orchestrator on LangGraph with human-in-the-loop checkpoints, (iii) an LLM-based Rule Generator finetuned on four base models producing deployable Snort 2/3, Suricata, and YARA rules (average acceptance rate 96.2%), (iv) a Three-Phase Attack Reconstructor combining Louvain community detection, LLM-driven hypothesis generation, and Bayesian scoring (87.5% kill-chain accuracy), and (v) a layered Governance-MCP-Agentic AI-Security architecture where all tools are exposed via the Model Context Protocol, governed by an AI Governance Policy Engine with a two-layer guardrail pipeline (regex + Llama Prompt Guard 2 semantic classifier, achieving 98.1% F1 score with experimental zero false positives). Designed for Managed Security Service Providers, the platform supports multi-tenant isolation, role-based access, and fully local deployment. Finetuned anomaly and threat detectors achieve weighted F1 scores of 99.0% and 91.0%, respectively, in intrusion-detection benchmarks, running inferences in $\approx$21 ms with a machine-side mean time to detect of 1.58 s, and the rule generator exceeds 91% deployability on live IDS engines. A systematic comparison against eight SOC platforms confirms that LanG uniquely satisfies multiple industrial capabilities all in one open-source tool, while enforcing selected AI governance policies.

#### 1. 核心问题与整体含义（研究动机和背景）
现代安全运营中心（SOC）面临三大挑战：**告警疲劳**（分析师 99% 的时间在处理误报）、**工具碎片化**（分析师需在 5-10 个独立控制台间切换）以及**跨源事件关联困难**。虽然大语言模型（LLM）在自动化推理方面展现了潜力，但将其引入 SOC 会带来提示词注入、隐私泄露、幻觉以及缺乏合规治理等新风险。
**LanG 平台**旨在通过一个开源、本地化部署且具备严格治理框架的智能体（Agentic）系统，实现统一的安全检测、响应和规则生成，同时满足欧盟 AI 法案和 NIST AI 风险管理框架的合规要求。

#### 2. 方法论：核心思想与关键技术
LanG 采用了自下而上的四层架构：**安全层 -> 智能体 AI 层 -> MCP 层 -> 治理层**。
*   **统一事件上下文记录 (UICR)：** 提出一种标准化数据结构，将 IoC、IoA、网络流、日志和 ML 特征聚合。通过关联引擎（基于 IP 重叠、时间窗口和 IoC 指纹）将离散告警合并为完整事件。
*   **智能体 AI 编排器：** 基于 **LangGraph** 构建五节点流水线（摄取 -> 分类 -> 人工审核 1 -> 日志分析 -> 规则建议 -> 人工审核 2 -> 部署）。引入“人机回环”机制，确保关键决策由人类授权。
*   **LLM 规则生成器：** 对 Phi-3、CodeLlama、Mistral 和 Qwen 等模型进行 **QLoRA 微调**，使用修改后的损失函数（Field-aware loss）来增强对 Snort/Suricata/YARA 规则语法的掌握。
*   **三阶段攻击重构：** 
    1.  **扫描聚合：** 规范化异构日志。
    2.  **关联假设：** 利用 Louvain 社区检测算法进行聚类，结合 LLM 生成攻击链假设，并使用**贝叶斯后验评分**评估可信度。
    3.  **可视化：** 生成带杀伤链标注的交互式图形。
*   **治理与护栏：** 所有工具通过 **Model Context Protocol (MCP)** 暴露。采用双层护栏：第一层是正则表达式过滤，第二层是 **Llama Prompt Guard 2** 语义分类器，拦截提示词注入和隐私泄露。

#### 6. 主要结论与发现
*   **检测精度：** 异常检测 F1 达 99.0%，多分类威胁检测 F1 达 91.0%。
*   **规则生成：** 微调后的模型在 IDS 引擎上的平均部署采纳率达 96.2%，显著优于通用模型。

#### 7. 优点
*   **治理优先：** 首次在安全智能体中深度集成 MCP 协议与 AI 治理策略引擎，解决了 LLM 接入 SOC 的合规顾虑。
*   **本地化与隐私：** 支持完全本地部署（通过 Ollama），无需将敏感安全数据上传至云端。
*   **端到端自动化：** 从流量摄取到规则部署的全流程自动化，显著降低了 MTTD。
*   **开源兼容：** 兼容多种主流 IDS 格式，且架构设计支持 MSSP 多租户隔离。

#### 8. 不足与局限
*   **身份验证简化：** 当前 RBAC 系统仍处于 Stub 阶段，需进一步集成 OAuth2/LDAP 等企业级认证。

*   **数据库限制：** 目前使用 SQLite，不支持高并发写入，需迁移至 PostgreSQL 等更强大的后端。
