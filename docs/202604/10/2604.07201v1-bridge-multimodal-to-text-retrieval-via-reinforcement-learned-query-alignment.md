## 摘要
多模态检索系统在处理针对纯文本语料库的图文查询时面临挑战：最先进的视觉-语言编码器在 MM-BRIGHT 数据集上仅达到 27.6 nDCG@10，表现逊于强力的纯文本检索器。我们认为瓶颈不在于检索器，而在于查询本身——原始多模态查询将视觉描述、对话噪声和检索意图交织在一起，从而系统性地降低了嵌入相似度。我们提出了 BRIDGE，这是一个由两个组件构成的系统，无需多模态编码器即可解决这种不匹配问题。FORGE（Focused Retrieval Query Generator，聚焦检索查询生成器）是一个通过强化学习训练的查询对齐模型，它将嘈杂的多模态查询提炼为紧凑且经过检索优化的搜索字符串。LENS（Language-Enhanced Neural Search，语言增强神经搜索）是一个推理增强型稠密检索器，在推理密集型检索数据上进行了微调，以处理 FORGE 生成的意图丰富的查询。在 MM-BRIGHT（包含 2,803 个查询，29 个领域）上的评估结果显示，BRIDGE 达到了 29.7 nDCG@10，超过了包括 Nomic-Vision (27.6) 在内的所有多模态编码器基准。当 FORGE 作为即插即用的对齐器应用于 Nomic-Vision 之上时，组合系统的 nDCG@10 达到了 33.3，超过了表现最好的纯文本检索器 (32.2)，这证明了查询对齐是多模态到文本检索中的关键瓶颈。

## Abstract
Multimodal retrieval systems struggle to resolve image-text queries against text-only corpora: the best vision-language encoder achieves only 27.6 nDCG@10 on MM-BRIGHT, underperforming strong text-only retrievers. We argue the bottleneck is not the retriever but the query -- raw multimodal queries entangle visual descriptions, conversational noise, and retrieval intent in ways that systematically degrade embedding similarity. We present \textbf{BRIDGE}, a two-component system that resolves this mismatch without multimodal encoders. \textbf{FORGE} (\textbf{F}ocused Retrieval Query Generato\textbf{r}) is a query alignment model trained via reinforcement learning, which distills noisy multimodal queries into compact, retrieval-optimized search strings. \textbf{LENS} (\textbf{L}anguage-\textbf{E}nhanced \textbf{N}eural \textbf{S}earch) is a reasoning-enhanced dense retriever fine-tuned on reasoning-intensive retrieval data to handle the intent-rich queries FORGE produces. Evaluated on MM-BRIGHT (2,803 queries, 29 domains), BRIDGE achieves \textbf{29.7} nDCG@10, surpassing all multimodal encoder baselines including Nomic-Vision (27.6). When FORGE is applied as a plug-and-play aligner on top of Nomic-Vision, the combined system reaches \textbf{33.3} nDCG@10 -- exceeding the best text-only retriever (32.2) -- demonstrating that \textit{query alignment} is the key bottleneck in multimodal-to-text retrieval. https://github.com/mm-bright/multimodal-reasoning-retrieval

#### 1. 核心问题与研究动机
*   **核心问题**：在多模态到文本（Multimodal-to-Text）检索任务中，现有的视觉-语言模型（VLM）表现往往不如纯文本检索器。
*   **研究动机**：作者认为瓶颈不在于检索器的模型容量，而在于**查询（Query）的表示**。原始的多模态查询通常包含视觉描述、对话噪声和检索意图的复杂交织，这种“噪声”导致嵌入向量的相似度计算失效。
*   **整体含义**：论文提出将多模态检索问题转化为“查询对齐”问题，通过将复杂的图文输入提炼为精简的、检索优化的纯文本搜索字符串，从而利用成熟的纯文本检索生态系统。

#### 2. 方法论
BRIDGE 系统由三个阶段组成，核心包含两个关键组件：
*   **视觉描述生成（Visual Captioning）**：利用 GPT-4o 将查询图像转换为详细的领域感知文本描述，将视觉信息“翻译”为文本。
*   **FORGE（聚焦检索查询生成器）**：
    *   **核心思想**：一个基于 Qwen2.5-7B-Instruct 的查询对齐模型，负责将“原始问题 + 图像描述”提炼为不超过 200 字的紧凑搜索字符串。
    *   **关键技术**：采用**强化学习（RL）**进行训练。使用 **GRPO（组相对策略优化）** 算法，以检索结果的 **nDCG@k** 作为奖励信号（Reward），使模型学习生成能让检索器排位更高的查询，而非简单模仿人类重写。
*   **LENS（语言增强神经搜索）**：
    *   **核心思想**：一个基于 Qwen3-Embedding-4B 的推理增强型稠密检索器。
    *   **技术细节**：在涵盖数学、医学、法律等推理密集型数据集上进行对比学习微调，专门处理 FORGE 生成的意图丰富的查询。
*   **流程**：图像 $\rightarrow$ 文本描述 $\rightarrow$ FORGE 提炼 $\rightarrow$ LENS 检索 $\rightarrow$ 纯文本语料库。推理时无需多模态编码器。

*   **数据集**：**MM-BRIGHT**，这是首个推理密集型多模态检索基准，包含 2,803 个查询，涵盖 29 个技术领域（如化学、法律、计算机科学等）。
*   **Benchmark 评价指标**：主要使用 **nDCG@10**。
*   **对比方法**：
    *   **多模态检索器**：CLIP, SigLIP, Jina-CLIP, Nomic Embed Vision（最强基准）, BGE-VL, GME-Qwen2-VL (2B/7B)。
    *   **查询重写方法**：HyDE, Query2Doc, 以及基于 GPT-4o 的零样本重写。

#### 4. 资源与算力
*   **硬件**：使用了 **4 张 NVIDIA H100 80GB GPU**。
*   **训练细节**：
    *   采用分布式数据并行训练。
    *   FORGE 和 LENS 均训练了 **3 个 Epoch**。
    *   FORGE 训练时 GRPO 每组采样 8 个 Rollout。
    *   视觉描述生成（GPT-4o）为离线预处理。

#### 5. 实验数量与充分性
*   **实验规模**：在 29 个不同领域进行了详尽的性能评估。
*   **消融实验**：
    *   验证了 BRIDGE 各组件（描述、SFT 重写、RL 对齐）的增量贡献。
    *   测试了不同参数规模（3B 到 72B）的 LLM 作为 FORGE 后端的效果。
    *   **即插即用实验**：将 FORGE 应用于 BM25、Nomic-Vision 等其他检索器，验证了其通用性。
*   **充分性评价**：实验设计非常充分且客观。通过跨领域对比和多种基准模型的横向评测，有力证明了“查询对齐”比“增加模型容量”更有效。

#### 6. 主要结论与发现
*   **性能超越**：BRIDGE 达到了 29.7 nDCG@10，超过了所有多模态编码器基准（如 Nomic-Vision 的 27.6）。
*   **缩小差距**：将多模态与纯文本检索之间的性能差距缩小了 46%。
*   **即插即用价值**：FORGE + Nomic-Vision 的组合达到了 33.3 nDCG@10，甚至超过了最强的纯文本检索器（32.2）。
*   **RL 的必要性**：直接针对检索奖励进行强化学习训练的效果显著优于传统的监督微调（SFT）或零样本提示。

#### 7. 优点
*   **架构解耦**：将视觉理解与检索逻辑分离，推理时无需昂贵的视觉编码器，部署更轻量、灵活。
*   **训练创新**：利用 GRPO 算法直接优化检索指标，解决了多模态查询中意图模糊的痛点。
*   **通用性强**：FORGE 可以作为任何现有检索系统的预处理插件，显著提升性能。

#### 8. 不足与局限
*   **依赖外部 API**：视觉描述阶段高度依赖 GPT-4o，这可能带来额外的成本、延迟以及对闭源模型的依赖。
*   **领域差异**：在视觉内容仅起装饰作用的领域（如法律、数学），BRIDGE 的提升相对有限，甚至略逊于某些基准。
*   **推理延迟**：虽然不需要视觉编码器，但增加了一个 LLM 生成查询的步骤，在实时性要求极高的场景下可能存在延迟挑战。
