## 摘要
智能体（Agents）是由大语言模型（LLM）驱动的组件，能够以强大且任意的方式改变环境。由于异步和故障，在生产环境中为智能体的执行提供保障具有挑战性。在本文中，我们提出了一种名为 LogAct 的新抽象，其中每个智能体都是一个播放共享日志的解构状态机。在 LogAct 中，智能体动作在执行前在共享日志中可见；可以通过可插拔、解耦的投票器（voters）在执行前拦截；并在智能体或环境发生故障时实现一致性恢复。LogAct 实现了智能体内省（introspection），允许智能体利用 LLM 推理分析自身的执行历史，进而实现恢复、健康检查和优化的语义变体。在我们的评估中，LogAct 智能体能够高效且正确地从故障中恢复；调试自身性能；优化集群（swarms）中的 Token 使用；并在代表性基准测试中，仅以 3% 的良性效用下降为代价，拦截了目标模型的所有非预期动作。

## Abstract
Agents are LLM-driven components that can mutate environments in powerful, arbitrary ways. Extracting guarantees for the execution of agents in production environments can be challenging due to asynchrony and failures. In this paper, we propose a new abstraction called LogAct, where each agent is a deconstructed state machine playing a shared log. In LogAct, agentic actions are visible in the shared log before they are executed; can be stopped prior to execution by pluggable, decoupled voters; and recovered consistently in the case of agent or environment failure. LogAct enables agentic introspection, allowing the agent to analyze its own execution history using LLM inference, which in turn enables semantic variants of recovery, health check, and optimization. In our evaluation, LogAct agents recover efficiently and correctly from failures; debug their own performance; optimize token usage in swarms; and stop all unwanted actions for a target model on a representative benchmark with just a 3% drop in benign utility.

*   **核心问题**：大语言模型（LLM）驱动的智能体在生产环境中缺乏可靠性保证。由于智能体执行的是异步且具有副作用的任意代码（如删除数据库、修改配置），一旦发生系统故障或产生有害决策，很难进行状态恢复、安全拦截或事后审计。
*   **研究背景**：现有的智能体框架（如 ReAct 或 CodeAct）通常采用命令式循环，缺乏分布式系统中的强一致性保障。传统的容错技术（如 WAL、SMR 或检查点）难以直接应用，因为智能体的动作是开放式的、非确定性的，且操作的是外部环境而非受控的本地状态。
*   **整体含义**：LogAct 提出将智能体重新定义为“在共享日志上运行的状态机”，通过将执行意图持久化到日志中，实现了动作的可观测、可拦截和可恢复。

### 2. 方法论：核心思想与关键技术
*   **核心思想**：将智能体逻辑解构为多个独立组件，通过一个名为 **AgentBus** 的共享日志进行通信和同步。
*   **关键技术细节**：
    *   **AgentBus（共享日志）**：一个持久化、强类型的追加日志。它不仅记录动作，还记录推理输出、投票、决策、邮件消息和策略变更。
    *   **解构状态机**：将智能体分为四个角色：
        1.  **Driver（驱动器）**：负责 LLM 推理并生成“意图”（Intent）。
        2.  **Voter（投票器）**：可插拔组件（基于规则或 LLM），在动作执行前进行安全审查。
        3.  **Decider（决策器）**：根据投票结果决定“提交”或“中止”。
        4.  **Executor（执行器）**：在沙箱中执行已提交的动作。
    *   **智能体内省（Agentic Introspection）**：这是 LogAct 的核心创新。智能体可以利用 LLM 分析自身的 AgentBus 历史记录，实现“语义化恢复”（理解崩溃点并生成补偿代码）和“语义健康检查”（诊断性能瓶颈）。

### 6. 主要结论与发现
*   **安全性**：LogAct 的双投票器机制成功拦截了所有针对环境的攻击动作，且良性任务的效用损失仅为 3%。
*   **容错性**：通过语义化恢复，智能体能够识别已完成的工作并修复导致崩溃的性能 Bug（实验中实现了 290 倍的提速），无需从头开始。
*   **效率优化**：在多智能体集群中，利用内省机制可以减少 41% 的 Token 消耗，并提升 17% 的工作产出。
*   **开销**：LogAct 带来的延迟和存储开销极低，主要耗时仍集中在 LLM 推理阶段。

### 7. 优点
*   **架构解耦**：将执行器与决策器分离，即使执行器被注入攻击，也无法修改投票逻辑，增强了系统鲁棒性。
*   **语义恢复**：超越了传统的字节级恢复，利用 LLM 的理解能力处理复杂的非确定性故障。
*   **高度可扩展**：支持在不重启系统的情况下动态热插拔投票器和更新安全策略。

### 8. 不足与局限
*   **测试复杂性**：由于内省过程依赖 LLM 推理，其输出具有随机性，难以进行确定性的回归测试。
*   **安全上限**：LogAct 只能保证“强制安全性”（即符合投票器逻辑的安全），如果投票器本身存在盲点或被绕过，系统仍面临风险。
*   **并发控制**：论文主要关注单智能体可靠性，对于多个智能体同时修改同一外部环境时的复杂并发冲突，尚未给出详尽的解决方案。
