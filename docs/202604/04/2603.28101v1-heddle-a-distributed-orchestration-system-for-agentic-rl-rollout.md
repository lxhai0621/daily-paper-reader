## 摘要
智能体强化学习（Agentic RL）通过在数据收集采样（rollout）阶段和策略训练阶段之间交替，使大语言模型（LLM）能够解决复杂任务。在采样过程中，智能体生成轨迹，即 LLM 与外部工具之间的多步交互。然而，频繁的工具调用会导致长尾轨迹生成，从而成为采样过程的瓶颈。这源于忽略轨迹上下文的以步为中心（step-centric）的设计，为长尾轨迹生成引发了三个系统问题：排队延迟、干扰开销以及单 token 时间膨胀。我们提出了 Heddle，这是一个以轨迹为中心（trajectory-centric）的系统，旨在优化智能体采样执行的时机、位置和方式。Heddle 集成了三个核心机制：利用运行时间预测和渐进优先级进行轨迹级调度，以最小化累积排队；通过预排序动态规划和工具调用空闲期间的机会性迁移实现轨迹感知放置，以最小化干扰；以及轨迹自适应资源管理器，动态调整模型并行度，在保持短轨迹高吞吐量的同时，加速长尾轨迹的单 token 时间。在多种智能体强化学习工作负载上的评估表明，Heddle 有效消除了长尾瓶颈，与最先进的基准系统相比，端到端采样吞吐量提升高达 2.5 倍。

## Abstract
Agentic Reinforcement Learning (RL) enables LLMs to solve complex tasks by alternating between a data-collection rollout phase and a policy training phase. During rollout, the agent generates trajectories, i.e., multi-step interactions between LLMs and external tools. Yet, frequent tool calls induce long-tailed trajectory generation that bottlenecks rollouts. This stems from step-centric designs that ignore trajectory context, triggering three system problems for long-tail trajectory generation: queueing delays, interference overhead, and inflated per-token time. We propose Heddle, a trajectory-centric system to optimize the when, where, and how of agentic rollout execution. Heddle integrates three core mechanisms: trajectory-level scheduling using runtime prediction and progressive priority to minimize cumulative queueing; trajectory-aware placement via presorted dynamic programming and opportunistic migration during idle tool call intervals to minimize interference; and trajectory-adaptive resource manager that dynamically tunes model parallelism to accelerate the per-token time of long-tail trajectories while maintaining high throughput for short trajectories. Evaluations across diverse agentic RL workloads demonstrate that Heddle effectively neutralizes the long-tail bottleneck, achieving up to 2.5$\times$ higher end-to-end rollout throughput compared to state-of-the-art baselines.

#### 1. 核心问题与研究动机
*   **研究背景**：智能体强化学习（Agentic RL）通过 LLM 与外部工具的多步交互（轨迹生成）来解决复杂任务。采样（Rollout）阶段占据了整个训练时间的 80% 以上。
*   **核心问题**：现有的系统设计是“以步骤为中心”（Step-centric）的，将每一步交互视为独立的推理请求。这导致了严重的**长尾效应（Straggler Effect）**：少数复杂的长轨迹由于频繁的工具调用和多步推理，显著拉长了整个 Batch 的完成时间，导致 GPU 资源在等待这些“掉队者”时大量闲置。
*   **瓶颈分析**：论文将采样延迟分解为三个维度：排队延迟（何时执行）、干扰开销（何处执行）以及单 Token 时间（如何分配资源）。

#### 2. 核心方法论：以轨迹为中心的设计
Heddle 提出了从“步骤”转向“轨迹”的编排思路，核心技术包括：
*   **轨迹级调度（When）**：
    *   **渐进式轨迹预测**：利用轻量级模型（如 Qwen-0.6B）在每一步交互后动态更新剩余轨迹长度的预测。
    *   **渐进优先级调度（PPS）**：根据预测长度赋予长轨迹更高优先级，并支持抢占式执行，确保长尾任务优先处理以减少累积排队时间。
*   **轨迹感知放置（Where）**：
    *   **预排序动态规划（DP）**：基于引理（最优划分应是排序后的连续子序列），通过 DP 算法将轨迹分配到不同 Worker，最小化长轨迹受到的计算干扰。
    *   **机会性状态迁移**：利用工具调用的空闲时间，通过 GPU-Direct RDMA 异步迁移 KV Cache，在不阻塞执行路径的情况下纠正初始放置偏差。
*   **轨迹自适应资源管理（How）**：
    *   **异构并行度分配**：打破传统的同构配置，为长尾轨迹分配高模型并行度（MP）以降低延迟，为短轨迹分配低 MP 以保持高吞吐。
    *   **排序初始化模拟退火**：快速搜索近乎最优的 GPU 资源分配方案。

#### 6. 主要结论与发现
*   **性能提升**：Heddle 在不同负载下比 Verl 提升 1.4x–2.3x，比 Slime 提升 1.2x–2.5x。
*   **规模效应**：随着模型参数量增大（如从 8B 到 32B），长尾轨迹带来的干扰更严重，Heddle 的优化效果越明显。
*   **预测价值**：即使初始预测不完全准确，通过每一步的“渐进式”修正和“机会性”迁移，依然能显著优化最终的 Makespan。

#### 7. 优点
*   **视角创新**：敏锐捕捉到 Agentic RL 中“步骤”与“轨迹”的语义鸿沟，提出了以轨迹为中心的系统抽象。
*   **机制协同**：调度、放置、资源分配三个模块环环相扣，全方位解决了长尾瓶颈。
*   **开销隐藏**：巧妙利用工具调用的“天然空闲期”进行预测和迁移，实现了近乎零成本的动态优化。

#### 8. 不足与局限
*   **预测模型依赖**：虽然预测模型轻量，但仍需针对特定任务的轨迹数据进行微调，对于完全未知的任务可能存在冷启动问题。
*   **异构管理复杂度**：动态调整模型并行度（MP）在超大规模集群中可能会带来更复杂的显存碎片管理和通信拓扑挑战。
*   **工具调用假设**：该系统高度依赖于“存在工具调用空闲期”这一假设，如果智能体任务主要是纯推理而无外部工具交互，迁移开销将无法被掩盖。
