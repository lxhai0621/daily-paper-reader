## 摘要
上下文强化学习 (ICRL) 使大语言模型 (LLMs) 能够直接在上下文窗口内从外部奖励中进行在线学习。然而，ICRL 的一个核心挑战是奖励估计，因为模型在推理过程中通常无法获取真实标签 (ground-truths)。为了解决这一局限性，我们提出了 TR-ICRL (Test-Time Rethinking for In-Context Reinforcement Learning)，这是一种专为推理和知识密集型任务设计的新型 ICRL 框架。TR-ICRL 首先针对给定查询从无标签评估集中检索最相关的实例。在每次 ICRL 迭代期间，LLM 为每个检索到的实例生成一组候选答案。接着，通过多数投票从该集合中推导出伪标签。该标签随后作为代理提供奖励信息并生成形成性反馈，引导 LLM 进行迭代优化。最后，将这些合成的上下文信息与原始查询整合，形成一个综合提示词，并通过最后一轮多数投票确定最终答案。TR-ICRL 在主流推理和知识密集型任务上进行了评估，展示了显著的性能提升。值得注意的是，TR-ICRL 在 MedQA 上使 Qwen2.5-7B 的平均性能提升了 21.23%，在 AIME2024 上甚至提升了 137.59%。广泛的消融实验和分析进一步验证了我们方法的有效性和鲁棒性。我们的代码可在 https://github.com/pangpang-xuan/TR_ICRL 获取。

## Abstract
In-Context Reinforcement Learning (ICRL) enables Large Language Models (LLMs) to learn online from external rewards directly within the context window. However, a central challenge in ICRL is reward estimation, as models typically lack access to ground-truths during inference. To address this limitation, we propose Test-Time Rethinking for In-Context Reinforcement Learning (TR-ICRL), a novel ICRL framework designed for both reasoning and knowledge-intensive tasks. TR-ICRL operates by first retrieving the most relevant instances from an unlabeled evaluation set for a given query. During each ICRL iteration, LLM generates a set of candidate answers for every retrieved instance. Next, a pseudo-label is derived from this set through majority voting. This label then serves as a proxy to give reward messages and generate formative feedbacks, guiding LLM through iterative refinement. In the end, this synthesized contextual information is integrated with the original query to form a comprehensive prompt, with the answer determining through a final round of majority voting. TR-ICRL is evaluated on mainstream reasoning and knowledge-intensive tasks, where it demonstrates significant performance gains. Remarkably, TR-ICRL improves Qwen2.5-7B by 21.23% on average on MedQA and even 137.59% on AIME2024. Extensive ablation studies and analyses further validate the effectiveness and robustness of our approach. Our code is available at https://github.com/pangpang-xuan/TR_ICRL.

### 1. 核心问题与整体含义（研究动机和背景）
*   **核心问题**：上下文强化学习（In-Context Reinforcement Learning, ICRL）允许大模型在不更新参数的情况下通过上下文中的奖励信号进行在线学习。然而，在**推理阶段（Test-Time）**，外部环境通常无法提供真实标签（Ground-truth），导致模型难以获得准确的奖励信号来引导自我改进。
*   **研究动机**：受 OpenAI o1 等模型通过增加推理时计算量（Test-Time Scaling）提升性能的启发，作者探讨如何将推理时缩放与 ICRL 结合，在无标签的情况下实现自主策略优化。

### 2. 方法论：TR-ICRL 框架
TR-ICRL 包含三个主要阶段，旨在通过无监督的方式构建反馈循环：
*   **上下文检索（Context Retrieval）**：针对目标查询（Query），从无标签的评估集中检索 $N$ 个语义最相关的实例作为 ICRL 的演示样本。
*   **测试时迭代反思（Test-Time Iterative Rethinking）**：
    *   **Rollout（采样）**：对每个检索到的问题进行 $K$ 次并行采样，生成多个推理路径。
    *   **伪标签生成**：利用**多数投票（Majority Voting）**从 $K$ 个答案中选出共识答案作为“伪标签”。
    *   **奖励与反馈**：将每个采样答案与伪标签对比，生成二元奖励信号（正确/错误）。随后，LLM 根据奖励信息生成纠错反馈（Feedback），诊断推理错误。
    *   **内存更新**：将（问题、答案、奖励、反馈）存入上下文，作为后续推理的参考。
*   **自一致性聚合（Self-Consistent Aggregation）**：将积累了 $N$ 轮反思经验的上下文与原始查询结合，进行最终推理，并通过多数投票确定最终答案。

### 3. 实验设计
*   **数据集/场景**：
    *   **数学推理**：MATH500, AMC, GSM8K, 以及高难度的 AIME2024, AIME2025。
    *   **知识密集型任务**：医学领域的 MedQA, MedXpertQA。
*   **对比方法（Baselines）**：
    *   基础模型（Zero-shot CoT）。
    *   推理时缩放方法：Best-of-N (BoN) 采样、Self-Refine、Reflexion。
*   **评估模型**：Qwen2.5-7B-Instruct, Llama3.1-8B-Instruct, 以及大语言推理模型（LRMs）如 Qwen3-8B 和 DeepSeek-R1-Qwen3-8B。

*   **硬件**：使用了 **2 张 NVIDIA A100 (80GB) GPU** 进行在线推理。
*   **推理框架**：采用 **vLLM** 提升推理效率。
*   **参数设置**：采样温度 0.6，top_p 0.8，最大生成长度 8192 tokens。每个检索问题采样 8 次以生成伪标签。

### 5. 实验数量与充分性
*   **实验规模**：涵盖了从 7B 到 8B 的多个指令微调模型和推理模型，并在 7 个主流基准测试上进行了验证。
*   **消融实验**：非常充分。作者测试了检索质量（随机、最小相似度、跨领域）、上下文顺序（相似度升序/降序）、以及“伪造奖励（Spurious Reward）”对性能的影响。
*   **公平性**：通过固定计算预算（FLOPs）对比了 7B 模型（使用 TR-ICRL）与 72B 大模型的性能，确保了对比的客观性。

### 6. 主要结论与发现
*   **显著提升**：TR-ICRL 在所有任务上均表现出色。Qwen2.5-7B 在 AIME2024 上的准确率提升了 **137.59%**，在 MedQA 上提升了 **21.23%**。
*   **“幸运奖励”现象（Lucky Reward）**：即使多数投票产生的伪标签本身是错误的，只要它与模型当前的错误答案不同，仍能提供正确的负反馈信号。实验显示，在 AIME2024 上，尽管标签准确率仅 16.56%，但奖励准确率高达 71.71%。
*   **超越大模型**：经过 TR-ICRL 增强的 7B 模型在数学任务上的表现可以超越参数量大十倍的 72B 模型。

### 7. 优点
*   **完全无监督**：无需任何真实标签或人工标注，纯靠推理时的计算和自我博弈实现提升。
*   **即插即用**：不需要对模型进行微调（Gradient-free），适用于任何具有强推理能力的 LLM。
*   **鲁棒的奖励机制**：通过“幸运奖励”理论解释了为何在低准确率场景下框架依然有效，具有较强的理论说服力。

### 8. 不足与局限
*   **上下文干扰**：随着迭代步数（Step）增加，上下文窗口会堆积大量信息，可能导致模型注意力分散，在某些模型（如 Qwen3-8B）上出现了性能随步数增加而下降的现象。
*   **奖励粒度单一**：目前仅使用二元（对/错）奖励，缺乏更细粒度的评分（如过程奖励 PRM）。
*   **推理开销**：虽然不需要训练，但推理时的多次采样（Rollout）和长上下文会显著增加 Token 消耗和响应延迟。
