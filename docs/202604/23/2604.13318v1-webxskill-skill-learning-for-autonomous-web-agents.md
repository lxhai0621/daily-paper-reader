## 摘要
由大语言模型（LLM）驱动的自主网络智能体在完成复杂浏览器任务方面展现出巨大潜力，但仍难以应对长程工作流。一个关键瓶颈在于现有技能表述中的具身鸿沟：文本工作流技能提供自然语言指导但无法直接执行，而基于代码的技能虽可执行但对智能体而言是不透明的，无法提供用于错误恢复或自适应的步骤级理解。我们提出了 WebXSkill，这是一个通过可执行技能弥合这一差距的框架，每项技能都将参数化的动作程序与步骤级自然语言指导相结合，从而实现直接执行和智能体驱动的自适应。WebXSkill 分三个阶段运行：技能提取从现有的合成智能体轨迹中挖掘可重用的动作子序列，并将其抽象为参数化技能；技能组织将技能索引到基于 URL 的图中，以进行上下文感知检索；技能部署提供两种互补模式：用于全自动多步执行的具身模式，以及技能作为步骤指令供智能体通过其原生规划来遵循的引导模式。在 WebArena 和 WebVoyager 上，WebXSkill 的任务成功率分别比基准提高了 9.8 和 12.9 个百分点，证明了可执行技能对网络智能体的有效性。代码已在 https://github.com/aiming-lab/WebXSkill 公开。

## Abstract
Autonomous web agents powered by large language models (LLMs) have shown promise in completing complex browser tasks, yet they still struggle with long-horizon workflows. A key bottleneck is the grounding gap in existing skill formulations: textual workflow skills provide natural language guidance but cannot be directly executed, while code-based skills are executable but opaque to the agent, offering no step-level understanding for error recovery or adaptation. We introduce WebXSkill, a framework that bridges this gap with executable skills, each pairing a parameterized action program with step-level natural language guidance, enabling both direct execution and agent-driven adaptation. WebXSkill operates in three stages: skill extraction mines reusable action subsequences from readily available synthetic agent trajectories and abstracts them into parameterized skills, skill organization indexes skills into a URL-based graph for context-aware retrieval, and skill deployment exposes two complementary modes, grounded mode for fully automated multi-step execution and guided mode where skills serve as step-by-step instructions that the agent follows with its native planning. On WebArena and WebVoyager, WebXSkill improves task success rate by up to 9.8 and 12.9 points over the baseline, respectively, demonstrating the effectiveness of executable skills for web agents. The code is publicly available at https://github.com/aiming-lab/WebXSkill.

### 1. 核心问题与整体含义（研究动机和背景）
*   **核心问题**：大语言模型（LLM）驱动的网页智能体在处理长流程任务时表现脆弱，主要因为它们缺乏对交互知识的保留与复用，每次遇到重复流程（如购物结算、后台管理）都需从头规划。
*   **具身鸿沟（Grounding Gap）**：
    *   **文本工作流技能**：提供自然语言指导但不可直接执行，容易产生落地误差。
    *   **代码/脚本技能**：可执行但对智能体是“黑盒”，一旦执行中途出错，智能体无法理解步骤或进行自适应恢复。
*   **研究目标**：提出 **WebXSkill** 框架，通过将“参数化动作程序”与“步骤级自然语言指导”配对，构建既可直接执行又可被智能体理解的“可执行技能”。

### 2. 方法论：核心思想与关键技术
WebXSkill 包含三个关键阶段：
*   **技能提取（Skill Extraction）**：
    *   从低成本的合成智能体轨迹中挖掘重复的动作子序列。
    *   利用 LLM 将具体动作抽象为带参数的技能（如将特定搜索词改为 `query: str` 参数）。
    *   **技能精炼**：通过在线去重（语义相似度）和环境验证（确保动作序列在浏览器中不报错）来保证技能质量。
*   **技能组织（Skill Organization）**：
    *   **技能图谱（Skill Graph）**：基于 URL 模式（如 `shopping/catalogsearch/*`）对技能进行索引。
    *   **上下文感知检索**：智能体根据当前页面的 URL 和 HTML 元素存在性，从图谱中精准检索相关技能，避免冗余。
*   **技能部署（Skill Deployment）**：
    *   **具身模式（Grounded Mode）**：将技能作为原子工具调用，由系统自动执行动作序列，追求高效率。
    *   **引导模式（Guided Mode）**：将技能转化为步骤指令，由智能体利用原生动作逐步执行，追求高自适应能力。

### 3. 实验设计

### 6. 主要结论与发现
*   **性能提升**：WebXSkill 在 WebArena 上比基准提升 9.8 个百分点，在 WebVoyager 上提升 12.9 个百分点。
*   **模式适配**：强模型（如 GPT-5）在“具身模式”下效率最高；而弱模型（如 Qwen）在“引导模式”下表现更好，因为步骤指导能弥补其规划能力的不足。
*   **跨环境迁移**：在 WebArena 提取的技能可以直接引导智能体在 WebVoyager（真实网站）上完成任务，证明了引导模式的泛化性。

### 7. 优点
*   **弥合鸿沟**：首次将可执行代码与自然语言步骤指导结合，解决了技能“好用但看不懂”或“看得懂但难落地”的问题。
*   **双模式灵活部署**：提供了效率（具身）与自主性（引导）之间的权衡方案。
*   **低成本获取**：利用合成轨迹而非昂贵的真实人类演示或大规模自主探索来获取技能。
*   **结构化组织**：通过 URL 技能图谱解决了大规模技能库下的检索噪声问题。

### 8. 不足与局限
*   **模型依赖**：技能的使用仍高度依赖骨干模型的基础推理能力，较小的模型（如 7B/14B 级别）可能难以有效利用这些技能。

*   **动态环境挑战**：虽然有引导模式，但在网页布局发生剧烈变化时，预定义的动作序列（Element Ref）仍可能失效。
