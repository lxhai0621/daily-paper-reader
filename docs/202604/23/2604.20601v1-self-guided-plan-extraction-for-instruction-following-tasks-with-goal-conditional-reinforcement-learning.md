## 摘要
我们介绍了 SuperIgor，这是一个用于指令遵循任务的框架。与以往依赖预定义子任务的方法不同，SuperIgor 使语言模型能够通过自学习机制生成并优化高层规划，从而减少了对手动数据集标注的需求。我们的方法涉及迭代协同训练：训练强化学习（RL）智能体以遵循生成的规划，同时语言模型根据 RL 的反馈和偏好调整并修改这些规划。这创建了一个反馈循环，使智能体和规划器能够共同提升。我们在具有丰富动力学特性和随机性的环境中验证了我们的框架。结果表明，SuperIgor 智能体比基线方法更严格地遵循指令，同时也展现出对先前未见指令的强大泛化能力。

## Abstract
We introduce SuperIgor, a framework for instruction-following tasks. Unlike prior methods that rely on predefined subtasks, SuperIgor enables a language model to generate and refine high-level plans through a self-learning mechanism, reducing the need for manual dataset annotation. Our approach involves iterative co-training: an RL agent is trained to follow the generated plans, while the language model adapts and modifies these plans based on RL feedback and preferences. This creates a feedback loop where both the agent and the planner improve jointly. We validate our framework in environments with rich dynamics and stochasticity. Results show that SuperIgor agents adhere to instructions more strictly than baseline methods, while also demonstrating strong generalization to previously unseen instructions.

在人工智能领域，使智能体遵循自然语言指令完成任务（Instruction Following）是一个核心挑战。现有方法主要分为两类：**基于演示的学习**（依赖昂贵的专家数据，难以扩展）和**基于经验的学习**（如强化学习，但在长程任务和稀疏奖励下表现不佳）。
现有的规划方法通常假设存在预定义的子任务库，这限制了其在开放、动态环境中的应用。本文提出了 **SuperIgor** 框架，旨在解决如何在**没有预定义技能库**且**仅有稀疏奖励**的情况下，让智能体自主从指令中提取高层规划并学习执行。

#### 2. 方法论：核心思想与关键技术
SuperIgor 采用了一种**迭代协同训练（Co-training）**的闭环机制，主要包含以下四个阶段：
*   **自引导计划生成（Plan Generation）：** 利用大语言模型（LLM）从指令中提取可能的子任务，构建子任务本体（Ontology），并根据前置依赖关系将复杂指令展开为线性规划序列。
*   **策略学习（Policy Learning）：** 使用 PPO 算法训练 RL 智能体。为了解决稀疏奖励问题，引入了**技能课程学习（Skill Curriculum Learning）**：智能体先学习简单的单步任务，只有当某项技能的成功率达到阈值（如 0.7）后，才将其加入更复杂的组合任务规划中。
*   **计划验证（Plan Validation）：** 智能体在环境中多次执行生成的规划，收集成功率等性能指标作为反馈信号。
*   **LLM 微调（LLM Fine-Tuning）：** 利用 **直接偏好优化（DPO）**，根据智能体的实际执行表现对 LLM 进行微调。这使得 LLM 能够学习并优先生成那些智能体更容易理解和执行的高质量规划。

*   **超越基线：** SuperIgor 在原子任务和组合任务上的成功率显著高于 PPO-T 和 FiLM 等传统基线。

#### 7. 优点
*   **无需人工标注：** 实现了从指令到执行的端到端自监督学习，极大降低了数据获取成本。
*   **动态对齐：** 规划器（LLM）能根据执行器（RL）的反馈进行自我进化，解决了“规划可行但执行不了”的脱节问题。
*   **鲁棒性：** 对指令的语言多样性（释义）具有很强的抵抗力。

#### 8. 不足与局限
*   **初始规划依赖：** 框架性能高度依赖于初始 LLM 生成子任务本体的质量。如果 LLM 无法正确理解环境逻辑，后续学习会受阻。
*   **本体冗余：** 自动生成的子任务库可能存在同义词冗余或循环依赖，虽然算法有一定容错，但仍可能影响效率。
*   **可解释性挑战：** 当训练停滞时，难以明确区分是 RL 探索不足还是 LLM 规划逻辑错误导致的。
*   **计算开销：** 尽管比人工标注便宜，但多轮迭代训练仍需要大量的 GPU 算力支持。
