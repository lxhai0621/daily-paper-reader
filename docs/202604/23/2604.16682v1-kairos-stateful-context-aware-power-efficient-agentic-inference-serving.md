## 摘要
功耗已成为 AI 推理的核心瓶颈。随着智能体 AI（agentic AI）成为一种主要的工作负载类型，这一问题变得愈发紧迫，然而先前的功耗管理技术几乎完全集中在单轮 LLM 服务上。我们的分析表明，智能体服务的行为模式有着本质的不同：每个请求都携带长期的上下文，并在工具交织的多轮交互中不断演进；此外，降低 GPU 频率可能会使系统陷入抖动（thrashing）状态，此时内存压力会急剧恶化性能和能效。这些观察结果表明，智能体服务的功耗优化需要重新思考。我们提出了 KAIROS，这是一个用于智能体 AI 服务的上下文感知功耗优化系统。KAIROS 将智能体上下文作为一级控制信号，协同管理 GPU 频率、单实例并发量以及多实例请求放置。这使得 KAIROS 能够在存在内存余量时节省功耗，同时避免系统抖动并维持性能目标。从高层设计来看，KAIROS 以智能体粒度跟踪请求，根据上下文增长和智能体进度调整本地控制，并在不同实例间路由智能体，以共同提高能效和内存稳定性。在多种软件和数据工程智能体任务上的评估结果显示，KAIROS 在满足性能目标的同时，实现了平均 27%（最高达 39.8%）的功耗降低。

## Abstract
Power has become a central bottleneck for AI inference. This problem is becoming more urgent as agentic AI emerges as a major workload class, yet prior power-management techniques focus almost entirely on single-turn LLM serving. Our analysis shows that agentic serving behaves fundamentally differently: each request carries long-lived context that evolves across tool-interleaved turns, and lowering GPU frequency can push the system into a thrashing regime where memory pressure sharply worsens both performance and power efficiency. These observations show that power optimization for agentic serving requires rethinking.   We present KAIROS, a context-aware power optimization system for agentic AI serving. KAIROS uses agent context as a first-class control signal to jointly manage GPU frequency, per-instance concurrency, and multi-instance request placement. This enables KAIROS to save power when memory headroom exists while avoiding thrashing and preserving performance targets. At a high level, KAIROS tracks requests at agent granularity, adapts local control to context growth and agent progress, and routes agents across instances to jointly improve power efficiency and memory stability. Evaluated across diverse software and data engineering agentic tasks, KAIROS achieves an average of 27% (up to 39.8%) power reduction while meeting the performance targets.

### 1. 核心问题与研究动机
*   **背景：** 智能体 AI（如自动编程、数据分析智能体）正成为主流工作负载。与传统的单轮 LLM 推理不同，智能体推理是**有状态的**，涉及多轮工具调用，且每个请求的上下文（KV Cache）会随时间动态增长并长期驻留。
*   **核心问题：** 
    1.  **功耗瓶颈：** 智能体推理的功耗比单轮推理高出 2-3 个数量级。
    2.  **传统方案失效：** 传统的动态电压频率调整（DVFS）在智能体场景下可能引发“**系统抖动（Thrashing）**”——降低频率会导致执行变慢，使得上下文在内存中驻留时间变长，最终超出 GPU 显存容量，迫使系统进行重计算或内存交换，反而大幅降低能效和性能。
    3.  **动态性挑战：** 智能体的生命周期、轮数和上下文增长率具有长尾分布，难以静态预测。

### 2. 方法论：KAIROS 系统设计
KAIROS 将**智能体上下文（Context）**作为一级控制信号，通过三个核心组件协同优化：
*   **智能体 ID 追踪器（Agent ID Tracker）：** 在不修改用户程序的前提下，通过轻量级包装器为每个智能体分配 ID，使推理后端能够识别并跟踪跨多轮交互的长效工作流。
*   **上下文感知的单实例控制器：**
    *   **频率控制：** 根据当前显存中总上下文占用率动态调整 GPU 频率。显存充足时降频省电；显存压力大时升频以加速任务完成并释放内存。
    *   **SLO 驱动的频率加速：** 实时监测每个智能体的吞吐量（tokens/s），若低于预设 SLO 目标，则强制提升频率。
    *   **防抖动并发控制：** 设定显存安全阈值，当预测到新智能体加入会导致显存溢出时，延迟其准入，避免陷入重计算的抖动状态。
*   **全局上下文感知路由器：**
    *   **负载整合：** 在低负载时将请求集中到少数 GPU 实例，让其他 GPU 处于低功耗待机状态。
    *   **负载均衡：** 在高上下文压力下，将新智能体路由至显存余量最大的实例，防止局部抖动。

### 3. 实验设计
*   **数据集/场景：**
    1.  **SWE-bench Verified：** 软件工程任务（修复 GitHub Issue）。
    2.  **DABStep：** 现实世界的数据分析任务。
    3.  **Terminal-Bench 2.0：** 复杂的命令行操作任务。
*   **智能体框架：** 使用了 `mini-swe-agent` 和 `Terminus-2` 两种不同架构的智能体。
*   **对比基准（Baselines）：**
    *   无频率控制（始终最高频率运行）。
    *   固定低频率（如 810MHz）。
    *   轮询调度（Round Robin）路由。
*   **性能指标：** 采用基于吞吐量的 SLO（如 P5 吞吐量 ≥ 20 tokens/s），认为这比单轮推理的延迟指标（TTFT/TBT）更能反映智能体的任务进度。

### 4. 资源与算力
*   **硬件：** 使用了 **NVIDIA H100 NVL** GPU（80GB 显存），配以 Intel Xeon Platinum 8592+ CPU。
*   **模型：** 主要使用 **Qwen3-Coder-30B**（FP8 量化），辅助测试了 **Ministral-3-14B**。
*   **软件栈：** 基于 vLLM (v0.14.0) 推理引擎，使用 Zeus 框架进行频率控制和功耗测量。
*   **时长：** 实验在 3 小时的窗口内运行，以捕捉长程上下文的动态演进。

### 5. 实验数量与充分性
*   **实验规模：** 涵盖了 3 个主流数据集、2 种智能体类型、2 种不同规模的模型，并在单实例和多实例（4 个 GPU）场景下进行了测试。
*   **消融实验：** 专门针对“防抖动机制”和“SLO 提升机制”进行了有效性验证，展示了在不同 SLO 目标（20/35/45 tokens/s）下的表现。
*   **客观性：** 通过录制并回放真实智能体请求序列，确保了不同方法在完全相同的输入负载（Token 分布、到达时间）下进行公平对比。

### 6. 主要结论与发现
*   **节能效果：** 在单实例场景下，KAIROS 平均降低功耗 **27%**（最高 39.8%）；在多实例场景下，通过负载整合实现了 **46.3%** 的功耗降低。
*   **性能维持：** 在大幅省电的同时，KAIROS 能够稳定维持预设的吞吐量 SLO，而固定降频方案会导致严重的 SLO 违规。
*   **稳定性：** 成功证明了通过并发控制可以有效避免显存抖动，维持系统在高负载下的吞吐量平稳。

### 7. 优点
*   **视角独特：** 首次识别并量化了智能体推理中“功耗-频率-内存稳定性”之间的复杂耦合关系。
*   **指标创新：** 提出了更符合智能体特性的“基于吞吐量的 SLO”评价体系。
*   **实用性强：** 采用非侵入式的 ID 追踪，无需修改现有的智能体代码或复杂的语义分析。

### 8. 不足与局限
*   **硬件依赖：** 实验主要基于 H100，不同架构的 GPU（如 L40S 或 A100）其功耗曲线和频率响应可能不同，泛化性有待更多硬件验证。
*   **模型架构限制：** 主要针对 ReAct 风格智能体，对于具有更复杂分支搜索（如 Tree-of-Thought）或超长生命周期的智能体，其上下文管理可能更具挑战。
*   **离线回放：** 虽然回放保证了公平，但真实环境中的智能体可能会根据 LLM 的响应速度改变后续行为（即反馈回路），这一点在离线实验中难以完全模拟。
