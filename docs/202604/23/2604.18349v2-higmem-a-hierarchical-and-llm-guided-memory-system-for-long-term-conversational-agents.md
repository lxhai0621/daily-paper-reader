## 摘要
长期对话大语言模型（LLM）智能体需要能够从历史交互中恢复相关证据的记忆系统，同时又不会让无关上下文淹没回答阶段。然而，现有的记忆系统（包括分层系统）通常仍仅依赖向量相似度进行检索。这往往会导致证据集臃肿：添加许多表面相似的对话轮次几乎不会增加召回率，反而会降低检索精度，增加回答阶段的上下文成本，并使检索到的记忆难以检查和管理。为解决这一问题，我们提出了 HiGMem（分层且由大语言模型引导的记忆系统），这是一种两级“事件-轮次”记忆系统，允许 LLM 将事件摘要作为语义锚点，以预测哪些相关的轮次值得阅读。这使得模型能够先检查高层级的事件摘要，然后专注于较小的一组潜在有用轮次，通过推理提供简洁且可靠的证据集，同时避免了与向量检索相比过高的检索开销。在 LoCoMo10 基准测试中，HiGMem 在五个问题类别中的四个上取得了最佳 F1 分数，并将对抗性 F1 分数从 A-Mem 的 0.54 提高到 0.78，同时检索的轮次减少了一个数量级。代码已在 https://github.com/ZeroLoss-Lab/HiGMem 公开。

## Abstract
Long-term conversational large language model (LLM) agents require memory systems that can recover relevant evidence from historical interactions without overwhelming the answer stage with irrelevant context. However, existing memory systems, including hierarchical ones, still often rely solely on vector similarity for retrieval. It tends to produce bloated evidence sets: adding many superficially similar dialogue turns yields little additional recall, but lowers retrieval precision, increases answer-stage context cost, and makes retrieved memories harder to inspect and manage. To address this, we propose HiGMem (Hierarchical and LLM-Guided Memory System), a two-level event-turn memory system that allows LLMs to use event summaries as semantic anchors to predict which related turns are worth reading. This allows the model to inspect high-level event summaries first and then focus on a smaller set of potentially useful turns, providing a concise and reliable evidence set through reasoning, while avoiding the retrieval overhead that would be excessively high compared to vector retrieval. On the LoCoMo10 benchmark, HiGMem achieves the best F1 on four of five question categories and improves adversarial F1 from 0.54 to 0.78 over A-Mem, while retrieving an order of magnitude fewer turns. Code is publicly available at https://github.com/ZeroLoss-Lab/HiGMem.

在长期对话场景中，智能体需要从海量的历史交互中提取相关信息。现有的记忆系统（如传统的 RAG 或 A-Mem）主要依赖**向量相似度检索**。这种方式存在显著缺陷：
*   **证据集臃肿**：为了保证召回率，系统往往会检索出大量语义相似但事实无关的对话片段。
*   **精度与成本矛盾**：冗余的上下文不仅降低了回答的精准度，还大幅增加了大模型（LLM）处理长文本的计算成本。
*   **缺乏推理**：纯向量检索无法像人类一样通过理解“事件”的逻辑来筛选关键细节。

**HiGMem** 的提出旨在通过“分层结构”和“LLM 引导推理”相结合，实现高召回、高精度且低成本的记忆检索。

#### 2. 方法论：核心思想与技术细节
HiGMem 采用了一种**两级（事件-轮次）分层架构**，将记忆组织从扁平化转为结构化：

*   **分层架构设计**：
    *   **轮次层（Turn Layer）**：存储原始对话及 LLM 生成的元数据（关键词、标签、时间戳、上下文摘要）。
    *   **事件层（Event Layer）**：将相关的对话轮次聚合成“事件节点”，包含简短摘要和结构化事实表（Fact Sheet），作为检索的语义锚点。
*   **记忆构建流程**：
    1.  **轮次分析**：新对话进入时，LLM 提取元数据。
    2.  **事件关联与更新**：通过向量相似度寻找候选事件，由 LLM 决定是将新轮次归入现有事件还是创建新事件，并动态更新事件摘要。
*   **LLM 引导的检索策略**：
    1.  **双层检索**：根据查询关键词，同时从事件层和轮次层检索候选节点。
    2.  **推理预测**：LLM 检查检索到的事件摘要，预测哪些关联的对话轮次真正包含答案。
    3.  **精细过滤**：将预测的轮次与语义检索的轮次合并，再次通过 LLM 过滤，形成最终的精简证据集。

#### 6. 主要结论与发现
*   **性能卓越**：HiGMem 在 LoCoMo10 的五个类别中有四个取得最佳 F1，尤其在**对抗性问题**上，F1 从 0.54 提升至 0.78。

#### 7. 优点
*   **精准定位**：利用事件摘要作为“语义锚点”，通过 LLM 推理而非单纯的向量匹配来定位证据，有效解决了语义漂移问题。
*   **结构化管理**：两级架构使得记忆更易于检查、追溯和管理。
*   **经济性**：通过“以推理换空间”的策略，显著降低了昂贵长上下文模型的调用成本。

#### 8. 不足与局限
*   **时间开销**：由于在检索过程中引入了多次 LLM 推理调用，响应延迟（Latency）高于纯向量检索方法。
*   **多方对话挑战**：在 DialSim 数据集的测试中，F1 表现略逊于 A-Mem，表明目前的事件-轮次结构在处理复杂的多人交互逻辑时仍有优化空间。
*   **依赖模型能力**：系统的有效性高度依赖于中间层 LLM 的推理和判断能力，若中间模型出现幻觉，会直接影响最终证据的质量。
