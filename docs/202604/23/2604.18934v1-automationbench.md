## 摘要
现有的软件自动化 AI 基准测试很少能同时兼顾跨应用协作、自主 API 发现和策略遵循。真实的业务工作流对这三者都有需求：单个任务可能跨越 CRM、收件箱、日历和即时通讯平台，要求智能体寻找正确的端点、遵循策略文档，并将正确的数据写入各个系统。为了填补这一空白，我们提出了 AutomationBench，这是一个用于评估 AI 智能体通过 REST API 进行跨应用工作流编排能力的基准测试。该基准测试借鉴了 Zapier 平台的真实工作流模式，任务涵盖销售、营销、运营、支持、财务和人力资源等领域。智能体必须自行发现相关端点，遵循分层的业务规则，并在包含无关甚至误导性记录的环境中进行导航。评分采用程序化方式且仅基于最终状态：即正确的数据是否最终进入了正确的系统。目前即使是最顶尖的前沿模型得分也低于 10%。AutomationBench 提供了一个具有挑战性且真实的衡量标准，用于评估当前模型与企业实际所需的智能体能力之间的差距。

## Abstract
Existing AI benchmarks for software automation rarely combine cross-application coordination, autonomous API discovery, and policy adherence. Real business workflows demand all three: a single task may span a CRM, inbox, calendar, and messaging platform - requiring the agent to find the right endpoints, follow a policy document, and write correct data to each system. To address this gap, we introduce AutomationBench, a benchmark for evaluating AI agents on cross-application workflow orchestration via REST APIs. Drawing on real workflow patterns from Zapier's platform, tasks span Sales, Marketing, Operations, Support, Finance, and HR domains. Agents must discover relevant endpoints themselves, follow layered business rules, and navigate environments with irrelevant and sometimes misleading records. Grading is programmatic and end-state only: whether the correct data ended up in the right systems. Even the best frontier models currently score below 10%. AutomationBench provides a challenging, realistic measure of where current models stand relative to the agentic capabilities businesses actually need.

### 2. 论文提出的方法论
**核心思想：**
AutomationBench 构建了一个基于 REST API 的模拟环境，要求智能体通过自然语言指令完成跨应用任务。其核心设计包含：
*   **自主 API 发现：** 智能体不直接获得任务所需的工具，而是通过 `Search`（基于 BM25 的关键字搜索）和 `Execute`（模拟 curl/fetch 请求）两个基础工具，在包含 47 个应用、约 500 个 API 端点的库中自行寻找解决方案。
*   **环境模拟：** 使用 Pydantic 模型作为“事实来源”来模拟应用数据库状态，保留了真实 API 的分页、必填字段和 4xx 错误代码等特征。
*   **端点状态评分（End-State Grading）：** 评分不关注智能体的操作过程或推理文本，而是通过程序化断言（Assertions）检查所有相关系统的最终数据状态是否正确。
*   **任务硬化（Hardening）：** 引入无关数据、诱饵记录、歧义信息和相互冲突的业务政策，以增加推理难度。

### 3. 实验设计
*   **数据集/场景：** 涵盖销售（Sales）、营销（Marketing）、运营（Operations）、支持（Support）、财务（Finance）和人力资源（HR）6 大领域。
*   **任务规模：** 共计 1200+ 个任务，其中 600 个公开用于研究，600+ 个私有用于评估（防止过拟合）。
*   **对比方法（模型）：** 评估了包括 Claude 系列（Opus 4.7, Sonnet 4.6, Haiku 4.5）、Gemini 3.1 Pro 以及 GPT 5.4（含不同推理努力程度的版本）。
*   **基准设置：** 任务是非交互式的（单次指令后自主运行），最大步数限制为 50 步。

### 4. 资源与算力
*   **算力说明：** 论文**未明确说明**训练这些模型所使用的具体 GPU 型号、数量或训练时长（因为主要评估的是现有的闭源前沿模型）。

### 5. 实验数量与充分性
*   **实验规模：** 针对 6 个领域的数百个私有任务进行了单次运行测试（运行间方差小于 1%）。
*   **充分性分析：** 实验设计较为充分。作者不仅对比了不同模型，还通过“提示词辅助模式（Hint sheet）”验证了任务的可解性。此外，还通过 Jaccard 相似度分析了不同模型解决任务的重合度，发现模型间的能力分布具有显著差异。
*   **客观性：** 采用确定性断言而非“LLM-as-a-judge”，消除了模型评分偏见，实验结果客观、公平。

### 6. 论文的主要结论与发现
*   **性能鸿沟：** 即使是目前最顶尖的模型，在 AutomationBench 上的得分也**均低于 10%**（最高分 Opus 4.7 仅为 9.9%）。
*   **主要失败模式：**
    1.  **虚假自信：** 72%-91% 的失败案例中，模型在任务失败时却声称已成功。
    2.  **搜索不彻底：** 无法在复杂环境中持久、有条理地寻找数据。
    3.  **列表处理遗漏：** 在处理包含多个条目（如多封邮件）的任务时，经常只处理部分条目。
    4.  **指令遵循不严：** 忽略特定的格式要求或政策细节。
*   **效率差异：** Gemini 在保持高准确率的同时，成本显著低于其他同级别模型。

### 7. 优点
*   **高度真实：** 任务模式源自 Zapier 真实的业务流反馈，具有极强的实战指导意义。
*   **抗作弊设计：** 强调“端到端结果”和“自主发现”，避免了智能体通过记忆特定工具调用顺序来刷分的可能。
*   **多层复杂度：** 结合了政策遵循、时区陷阱、诱饵数据等多种干扰因素，能有效区分模型的深度推理能力。

### 8. 不足与局限
*   **合成数据风险：** 尽管经过人工审计，但合成生成的任务仍可能存在与现实生产环境细微的脱节或逻辑瑕疵。
*   **主观性限制：** 为了保证评分的确定性，基准测试限制了需要高度主观判断的任务，这可能无法完全覆盖某些需要“软技能”的业务场景。
*   **静态环境：** 虽然模拟了 API，但环境在任务执行期间是静态的，未考虑真实世界中可能出现的并发修改或网络波动。
