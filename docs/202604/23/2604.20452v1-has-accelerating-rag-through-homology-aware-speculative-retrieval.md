## 摘要
检索增强生成（RAG）通过在推理阶段检索外部文档作为上下文，扩展了大语言模型（LLM）的知识边界。然而，随着知识库规模的增长，检索过程变得日益耗时。现有的加速策略要么通过近似检索牺牲准确性，要么通过重用完全相同查询的结果仅获得微小的收益。我们提出了 HaS，一种同源感知投机检索框架，它在受限范围内执行低延迟的投机检索以获取候选文档，随后验证这些文档是否包含所需的知识。该验证基于查询之间的同源关系，被形式化为同源查询重识别任务：一旦之前观察到的查询被识别为当前查询的同源重现，则认为草案（draft）是可接受的，从而允许系统绕过缓慢的全库检索。得益于现实世界流行模式下同源查询的普遍性，HaS 实现了显著的效率提升。广泛的实验表明，HaS 在不同数据集上将检索延迟降低了 23.74% 和 36.99%，而准确率仅有 1-2% 的微小下降。作为一种即插即用的解决方案，HaS 还能显著加速现代智能体 RAG 流水线中的复杂多跳查询。源代码可在以下地址获取：https://github.com/ErrEqualsNil/HaS。

## Abstract
Retrieval-Augmented Generation (RAG) expands the knowledge boundary of large language models (LLMs) at inference by retrieving external documents as context. However, retrieval becomes increasingly time-consuming as the knowledge databases grow in size. Existing acceleration strategies either compromise accuracy through approximate retrieval, or achieve marginal gains by reusing results of strictly identical queries. We propose HaS, a homology-aware speculative retrieval framework that performs low-latency speculative retrieval over restricted scopes to obtain candidate documents, followed by validating whether they contain the required knowledge. The validation, grounded in the homology relation between queries, is formulated as a homologous query re-identification task: once a previously observed query is identified as a homologous re-encounter of the incoming query, the draft is deemed acceptable, allowing the system to bypass slow full-database retrieval. Benefiting from the prevalence of homologous queries under real-world popularity patterns, HaS achieves substantial efficiency gains. Extensive experiments demonstrate that HaS reduces retrieval latency by 23.74% and 36.99% across datasets with only a 1-2% marginal accuracy drop. As a plug-and-play solution, HaS also significantly accelerates complex multi-hop queries in modern agentic RAG pipelines. Source code is available at: https://github.com/ErrEqualsNil/HaS.

随着知识库规模的扩大，检索增强生成（RAG）中的检索环节已成为主要的性能瓶颈，其延迟甚至超过了 LLM 生成首个 Token 的时间。
*   **现有技术的局限性：** 
    *   **近似最近邻搜索（ANNS）：** 虽然快，但通过缩小搜索范围来换取速度，不可避免地导致召回率和准确率下降。
    *   **基于重用的缓存：** 仅在查询语义完全一致时才生效，但在现实中，用户往往会针对同一实体的不同属性提出多样化查询，导致缓存命中率极低。
*   **研究动机：** 借鉴大模型中的“投机采样”思想，提出一种**投机检索**框架。其核心发现是：现实中的查询具有“同源性”（Homology），即大量查询指向相同的实体。如果能快速识别出当前查询与历史查询的同源关系，就可以安全地复用或参考历史检索结果，从而绕过耗时的全库检索。

### 2. 方法论：HaS 框架
HaS（Homology-aware Speculative Retrieval）是一个即插即用的组件，其核心流程如下：

*   **核心思想：** 先进行低延迟的局部检索生成“草案文档（Draft）”，再通过“同源查询重识别”任务验证该草案是否包含所需知识。
*   **关键技术细节：**
    1.  **双通道快速检索（Two-Channel Fast Retrieval）：**
        *   **缓存通道（Cache Channel）：** 包含近期查询检索到的文档，提供初始知识覆盖。
        *   **模糊通道（Fuzzy Channel）：** 配置极其激进的 ANNS（仅检索极小比例的桶），用于捕捉缓存中缺失的细粒度信息。
    2.  **同源验证机制（Homology Validation）：**
        *   **定义同源性：** 两个查询指向同一个实体即为同源。同源查询极大概率共享至少一个“金牌文档（Golden Document）”。
        *   **同源得分公式：** $s(q, q_h) = |D \cap D_h| / k$，即当前草案 $D$ 与历史检索结果 $D_h$ 的重合比例。
        *   **倒排索引加速：** 维护一个“文档-查询”倒排索引，通过草案中的文档快速反查相关的历史查询，计算得分。
    3.  **算法流程：** 
        *   输入查询 $q$ -> 双通道检索得到 Top-k 草案 $D$ -> 通过倒排索引寻找同源得分超过阈值 $\tau$ 的历史查询 -> 若找到，则接受草案并直接交给 LLM；若未找到，则回退（Fallback）执行全库检索并更新缓存。

### 7. 优点（亮点）
*   **即插即用：** 不需要重新训练模型或改变现有的 RAG 架构，可作为轻量级中间件部署。
*   **理论创新：** 首次将“同源性”引入 RAG 检索加速，并将其形式化为重识别任务，避开了高昂的 LLM 验证成本。
*   **双通道设计：** 巧妙结合了历史缓存和实时模糊检索，兼顾了知识覆盖面和验证的可靠性。

### 8. 不足与局限
*   **依赖查询分布：** HaS 的效能高度依赖于查询的流行度（Popularity Pattern）。对于极其冷门、长尾且无历史重合的查询，HaS 不仅不能加速，还会因为额外的投机步骤增加少量延迟。
*   **实体对齐依赖：** 该方法依赖于语义编码器对实体的敏感度。如果编码器无法很好地将同源查询映射到相似的文档空间，同源得分的有效性会下降。
*   **存储开销：** 虽然模糊通道可以压缩，但维护历史查询的文档缓存和倒排索引仍需一定的内存空间（尽管文中提到 5000 条记录仅需约 31MB）。
