## 摘要
LLM 控制器何时在知识图谱探索中优于基于规则的遍历？我们通过 RLM-on-KG 研究了这一问题。RLM-on-KG 是一个检索系统，它将 LLM 视为在 RDF 编码的提及图（mention graph）上进行自主导航的导航器，用于有依据的问答。与依赖离线 LLM 索引的 GraphRAG 流水线不同，RLM-on-KG 在查询时利用确定性图构建和固定工具集，执行实体优先的多跳探索。我们的核心发现是一种有条件的优势：LLM 控制的价值取决于证据的离散程度和工具调用的复杂程度。本文的核心主张是 LLM 控制与启发式遍历的对比，而非对 GraphRAG 的全面胜出。在 GraphRAG-Bench Novel（519 个问题）上，Gemini 2.0 Flash 的 F1 分数比基于规则的启发式基准高出 2.47 个百分点（pp）（p < 0.0001），但仅比 GraphRAG-local 变体高出 0.16 个百分点（不显著）。使用更强大的控制器 Claude Haiku 4.5 时，相对于启发式方法的增益增长至 +4.37 pp (p < 0.001)，并且相对于 GraphRAG-local 实现了 +2.42 pp 的显著提升 (p < 0.001)。当黄金证据散布在 6-10 个分块中时，增益最大（+3.21 pp），而对于集中证据，增益最小（+1.85 pp）。在 MuSiQue 上的跨规模验证确认了 LLM 优于启发式方法的优势具有迁移性，但在较小的单问题图上会出现预期的衰减。核心架构见解是将候选发现与排序分离：LLM 通过探索广度增加价值，而最终的证据选择最好由纯向量重排序处理。除了检索之外，探索轨迹还为结构化数据质量提供了一种建议的压力测试框架，可用于诊断覆盖范围、连通性、溯源性和可查询性。

## Abstract
When does an LLM controller outperform rule-based traversal for knowledge graph exploration? We study this question through RLM-on-KG, a retrieval system that treats an LLM as an autonomous navigator over an RDF-encoded mention graph for grounded question answering. Unlike GraphRAG pipelines that rely on offline LLM indexing, RLM-on-KG performs entity-first, multi-hop exploration at query time using deterministic graph construction and a fixed tool set. Our central finding is a conditional advantage: the value of LLM control depends on evidence scatter and tool-calling sophistication. The paper's core claim is LLM control versus heuristic traversal, not a generic win over GraphRAG. On GraphRAG-Bench Novel (519 questions), Gemini 2.0 Flash achieves +2.47 pp F1 over a rule-based heuristic baseline (p < 0.0001), but only +0.16 pp over a GraphRAG-local variant (not significant). With a stronger controller, Claude Haiku 4.5, the gain over heuristic grows to +4.37 pp (p < 0.001) and extends to a +2.42 pp significant improvement over GraphRAG-local (p < 0.001). The gain is largest when gold evidence is scattered across 6-10 chunks (+3.21 pp) and smallest for concentrated evidence (+1.85 pp). Cross-scale validation on MuSiQue confirms that the LLM-over-heuristic advantage transfers, with expected attenuation on smaller per-question graphs. The core architectural insight is the separation of candidate discovery from ranking: the LLM adds value through exploration breadth, while final evidence selection is best handled by pure vector re-ranking. Beyond retrieval, exploration traces provide a proposed stress-test harness for structured data quality, yielding diagnostics for coverage, connectivity, provenance, and queryability.

#### 1. 核心问题与整体含义（研究动机和背景）
论文探讨的核心问题是：**在知识图谱（KG）探索中，LLM 控制器何时能优于基于规则的启发式遍历？**
传统的 RAG 在处理简单事实时表现良好，但面对证据散落在多个文档段落、实体和关系中的复杂问题（Scattered Evidence）时往往失效。现有的 GraphRAG 方案依赖昂贵的离线 LLM 索引（如实体提取、社区摘要）。本文提出了 **RLM-on-KG**，旨在通过在查询时（Query-time）利用 LLM 作为自主导航员，在确定性构建的“提及图”（Mention Graph）上进行自适应多跳探索，从而在不进行昂贵预处理的前提下，解决复杂的多跳检索任务。

#### 2. 方法论：核心思想与技术细节
RLM-on-KG 采用“递归语言模型”（Recursive Language Model）框架，将检索过程视为 LLM 与图环境的交互。
*   **核心思想**：将候选证据的“发现”（Discovery）与“排序”（Ranking）分离。LLM 负责通过图遍历寻找潜在分块，而最终筛选则交给纯向量相似度计算。
*   **提及图构建（离线）**：使用确定性 NLP 工具（如 spaCy）提取实体，构建“分块-实体”二部图。不使用 LLM 进行索引，降低了离线成本。
*   **在线探索流程**：
    1.  **实体发现阶段**：LLM 调用工具识别问题中的种子实体，并获取关联的文本分块。
    2.  **图扩展阶段**：利用 `expand_neighbors` 等工具，通过共现关系发现相关实体，进行多跳跳转。
    3.  **验证与提取阶段**：LLM 读取分块内容，验证事实，并显式收集（collect）相关证据。
*   **算法逻辑**：LLM 在一个循环中运行，每一步根据当前状态（已探索实体、已收集证据）决定下一步动作，直到满足停止条件（证据足够、陷入停滞或达到预算上限）。
*   **最终排序**：对 LLM 发现的所有分块进行向量重排序，LLM 显式收集的分块会获得微小的分数加成（+0.10）。

#### 6. 主要结论与发现
*   **LLM 控制器的条件优势**：LLM 驱动的遍历显著优于启发式规则（Claude 提升 +4.37 pp F1），但这种优势在证据高度分散（跨 6-10 个分块）时最为明显。
*   **模型能力决定效果**：检索性能与 LLM 的工具调用能力呈正相关。Claude Haiku 4.5 是首个在统计学上显著超越 GraphRAG-local 的控制器。
*   **发现优于判断**：LLM 的核心价值在于通过图路径“发现”向量搜索难以触达的冷门分块，而非对分块进行复杂的评分。
*   **KG 诊断价值**：LLM 的探索轨迹可以作为诊断底层图数据质量（如连通性、覆盖率）的压力测试工具。

#### 7. 优点
*   **自适应性**：能够根据问题的复杂程度动态调整探索深度，类似于外部化的“自适应计算”。
*   **低离线成本**：无需 LLM 预索引，适合内容频繁更新的动态语料库。
*   **架构简洁**：通过分离发现与排序，简化了 RAG 系统的优化路径。
*   **可解释性**：探索轨迹提供了清晰的证据链条和溯源信息。

#### 8. 不足与局限
*   **高延迟与高成本**：分钟级的响应时间和数万 token 的消耗限制了其在大规模实时生产环境中的应用。
*   **本地模型表现不佳**：当前的开源小模型（如 Gemma 4）在复杂工具调用上仍存在瓶颈，甚至不如简单的启发式规则。
*   **评估偏差风险**：金标证据的映射依赖于语义相似度回退，且使用了与检索相同的嵌入模型，可能存在一定的评估偏置。
*   **任务局限**：在证据非常集中的简单任务中，LLM 的过度探索反而会引入噪声，降低精度。
