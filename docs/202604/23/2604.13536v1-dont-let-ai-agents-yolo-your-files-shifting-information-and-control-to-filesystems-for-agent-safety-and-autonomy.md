## 摘要
AI 编程智能体直接在用户的文件系统上运行，经常导致数据损坏、文件删除和密钥泄露。目前的方法被迫在安全性与自主性之间进行权衡：不受限制的访问存在风险，而频繁的权限提示则增加了用户负担并阻碍了智能体。为了理解这一问题，我们对智能体文件系统误用进行了首次系统性研究，分析了 13 个框架中的 290 份公开报告。我们的分析表明，目前的智能体对其文件系统操作的影响了解有限，且缺乏足够的控制能力。因此，我们主张将这些信息和控制权转移到文件系统本身。基于这一原则，我们设计了 YoloFS，这是一种具有三项技术的智能体原生文件系统。暂存（Staging）在提交前隔离所有变更，为用户提供纠正性控制；快照（Snapshots）将这种控制扩展到智能体，使其能够检测并纠正自己的错误；渐进式权限（Progressive permission）通过以最少的交互限制访问，为用户提供预防性控制。为了评估 YoloFS，我们引入了一种捕获用户-智能体-文件系统交互的新方法。在 11 个具有隐藏副作用的任务中，YoloFS 使智能体在 8 个任务中实现了自我纠正，同时保持所有影响处于暂存状态且可审查。在 112 个常规任务中，YoloFS 在保持与基准相当的成功率的同时，减少了用户交互。

## Abstract
AI coding agents operate directly on users' filesystems, where they regularly corrupt data, delete files, and leak secrets. Current approaches force a tradeoff between safety and autonomy: unrestricted access risks harm, while frequent permission prompts burden users and block agents. To understand this problem, we conduct the first systematic study of agent filesystem misuse, analyzing 290 public reports across 13 frameworks. Our analysis reveals that today's agents have limited information about their filesystem effects and insufficient control over them. We therefore argue for shifting this information and control to the filesystem itself.   Based on this principle, we design YoloFS, an agent-native filesystem with three techniques. Staging isolates all mutations before commit, giving users corrective control. Snapshots extend this control to agents, letting them detect and correct their own mistakes. Progressive permission provides users with preventive control by gating access with minimal interaction. To evaluate YoloFS, we introduce a new methodology that captures user-agent-filesystem interactions. On 11 tasks with hidden side effects, YoloFS enables agent self-correction in 8 while keeping all effects staged and reviewable. On 112 routine tasks, YoloFS requires fewer user interactions while matching the baseline success rate.

*   **研究动机**：AI 编程智能体（如 Claude Code, Cursor, GitHub Copilot）已广泛应用，但它们直接以用户权限操作文件系统，经常导致误删文件、破坏数据或泄露密钥（如 `.env` 文件）。
*   **核心矛盾**：现有的防御机制（如权限提示）在“安全性”与“自主性”之间存在权衡。频繁的提示会导致用户产生“审批疲劳”，从而开启“YOLO 模式”（全自动运行），这极大地增加了系统风险。
*   **根本原因**：论文通过对 290 份公开误用报告的分析，指出当前智能体存在两个缺口：
    1.  **信息缺口**：用户和智能体都无法准确预知或审计工具调用（Tool Call）产生的具体文件系统影响。
    2.  **控制缺口**：现有的模型指令或字符串过滤机制极易被绕过，且一旦发生破坏性操作，缺乏有效的撤销手段。

### 2. 方法论：核心思想与关键技术
论文主张将信息感知和操作控制权从智能体框架下沉到**文件系统层**。YoloFS 作为一个 Linux 堆栈式文件系统，实现了以下三项关键技术：

*   **暂存机制（Staging）**：
    *   **核心思想**：所有文件修改、创建和删除操作首先重定向到一个暂存层，而不直接修改底层文件系统。
    *   **技术细节**：利用内存中的“覆盖树”（Override Tree）记录路径重定向，并配合“目录日志”（Directory Journal）记录操作序列。只有在用户审查并确认后，才会将更改“提交”（Commit）到基准文件系统。
*   **快照与非破坏性穿梭（Snapshots & Travel）**：
    *   **核心思想**：允许智能体在发现错误时自行回溯状态。
    *   **技术细节**：不同于传统的破坏性回滚，YoloFS 采用“穿梭”机制，在回溯时保留所有分支历史。通过生成号（Generation）管理文件版本，实现高效的写时复制（CoW）。
*   **渐进式权限（Progressive Permission）**：
    *   **核心思想**：权限规则随会话动态演进，而非静态配置。
    *   **技术细节**：采用路径级别的规则树（支持 Allow, Read-only, Deny, Hidden, Ask 五种状态）。当遇到“Ask”状态时，系统挂起操作并请求用户决策，用户的决策会更新规则树，从而减少后续重复提示。

### 6. 主要结论与发现
*   **自我纠错**：在 11 个具有隐藏副作用的任务中，YoloFS 帮助智能体在 8 个任务中实现了完全的自我检测与回溯。
*   **交互优化**：在常规任务中，YoloFS 在保持 99% 成功率的同时，显著减少了用户交互次数（平均每任务 0.4 次，远低于 Gemini 的 2.2 次）。
*   **性能表现**：YoloFS 的 I/O 开销极低（与原生 Ext4 相比几乎无异），且能支持数百个快照而性能不下降。

### 7. 优点
*   **设计范式转移**：首次提出“智能体原生文件系统”概念，将安全防线从不可靠的模型层移至可靠的内核层。
*   **非破坏性回溯**：其“穿梭”机制非常契合 AI 智能体多路径探索的特性，避免了回滚导致的数据丢失。
*   **实用性强**：作为堆栈式文件系统，无需修改底层文件系统格式，易于部署。

### 8. 不足与局限
*   **平台限制**：目前仅在 Linux 上实现，Windows 和 macOS 用户尚无法直接使用。
*   **不可逆操作**：虽然能控制文件系统，但对于已经通过网络泄露的数据或已触发的外部 API 调用，文件系统层无法撤销。
*   **集成依赖**：需要智能体框架提供 Hook（如 Claude Code 的 PreToolUse）才能发挥最大效用。
