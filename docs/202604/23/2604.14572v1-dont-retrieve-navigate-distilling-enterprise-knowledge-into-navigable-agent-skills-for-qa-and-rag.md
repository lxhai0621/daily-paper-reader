## 摘要
检索增强生成（RAG）将大语言模型（LLM）的响应建立在外部证据之上，但将模型视为搜索结果的被动消费者：它从未看到语料库是如何组织的，也不知道尚未检索到什么，这限制了其回溯或整合分散证据的能力。我们提出了 Corpus2Skill，它在离线状态下将文档语料库蒸馏为层级化的技能目录，并允许 LLM 智能体在推理时对其进行导航。该编译流水线迭代地对文档进行聚类，在每个层级生成由 LLM 编写的摘要，并将结果实例化为一棵可导航技能文件树。在推理时，智能体获得语料库的全景视图，通过逐渐细化的摘要深入探索主题分支，并根据 ID 检索完整文档。由于层级结构是显式可见的，智能体可以推理寻找位置，从无效路径回溯，并跨分支整合证据。在企业级客户支持 RAG 基准测试 WixQA 上，Corpus2Skill 在所有质量指标上均优于稠密检索、RAPTOR 和智能体化 RAG 基线。

## Abstract
Retrieval-Augmented Generation (RAG) grounds LLM responses in external evidence but treats the model as a passive consumer of search results: it never sees how the corpus is organized or what it has not yet retrieved, limiting its ability to backtrack or combine scattered evidence. We present Corpus2Skill, which distills a document corpus into a hierarchical skill directory offline and lets an LLM agent navigate it at serve time. The compilation pipeline iteratively clusters documents, generates LLM-written summaries at each level, and materializes the result as a tree of navigable skill files. At serve time, the agent receives a bird's-eye view of the corpus, drills into topic branches via progressively finer summaries, and retrieves full documents by ID. Because the hierarchy is explicitly visible, the agent can reason about where to look, backtrack from unproductive paths, and combine evidence across branches. On WixQA, an enterprise customer-support benchmark for RAG, Corpus2Skill outperforms dense retrieval, RAPTOR, and agentic RAG baselines across all quality metrics.

### 论文总结：莫检索，重导航（Don't Retrieve, Navigate）

#### 1. 核心问题与整体含义
*   **研究背景**：传统的检索增强生成（RAG）将大语言模型（LLM）视为搜索结果的“被动消费者”。模型只能看到检索到的前 K 个片段，而无法感知整个语料库的组织结构，也无法知道哪些信息未被检索到。
*   **核心问题**：在处理复杂的企业级查询（如涉及多个业务模块的政策）时，简单的语义相似度检索往往会遗漏关键的上下文，且 LLM 缺乏回溯和主动探索知识库的能力。
*   **研究目的**：提出 **Corpus2Skill** 框架，将语料库转化为可导航的“技能树”，让 LLM 智能体像人类查阅目录一样主动导航、发现并整合知识。

#### 2. 方法论
*   **核心思想**：采用“先编译，后导航”的策略。将静态文档库蒸馏为层级化的文件系统，利用 LLM 智能体的推理能力在目录中进行路径选择。
*   **编译阶段（离线）**：
    1.  **嵌入与聚类**：使用嵌入模型（如 Qwen3-Embedding）对文档向量化，通过 K-Means 进行迭代自底向上聚类。
    2.  **层级摘要**：LLM 为每个聚类生成摘要，描述该分支涵盖的主题、可回答的问题及关键词。
    3.  **文件实例化**：将结果保存为树状结构，根节点为 `SKILL.md`（技能概览），中间节点和叶节点为 `INDEX.md`（包含子组或文档 ID 列表）。
*   **服务阶段（在线）**：
    1.  **渐进式披露**：智能体初始仅加载技能名称和简短描述，节省上下文窗口。
    2.  **导航工具**：智能体使用 `code_execution` 工具（执行 `ls` 和 `cat`）浏览目录，并使用 `get_document(id)` 获取最终文档全文。
    3.  **自主决策**：智能体根据摘要决定进入哪个分支，若发现路径不对可回溯，或跨分支整合证据。

#### 3. 实验设计
*   **数据集**：**WixQA**，一个包含 6,221 篇企业客服文章和 200 个专家编写的复杂查询的真实基准测试。
*   **对比方法**：
    *   传统检索：BM25（关键词）、Dense（稠密向量）、Hybrid（混合检索）。
    *   层级检索：**RAPTOR**（递归摘要树检索）。
    *   智能体化 RAG：允许智能体多次调用传统检索工具的基线。
*   **评估指标**：词汇重叠度（F1, BLEU, ROUGE）和 LLM 评判指标（事实性 Factuality、上下文召回率 Context Recall）。

#### 4. 资源与算力
*   **编译算力**：在 32 核 CPU 服务器上，编译 6,221 篇文档仅需 **6.5 分钟**。
*   **模型使用**：
    *   嵌入：Qwen3-Embedding-0.6B（可在 CPU 运行）。
    *   推理/导航：默认使用 Claude 3.5 Sonnet，消融实验中测试了 Claude 3.5 Haiku。
*   **成本**：离线编译成本约 $5-$10。在线推理成本较高（约 $0.17/查询），主要源于 Skills API 在每轮对话中重复包含导航文件的 Token 开销。

#### 5. 实验数量与充分性
*   **实验规模**：针对 200 个复杂专家查询进行了完整测试，并提供了详细的导航轨迹（Trace）分析。
*   **消融实验**：涵盖了聚类结构（树的宽窄）、智能体探索预算（最大轮数）、以及不同性能/成本等级的 LLM 驱动器。
*   **公平性**：所有方法在评估时均统一了上下文窗口大小（8,000 字符），确保对比客观。

#### 6. 主要结论与发现
*   **性能领先**：Corpus2Skill 在所有质量指标上均优于所有基线。Token F1 比智能体化 RAG 提升 19%，比稠密检索提升 27%。
*   **层级优势**：层级化组织（Corpus2Skill 和 RAPTOR）显著优于扁平检索，证明了聚类摘要能捕捉语义相似度无法覆盖的主题联系。
*   **导航能力**：智能体能够执行跨分支探索（如同时查看“在线课程”和“账单设置”分支），这种全局视野是传统 RAG 无法提供的。
*   **模型鲁棒性**：即使使用较便宜的模型（Haiku），导航性能依然稳健，证明了知识结构的质量比导航者的聪明程度更关键。

#### 7. 优点
*   **结构可见性**：赋予 LLM “上帝视角”，使其知道语料库的全貌，从而能进行有目的的搜索。
*   **无需向量数据库**：运行时仅依赖文件系统和 LLM，简化了企业生产环境的架构。
*   **推理驱动**：将检索问题转化为推理问题，充分利用了现代 LLM 的长程规划能力。

#### 8. 不足与局限
*   **推理成本高**：由于 Skills API 的机制，每轮导航都会累积 Token，导致单次查询成本远高于单次检索。
*   **静态限制**：目前不支持增量更新，文档库变动需重新编译。
*   **硬聚类瓶颈**：每个文档仅属于一个路径，若文档跨主题（如既属于“计费”又属于“订阅”），可能导致导航路径单一化。
*   **延迟**：多轮导航交互比单次检索响应慢。
