## 摘要
用户在向基于大语言模型（LLM）的智能体提出请求时，往往会省略关键细节，导致工具使用的输入信息不足。这对工具增强型智能体构成了根本性挑战，因为 API 执行通常需要完整的参数，从而凸显了个性化工具调用的必要性。为了研究这一问题，我们引入了 MPT，这是一个包含 265 个多会话对话的基准测试，涵盖了三个挑战：偏好召回（Preference Recall）、偏好归纳（Preference Induction）和偏好迁移（Preference Transfer）。我们还提出了 PRefine，这是一种测试时内存增强方法，将用户偏好表示为不断演化的假设。通过“生成-验证-细化”（generate--verify--refine）循环，它从历史记录中提取可重用的约束条件，在提高工具调用准确性的同时，仅消耗全历史提示（full-history prompting）所需 Token 数量的 1.24%。这些结果表明，智能体系统中稳健的个性化取决于能够捕捉用户选择背后原因的记忆，而不仅仅是选择本身。

## Abstract
Users often omit essential details in their requests to LLM-based agents, resulting in under-specified inputs for tool use. This poses a fundamental challenge for tool-augmented agents, as API execution typically requires complete arguments, highlighting the need for personalized tool calling. To study this problem, we introduce MPT, a benchmark comprising 265 multi-session dialogues that cover three challenges: Preference Recall, Preference Induction, and Preference Transfer. We also propose PRefine, a test-time memory-augmented method that represents user preferences as evolving hypotheses. Through a generate--verify--refine loop, it extracts reusable constraints from history and improves tool-calling accuracy while using only 1.24% of the tokens required by full-history prompting. These results indicate that robust personalization in agentic systems depends on memory that captures the reasons behind user choices, not just the choices themselves.

*   **核心问题**：如何从跨会话、包含噪声且无序的历史记录中，提取出隐式的、持久的决策约束（如“用户总是倾向于廉价选择”），并将其应用于新的、参数缺失的工具调用场景中。
*   **整体含义**：本文强调个性化工具调用不仅是记忆检索问题，更是一个**抽象推理问题**，需要模型理解用户选择背后的逻辑。

### 2. 方法论：PRefine
*   **核心思想**：将用户偏好建模为“不断演化的假设”（Evolving Hypotheses），通过一个闭环机制持续优化。
*   **关键技术细节**：
    *   **生成-验证-细化（Generate-Verify-Refine）循环**：
        1.  **生成（Generate）**：根据当前会话、执行的 API 调用和先验记忆，提出解释用户行为的抽象偏好假设。
        2.  **验证（Verify）**：验证器根据四个维度评估假设：证据支持（是否有多次记录支持）、抽象质量（是否泛化而非复述）、可操作性（是否能指导未来决策）、时间一致性（是否符合最新行为）。
        3.  **细化（Refine）**：若验证未通过，根据反馈修正假设，剔除过度特定或无证据的描述。
    *   **模式无关记忆（Schema-Agnostic Memory）**：记忆存储的是抽象的文本约束（如“偏好经济型旅行”），而非特定 API 的参数名。这使得记忆在 API 模式（Schema）发生变化时依然有效。

    *   **三大挑战场景**：
        1.  **偏好召回 (Recall)**：直接复用同一领域内的历史选择。
        2.  **偏好归纳 (Induction)**：跨任务/领域聚合证据（如从餐厅和酒店选择中归纳出“省钱”偏好）。
        3.  **偏好迁移 (Transfer)**：将已知偏好应用到从未出现过的新领域。
*   **对比方法**：

### 6. 主要结论与发现
*   **性能提升**：PRefine 在偏好归纳和迁移任务上显著优于全历史提示和 RAG 方法。
*   **极高效率**：PRefine 仅需全历史方法 **1.24%** 的 Token 消耗，且记忆长度不随会话增加而线性增长，保持了极高的压缩率。
*   **基准局限**：实验发现，现有的 LLM 在“偏好迁移”上表现最差，说明跨领域应用抽象规则仍是当前智能体的短板。

### 7. 优点
*   **分类科学**：首次将个性化工具调用细分为召回、归纳、迁移三类，为后续研究提供了清晰的框架。
*   **轻量化与可扩展**：无需微调模型，通过纯 Prompt 机制实现了高效的记忆管理。
*   **Schema 灵活性**：抽象化的偏好描述解决了 API 频繁更新导致的记忆失效问题。

### 8. 不足与局限
*   **偏好维度有限**：目前 MPT 仅涵盖了“预算（Budget）”和“旅行人数（Travel Group）”两个主要维度，尚未覆盖更复杂的个性化需求（如饮食禁忌、品牌偏好等）。
*   **保守性风险**：实验观察到某些推理模型（如 R1-Distill-Llama）在应用 PRefine 后变得过于保守，导致生成的参数数量减少，可能影响某些场景的召回率。
*   **合成数据依赖**：MPT 基于合成的对话数据集，真实世界中用户的语言表达可能更具歧义和噪声。
