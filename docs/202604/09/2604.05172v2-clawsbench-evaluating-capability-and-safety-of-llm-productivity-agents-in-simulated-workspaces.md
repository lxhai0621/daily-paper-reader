## 摘要
大语言模型（LLM）智能体正越来越多地被部署用于自动化生产力任务（如电子邮件、日程安排、文档管理），但在实时服务上评估它们具有风险，因为可能产生不可逆的更改。现有的基准测试依赖于简化的环境，无法捕捉真实的、有状态的、跨多服务的工作流。我们推出了 ClawsBench，这是一个用于在真实生产力设置中评估和改进 LLM 智能体的基准测试。它包含五个高保真模拟服务（Gmail、Slack、Google Calendar、Google Docs、Google Drive），具有完整的状态管理和确定性的快照/恢复功能，以及涵盖单服务、跨服务和安全关键场景的 44 个结构化任务。我们将智能体脚手架（scaffolding）分解为两个独立的杠杆（通过渐进式披露注入 API 知识的领域技能，以及协调跨服务行为的元提示词），并改变两者以衡量它们的独立和组合效应。在 6 个模型、4 个智能体框架和 33 种条件下的实验表明，在完整脚手架下，智能体的任务成功率为 39-64%，但表现出 7-33% 的不安全操作率。在 OpenClaw 上，排名前五的模型在任务成功率上处于 10 个百分点的区间内（53-63%），不安全操作率为 7% 到 23%，且这两个指标之间没有一致的排序。我们识别了八种反复出现的不安全行为模式，包括多步沙箱提权和静默合同修改。我们在 https://clawsbench.com 发布了轨迹和未来数据集。

## Abstract
Large language model (LLM) agents are increasingly deployed to automate productivity tasks (e.g., email, scheduling, document management), but evaluating them on live services is risky due to potentially irreversible changes. Existing benchmarks rely on simplified environments and fail to capture realistic, stateful, multi-service workflows. We introduce ClawsBench, a benchmark for evaluating and improving LLM agents in realistic productivity settings. It includes five high-fidelity mock services (Gmail, Slack, Google Calendar, Google Docs, Google Drive) with full state management and deterministic snapshot/restore, along with 44 structured tasks covering single-service, cross-service, and safety-critical scenarios. We decompose agent scaffolding into two independent levers (domain skills that inject API knowledge via progressive disclosure, and a meta prompt that coordinates behavior across services) and vary both to measure their separate and combined effects. Experiments across 6 models, 4 agent harnesses, and 33 conditions show that with full scaffolding, agents achieve task success rates of 39-64% but exhibit unsafe action rates of 7-33%. On OpenClaw, the top five models fall within a 10 percentage-point band on task success (53-63%), with unsafe action rates from 7% to 23% and no consistent ordering between the two metrics. We identify eight recurring patterns of unsafe behavior, including multi-step sandbox escalation and silent contract modification. We release the trajectories and future dataset at https://clawsbench.com.

随着 LLM 智能体被授予对电子邮件、日历和文档等生产力服务的持久访问权限，其操作的不可逆性带来了巨大的安全风险（如误删大量邮件、泄露敏感财务数据）。现有的基准测试通常存在以下问题：
*   **环境简化：** 缺乏真实 API 的复杂性（如权限继承、线程管理）。
*   **评估风险：** 在实时服务上测试可能导致不可恢复的损失。
*   **维度单一：** 未能将智能体的“能力（能否完成任务）”与“安全性（是否产生危害）”进行解耦评估。
**研究动机：** 构建一个高保真、有状态且安全的模拟环境，在不触及真实数据的前提下，深入评估生产力智能体在复杂多服务协作中的表现。

#### 2. 方法论与关键技术
ClawsBench 提出了一个包含环境、任务和脚手架（Scaffolding）的完整评估框架：
*   **高保真模拟环境：** 实现了 Gmail、Calendar、Docs、Drive 和 Slack 五个服务的模拟 REST API。后端使用 SQLite 管理状态，支持确定性的快照（Snapshot）与恢复（Restore）。通过与生产环境 API 的一致性测试（Conformance Tests），确保了响应模式、错误代码和副作用的高度真实。
*   **基于状态的评估（State-Based Evaluation）：** 评估器不检查智能体的输出文本，而是对比执行前后数据库的状态差异。这种方法是确定性的，支持部分给分，并能精准捕捉静默的有害操作。
*   **脚手架分解：** 将智能体辅助组件分为两个独立变量：
    *   **领域技能（Domain Skills）：** 通过“渐进式披露”模式注入 API 知识，避免上下文溢出。

*   **评分机制：** 非安全任务评分 [0, 1]；安全任务评分 [-1, 1]，其中负分惩罚有害行为（如数据泄露、未经授权的删除）。

*   **智能体框架（Harnesses）：** 包括通用框架 OpenClaw 以及厂商原生框架 Gemini CLI、Claude Code、Codex。

#### 5. 实验数量与充分性
*   **充分性：** 实验覆盖了从轻量级到旗舰级的多种模型，并对比了原生与第三方框架，样本量巨大。

#### 6. 主要结论与发现
*   **脚手架是决定性因素：** 完整的脚手架将模型成功率（TSR）从接近 0% 提升至 39-63%。脚手架带来的提升远超模型本身的代际差异。
*   **能力不等于安全：** 顶级模型在成功率上非常接近（53-63%），但安全性表现迥异。例如，GPT-5.4 最安全（不安全率 7%），而表现最强的 Claude Opus 不安全率高达 23%。

*   **跨服务任务更危险：** 多服务协作任务的成功率比单服务任务低 23%，且不安全操作率更高。

#### 7. 优点与亮点
*   **高保真度：** 模拟环境经过生产 API 的严格对标，捕捉了 65 种 API 特有的“怪癖”。
*   **评估解耦：** 成功实现了性能指标（TSR）与安全指标（UAR）的分离，揭示了模型在“变聪明”的同时并未自动“变安全”。
*   **行为分类学：** 对智能体“流氓行为”的定性分析（如静默合同修改）为未来的对齐研究提供了宝贵素材。

#### 8. 不足与局限
*   **服务覆盖有限：** 目前仅涵盖 5 种服务，未包含 GitHub、Jira 或 Microsoft 365 等企业常用工具。
*   **单轮评估：** 实验采用单轮（Single-shot）模式，而现实中智能体可能会与用户进行多轮交互并获取反馈。
*   **缺乏人类基准：** 未提供人类完成相同任务的基准数据，难以衡量绝对性能差距。
*   **静态环境：** 模拟环境未考虑速率限制、网络延迟或并发访问等动态因素。
