## 摘要
随着大语言模型（LLMs）扩展到支持超过一百万个 token 的上下文窗口，键值（KV）缓存的线性增长带来了严重的内存容量和带宽瓶颈，限制了长上下文推理的效率。现有的压缩方法通常基于局部显著性指标对 token 进行优先级排序，以将预填充计算与解码内存解耦。然而，这些方法往往依赖于特定层的局部显著性快照，从而系统性地丢弃了那些在整个网络深度中充当全局信息枢纽、但在选定的剪枝特定层中暂时处于休眠状态的 token。为了解决这一局限性，我们提出了 StructKV，这是一个结构感知的 KV 缓存压缩框架，它引入了三项核心创新：首先，全局入度中心性（Global In-Degree Centrality）聚合了整个网络深度的注意力模式，以识别全局信息枢纽。其次，动态枢轴检测（Dynamic Pivot Detection）利用信息论指标自适应地定位压缩的最佳层。最后，结构传播与解耦（Structural Propagation and Decoupling）将计算预算与内存存储预算分离。在 LongBench 和 RULER 基准测试上的实验结果表明，StructKV 有效地保留了长程依赖性和检索鲁棒性。

## Abstract
As Large Language Models (LLMs) scale to support context windows exceeding one million tokens, the linear growth of Key-Value (KV) cache imposes severe memory capacity and bandwidth bottlenecks, constraining the efficiency of long-context inference. Existing compression approaches typically prioritize tokens based on local saliency metrics to decouple prefill computation from decoding memory. However, these methods often rely on local saliency snapshots at a specific layer, thereby systematically discarding tokens that act as global information hubs across the network depth but appear temporarily dormant at the specific layer selected for pruning. To address this limitation, we propose StructKV, a structure-aware KV cache compression framework that introduces three core innovations: First, Global In-Degree Centrality aggregates attention patterns across the network depth to identify global information hubs. Second, Dynamic Pivot Detection utilizes information-theoretic metrics to adaptively locate the optimal layer for compression. Finally, Structural Propagation and Decoupling separates the computational budget from the memory storage budget. Experimental results on the LongBench and RULER benchmarks demonstrate that StructKV effectively preserves long-range dependencies and retrieval robustness.

随着大语言模型（LLM）支持的上下文窗口扩展至百万级，**KV 缓存（KV Cache）** 的线性增长成为了推理效率的瓶颈，主要表现为预填充（Prefill）阶段的计算开销和解码（Decoding）阶段的内存带宽限制。
*   **现有方法的缺陷**：目前的压缩技术（如 SnapKV、FastKV）大多依赖于特定层的“局部显著性快照”来决定保留哪些 token。这种方法具有**近视性**，容易误删那些在整个网络深度中起全局枢纽作用、但在剪枝层恰好表现不活跃的 token。
*   **研究动机**：提出一种“结构感知”的压缩框架，通过识别上下文的“结构骨架”而非瞬时显著性，在大幅压缩 KV 缓存的同时，保持长程依赖和检索的鲁棒性。

### 2. 方法论：核心思想与关键技术
StructKV 引入了三项核心创新技术，旨在从全局视角捕捉 token 的重要性：

*   **全局入度中心性（Global In-Degree Centrality, $C_{global}$）**：
    不再依赖单层注意力分数，而是通过递归累加从输入层到“枢轴层（Pivot Layer）”的所有注意力模式。利用层级衰减因子 $\lambda$ 赋予深层语义更高的权重，从而识别出在多层中持续作为信息汇聚点的“全局枢纽 token”。
*   **动态枢轴检测（Dynamic Pivot Detection）**：
    放弃了固定剪枝层的做法，引入在线检测机制。通过监控注意力熵（Entropy）、稀疏度（Sparsity）和方差（Variance）的梯度变化，自动定位模型从“广泛探索”转向“聚焦提取”的相位转换点（即最佳压缩层 $L^*$）。
*   **结构化传播与解耦（Structural Propagation & Decoupling）**：
    *   **计算与存储解耦**：在枢轴层之后，仅传播由 $C_{global}$ 选出的“结构骨架”以加速深层计算（预填充预算 $R_{struct}$）；同时，独立维护一个更精简的 KV 缓存用于生成（存储预算 $R_{KV}$）。
    *   **位置对齐**：通过重新排列 Position ID 确保旋转位置嵌入（RoPE）在压缩后的序列中依然保持一致性。

### 3. 实验设计
*   **评估基准（Benchmarks）**：
    *   **LongBench**：包含 16 个子任务，涵盖单/多文档问答、摘要、少样本学习、合成任务和代码。
    *   **RULER**：比“大海捞针”更严苛的长文本检索测试，支持高达 128K 的上下文。
    *   **Needle-in-a-Haystack**：基础的长文本检索测试。
*   **对比方法**：
    *   解码端压缩：StreamingLLM, H2O, SnapKV。

*   **测试模型**：LLaMA-3.1-8B-Instruct, Ministral-8B-Instruct, 以及 Qwen-2.5 全系列（7B, 14B, 32B）。

*   **硬件环境**：所有实验均在单张 **NVIDIA A800 GPU (80GB)** 上运行。
*   **软件框架**：基于 Hugging Face Transformers 和 FlashAttention-2 实现。
*   **开销说明**：论文明确指出，StructKV 引入的额外组件（全局分数累加器和动态检测器）在 32K 上下文下的开销仅约为 **35ms**，占总延迟不到 **2.5%**，主要因为这些操作是元素级向量运算，属于内存带宽受限而非计算受限。

### 5. 实验数量与充分性
实验设计非常充分且具有客观性：
*   **跨架构验证**：在 Llama、Mistral 和 Qwen 三个不同的模型家族上进行了测试，证明了方法的通用性。
*   **消融实验**：详细分析了衰减因子 $\lambda$ 的敏感性、计算与存储解耦对准确率的提升（提升达 13.8%）、以及动态枢轴检测在不同深度模型（28层到64层）中的自适应性。
*   **极端场景**：在 RULER 128K 长度下进行了压力测试，验证了其在超长文本下的稳定性。

### 6. 主要结论与发现
*   **性能卓越**：在仅保留 10% KV 缓存的情况下，StructKV 在 LongBench 上的表现显著优于 FastKV 和 GemFilter，甚至在减少 40% 预填充计算量的情况下，准确率接近全上下文（Full-Context）水平。
*   **检索鲁棒性**：在 128K 的 RULER 测试中，StructKV 解决了 FastKV 在超长文本下性能骤降的问题，证明了全局中心性作为“安全网”的作用。
*   **自适应能力**：实验发现模型越大，最佳压缩层越深（如 Qwen-32B 在第 28 层才稳定），StructKV 的动态检测机制成功捕捉到了这一规律。

### 7. 优点（亮点）
*   **全局视野**：通过跨层累加解决了局部显著性导致的误删问题，保留了“休眠”的关键信息。
*   **三难困境的平衡**：有效平衡了预填充速度、解码延迟和长文本准确性。
*   **即插即用与低开销**：无需重新训练，且动态检测和分数累加的计算成本极低。
*   **解耦策略**：首次明确强调并量化了计算预算与存储预算分离对性能恢复的重要性。

### 8. 不足与局限
*   **长度验证上限**：受限于计算资源，实验最高验证到 128K token，尚未在百万级（1M+）窗口下验证结构骨架的长期稳定性。
*   **模型架构覆盖**：主要针对标准的 Dense Transformer 架构，对于混合专家模型（MoE）或非注意力架构（如 SSM/Mamba）的适用性有待进一步研究。
*   **硬件依赖**：虽然在 A800 上开销极低，但在内存带宽极度受限的边缘设备上，向量聚合操作可能仍存在优化空间。
