## 摘要
随着大语言模型（LLM）智能体从解决短期、静态问题转向在动态环境中执行复杂的长程任务，在任务执行过程中处理用户中断（如增加需求或修改目标）的能力，正成为实际部署的核心要求。然而，现有的基准测试大多假设智能体行为不被中断，或者仅在简短、无约束的语言任务中研究中断。在本文中，我们首次对长程、基于环境的网页导航任务中的可中断智能体进行了系统研究，在这些任务中，动作会引起持久的状态变化。我们形式化了三种现实的中断类型，包括增加、修改和撤回，并推出了 InterruptBench，这是一个源自 WebArena-Lite 的基准测试，在严格的语义约束下合成高质量的中断场景。利用统一的中断模拟框架，我们在单轮和多轮中断设置下评估了六种强大的 LLM 骨干模型，分析了它们在适应更新意图方面的有效性以及从任务中期变更中恢复的效率。我们的结果表明，在长程智能体任务中有效且高效地处理用户中断，对于强大的大规模 LLM 来说仍然具有挑战性。代码和数据集可在 https://github.com/HenryPengZou/InterruptBench 获取。

## Abstract
As LLM agents transition from short, static problem solving to executing complex, long-horizon tasks in dynamic environments, the ability to handle user interruptions, such as adding requirement or revising goals, during mid-task execution is becoming a core requirement for realistic deployment. However, existing benchmarks largely assume uninterrupted agent behavior or study interruptions only in short, unconstrained language tasks. In this paper, we present the first systematic study of interruptible agents in long-horizon, environmentally grounded web navigation tasks, where actions induce persistent state changes. We formalize three realistic interruption types, including addition, revision, and retraction, and introduce InterruptBench, a benchmark derived from WebArena-Lite that synthesizes high-quality interruption scenarios under strict semantic constraints. Using a unified interruption simulation framework, we evaluate six strong LLM backbones across single- and multi-turn interruption settings, analyzing both their effectiveness in adapting to updated intents and their efficiency in recovering from mid-task changes. Our results show that handling user interruptions effectively and efficiently during long-horizon agentic tasks remains challenging for powerful large-scale LLMs. Code and dataset are available at https://github.com/HenryPengZou/InterruptBench.

#### 1. 核心问题与整体含义（研究动机和背景）
随着大语言模型（LLM）智能体从简单的单步任务转向复杂的、需要数百次交互的长程（Long-horizon）任务，现实应用中的一个核心矛盾凸显：**用户往往会在任务执行中途改变主意**（如增加新要求、修正之前的错误或撤销某些限制）。
现有的智能体评测基准（如 WebArena）大多假设用户意图是静态且不可中断的。本文旨在填补这一空白，首次系统性地研究了在具有环境约束和持久状态变化的网页导航场景中，智能体处理动态用户干预的能力。

#### 2. 论文提出的方法论
论文通过以下三个核心步骤构建了研究框架：
*   **形式化中断场景**：定义了三种典型的中断类型：
    *   **Addition（增加）**：用户在初始模糊需求基础上补充细节。
    *   **Revision（修改）**：用户纠正初始输入中的错误信息（如改错日期或地点）。
    *   **Retraction（撤回）**：用户移除之前设定的额外约束。
*   **InterruptBench 基准构建**：基于 WebArena-Lite，利用 Claude-Opus-4.5 配合严格的语义约束（一致性、必要性、真实性）合成中断数据。确保“初始查询 + 中断消息”在语义上等同于原始任务目标。
*   **轨迹感知模拟（Trajectory-Grounded Simulation）**：
    1.  首先运行无中断任务获取完整轨迹。
    2.  根据任务进度比例（如执行到 60% 处）动态注入中断消息。
    3.  智能体需根据更新后的意图调整后续动作，而非重置环境或任务。

#### 3. 实验设计
*   **数据集与场景**：使用了 **WebArena-Lite**（包含 165 个经过人工验证的任务），涵盖 Reddit（社交）、GitLab（代码）、CMS（内容管理）、Map（地图）、OneStopShop（购物）五个领域。
*   **对比方法（模型）**：评估了 6 个顶尖 LLM 骨干模型：
    *   闭源模型：Claude-4.5 系列（Haiku, Sonnet, Opus）。
    *   开源/权重开放模型：Qwen3-Coder-480B-A35B、DeepSeek-V3.1、Mistral-Large-3。
*   **评估指标**：
    *   **成功率（SR）**：最终任务是否达成。
    *   **SR(k) 曲线**：在中断后 $k$ 个动作预算内的成功率，衡量适应速度。
    *   **效率分析**：对比中断前后 Token 消耗和动作数量的变化。
    *   **配对结果象限**：将结果分为 S/F（中断导致失败）、F/S（中断促成成功）等四类进行深度分析。

#### 5. 实验数量与充分性
*   **实验规模**：针对 165 个任务，每个任务分别生成了三种中断类型的变体，并进行了单轮和多轮中断测试。
*   **维度覆盖**：实验涵盖了不同模型、不同中断类型、不同中断位置（20% 到 80% 进度）以及多轮交互（最多 3 轮中断）。
*   **客观性与公平性**：通过设置“无中断但按最终目标评估”的基线（Lower-bound）来量化中断信息的实际贡献；采用配对分析法排除了任务本身难度的干扰，实验设计较为严谨、客观。

#### 6. 主要结论与发现
*   **适应挑战巨大**：即使是顶级模型，在处理中断时也经常表现出“思维惯性”，无法完全撤销过时的环境状态或假设。
*   **模型能力分层**：Claude 系列（尤其是 Opus）在处理中断的稳健性和一致性上显著优于开源模型。DeepSeek-V3.1 在多轮中断中甚至出现了性能倒退（第 3 轮中断后成功率下降）。
*   **效率代价**：中断主要增加了 **Token 消耗（思考成本）**，而非动作数量。在失败案例中，模型往往会陷入长时间且无意义的重新规划中。
*   **位置敏感性**：大型模型（如 Opus）在任务后期中断时表现更好（具备修复能力），而较小模型在早期中断时表现更好，后期中断容易导致其陷入错误的执行轨迹无法自拔。

#### 7. 优点
*   **首创性**：填补了长程、环境约束任务中“可中断性”研究的空白。
*   **数据质量高**：通过严格的 LLM 合成加人工校验，确保了中断信息的必要性和语义等价性。
*   **分析深入**：不仅关注成功率，还通过 SR(k) 曲线和 Token 效率分析揭示了智能体在适应过程中的内在行为。

#### 8. 不足与局限
*   **基准规模限制**：基于 WebArena-Lite（165个任务），虽然质量高但样本量相对较小，可能存在领域偏差。
*   **中断注入方式**：中断是按预设比例静态注入的，未能模拟用户根据智能体实时表现进行“按需中断”的交互特性。
*   **缺乏主动性评估**：实验仅关注智能体被动接受中断，未涉及智能体在遇到歧义时主动请求用户干预的情况。
