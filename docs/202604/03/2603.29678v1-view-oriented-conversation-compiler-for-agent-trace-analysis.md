## 摘要
在上下文学习和框架驱动的智能体认知时代，智能体轨迹具有日益增长的分析价值，然而此前的大多数工作都将对话格式视为微不足道的工程细节。现代智能体对话包含深度结构化的内容，包括嵌套的工具调用及结果、思维链推理块、子智能体调用、上下文窗口压缩边界以及框架注入的系统指令，其复杂程度远超简单的用户-助手交互。将此类轨迹以纯文本、JSON、YAML 格式或通过 grep 提供给反思器或其他分析机制，会显著降低分析质量。本文提出了 VCC（面向视图的对话编译器），这是一个包含词法分析、解析、中间表示（IR）、降级和生成的编译器，它将原始智能体 JSONL 日志转换为一系列结构化视图：全视图（作为规范行号坐标系统的无损转录）、用户界面视图（重建用户实际感知的交互）以及自适应视图（由相关性谓词控制的保持结构的投影）。在 AppWorld 的上下文学习实验中，仅将反思器的输入格式从原始 JSONL 替换为 VCC 编译的视图，就在所有三种测试模型配置中实现了更高的通过率，同时将反思器的 Token 消耗降低了二分之一到三分之二，并生成了更简洁的学习记忆。这些结果表明，消息格式是上下文学习的基础设施，而非偶然的实现选择。

## Abstract
Agent traces carry increasing analytical value in the era of context learning and harness-driven agentic cognition, yet most prior work treats conversation format as a trivial engineering detail. Modern agent conversations contain deeply structured content, including nested tool calls and results, chain-of-thought reasoning blocks, sub-agent invocations, context-window compaction boundaries, and harness-injected system directives, whose complexity far exceeds that of simple user-assistant exchanges. Feeding such traces to a reflector or other analytical mechanism in plain text, JSON, YAML, or via grep can materially degrade analysis quality. This paper presents VCC (View-oriented Conversation Compiler), a compiler (lex, parse, IR, lower, emit) that transforms raw agent JSONL logs into a family of structured views: a full view (lossless transcript serving as the canonical line-number coordinate system), a user-interface view (reconstructing the interaction as the user actually perceived it), and an adaptive view (a structure-preserving projection governed by a relevance predicate). In a context-learning experiment on AppWorld, replacing only the reflector's input format, from raw JSONL to VCC-compiled views, leads to higher pass rates across all three model configurations tested, while cutting reflector token consumption by half to two-thirds and producing more concise learned memory. These results suggest that message format functions as infrastructure for context learning, not as an incidental implementation choice.

#### 1. 核心问题与整体含义（研究动机和背景）
在当前的 AI 智能体研究中，智能体执行任务的“轨迹”（Traces）包含了丰富的认知信息（如工具调用、思维链 CoT、系统指令等）。然而，现有的分析方法通常将这些轨迹视为简单的 JSON、YAML 或纯文本。
*   **痛点**：现代智能体对话极其复杂，单个会话可能超过万行，其中充斥着大量的工具输出、Base64 编码媒体和冗余的系统指令。
*   **后果**：直接将原始日志喂给 LLM 进行反思（Reflection）或学习，会导致 Token 浪费、关键信息被淹没，进而降低分析质量和学习效率。
*   **核心目标**：论文认为“消息格式”不应是琐碎的工程细节，而应作为上下文学习的基础设施。为此，作者提出了 **VCC (View-oriented Conversation Compiler)**，旨在通过编译器技术将原始日志转化为更易于 LLM 理解的结构化视图。

#### 2. 方法论：核心思想与关键技术细节
VCC 借鉴了传统编译器的架构（词法分析 → 解析 → 中间表示 → 降级 → 生成），其核心思想是**“一次分配行号，多视图投影”**。

*   **编译器流水线**：
    1.  **Lexing（词法分析）**：将 JSONL 原始记录标记化，过滤掉无意义的元数据（如进度条、API 错误）。
    2.  **Parsing（解析）**：构建类型化的中间表示（IR），识别用户、助手、工具调用、工具结果、思维块等语义节点。
    3.  **Line Assignment（行号分配）**：在 IR 上进行单次顺序扫描，分配唯一的、单调递增的行号。这是所有视图共享的“坐标系统”。
    4.  **Lowering（视图降级）**：根据需求将 IR 投影为不同的视图，但不改变行号。
*   **三种核心视图**：
    *   **Full View（全视图）**：无损的规范转录，作为所有行号引用的基准。
    *   **UI View（用户界面视图）**：模拟人类用户的感知。省略工具调用细节和 CoT，将工具调用压缩为单行摘要，并附带指向全视图的行号指针。
    *   **Adaptive View（自适应视图）**：基于谓词（如正则匹配）过滤内容，但保留对话的结构骨架（如标题、边界），使匹配内容带有语义标签和坐标。
*   **关键技术特性**：**引用一致性（Referential Consistency）**。无论在哪个视图中，行号始终指向全视图中的相同内容，方便智能体在不同分辨率的视图间跳转。

*   **工程化思维**：首次将编译器理论引入智能体轨迹分析，解决了长文本上下文中的“信息淹没”问题。

*   **实用性强**：在不升级模型的前提下，通过优化数据表征同时实现了性能提升和成本下降。
