## 摘要
大语言模型（LLMs）为自主信息物理系统的意图驱动控制提供了一个极具前景的接口，但其在任务关键型战场物联网（IoBT）环境中的直接应用引发了显著的安全性、可靠性和策略合规性担忧。本文提出了一种策略感知的大语言模型检索增强生成（简称 PA-LLM-RAG）框架，这是一种部署在边缘的 IoBT 任务控制 LLM 编排框架，集成了检索增强推理和独立的指令验证。所提出的 PA-LLM-RAG 框架结合了一个轻量级检索模块（该模块基于操作策略和遥测数据进行决策）、一个用于任务规划的本地托管 LLM，以及一个用于在执行前验证用户生成指令的辅助 JudgeLLM。为了评估 PA-LLM-RAG，我们使用 RoboDK 实现了一个模拟 IoBT 环境，并在复杂度不断增加的受控任务场景中评估了四种开源 LLM，场景包括基准操作、威胁检测、覆盖恢复、多事件协调和违反策略的请求。实验结果表明，该框架能有效检测违反策略的指令，同时保持适用于边缘部署的低延迟响应。其中，Gemma-2B 以 4.17 秒的延迟和 100% 的成功率实现了最高的综合可靠性。研究结果强调了不同模型在推理能力与响应速度之间存在的明显权衡，并表明将确定性保障措施与 JudgeLLM 验证相结合，能显著提高 LLM 驱动的 IoBT 编排的可靠性。

## Abstract
Large Language Models (LLMs) offer a promising interface for intent-driven control of autonomous cyber-physical systems, but their direct use in mission-critical Internet of Battlefield Things (IoBT) environments raises significant safety, reliability, and policy-compliance concerns. This paper presents a Policy-Aware Large Language Model Retrieval-Augmented Generation (referred as PA-LLM-RAG), an edge-deployed LLM orchestration framework for IoBT mission control that integrates retrieval-augmented reasoning and independent command verification. The proposed PA-LLM-RAG framework combines a lightweight retrieval module that grounds decisions in operational policies and telemetry with a locally hosted LLM for mission planning and a secondary JudgeLLM for validating user generated commands prior to execution.   To evaluate PA-LLM-RAG, we implement a simulated IoBT environment using RoboDK and assess four open-source LLMs across controlled mission scenarios of increasing complexity, including baseline operations, threat detection, coverage recovery, multi-event coordination, and policy-violation requests. Experimental results demonstrate that the framework effectively detects policy-violating commands while maintaining low-latency response suitable for edge deployment. Gemma-2B achieving the highest overall reliability with 4.17 sec latency and 100% success rate. The findings highlight a clear tradeoff between reasoning capacity and responsiveness across models and show that combining deterministic safeguards with JudgeLLM verification significantly improves reliability in LLM-driven IoBT orchestration.

#### 1. 核心问题与整体含义
战场物联网（IoBT）涉及无人机（UAV）、无人车（UGV）等多种异构设备的协同，环境动态且具有对抗性。传统的指令控制方式过于僵化，而直接引入大语言模型（LLM）虽能提升灵活性，但面临三大挑战：
*   **安全性与合规性**：LLM 可能产生幻觉，生成违反军事操作规程（ROE）或安全策略的指令。
*   **实时性与边缘限制**：战场环境带宽受限，依赖云端 LLM 延迟过高，且边缘设备算力有限。
*   **缺乏闭环反馈**：LLM 往往无法实时感知设备状态（遥测数据）并据此调整决策。

本研究提出了 **PA-LLM-RAG** 框架，旨在通过检索增强生成（RAG）和独立验证机制，在边缘端实现安全、合规且低延迟的意图驱动任务编排。

#### 2. 方法论
PA-LLM-RAG 框架的核心思想是将“策略约束”与“实时遥测”注入 LLM 的推理过程，并引入二次验证。其工作流程如下：
1.  **任务启动**：接收自然语言指令（如“派无人机监控北门”）。
2.  **语义检索（RAG）**：检索模块从知识库中提取相关的**操作策略**（如交战规则）和**实时遥测数据**（如设备位置、电量）。技术手段包括模糊序列匹配、Jaccard 相似度计算，并取 Top-k（前3条）最相关规则。
3.  **上下文提示词构建**：将原始指令、检索到的策略、实时遥测和输出格式要求（JSON）整合成结构化 Prompt。
4.  **LLM 决策生成**：本地 LLM 根据 Prompt 生成初步的任务计划。
5.  **JudgeLLM 独立验证**：引入第二个 LLM 实例（JudgeLLM）作为“法官”，对生成的指令进行合规性审查。如果指令违反策略（如撤走所有守卫导致覆盖空缺），则予以拦截。
6.  **闭环执行与反馈**：验证后的指令发送至设备执行，设备返回状态更新遥测数据库，形成闭环。

*   **实验场景**：使用 **RoboDK** 软件构建了一个模拟战场检查站环境，包含无人机、无人车和机器人。
*   **测试任务**：设计了 10 个复杂度递增的场景，分为五类：
    *   基准控制（简单移动）。
    *   未知车辆检测（识别与响应）。
    *   覆盖恢复（处理设备故障/低电量）。
    *   多事件协调（并发威胁处理）。
    *   策略违规测试（故意下达违规指令，测试系统拦截能力）。
*   **对比方法（Benchmark）**：对比了四种主流开源轻量级模型：**Gemma-2B、LLaMA-3.1-8B、Mistral-7B、Qwen-2.5-7B**。
*   **评估指标**：混合成功率（JudgeLLM 判定）、严格成功率（规则硬性匹配）、端到端延迟、精确率、召回率及 F1 分数。

#### 4. 资源与算力
*   **硬件环境**：AMD Ryzen 7 7800X3D 8核 CPU (4.2 GHz)，32 GB RAM。

*   **模型优化**：所有模型均采用了 **4-bit 量化**（如 Q4_0 或 Q4_K_M），以降低内存占用并提升推理速度。

#### 5. 实验数量与充分性
*   **实验规模**：针对 4 个模型，在 10 个标准化任务场景下进行了多次重复实验，记录了执行轨迹和延迟数据。

#### 6. 主要结论与发现
*   **模型表现**：**Gemma-2B** 表现最优，实现了 100% 的成功率和最低的平均延迟（4.17秒），证明了超轻量级模型在特定任务编排中的潜力。
*   **性能权衡**：模型规模越大（如 7B/8B），推理延迟显著增加（最高达 6.79秒），但在处理极复杂逻辑时可能更稳健。

*   **RAG 的作用**：通过实时注入策略和遥测，显著减少了 LLM 的幻觉现象，使决策更符合实战逻辑。

#### 7. 优点
*   **策略感知**：将抽象的军事规则转化为 RAG 知识库，解决了 LLM 难以遵循特定领域约束的问题。
*   **边缘友好**：证明了在无 GPU 的 CPU 环境下运行量化 LLM 进行任务编排的可行性。
*   **双重保障**：生成与验证角色分离（JudgeLLM），为自主系统增加了关键的安全层。
*   **闭环设计**：整合实时遥测，使系统具备动态适应能力。

#### 8. 不足与局限
*   **环境局限性**：实验完全基于 RoboDK 模拟，未考虑真实战场的传感器噪声、通信中断和物理对抗。

*   **安全防御不足**：虽然能拦截逻辑违规，但未深入探讨针对 LLM 的恶意攻击（如提示词注入攻击或知识库投毒）。
*   **样本量较小**：10 个测试指令虽然具有代表性，但不足以覆盖战场上可能出现的数千种极端情况。
