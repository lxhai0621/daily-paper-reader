## 摘要
分布式前缀缓存已成为高效大语言模型（LLM）服务的核心技术。然而，对于具有高缓存命中率的长上下文请求，从远程服务器检索可重用的 KVCache 块已成为新的性能瓶颈。随着智能体 AI（agentic AI）工作负载的持续增长，这种网络密集型 LLM 推理预计将变得越来越普遍。然而，现有的 LLM 推理引擎在很大程度上仍以计算为中心：它们将 KVCache 加载视为 GPU 执行的附属阶段，且在调度过程中往往未能明确考虑其延迟。我们提出了 CALVO，这是一种将 KVCache 加载视为首要关注点的 LLM 服务引擎。CALVO 将 KVCache 加载和 GPU 计算解耦为独立管理、异步进行的阶段，从而能够更好地利用网络、PCIe 和计算资源。此外，CALVO 将 KVCache 加载延迟作为单次请求服务成本的明确组成部分，从而实现了更准确的调度决策。在具有多种长上下文工作负载的真实测试平台上的实验表明，CALVO 显著提高了网络密集型 LLM 推理的效率，与基准方案相比，其服务水平目标（SLO）达成率提高了多达 61.67%。

## Abstract
Distributed prefix caching has become a core technique for efficient LLM serving. However, for long-context requests with high cache hit ratios, retrieving reusable KVCache blocks from remote servers has emerged as a new performance bottleneck. Such network-intensive LLM inference is expected to become increasingly common as agentic AI workloads continue to grow. However, existing LLM inference engines remain largely compute-centric: they treat KVCache loading as a subordinate phase to GPU execution and often fail to account for its delay explicitly during scheduling.   We present CALVO, an LLM serving engine that treats KVCache loading as a first-class concern. CALVO decouples KVCache loading and GPU computation into independently managed, asynchronously progressing stages, enabling better utilization of network, PCIe, and computation resources. In addition, CALVO incorporates KVCache loading delay as an explicit component of per-request service cost, leading to more accurate scheduling decisions. Experiments on a real testbed with diverse long-context workloads show that CALVO substantially improves the efficiency of network-intensive LLM inference, achieving up to 61.67% higher SLO attainment than the baseline.

### 1. 研究动机与核心问题
*   **背景**：随着智能体 AI（Agentic AI）的兴起，长上下文（Long-context）请求日益增多。为了提高效率，业界普遍采用分布式前缀缓存（Distributed Prefix Caching）技术（如 Mooncake, LMCache），将 KVCache 存储在远程节点（L3）中以实现复用。
*   **核心问题**：在“长上下文、短查询”的场景下，从远程服务器检索 KVCache 的网络传输延迟已成为新的性能瓶颈，作者称之为**网络密集型 LLM 推理**。
*   **现有缺陷**：目前的推理引擎（如 vLLM）是“以计算为中心”的，将 KVCache 加载视为计算的附属阶段。这导致了两个问题：
    1.  **资源利用率低**：采用集中式控制，各阶段（L3→L2, L2→L1, 计算）无法充分流水线化，导致网络、PCIe 和 GPU 资源出现空闲。
    2.  **调度不准确**：调度器（如 FIFO 或基于计算量的 SJF）忽略了巨大的 KVCache 加载成本，导致服务顺序非最优，损害了首字延迟（TTFT）和 SLO 达成率。

### 2. 方法论
CALVO 的核心思想是将 **KVCache 加载视为与计算同等地位的“一等公民”**，通过解耦和成本感知优化服务效率。
*   **阶段间工作流优化（解耦控制）**：
    *   **独立调度执行**：为每个加载阶段（L3→L2, L2→L1）引入独立的调度器（Dispatcher）和执行器（Executor）对。
    *   **主动空间分配**：低层调度器会主动触发高层存储空间的分配（例如 L3→L2 调度时同时请求 GPU 显存分配），从而在数据依赖满足时立即开始异步加载，实现网络传输、PCIe 传输与 GPU 计算的深度重叠。
*   **请求间调度优化（成本感知）**：
    *   **二元线性成本模型**：通过系统分析，将预填充（Prefill）成本建模为 $T_{load}$（加载延迟，与 token 数线性相关）和 $T_{comp}$（计算延迟）之和。
    *   **优化算法**：
        *   **最小化平均 TTFT**：采用基于总预填充成本的短作业优先（SJF）策略。
        *   **最大化 SLO 达成率**：采用最小松弛时间优先（LSTF）策略，其中松弛时间定义为 $DDL - (T_{load} + T_{comp})$。

### 3. 实验设计
*   **数据集/场景**：选取了三个代表性的长上下文数据集：
    *   **LooGLE**：长文档问答。
    *   **ICL**：多样本上下文学习（分类、推理等）。
    *   **Code**：项目级代码补全。
*   **模型**：Llama-3.1-8B-Instruct 和 Qwen2.5-14B-Instruct-1M。
*   **基准方法（Benchmark）**：主流的 vLLM (v0.9.1) 集成 LMCache (v0.3.1) 方案。
*   **对比实验**：对比了 CALVO、不带调度优化的 CALVO（仅阶段解耦）以及原始基准方案。

### 4. 资源与算力
*   **硬件平台**：
    *   **GPU 节点**：1 台配备 80GB 显存 GPU 的服务器，128GB CPU DRAM。
    *   **远程存储节点**：1 台配备 512GB DRAM 的 CPU 服务器。
    *   **网络**：两节点通过 400 Gbps RDMA 链路互连。
*   **软件实现**：基于 vLLM 和 LMCache，使用 ZeroMQ 进行进程间通信，Mooncake 作为 L3 存储后端。

### 5. 实验数量与充分性
*   **实验规模**：
    *   针对 2 个模型、3 个数据集在不同查询强度（QPS 从 0.5 到 4）下进行了端到端性能测试。
    *   进行了消融实验，验证了调度优化（SJF/LSTF）相对于阶段解耦的独立贡献。
    *   进行了微基准测试（Micro-benchmarks），包括成本模型的准确性验证、不同调度策略（EDF vs LSTF）的对比以及缓存命中率的敏感性分析。
*   **充分性**：实验覆盖了当前长上下文推理的主要痛点，对比维度全面，使用了真实的硬件环境和主流开源模型，实验设计较为客观公平。

### 6. 主要结论与发现
*   **性能提升**：在网络密集型负载下，CALVO 显著降低了平均 TTFT。在 ICL 数据集（QPS=1.2）下，平均 TTFT 降低了 **81.3%**。
*   **SLO 优化**：CALVO 的 SLO 达成率比基准方案高出多达 **61.67%**。
*   **调度关键性**：实验证明，如果调度器对加载成本“失明”，即使采用 SJF 也会因为优先级错误导致性能甚至不如 FIFO；而 CALVO 的二元成本模型能提供准确的优先级排序。

### 7. 优点
*   **视角独特**：敏锐捕捉到分布式缓存普及后，LLM 推理从“计算密集型”向“网络密集型”转变的趋势。
*   **系统性解耦**：通过异步调度和主动分配机制，打破了传统推理引擎串行控制的瓶颈，极大地提升了硬件流水线的并行度。
*   **实用性强**：直接在 vLLM 等主流框架上实现，且对生产环境中的 SLO 管理有直接提升。

### 8. 不足与局限
*   **显存开销**：主动空间分配机制虽然提升了速度，但会提前占用 GPU 显存，在显存极度紧张的场景下可能导致 Batch Size 受限或触发回退机制。
*   **覆盖范围**：研究主要集中在 Prefill（预填充）阶段的 TTFT 优化，对于 Decoding（解码）阶段以及长输出请求的优化讨论较少。
*   **模型规模限制**：实验主要在 8B 和 14B 模型上完成，对于超大规模模型（如 70B+）在多卡张量并行（TP）环境下的网络竞争情况尚需进一步验证。
