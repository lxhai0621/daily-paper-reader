## 摘要
基于大语言模型（LLM）的智能体依赖记忆机制来重用过去解决问题经验中的知识。现有方法通常以单智能体的方式构建记忆，将存储的知识与单个模型的推理风格紧密耦合。在具有异构智能体的现代部署中，一个自然产生的问题是：单个记忆系统能否在不同模型之间共享？我们发现，在智能体之间直接迁移记忆往往会导致性能下降，因为此类记忆将任务相关知识与智能体特有的偏置纠缠在一起。为了应对这一挑战，我们提出了 MemCollab，这是一个协作记忆框架，通过对比不同智能体在同一任务上生成的推理轨迹来构建与智能体无关的记忆。这一对比过程蒸馏出了抽象的推理约束，这些约束捕捉了共享的任务级不变性，同时抑制了智能体特有的偏差。我们进一步引入了一种任务感知检索机制，根据任务类别对记忆访问进行条件化处理，确保在推理时仅使用相关的约束。在数学推理和代码生成基准测试上的实验表明，MemCollab 在包括跨模型家族设置在内的多种智能体中，一致地提高了准确性和推理效率。我们的结果表明，协作构建的记忆可以作为多种基于 LLM 的智能体的共享推理资源。

## Abstract
Large language model (LLM)-based agents rely on memory mechanisms to reuse knowledge from past problem-solving experiences. Existing approaches typically construct memory in a per-agent manner, tightly coupling stored knowledge to a single model's reasoning style. In modern deployments with heterogeneous agents, a natural question arises: can a single memory system be shared across different models? We found that naively transferring memory between agents often degrades performance, as such memory entangles task-relevant knowledge with agent-specific biases. To address this challenge, we propose MemCollab, a collaborative memory framework that constructs agent-agnostic memory by contrasting reasoning trajectories generated by different agents on the same task. This contrastive process distills abstract reasoning constraints that capture shared task-level invariants while suppressing agent-specific artifacts. We further introduce a task-aware retrieval mechanism that conditions memory access on task category, ensuring that only relevant constraints are used at inference time. Experiments on mathematical reasoning and code generation benchmarks demonstrate that MemCollab consistently improves both accuracy and inference-time efficiency across diverse agents, including cross-modal-family settings. Our results show that the collaboratively constructed memory can function as a shared reasoning resource for diverse LLM-based agents.

### 2. 论文提出的方法论：MemCollab
MemCollab 框架分为两个主要阶段：**对比驱动的记忆构建**和**任务感知的记忆检索与推理**。

*   **核心思想**：通过对比不同智能体在同一任务上的推理轨迹（Trajectory），识别出导致成功的“推理不变性（Invariants）”和导致失败的“错误模式（Error Patterns）”，从而蒸馏出抽象的推理约束。
*   **关键技术细节**：
    1.  **轨迹配对与偏好选择**：让强、弱两个智能体（如 32B 和 7B）处理同一任务，根据结果将其分为“首选轨迹（$\tau^+$）”和“非首选轨迹（$\tau^-$）”。
    2.  **对比轨迹分析**：利用骨干模型对比 $\tau^+$ 和 $\tau^-$，提取出结构化的引导信息。
    3.  **记忆条目生成**：将差异总结为规范性约束，格式为：`执行 [不变性推理步骤]；避免 [特定错误模式]`。这些约束使用抽象概念（如变量隔离、案例枚举）而非具体数值。
    4.  **任务感知检索**：
        *   **分类**：使用 LLM 将任务预先分类（如代数、数论、代码逻辑等）。
        *   **路由**：推理时先识别新任务类别，仅在同类记忆池中进行相似度检索，以减少噪声干扰。
*   **算法流程**：
    *   构建期：输入任务集 $\rightarrow$ 生成轨迹对 $\rightarrow$ 对比蒸馏 $\rightarrow$ 存入分类记忆库。
    *   推理期：输入新查询 $\rightarrow$ 任务分类 $\rightarrow$ 检索 Top-p 约束 $\rightarrow$ 增强提示词（Prompting） $\rightarrow$ 智能体生成答案。

### 6. 论文的主要结论与发现
1.  **协作记忆优于单体记忆**：MemCollab 构建的记忆在所有测试中均优于模型使用自身轨迹构建的记忆。
2.  **跨模型增益显著**：弱模型（7B/8B）在获得协作记忆后，性能大幅提升，甚至在某些指标上接近强模型。
3.  **强模型同样受益**：即使是 32B 的强模型，在使用协作记忆后也能减少系统性错误，进一步提升准确率。
4.  **推理效率提升**：由于记忆提供了明确的“避坑指南”，智能体在推理过程中的平均尝试轮数（Reasoning Turns）显著减少（例如在代码任务中减少了约 50%）。
5.  **跨架构兼容性**：对比不同架构的模型（如 Llama 和 Qwen）产生的记忆比同架构模型更具互补性，效果有时更好。

### 7. 优点（亮点）
*   **解耦思想**：成功将“任务逻辑”与“模型风格”解耦，解决了异构智能体记忆共享的难题。
*   **对比学习的应用**：巧妙地将对比学习（Contrastive Learning）引入轨迹分析，通过“找茬”的方式精准定位关键推理步骤。
*   **任务感知检索**：引入分类过滤机制，有效解决了长上下文或无关记忆带来的干扰（Noise）问题。
*   **实用性强**：不仅提升了准确率，还通过减少推理轮数降低了推理成本。

### 8. 不足与局限
*   **构建成本**：需要同时运行多个模型生成轨迹并进行对比，初始的记忆库构建成本高于单模型方法。
*   **依赖强模型蒸馏**：对比分析过程通常需要一个较强的模型（如 32B 或更高）来总结规律，若缺乏强模型，蒸馏质量可能受限。
*   **任务类型局限**：目前主要集中在数学和代码等逻辑严密的结构化任务上，在创意写作或开放式对话等非结构化任务上的效果尚待验证。
*   **分类器依赖**：检索效果高度依赖于第一步的任务分类准确性，若分类错误，检索到的记忆可能产生负面引导。
