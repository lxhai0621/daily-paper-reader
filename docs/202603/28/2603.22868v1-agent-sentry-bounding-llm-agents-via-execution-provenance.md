## 摘要
代理计算系统能够根据自然语言指令自主生成新功能，正变得日益普及。尽管这些系统功能强大，但也引发了严重的安全性、隐私和安全问题。从根本上说，这些系统提供的全套功能及其概率性的执行流是无法预先获知的。由于缺乏这种特征描述，验证系统是成功执行了用户的预期任务，还是执行了无关操作（可能是由于受到攻击所致），变得非常困难。在本文中，我们提出了 Agent-Sentry，这是一个旨在通过约束代理系统来解决该问题的框架。我们的核心见解是，代理系统是为特定用例设计的，因此不需要暴露无限制或未指定的功能。一旦受到约束，这些系统就更容易被审查。Agent-Sentry 通过挖掘代理系统提供的常用功能及其执行轨迹来构建行为边界，从而实现这一见解。随后，它从这些轨迹中学习策略，并拦截偏离已学习行为或与用户意图不符的工具调用。我们的评估表明，Agent-Sentry 有助于防止超过 90% 试图触发越界执行的攻击，同时保留了高达 98% 的系统效用。

## Abstract
Agentic computing systems, which autonomously spawn new functionalities based on natural language instructions, are becoming increasingly prevalent. While immensely capable, these systems raise serious security, privacy, and safety concerns. Fundamentally, the full set of functionalities offered by these systems, combined with their probabilistic execution flows, is not known beforehand. Given this lack of characterization, it is non-trivial to validate whether a system has successfully carried out the user's intended task or instead executed irrelevant actions, potentially as a consequence of compromise. In this paper, we propose Agent-Sentry, a framework that attempts to bound agentic systems to address this problem. Our key insight is that agentic systems are designed for specific use cases and therefore need not expose unbounded or unspecified functionalities. Once bounded, these systems become easier to scrutinize. Agent-Sentry operationalizes this insight by uncovering frequent functionalities offered by an agentic system, along with their execution traces, to construct behavioral bounds. It then learns a policy from these traces and blocks tool calls that deviate from learned behaviors or that misalign with user intent. Our evaluation shows that Agent-Sentry helps prevent over 90\% of attacks that attempt to trigger out-of-bounds executions, while preserving up to 98\% of system utility.

*   **核心挑战**：由于智能体的执行流是概率性的且功能集预先不可知，很难验证其操作是符合用户意图的合法行为，还是受到攻击后的恶意行为。
*   **整体含义**：论文提出 **Agent-Sentry** 框架，核心见解是：特定用途的智能体（如银行、旅游助手）在实际使用中表现出高度的规律性。通过学习这些规律并构建“功能图”（Functionality Graphs），可以为智能体设定行为边界，从而在不牺牲灵活性的前提下实现安全管控。

### 2. 方法论
Agent-Sentry 结合了结构化行为分析和语义意图验证：
*   **执行溯源（Execution Provenance）**：记录工具调用的顺序（控制流）和参数来源（数据溯源）。将执行轨迹抽象为不含具体敏感数据的执行流。
*   **功能图构建**：
    *   从良性轨迹中提取**良性功能图**。
    *   从攻击轨迹中提取**攻击功能图**。
    *   两者重合的部分标记为**歧义功能图**。
*   **运行时强制执行**：
    *   拦截智能体的工具调用。
    *   若匹配良性图，则允许执行；若匹配攻击图，则拦截。
    *   若匹配歧义图或属于从未见过的流，则触发**意图对齐检查（Intent Alignment）**。
*   **意图对齐检查**：利用 LLM 作为裁判，仅基于**受信任的输入**（原始用户请求、工具调用历史、当前工具描述）来判断当前操作是否符合用户初衷，从而规避注入在检索内容中的恶意指令。

### 6. 主要结论与发现
*   **高安全性与高效用**：Agent-Sentry 在 Agent-Sentry Bench 上阻止了超过 90% 的攻击，同时保留了 95% 以上的效用；在 AgentDojo 上，攻击成功率（ASR）降至 3.7%，效用保留高达 98%。
*   **覆盖率影响**：随着功能图覆盖率增加，系统效用稳步提升。即使在 50% 的低覆盖率下，系统通过保守拦截仍能保持极低的攻击成功率。
*   **防御优势**：相比 CaMeL（延迟高、效用低）和 Progent（需手动编写规则、扩展性差），Agent-Sentry 在效用、安全性和延迟之间取得了最佳平衡。

### 7. 优点
*   **自动化策略学习**：无需手动编写复杂的安全规则，通过观察历史轨迹自动学习行为边界。
*   **混合防御机制**：结合了确定性的结构匹配（功能图）和概率性的语义推理（意图对齐），兼顾效率与准确性。
*   **鲁棒性**：意图对齐检查仅依赖受信任输入，天然免疫针对防御层本身的“元注入”攻击。
*   **低开销**：大部分决策通过图匹配完成，仅在歧义情况下调用 LLM，显著降低了推理延迟。

### 8. 不足与局限
*   **拟态攻击（Mimicry Attacks）**：如果攻击者精心构造攻击流，使其在结构和语义上完全模仿良性行为（例如修改转账金额但保持转账动作本身），系统可能难以识别。
*   **冷启动问题**：系统依赖于初始的执行轨迹积累，对于全新的、从未见过的良性工作流，初期可能会有较高的拦截率或依赖频繁的意图检查。
*   **应用限制**：目前主要针对特定领域的智能体，对于完全通用的、行为极度发散的通用助手，功能图的构建可能会面临组合爆炸问题。
