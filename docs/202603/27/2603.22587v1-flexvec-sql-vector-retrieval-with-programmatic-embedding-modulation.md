## 摘要
随着 AI 智能体成为检索 API 的主要消费者，有机会向调用者暴露更多的检索流水线。flexvec 是一个检索内核，它将嵌入矩阵和评分数组暴露为可编程表面，允许在选择之前对两者进行算术运算。我们将查询时在该表面上组合操作称为程序化嵌入调制（PEM）。本文描述了一组此类操作，并通过一个支持可组合查询原语的查询物化器将其集成到 SQL 接口中。在包含 240,000 个数据块（chunks）的生产语料库上，在不使用近似索引的情况下，三种组合调制在台式机 CPU 上端到端执行仅需 19 毫秒。在一百万个数据块的规模下，相同的操作在 82 毫秒内执行。

## Abstract
As AI agents become the primary consumers of retrieval APIs, there is an opportunity to expose more of the retrieval pipeline to the caller. flexvec is a retrieval kernel that exposes the embedding matrix and score array as a programmable surface, allowing arithmetic operations on both before selection. We refer to composing operations on this surface at query time as Programmatic Embedding Modulation (PEM). This paper describes a set of such operations and integrates them into a SQL interface via a query materializer that facilitates composable query primitives. On a production corpus of 240,000 chunks, three composed modulations execute in 19 ms end-to-end on a desktop CPU without approximate indexing. At one million chunks, the same operations execute in 82 ms.

### 2. 论文提出的方法论
*   **核心思想**：将嵌入矩阵保留在内存中（不使用近似索引 ANN），利用暴力搜索（Brute-force）的高效矩阵运算，在评分和选择阶段之间插入可编程的调制算术操作。
*   **三阶段架构**：
    1.  **Phase 1: SQL 预过滤**：利用标准 SQL 子查询缩小候选集（如按项目、时间过滤），解决“池饥饿”问题。
    2.  **Phase 2: numpy 调制**：在内存中执行矩阵乘法计算余弦相似度，随后应用 PEM 算子（如 `suppress` 抑制、`decay` 衰减、`diverse` 多样化等）重塑评分。
    3.  **Phase 3: SQL 组合**：将评分最高的 K 个结果物化为临时表，与原数据库进行 JOIN 操作，完成最终的元数据关联和排序。
*   **关键技术细节（PEM 算子）**：
    *   `suppress:X`：从当前评分中减去与概念 X 的方向相似度（`scores -= w * (M @ embed(X))`）。
    *   `decay:N`：按半衰期 N 天进行倒数衰减（`scores *= 1/(1 + days/N)`）。
    *   `centroid:ids`：将查询向量向已知相关文档的质心偏移（Rocchio 反馈）。
    *   `from:A to:B`：沿特定轨迹（如从原型到生产）增强相似度。
    *   `diverse`：使用最大边际相关性（MMR）算法迭代选择，平衡相关性与多样性。
*   **查询物化器**：一个拦截器，识别 SQL 中的伪函数（如 `vec_ops`），在外部执行 numpy 运算并重写 SQL 交给 SQLite 执行。
