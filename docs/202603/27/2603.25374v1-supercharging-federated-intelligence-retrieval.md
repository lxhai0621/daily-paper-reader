## 摘要
RAG 通常假设可以集中访问文档，但当知识分布在私有数据孤岛中时，这一假设便不再成立。我们提出了一个使用 Flower 构建的安全联邦 RAG 系统，该系统执行本地孤岛检索，而服务器端的聚合和文本生成则在经过认证的机密计算环境中运行，从而在存在“诚实但好奇”或被攻破的服务器的情况下，依然能够实现机密的远程大语言模型（LLM）推理。此外，我们还提出了一种级联推理方法，在不削弱机密性的前提下，将非机密第三方模型（如 Amazon Nova）作为辅助上下文引入。

## Abstract
RAG typically assumes centralized access to documents, which breaks down when knowledge is distributed across private data silos. We propose a secure Federated RAG system built using Flower that performs local silo retrieval, while server-side aggregation and text generation run inside an attested, confidential compute environment, enabling confidential remote LLM inference even in the presence of honest-but-curious or compromised servers. We also propose a cascading inference approach that incorporates a non-confidential third-party model (e.g., Amazon Nova) as auxiliary context without weakening confidentiality.

### 1. 核心问题与研究动机
*   **核心问题**：传统的检索增强生成（RAG）假设可以集中访问所有文档，但在医疗、金融等敏感领域，数据通常分布在不同的私有孤岛（Silos）中，且受法规限制无法汇总。
*   **研究动机**：现有的联邦 RAG（FedRAG）虽然解决了数据本地化问题，但安全性不足。检索到的文档在服务端聚合和生成阶段通常以明文形式存在，容易受到“诚实但好奇”或已被攻破的服务器运营商的威胁。
*   **目标**：构建一个端到端安全的联邦 RAG 系统，确保从检索、聚合到 LLM 推理的全过程机密性。

### 2. 方法论
该系统基于 **Flower** 联邦学习框架构建，核心思想是将机密计算（Confidential Computing）与联邦检索相结合。
*   **关键技术细节**：
    *   **本地检索**：每个客户端（数据孤岛）使用 FAISS 索引对其私有语料库进行本地检索。
    *   **机密聚合**：服务器运行在**受信任执行环境（TEE）**中。它接收各客户端返回的 Top-k 文档及其评分，在 TEE 内部进行合并和重排序。
    *   **重排序算法**：采用倒数排名融合（Reciprocal Rank Fusion, RRF），公式为：$Score = 1 / (k_{RRF} + doc\_rank + 1)$。
    *   **三种推理模式**：
        1.  **独立推理 (Standalone)**：在服务器 TEE 内的 CPU 上运行轻量级 LLM（如 SmolLM）。
        2.  **级联推理 (Cascading)**：将非机密第三方模型（如 AWS Nova）的预测结果作为辅助上下文，输入到 TEE 内的机密模型中，实现“混合信任”推理。
        3.  **机密推理 (Confidential)**：利用 **Flower CRC**（机密远程计算），在配备硬件保护（如 H100 GPU）的远程环境中运行大规模模型（如 Qwen3）。

### 3. 实验设计
*   **数据集/场景**：使用了 MedRAG Toolkit 中的四个医疗语料库：PubMed (23.9M 摘要)、StatPearls (301k)、Textbooks (126k) 和 Wikipedia (29.9M)。
*   **Benchmark**：MIRAGE 医疗问答基准测试，包括 PubMedQA、BioASQ 和 MedQA。
*   **对比方法**：对比了上述三种推理模式（Standalone vs. Cascading vs. Confidential），评估指标为准确率（Accuracy）和端到端查询时间（Time）。

### 4. 资源与算力
*   **本地模型**：服务端 TEE 内部部署了 **SmolLM 1.7B Instruct**，完全基于 **CPU** 运行，未开启 GPU 加速。
*   **第三方模型**：使用了 **Amazon Nova Micro**。
*   **高性能模型**：Flower CRC 模式下使用了 **Qwen3 235B**，运行在 **NVIDIA H100 GPU** 上。
*   **参数设置**：Top-k 设为 8，$k_{RRF}$ 设为 60。

### 5. 实验数量与充分性
*   **实验规模**：针对三个主流医疗数据集进行了完整的端到端测试。
*   **充分性评价**：实验设计较为合理，涵盖了从轻量级 CPU 推理到高性能 GPU 推理的多种场景。通过对比级联推理和独立推理，验证了引入外部知识的有效性。
*   **局限性**：实验主要集中在医疗垂直领域，缺乏在通用领域或其他行业（如法律、金融）的泛化性验证。

### 6. 主要结论与发现
*   **级联推理的优越性**：即使使用轻量级的第三方模型（Nova Micro）提供辅助上下文，也能显著提升性能。在 PubMedQA 和 MedQA 上，准确率分别提升了约 40% 和 46%。
*   **机密推理的性能**：使用 Flower CRC（Qwen3 + H100）获得了最高的准确率和最低的延迟（约 25s），证明了高性能硬件在机密计算中的重要性。
*   **安全性与效能平衡**：证明了在 CPU 绑定的 TEE 环境中，通过级联机制可以克服算力限制，在保证隐私的前提下获得可用的推理性能。

### 7. 优点
*   **端到端安全性**：通过 TEE 和远程认证（Attestation）确保了文档聚合和 LLM 推理过程中的数据不外泄。
*   **架构灵活性**：提出的级联推理模式允许在不牺牲机密性的情况下利用强大的第三方 API。
*   **实用性强**：基于 Flower 框架，能够很好地处理异构客户端和复杂的联邦工作流。

### 8. 不足与局限
*   **硬件依赖**：系统高度依赖支持 TEE（如 Intel SGX/TDX 或 NVIDIA H100 TEE）的硬件基础设施。
*   **CPU 推理延迟**：在 Standalone 模式下，由于 TEE 内 CPU 推理速度限制，单次查询耗时超过 40 秒，难以满足实时性要求。
*   **侧信道风险**：论文明确指出侧信道攻击（Side-channel attacks）不在其讨论的安全边界内。
*   **评估范围**：未讨论大规模客户端（如成千上万个孤岛）情况下的通信开销和扩展性问题。
