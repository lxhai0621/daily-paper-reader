## 摘要
新兴的智能体网络（agentic web）构想了这样一种愿景：AI 智能体通过与现有的 Web 服务交互，可靠地完成用户基于自然语言（NL）的任务。然而，现有的授权模型与这一愿景并不匹配。特别是，以 OAuth 为代表的当今基于操作算子范围（operator-scoped）的授权，授予的是与操作算子（例如转账操作）相关的广泛权限，而非用户任务所隐含的具体操作（例如向 Bob 转账 100 美元）。这将不可避免地导致智能体权限过大。我们提出了精确任务范围隐式授权（PAuth），这是一种根本不同的模型，其中提交自然语言任务会隐式地仅授权其忠实执行所需的具体操作。为了使其在服务器端可强制执行，我们提出了 NL 切片（NL slices）：这是根据任务和上游结果推导出的、每个服务所预期的调用的符号化规范。作为补充，我们还提出了信封（envelopes）：一种特殊的数据结构，用于将每个操作数的具体值与其符号溯源（symbolic provenance）绑定，使服务器能够验证所有操作数均源自合法的计算。PAuth 在智能体安全评估框架 AgentDojo 中实现了原型。我们在良性设置和攻击场景（在正常的任务中注入伪造操作）下对其进行了评估。在所有良性测试中，PAuth 成功执行了任务，且无需任何额外权限。在所有攻击测试中，PAuth 均正确地发出了权限缺失的警告。这些结果表明，PAuth 对权限的推理确实是精确的。我们进一步分析了这些任务的特征，并测量了相关的 token 开销。

## Abstract
The emerging agentic web envisions AI agents that reliably fulfill users' natural-language (NL)-based tasks by interacting with existing web services. However, existing authorization models are misaligned with this vision. In particular, today's operator-scoped authorization, exemplified by OAuth, grants broad permissions tied to operators (e.g., the transfer operator) rather than to the specific operations (e.g., transfer $100 to Bob) implied by a user's task. This will inevitably result in overprivileged agents.   We introduce Precise Task-Scoped Implicit Authorization (PAuth), a fundamentally different model in which submitting an NL task implicitly authorizes only the concrete operations required for its faithful execution. To make this enforceable at servers, we propose NL slices: symbolic specifications of the calls each service expects, derived from the task and upstream results. Complementing this, we also propose envelopes: special data structure to bind each operand's concrete value to its symbolic provenance, enabling servers to verify that all operands arise from legitimate computations.   PAuth is prototyped in the agent-security evaluation framework AgentDojo. We evaluate it in both benign settings and attack scenarios where a spurious operation is injected into an otherwise normal task. In all benign tests, PAuth executes the tasks successfully without requiring any additional permissions. In all attack tests, PAuth correctly raises warnings about missing permissions. These results demonstrate that PAuth's reasoning about permissions is indeed precise. We further analyze the characteristics of these tasks and measure the associated token costs.

### 论文总结：PAuth - 面向智能体的精确任务范围授权

#### 1. 核心问题与整体含义（研究动机和背景）
随着 AI 智能体（Agents）在 Web 任务（如购物、转账、预订）中的应用日益广泛，传统的授权模型（如 OAuth 2.0）暴露出严重的安全隐患。
*   **核心矛盾**：现有的授权是**“操作员范围”（Operator-scoped）**的。例如，为了让智能体转账 100 美元，用户必须授予其“转账”权限，但这通常意味着智能体获得了向任何人转账任意金额的广泛权限。
*   **安全风险**：这种权限过大（Overprivilege）使得智能体在遭遇提示词注入（Prompt Injection）或发生幻觉时，可能执行非用户意图的恶意操作。
*   **研究目标**：提出一种**“精确任务范围”（Precise Task-scoped）**的授权模型，确保智能体仅被授予完成特定自然语言任务所必需的、最小化的权限。

#### 2. 方法论：核心思想与关键技术
PAuth 的核心思想是将授权与具体的自然语言任务语义绑定，通过以下两个关键机制实现：

*   **自然语言切片（NL Slice）**：
    *   **生成**：当用户提交任务时，服务端利用 LLM 将自然语言任务转化为一段符号化的命令代码（Imperative Code）。
    *   **定义**：针对每一个具体的 API 调用，服务端推导出其“切片”——即该调用在任务逻辑中所期望的符号化表示（包括操作数、前置条件和计算逻辑）。
    *   **作用**：它定义了“什么样的调用是合法的”，例如：`Chase.transfer(User, Citi, Citi.getBalance()/4)`。

*   **信封机制（Envelopes）**：
    *   **结构**：一种绑定了“具体数值”与“符号溯源（Symbolic Provenance）”的数据结构。
    *   **验证**：服务端产生的信封会经过数字签名。当智能体调用下一个服务时，必须携带之前步骤产生的信封。
    *   **逻辑**：接收端服务器会验证：(1) 签名是否真实；(2) 具体数值是否符合符号溯源的计算逻辑；(3) 该调用是否符合预先生成的 NL 切片。

*   **工作流程**：用户提交任务 -> 服务端生成切片规则 -> 智能体执行任务并传递信封 -> 服务端实时拦截并校验每一条指令的精确性。

#### 7. 优点
*   **范式创新**：从传统的“基于身份/操作员”的授权转向“基于任务语义”的授权，解决了智能体权限过大的根本问题。
*   **隐式授权**：用户只需提交任务，无需频繁点击“允许”弹窗，提升了用户体验。
*   **可验证性**：通过信封和签名机制，在不可信的智能体环境下建立了可信的数据流链路。

*   **部署开销**：每个 Web 服务都需要集成 PAuth 运行时并调用 LLM，对于小型服务商可能存在技术和成本门槛。
*   **隐私权衡**：为了验证调用，服务端需要了解任务的部分上下文，这在多方协作中可能涉及一定的隐私泄露风险（尽管论文提出了“按需获知”原则）。
