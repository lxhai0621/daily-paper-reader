## 摘要
现有的基于大语言模型（LLM）的 Kubernetes 诊断系统无法从运维经验中学习，仅在静态知识库上运行，无法从过去的解决方案中获得提升。我们提出了 MetaKube，这是一种通过三项协同创新实现的经验感知型 LLM 框架：(1) 情节模式记忆网络（EPMN），它从历史解决方案中抽象出诊断模式，并提供置信度校准的检索，以实现快速模式匹配和引导式因果探索；(2) 元认知控制器，根据问题的熟悉程度在直觉和分析路径之间进行动态路由，从而优化速度与深度之间的权衡；(3) KubeLLM，一个可本地部署的 8B 模型，通过在我们包含 7,000 个样本的 Kubernetes 故障解决数据集上进行领域特定的后训练得到增强。对 1,873 个真实场景的评估表明，MetaKube 将 Qwen3-8B 的评分从 50.9 提升至 90.5 分，在确保完全数据隐私的同时，性能接近 GPT-4.1。EPMN 通过经验学习贡献了 15.3% 的提升，持续学习实验显示，随着系统积累运维知识，性能会逐步提高。源代码及相关资源可在 https://github.com/MetaKube-LLM-for-Kubernetes-Diagnosis/MetaKube 获取。

## Abstract
Existing LLM-based Kubernetes diagnostic systems cannot learn from operational experience, operating on static knowledge bases without improving from past resolutions. We present MetaKube, an experience-aware LLM framework through three synergistic innovations: (1) an Episodic Pattern Memory Network (EPMN) that abstracts diagnostic patterns from historical resolutions and provides confidence-calibrated retrieval for both rapid pattern matching and guided causal exploration, (2) a meta-cognitive controller that dynamically routes between intuitive and analytical pathways based on problem familiarity, optimizing the trade-off between speed and depth, and (3) KubeLLM, a locally-deployable 8B model enhanced through domain-specific post-training on our 7,000-sample Kubernetes Fault Resolution Dataset. Evaluation on 1,873 real-world scenarios demonstrates MetaKube transforms Qwen3-8B from 50.9 to 90.5 points, approaching GPT-4.1 performance while ensuring complete data privacy. EPMN contributes 15.3% improvement through experiential learning, with continuous learning experiments showing progressive gains as the system accumulates operational knowledge. The source code and related resources are available at https://github.com/MetaKube-LLM-for-Kubernetes-Diagnosis/MetaKube.

### MetaKube：一种用于 Kubernetes 故障诊断的经验感知型大语言模型框架

#### 1. 核心问题与整体含义
Kubernetes（K8s）作为现代云原生基础设施，其架构复杂且组件依赖繁多，导致故障诊断极具挑战。现有的基于大语言模型（LLM）的诊断方案存在三大痛点：
*   **缺乏经验学习能力**：大多依赖静态知识库（如 RAG），无法从过去的诊断案例中积累经验，导致“同样的坑掉两次”。
*   **高质量数据稀缺**：K8s 诊断知识分散在文档、论坛和私有运行手册中，缺乏结构化的训练数据。
*   **隐私与性能权衡**：企业环境对数据隐私要求极高，禁止使用闭源 API，而本地部署的小参数模型（<10B）通常缺乏足够的逻辑推理能力。

**MetaKube** 旨在通过引入“经验感知”机制，使本地部署的小规模模型能够像专家一样，既能利用直觉快速匹配历史模式，又能通过严谨的因果推理解决复杂问题。

#### 2. 方法论
MetaKube 模拟了人类专家的**认知双过程理论**，构建了双路径诊断架构：

*   **核心组件**：
    1.  **情节模式记忆网络 (EPMN)**：这是系统的“经验大脑”。它存储具体的诊断情节（Episodes），并将其抽象为通用模式（Patterns）。通过余弦相似度和时间衰减因子（Recency）计算置信度，实现经验的快速检索。
    2.  **元认知控制器 (Meta-cognitive Controller)**：充当“调度员”。根据问题熟悉度（记忆匹配的置信度）动态路由：
        *   **直觉路径 (Intuitive Pathway)**：若置信度高，直接调用 EPMN 匹配的模式生成方案，响应极快。
        *   **分析路径 (Analytical Pathway)**：若置信度低（新问题），则结合知识图谱（KubeGraph）进行多步因果链探索。
    3.  **KubeLLM**：基于 Qwen3-8B，通过在 7,000 条领域特定数据上进行后训练（SFT + LoRA）得到的专用模型。
    4.  **KubeGraph**：利用 LLM 从官方文档、技术博客和书籍中提取实体与关系，构建的 K8s 专用因果知识图谱。

*   **算法流程**：输入查询 $Q$ $\rightarrow$ EPMN 检索模式 $\rightarrow$ 元认知控制器评估置信度 $\rightarrow$ 选择路径 $\rightarrow$ KubeLLM 生成最终诊断建议 $\rightarrow$ 诊断结果反馈至 EPMN 进行持续学习。

*   **小模型潜力**：通过领域微调和认知架构优化，本地部署的 8B 模型完全可以胜任复杂的工业级诊断任务，同时解决隐私忧虑。

#### 7. 优点
*   **架构创新**：首次将情节记忆和元认知路由引入 K8s 诊断，解决了 LLM 在运维中的“健忘”和“推理深度不足”问题。
*   **数据贡献**：发布了 KFRD 数据集，填补了 K8s 领域高质量诊断语料的空白。
*   **实用性强**：强调本地化部署和数据隐私，非常符合电信、金融等对安全性敏感的行业需求。

#### 8. 不足与局限
*   **合成数据风险**：KFRD 数据集中包含部分由 LLM 生成的增强数据，可能存在潜在的偏见或幻觉传递。

*   **维护成本**：随着 K8s 版本迭代，KubeGraph 和 EPMN 的知识更新需要持续的人工或自动化维护。
