## 摘要
检索增强生成（RAG）通过语义相似性对段落进行排序，隐式假设语义相似性是下游任务中可靠适用性的指示。当任务成功不依赖于主题相关性，而是依赖于应用正确的规则、约束或流程指导时，这一假设就会失效。在这种情况下，最有用的上下文可能是输入触发的规则，而非最语义相似的段落。我们提出任务对齐检索（TAG），这是一个用基于适用性的规则选择替代基于相似性检索的检索框架。TAG将源文档转换为可追踪的条件-动作规则，通过成对LLM判断识别哪些规则适用于给定输入，并仅基于选定的动作生成输出。我们通过实验观察到，在维基百科NPOV重写、符合PEP~8的HumanEval以及RuleArena上的NBA交易推理任务中，TAG始终优于标准RAG，在高不匹配场景下提升最大（高达12.2%），同时将检索上下文减少多达93%。这些结果表明，在规则和指令驱动的任务中，检索应优化适用性，而非仅优化语义相似性。

## Abstract
Retrieval-augmented generation (RAG) ranks passages by semantic similarity to the input, implicitly assuming that semantic similarity is a reliable indication of applicability in downstream tasks. This assumption breaks down when task success depends not on topical relevance but on applying the correct rules, constraints, or procedural guidance. In such settings, the most useful context may be the rule triggered by the input rather than the most semantically similar passage. We propose Task-Aligned Retrieval (TAG), a retrieval framework that replaces similarity-based retrieval with applicability-based rule selection. TAG transforms source documents into traceable condition-action rules, identifies which rules apply to a given input through pairwise LLM judgments, and generates the output conditioned only on the selected actions. We empirically observe that across Wikipedia NPOV rewriting, HumanEval with PEP~8 compliance, and NBA transaction reasoning on RuleArena, TAG consistently outperforms standard RAG, with the largest gains in high-mismatch settings (up to 12.2\%) while reducing retrieved context by up to 93\%. These results suggest that, in rule- and instruction-governed tasks, retrieval should optimize for applicability rather than for semantic similarity alone.

## 1. 核心问题与整体含义（研究动机与背景）
- **核心问题**：标准检索增强生成（RAG）基于语义相似性检索上下文，但在规则约束型任务（如政策合规、代码风格检查、交易合法性判断）中，任务成功取决于**匹配正确的规则**而非**主题相似性**。语义相似性与下游任务实用性之间存在系统性偏差，作者称为**“检索目标失配”**。
- **整体含义**：在规则与指令驱动的任务中，检索应当从“相似性优先”转向“**适用性优先**”，即根据输入是否满足规则的条件来检索，而非根据语义向量距离。

## 2. 论文提出的方法论：TAG 框架
### 核心思想
将源文档离线转换为**结构化条件-动作规则集**，在线通过**成对LLM判断**确定输入触发了哪些规则的条件，然后仅将**匹配规则的动作**（而非规则文本或原始文档）提供给生成模型。

### 关键技术细节
- **三阶段流水线**：
    1. **离线规则提取（五阶段）**：
        - Phase 1：规范文本范围检测（提取指令性文本片段）
        - Phase 2：原子化分解（将复合规则拆成单一条件-动作对）
        - Phase 3：可操作化（将模糊条件/动作转化为可判断、可执行的格式）
        - Phase 4：去重与冲突解决（基于标签分组比较，避免二次方复杂度）
        - Phase 5：验证（忠实性、覆盖率、独立性检查）
    2. **在线成对适用性匹配（Stage 2）**：
        - 对每个输入-规则对独立调用 LLM（温度=0），判断**输入是否满足规则的条件**（而非是否相关）。
        - 规则的动作字段**不暴露**给匹配器，避免偏见。
    3. **规则引导执行（Stage 3）**：
        - 仅将匹配规则的动作（actions）提供给生成模型，条件和源文本被隐藏，保持匹配器与执行器职责分离。

### 技术特点
- 将检索从“文本块”变为“原子规则”，从“向量相似度”变为“二值条件满足”。
- 规则提取和匹配均使用 LLM，不依赖特殊嵌入模型。

## 6. 主要结论与发现
1. **检索目标失配广泛存在**：在规则驱动任务中，语义相似性无法可靠预测规则适用性，最相似的文本块往往不是最适用的规则。
2. **TAG 显著优于标准 RAG**：在 NPOV 上 VFR 提升 7.4个百分点（68.2% vs 60.8%）；在 PEP 8 上 Pylint 略有提升但功能正确性不受影响；在 NBA 推理上 strict accuracy 提升至44.2%（DeepSeek-V4）。
3. **大幅减少上下文量**：TAG 平均检索规则数仅 14-33 条，比全规则基线减少 4-6 倍。
4. **适用性关系贡献大于规则结构化**：2×2 消融显示，将检索关系从相似性改为适用性带来的提升（+6.5~+10.3点）远大于单元从块改为规则（+0.9~+4.7点）。
5. **适用性帮助最大的条件**：抽象间隙大（输入具体 vs. 规则抽象）、强条件性（条件为二值）、高干扰密度（规则间表面相似高）。
6. **适用性帮助有限的场景**：相似性与适用性已对齐（如 PEP 8）、总规则少可全提示、任务瓶颈在多步推理而非规则选择（如 NBA L2 级别）。

## 7. 优点
- **问题定义清晰**：首次明确提出“检索目标失配”问题，并设计出针对性解决方案。
- **方法论创新**：将检索从“相似度排序”重构为“条件满足判断”，且规则提取和匹配均保持可解释与可追溯。
- **实验设计严谨**：多领域交叉验证、系统消融（五大阶段 + 2×2因子）、人类评估验证自动评估可靠性、分离相关性排序基线。
- **实践价值突出**：在多数任务中达到或超过所有规则（全上下文）效果，而实际使用的上下文仅为 10-20%，大幅降低 LLM 计算成本。
- **开源透明**：所有 prompt 全文附录呈现，便于复现。

## 8. 不足与局限
- **规则提取依赖假设**：要求源文档可被忠实转化为条件-动作规则，高度隐性、模糊或纯事实性知识不适应。
- **额外推理代价**：成对 LLM 判断（每输入-规则一次调用）比一次性向量检索成本高，虽然部分被减少执行器上下文长度抵消。
- **多步推理瓶颈未解决**：在 NBA L2 级别（需组合多条规则推理的场景）TAG 提升有限，说明问题不全是检索而是 LLM 推理能力不足。
- **实验规模较小**：每个领域不足 200 样本，统计显著性可能受限；仅覆盖三种任务类型，需更多规则驱动场景验证。
- **仅评估单次检索**：未与迭代检索、自适应检索等方法对比；标准 RAG 基线采用基础版，可能未代表最佳实践。
- **LLM 即判官的可靠性**：虽然做了人类评估，但 LLM 在 NPOV 上比人类更严格（认知差异），且仅验证了一个领域。
