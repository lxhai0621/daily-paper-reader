## 摘要
基于Transformer的大语言模型在许多语言任务上取得了优异结果；然而，长输入仍然具有挑战性，因为上下文窗口有限，且预填充延迟和内存随提示长度快速增长。因此，平坦的令牌流处理和基于块的检索可能会将与查询无关的文本消耗大量计算和上下文预算。离线索引的RAG还引入了外部存储和索引管理开销，并且通常将检索到的证据作为原始文本附加，增加了预填充成本和延迟。H^{2}MT使长上下文推理具有结构感知能力：它离线构建语义层次结构，通过自底向上的后序聚合为每个节点计算内存嵌入，并在推理时通过粗到细的路由早期剪枝无关分支。在LongBench QA（NarrativeQA、HotpotQA、QASPER）以及两个结构化技术文档场景中，H^{2}MT实现了良好的质量-效率权衡，与提示压缩、记忆令牌方法和检索增强生成基线相比，在较低的峰值GPU内存和首令牌延迟（TTFT）下提供了具有竞争力的ROUGE-L和F1分数（如果适用）。

## Abstract
Transformer-based LLMs achieve strong results on many language tasks; however, long inputs remain challenging because context windows are finite, and prefill latency and memory grow rapidly with prompt length. Flat token-stream processing and chunk-based retrieval can therefore spend substantial computation and context budget on text unrelated to the query. Offline-indexed RAG additionally introduces external storage and index management overhead, and typically appends retrieved evidence as raw text, increasing prefill cost and latency. H^{2}MT makes long-context inference structure-aware: it builds a semantic hierarchy offline, computes a memory embedding for each node via bottom-up post-order aggregation, and routes queries coarse-to-fine at inference to prune irrelevant branches early. On LongBench QA (NarrativeQA, HotpotQA, QASPER) and two structured technical-document settings, H MT achieves favorable quality efficiency trade-offs, delivering competitive ROUGE-L and F1 (where applicable) with lower peak GPU memory and time-to-first-token (TTFT) than prompt compression, memory-token methods, and retrieval-augmented generation baselines.

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程
- **核心思想**：将文档表示为一棵语义层次树（如根据目录构造），离线为每个节点计算一个固定维度的记忆嵌入（通过自底向上后序聚合），在线推理时对查询进行粗到细（coarse-to-fine）的遍历，**动态剪枝**低分子树，只将选中的少量节点记忆作为上下文输入生成阶段。
- **关键技术细节**：
  1. **语义层次树的构建**：针对结构化文档（如技术手册）直接利用目录；针对非结构化文档（如叙事文本、多文档数据集）采用启发式分割（段落、分块）或GMM聚类（如HotpotQA）构建树状结构。
  2. **记忆令牌构造（离线）**：
     - **叶子节点**：为每个节点文本插入一个写嵌入（\(e^{\text{write}}\)）和一个读嵌入（\(e^{\text{read}}\)），通过冻结骨干模型运行，取读嵌入位置的隐藏状态作为节点记忆 \(m_v\)。
     - **中间节点**：先聚合子节点记忆（可使用均值池化、自注意力、交叉注意力、GAT风格或父令牌自注意力等多种方式）得到 \(\tilde{m}_v\)，再将 \(\tilde{m}_v\) 与节点文本拼接，通过骨干模型产生该节点记忆 \(m_v\)。采用后序遍历保证子节点先处理。
     - 所有节点记忆 \(\{m_v\}_{v \in V}\) 被缓存，可跨查询复用。
  3. **在线推理（粗到细路由）**：
     - 将查询嵌入为向量 \(q\)（类似读取嵌入方式）。
     - 从根节点开始，对每个父节点 \(p\)，使用注意力得分 \(s(u|q) = (W_q q)^\top (W_k m_u)/\sqrt{d_h}\) 对子节点 \(u\) 打分。
     - 每层对每个父节点保留得分最高的 \(k\) 个子节点（per-parent top-\(k\)），形成候选集 \(\mathcal{S}_{\ell+1}\)。
     - 遍历直至叶子或达到预算，得到选中节点集 \(R\)，堆叠它们的记忆 \(M_{\text{ret}}\)。
     - 生成时，将 \(M_{\text{ret}}\) 作为前缀附加到查询令牌后，驱动骨干模型生成答案。
  4. **训练目标**：
     - 预训练阶段：对各节点文本的语言建模损失（LLM），以及可选的重建损失（LAE）。
     - 微调阶段：结合生成损失（Lgen）、路由损失（Lroute，针对单条金标签路径）和选择损失（Lsel，针对金集合的 top-\(k\) 选择），以及权重系数 \(\lambda_r, \lambda_s, \lambda_{ae}\)。

## 6. 论文的主要结论与发现
- **H²MT在质量-效率权衡上优于现有方法**：
  - 在多个数据集上，H²MT的ROUGE-L和F1与HMT、UltraGist等相当或略高，但**显著降低TTFT**（1~2个数量级）和**峰值GPU内存**（尤其在长文档上）。
  - 相比RAPTOR等检索方法，H²MT无需拼接原始文本，推理时只使用固定大小的内存嵌入，因此预填充延迟低，但牺牲了部分词汇精确度（ROUGE-L略低）。
- **层次结构和粗到细路由是关键**：它使模型避免处理无关内容，将计算集中在相关子树上。
- **聚合策略影响：** 图注意力或交叉注意力聚合比分池或自注意力更鲁棒；适中的 \(k\)（如12~20）能平衡覆盖与噪声。
- **对弱结构数据（如HotpotQA）**，通过GMM诱导层次后H²MT仍能取得有竞争力的结果，但与显式文本检索方法（SBERT+RAPTOR）相比，ROUGE-L有差距（46.64% vs 56.39%），体现了压缩的固有限制。

## 8. 不足与局限
- **依赖文档语义结构**：当文档缺乏明确层次（如HotpotQA的多文档混合）或层次构建错误时，H²MT的性能会下降。虽然可通过GMM聚类诱导，但聚类误差会传播至路由和记忆构造，导致信息丢失。
- **压缩丢失细粒度信息**：每个内部节点仅用一个固定向量表示其整个子树，如果关键证据仅出现在某个后代节点且分布稀疏，可能在聚合时被稀释，导致路由阶段将其剪枝。
