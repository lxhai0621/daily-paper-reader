## 摘要
基于图结构的检索增强生成系统能够提升多跳问题的答案质量，但许多现有系统在索引阶段依赖大型语言模型提取实体、关系和摘要。这些调用增加的令牌成本和实时成本会随着语料库规模增长。我们提出ContextRAG，一种图RAG系统，其图拓扑结构无需基于LLM的实体或关系提取。ContextRAG利用残差量化k-means和基于Lukasiewicz剩余逻辑的形式概念分析，在块嵌入上推导出模糊概念图。桥接式和汇合式上下文节点通过软模糊连接和汇合操作生成，而非由LLM编写的图边。在130个任务的UltraDomain子集上，ContextRAG仅用30次LLM调用和22,073个令牌构建索引。相比之下，本地HiRAG复现压力测试在20个任务子集上需要870次索引调用和354万个令牌，随后在图构建过程中失败；线性外推至130个任务意味着超过2300万个索引令牌。ContextRAG总体F1为33.6%，多跳任务F1为36.8%。激活分析显示，在前五个检索结果中至少包含一个格派生节点的查询比不包含的查询F1高出3.9个百分点；这种关联是诊断性的而非因果性的。

## Abstract
Graph-structured retrieval-augmented generation (RAG) systems can improve answer quality on multi-hop questions, but many current systems rely on large language models (LLMs) to extract entities, relations, and summaries during indexing. These calls add token and wall-clock costs that grow with corpus size. We present ContextRAG, a graph RAG system whose graph topology is constructed without LLM-based entity or relation extraction. ContextRAG derives a fuzzy concept graph over chunk embeddings using residual-quantization k-means and Formal Concept Analysis with Lukasiewicz residuated logic. Bridge-like and meet-derived context nodes are induced by soft fuzzy join and meet operations, rather than by LLM-written graph edges. On a 130-task UltraDomain subset, ContextRAG builds its index with 30 LLM calls and 22,073 tokens. In contrast, a local HiRAG reproduction stress test required 870 indexing calls and 3.54M tokens on a 20-task subset before failing during graph construction; linear extrapolation to 130 tasks implies over 23M indexing tokens. ContextRAG obtains 33.6% F1 overall and 36.8% F1 on multi-hop tasks. An activation analysis shows that queries retrieving at least one lattice-derived node in the top five achieve +3.9 percentage points F1 over queries that do not; this association is diagnostic rather than causal.

- **整体含义**：论文提出 ContextRAG，一种**免抽取**（extraction‑free）的图构建方法，显著降低索引成本，同时保持具有竞争力的答案质量，证明了在不依赖 LLM 抽取的情况下构建有效图结构的可行性。

## 2. 提出的方法论

### 2.1 核心思想
利用残差量化 K‑Means（RQ‑KMeans）对稠密块嵌入进行层次聚类，然后通过**模糊形式概念分析**（Fuzzy Formal Concept Analysis, FCA）和 **Łukasiewicz 残差逻辑**，从块嵌入中推导出模糊概念图。图拓扑完全由数据几何决定，而非 LLM 输出。

### 2.2 关键技术细节
- **层次聚类 (RQ‑KMeans)**：  
  定义 L 层码本（|C0|=96，|C1|=24，|C2|=12），逐级量化残差。  
  - L0 捕获粗粒度主题  
  - L1 捕获主题内变化  
  - L2 捕获更细的残差信息（当前语料规模下 L2 基本退化）
- **模糊形式概念分析**：  
  - 以块为对象，RQ‑KMeans 的簇分配为属性，建立模糊形式背景（fuzzy formal context）。  
  - 采用 **Łukasiewicz t‑norm**（a⊗b = max(0, a+b‑1)）和对应的残差蕴含（a→b = min(1, 1‑a+b)）。  
  - 模糊 Galois 连接定义：
    \[
    A^\uparrow(m) = \inf_{g\in G}[A(g) \to I(g,m)],\quad B^\downarrow(g) = \inf_{m\in M}[B(m) \to I(g,m)]
    \]
  - 通过**软模糊连接（join）** 和**软模糊汇合（meet）** 生成派生节点：  
    - 连接节点（桥接节点）：对两个概念的程度取模糊并（max），编码跨簇桥接信息。  
    - 汇合节点（上下文节点）：对两个概念的程度取模糊交（min），编码高重叠度的特殊化信息。
- **额外边**：添加**共现边**，在检索窗口中共现频率超阈值的概念节点之间建立横向连接。
- **模糊路由**：查询时计算查询与概念节点的模糊激活度 \(\mu(q,v)\)，再结合块与概念的隶属度得到路由得分。

### 2.3 算法流程（文字说明）
1. 对语料分块并生成稠密嵌入（e5‑large‑v2）。
2. 对嵌入执行 RQ‑KMeans，获得三级簇分配。
3. 基于簇分配建立模糊概念图：种子概念 + 软连接/软汇合派生节点 + 共现边。
4. **可选步骤**：对每个簇用 LLM 生成摘要虚拟块（共 30 次 LLM 调用，计入索引成本）。
5. 检索时混合 BM25、余弦相似度和模糊路由得分，多查询改写 + RRF 融合 + LLM 重排。
6. LLM 生成最终答案。

2. **答案质量具有竞争力**：总体 F1 为 33.6%，多跳任务 F1 为 36.8%（注：未与同设置下 HiRAG 质量直接对比）。

4. **体系结构权衡**：ContextRAG 将语义推理后移到查询阶段（每查询平均 3.88 次 LLM 调用），适合频繁重索引的低/中查询量场景；HiRAG 将推理前置到索引阶段，适合高查询量场景。

## 7. 优点

- **方法创新**：首次将模糊形式概念分析与残差量化聚类结合，构建免 LLM 抽取的图结构，理论框架扎实（Lukasiewicz 残差逻辑提供可计算性）。
