## 摘要
检索增强生成（RAG）已成为将大型语言模型与外部知识相结合的标准方式，但许多系统仍将证据组织为平面片段，并通过高度非结构化的搜索进行检索。这种弱结构成为复杂检索的瓶颈：系统必须决定搜索何处、如何从粗粒度主题转移到实体关系证据、哪些证据已被验证、以及哪些中间产物可以重用。我们将这些中间变量定义为检索状态，并将RAG研究视为结构化状态管理。EfficientGraph-RAG通过三种耦合机制使这种状态显式化：TAM定义了证据上的类型化层次状态空间，MARS通过角色专业化的智能体更新和验证状态，SMP在层次感知的访问控制下存储可重用状态。使用一个共享的框架配置，EfficientGraph-RAG在三个评估的LongBench检索风格子集上平均的报告答案质量指标中排名第一，在HotpotQA EM上与最强的智能体基线持平，同时将大型模型令牌使用量减少了3.51倍，并在跨模态方法中为DocVQA提供了低令牌结果。组件分析显示了角色特定的机制：MARS是答案质量的主要驱动因素，TAM提供类型化遍历状态和自适应路由信号，SMP支持依赖于语料库的重用，跨查询缓存命中率从3.77%到23.18%不等。

## Abstract
Retrieval-augmented generation (RAG) has become the standard way to ground large language models in external knowledge, but many systems still organize evidence as flat chunks and retrieve it through largely unstructured search. This weak structure becomes a bottleneck for complex retrieval: the system must decide where to search, how to move from coarse topics to entity-relation evidence, which evidence has been verified, and which intermediate artifacts can be reused. We define these intermediate variables as a retrieval state and study RAG as structured state management. EfficientGraph-RAG makes this state explicit through three coupled mechanisms: TAM defines a typed hierarchical state space over evidence, MARS updates and verifies the state through role-specialized agents, and SMP stores reusable state under hierarchy-aware access control. Using one shared framework configuration, EfficientGraph-RAG ranks first on the reported answer-quality metrics averaged over the three evaluated LongBench retrieval-style subsets, matches the strongest agentic baseline on HotpotQA EM while reducing large-model token usage by $3.51\times$, and provides a low-token DocVQA result among retrieval-organizing cross-modal methods. Component analysis shows role-specific mechanisms: MARS is the main answer-quality driver, TAM supplies the typed traversal state and Adaptive Routing signal, and SMP enables corpus-dependent reuse, with cross-query cache hit rates ranging from 3.77% to 23.18%.

- **整体含义**：论文将检索过程中的中间变量（如计划、遍历路径、证据候选集、验证信号、可复用产物）统一定义为**检索状态（retrieval state）**，并将RAG视为**结构化状态管理**问题。通过显式建模和管理这种状态，可以统一证据结构、检索时计算和可复用记忆，从而提高检索效率和质量。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：EfficientGraph-RAG 通过三个耦合机制实现检索状态的显式管理：
  - **TAM (Tree-based Abstract Memory)**：定义类型化的层次状态空间。构建一棵树，叶子节点存储原始证据（文本段落、图像-标题对等），中间层节点编码实体-关系抽象，高层节点编码主题级概念。查询时自顶向下路由，比较查询与各层节点抽象，实现对数深度的证据定位。
  - **MARS (Multi-Agent Retrieval State update)**：通过五个角色专业化的智能体更新和验证状态：规划器（分解查询）、导航器（遍历TAM）、检索器（选择具体证据）、验证器（检查相关性和充分性）、推理器（生成最终答案）。仅推理器使用大模型，其余使用小模型，将检索侧计算与大模型解耦，并支持验证失败后的状态修正。
  - **SMP (Shared Memory Pool)**：分三层存储可复用状态：全局内存（跨查询重用）、任务内存（当前查询内共享）、智能体私有内存，并实施角色-层级感知的访问控制。支持缓存嵌入、已验证证据、摘要等，实现受控重用。
- **关键技术细节**：
  - TAM构造：将语料分割为原子证据单元作为叶子，递归聚类生成中间层与高层节点，每个非叶子节点由小模型生成自然语言抽象。
  - TAM遍历：保持束搜索（beam），每层选择top-k子节点，最终到达叶子层并重排序。
  - 自适应路由（Adaptive Routing）：若TAM叶子数少于阈值τ，则绕过MARS直接推理，减少不必要开销。
  - MARS验证循环：当验证器判定证据不充分时，触发重新规划、重新导航、重新检索，直至满足条件或达到最大迭代次数。

- **主要结论**：EfficientGraph-RAG将复杂RAG建模为结构化检索状态管理，在三种任务家族上取得领先效果。

## 7. 优点

- **方法创新**：首次明确将RAG定义为检索状态管理，提出TAM、MARS、SMP三位一体的结构化框架，统一了证据组织、检索过程和记忆重用。
- **效率-质量平衡**：通过小模型代理执行检索侧操作（规划、导航、检索、验证），保留大模型仅用于最终推理，大幅降低大模型令牌使用，同时保持或提升质量。
- **自适应路由**：基于TAM叶子数量阈值自适应决定是否执行完整多智能体循环，有效处理短上下文查询（如DocVQA），避免不必要开销。
- **明确的失败模式**：MARS将失败分为规划、导航、检索、验证等类型，支持差异化修正，而非简单重试。
- **受控记忆共享**：SMP的三层架构和角色权限管理避免状态干扰，支持跨查询缓存提高效率。

## 8. 不足与局限

- **TAM路由仍有缺陷**：小模型生成的抽象可能混淆实体、丢失细节（如日期、数值），或导致错误跨文档关联。在手动检查的36个失败中，实体混淆占44.4%，细节丢失27.8%，错误关联27.8%。
- **跨模态评估有限**：仅测试DocVQA，自适应路由阈值τ针对文档图像问题调节，是否适用视频QA、科学图表理解等尚不明确。
- **跨任务广度有限**：虽声称跨任务，但仅测试三种文本QA和一种视觉QA，未覆盖对话状态检索、代码检索、跨语言检索等。
- **全局内存重用行为依赖部署方式**：实验中Mg为每基准独立初始化、序列执行可提高命中率，但实际部署中作为多用户共享资源时行为可能不同（尤其对模板化文档）。
- **效率度量**：仅报告大模型侧令牌和延迟，未给出硬件归一化FLOPs或端到端墙钟时间，且小模型侧开销未计入（但作者明确区分了此意图）。
