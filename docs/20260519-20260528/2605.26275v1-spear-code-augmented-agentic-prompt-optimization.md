## 摘要
自动提示工程（APE）通过重写提示词来提升下游任务性能，但现有的APE循环将优化器本身视为固定流程。我们将CodeAct（Wang等人，2024a）的代码即行动范式移植到APE中，并提出SPEAR（具备主动回滚的沙盒提示工程师），这是一种具有四种工具（评估、Python、设置提示词、完成）的自由形式智能体优化器，可自主决定如何使用这些工具。其独特工具是Python沙盒：优化器在当前评估数据帧上编写并执行任意Python代码，执行智能体自身编写的结构性错误分析（混淆矩阵、错误聚类、分组指标）。两个防护栏将长周期智能体转变为单调改进型优化器：指标回归时自动回滚，以及可选的防护指标下限。我们在三个工业级LLM作为评判者的任务集（涵盖招聘接待、对话记忆、查询细化系统的13个评判任务）以及七个BBH任务和GSM8K上进行了评估。SPEAR在主要指标上赢得了所有工业任务（工具选择上κ 0.857对比0.359；过滤相关性上宏F1 0.815对比0.763；最难的提取维度上κ 0.254对比0.218）。在BBH-7上，SPEAR平均准确率0.938，对比GEPA的0.628和TextGrad的0.484。消融实验表明，Python工具是复杂评判任务中最主要的单一杠杆（在5类工具选择评判中移除时Δ≈+0.79κ，在最难提取维度上移除时Δ≈+0.35κ）；其不可替代的贡献在于类别对混淆聚合，而长上下文LLM无法从原始评估数据帧中可靠提取该信息。

## Abstract
Automatic prompt engineering (APE) rewrites prompts to improve downstream task performance, but existing APE loops treat the optimizer itself as a fixed pipeline. We port the code-as-action paradigm of CodeAct (Wang et al., 2024a) to APE and propose SPEAR (Sandboxed Prompt Engineer with Active Roll-back), a free-form agentic optimizer with four tools -- evaluate, python, set_prompt, finish -- that decides autonomously how and when to use them. The distinctive tool is the Python sandbox: the optimizer writes and executes arbitrary Python on the current evaluation DataFrame, performing structural error analysis (confusion matrices, error clustering, per group metrics) the agent itself authors. Two guardrails turn the long-horizon agent into a monotone-improving optimizer: auto-rollback on metric regression, and an optional guard metric floor. We evaluate on three industrial LLM-as-judge suites (13 judge tasks across recruiter-intake, conversational-memory, and query-refinement systems) plus seven BBH tasks and GSM8K. SPEAR wins every industrial task on the primary metric ($κ$ 0.857 vs 0.359 on tool-selection; F1-macro 0.815 vs 0.763 on filter-relevance; $κ$ 0.254 vs 0.218 on the hardest extraction dimension). On BBH-7 SPEAR averages 0.938 accuracy vs GEPA 0.628 and TextGrad 0.484. Ablations show the Python tool is the largest single lever on complex judge tasks ($Δ\approx +0.79κ$ on the 5-class tool-selection judge, $Δ\approx +0.35κ$ on the hardest extraction dimension when removed); its irreplaceable contribution is class-pair confusion aggregation that a long-context LLM cannot extract reliably from the raw eval DataFrame.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题**：现有自动提示工程（APE）系统（如OPRO、TextGrad、GEPA等）都将优化器本身设计为固定流水线（fixed pipeline）。优化器的错误信号（标量损失、帕累托前沿或单行文本批评）在设计时就被选定，其对错误的分析完全依赖于预置管道。当错误具有结构化特征（如混淆的类别对、只有按特征分组才能发现的标签规则矛盾）时，固定流水线无法将这些结构暴露给优化器，导致优化效率低下。
- **整体含义**：本文提出将代码即行动（code-as-action）范式迁移到APE中，让优化器能够自主编写并执行分析代码，从而发现固定流水线无法捕捉的结构化错误模式，显著提升复杂任务（尤其是LLM作为评判者的任务）的提示优化效果。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：SPEAR是一个自由形式的智能体优化器，配备四个工具：`evaluate`（评估当前提示词，返回每行预测）、`python`（在当前评估数据帧上执行任意代码）、`set_prompt`（替换系统提示词）、`finish`（终止）。智能体自主决定何时使用哪个工具，打破了固定流水线的顺序约束。
- **关键技术细节**：
  - **Python沙盒**：最独特的工具。优化器可编写并运行任意Python代码（受AST限制的沙盒，模块白名单，无网络/系统调用，60秒墙钟+512MB RSS上限）。数据帧中包含每行预测、真实标签等。智能体可构建混淆矩阵、错误聚类、分组指标分析等。
  - **两个防护栏**：
    1. **自动回滚（auto-rollback）**：当一次完整评估（full-split evaluate）后主要指标低于历史最佳值时，自动将提示词回滚到上一个最佳状态。抽样评估不触发回滚，防止智能体通过选择容易行来虚增指标。
    2. **防护指标下限（guard-metric floor）**：可选副指标，当某次改写导致该指标低于阈值时，拒绝该改写。用于防止优化偏废。
  - **流程**：智能体在一个while循环中运行，每步选择一个工具。初始强制进行一次`evaluate`。`python`工具不消耗评估预算；`set_prompt`和`finish`免费；完整`evaluate`消耗一个预算单位（默认20次）。最大步数为5倍评估调用次数。
  - **评估数据帧设计**：训练集提供完整列用于分析；验证集仅暴露聚合标签分布（不暴露行内容），用于评分而不用于深入分析，防止过拟合。
- **算法文字说明**：
  1. 初始化：种子提示词`P0`，最佳提示词`P_best`，最佳指标`κ_best`，评估预算计数器`b=0`，步数`s=0`。
  2. 强制初始评估（`evaluate(P, D_valid)`），更新`κ_best`和`P_best`。
  3. 循环直到预算耗尽或终止：
     - 智能体根据当前状态选择动作（`python`、`evaluate`、`set_prompt`、`finish`）。
     - 若为`python`，在沙盒中执行代码，不消耗预算。
     - 若为`evaluate`，执行评估，消耗预算。若是完整验证集评估，检查是否回滚。
     - 若为`set_prompt`，替换当前提示词。
     - 若为`finish`，退出。
  4. 循环结束后返回最佳提示词及指标。

## 6. 主要结论与发现

- SPEAR在工业LLM评判任务上一致优于TextGrad和GEPA：在12个可比较维度中赢得11个，最大绝对增益出现在最难维度（如招聘助理工作地点κ 0.76 vs 0.11/0.36；CMA工具缺失κ 0.976 vs 0.69/0.63）。
- BBH-7平均准确率0.938，远超GEPA的0.628和TextGrad的0.484。但大部分增益来自输出格式改写（3个格式不匹配任务），非格式任务平均增益仅+0.033（与GEPA置信区间重叠）。
- GSM8K上所有方法均不能显著提升（SPEAR 0.965，GEPA 0.960，TextGrad 0.956），因为格式已匹配且任务已近饱和。
- Python工具是最大增益杠杆：移除后复杂任务损失显著（CMA工具缺失κ降0.79，招聘助理工作地点κ降0.35）。通过附加完整数据帧上下文的消融（A6）表明，Python工具的核心价值是多类混淆矩阵的结构化聚合，LLM从原始文本中无法可靠提取。
- 智能体自主编排比固定流水线重要（A4损失0.27κ和26pp准确率）。
- 自动回滚不提升均值但提升下限（无一次SPEAR运行低于种子指标）。

## 7. 优点

1. **方法创新**：首次将代码即行动范式引入APE，使优化器能主动编写分析代码，解决固定流水线无法识别结构化错误的根本局限。
2. **防护栏设计**：自动回滚和防护指标下限保证优化单调性，提升可靠性。
3. **实验全面性**：覆盖最多13个工业LLM评判任务、7个BBH任务和GSM8K；有跨模型迁移、多种子方差、统一优化器模型消融等大量辅助分析。
4. **消融实验设计精巧**：A6（附加原始数据帧但无Python工具）精确地分离了“更丰富信息”与“代码聚合能力”的不同贡献，揭示Python工具的不可替代价值在于结构聚合而非信息量。
5. **案例分析揭示定性发现**：通过具体跟踪（如招聘助理工作地点维度的标签规则矛盾发现、CMA多类混淆矩阵分析）直观展示代码执行如何引导不同性质的改写（规则发现vs规则精炼）。
6. **成本优势**：SPEAR在2-3次全评估内收敛，总成本与GEPA相差17%以内，但性能更优。

## 8. 不足与局限

1. **可复现性限制**：优化器模型GPT-5.4是内部部署，无法公开具体版本；工业数据集和优化后提示词因专有政策无法公开，仅提供了合成评判任务存根和统一视角数字。外部研究者在完全复现上存在困难。
2. **统计局限性**：
   - GPT-4o在温度0下边界行不可复现（标准差高达0.28）。
   - 单种子消融实验，Δ≤0.05的差异仅为方向性解读。
   - CMA验证集仅约50行/5类，小样本可能带来偶然性。（统一视角消融验证了增益的稳健性）。
3. **验证集读取侧适应**：SPEAR在验证集上看到聚合标签分布（尽管行内容被屏蔽），与GEPA/TextGrad不对称。虽然测试集重分配和多种子分析减轻了该风险，但仍无法完全排除。
4. **沙箱非对抗性**：AST白名单已知有泄漏风险，若部署在用户提供数据帧的环境中需更强隔离（容器或WASM）。目前仅基于信任的优化器LLM和内部环境。
5. **提示词长度增长**：SPEAR优化后的提示词长度增长约2倍，可能增加推理成本，生产需配合长度压缩工具。
6. **偏差继承**：评判提示对齐人工标签会继承注释管道的偏差，不保证代表公平性。论文未对受保护属性进行偏差监控分析。
7. **BBH增益主要来自格式改写**：在格式匹配的任务（GSM8K）上无优势，其核心竞争力主要集中在工业复杂评判任务上。
