## 摘要
LLM智能体需要检索以表现得不像一次性上下文获取，而更像推理：搜索、阅读、遍历、判断何时证据充分。然而，当前的检索增强生成（RAG）系统将外部知识组织为通过嵌入相似性检索的平面块，暴露出一种检索即查找的接口，不适合迭代推理智能体。我们提出LLM-Wiki，一个智能体原生检索系统，通过将外部知识视为可编译、可组合、自我进化的结构，而非静态检索索引，实现了“检索即推理”范式。LLM-Wiki将文档编译成具有双向链接的结构化Wiki页面，通过标准工具调用接口暴露搜索、阅读和链接跟踪操作，并引入错误簿用于持久的结构和语义自我修正。LLM-Wiki在HotpotQA、MuSiQue和2WikiMultiHopQA上取得了最先进的结果，比HippoRAG 2、LightRAG和GraphRAG高出2.0-8.1个F1点。在AuthTrace上，LLM-Wiki实现了最佳总体准确率，在多文档结构化查询上尤其强劲，证实了基于编译的检索超越了链式多跳推理。

## Abstract
LLM agents require retrieval to behave less like one-shot context fetching and more like reasoning: searching, reading, traversing, and deciding when evidence is sufficient. Yet current Retrieval-Augmented Generation (RAG) systems organize external knowledge as flat chunks retrieved by embedding similarity, exposing a retrieval-as-lookup interface ill-suited to iterative reasoning agents. We propose LLM-Wiki, an agent-native retrieval system that operationalizes the Retrieval-as-Reasoning paradigm by treating external knowledge as a compilable, composable, and self-evolving structure rather than a static retrieval index. LLM-Wiki compiles documents into structured Wiki pages with bidirectional links, exposes search, read, and link-following operations through standard tool-calling interfaces, and introduces an Error Book for persistent structural and semantic self-correction. LLM-Wiki achieves state-of-the-art results on HotpotQA, MuSiQue, and 2WikiMultiHopQA, outperforming HippoRAG 2, LightRAG, and GraphRAG by 2.0-8.1 F1 points. On AuthTrace, LLM-Wiki achieves the best overall accuracy, with especially strong gains on multi-document structured queries, confirming that compilation-based retrieval generalizes beyond chain-style multi-hop reasoning.

## 1. 论文的核心问题与整体含义（研究动机和背景）
- **核心问题**：现有 RAG 系统将外部知识组织为平面文本块，通过嵌入相似性进行一次性检索（即“检索即查表”），无法支持 LLM 智能体在迭代推理过程中所需的搜索、阅读、遍历、判断证据充分性等操作。
- **背景**：LLM 智能体（如 ReAct 风格的工具调用循环）需要知识库能够动态响应中间观察，而现有系统存在三个根本局限：
  - 平面块降低检索为匹配而非推理；
  - 检索是单次黑盒，智能体无法控制后续检索；
  - LLM 编译的结构化知识库缺乏自我修正能力，易出现死链接、矛盾事实等错误。
- **整体含义**：提出“检索即推理”（Retrieval-as-Reasoning）范式，将检索本身视为由智能体驱动的组合推理活动，而非停留在一次性上下文获取。该范式要求知识库具备可编译（compilable）、可组合（composable）、可进化（evolvable）三个原则。

## 2. 论文提出的方法论：核心思想、关键技术细节
### 核心思想
- 将原始文档编译为**具有双向链接的结构化 Wiki 页面**，并暴露标准工具接口（`wiki_search`、`wiki_read`），使智能体能够通过组合搜索、阅读、链接跟随和充分性检查来迭代收集证据。
- 引入**错误簿（Error Book）**，实现持久的结构和语义自我修正。

### 关键技术细节
- **Wiki 结构化知识**：编译后形成目录索引（`index.md`、`_index.md`）、结构化 Markdown 页面（含元数据、别名、标签、事实、来源引用、双向 wikilinks）、源档案。页面采用固定 Schema。
- **组合检索**：智能体可调用 `wiki_search(query)` 搜索索引（优先匹配页面名、别名、标签，再回退内容）；`wiki_read(paths)` 批量读取页面或目录索引。遍历策略包括：
  - **搜索优先**：用于实体锚定查询，先搜索再阅读并跟随链接。
  - **浏览优先**：用于开放或枚举查询，先读目录索引获得结构化概览再选读页面。
  - **终止条件**：达到最大工具调用预算 `Tmax=15`、连续空搜索超过耐心阈值 `P=3`、或证据已充分（至少一次 `wiki_read` 后才能回答）。
- **错误簿**：生命周期五阶段——发现（结构验证 + 源引证 LLM 验证 + 跨页一致性检查）、归因（追溯根因）、约束（形式化为自然语言规则）、注入（追加到编译 prompt）、验证与关闭。错误分为 7 类（死链接、不完整页面、格式错误引用、未见过覆盖、索引不一致、无根据事实、跨页矛盾）。修复分两层：
  - **代码自动修复**（每批次后）：修复死链接、格式、索引不一致等结构错误。
  - **LLM 周期性修复**（每 N 批）：修复缺失页面、不完整摘要、无根据事实、跨页矛盾。
  - 最终化阶段执行三轮代码修复与 LLM 修复循环。

### 算法流程
- 索引时编译（Algorithm 1）：
  1. 对每个源段落选择相关现有页面；
  2. 生成结构化 Wiki 更新（页面、链接、索引更新）；
  3. 执行结构和内容验证；
  4. 将错误记录到错误簿，提取约束；
  5. 应用代码自动修复；
  6. 应用更新；
  7. 周期性触发 LLM 修复并验证关闭。

## 6. 论文的主要结论与发现
1. **编译式知识组织优于平面块和图增强检索**：LLM-Wiki 在所有公共基准上取得最佳 F1 和 EM，增益随推理深度（跳数）增加而扩大（2WikiMHQA 上 4-hop 比最强基线高 8.3 F1）。

4. **泛化性强**：更换答案 LLM 为 GPT-4o 后仍保持显著优势（+5.1–16.9 F1），说明收益来自知识组织而非特定模型。
5. **查询时间效率高**：LLM-Wiki 的查询延迟与简单 RAG 相当（14.9–27.1s），远低于 LightRAG、HippoRAG 2 等图方法（32.4–51.3s）。

## 7. 优点
- **范式创新**：提出并实现了“检索即推理”范式，将检索从静态查找转变为显式的、智能体驱动的推理过程，符合 LLM 智能体的需求。
- **知识表示人性化**：编译为 Wiki 页面，人类可读且机器可遍历，支持多种遍历策略（搜索优先、浏览优先）。
- **自我进化机制**：错误簿通过约束注入和两层修复实现持久自我修正，减少重复错误，避免知识库退化。
- **实验全面且扎实**：覆盖多数据集、类型/跳数分析、消融、跨模型验证、效率分析、人类审计，充分证明方法有效性。
- **实用性强**：查询延迟低，编译成本可摊销，适合知识密集型智能体任务。

## 8. 不足与局限
- **编译成本较高**：每个源段落需要 LLM 调用选择页面和编译，初始构建比简单 chunck-and-embed 昂贵，虽然后续查询摊销但未量化具体开销。
- **可扩展性问题**：当 Wiki 增长到数万页时，目录索引可能变得庞大，页面选择和质量可能下降。论文提及但未解决 web 规模、动态语料场景下的层级索引、分片、过期事实处理。
