## 摘要
顺序演化的大语言模型记忆使智能体能够复用过去经验，但现有系统通常直接部署每个本地生成的记忆更新，而不检查其是否改进了未来行为。结果，有助于当前任务的更新可能覆盖有用知识、引入过度特定规则或使最终记忆偏向近期示例。我们提出Janus，一种即插即用的记忆控制器，决定是接受候选记忆更新还是保留先前记忆。为了高效决策，Janus使用记忆动量触发器识别记忆更新轨迹中的可疑偏差，并在覆盖度、边界和新任务构成的紧凑混合评估集上比较新旧记忆，而非重放全部历史。Janus方法无关，可包装现有更新器而不改变其更新规则。在六个数据集、两个骨干大语言模型和两个记忆更新器上，Janus相比对应基础更新器平均准确率提升2.7至4.6个百分点。

## Abstract
Sequentially evolving LLM memory enables agents to reuse past experience, but existing systems usually deploy each locally generated memory update without checking whether it improves future behavior. As a result, updates that help the current task may overwrite useful knowledge, introduce over-specific rules, or bias the final memory toward recent examples. We propose Janus, a plug-in memory controller that decides whether to accept a candidate memory update or retain the previous memory. To make this decision efficient, Janus uses a Memory Momentum Trigger to identify suspicious deviations in the memory-update trajectory, and compares old and new memories on a compact hybrid evaluation set of coverage, boundary, and fresh tasks instead of replaying the full history. Janus is method-agnostic and wraps existing updaters without changing their update rules. Across six datasets, two backbone LLMs, and two memory updaters, Janus improves average accuracy by +2.7 to +4.6 points over the corresponding base updaters.

## 1. 核心问题与整体含义（研究动机与背景）
- **研究动机**：在大语言模型（LLM）智能体中，顺序演进的记忆（sequentially evolving memory）允许智能体从过去的交互经验中学习，但现有的记忆系统往往**无条件地接受每个本地生成的记忆更新**，而不评估其对未来任务的全局影响。
- **核心问题**：本地更新可能对当前任务有用，但可能带来负面后果——覆盖先前积累的有用知识、引入过度具体的任务规则、或使最终记忆偏向近期遇到的示例，导致未来任务性能下降。论文将这种现象称为“记忆验证问题”（memory validation problem）。
- **整体意义**：该文指出，关键不仅在于如何生成记忆更新，更在于**如何决定是否部署候选更新**。这从“更新生成”转向“更新控制”，为顺序记忆系统提供了一种更可靠的测试时适应机制。

## 2. 方法论：Janus 的核心思想与关键技术
- **整体思路**：Janus 是一个**即插即用的记忆控制器**，缠绕（wrap）现有基础记忆更新器，对每个候选更新做出“接受”或“拒绝”的部署决策，而不修改底层更新规则。
- **两大核心组件**：
  - **记忆动量触发器（Memory Momentum Trigger, MMT）**：
    - 将记忆更新视为轨迹，使用文本编码器 ϕ(·) 将记忆状态映射为向量。
    - 定义候选更新方向 z_t = ϕ(cM_t) - ϕ(M_{t-1})。
    - 维护更新方向的指数移动平均 m_t = β m_{t-1} + (1-β) z_t，β=0.9。
    - 当候选更新方向与历史动量方向严重不对齐时（余弦相似度低于阈值 τ，默认 τ=0.0），触发比较；否则直接接受候选更新。这避免了在每个任务后都进行昂贵比较。
  - **混合触发时间评估集（Hybrid Trigger-Time Evaluation Set）**：
    - 触发比较时，不是重放全部历史任务，而是在一个紧凑的评估集上比较旧记忆与新记忆。
    - 评估集由三部分组成：
      - **覆盖集（Coverage set）**：通过聚类所有已见任务，选取最接近每个类中心的代表任务，保持对已见任务分布的广泛覆盖。
      - **边界集（Boundary set）**：收集那些**记忆切换会改变正确性**的任务（即旧记忆和新记忆预测不同的样本），关注记忆敏感区域，并定期从覆盖集和上一轮边界集中更新。
      - **新鲜集（Fresh set）**：从最近一次触发后遇到的新任务中采样，防止评估集过时。
    - 比较后，部署在评估集上性能更好的记忆状态。
- **关键公式**：触发条件 cos(z_t, m_{t-1}) < τ；评估集大小通过超参数 K（支持集大小）、KF（新鲜集大小）控制，默认 K=20，KF=5。

## 6. 主要结论与发现
- **Janus 持续提升最终记忆有用性**：在全部6个数据集和2个LLM上，DC-RS+Janus 平均准确率比 DC-RS 提高2.7-4.6个百分点，ExpeL+Janus 类似提升（3.2-4.6点）。
- **触发器时机至关重要**：MMT 在类似触发预算下优于随机触发和周期性触发，接近始终触发但成本更低。
- **混合评估集各组件均不可或缺**：移除覆盖集、边界集或新鲜集都会导致性能下降，其中新鲜集影响最大，说明新鲜任务能防止评估过时。
- **选择性部署优于全盘接受**：直接接受所有更新可能导致性能随时间波动甚至下降，而 Janus 保持更稳定且上升的趋势。
- **Janus 对超参数稳健**：默认设置（K=20, τ=0.0）效果良好，更大的支持集不一定更好，体现了紧凑但信息丰富的评估集的重要性。
