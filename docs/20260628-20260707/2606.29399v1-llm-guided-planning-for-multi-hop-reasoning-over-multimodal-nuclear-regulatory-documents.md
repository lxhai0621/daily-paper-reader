## 摘要
审查核监管文档需要对数万页内容进行多跳推理，判断依据来自多个章节的证据。我们将此任务建模为规划问题：基于LLM的智能体观察已收集到的证据，选择下一个待检查的文档片段，并在证据充分时停止。智能体通过浏览、阅读和搜索工具在无向文档树上操作，并维护一个动态知识图谱作为状态。在NuScale最终安全分析报告文档的200个问题基准测试中，系统达到81.5%的准确率，RAGAS忠实度为0.93。主导性能因素为规划：与使用相同文档树但无状态条件动作选择的PageIndex相比，差距为+38.0个百分点（43.5%对81.5%，p<0.001）。该系统还优于LightRAG（73.0%，p<0.05）、HippoRAG（70.5%，p<0.01）和GraphRAG（49.5%，p<0.001），并在无离线索引的情况下与RAPTOR（75.5%，p=0.11）相当。边缘推理增加2.8倍成本但未提高准确率；我们将其保留作为可追溯性模块。在7,391条推断边中，有3条“违反”边（0.04%）标记了范围边界（Q058）和部分符合（Q176），作为人类审阅者可审计的类型化注释。

## Abstract
Reviewing nuclear regulatory documents requires multi-hop reasoning across tens of thousands of pages, where judgments depend on evidence assembled across multiple chapters. We frame this task as planning: an LLM-based agent observes the evidence collected so far, picks the next document fragment to inspect, and stops when the evidence is sufficient. The agent operates over a vectorless document tree using browse, read, and search tools, and maintains a dynamic knowledge graph (KG) as state. On a 200-question benchmark over NuScale Final Safety Analysis Report (FSAR) documents, the system reaches 81.5% accuracy with a RAGAS Faithfulness of 0.93. The dominant performance factor is planning: against PageIndex, which uses the same document tree without state-conditioned action selection, the gap is +38.0pp (43.5% to 81.5%, p<0.001). The system also outperforms LightRAG (73.0%, p<0.05), HippoRAG (70.5%, p<0.01), and GraphRAG (49.5%, p<0.001), and matches RAPTOR (75.5%, p=0.11) without offline indexing. Edge inference adds 2.8x cost without raising accuracy; we retain it as a traceability module. Of 7,391 inferred edges, 3 Violates edges (0.04%) flag scope boundaries (Q058) and partial conformance (Q176) as typed annotations that a human reviewer can audit.

- **研究动机**：审查核监管文档（如《最终安全分析报告》FSAR）需要跨章节、跨文档乃至跨模态（文本、表格、工程图纸）的多跳推理，且要求证据充分性判断（何时可以做出结论）。现有RAG方法（如GraphRAG、LightRAG、RAPTOR等）均为单次检索，缺乏迭代证据积累和动态终止能力；且依赖离线索引，不适用于不断修订的FSAR。
- **核心问题**：如何将核监管文档审查建模为**规划问题**——给定目标（监管判断）、当前状态（已收集证据）和动作（文档导航），智能体需决定下一步检查什么。
- **整体含义**：该工作首次将LLM引导的规划范式应用于安全关键的多跳多模态推理任务，提出了一个可转移的“文档即环境”框架，并验证了规划（而非更强的检索或索引）是性能主导因素。

## 2. 方法论

### 核心思想
- 将核监管文档审查形式化为规划问题 ⟨S, A, f_tr, φ⟩：
  - 状态 s_t：动态子知识图谱 G_t = (V_t, E_t)，表示已收集证据及推断的关系。
  - 动作 a_t：工具调用 {browse(d,v), read(d,v), search(κ)}。
  - 转移函数 f_tr：工具执行 → 节点集成 → 可选边推断 → 更新KG。
  - 目标测试 φ(s_t, q)：LLM判断当前KG是否包含足够证据回答问题，若满足则终止。

### 关键技术细节
1. **文档环境**：无向量文档树（JSON层级结构），按章→节→段组织，无分块/嵌入。支持多模态引用解析（表格/图片通过PyMuPDF链接到页）。
2. **搜索**：BM25Okapi（章节标题权重×3），配合伪相关反馈（PRF/RM3）、搜索历史去重。
3. **状态（短时记忆）**：动态子KG，采用**双层本体**：
   - 结构层（Tier 1）：REFERENCES, SPECIFIES
   - 语义层（Tier 2）：SATISFIES/VIOLATES, SUPPORTS/CONTRADICTS, LEADS_TO, IS_PREREQUISITE_OF
   - 边保留阈值≥0.4。
4. **动作规划**：闭循环规划，每步LLM根据当前KG选择动作，环境反馈立即影响下一步。强制首步“浏览优先”（注入目录）。
5. **动态终止**：从第2步开始检查证据充分性，33%查询提前终止（平均3.4步，最大4步）。
6. **后检索边推断**（可选）：两阶段——LLM生成自由文本描述，再映射到本体；增加可审计性但不提高准确率。
7. **视觉增强答案生成**：仅在最终回答步骤调用视觉API（GPT-4.1 VLM），中间操作保持文本。表格用PyMuPDF结构化提取。

### 算法流程（文字说明）
```
输入：查询q，文档D，最大步数T
初始化KG为空，在第0步注入目录
for t = 0 to T-1:
```

## 6. 主要结论与发现

1. **规划是主导性能因素**：与无状态规划的PageIndex相比，提升+38.0个百分点（43.5% → 81.5%，p<0.001）。
2. **超越多数现有RAG**：优于GraphRAG（49.5%）、HippoRAG（70.5%）、LightRAG（73.0%），与RAPTOR（75.5%）相当但无需离线索引。
3. **边推断不提高准确率**：200问题消融显示精确率保持不变（81.5% vs 81.0%），但增加2.8倍成本；保留作为**可审计性**模块。
4. **动态终止校准良好**：早期终止查询准确率85.5% > 全预算查询78.3%，说明自信判断可靠。
5. **VIOLATES边提供结构化的监管价值**：0.04%的边标记了范围边界和部分符合性，使人类审阅者可直接聚焦，满足10 CFR 50 Appendix B追溯要求。
6. **双重评估必要**：RAGAS与Judge一致率66.2%，29个案例RAGAS好但Judge误（措辞差异），38个案例RAGAS差但Judge对（KG未覆盖的内部知识），单一指标均会漏报。
7. **真实失败率低**：排除措辞匹配后，部署相关失败率4.5%，其中幻觉仅1.0%。

## 7. 优点

- **方法新颖性**：首次将核监管文档审查形式化为规划问题，提出**无向量文档树+动态KG状态**的闭循环规划框架，无需训练、无需离线索引。
