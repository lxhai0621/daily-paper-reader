## 摘要
长时域工具智能体的瓶颈在于它们的上下文如何增长到上下文窗口的极限。最近的系统使上下文管理由智能体或系统控制，但它们要么学习一种丢弃证据的压缩策略，要么在智能体从未见过的层中管理上下文。我们认为这两者都留下了一个更基本的空白未解决。前沿语言模型对其自身的上下文是本体感知盲的。仅凭提示，它们无法看到每个块有多大、有多旧、有多久未被使用，这些是保留或丢弃决策所需的信号。我们假设，能力强的模型中已经潜伏着胜任的上下文管理能力，缺失的不是学习到的策略，而是暴露这种状态的接口。我们引入了VISTA（可见内部状态工具智能体），一个无需训练、与模型无关的层，它将工作记忆表示为带类型的、可寻址的块，展示每个块令牌使用量、最近使用和访问历史的运行时仪表盘，并将块归档为可恢复的全保真负载。在LOCA-Bench、BrowseComp-Plus和GAIA上，相同的未训练接口跨百万、10万和1万规模轨迹迁移。在LOCA-Bench上，它改进了四个骨干模型，并将Gemini-3-Flash从22.7%提升到50.7%。提升随着上下文压力增加而增加，并且跨骨干模型迁移。消融实验进一步证实了仪表盘的重要性，而不仅仅是归档和恢复工具。

## Abstract
Long-horizon tool agents are bottlenecked by how their context grows toward the limits of the context window. Recent systems make context management agent- or system-controlled, but they either learn a compression policy that discards evidence or manage context in a layer the agent never sees. We argue both leave a more basic gap unaddressed. Frontier language models are proprioceptively blind to their own context. From the prompt alone they cannot see how large, how old, or how used each block is, the signals a keep-or-drop decision needs. We hypothesize that competent context management is already latent in capable models, and that what is missing is not a learned policy but an interface exposing this state. We introduce VISTA (Visible Internal State for Tool Agents), a training-free, model-agnostic layer that represents working memory as typed, addressable blocks, surfaces a runtime dashboard of per-block token usage, recency, and access history, and archives blocks as recoverable full-fidelity payloads. On LOCA-Bench, BrowseComp-Plus, and GAIA, the same untrained interface transfers across million-, 100K-, and 10K-scale trajectories. On LOCA-Bench it improves four backbones and lifts Gemini-3-Flash from 22.7 to 50.7%. The lift grows with context pressure and transfers across backbones. Ablations further confirm that the dashboard matters beyond archive and recovery tools.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：长时域工具智能体（Long-horizon tool agents）在执行多步任务时，其工作记忆（上下文）会不断累积，直至接近或超出上下文窗口的限制。现有方法要么通过压缩丢弃证据（如代理控制的压缩），要么在智能体不可见的运行时层进行管理（如操作系统式分页），但两者都忽略了一个根本问题：**LLM 对其自身的上下文状态是本体感知盲的（proprioceptively blind）**——它无法从提示文本中知道每个块的大小、新鲜度、访问历史以及剩余预算，而这些正是做出保留或丢弃决策所需的关键信号。
- **研究动机**：作者假设，能力强的前沿模型（如 GPT-4、Claude 等）在预训练阶段已经具备隐式的上下文管理能力（例如通过笔记、检索、重组等训练数据），当前瓶颈并非缺乏学习策略，而是**缺少一个暴露上下文运行时状态的接口**。因此，无需重新训练，只需要设计合适的接口即可激发模型的自我上下文管理能力。
- **整体含义**：本文倡导一种“引发（elicitation）”视角，认为部分智能体能力是通过让隐藏的运行时状态变得可感知而释放的，而不只是通过增加学习策略。这为未来研究提供了一种无需微调、模型无关的高效上下文管理方案。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：VISTA（Visible Internal State for Tool Agents）是一个无需训练、与模型无关的上下文管理层。它将工作记忆表示为带类型的、可寻址的块（blocks），并通过一个运行时仪表盘（dashboard）暴露每个块的令牌用量、新鲜度（age）、访问历史以及剩余预算。同时，提供无损的归档（archive）与恢复（recover）工具，使得智能体可以将大型块移出提示窗口但保留其完整内容，需要时再精确恢复。
- **关键技术细节**：
  - **上下文流（Context Stream）**：将原始对话拆分为带类型（用户消息、助手消息、工具调用、工具结果）、稳定ID的块。大块结果可先标记为“阻塞（blocked）”或直接归档为隐藏轨迹中的无损负载。
  - **仪表盘（Dashboard）**：每步动态刷新，展示预算条、每个块的ID、估计令牌数、年龄、类型、状态（可见/固定/归档/阻塞）等。它不提供额外任务证据，只暴露运行时状态。
  - **元上下文工具（Meta-Context Tools）**：智能体可以使用 `archive(id, summary)` 将块移出提示窗口，同时生成一个包含路径、校验和等信息的句柄（handle）；使用 `retrieve(path)` 或文件/终端工具恢复原数据。归档是分层的（可多级分组）。恢复是无损的，支持部分读取（避免重新加载完整大块）。
  - **预算循环**：当新结果导致提示超出预算时，系统进入溢出模式（overflow mode），此时仅允许上下文管理动作（归档/恢复），直到上下文缩小至预算内。还有一个预检卸载（preflight offload）机制，在接近硬限制时自动外部化最大块。
  - **损失必要性论证**：Proposition 1 理论上证明，在预算压力下，非恢复性方法（如删除、掩码、总结）必须丢弃信息，而 VISTA 通过无损归档+恢复可以保持成功率 1（只要指令、句柄和一个恢复块能放进预算）。

## 6. 论文的主要结论与发现

- **主要结论**：VISTA 通过暴露每块元数据的仪表盘，配合无损归档和恢复，能够**无需训练、模型无关地激发前沿 LLM 的隐式上下文管理能力**，显著提升长时域智能体任务的成功率。

  - 在 LOCA-Bench 上，VISTA 以 50.7% 的成功率超过 ReAct（22.7%）、Claude Code（42.7%）等所有基线，且令牌消耗低于 Claude Code。

## 8. 不足与局限

- **依赖模型自身能力**：VISTA 仅提供信息，不保证智能体正确使用仪表盘。对于能力较弱的模型（如 GLM-5，提升幅度较小），激发效果有限。论文未探讨低能力端模型的行为。
- **未与后训练方法结合**：VISTA 与学习型策略（如记忆编辑、RL 压缩）是互补的，但论文未实验结合后训练的效果。
- **AMA-Bench 参照不够官方**：EMem-style 和 Mem0-style 行是本地适配器，而非官方复制品，因此该迁移实验的结论应视为诊断而非最终性能声明。
- **安全性未评估**：未考虑恶意文档或工具结果可能试图操纵 archive/recovery 决策的风险。
- **基线覆盖有限**：虽然覆盖了多种主流方法，但训练型压缩器（如 CAT、Context-Folding 等）由于无发布代码，只能复现推理时设计，未直接参与排名；且缺少与更近期的学习型记忆方法（如 Memex(RL)）的对比。
- **计算成本**：虽然 VISTA 减少了每步令牌消耗（工作集小而精），但由于总步骤增加（更长存活），在一些场景（如 BrowseComp-Plus）API 令牌总量反而增加，导致效率不是纯增益；论文对此有诚实的说明。
