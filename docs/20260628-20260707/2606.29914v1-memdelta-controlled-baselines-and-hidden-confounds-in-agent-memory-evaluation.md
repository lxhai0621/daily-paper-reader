## 摘要
智能体记忆系统日益与RAG和全上下文基线进行对比评估，但报告的性能提升往往同时改变了记忆方法以及语言模型、嵌入模型或检索流水线，导致实际测量目标不明确。我们提出MemDelta，一种受控评估协议，在LongMemEval-S（500个问题，50+轮次，三个模型家族）上每次仅变动一个组件。四项发现如下：（1）逐字RAG与全上下文GPT-4o-mini性能相当（47.2% vs. 49.8%，p=0.34），但排名在不同模型间反转：Gemini从全上下文中获益+14个百分点，而Sonnet从RAG获益+31个百分点，部分原因是Sonnet拒绝了63%的全上下文查询；（2）在相同流水线中仅更换嵌入模型，n=500时准确率波动+6.2个百分点（p=0.004），Mem0优于MiniLM-RAG达+11个百分点，但落后于cloud-RAG 1.2个百分点，因此单一变量即可颠覆结论；（3）智能体自记忆（42%）表现低于基本检索（47%）；（4）在6类问题中的2类（n=88）上，Mem0以50倍成本与cloud RAG持平（72.7% vs. 73.9%，p=1.0），表明收益狭窄而非普遍。我们建议记忆评估在比较中固定嵌入模型，按模型家族分层，并在将性能提升归因于架构前报告写路径成本。

## Abstract
Agent memory systems are increasingly evaluated against RAG and full-context baselines, but reported gains often mix changes in the memory method with changes in the language model, embedding model, or retrieval pipeline, making it unclear what is actually being measured. We present MemDelta, a controlled evaluation protocol that varies one component at a time on LongMemEval-S (500 questions, 50+ sessions, three model families). Four findings emerge: (1) verbatim RAG matches full-context GPT-4o-mini (47.2% vs. 49.8%, p = 0.34), but the ranking reverses across models: Gemini gains +14pp from full context, while Sonnet gains +31pp from RAG, partly because it refuses 63% of full-context queries; (2) swapping only the embedding model in an identical pipeline shifts accuracy by +6.2pp at n = 500 (p = 0.004), and Mem0 beats MiniLM-RAG by +11pp but loses to cloud-RAG by 1.2pp, so one variable flips the conclusion; (3) agent self-memory (42%) underperforms basic retrieval (47%); (4) on 2 of 6 question types (n = 88), Mem0 matches cloud RAG (72.7% vs. 73.9%, p = 1.0) at 50x the cost, suggesting narrow rather than general gains. We recommend memory evaluations fix embedding models across comparisons, stratify by model family, and report write-path cost before attributing gains to architecture.

## 1. 论文的核心问题与整体含义（研究动机和背景）

当前智能体（Agent）记忆系统的评估通常将其与 RAG（检索增强生成）或全上下文（full-context）基线进行对比。然而，报告的性能提升往往同时改变了记忆方法、语言模型、嵌入模型或检索流水线等多个变量，导致无法判断增益的实际来源。例如，当 Mem0 在 LongMemEval-S 上以 MiniLM 嵌入的 RAG 基线进行对比时，表现优于基线 11 个百分点；但若仅将基线换成云嵌入（相同代码），结论反转，Mem0 反而落后 1.2 个百分点。这种隐藏的混淆因素使得架构性结论不可靠。

论文的核心问题：**当智能体记忆系统超越基线时，究竟什么因素真正提高了性能？** 作者因此提出 MemDelta 受控评估协议，旨在隔离四个关键混淆因素：检索质量、嵌入选择、语言模型行为以及写路径（write-path）成本。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 核心思想
每次仅变动一个组件，固定其他所有变量，进行配对比较。不是直接比较两个系统，而是构造只差一个变量的条件对。

### 2.2 关键技术细节

- **策略定义**：定义了 7 种记忆策略（S0–S4b），按写路径复杂度排序。

  - S1：全历史（约115k token）
  - S4：逐字 RAG（MiniLM 嵌入，384维，ChromaDB，top-10）
  - S4b：逐字 RAG（云嵌入，text-embedding-3-small，1536维），与 S4 仅嵌入不同
  - S2：智能体自记忆（scratchpad，4096 token，topic-organized，~250次LLM调用）
  - S3：Mem0 v2.0 提取管道（~1000+次LLM调用，~120分钟，$0.50+）

- **执行流程**（每问题五步）：
  1. 重置（新存储）
  2. 摄入（流式读取用户历史，使用策略写路径）
  3. 构建上下文（检索或组装）
  4. 回答（固定 prompt，温度0）

- **配对比较**：Table 2 定义了六组比较，每组仅变换一个因素：

  - S4b vs S3：写路径复杂度（嵌入≈匹配）

## 6. 论文的主要结论与发现

1. **检索质量主导性能**：从无记忆（2.2%）到基本RAG（47.2%），提升45pp，覆盖了大多数性能差距。
2. **模型选择会导致结论反转**：在 GPT-4o-mini 上，全上下文与RAG无显著差异（49.8% vs 47.2%，p=0.34）；但 Gemini Flash 上全上下文优于RAG 14pp；Claude Sonnet 上 RAG 优于全上下文 31pp（因为Sonnet在长上下文中拒绝63%的查询）。单模型评估会误导结论。
3. **嵌入模型交换效果显著**：在完全相同的管道中，仅将MiniLM换成云嵌入（text-embedding-3-small），准确率从47.2%升至53.4%（+6.2pp，p=0.004），足以反转Mem0与RAG的比较结论。
4. **智能体自记忆（42%）不如基本RAG（47%）**：压缩策略在跨会话问题上尤其失败（准确率仅3.3%）。
5. **Mem0 在高成本下与云RAG持平**：在88个匹配实例上，Mem0（72.7%）与云RAG（73.9%）无显著差异（p=1.0，90%置信区间[-10.8, +8.4]pp），但写路径成本高出50倍（120分钟 vs 60秒）。Mem0的优势集中在SS-User和Multi-Session类型，且非普遍。
6. **不同问题类型有结构性差异**：检索擅长单会话问题（云RAG达87%）；全上下文在知识更新（72%）和多会话（37%）问题上表现较好；云嵌入缩小了多会话和时序问题上的差距。
7. **推荐评估标准**：①报告逐字RAG基线并指定嵌入模型；②包含随机检索对照；③至少两个模型家族；④披露嵌入模型并进行嵌入式敏感性测试；⑤报告写路径成本（LLM调用、时间、美元）；⑥对昂贵系统使用匹配实例比较。

## 8. 不足与局限

- **评估覆盖不完整**：Mem0 仅评估了88个实例（2/6问题类型），时序推理和知识更新问题未测试，而这些可能是提取最有价值的场景。

- **嵌入近似匹配**：S4b vs S3 使用不同OpenAI嵌入模型（text-embedding-3-small vs ada-002），并非完全受控。
- **忽略其他变量**：未控制分块大小、top-k、查询改写、提示模板等因素，这些也可能影响结论。

- **成本数据来自试运行**（n=5），可能存在统计噪声。
- **未讨论架构性改进的价值**：论文主要集中于混淆因素，未深入探讨在完全受控条件下记忆架构何时真正有效（但附录B.3有简要讨论，认为知识更新等问题可能保留全上下文优势）。
