## 摘要
记忆对 AI 智能体至关重要。许多现有的智能体记忆系统采用提前（Ahead-of-Time, AOT）设计，即在特定请求到来之前就构建记忆。虽然这降低了在线服务成本，但这种与请求无关的记忆构建方式可能丢弃后来变得重要的细粒度信息。为解决这一局限，我们提出即时智能体记忆（Just-In-Time Agent Memory, JAM），一个可在运行时根据查询条件构建上下文的可训练框架。其中，Memorizer 在分层页面存储中保存完整的原始历史，并配有紧凑的导航摘要；Researcher 则针对每个请求迭代地检索、检查和整合证据。为训练这些记忆使用行为，我们引入 Memory-Gym，一个以证据为基础的数据合成流水线，涵盖六个领域中的九种任务类型，并通过基于已验证轨迹的监督微调以及提示引导的组相对策略优化（Hint-guided Group Relative Policy Optimization）来优化 Researcher。我们在智能体记忆和长上下文处理的各种基准上证明了 JAM 的有效性，其任务性能优于 AOT 式记忆系统，同时相比先前经过训练的智能体式记忆方法显著更高效。为支持可复现性和未来研究，我们在 https://github.com/VectorSpaceLab/general-agentic-memory 发布了匿名化源代码。

## Abstract
Memory is critical for AI agents. Many existing agent-memory systems follow an Ahead-of-Time (AOT) design, constructing memory before a specific request arrives. While this reduces online serving cost, such request-agnostic memory construction can discard fine-grained information that later becomes important. To address this limitation, we propose Just-In-Time Agent Memory (JAM), a trainable framework for query-conditioned context construction at runtime. A Memorizer preserves complete raw histories in a hierarchical page-store with compact navigational summaries, while a Researcher iteratively retrieves, inspects, and integrates evidence for each request. To train these memory-use behaviors, we introduce Memory-Gym, an evidence-grounded data synthesis pipeline covering nine task types across six domains, and optimize the Researcher through verified-trajectory supervised fine-tuning followed by Hint-guided Group Relative Policy Optimization. We demonstrate the effectiveness of JAM across a variety of benchmarks on agent memory and long-context processing, where it achieves stronger task performance than AOT-style memory systems while remaining substantially more efficient than prior trained agentic memory approaches. To support reproducibility and future research, we release our anonymized source code at https://github.com/VectorSpaceLab/general-agentic-memory.

## 1. 核心问题与整体含义

- **研究动机**：AI 智能体在执行深度研究、软件工程等复杂任务时会持续产生长且演化的历史记录（观察、推理轨迹、交互），记忆系统对构建下游任务所需上下文至关重要。
- **现有范式局限**：主流智能体记忆系统采用 **Ahead-of-Time（AOT）** 设计，即在具体请求到来之前就压缩/组织原始历史（如摘要、记忆笔记）。虽然降低了在线服务成本，但**与请求无关的预处理会丢弃细粒度信息与跨会话依赖**，这些信息在后续可能变得关键。
- **核心痛点**：当任务相关证据分散在庞大、演化、时序相互依赖的历史中时，固定检索或摘要流水线难以组装出针对查询的上下文。
- **整体含义/主张**：记忆不应仅被视为"存储过去信息"，而应被视为**在运行时构建与查询相关的上下文**。论文提出 **Just-In-Time（JIT）** 设计哲学，将离线记忆组织与运行时记忆构建分离。

## 2. 方法论

### 2.1 核心思想
- **JAM 双组件框架**：
  - **Memorizer（离线）**：保留完整原始历史于分层页面存储（hierarchical page-store），同时构建紧凑的导航摘要。
  - **Researcher（运行时）**：在轻量记忆导航引导下，迭代检索、检查、整合证据，为每个请求组装优化上下文。
- **问题形式化**：给定请求 $q$ 与历史 $H$，记忆系统产生上下文 $c^* \leftarrow \text{Memory}(q, H)$，目标是在性能最优的前提下最小化上下文规模：
  $$C^*(q,H) = \arg\max_{c \in C(H)} \text{Perf}_A(q,c), \quad c^* = \arg\min_{c \in C^*(q,H)} |c|$$
  - AOT 式记忆通过请求无关的预压缩近似 $c^*$；JIT 记忆则在运行时按请求 $q$ 条件化构建 $c^*$。

### 2.2 Memorizer：分层工作区构建
- 两个轻量操作：
  - **memorize**：为每个会话 $s_i$ 生成简洁备忘 $\mu_i$：$\text{Memorizer.memorize}(s_i, W_{<i}) \to \mu_i$
  - **write**：将 $s_i$ 原始内容存为源文件，并用 $\mu_i$ 组织其层次位置：$\text{Memorizer.write}(s_i, \mu_i, W_{<i}) \to W_{\le i}$
- 语义相关会话按备忘分组到一致目录；每个目录维护由子文件/子文件夹备忘构成的 **README**，作为紧凑导航摘要。
- 原始文件保持完整、路径可追溯，作为证据源；备忘与 README 引导 Researcher 定位相关会话。

### 2.3 Researcher：运行时智能体式研究
- **三种工作区访问工具**（动作空间 $\mathcal{T} = \{\text{open}, \text{search}, \text{browse}\}$）：
  - `open(p)`：读取路径 $p$ 下的 README 与目录列表
  - `search(κ)`：用 BM25 与稠密嵌入做混合检索
  - `browse(p, κ)`：读取特定路径并抽取查询相关信息
- **迭代 think–explore–reflect 循环**：
  - **Thinking**：生成动作集合 $A_i = \{a_i^1,\dots,a_i^{K_i}\} \sim \pi_\theta(\cdot \mid q, h_{i-1})$，$a_i^k = (t_i^k, \rho_i^k)$
  - **Exploration**：执行动作得观察 $O_i = \{o_i^k\}$，$o_i^k = \text{Exec}(a_i^k, W)$；轨迹更新 $h_i = h_{i-1} \oplus (A_i, O_i)$
  - **Reflection**：判断信息充分性 $y_i = \text{Reflect}_\theta(q, h_i)$，满足或达预算则停止
  - **Finalize**：构建最终上下文 $c^* = \text{Finalize}_\theta(q, h_T)$，保留请求相关信息与来源溯源；预算耗尽时做尽力而为的总结

### 2.4 训练：Memory-Gym 与级联优化
- **Memory-Gym 数据合成管线**：
  - **任务分类（3 族 9 类）**：单跳定位（属性抽取、概念解释、条件定位）、多跳证据连接（比较、溯源追踪、交集选择）、多会话摘要（状态演化、集合枚举、聚合摘要）
  - **六大领域**：web、书籍、对话、新闻、学术论文、长文档
  - **四阶段构建**：① 锚点发现 → ② 任务相关会话扩展 → ③ 实例化（生成 query-answer 对）→ ④ 验证过滤（唯一性、逻辑支撑、无泄漏、任务一致性、覆盖率、完整性、忠实性）
  - **规模**：28,276 个候选 → 16,794 个保留（接受率 59.4%）；人工审计 200 条保留实例，95.0% 满足全部质量标准
- **级联优化流程**：
  - **Verified-trajectory SFT**：用强教师模型在 JAM 工作流下解题，LLM-as-a-judge 过滤正确答案与高质量探索轨迹，最大化演示动作集似然：
    $$\mathcal{L}_{\text{SFT}}(\theta) = -\sum_{\tau \in D_{\text{SFT}}} \sum_{i=1}^{|\tau|} \log \pi_\theta(A_i \mid q, h_{i-1})$$
  - **Hint-guided GRPO**：每 $K_h$ 步注入任务相关提示 $\eta_k$（不直接泄露答案或规定完整搜索路径，仅训练时使用，推理时移除）；奖励为源召回：
    $$R(\tau) = \text{Recall}(E_\tau, E_q^*) = \frac{|E_\tau \cap E_q^*|}{|E_q^*|}$$
    组内归一化得优势 $A_j$，用 GRPO 目标优化（含 KL 惩罚项，$\beta$ 控制，$\epsilon$ 为裁剪比）。

## 6. 主要结论与发现

- **性能优越**：JAM 在 4 个基准上普遍优于 AOT 式记忆系统，且以 4B 主干超越 7B–14B 训练式基线（如 LoCoMo F1 52.09 vs MemAgent 46.13）。
- **跨域泛化**：在 Memory-Gym 未覆盖的 LongCodeQA 上，准确率从 Untrained 54.08% → SFT 65.67% → SFT+RL 75.54%，说明记忆使用行为可迁移。
- **数据多样性有效**：Memory-Gym 优于 MemAgent/Memory-R1 派生监督；任务族互补（SH 利于 LoCoMo，MH 利于 HotpotQA，SU 利于 LME/NAQA），全混合最佳。
- **组件贡献**：Researcher 与 Memorizer 均关键；分层工作区相比扁平原始存储，LoCoMo F1 从 49.06 → 52.09，在线延迟从 17.11 s → 13.81 s，平均轮数 3.57 → 3.16；BM25 与稠密检索互补。
- **测试时扩展**：增加动作预算与检索条目数持续提升性能，但 20 轮主要是探索余量而非固定成本（LoCoMo/LME/NAQA 中位轮数仅 3，HotpotQA 为 6；预算耗尽率 0–4.70%）。
- **质量–成本权衡**：相比 MemAgent，JAM 查询延迟降低 76.2%（58.08 s → 13.81 s）同时 F1 提升（46.13 → 52.09）。
- **稳定性**：多种子推理标准差均 <1.5 分；LLM 评判下 JAM 在三个基准均最高（LoCoMo 79.16%、NAQA 68.00%、HotpotQA 69.79%）。

## 7. 优点

- **范式创新**：将记忆从"请求无关的预压缩"转向"运行时查询条件化的上下文构建"，思路清晰且切中 AOT 的信息丢失痛点。
- **架构合理**：Memorizer 保留完整原始证据（可溯源）+ 轻量导航摘要，Researcher 通过 open/search/browse 工具做 coarse-to-fine 探索，兼顾证据完整性与效率。
- **数据管线系统化**：Memory-Gym 覆盖 3 族 9 类任务 × 6 领域，构建流程严谨（四阶段 + 多重质量验证 + 污染控制），并做了详实的人机一致性审计（κ>0.8）。
- **训练方法设计巧妙**：验证轨迹 SFT + Hint-guided GRPO 级联，提示仅用于训练、推理移除，且不泄露答案；以源召回为奖励，直接针对"定位相关信息"而非模仿教师。
- **实验充分且多维**：主实验、消融、跨域迁移、多种子、LLM 评判、效率与 token 分析、主干敏感性、人工审计齐备。
- **开源可复现**：提供匿名代码仓库。

## 8. 不足与局限

- **Memorizer 未参与训练**：论文固定 Memorizer、只优化 Researcher，未研究 Memorizer 微调或联合优化；主干敏感性实验显示更换更强 Memorizer（122B-A10B）反而略降 F1（52.09 → 51.30），说明当前工作区构建策略的收益上限未充分探索。
- **基线可比性受限**：Memory-R1 非公开，结果引自原论文，与本文统一评测协议不可完全对齐（LLM 评判表中亦单独标注参考）。
- **在线延迟仍高于单次记忆系统**：迭代式 Researcher 引入额外查询延迟，高于 MemoryOS/LightMem 等一次性系统，对延迟敏感场景可能不适用。
- **预算耗尽处理为"尽力而为"**：HotpotQA 上 4.70% 查询耗尽预算，此情况下的最终化仅为已有证据总结，不保证答案正确。
- **领域与任务覆盖有限**：虽含 6 领域，但 LongCodeQA 是唯一跨域迁移验证，且 Memory-Gym 不含代码类任务；对更多专业领域（如医学、法律）的泛化未验证。
