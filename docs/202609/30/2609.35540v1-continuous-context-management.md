## 摘要
长时程大语言模型（LLM）智能体通常保留完整的交互历史，直到在预定义阈值处触发压缩。我们研究连续上下文管理（CCM），它在每一轮都执行压缩，以防止交互历史在活跃提示中累积。在每一轮，CCM 智能体在输出环境动作的同时，还输出更新后的记忆；其下一轮提示包含原始任务、保留的记忆以及最新观测，而不是完整对话记录。我们首先在 TerminalBench-2 上，使用 Claude Sonnet 4.6、Claude Opus 4.6、GLM-5 和 Kimi K3 对未经微调的 CCM 进行评估。CCM 大幅降低了累计输入用量和活跃提示大小，尽管它降低了大多数模型的任务成功率，但对 Kimi K3 保持了性能。我们使用带有特权全历史蒸馏的 GRPO 来改进开放权重模型中的 CCM。学生初始模型的一个冻结副本，在该学生 rollout 重建出的完整历史下，对每个采样的学生动作进行评分，从而无需单独的教师 rollout 或参考解，即可提供密集的动作 token 监督。在 WebShop 上，该目标在两个评估模型规模上均显著优于 GRPO 改进 CCM，并且在 Qwen3-4B-Instruct 上超过了全历史 GRPO，但在 Qwen3-8B 上未超过。在 Endless Terminals 上，增强方法相比 GRPO 提供了适度提升，且两种 CCM 策略均优于未训练的全历史基线。这些结果表明，CCM 是一种可行的推理范式，可供在显著减少保留上下文的情况下运行的智能体使用，并且其性能可通过带有特权全历史蒸馏的强化学习得到提升。

## Abstract
Long-horizon large language model (LLM) agents commonly retain their complete interaction history until compaction is triggered at a predefined threshold. We study Continuous Context Management (CCM), which performs compaction at every turn to prevent interaction history from accumulating in the active prompt. At each turn, a CCM agent emits an updated memory together with an environment action; its next prompt contains the original task, retained memory, and newest observation rather than the complete transcript. We first evaluate CCM without fine-tuning on TerminalBench-2 using Claude Sonnet 4.6, Claude Opus 4.6, GLM-5, and Kimi K3. CCM substantially reduces cumulative input usage and active-prompt size, although it lowers task success for most models while preserving performance for Kimi K3. We use GRPO with privileged full-history distillation to improve CCM in open-weight models. A frozen copy of the student's initial model scores each sampled student action under the complete history reconstructed from that student's rollout, providing dense action-token supervision without a separate teacher rollout or reference solution. On WebShop, this objective substantially improves CCM over GRPO at both evaluated model scales and surpasses full-history GRPO for Qwen3-4B-Instruct, though not for Qwen3-8B. On Endless Terminals, the augmented method provides a modest improvement over GRPO, with both CCM policies outperforming the untrained full-history baseline. These results demonstrate that CCM is a viable inference paradigm for agents operating with substantially reduced retained context and that its performance can be improved through reinforcement learning with privileged full-history distillation.

# 论文总结：Continuous Context Management（连续上下文管理）

## 1. 核心问题与研究背景

- **问题**：长时程 LLM 智能体（long-horizon agents）在 ReAct 式循环中通常把完整的推理、动作与观测序列保留在后续提示中，导致活跃上下文随任务推进不断膨胀。历史受限于模型上下文窗口，且即便在窗口内，输入变长或包含无关信息也会导致性能退化（"context rot"、"lost in the middle"）。
- **现有做法**：主流方案是"积累—压缩"（accumulate-compact）范式——当上下文达到预设 token 阈值时才触发压缩，用摘要替换早期内容。缺点是压缩事件之间上下文仍会持续累积，在再次压缩前可能占用窗口的很大比例。
- **本文主张**：把记忆管理下沉到**每一个动作步**，即连续上下文管理（CCM）。"连续"指记忆管理发生在最细粒度的步级，而非数学意义上的连续。
- **现实意义**：在 GPU 显存受限的场景（消费级 GPU 本地部署、单机多并发 agent 会话）中，保持活跃上下文紧凑可显著降低 KV cache 占用，从而在同一显存预算下运行更大模型或更多并发任务。

## 2. 方法论

### 2.1 CCM 交互协议

- 对任务 \(x\)，初始观测 \(o_0\)，初始记忆 \(m_0\) 为空。第 \(n\) 轮时智能体接收 \(x\)、\(m_{n-1}\)、\(o_{n-1}\)，生成：
  \[
  (m_n, a_n) \sim \pi_\theta(\cdot \mid x, m_{n-1}, o_{n-1})
  \]
- 响应 \(y_n = [m_n; a_n]\)，即**更新记忆在前、环境动作在后**。执行 \(a_n\) 得到 \(o_n\)，下一轮提示仅由 \(x, m_n, o_n\) 构成，不包含此前任何响应与观测。
- 关键推论：早期信息只有在智能体主动写入 \(m_n\) 时才得以保留；CCM 压缩的是**累积交互历史**，但**不压缩当前观测**（终端输出可达数万字符）。

### 2.2 训练方法：GRPO + 特权全历史自蒸馏

- **学生** \(\pi_\theta\)：按 CCM 协议 rollout；**教师** \(\pi_{\theta_0}\)：训练前学生模型的冻结副本，全程不更新、不刷新。
- **特权信息**：由学生自身 rollout 重建的动作前环境历史 \(h_n^S = (o_0, a_1, o_1, \dots, a_{n-1}, o_{n-1})\)，**不含当前动作**，也不需要单独的教师 rollout 或成功参考轨迹。
- **置信度差与门控**：
  \[
  \Delta_{n,t} = \text{stopgrad}\big[\log \pi_{\theta_0}(a_{n,t}\mid s^+_{n,t}) - \log \pi_\theta(a_{n,t}\mid s^C_{n,t})\big]
  \]
  \[
  g_{n,t} = \text{stopgrad}[\sigma(\beta \Delta_{n,t})]
  \]
  教师更"自信"的 token（\(\Delta>0\)）获得更大门控权重；学生本已自信的 token 被衰减但保留正权重。\(\beta=5\) 控制门控锐度。
- **蒸馏损失**（仅作用于有效**动作** token，掩码 \(M_{i,n,t}\)）：
  \[
  \mathcal{L}_{\text{distill}} = -\frac{\sum M_{i,n,t} g_{i,n,t}\log \pi_\theta(a_{i,n,t}\mid s^C_{i,n,t})}{\sum M_{i,n,t}}
  \]
- **总损失**：\(\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{GRPO}} + \lambda_{\text{distill}}\mathcal{L}_{\text{distill}}\)，其中 \(\lambda_{\text{distill}}=0.01\)。GRPO 监督记忆 token + 动作 token，蒸馏只监督动作 token。
- **理论分析（附录 C）**：在固定上下文、on-policy 采样下，期望的 SDAR 式更新等价于一个**有界、中心化的 sigmoid 变换**：有效权重 \(w_{\text{SDAR}}(\delta)=\sigma(\beta\delta)-1/2=\tfrac12\tanh(\beta\delta/2)\)，保留教师偏好的符号与序关系但压缩幅度；当 \(|\beta\delta|\ll1\) 时，\(w_{\text{SDAR}}\approx \frac{\beta}{4}\delta\)，局部逼近按比例缩放的 OPD（on-policy distillation）梯度。作者明确指出这只是**局部近似**，不构成完整训练过程的精确 reverse-KL 最小化。
- **消融发现**：仅用蒸馏、关闭 GRPO 时，两个模型在 WebShop 上几乎零成功（0/128 与 1/128），说明蒸馏只能作为辅助目标，记忆 token 仍需 GRPO 的轨迹级监督。

### 2.3 GRPO 细节（附录 B）

- 组归一化优势 \(A^{(i)} = (R^{(i)}-\mu_R)/(\sigma_R+\varepsilon_{\text{std}})\)；裁剪 PPO 目标 + 双裁剪（负优势，系数 3.0）+ 采样 KL 参考正则。
- 超参：学习率 \(1\times10^{-6}\)、恒定调度、PPO clip 0.2、entropy 0.001（Endless Terminals 为 0.0）、KL 系数 0.01、每步 32 任务 × 8 rollout = 256 轨迹。

## 6. 主要结论与发现

- **CCM 作为免训练推理范式有效压缩上下文**：TerminalBench-2 上中位峰值提示从 9,472–17,560 token 降至 3,243–4,280；累计输入 token 分别减少 83.1%（Sonnet）、81.5%（Opus）、84.3%（GLM-5）、75.8%（Kimi K3）；保留记忆最大仅 561–1,403 token。
- **性能代价因模型而异**：Sonnet −11.2pp、Opus −18.0pp、GLM-5 −5.6pp，而 Kimi K3 反而 +1.1pp（62.9%→64.0%）。
- **成本未必随 token 下降**：由于前缀缓存，Sonnet 两种模式成本几乎相同（$0.468 vs $0.472）；Opus 与 Kimi 的全历史反而更便宜（缓存读占比 88–93% vs CCM 的 0–42%）；仅在不支持缓存的 GLM-5 端点上 CCM 显著省钱（$0.515→$0.124）。
- **训练显著提升 CCM**：
  - WebShop：Qwen3-4B-Instruct 上蒸馏使精确成功从 24.22%→86.72%（+62.50pp），部分分 0.817→0.948，并**超过全历史 GRPO（75.78%）**，平均 5.36 轮完成；Qwen3-8B 从 11.72%→57.81%（+46.09pp），但全历史 GRPO 仍最强（80.47%）。
  - Endless Terminals：CCM+GRPO+蒸馏最佳 32.00%（step 50）> CCM+GRPO 29.00%（step 30）> 未训练全历史 20.33%；但全历史 GRPO 最强（35.33%）。
- **行为层面**：CCM+GRPO 的记忆更新率极低（4B 12.9%、8B 9.1%），几乎整段复用前缀；加蒸馏后变得主动（100%、96.9%），前缀保留率降至 77.2%、82.3%，累计输入进一步下降 65.0%、43.8%。
- **通用能力保持**：特权蒸馏缓解遗忘，最明显的是 WebShop 的 Qwen3-4B（MMLU-Pro −1.03pp、HellaSwag −5.62pp、IFEval −0.12pp，优于 CCM+GRPO 的 −10.09/−13.46/−0.99），但该效果在不同规模、环境、评测任务间**并不一致**。
- **关键反直觉点**：CCM 不自动减少总输入（未训练 Qwen3-8B 的 CCM 因轮数更多而处理了更多 token）；且压缩交互历史不等于压缩当前观测，因此峰值提示仍可能被长终端输出主导。

## 7. 优点

- **问题设定清晰且有现实锚点**：把"压缩时机"从阈值触发推进到每步触发，动机（KV cache 与显存竞争）明确，区别于 MEM1 等已有工作。
- **训练信号设计巧妙**：教师是学生初始权重的冻结副本，用学生自己的 rollout 重建特权历史，**无需单独教师模型、额外 rollout 或成功参考解**，显著降低数据与算力门槛。
- **理论支撑**：附录 C 给出了 SDAR 门控与 OPD 梯度之间的等价/近似关系，说明有界中心化 sigmoid 权重保留符号与序关系、抑制极端分歧，态度审慎（明确声明仅为局部刻画）。
- **实验透明度高**：报告 token 明细（uncached/cache-read/cache-write）、成本拆解、记忆更新率与前缀保留率，并诚实指出 CCM 不必然省钱、不必然省 token。
- **通用能力评估**：在 agent 后训练后检验 MMLU-Pro/HellaSwag/IFEval，避免只看任务成功率，并发现蒸馏的保持优势。
- **定性轨迹分析扎实**：给出失败模式（重复点击已选选项、记忆不更新、冗余命令不终止）与成功序列（search→product→color→size→purchase），可解释性强。

## 8. 不足与局限

- **性能未全面超越全历史**：除 WebShop + Qwen3-4B 外，全历史 GRPO 在 8B 和 Endless Terminals 上仍最强；CCM 的免训练版本在 4 个模型中有 3 个明显掉点。
- **成本结论高度依赖外部因素**：前缀缓存与定价策略决定了 CCM 是否真正省钱，使得"减少上下文"与"降低成本"之间存在断裂，削弱了部分动机的普适性。
- **不压缩当前观测**：CCM 只管理累积历史，长终端输出仍可使提示达 50k+ token，压缩收益被削弱；Endless Terminals 中所有条件都至少一次触及上下文硬截断。
- **实验覆盖有限**：训练仅 Qwen3-4B/8B，环境仅 WebShop 与 Endless Terminals；评估集偏小（128/300 任务），单 seed，统计显著性未做检验；缺少与 MEM1、MemAgent、MEMENTO、Compaction RL 的数值横向对比。
- **超参与消融不充分**：\(\lambda_{\text{distill}}\)、\(\beta\)、教师刷新策略等均未做敏感性分析；蒸馏-only 的失败说明方法对 GRPO 存在强依赖，方法鲁棒性边界不明。
- **理论保证有限**：作者自己承认局部等价性不覆盖记忆生成、动作序列生成、环境历史分布、行为策略快照复用与掩码归一化等环节，不保证 KL 单调下降或任务提升。
- **安全与部署风险**：记忆中的错误或遗漏会传播到后续动作；记忆可能含观测中的敏感信息；作者在伦理声明中明确表示基准结果不足以证明 CCM agent 可安全无限制部署，需访问控制、数据处理保障与人类监督。
- **API 结果可复现性受限**：托管模型会随提供商更新而漂移，文中也提示了这一点。
