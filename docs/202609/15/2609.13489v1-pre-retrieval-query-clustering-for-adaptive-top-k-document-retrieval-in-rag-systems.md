## 摘要
RAG 系统通常检索固定数量的文档（top-k）来为生成提供依据，但这种静态方法很脆弱：简单查询会过度检索（引入噪声和成本），而复杂查询则检索不足，导致召回失败并级联为错误答案。受“为了可靠回答任意查询，必须检索多少篇文档”这一问题的驱动，我们提出了一种实用且通用的查询自适应检索深度框架。离线阶段，我们通过在默认检索器下测量 NDCG，并从 NDCG-k 曲线中推导查询特定的“饱和”点 k*，来估计每个查询的检索难度。由于在线计算这些信号成本高昂，我们在嵌入空间中对大量查询进行聚类，并使用均值加方差规则，为每个簇总结出一个推荐检索深度，以目标高覆盖率（例如约95%）。在运行时，系统将传入查询分配到某个簇，并在常数时间内选择相应的 top-k。与依赖对已检索文档进行聚类的检索后置信度方法相比，我们的方法是检索前且以查询为中心的，这使其在异构、类案卷式语料中具有鲁棒性，并可适用于法律、医疗、金融和企业搜索等领域。最后，该框架已在全流量查询中测试，在低复杂度簇上，F1 提升超过36%，同时 token 使用量减少14%，且没有精度损失。

## Abstract
RAG systems commonly retrieve a fixed number of documents (top-k) to ground generation, but this static approach is brittle: simple queries suffer over-retrieval (adding noise and cost) while complex queries are under-retrieved, causing recall failures that cascade into incorrect answers. Motivated by the question of how many documents must be retrieved to answer an arbitrary query reliably, we propose a practical, general framework for query-adaptive retrieval depth. Offline, we estimate per-query retrieval difficulty by measuring NDCG under the default retriever and deriving a query-specific "saturation" point k* from the NDCG-k curve. Because computing these signals online is expensive, we cluster a large set of queries in embedding space and summarize each cluster with a recommended retrieval depth that targets high coverage (e.g., \textasciitilde{}95\%) using a mean-plus-variance rule. At runtime, the system assigns an incoming query to a cluster and selects the corresponding top-k in constant time. Compared with post-retrieval confidence methods that rely on clustering retrieved documents, our approach is pre-retrieval and query-centric, making it robust in heterogeneous, case-like corpora and applicable across domains such as legal, healthcare, finance, and enterprise search. Finally, this framework has been tested in full-traffic queries that improved $F_1$ by over 36\% while reducing token usage by 14\% on low-complexity clusters without accuracy loss.

## 1. 核心问题与研究动机

- **背景**：RAG 系统通过检索外部文档为大模型生成提供依据，但绝大多数实现仍沿用**静态 top-k** 规则——编码查询、检索固定数量文档、全部塞入上下文。
- **核心矛盾**：静态 top-k 与真实用户行为根本性错配：
  - **简单查询**（如"原告出生日期"）只需一两篇权威文档，固定大 k 造成**过度检索**，引入冗余噪声、抬高 token 成本与延迟。
  - **复杂查询**（如"列出所有治疗项目及日期与提供者"）需要广泛证据覆盖，固定小 k 造成**欠检索**，召回失败会级联为错误答案。
- **关键研究问题**：为可靠回答任意查询，到底需要检索多少篇文档？检索深度应随查询而变化。
- **现有方法局限**：以 CAR 为代表的后检索方法（post-retrieval）必须先检索一个大候选池，再基于排序相似度曲线的聚类断点做截断。其问题在于：(i) 检索本身昂贵时（多阶段检索、交叉编码器）成本高；(ii) 近重复语料下信号失真；(iii) 难以在下游组件前预知预算与延迟。
- **本文定位**：提出 **QCAR（Query-Clustering Adaptive Retrieval）** 框架，主张**检索前、以查询为中心**地估计检索深度，与后检索方法互补。

## 2. 方法论

### 2.1 核心思想

- 在**有界领域**（bounded domain）中，检索深度在很大程度上可由查询本身预测：相同问题类型因语料结构与相关性分布稳定而需要相近的检索深度。
- 查询复杂度由两个维度构成，通过**优先级规则**整合：
  - **词汇范围标记**（约 20% 查询）：如量词"all/every"、基数参数"top 5"、结构迭代"for each provider"、综合任务"timeline/chronological"等，作为**确定性覆盖**，直接令 k* = k_max。
  - **语义意图**（约 80% 查询）：无显式标记但复杂度差异大，需从领域数据中学习，依赖聚类先验。

### 2.2 离线阶段：构建查询-簇数据库 D_qc

1. **查询嵌入与降维**：
   - 使用 `text-embedding-ada-002` 生成 1536 维向量。
   - 对比 PCA（186 维解释 80% 方差，560 维达 95%）与 UMAP；PCA 配对聚类 SS≈0、DBI>2，效果差。
   - 最终选择 **UMAP**（n_components=190, n_neighbors=200, min_dist=0.0）。
2. **聚类**：
   - 对比 K-means、Ward 凝聚聚类、HDBSCAN。
   - HDBSCAN 将约 1/3 查询判为噪声，故仅用于确定自然簇数与稳定质心，再用 **K-means** 初始化分配全部查询。
   - 最终 **K=80 个簇**（SS=0.369，DBI=1.019，LLM 定性评分高）。注意 N=2 时数值最优（SS=0.6, DBI=0.46）但语义塌缩严重。
3. **相关性标注**：
   - 每簇随机采样 21 条查询，用 **Claude Sonnet 4.5** 做 LLM-as-a-Judge 少样本标注。
   - 每页（每案约 190 页）打三级标签：0（不相关）、1（部分相关）、2（完全相关）。
4. **检索深度估计（NDCG 驱动）**：
   - DCG_k = Σ_{i=1}^{k} (2^{rel_i} − 1) / log₂(i+1)；IDCG 用全部相关文档最优排序计算；NDCG_k = DCG_k / IDCG_n。
   - **每查询肘点**：以 k=100 为最大深度，逐点计算 NDCG，定义饱和点：
     **k*(q) = max{ k | NDCG_{k+1}(q) − NDCG_k(q) ≥ ε }**，阈值 ε=0.001。
   - **簇级聚合**：对簇 C_j 内查询的 k* 计算均值 μ_j 与标准差 σ_j，按**均值加方差规则**设定推荐深度：
     **k*_cluster = μ_j + 2σ_j**，目标覆盖约 95% 相关文档。

### 2.3 在线阶段：常数时间推理（Algorithm 1）

- **Step 1 词汇启发式**：匹配预定义模式则 k* = k_max，直接检索。
- **Step 2 语义映射**：否则嵌入查询 → UMAP 投影 → 与 K 个质心做最近邻 → 查表得 k*。
- **Step 3 RAG 执行**：按 k* 精确检索并生成。
- **开销**：词汇匹配 <1ms、一次嵌入 30–50ms（检索本就需）、投影 ~1ms、质心最近邻 <1ms（K≤100）、O(1) 查表。
- 查询分布漂移通过周期性重建 D_qc 或触发式更新应对。

## 6. 主要结论与发现

- **自适应检索显著优于静态检索**：线上 A/B 测试中 **F1 提升 36.64%**（p=1.14×10⁻³⁴），token 消耗增加 51.19%（p=2.87×10⁻¹³⁴，因复杂查询扩展上下文所致）。
- **简单查询实现"零损失降本"**：相对 k=50 基线，token 减少 35.95%（最高 40.77%）同时 F1 反升 +0.37；端到端 token 降幅最高 23% 且概念上无损失。
- **复杂查询召回改善**：最优 k* 常触达 100 上限，相对 k=50 的 F1 提升 +0.37，token 增加 85.95%；端到端事实召回率提升 **9%–17%**。
- **随机降 token 会立即损害质量**：随机 k 的 NDCG/F1 呈陡峭线性下降，而自适应策略保持稳健平台，证明 QCAR 能识别并丢弃冗余文档而不伤精度。
- **检索深度与 F1 正相关**：印证静态深度对复杂信息需求根本性次优。

## 7. 优点

- **预检索、查询中心的设计**：把昂贵的标注与调参完全离线化，在线仅需常数时间查表，延迟可预测，适合有预算约束的生产系统。
- **词汇覆盖 + 语义先验的混合优先级**：显式量词等标记作为确定性覆盖，兼顾高风险"list all"类查询的召回安全。
- **NDCG 肘点 + 均值加方差规则**：k* 的推导有明确的信息检索理论依据（饱和点、95% 覆盖率），而非拍脑袋启发式。
- **数值 + LLM 定性双重聚类评估**：发现并纠正了"数值最优但语义塌缩"的陷阱，方法学上值得借鉴。
- **真实全流量 A/B 验证**：不仅有离线仿真，还有生产环境的 Tier-1 指标与显著性检验，外部效度较强。
- **与后检索方法互补的定位清晰**：明确 QCAR 提供"先验"、CAR 提供"后验修正"，可组合成混合方案。
- **模块化、可迁移**：迁移新垂直领域只需历史查询日志、标注机制与可选词汇模式，聚类与深度估计机制直接复用。

## 8. 不足与局限

- **领域覆盖单一**：仅验证人身伤害法律，作者承认开域场景下可预测性减弱，跨域（医疗、金融、企业搜索）缺乏实证。
