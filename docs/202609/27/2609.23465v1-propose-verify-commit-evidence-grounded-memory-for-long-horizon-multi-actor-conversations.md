## 摘要
长时程对话记忆在多参与者场景中尤为困难，因为相关证据分散在不同参与者和上下文中，且先前确立的信息之后可能被修改。我们提出 EGMEMORY，它将长时程多参与者记忆建模为一个可搜索的状态机，将持久化的消息级证据与显式的活跃状态分离。在写入时，自适应状态解析与基于证据的“提议-验证-提交”协议共同支配该状态如何演化。在读取时，自适应证据导航迭代地解析查询所需的状态与支持性证据，利用对话结构缩小搜索空间，并利用词汇-语义相关性对候选进行排序。该系统通过提示与工具使用运行，无需针对记忆的专门策略训练。EGMEMORY 在 GroupMemBench 上达到 68.2%，在 EverMemBench 上达到 77.9%，分别比评估中最强的基线高出 22.7 和 21.4 个百分点。它在双人 LoCoMo 基准上进一步达到 73.6%，表明其可泛化到多参与者对话之外。我们将在正式发表后发布代码库。

## Abstract
Long-horizon conversational memory is especially challenging in multi-actor settings, where relevant evidence is distributed across participants and contexts and previously established information may later be revised. We introduce EGMEMORY, which formulates long-horizon multi-actor memory as a searchable state machine that separates persistent message-level evidence from an explicit active state. At write time, adaptive state resolution and an evidence-grounded propose-verify-commit protocol govern how this state evolves. At read time, adaptive evidence navigation iteratively resolves the state and supporting evidence required for a query, using conversational structure to narrow the search space and lexical-semantic relevance to rank candidates. The system operates through prompting and tool use without memory-specific policy training. EGMEMORY achieves 68.2% on GroupMemBench and 77.9% on EverMemBench, outperforming the strongest evaluated baselines by 22.7 and 21.4 percentage points, respectively. It further reaches 73.6% on the dyadic LoCoMo benchmark, demonstrating generalization beyond multi-actor conversations. We will release the codebase upon formal publication.

## 1. 核心问题与研究动机

- **研究背景**：LLM 智能体的交互时长已远超单次上下文窗口，持久化记忆成为长时程智能体的核心组件。已有记忆系统在记忆的构建、更新、组织和检索上取得进展，但大多针对**双人对话（dyadic）或局部化交互**，记忆通常绑定于单一对话上下文。
- **核心问题**：长时程**多参与者（multi-actor）**对话引入了不同的记忆范式——
  - 信息分散在不同参与者、话题线索（threads）和演化上下文中；
  - 相似表述可能指向不同讨论；
  - 先前确立的决定可能被后续发言**修订**。
- **现有工作的缺口**：
  - 动态/结构化记忆方法能保留演化历史与来源（provenance），但**未说明何时新证据足以推进活动状态**，而非仅与旧信息并存；
  - 智能体式检索支持迭代访问，但多参与者场景把「状态管理」与「自适应访问」耦合为同一问题；
  - 成功的记忆访问不只是找语义相似文本，还需判断**谁的证据相关、指向哪个对话状态、该状态是否仍然有效**。
- **整体含义**：论文将长时程多参与者记忆形式化为一个**可搜索状态机（searchable state machine）**，并由此提出 EGMEMORY 系统，分离「发生了什么」与「现在什么是有效的」这两个在扁平记忆存储中被混同的问题。

## 2. 方法论

### 2.1 核心思想

- 记忆被建模为可搜索状态机，由两条不变量指导：
  1. **修订是非破坏性的**：新证据可改变活动状态，但不擦除先前证据；
  2. **状态权威是显式的**：检索到或语义相似的消息本身不能重新定义当前有效状态。
- 框架通过**共享的版本化记忆**耦合两个过程：
  - **写入时**：证据锚定的状态演化（自适应状态解析 + 提议–验证–提交协议）；
  - **读取时**：自适应证据导航（迭代解析查询所需状态与支持证据）。

### 2.2 问题形式化

- 长时程多参与者对话记为 $C_t=\{m_1,\dots,m_t\}$，每条消息 $m_i=(x_i,a_i,t_i,c_i)$ 含内容、参与者、时间戳、对话上下文。
- 记忆表示为 $M_t=(E_t,S_t,R_t)$：$E_t$ 为持久证据库，$S_t$ 为当前活动状态集，$R_t$ 记录来源与状态转移关系。
- 证据单调保留：$E_{t-1}\subseteq E_t$；而 $S_t$ 可随新证据建立或取代旧状态而演化。
- 自适应访问过程（迭代式）：
  - $r_j=\pi(x,H_{j-1})$：基于输入与已观察证据生成记忆请求；
  - $O_j=\text{Access}(M,r_j)$：返回证据；
  - $H_j=H_{j-1}\cup O_j$：累积观察。
  - 即后续访问依赖先前访问揭示的内容，而非仅依赖原始查询。

### 2.3 写入侧：基于证据的状态演化

- **自适应状态解析**：构造记忆前，writer 可多次检索/检查活动记忆（最多 6 轮 writer-agent 循环，最多 3 次 registry 检索），逐步确定新消息指向哪个既有状态，而非从消息本身一次性判定。
- **提议–验证–提交协议**：
  - **Propose**：生成结构化更新 $\Delta_t=\text{Propose}(m_t,H^w_t)$，含话题、与既有状态的关系、状态承载值（state-bearing value）、上下文解析后的记忆表示等字段（实现中为 7 个字段：keep、topic、phase、verdict、value_quote、prior_ref、rewritten；verdict ∈ {new, restate, revision, null}）。
  - **Verify**：$\hat{\Delta}_t=\text{Verify}(\Delta_t;m_t,M_{t-1})$，用**确定性证据检查**（基于 token 重叠的 grounding）验证状态值是否有源消息支持、声称的修订是否能解析到有效先前状态。阈值：value_quote ≥ 0.9，prior_ref ≥ 0.8。这将「语义解释」与「状态权威」分离：LLM 只提议解释，确定性检查决定其能否修改持久状态。
  - **Commit**：$(e_t,M_t)=\text{Commit}(M_{t-1},\hat{\Delta}_t)$，将验证后的更新转为规范证据记录，并保留参与者、时间戳、话题、结构上下文等来源信息。
- 修订需关联到既有活动状态，否则视为建立新状态；无 grounded value 的决定不会被提交为权威决定状态。

### 2.4 版本化状态维护

- 每个已建立对话状态维护**当前支持其活动值的证据记录**。
- 修订提交时，新证据显式**取代（supersedes）**先前持有者并成为新活动状态，旧记录仍保留在 $E_t$ 中。
- 记 $e^{(k)}\prec e^{(k+1)}$ 表示取代关系，重复修订形成版本轨迹 $e^{(1)}\prec e^{(2)}\prec\cdots\prec e^{(K)}$，其中 $e^{(K)}$ 支持当前活动状态。
- 由此可区分**当前状态查询**与**历史查询**：前者暴露活动持有者，后者沿版本轨迹回溯。
- 对长轨迹，构造**紧凑派生视图**（将相关版本置于单一检索单元，但保留到底层记录的来源）；派生视图仅为检索辅助，规范消息级记录不变。
- 修订链接分两个置信层级：含 grounded 引用者为高置信，读取时仅高置信修订链接作为权威状态转移；被拒的修订边同时移除其过期状态载荷。
- 版本链物化的嵌入由已有消息嵌入平均并重归一化得到，不额外调用嵌入模型。

### 2.5 读取侧：自适应证据导航

- 检索为迭代过程而非单次「检索–阅读」：每个新请求以查询与已观察证据为条件。
- **两阶段检索**：
  - 第一遍：全局词汇–语义检索，选出少量高相关**锚点（anchors）**；
  - 由锚点诱导查询条件候选池（话题桶 + 来源邻域，含回复链、兄弟回复、前向/后向版本关系），可选参与者约束进一步限制范围；
  - 第二遍：在受限候选池内重新做词汇–语义检索。
- **关键设计**：对话结构用于决定「在哪里搜」，而非作为独立相关性信号；结构缩小候选空间，内容（词汇+语义）决定排序。
- **专用工具**（共享同一交互历史，一个工具揭示的证据可引导后续访问）：
  - `search_memory`：混合稠密–词汇检索，支持 topic/phase/author 约束；
  - `lookup_phrase`：针对段落级嵌入表示不佳的局部表达做词汇查找；
  - `get_current_decision`：取版本化决定链的当前状态；
  - `resolve_date`：基于消息或阶段时间戳确定性地解析相对时间表达。
- 已展示过的段落会在后续检索中抑制，使后续访问暴露新证据；收集到足够 grounded 证据或记忆不支持合理回答时终止。
- 最终回答 $\hat{y}=\text{Answer}(q,H^{rq})$ 由累积证据生成，而非单一固定检索结果。
- 检索配置：RRF（k=60）、稠密/BM25 融合深度 200、rerank 深度 50、reranker 文档截断 4000 字符、首轮 5 段、结构锚 3 个、二轮 10 段、每次工具返回最多 12 段、回答 agent 最多 10 轮。

## 3. 实验设计
