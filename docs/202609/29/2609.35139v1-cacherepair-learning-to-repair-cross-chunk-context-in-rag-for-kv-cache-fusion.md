## 摘要
多文档检索增强生成（RAG）要求语言模型在回答问题前处理多个检索到的文本块。独立预计算每个块的 KV 缓存，并在检索到这些块时拼接缓存，可以加速这一步骤。然而，组装后的缓存缺少跨块注意力信息，从而降低答案质量。选择性重计算方法通过在选定 token 上重新运行目标 LLM 来恢复缺失的跨块上下文，但会带来大量在线计算。我们提出 CacheRepair，这是一种轻量级网络，用于学习独立计算的 KV 缓存与将各块一起处理时产生的 KV 缓存之间的差异。该网络将压缩的 KV 特征与 token 嵌入相结合，并使用在每个块内双向、且从较早块流向较晚块的注意力。每个修复块接收压缩后的缓存特征，预测的残差被加到每个文档 token 的缓存中。每个修复网络针对特定的冻结目标 LLM，在通用检索语料上训练，并复用于下游数据集。我们的分析表明，修复降低了块边界附近以及块内部各处的 KV 误差。在三个目标 LLM 和四个下游数据集上的评估表明，在十二个模型-数据集组合中的十一个组合上，CacheRepair 位于所测得的答案质量-延迟 Pareto 前沿。报告的首 token 时间（TTFT）包括在线缓存传输和修复。在所有十二个组合中，规模最大的修复网络相对于完整预填充在中位 TTFT 上实现了 1.69-4.61 倍的加速，并将平均 F1 相较于直接缓存复用提高了 2.1-26.1 个百分点。

## Abstract
Multi-document retrieval-augmented generation (RAG) requires a language model to process multiple retrieved text chunks before answering a question. Precomputing each chunk's KV cache independently and concatenating the caches when the chunks are retrieved can accelerate this step. However, the assembled cache lacks cross-chunk attention information, reducing answer quality. Selective recomputation methods recover the missing cross-chunk context by rerunning the target LLM on selected tokens, incurring substantial online computation. We introduce CacheRepair, a lightweight network that learns the difference between independently computed KV caches and those produced by processing the chunks together. The network combines compressed KV features with token embeddings and uses attention that is bidirectional within each chunk and flows from earlier to later chunks. Each repair block receives the compressed cache features, and the predicted residual is added to every document token's cache. Each repair network is trained for a specific frozen target LLM on a generic retrieval corpus and reused across downstream datasets. Our analysis shows that repair reduces KV errors both near chunk boundaries and throughout chunk interiors. Evaluation across three target LLMs and four downstream datasets places CacheRepair on the measured answer-quality-latency Pareto frontier in eleven of twelve model-dataset combinations. Reported time to first token (TTFT) includes online cache transfer and repair. Across all twelve combinations, the largest repairers achieve 1.69-4.61$\times$ speedups in median TTFT over full prefill and improve mean F1 by 2.1-26.1 percentage points over direct cache reuse.

# CacheRepair 论文详细总结

## 1. 核心问题与研究背景

- **多文档 RAG 的预填充瓶颈**：检索增强生成（RAG）需在回答前处理多个检索文本块，多文档场景下预填充计算量大，显著增加首 token 时间（TTFT）。
- **独立 KV 缓存复用**：将每个块独立预计算并存储 KV 缓存，检索时按请求顺序拼接，可跨请求、跨块组合复用，避免重复预填充。
- **核心矛盾**：独立预计算的块缓存彼此不可见，拼接后缺失跨块注意力信息，形成 **stale KV cache**；而联合预填充得到的是 **joint KV cache**，二者不等（KV_stale ≠ KV_joint）。
- **现有方案及其代价**：
  - 选择性重算（CacheBlend、EPIC、InfoFlow）在选定 token 上重跑目标 LLM，在线开销大。
  - 其他方法通过重塑注意力、微调目标 LLM 或离线学习可复用缓存组件，但改变了冻结 LLM 或缓存复用前提。
- **本文核心问题**：能否用一个轻量外部网络，直接修复 stale KV 中缺失的跨块上下文，同时保持目标 LLM 冻结、块缓存可复用？
- **经验观察支撑**：对 Qwen2.5-3B 的分析发现，stale 与 joint KV 的误差既有**块边界局部热点**，也有跨越块内部的**层持久性误差带**，说明修复不应局限于边界，而应覆盖所有文档 token。

## 2. 方法论

### 2.1 核心思想

- 学习一个残差算子 `Rθ`，输入 stale KV 与文档 token，输出对 joint KV 的近似：
  - `dKV_r = Rθ(KV_stale, D_r) ≈ KV_joint - KV_stale`
- 修复结果通过残差加回 stale KV，目标 LLM 保持冻结，且修复仅依赖有序文档、不依赖查询文本。

### 2.2 关键技术细节

- **块缓存准备与坐标约定**：
  - 每个块独立预填充后，K 去掉局部 RoPE 存为 canonical 坐标；V 保持原生坐标。
  - 服务时按文档顺序拼接为 `KV_stale^c`。
- **StaleEncoder 与 token 融合**：
  - 将目标 LLM 所有层、KV 头、K/V 分量的 KV 压缩为宽度 `db` 的特征 `st`，使用固定 RMS 统计量 `σ_stale` 归一化。
  - 并行的 token 投影 `P_tok` 将冻结 token 嵌入 `E_M(x_t)` 映射到 `db`。
  - 线性融合层 `F` 合并缓存内容与 token 身份，得到修复主干输入 `h0_t`。
- **Repair Blocks 与块因果注意力**：
  - 掩码 `A_ij = 1[c(j) ≤ c(i)]`：块内双向可见，块间仅从较早块流向较晚块，匹配缺失上下文的流动方向。
  - 每个修复块接收原始编码特征的学习投影 `P_b(s)`，实现**stale 特征重注入**，使隐藏状态持续条件化于缓存内容。
- **KV 残差输出与全局 RoPE**：
  - LayerNorm + KV Residual Head 输出归一化残差 `z_t`。
  - 用固定残差尺度 `σ_Δ` 恢复单位并加回完整 stale KV（输出 skip connection）。
  - 随后对 K 施加全局请求位置 RoPE，V 保持原生坐标，交由冻结目标 LLM 使用。
- **训练**：
  - 对同一有序文档序列，目标 LLM 同时生成独立块缓存与联合预填充缓存，两者在 canonical 坐标下的差作为监督 `ΔKV_c*_t`。
  - 按层、KV 头、K/V 分量、头坐标分别统计 `σ_stale` 与 `σ_Δ`。
  - 损失为归一化坐标下的 MSE，对所有文档 token 和 KV 坐标等权。
  - 每个目标 LLM 训练一个修复器及固定归一化统计量，跨下游数据集复用。

## 6. 主要结论与发现

- **Pareto 前沿**：在 12 个模型–数据集组合中的 **11 个**，CacheRepair 至少贡献一个非支配质量–延迟工作点。
- **延迟与质量**：
  - 最大修复器相对 Full Prefill 实现 **1.69–4.61×** 的 p50 TTFT 加速。
  - 相对直接 Stale KV 复用，平均 F1 提升 **2.1–26.1 个百分点**。
  - 相对最高重算预设（CacheBlend 0.6、EPIC64、InfoFlow 0.25），修复器在全部 36 对比较中 TTFT 更快（1.30–6.76×），F1 差异范围 **−3.86 至 +4.43** 个百分点。
- **KV 误差修复**：
  - Qwen2.5-3B 30M 修复器在 MuSiQue 上，K 相对 RMSE 在边界从 0.310 降至 0.143（−53.9%），内部从 0.182 降至 0.089（−50.9%）。
  - V 边界下降 24.4%，内部下降 16.2%；所有配对 95% 区间均在零以上。
  - 修复还使教师强制 KL 从 1.731 降至 0.555，查询注意力输出相对 RMSE 从 0.598 降至 0.328。
- **设计验证**：
  - 块对角注意力（无跨块信息）F1 仅 0.0133；移除残差路径（直接预测 joint KV）F1 仅 0.0049；残差预测优势约 **23.44 个百分点**。
  - MSE 目标优于 QK/V（+4.78 pp）和 Huber（+1.08 pp）。
- **块数与长度**：
  - 文档内容固定、块数从 8 增至 16 时，Stale KV F1 从 0.231 降至 0.165，而 CacheRepair 保持 0.289/0.277，TTFT 约 33 ms。
  - 16K token 时最大修复器相对 Full Prefill 加速 3.43–6.14×，仅使用其 2.0–4.0% 的密集矩阵 MACs。
- **并发**：C=8 时 Qwen2.5-3B 30M 修复器吞吐 30.70 req/s，Full Prefill 为 11.35 req/s（2.70×），但 KV Packet 达 46.80 req/s。

## 7. 优点

- **问题切入清晰**：将 KV 缓存融合明确形式化为 stale→joint 的残差学习问题，并给出跨块误差的结构化证据（边界热点 + 层持久带），设计有据可依。
- **免在线重算**：完全不需要在线重跑目标 LLM，目标 LLM 冻结，兼容现有部署与量化配置。
- **训练–推理解耦**：在通用检索语料上离线训练，一个检查点跨四个下游数据集复用，具备跨任务泛化能力。
- **架构设计合理**：
  - 块因果注意力匹配缺失上下文的方向性；
  - 逐块特征重注入保持缓存条件化；
  - K 去 RoPE 再全局 RoPE，将位置对齐与上下文修复解耦；
  - 输出 skip connection 保留原始 KV 信息。
- **实验与统计较严谨**：
  - 数据集去污染三重规则；
  - 配对 bootstrap 置信区间；
  - 同时报告质量、TTFT、MACs、内存、并发吞吐；
  - 消融覆盖注意力拓扑、残差路径、归一化、损失函数、输出选择等关键设计。
- **系统测量完整**：给出 H2D 传输、修复执行、RoPE、KV 写入等 TTFT 分量，揭示大模型上缓存传输可能比修复本身更耗时。

## 8. 不足与局限

- **每个目标 LLM 需单独训练**
