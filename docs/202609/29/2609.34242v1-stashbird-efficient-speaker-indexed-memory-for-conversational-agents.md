## 摘要
AI 智能体需要一种记忆，能够在用户-智能体交互、用户间对话以及有或没有智能体参与的群组对话中保存信息，同时支持在证据发生变化或被移除时进行更新。我们提出 Stashbird，一种智能体记忆系统，它通过显式溯源将源情节与派生记忆状态关联起来。Stashbird 将记忆组织为情节记录、语义关系、社区摘要和持久化图状态，并提供用于增量更新和情节级删除的生命周期操作。我们在四个长期记忆基准上评估问答准确率和面向模型的工作负载。在 LoCoMo 上，Stashbird 使用的摄取提示 token 比 Graphiti 少 76.4 倍。在同一基准上，与复现的 Hindsight 相比，它使用的检索提示 token 少 8.1 倍，准确率低 1.6 个百分点。它在 LongMemEval-S 和 GroupMemBench 上取得了比 Hindsight 更高的准确率，并在 EverMemBench 上取得了相当的准确率。

## Abstract
AI agents require memory that preserves information across user-agent exchanges, user-to-user conversations, and group conversations with or without agent participation, while supporting updates as evidence changes or is removed. We present Stashbird, an agent memory system that links source episodes to derived memory state through explicit provenance. Stashbird organizes memory into episodic records, semantic relations, community summaries, and persisted graph state, with lifecycle operations for incremental updates and episode-level deletion. We evaluate question-answering accuracy and model-facing workload across four long-term memory benchmarks. On LoCoMo, Stashbird uses 76.4x fewer ingestion prompt tokens than Graphiti. Compared with reproduced Hindsight on the same benchmark, it uses 8.1x fewer retrieval prompt tokens, with accuracy 1.6 percentage points lower. It achieves higher accuracy than Hindsight on LongMemEval-S and GroupMemBench and comparable accuracy on EverMemBench.

## 1. 核心问题与整体含义

- **研究背景**：AI 智能体越来越多地运行在无法仅靠全上下文提示可靠处理的交互历史上。随着历史增长（尤其是多方共享场景），智能体必须保留事实、偏好、计划和先前决策，同时还要能对修正和变化的证据保持响应。
- **核心问题**：现有记忆系统通常以外部记忆层附加于模型（向量存储+RAG、实体关系图、层次化记忆等），但存在两个关键缺口：
  - 记忆需要随对话证据变化而演化（支持更新与删除）；
  - 需要将源片段（episode）与派生记忆状态通过**显式溯源**关联，并在片段新增或删除时进行协调。
- **整体含义**：论文提出 Stashbird，一种以情节为锚、带溯源、可更新、可删除的智能体记忆系统，旨在在**回答质量与模型调用/Token 成本之间取得更优权衡**，并特别面向用户-智能体、用户间及群组多方对话场景。

## 2. 方法论

### 2.1 核心思想

- 将记忆组织为相互链接的多个视图：**情节记录、语义关系、偏好轨迹、社区摘要、持久化图状态**。
- 与仅存储检索片段或抽取记忆项的系统不同，Stashbird 保留**原始对话证据**并链接到**派生语义状态**，使记忆可被延续、修订、删除和查询。

### 2.2 记忆视图与更新行为（表 1）

| 视图 | 存储单元 | 更新行为 | 用途 |
|---|---|---|---|
| Episodes | 对话分块 | 追加/删除 | 证据召回 |
| Entities | 规范实体 | 合并/失效 | 接地 |
| Relations | 实体关系 | 替换/版本化 | 推理 |
| Preferences | 用户特质 | 覆盖 | 个性化 |
| Communities | 实体聚类 | 重新摘要 | 高层上下文 |

### 2.3 摄取与更新

- 以有序带时间戳的情节序列 $E=\{e_1,\dots,e_T\}$ 摄入，每个情节保存轮次作者、内容、消息时间、摄入时间。
- 为避免重复全历史 LLM 调用：
  - 用 **15K Token 窗口**构建全局摘要；
  - 以 **20K Token 分块、10% 重叠**处理情节；
  - 使用 NER 模型（spaCy）减少遗漏提及；
  - 骨干 LLM 从分块文本、全局摘要和**滚动实体上下文**中抽取实体与关系；
  - 滚动上下文上限 **4K Token**，超限时压缩，仍超限则按支持度移除最少支持的实体。
- **实体协调**：余弦相似度与 Levenshtein 比率**均 > 0.85** 时接受匹配；任一指标 > 0.75 的候选交由骨干模型裁决。阈值跨基准固定。
- **关系协调**：在每对实体内部进行；重复关系扩展溯源，矛盾关系替换旧关系。
- **社区摘要**：启用时用标签传播（label propagation）对实体图聚类，每簇摘要为社区节点并链接成员。
- **增量更新**：持久化检查点存储对话摘要、序列化滚动上下文、最后处理情节、当前实体数；更新时加载检查点、恢复滚动上下文、追加新情节、更新摘要、复用已有实体与关系，新实体分配给已有社区。

### 2.4 删除（Algorithm 1）

- 删除在**情节级**进行。删除请求指定情节 ID，通过溯源 $P(x)$（支持实体/关系 $x$ 的情节集合）识别受影响实体、关系、社区。
- 对每个受影响关系 $r$：$P(r) \leftarrow P(r)\setminus\{d\}$；仍有支持则保留并更新溯源，无支持则从图和索引中移除。
- 对每个受影响实体 $e$：$P(e) \leftarrow P(e)\setminus\{d\}$，并应用 **Entity Meta-forgetting with Neighbor Adoption**：
  - 仍有支持：仅更新溯源；
  - 无支持且无存活邻居：移除；
  - 无支持但有存活邻居：清除情节派生元数据，保留为连接锚点（connective anchor），并移除过期搜索文档。
- 最后移除情节本身，重连其前驱与后继，将受影响社区标记为 dirty 延迟重摘要，并移除过期社区文档。

### 2.5 检索

- 保留原始查询 $q_0$，用骨干生成最多 **4 个聚焦子查询** $Q=\{q_0,\dots,q_k\}$。
- 每个查询变体嵌入，时间表达式相对问题日期解析。
- 进行**对话范围混合搜索**：检索情节、实体、关系文档（启用时含社区文档）。
- 跨查询结果合并去重，使用**倒数排名融合（RRF，k=60）**融合多源证据。
- LLM 相关性打分器对融合候选打分，取 top 候选组成最终证据集。
- 回答生成器将上下文与问题日期传给骨干，指示**仅使用检索证据作答**。

## 6. 主要结论与发现

- **准确率**：
  - **LongMemEval-S**：Stashbird 75.6%（GPT-4o-mini）略高于 Hindsight 74.8%；81.0%（GPT-4.1-mini）比 Hindsight 高 2.7 个百分点。单会话偏好问题上优势最大（74.6%/88.4% vs 53.7%/55.3%），且运行间方差更小。
  - **LoCoMo**：Stashbird 80.4%（GPT-4o-mini）、87.5%（GPT-4.1-mini），优于 Zep、Nemori、Mem0、Graphiti，但低于 Hindsight（85.9%、89.1%）。
  - **EverMemBench**：Stashbird 55.4%，与复现 Hindsight 54.8% 相当；单跳召回、约束意识、画像理解较强，多跳、时间召回、主动性、知识更新较弱。
  - **GroupMemBench**：Stashbird 51.1%，比 Hindsight 24.9% 高 26.2 个百分点；时间推理 72.3% vs 2.2%，用户隐式 60.8% vs 22.8%。
- **效率**：
  - LoCoMo 摄取提示 Token 比 Graphiti 少 **76.4 倍**；检索提示 Token 比 Hindsight 少 **8.1 倍**，准确率仅低 1.6 个百分点。
  - LongMemEval-S：摄取 LLM 调用 29K（Hindsight 137K、Graphiti 1.3M）；摄取提示 Token 164M（Hindsight 700M、Graphiti 3.6B）。
  - 检索时 Stashbird 调用更多 LLM，但提示 Token 显著更少。
- **权衡**：Stashbird 以"更多检索调用换更少提示 Token"，整体呈现明显的质量-成本权衡。
- **稳健性**：Top K 在 10–50 范围内性能稳定（EverMemBench 55.2%–55.5%，LoCoMo 87.0%–87.5%），说明结果不依赖狭窄的 K 选择。
- **骨干敏感性**：LoCoMo 上更强骨干持续提升（87.5% → 89.9% → 92.0%）；EverMemBench 提升较小且非单调，说明其更受检索限制而非骨干限制。

## 7. 优点

- **溯源驱动的设计**：显式关联源情节与派生记忆状态，使记忆可追溯、可协调、可删除，这是许多现有系统未系统处理的。
- **完整的生命周期操作**：不仅支持增量更新，还给出情节级删除算法（Algorithm 1），包括关系/实体溯源更新、Entity Meta-forgetting with Neighbor Adoption、社区 dirty 标记与图重连。
- **多视图记忆结构**：情节、实体、关系、偏好、社区摘要、持久图状态统一在同一对话状态之上，兼顾证据召回与高层推理。
- **检索管线完整**：查询分解 + 混合搜索 + RRF 融合 + LLM 重排，多源证据融合合理。
- **评测严谨性**：统一 harness、同骨干同 judge、5 次重复并报告置信区间、明确区分复现与引用结果。
- **成本意识**：同时报告准确率与 Token/调用量，揭示质量-成本权衡，对实际部署有参考价值。
- **群组场景表现突出**：GroupMemBench 上时间与用户隐式问题大幅领先，验证了保留说话人与时间信息的价值。

## 9. 启示与展望

- **溯源是一等公民**：将情节级溯源显式建模为可查询、可更新、可删除的结构，是让记忆系统具备"遗忘权"与"证据可审计性"的关键，值得被后续系统采纳为标准设计。
- **成本-质量权衡应被显式报告**：本文以调用数/Token 数作为一等评测维度，提示记忆系统评测不应只比准确率，尤其在生产环境中提示 Token 直接决定成本与延迟。
- **群组场景是未被充分覆盖的战场**：GroupMemBench 上 Stashbird 对 Hindsight 的大幅领先（51.1% vs 24.9%，时间推理 72.3% vs 2.2%）说明保留说话人、时间与多方归属信息对群组记忆至关重要，未来基准应进一步扩展多方、跨频道、长周期设置。
- **可继续探索的方向**：
  - 将增量更新与删除纳入标准化评测（如设计"删除后查询不应召回"的对照指标）；
  - 组件级消融以定位社区摘要、偏好视图、查询分解、RRF、重排各自的边际贡献；
  - 自适应阈值与在线校准，替代跨基准固定的 0.85/0.75 协调阈值；
  - 面向多跳与时间推理的证据链显式建模，补齐 EverMemBench 上的短板；
  - 减少检索侧 LLM 调用（如用轻量重排器替代 LLM 打分）以改善延迟。

## 10. 总体评价

Stashbird 是一篇定位清晰的智能体记忆系统工作：其核心贡献不在单一模块的算法创新，而在于**将"情节-派生状态"的显式溯源、完整的生命周期操作（增量更新与情节级删除）与多视图记忆组织整合为一个统一系统**，并在用户-助手、双人、多方群组四类基准上同时报告准确率与模型侧成本。实验在统一 harness 下复现关键基线、多次重复并报告置信区间，方法学较为严谨；群组场景的显著优势与成本效率（LoCoMo 摄取提示 Token 较 Graphiti 少 76.4 倍）构成其最有说服力的证据。主要短板在于**论文最强调的更新与删除能力恰恰未被实证评测**，组件级消融缺失，算力信息不透明，且在 LoCoMo 上仍落后于 Hindsight。总体而言，这是一项在"可演化、可溯源、成本可控的记忆"方向上具有参考价值与工程启发性的工作，但其核心系统能力仍需后续独立评测加以验证。
