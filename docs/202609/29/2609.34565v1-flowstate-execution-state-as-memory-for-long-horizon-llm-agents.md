## 摘要
长时程任务要求 LLM 智能体持续利用早期交互中的信息。然而，保留完整历史会增加上下文成本，而压缩历史则可能丢失后续所需细节，并且历史信息的相关性往往随着任务推进才逐渐显现。为应对这些挑战，我们提出 FlowState，将执行状态视为可在不同请求间保留并重新访问的记忆，从而统一当前决策与历史信息复用。FlowState 保留具有语义类型的状态节点、它们之间的关系以及对原始工具观测的引用，将持久保留与按需访问分离。在单次执行循环内，增量状态更新（ISU）基于新输入和反馈维护当前状态，而渐进式状态访问（PSA）在推理过程中按需逐步揭示历史状态和支持证据。这些机制共同使智能体能够根据新信息重新评估先前决策，并指导后续行动。与使用相同 DeepSeek-V4-Flash 模型的完整上下文基线相比，FlowState 在 MemoryArena 上的平均成功率以及在 $τ^3$-Bench 上的平均通过率分别提高了 4.55 和 13.95 个百分点，同时将总 token 消耗量分别降低了 43.2% 和 40.6%。这些结果证明了 FlowState 在长时程任务上的性能与效率优势。

## Abstract
Long-horizon tasks require LLM agents to continually draw on information from earlier interactions. However, retaining the full history increases context costs, while compressing it risks losing details needed later, and the relevance of historical information often becomes apparent as the task progresses. To address these challenges, we propose FlowState, which treats execution state as memory that can be retained and revisited across requests, unifying current decision-making with the reuse of historical information. FlowState preserves semantically typed state nodes, their relations, and references to raw tool observations, separating persistent retention from on-demand access. Within a single execution loop, Incremental State Update (ISU) maintains the current state based on new inputs and feedback, while Progressive State Access (PSA) progressively reveals historical states and supporting evidence as needed during reasoning. Together, these mechanisms enable agents to reassess prior decisions in light of new information and guide subsequent actions. Compared with a full-context baseline using the same DeepSeek-V4-Flash model, FlowState improves the average success rate on MemoryArena and the average pass rate on $τ^3$-Bench by 4.55 and 13.95 percentage points, respectively, while reducing total token consumption by 43.2% and 40.6%. These results demonstrate the performance and efficiency advantages of FlowState on long-horizon tasks.

## 1. 核心问题与整体含义

- **研究动机**：长时程任务中，LLM 智能体需要持续利用早期交互中的约束、观测、中间结果和决策。但保留完整历史会显著增加上下文成本，甚至让关键证据被淹没；压缩历史又可能丢失后续才变得重要的细节。
- **关键矛盾**：历史信息的重要性往往不是一开始就明确，而是在任务推进、新反馈出现或约束变化后才显现。因此，固定式压缩、固定式检索或全上下文拼接都难以同时保证性能与效率。
- **核心问题**：能否把“执行状态”本身作为统一表示，既服务当前决策，又作为可跨请求保留、重访和复用的长期记忆？
- **整体含义**：FlowState 将执行状态扩展为可持久化、可寻址、可按需披露的记忆单元，通过“持久保留”与“上下文可见性”分离，试图在长时程 LLM 智能体中同时提升任务成功率并降低 token 消耗。

## 2. 方法论

### 2.1 核心思想

- 将用户需求、环境信息、智能体判断和执行产物表示为**语义类型状态节点**，并保留节点间关系及对原始工具观测的引用。
- 完整内容存放在**持久状态仓库**中，模型上下文中只保留轻量索引和当前活动状态。
- 通过两个机制在同一执行循环中协作：
  - **ISU，Incremental State Update**：基于新输入和反馈增量维护当前状态。
  - **PSA，Progressive State Access**：在推理需要时逐步揭示历史状态及其支持证据。

### 2.2 状态组成

- **Persistent State Repository，\(M_k\)**：请求 \(q_k\) 开始时的持久仓库，保存先前请求、状态节点和关系。每个节点记录来源请求、语义标识、类别和完整内容；被新状态引用的原始工具结果也会保留为可访问节点。\(M_k\) 不直接进入模型上下文。
- **Historical State Index，\(G_k = \text{Index}(M_k)\)**：历史状态的轻量索引，按请求分组，仅包含状态标识和简短摘要，放入当前模型上下文。
- **Active State，\(S_{k,t}\)**：第 \(k\) 个请求第 \(t\) 步可用于决策的状态，包含当前请求创建的状态、已披露历史状态及其关系；未披露历史状态的完整内容不进入活动状态。
- **五类状态类型**：
  - 用户侧：preferences，用户偏好、约束和需求。
  - 环境侧：knowledge，工具观测；attributes，从观测中提炼的实体属性。
  - 智能体侧：judgements，目标、计划、决策和风险评估；artifacts，可复用输出、代码或工具产物。

### 2.3 执行循环与公式流程

- 每步模型输入：
  \[
  C_{k,t}=\text{Serialize}(q_k,O_{k,t},G_k,S_{k,t})
  \]
  其中 \(O_{k,t}\) 是上一步工具观测。
- 模型输出三元组：
  \[
  y_{k,t}=(\Delta S_{k,t},R_{k,t},z_{k,t})
  \]
  分别表示候选状态增量、历史状态访问请求、执行决策；三者不能同时为空。
- **ISU 流程**：
  \[
  d\Delta S_{k,t}=\text{Validate}_{upd}(\Delta S_{k,t}|P,S_{k,t})
  \]
  \[
  S^+_{k,t}=\text{Commit}(S_{k,t},d\Delta S_{k,t})
  \]
  ISU 支持 Add、Update、Remove；Update/Remove 只能作用于当前请求创建的状态。模型无需每步重建完整状态。
- **PSA 流程**：
  \[
  \hat R_{k,t}=\text{Validate}_{acc}(R_{k,t}|P,G_k,S_{k,t})
  \]
  \[
  S_{k,t+1}=S^+_{k,t}\cup \text{Disclose}(M_k,S_{k,t},\hat R_{k,t})
  \]
  访问目标必须属于历史索引标识或当前活动状态引用的工具结果：
  \[
  \hat R_{k,t}\subseteq R_{k,t}\cap(\text{IDs}(G_k)\cup\text{ToolRefs}(S_{k,t}))
  \]
  披露关系时只给关系类型和目标标识，不直接展开目标节点完整内容。
- **请求结束持久化**：
  \[
  M_{k+1}=\text{Persist}(M_k,q_k,S_{k,T_k+1},O_k)
  \]
  \[
  G_{k+1}=\text{Index}(M_{k+1})
  \]
- **执行规则**：Add 需使用未占用语义标识；Update/Remove 目标必须存在于当前活动状态且由当前请求创建；引用关系必须解析到有效节点。PSA 披露的信息从下一次模型调用起可用于决策，必要时当前步可设 \(z_{k,t}=\emptyset\) 推迟行动。
