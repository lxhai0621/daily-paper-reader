## 摘要
服务于不同用户的大语言模型（LLM）智能体常常解决相关任务，但彼此分离的用户历史可能导致可复用经验无法被其他智能体获取。汇聚记忆可扩大访问范围，但存在迁移与接收方用户需求相冲突的偏好的风险。我们提出 ShareMem，一种记忆架构，在共享可复用经验的同时，将其应用建立在接收方用户自身偏好之上。共享经验指示如何行动以及应查询哪些偏好；接收方用户的记忆则提供其具体偏好值。两阶段整合先在本地精炼经验，再将接受的编辑整合到共享池中。在执行阶段，范围优先的检索在统一条目预算下联合选择本地与共享经验，而用户绑定的通道支持初始偏好检索和由智能体发起的偏好检索。我们在四种骨干模型上，跨网页导航（Mind2Web）、在线个性化交互（VitaBench 2.0）和多会话编码（MemoryCode）评估 ShareMem。在全部四种模型上，相较于匹配的用户本地记忆，它分别提升了步骤成功率、平均任务成功率和对话宏平均编码分数。消融实验表明，两阶段整合有利于获得更小的共享池、更低的归纳 token 消耗和更好的下游性能，并支持经验指导与主动偏好检索之间的互补性。进一步分析表明，当相关本地经验稀缺时，共享带来的帮助最大；而来源质量和跨用户偏好干扰会限制有效迁移。

## Abstract
Large language model (LLM) agents serving different users often solve related tasks, yet separate user histories can leave reusable experience inaccessible to other agents. Pooling memories expands access but risks transferring preferences that conflict with the receiving user's requirements. We introduce ShareMem, a memory architecture that shares reusable experience while grounding its application in the receiving user's own preferences. Shared experiences indicate how to act and which preferences to consult; the receiving user's memory supplies their concrete values. Two-stage consolidation refines experience locally before integrating accepted edits into a shared pool. During execution, scope-first retrieval jointly selects local and shared experiences under a common entry budget, while a user-bound channel supports initial and agent-initiated preference retrieval. We evaluate ShareMem across web navigation (Mind2Web), online personalized interaction (VitaBench~2.0), and multi-session coding (MemoryCode) with four backbone models. It improves step success, average task success, and dialogue-macro coding scores, respectively, over matched user-local memory across all four models. Ablations favor two-stage consolidation for smaller shared pools, lower induction token usage, and better downstream performance, and support complementarity between experience guidance and active preference retrieval. Further analyses show that sharing helps most when relevant local experience is scarce, while source quality and cross-user preference interference limit useful transfer.

## 1. 核心问题与整体含义

- **研究动机**：多用户 LLM 智能体常面对相似任务，但每个用户的历史记忆彼此隔离，导致“经验可达性瓶颈”：某个智能体已学会的可复用流程，其他用户无法使用。
- **核心矛盾**：直接汇聚所有用户记忆虽能扩大经验访问，却可能把贡献者的个人偏好、命名习惯、具体选择等迁移给接收用户，与其真实需求冲突。
- **中心问题**：智能体如何复用他人的经验，同时仍按“自己用户”的偏好来执行？
- **整体含义**：论文区分“经验的可访问性”与“偏好的适用性”。共享的应是“如何做、应查询哪些偏好维度”的程序性指导；具体偏好值必须由接收用户自己的记忆提供。

## 2. 方法论：ShareMem

- **核心思想**：解耦“可复用经验”和“用户偏好”。共享池提供行动指导，用户本地记忆提供具体偏好值；执行时由当前用户偏好约束经验的应用。
- **记忆结构**：
  - 用户本地记忆 \(M_u\) 包含偏好 \(P_u\) 与按适用范围 \(s\) 组织的经验 \(E_{u,s}\)。
  - 共享记忆 \(S\) 包含跨用户经验集合 \(R_s\)，但不包含其他用户偏好。
  - 环境适配器负责分配 scope 与检索优先级。
- **两阶段经验巩固**：
  1. **本地更新**：对轨迹或会话 \(\tau\)，本地检索器取最多 \(k_w=5\) 个近邻 \(N_{u,s}\)，LLM 更新算子 \(U_{\text{local}}\) 生成更新后本地经验 \(E'_{u,s}\) 与接受的编辑集 \(\Delta_{u,s}\)。编辑可为 add / replace / remove / no-op。
  2. **共享整合**：对每个本地接受的编辑 \(\delta\)，从共享池检索近邻，再由共享更新算子 \(U_{\text{shared}}\) 独立决定如何更新共享池 \(R'_s\)。本地替换或删除不会机械复制到共享池。
- **执行阶段检索**：
  - **Scope-first 经验检索**：按任务构造从直接匹配到更广回退的 scope 组 \(G(x)\)。每组内联合检索本地与共享经验候选，最终用 `ScopeTopK` 在统一预算 \(K=5\) 下重排选择；低优先级组只能填补剩余槽位，不能挤掉高优先级结果。
  - **用户绑定偏好通道**：初始用任务查询从当前用户偏好 \(P_u\) 检索最多 \(k_p=10\) 条；执行中策略 \(\pi_\theta\) 可选择环境动作、偏好检索动作或终止输出。偏好检索返回 \(o_t=R_{\text{pref}}(q_t,P_u;k_p)\)，上下文更新为 \(h_{t+1}=h_t \parallel (a_t,o_t)\)。
  - 经验指导“何时该查偏好”，但当前任务要求与当前用户偏好优先。
- **关键参数**：\(k_w=5\)，\(K=5\)，\(k_p=10\)，候选阶段每集合最多 \(K_c=25\)。

## 6. 主要结论与发现

- **跨用户经验共享总体有效**：
  - Mind2Web 上，ShareMem 相比 LOCAL 提升步骤成功率 2.35–4.10 个百分点，相比 NONE 平均约提升 10.5 个百分点。
  - VitaBench 2.0 上，ShareMem 在四个 backbone 上取得最高 Avg@3，平均比 LOCAL 约高 1.8 个百分点。
  - MemoryCode 上，ShareMem 平均 D-MS 均高于 LOCAL，但 DeepSeek 增益仅 +0.16。
- **共享收益取决于本地经验覆盖**：
  - 本地同站覆盖 0.00% 时，ShareMem 比 LOCAL 高 4.10 个百分点。
  - 覆盖 49.60% 时，增益降至 1.30。
  - 覆盖 98.81% 时，增益为 -0.13，说明本地已有相关经验时共享增量消失。
- **两阶段巩固优于直接写入和 append-only**：
  - 共享池更

- 共享池更紧凑、噪声更低，避免将每次局部编辑都机械同步到全局；append-only 虽保留更多原始经验，但会带来冗余、冲突和检索干扰，直接写入则容易把偶然性、局部性经验过早全局化。
  - 两阶段巩固在 token 成本上也有优势：共享阶段约 77.6 万 token，而直接写入约 443.8 万 token；计入本地归纳后，总归纳 token 约降低 49%。

- **scope-first 检索优于扁平相似度检索**：
  - 按适用范围从直接匹配到更广回退组织候选，可避免“语义相似但适用条件不符”的经验挤占有限预算。
  - 该优势在跨站、跨域或任务边界较明显时更突出；当任务高度同质时，两种检索差距缩小。

- **经验预算存在权衡**：
  - \(K\) 过小会导致可复用经验不足，\(K\) 过大则引入噪声和无关经验。
  - 论文中 \(K=5\) 左右通常是较优折中，说明共享经验并非“越多越好”，而需要在覆盖度与干扰之间平衡。

- **主动偏好检索有效，但依赖经验指导**：
  - 初始召回 + 执行中主动检索通常优于仅初始召回，说明智能体需要根据任务进展动态查询当前用户偏好。
  - 有经验时主动检索收益更明显；无经验时，主动检索可能增加交互成本而收益有限。
  - 这支持论文的核心观点：共享经验应指导“何时、查询哪些偏好维度”，而不是直接提供偏好值。

- **共享收益受本地经验覆盖和来源质量影响**：
  - 本地已有高度相关经验时，共享增量显著下降，甚至可能为负；本地覆盖不足时，共享收益最大。
  - 来源质量方面，gold demonstration 比例越高，共享收益通常越大；比例下降时收益衰减，但并非完全消失，说明共享经验仍有一定可迁移性。
  - 在线准入阈值 \(\tau\) 需要权衡：过低会引入低质经验，过高则更新不足，导致共享池覆盖受限。

- **偏好槽位保留与跨用户偏好隔离**：
  - 相比纯相似度排序，保留偏好槽位有助于减少偏好遗漏和冲突，使执行更贴合当前用户。
  - 跨用户偏好干扰审计中，ShareMem 相比 SHARE-ALL 明显降低偏好泄漏，说明“共享经验、绑定偏好”的设计在机制上更安全。
  - 但该审计依赖 LLM 判断，可能存在漏报；论文也承认 screening misses 未被完全测量，因此不能视为绝对无泄漏。

  - 设计更可靠的偏好泄漏检测，结合规则、模型审计与人工评估。
