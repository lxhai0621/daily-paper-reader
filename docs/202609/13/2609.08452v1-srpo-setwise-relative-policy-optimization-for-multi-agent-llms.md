## 摘要
多智能体大语言模型通过在共享环境中协调多个策略来解决复杂任务。然而，现有的强化学习方法通常分别优化每个响应或轨迹，即使多个输出共同导致一次状态转移。因此，更新单元与系统执行的动作不一致。为了解决这一问题，我们提出 SRPO（Setwise Relative Policy Optimization，集合级相对策略优化），它将活跃集——即一次状态转移所消耗输出的最小集合——视为一个多智能体动作。具体而言，SRPO 将成员对数比率合并为一个按基数归一化的集合比率，分配一个相对优势，并对该集合进行一次裁剪。该公式将分工与联合协同演化统一为具有不同集合大小的动作。在数学推理和多轮搜索上的实验表明，一个训练接口可适用于四种模型规模下的固定、混合和动态路由工作流，并在所报告的比较中取得了最强的宏平均结果。优化诊断进一步刻画了其在不同事件归约和集合大小下的稳定性。

## Abstract
Multi-agent large language models solve complex tasks by coordinating several policies in a shared environment. However, existing reinforcement learning methods usually optimize each response or trajectory separately, even when several outputs jointly cause one state transition. Consequently, the update unit differs from the action executed by the system. To address this problem, we propose SRPO (Setwise Relative Policy Optimization), which treats the active set the minimal set of outputs consumed by one transition, as one multi-agent action. Specifically, SRPO combines member log-ratios into one cardinality-normalized set ratio, assigns one relative advantage, and clips the set once. This formulation unifies division of labor and joint co-evolution as actions with different set sizes. Experiments on mathematical reasoning and multi-turn search demonstrate one training interface for fixed, mixed, and dynamically routed workflows across four model scales, with the strongest macro-average results among the reported comparisons. Optimization diagnostics further characterize its stability under different event reductions and set sizes.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：大语言模型（LLM）正被广泛部署为能够推理、检索、调用工具并修正答案的智能体；多智能体系统（MAS）通过两种反复出现的协作范式扩展这些能力——**分工（division of labor）**（将任务拆给专门角色）与**联合协同演化（joint co-evolution）**（多个提案在交互中共同进化）。
- **核心矛盾**：现有 MAS 强化学习方法通常以“某条响应”“某条轨迹”“某个角色/轮次/分组”为更新单元，但系统真正让环境发生状态转移的动作，往往是**若干个输出被共同消耗**。于是**优化器的更新单元 ≠ 系统实际执行的动作**。
- **后果**：智能体身份、执行顺序或 rollout 布局决定了优化器把什么当作动作，而非团队真正产生的状态转移。同一个环境决策，在贡献智能体数量或顺序变化时会收到不同的更新，导致**分工与协同无法共享同一套优化规则**，混合/动态路由系统还需额外规则。
- **中心挑战**：定义一个**与智能体顺序、角色、编排布局无关**的 MAS 动作。
- **整体含义**：作者提出 **SRPO（Setwise Relative Policy Optimization）**，把“一次状态转移所消耗输出的最小集合”（活跃集）作为一个多智能体动作来优化，从而在同一个策略优化框架内统一分工、联合协同演化及二者的混合形态，同时保持 rollout 生成、奖励设计、优势估计与优化器不变。

## 2. 方法论

### 2.1 核心思想：活跃集即动作

- **系统组成**：N 个 worker 策略 {π_θi}、一个 router μ_φ、一个 aggregator α_ψ；在决策事件 e 上，系统处于共享的 pre-action 状态 s_e。
- **定义 1（活跃集）**：活跃集 S_e 是环境**共同消耗以产生下一状态**的、新采样输出的最小集合；对应的集合值动作 a_e = {a_{e,j} : j ∈ S_e}。
- **关键判定规则**：
  - 环境状态既包含外部任务状态，也包含共享编排记忆；被提交进共享记忆的提案即构成状态转移，即使外部工具状态未变。
  - 未被提交/未被消耗的私有草稿不算动作。
  - 若只有 aggregator 输出被提交，则活跃集是 aggregator 的**单元素输出**，而非其私有输入。
  - 同一事件内所有观测来自同一逻辑 pre-action 状态；若一个输出先于另一个策略被揭示，则二者属于**相继事件**。
- **事件动作的可训练概率**按成员分解：
  π_Θ(a_e | s_e) = Π_{j∈S_e} q_{e,j}(a_{e,j} | o_{e,j})，其中 q_{e,j} ∈ {μ_φ, π_θ1…π_θN, α_ψ}。

### 2.2 两种协作范式的统一

- 仅由活跃集基数区分：K_e = |S_e| = 1 为**分工**，K_e > 1 为**联合协同演化**。
- router 与最终 aggregator 产生单元素事件；混合工作流只是 K_e 随时间变化。
- 因此**分工不是独立的优化问题，而是同一集合值策略的单元素边界情形**。

### 2.3 为什么活跃集是自然的近端单元（proximal unit）

- 若对每个成员响应独立裁剪：一次依赖多个输出的转移会收到多个互不相关的约束。
- 若直接相乘成员比率而不归一化：更大的活跃集会成为按比例更大的似然事件，更新尺度随 K_e 增长。
- 因此 SRPO 用 **1/√K_e 归一化求和后的对数比**，并对事件做**一次**裁剪，使优化单元与环境转移对齐，同时允许基数逐事件变化。

### 2.4 集合级策略比率

- **掩码序列对数比**（逐成员）：ℓ_{e,j} = Σ_u m_{e,j,u} · log[ q^cur_{e,j}(a_{e,j,u}|o_{e,j,u}) / q^old_{e,j}(a_{e,j,u}|o_{e,j,u}) ]，其中 m ∈ {0,1} 排除 prompt、padding 与环境 token。
- **集合对数比与集合比率**：
  L^set_e = (1/√K_e) Σ_{j∈S_e} ℓ_{e,j}，ρ^SRPO_e = exp(L^set_e)。
  - K_e = 1 时退化为普通序列级似然比；K_e > 1 时为**基数归一化代理**，在裁剪前抑制联合对数比的增长。
- **尺度分解（协方差）**：若各成员对数比方差为 σ²_e，则
  Var(L^set_e) = σ²_e + (2/K_e) Σ_{i<j} Cov(ℓ_{e,i}, ℓ_{e,j})。
  即**独立成员的尺度被精确保持**，相关成员通过第二项显式贡献；SRPO 不要求该项消失。

### 2.5 一个事件，一个优势

- 每个决策事件分配**一个**优势；在 group-relative 实现中，可比事件共享分组 g(e)：
  Â_e = (R_e − μ_{g(e)}) / (σ_{g(e)} + ε)，R_e 为下游团队回报，ε 防止除零。
- **同一标量 Â_e 赋给该事件的全部成员**；critic、GAE 或其他与动作无关的基线均可替换该估计器而不改变集合比率。

### 2.6 集合级裁剪与事件归约

- 目标函数：
  J_SRPO(Θ) = (1/|B|) Σ_{e∈B} min[ ρ_e·Â_e, clip(ρ_e, 1−ϵ, 1+ϵ)·Â_e ]。
- **对完整活跃集裁剪一次**，并在**事件层面**（而非 token 行或成员行）求平均，确保每次环境转移只贡献一次。
- 算法四步：识别完整事件 → 计算成员对数比 → 归约为一个集合比率 → 用事件优势裁剪一次。

### 2.7 实现要点（事件原子批处理）

- 每条采样响应存储：事件标识、pre-action 状态标识、成员索引、期望基数、策略版本、行为对数概率。
- **同一事件的所有行必须留在同一全局 mini-batch**；**缺失成员直接作废该事件**（而非静默改变其动作）；被选中但 aggregator 未引用的输出仍属于该动作。
- 这是相对标准 rollout/优化机制唯一新增的系统要求。算法 1 给出了完整训练循环：构造事件 → 归约成员对数比 → 单次裁剪。
