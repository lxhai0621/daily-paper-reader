## 摘要
语言模型智能体日益依赖技能：用于推理、工具使用和交互的可复用程序性知识。现有工作研究了技能如何被获取、检索、压缩或组合，但往往假设一旦选定某个技能，其与智能体的接口就是固定的。我们认为，这忽略了技能效用的一大关键来源：同一技能可能因呈现方式不同而提供帮助、造成干扰或产生误导。我们提出 SkillAlign，一个与提供方无关的框架，将候选技能表示为多视图程序性卡片，并通过不同的暴露接口进行呈现，包括完整指令、提示、压缩摘要、工作流或不暴露。这支持反事实评估，其中任务、智能体和候选技能保持不变，只有暴露接口发生变化。在 ALFWorld 和 SkillsBench 上，我们表明暴露形式会显著影响任务成功率和渲染上下文成本，并且紧凑的 top-k 暴露可以优于全库注入。我们进一步在 ALFWorld 上进行了基于回放的政策学习分析，表明自适应暴露包含可学习信号，但仍远未达到 oracle 选择。我们的结果表明，技能增强型智能体不仅应优化使用哪些技能，还应优化这些技能如何呈现。

## Abstract
Language-model agents increasingly rely on skills: reusable procedural knowledge for reasoning, tool use, and interaction. Existing work studies how skills are acquired, retrieved, compressed, or composed, but often assumes that once a skill is selected, its interface to the agent is fixed. We argue that this overlooks a key source of skill utility: the same skill can help, distract, or mislead depending on how it is exposed. We propose SkillAlign, a provider-agnostic framework that represents candidate skills as multi-view procedural cards and renders them through alternative exposure interfaces, including full instructions, hints, compressed summaries, workflows, or no exposure. This enables counterfactual evaluation where the task, agent, and candidate skills are fixed while only the exposure interface varies. Across ALFWorld and SkillsBench, we show that exposure form substantially affects task success and rendered context cost, and that compact top-k exposure can outperform full-library injection. We further conduct a replay-based policy-learning analysis on ALFWorld, showing that adaptive exposure contains learnable signal but remains far from oracle selection. Our results suggest that skill-augmented agents should optimize not only which skills to use, but also how those skills are presented.

## 1. 核心问题与整体含义

- **研究背景**：LLM 智能体日益依赖"技能"（skills），即用于推理、工具调用与交互的可复用程序性知识。已有工作覆盖技能的获取、表示、检索、压缩、组合与演化等全生命周期，但普遍隐含一个假设——**技能一旦被选中，其呈现给智能体的接口就是固定的**。
- **被忽视的关键维度**：论文指出，同一个技能可能因暴露方式不同而产生帮助、干扰或误导三种截然不同的效果。技能并非"相关就有用"：它可能过长、过泛、过专、过时、与当前环境脱节或层级过高；反之，一份作为完整文档失败了的技能，也可能作为一句简短提示、一份紧凑的"可供性—风险"摘要或一个工作流模板而发挥作用。
- **核心论点**：技能应被视为**外部化的程序性先验（externalized procedural priors）**，其效用不仅取决于内容，还取决于它用来条件化智能体的**接口**。因此真正的问题不只是"该选哪个技能"，更是"选中的技能该如何暴露"。
- **整体含义**：论文把"技能接口对齐"（skill-interface alignment）确立为技能增强型智能体的一个缺失问题，主张未来的技能系统需同时优化**技能选择**与**技能呈现**两个环节。

## 2. 方法论

### 2.1 核心思想

- 提出 **SkillAlign**，一个**与技能提供方无关（provider-agnostic）**的暴露层，将"技能选择"与"技能暴露"解耦：上游提供方决定哪些技能可用，SkillAlign 决定这些技能如何条件化智能体。
- 输入为任务上下文 `x`、智能体上下文 `a`、候选技能集 `Sx = {s1, ..., sk}`；输出为经渲染的技能上下文 `r`，注入智能体常规交互循环。注意：渲染**不修改原始技能工件**，只是推理时的接口形式。

### 2.2 关键公式与流程

- **暴露接口决策**：`m = π(x, a, Sx)`，其中 `m ∈ M`。
- **渲染**：`r = Render(Sx, m; x, a)`。
- **接口集合**（主实验）：`M = {none, full, hint, compressed, workflow}`
  - `full`：原始技能文档，保留脚本、参数、假设、示例、API 等执行关键细节；
  - `hint`：一句简短、面向任务的动作提示，作为弱激活信号；
  - `compressed`：紧凑的"触发条件—输入/状态—核心动作—期望输出—风险"操作规范；
  - `workflow`：有序步骤，含校验点与停止条件；
  - `none`：抑制技能文本（当候选技能无关、误导或成本过高时）。
- **多视图技能卡片**：`c(s) = {v_full, v_hint, v_comp, v_flow, η}`，其中 `η` 为元数据（技能 id、来源、路径、面向检索的摘要）。各视图**在语义角色上不同，而非仅长度不同**。卡片字段包括 `routing_summary`（用/不用边界）、`short_hint`、`compressed`、`workflow`、`raw_text` 等。

### 2.3 反事实评估协议

- **固定暴露模式**：`π_m(x, a, Sx) = m`，对同一任务与候选技能集运行多种接口，得到轨迹集合 `{τ^m_x : m ∈ M}`。
- 由于任务、智能体后端、候选技能均被固定，仅接口变化，因此性能差异可直接归因于暴露形式，而非格式装饰。
- **负迁移（negative transfer）判定**：若无暴露运行成功而某接口 `m` 失败，或标量奖励下降，则记为接口 `m` 的负迁移案例。

### 2.4 探索性暴露策略学习（非框架必需组件）

- **效用函数**：`U_x(m) = R_x(m) − αC_x(m) − βT_x(m)`，其中 `R` 为奖励/成功，`C` 为归一化上下文成本，`T` 为归一化轨迹长度。
- **SFT 标签**：`m*_x = arg max_{m∈M} U_x(m)`；效用差距足够的接口对构成 **DPO 偏好样本**。
- 策略输入任务描述、候选技能卡片内容与来源元数据，输出单一接口标签；在 **Qwen3-4B** 上训练轻量 **LoRA** 适配器。
- 明确声明该组件刻意保持轻量，仅用于验证自适应暴露的**可行性**，并以 oracle 暴露量化剩余提升空间。

## 3. 实验设计

### 3.1 数据集与 Benchmark

- **ALFWorld**：文本化具身环境，多步家庭任务；采用 ReAct 式文本设定，**140 个评估回合**，最多 30 步。
- **SkillsBench**：真实技术任务配人工整理技能，覆盖数据分析、科学计算、金融建模、工程工作流等；**94 个任务实例**，使用 Harbor 与 Terminus-2 容器化执行框架。
- **ScienceWorld**：作为**辅助数据**，用于生成暴露策略学习的反事实监督数据（另有早期 TextWorld 运行）。

### 3.2 技能库与候选来源

- 技能库记为 `skills_N`（N 为可用技能数，非评估任务数）：主实验 `skills_1000`；规模分析另用 `skills_200 / 500 / 1000 / 2000`。
- **候选来源**：
  - `none`（无技能上下文，无暴露对照）；
  - `all`（全库可用，不做任务过滤）；
  - `vector-top-k`（text-embedding-3-large 语义检索，ALFWorld k=5，SkillsBench k=8）；
  - `graph-top-k`（Graph-of-Skills，结构化图检索，仅用于验证暴露效应是否在结构化选择下持续存在）。

### 3.3 对比对象与指标

- **后端**：`minimax-m2.7`、`gpt-5.3-codex`、`glm-5`（API 访问）。
- **指标**：ALFWorld 报告成功率（SR），SkillsBench 报告平均奖励（AR），外加渲染技能上下文成本 `C`（千 token 计）。
- **对照维度**：同一候选来源下横向比较 5 种暴露接口；跨 3 个后端、2 个 benchmark、4 种候选来源。
- **额外对照实验**：
  - 与 **Generic Summary（长度匹配的通用自由摘要）** 对比，以区分"暴露结构"与"单纯缩短上下文"；
  - 学习策略 vs 最佳固定接口 vs oracle 暴露（回放评估）；
  - 生成视图的**人工保真度审计**（2 名独立标注者，60 个随机任务共 180 个任务—技能—视图实例）。

## 4. 资源与算力

## 5. 实验数量与充分性

- **实验规模大致如下**：
  - 主表：3 后端 × 2 benchmark × 4 候选来源 × 5 接口（`none` 单列），构成约 100+ 个性能—成本观测点；
  - 结构化提供方（Graph-top-k）分析：3 后端 × 2 benchmark × 4 接口；
  - 技能库规模分析：4 个规模（200/500/1000/2000）× 5 接口（ALFWorld + MiniMax M2.7）；
  - 通用长度匹配摘要对照：12 个 benchmark–provider–backend 组合；
  - 暴露策略学习：SFT 与 DPO 两种策略 × 2 种候选来源，含 oracle 上界；
  - 保真度审计：180 个实例、2 名标注者；
  - 全部性能结果均给出 **10,000 次任务级 bootstrap 重采样的 95% 置信区间**。
- **充分性与公平性评价**：
  - **优点**：反事实设计严格控制变量（任务、后端、候选技能固定，仅变接口），因果解释力较强；覆盖 2 个性质差异较大的 benchmark、3 个后端、4 种候选来源、4 种技能库规模，交叉验证较全面；引入长度匹配摘要对照，排除"只是变短"这一混淆解释。
  - **需谨慎之处**：作者自己指出，数值接近的结果其置信区间常大幅重叠，因此不应过度解读细微排名差异；SkillsBench 成本项在全库设置下反映的是后端截断/拒答前的渲染规模，成本口径存在一定理想化；策略评估为**离策略回放（off-policy replay）**，非真实在线交互。

## 6. 主要结论与发现

1. **暴露形式是一等条件变量**：在同一 `all` 候选来源下，ALFWorld 成功率随接口从 47.9 变到 72.1（MiniMax）、从 70.7 变到 82.1（GLM）；`vector-top-k` 下也出现 64.3–75.0（ALFWorld/MiniMax）与 28.9–32.2（SkillsBench/GPT-Codex）的差异。
2. **候选质量与暴露形式互补**：`all + compressed` 优于 `all + full`，但仍需聚合 1000 个技能的信息；`vector-top-k` 先大幅缩小候选集再暴露，效果更佳——检索降低无关技能质量，SkillAlign 控制剩余先验的呈现方式。
3. **紧凑暴露常常更高效**：`hint` 与 `compressed` 在多个列中取得最佳或接近最佳的奖励，同时成本低于 1K token 量级；`compressed` 在技术性更强的 SkillsBench 上可胜过 `hint`，因为其保留触发条件、状态假设、动作、输出与风险。
4. **全库 + Full 作为诊断性压力条件**：表现常差于紧凑替代方案，但作者不将其归因于单一机制（可能混合后端截断/拒答、注意力稀释、无关先验、多技能指令冲突），需专门控制实验才能厘清。
5. **结构化提供方下效应依旧存在**：`Graph-top-k + Compressed` 普遍更强，`Graph-top-k + Full` 更贵且并非稳定更优，说明更好的候选选择**不能消除**暴露问题。
6. **规模增大使暴露问题更突出**：小库时 Full 尚有竞争力；库增大后 Full 急剧退化（`skills_1000` 降至 47.9），而 `compressed` 保持稳定（72.1）；`skills_2000` 时噪声与成本进一步上升。
7. **自适应暴露存在可学习信号但远未解决**：回放评估中，最佳固定接口为 75.0（vector）/71.4（graph），SFT 提升至 76.4/73.6，DPO 进一步提升至 78.6/76.4，而 oracle 暴露为 92.9/85.7，差距仍大；标签分布显示 oracle 标签多样，说明**不存在普遍最优的单一暴露形式**。
8. **保真度可控但未完全消除**：Hint/Compressed/Workflow 的任务相关遗漏率分别为 3.3%/5.0%/6.7%，扭曲、矛盾与误导性添加同样罕见；安全敏感场景可加保真校验并回退到 Full。
9. **缩短只能解释部分收益**：在 12 个 benchmark–provider–backend 设置中，`compressed` 通常优于长度匹配的通用摘要，说明**结构**而非仅仅长度带来增益，但 Full 在部分设置中仍具竞争力。

## 7. 优点

- **问题识别新颖且切中要害**：把"技能如何暴露"从隐性工程细节提升为可研究的一等设计变量，视角清晰且与检索/压缩/组合等既有工作形成互补而非竞争。
- **反事实实验设计严谨**：固定任务、后端与候选技能，仅改变暴露接口，配合负迁移判定，使接口效应可被直接测量。
- **提供方无关的抽象**：SkillAlign 作为独立暴露层，不绑定具体 benchmark runner 或检索系统，仅在 `none / all / vector-top-k / graph-top-k` 多种来源下验证，泛化性论证较强。
- **多视图卡片设计有语义依据**：各视图对应不同认知角色（弱激活、可供性—风险、顺序编排、完整执行契约），而非单纯截断长度。
- **对照控制细致**：加入长度匹配的通用摘要基线、人工保真度审计、bootstrap 置信区间，主动排除"只是变短""生成视图失真"等替代解释。
- **成本—性能视角务实**：同时报告成功率与渲染上下文成本，并给出成本—性能权衡图，贴近真实部署关切。
- **对自身局限坦诚**：明确把策略学习定位为可行性探针，用 oracle 上界量化剩余空间，并指出未来方向。

## 8. 不足与局限

- **接口空间有限且手工设计**：仅 5 种固定接口，未覆盖更丰富的技能表示设计空间；作者建议未来学习更丰富的接口或直接生成任务自适应视图。
- **策略学习过于初步**：SFT/DPO 仅作为可行性验证，与 oracle 差距悬殊；未使用在线强化学习（会引入探索混淆），标签分布也显示学习策略存在偏置。
- **评估为离策略回放**：ALFWorld 上的策略评估通过查表匹配固定接口轨迹，而非重新在线运行，可能高估/偏离真实在线表现。
- **与检索互补而非替代**：候选技能质量仍决定上限，差的检索会限制

- **与检索互补而非替代**：候选技能质量仍决定上限，差的检索会限制 SkillAlign 的收益空间；论文并未主张暴露层可以替代选择层，而是强调两者需协同优化，因此"暴露对齐"的增益是在给定候选集内的条件性增益，而非对检索缺陷的补救。
- **后端与场景覆盖仍偏窄**：主实验仅使用 3 个商用 API 后端（minimax-m2.7、gpt-5.3-codex、glm-5），未覆盖开源权重模型、本地部署模型或不同规模/指令微调程度的模型；benchmark 集中于文本化具身（ALFWorld）与技术任务（SkillsBench），ScienceWorld 仅作辅助，缺少多模态、长程规划、多智能体协作等场景的验证，故结论的普适性有待扩展。
- **技能库构造与真实性存疑**：`skills_200/500/1000/2000` 的构造方式、技能来源与去重/时效处理未充分刻画，技能库的"自然分布"可能与真实生产环境不同；规模分析中的退化趋势也可能部分由库构造偏差而非纯粹规模效应导致。
- **效用函数与权重缺乏敏感性分析**：`U_x(m) = R_x(m) − αC_x(m) − βT_x(m)` 中的 α、β 如何取值、是否做过网格搜索或敏感性实验，论文未充分展开；线性加权假设也较简化，未考虑奖励与成本的非线性权衡或风险约束。
- **负迁移判定较为粗略**：仅以"无暴露成功而某接口失败"或标量奖励下降作为负迁移判据，属二值/阈值式定义，未区分失败的严重程度、可恢复性或对下游步骤的级联影响，可能掩盖部分细粒度的接口危害。
- **保真度审计的规模有限**：180 个实例、2 名标注者虽提供了初步证据，但样本量与标注者数量偏小，且未报告标注者间一致性指标（如 Cohen's κ），生成视图在更大规模或不同生成模型下的稳定性仍属未知。
- **接口空间与渲染器未解耦**：5 种接口的生成方式（尤其 compressed/workflow）依赖特定提示与生成模型，论文未系统报告渲染器模型更换或提示扰动对结果的影响，接口效应的可复现性部分依赖于实现细节。

## 9. 潜在影响与未来方向

- **对技能增强型智能体设计的启示**：技能系统不应只优化"检索—选择"流水线，还需引入独立的**暴露/接口层**；把技能当作可外部化、可多视图渲染的程序性先验，有助于统一技能获取、压缩、组合与演化等既有工作。
- **对评测范式的启示**：反事实暴露协议（固定任务、后端、候选集，仅变接口）提供了一种可迁移的评测思路，可用于评估工具调用格式、记忆注入方式、系统提示结构等其他"条件化接口"。
- **可能的工程落地方向**：
  - 将 SkillAlign 作为中间件接入现有智能体框架，配合保真度校验与"回退到 Full"的安全机制；
  - 与结构化检索（如 Graph-of-Skills）联合优化，形成"选择 + 暴露"的端到端技能供给链；
  - 面向成本敏感场景，优先采用 `hint`/`compressed` 以降低渲染 token 开销。
- **值得推进的研究问题**：
  - 学习**更丰富的接口空间**，甚至直接生成任务自适应视图，而非从固定集合中选择；
  - 用**在线强化学习**替代离策略回放，检验自适应暴露在真实交互中的收益；
  - 刻画**暴露形式与后端能力**的交互（如上下文窗口、指令遵循强度、截断策略）对最优接口的影响；
  - 建立**保真度—效用**的联合优化目标，兼顾安全敏感场景的可靠性。

## 10. 总体评价

- **定位**：这是一篇问题导向、设计克制、证据较扎实的工作。其最大价值不在于提出一个复杂的模型，而在于**识别并形式化了一个此前被隐性处理的维度**——技能接口对齐，并用反事实协议给出了可测量的初步证据。
- **贡献强度**：
  - **概念贡献 > 方法贡献 > 性能贡献**。SkillAlign 的抽象（provider-agnostic 暴露层、多视图卡片、反事实评估）具有较好的可迁移性；但其性能提升更多是"揭示了固定接口的次优性"，而非给出一个已解决问题的方案。
  - 自适应策略学习目前是**可行性探针**而非实用组件，oracle 与学习策略之间的巨大差距表明该方向仍处早期。
- **可信度**：反事实控制、长度匹配摘要对照、bootstrap 置信区间与人工保真度审计，使主要结论（"暴露形式显著影响性能、紧凑结构化视图常更优、规模增大使问题更突出"）具备较强的说服力；但涉及具体排名与数值差距的结论需结合置信区间重叠谨慎解读。
- **局限的诚实度**：作者主动标注了离策略评估、接口空间有限、成本口径理想化等问题，并给出 oracle 上界以量化剩余空间，学术诚实度较高。
- **一句话结论**：SkillAlign 把"技能如何被呈现"从工程细节提升为一等研究问题，证明**同一技能的不同暴露接口可导致显著不同的智能体表现**，并展示了自适应暴露的可学习信号，但如何学得更好、如何在线验证、如何与检索/后端协同，仍是开放问题。
