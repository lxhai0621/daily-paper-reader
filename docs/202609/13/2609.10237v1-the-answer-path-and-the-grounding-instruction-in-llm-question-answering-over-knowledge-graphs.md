## 摘要
图检索增强生成流水线选择将哪些三元组放入提示中、用什么语法书写它们、按什么顺序书写它们，以及用一句话告诉模型如何处理它们。我们在六个大语言模型和两个知识图谱问答基准上变化这四个方面。四个选择中有两个会改变答案，另外两个则没有影响。第一个是答案路径——即到达答案所需的三元组——是否根本出现在提示中。在固定三元组数量的情况下，将每一个不在该链上的三元组替换为来自无关实体的材料，会使答案准确率变化 +0.003 F1，而移除该链则会损失图所带来的大部分价值。检索预算应放在召回率上，而在我们可测试的范围内，精确率毫无收益。这里没有检索器：子图来自金标准 SPARQL，因此精确率描述的是我们构建的上下文，而不是系统设置。第二个是接地指令。当提示中没有事实时，告诉模型仅使用所提供的事实来回答，会使 F1 从 0.299 降到 0.035，相差 8.63 倍。该数字描述的是带空上下文分支的评估，而不是一个可工作的流水线；而且一个实验若将指令应用于其上下文分支，却不应用于其无上下文基线，就会制造出一个虚假发现，即图上下文在深层会损害性能。我们在自己的结果中发现了这样一个虚假发现，并将其撤回。语法、三元组顺序和子图大小在多跳深度下没有产生我们能测量到的效应。若要衡量接地指令相对于正确上下文的代价，这种比较无法用对格式敏感的评分器测量，因为该指令决定了响应格式；我们将其报告为一个开放对比，而不是一个数值。

## Abstract
A graph retrieval-augmented generation pipeline chooses which triples to put in the prompt, a syntax to write them in, an order to write them in, and a sentence telling the model what to do with them. We vary all four over six large language models and two knowledge-graph question answering benchmarks. Two of the four choices move the answer and the other two are flat. The first is whether the answer path, the triples needed to reach the answer, is in the prompt at all. Holding the number of triples fixed and replacing every triple that is not on the chain with material from an unrelated entity changes answer accuracy by +0.003 F1, while removing the chain costs most of what the graph was worth. Retrieval budget belongs on recall, and precision in the range we can test buys nothing. There is no retriever here: subgraphs come from gold SPARQL, so precision describes the context we build, not a system setting. The second is the grounding instruction. With no facts in the prompt, telling a model to answer using only the provided facts drops F1 from 0.299 to 0.035, a factor of 8.63. That figure describes an evaluation with an empty context arm rather than a working pipeline, and an experiment that applies the instruction to its context arm but not to its no-context baseline manufactures a spurious finding that graph context hurts at depth. We found one in our own results and retract it. Syntax, triple order and subgraph size produce no effect we can measure at multi-hop depth. The comparison that would price the grounding instruction against correct context is not measurable with a format-sensitive scorer, because the instruction determines the response format; we report it as an open contrast rather than a number.

# 论文结构化总结：LLM 知识图谱问答中的答案路径与接地指令

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：图检索增强生成（GraphRAG）流水线从知识库检索子图、序列化为文本、放入 LLM 上下文。该流水线实际上隐含四个设计决策：
  1. 把哪些三元组放进提示；
  2. 用什么语法书写（序列化格式）；
  3. 按什么顺序书写；
  4. 系统提示告诉模型"如何使用"这些事实（接地指令 / grounding instruction）。
- **核心问题**：在这四个决策中，哪些真正改变答案质量、值得工程投入，哪些是可测量的"零效应"？文献中"检索质量"常被笼统对待，而 prompt 措辞、序列化格式、子图规模等因素的效果相互纠缠。
- **整体含义**：
  - 只有**首（是否包含答案路径）**与**尾（接地指令）**两个决策有影响，中间两个（语法、顺序）在可测范围内无影响。
  - 检索预算应投向**召回**而非精度：在固定三元组数量下，把非链三元组全部替换为无关实体材料，F1 仅变 +0.003。
  - 论文同时是一篇**方法学批判**：作者发现自己的一个"图上下文在深层有害"的结论源于上下文分支与无上下文基线使用不同 prompt（指令 + 响应格式同时改变），因此**主动撤回**该发现。
  - 论文还指出：**错误子图不会被模型识别**，知识库写入路径构成一种"具有 prompt injection 触达范围、却无其可见特征"的攻击面。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：用一个**无检索器**的受控实验台，把 GraphRAG 的四个选择正交化，逐项变化、其余固定，用同一语料、同一批模型、同一评分器对比。
- **子图构造**：
  - 每个问题用 **gold SPARQL** 抽取 oracle 子图，固定 50 条三元组 = **答案链（chain triples，答案路径）** + **干扰三元组（distractor triples，问题实体邻域中的真实 Wikidata 事实）**。
  - 使用真实事实而非合成噪声，以近似"合理的检索器输出"。
- **四个自变量**：
  1. **检索精度**：固定 50 条、始终保留答案链，将 0/25/50/100% 的干扰槽位替换为另一问题的子图材料，使上下文精度从 1.00 降到约 0.51（保持体积不变，只改来源）。
  2. **序列化格式（7 种）**：prose、tabular（管道分隔表）、Turtle、N-Triples、Cypher、JSON-LD、RDF/XML。其中 5 种输出人类可读谓词名，JSON-LD 与 RDF/XML 只输出 P-number。
  3. **三元组顺序（5 种）**：按主语分组（entity-centric）、路径优先（path-centric）、从问题实体做 BFS、带种子随机打乱、字母序。注意 Turtle/JSON-LD/RDF/XML 会按主语重排，prose 最能保留指定顺序。
  4. **Prompt 机制**：
     - **Strict**："仅使用所提供事实回答"，并要求固定响应格式（`Answer:` 行 + `Evidence:` 三元组引用列表）。
     - **Permissive**：允许结合自身知识，不限定格式。
     - **无上下文条件**：把 facts 块替换为 "No facts are available"，其余 prompt 相同（**matched prompt**）。
- **Prompt 不对称与"接地抑制"的度量**：strict 与 permissive 在无事实条件下的 F1 差即参数化知识被抑制的幅度。
- **错误上下文实验**：把某问题的正确子图整体替换为另一问题的子图（确定性偏移），分别在 strict / permissive 下测试。
- **评价：双轴评估**：
  - **Answer F1**：token 级匹配（小写化、去冠词、日期归一、别名表解析），多答案用最优二分匹配（顺序无关），0–1 分。
  - **Evidence faithfulness**：被引用三元组与所给子图匹配的比例，支持 6 种引用形式（箭头、破折号箭头、冒号、括号、逗号分隔、自然语言）并做模糊匹配。该轴可区分"正确答案 + 伪造证据"（参数化回忆 + 编造引用）与"错误答案 + 有效证据"。
- **统计方法**：95% bootstrap 区间（对问题重采样）；小样本用 **exact sign-flip permutation test**（作者认为 percentile bootstrap 在小样本下偏乐观）；报告中给出 permutation p 值。
- **模型与解码**：6 个模型、3 家厂商、2 个能力层级，统一 API 网关，**temperature = 0**（另做 temperature = 0.7、每 trial 5 采样的验证）。
- **补充杠杆实验**：evidence-first 提示、chain-of-thought 提示、dynamic oracle per-hop 分解、子图规模（chain-only / 25 / 50 / 200 条）、采样验证。

  - hop 分布：1-hop 46、2-hop 36、3-hop 29、4-hop 12、5–6 hop 2（后 2 题只进聚合结果）。

## 6. 主要结论与发现

- **结论 1：精度不是杠杆，召回是。** 链保留、prompt 固定 50 条时，把上下文精度从 1.00 降到 0.51，F1 变化 +0.003（95% CI [−0.019, +0.031]，p = 0.812）；各深度（+0.030 / −0.021 / −0.007 / −0.001）与"无辅助时 F1=0"的 48 题子集（+0.015）同样为零。移除答案链则大幅损失：permissive 下 0.231，strict 下 0.005。**证据忠实度**是唯一随精度下降的指标（0.914 → 0.888）。
- **结论 2：接地指令抑制参数化召回，但该数字描述的是"空上下文评测"。** 无事实时 strict prompt F1 = 0.035 vs permissive 0.299，差 0.264、**8.63 倍**，是全文最大效应；改写模板得 0.019，抑制依然存在。该结果刻画的是评测设置，而非可工作的
