## 摘要
当前最先进的检索增强生成（RAG）方法利用文档结构来获取充分证据，但往往会产生可观的token开销。为了在不损害高RAG准确率的情况下减少结构上下文token，我们提出VikingRAG，一个目录感知的语义数据管理系统，它紧密集成语义访问与结构访问，以支持结构上下文高效、证据缺口驱动的多轮检索。为了进一步降低多轮交互的token开销，我们将智能体式多轮检索轨迹物化为经验边，并为相似查询复用这些边，从而避免重复的多轮探索。为了额外降低在不需要智能体式多轮检索时的token成本，我们引入一种自适应升级策略：当证据充分时，基于一轮经验增强检索来回答；仅在其他情况下才调用智能体式多轮检索。在真实数据集上的实验表明，基础系统VikingRAG在仅消耗当前最先进方法11.6%--51.9%的token的情况下，达到了与其相当的高准确率。借助检索轨迹复用和自适应升级，token成本降至5.1%--32.5%，同时保持有竞争力的准确率和实用的文档存储性能，显示出这项工作对新兴AI知识库的效用。

## Abstract
State-of-the-art retrieval-augmented generation (RAG) methods exploit document structures to acquire sufficient evidence, but often incur substantial token costs. To reduce structural-context tokens without compromising high RAG accuracy, we present {\sf VikingRAG}, a directory-aware semantic data management system that tightly integrates semantic and structural access to support structural-context-efficient, evidence-gap-driven multi-round retrieval. To further reduce token overhead of multi-round interaction, we materialize agentic multi-round retrieval traces as experience edges, and reuse these edges for similar queries, avoiding repeated multi-round exploration. To additionally reduce token costs when agentic multi-round retrieval is unnecessary, we introduce an adaptive escalation strategy that answers from one-round experience-augmented retrieval when the evidence is sufficient, and invokes agentic multi-round retrieval only otherwise. Experiments on real datasets show that the base system {\sf VikingRAG} matches high accuracy of state-of-the-art methods while consuming only 11.6\%--51.9\% of their tokens. With retrieval-trace reuse and adaptive escalation, token costs drop to 5.1\%--32.5\% while maintaining competitive accuracy and practical document-storage performance, showing the utility of this work for emerging AI knowledge bases.

## 1. 核心问题与整体含义

- **研究背景**：检索增强生成（RAG）通过从数据库中提取证据，帮助大语言模型减少幻觉、获取最新知识而无需重训练，已广泛应用于企业问答、法律金融文档分析、科学文献探索等场景。这些场景的底层语料通常是由章节、段落、附录组织的**结构化文档**。

- **核心痛点**：现有 RAG 方法在结构化文档上难以同时兼顾高准确率与低 token 消耗：
  - **忽略结构的方法**（NaiveRAG 的 chunk-embed-retrieve、SQL-RAG、图 RAG）把文档抽象为扁平块、关系元组或语义图，无法利用结构线索，准确率低。
  - **利用结构的方法**（MoDora、BookRAG、KohakuRAG）虽显式利用文档结构，但**未闭环"证据获取—答案推理"反馈**，缺乏证据缺口驱动的多轮检索，难以发现潜在实体、隐式依赖或散落于远距离章节的事实。
  - **DeepRead** 虽实现了证据缺口驱动的多轮目录检索，但把每个候选文档的**完整目录序列化为纯文本**注入 prompt，结构 prompt 成本随目录数量与规模增长；且每轮追加历史，上下文持续膨胀，token 开销巨大。

- **整体含义**：论文致力于在**不牺牲 RAG 准确率**的前提下，消除不必要的结构上下文 token 与多轮交互 token，为新兴的 AI 知识库（企业/私有文档集合）提供可落地的成本可控方案。

## 2. 方法论

### 2.1 核心思想

将文档层级作为**外部、可查询的状态**而非 prompt 驻留文本；通过**语义访问与结构访问的紧耦合**，实现按需暴露目录片段；并用**经验边复用**和**自适应升级**进一步压缩多轮交互 token。系统共三个层次：VikingRAG → VikingRAG-E → VikingRAG-E+。

### 2.2 关键技术细节

**（1）提示解耦、保留层级的语义存储模型（VikingRAG 基础）**

- 对每个文档提取目录树 $T_D$，在结构区域内做**目录感知分块**，满足块大小上界 $L$；每个块记录其归属节点 $\rho_D(c_i)$。
- **自底向上多粒度摘要**：叶节点摘要其拥有的块，内部节点摘要其子节点摘要。摘要集 $\mathcal{A}_D$，向量索引对象集 $\mathcal{X}_D = \mathcal{C}_D \cup \mathcal{A}_D$。
- **共享 URI 物化**：通过单射 $\phi_D$ 为结构节点与索引对象分配 URI，路径编码包含关系（祖先—后代对应 URI 前缀）。例如：
  - 目录节点：`viking://home_cooking/Pasta/Carbonara/`
  - 摘要：`.../Carbonara/.abstract.md`
  - 块：`.../Carbonara/Carbonara_1.md`
- 每条向量记录为 $\langle \text{Embed}(x), \phi_D(x), \text{type}(x), \text{depth}(x), \text{preview}(x) \rangle$。
- **五条存储性质**：直接可寻址、层级保留命名空间、多粒度索引覆盖、跨层可解析、作用域隔离。

**（2）证据缺口驱动的多轮目录检索（Algorithm 1）**

- 暴露四个文档访问工具：
  - `Search(q, u, K)`：在可选 URI 作用域内做向量检索，返回 top-K 块/摘要及 URI、分数、预览。
  - `List(u)`：返回目录 URI 的直接子节点。
  - `Grep(p, u)`：在 URI 作用域内做词法/正则匹配。
  - `Read(u)`：读取 URI 对象的完整内容。
- 流程：初始化上下文 $M^{(0)}$ → 每轮 LLM 生成检索响应 $R_t$ → 若无函数调用则直接给出答案；否则解析并执行函数调用 $F_t$，输出 $O_t$，追加到上下文 $M^{(t)}$ → 受轮数预算 $B$ 约束；预算耗尽则调用 `FinalizeWithContext`。
- 上下文可表示为 $M^{(t)} = M^{(0)} \oplus [(R_1,F_1,O_1),\dots,(R_t,F_t,O_t)]$。
- 核心优势：结构 prompt 足迹正比于**被选择性访问的目录片段**，而非完整候选目录。

**（3）经验边（VikingRAG-E）**

- **动机**：相似查询会重复走相同的多轮检索路径；图 RAG 的边是内容派生的（离线构建、编码语料语义），而经验边是**使用派生的**（增量构建、编码检索经验）。
- **定义**：经验边 $\varepsilon_{v\to u} = (v, u, r_\varepsilon)$，其中 $r_\varepsilon = (\text{Embed}(Q), H)$，$Q$ 为历史查询，$H$ 为多轮函数调用轨迹的紧凑摘要。
- **在线构建（Algorithm 2）**：源端点 $U_{src}$ 为 Search 返回的 URI；候选目标 $U_{cand}$ 为 Grep 返回与 Read 目标 URI；用 LLM 判断保留真正支持答案的 URI 得 $U_{tgt}$，并剔除已由经验边扩展而来的 URI 以防冗余增长；为每对 $(v,u)$ 建边。
- **使用（Algorithm 3）**：对向量检索 top-K 种子 URI，做**查询条件化的多跳扩展**——仅当 $\text{sim}(z_{Q'}, r_\varepsilon.z_Q) \geq \gamma$ 时激活边，避免盲目遍历；返回增强结果 $Y$。
- **维护**：存储反向记录，删除节点时本地化移除出边与入边。

**（4）自适应检索升级（VikingRAG-E+）**

- **思想**：一轮经验增强的非智能体检索若证据充分，直接回答；否则才升级到智能体多轮检索，省去固定且累积的智能体开销（工具指令、中间结果、函数调用历史等）。
- **关键挑战**：证据充分性判断。若把不完整证据误判为充分，会直接损害准确率。
- **设计**：采用**约束感知的证据充分性检查**——先让 LLM 识别必须由证据支持的关键约束（实体、时间、范围等），再据此选取直接证据并判断是否足以回答；不充分或有歧义时默认升级。

### 2.3 复杂度

- 文档插入时间 $O(N + |V_D| + T_{sum} + T_{mat} + T_{emb} + T_{idx})$，空间 $O(N + N_A + |V_D| + |\mathcal{X}_D|\cdot d + S_{idx})$。
- 多轮检索运行时间与工作空间均与累积上下文 $M^{(B)}$ 成正比。
- 经验边构建时间 $O(T_{URI} + T_{Emb} + T_{SUM} + |U_{src}|\cdot|U_{tgt}|)$；边检索时间包含种子检索、相似度计算与多跳访问成本。

## 6. 主要结论与发现

- **VikingRAG 基础版**在匹配 SOTA 准确率的同时，仅消耗最强基线 **11.6%–51.9%** 的 token。
- **加入经验边复用与自适应升级后（VikingRAG-E+）**，token 成本进一步降至 **5.1%–32.5%**，同时保持有竞争力的准确率与实用的文档存储性能。
- 经验边带来查询时节省而数据管理开销低：VikingRAG-E 平均仅消耗 VikingRAG 的 **67.3%–88.1% token、72.3%–91.5% 延迟**；单条历史查询构建经验边仅需数秒。
- VikingRAG-E+ 平均仅消耗 VikingRAG-E 的 **49.8%–81.1% token、73.1%–89.8% 延迟**。
- 约束感知的证据充分性检查显著优于朴素 prompt（正确率更高、误判"不升级"率更低）。
- 端到端延迟在可接受范围内，且明显快于最准基线 DeepRead。
- 结论在 GPT-5.5、Seed-2.0、GLM-4.7 上保持一致，说明优势对 backbone LLM 鲁棒。
- 随文档数量增加，VikingRAG(-E+) 检索性能基本稳定，而 DeepRead 等基线准确率下降、token 与延迟上升。

## 7. 优点

- **存储与访问紧耦合的范式创新**：以 URI 为共享标识，使语义检索结果可直接解析到结构上下文，目录 URI 又能限定后续语义/词法检索作用域，实现结构上下文的按需暴露，区别于 DeepRead 的"全目录注入 prompt"。
- **证据缺口驱动的多轮检索**：闭环"证据获取—推理"，能发现散落于远距离章节/文档的证据，弥补 MoDora、BookRAG、KohakuRAG 的不足。
- **经验边机制巧妙**：使用派生而非内容派生，查询条件化激活避免盲目遍历；反向记录支持本地化维护；剔除已扩展 URI 抑制冗余边增长。
- **自适应升级务实**：将"何时需要智能体"作为显式决策，用约束感知的充分性检查降低误判风险，兼顾成本与鲁棒性。
- **工程落地性强**：四类工具接口（Search/List/Grep/Read）类 Unix 直觉，核心机制已集成到开源 OpenViking，代码开源。
- **实验设计较为严谨**：历史问题与评估问题独立、专家验证 judge、多 LLM 复现、多维度指标（准确率/延迟/token/存储）。

- **算力信息不完整**：未披露 GPU 训练/推理总时长、API 调用成本与能耗，复现成本难以评估。
- **基线对比不完整**：多个数据集上 LightRAG、HippoRAG-2、BookRAG 因 24 小时摄入超时报告 N/A，削弱了部分横向结论的全面性；第二准基线常与 VikingRAG 准确率差距较大，token 比值对比的参照强度有限。
- **依赖历史查询**：经验边的收益依赖历史工作负载与测试问题的相似度（VersionQA 达 60%，其他数据集仅约 26%–31%），冷启动或查询分布漂移场景下收益可能下降。
- **证据充分性判断仍有误判**：本文方法的 false-NoEscalation 率在多个数据集仍超过 5%，论文解释为这些难查询即使升级也未必成功，但这意味着潜在准确率损失未被完全消除。
- **摄入期额外 token 开销**：为每个向量索引对象生成 preview 导致摄入 token 高于 DeepRead/MoDora，论文以"摄入不频繁"为由接受，但对频繁更新文档的场景可能不友好。
- **结构依赖**：方法假设文档具备清晰的章节层级；对结构混乱或非层级化文档（如纯对话记录、扫描件）的适用性未做验证。
- **数据集规模**：最大语料 8.78M token，虽已具挑战性，但相对真实企业级知识库（可能达数十亿 token）仍有差距，超大规模下的可扩展性证据有限。
- **评估指标**：准确率依赖 LLM-as-a-judge，尽管有专家验证，仍存在主观性与 judge 偏差风险。
