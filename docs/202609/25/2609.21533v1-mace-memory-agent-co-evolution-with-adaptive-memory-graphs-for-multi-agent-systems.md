## 摘要
基于LLM的多智能体系统会生成协作轨迹，这些轨迹记录了智能体如何规划任务、验证中间结果并修复故障。复用这些流程需要保留动作的前置条件以及后续智能体所需的输出。我们的实证研究表明，将这些依赖关系分组为功能性记忆单元可以提高其保持率，而连接这些单元则能增加对任务共同所需的单元与链接的检索。即便每个组合的内容在不同格式间固定不变，偏好的单元组合也会在指令与清单之间发生变化。根据每种组合与格式配对的结果来更新选择，优于分别对组合和格式进行评分。这些发现启发了MACE，一个通过执行反馈自适应调整记忆组织与智能体记忆使用的记忆-智能体协同演化框架。其MemGoG结构将功能性单元表示为相关条件、动作和输出的子图，并通过支持、冲突和修复关系将它们连接起来。MACE Loop在记忆预算内选择与任务相关的单元和关系，并为每个智能体提供其当前操作的指令或清单。它记录所选单元、呈现格式、智能体输出和任务结果，以更新用于检索的单元分数和关系，并指导后续的呈现选择。在八个基准测试中，MACE以平均81.11%的得分优于十个基线，而最强基线SAGE为78.97%。

## Abstract
LLM-based multi-agent systems generate collaboration traces that record how agents plan tasks, verify intermediate results, and repair failures. Reusing these procedures requires preserving an action's prerequisites and the outputs needed by subsequent agents. Our empirical studies show that grouping these dependencies into functional memory units improves their retention, while connecting units increases retrieval of the units and links jointly required by a task. The preferred combination of units also changes between instructions and checklists, even when each combination's content is fixed across formats. Updating choices from the outcomes of each combination and format pairing outperforms scoring combinations and formats separately. These findings motivate MACE, a memory-agent co-evolution framework that adapts memory organization and agent memory use through execution feedback. Its MemGoG structure represents functional units as subgraphs of related conditions, actions, and outputs, connecting them through support, conflict, and repair relations. MACE Loop selects task-relevant units and relations within a memory budget and provides each agent with instructions or checklists for its current operation. It records the selected units, presentation formats, agent outputs, and task outcomes to update unit scores and relations for retrieval and inform subsequent presentation choices. Across eight benchmarks, MACE outperforms ten baselines with an average score of 81.11%, compared with 78.97% for the strongest baseline, SAGE.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：基于 LLM 的多智能体系统（MAS）通过通信与工具调用协作求解复杂任务，执行过程中产生大量"协作轨迹"，记录任务分解、中间结果验证、错误修复等流程，可复用为后续任务的经验。
- **核心问题**：复用一段历史流程，必须同时保留三样东西——动作的**适用前置条件**、**动作本身**、以及**传递给下游智能体的输出**。因此多智能体记忆的关键难点是：
  1. 在一次/多次历史执行中，应当保留哪些**内部与跨经验的依赖关系**；
  2. 检索到的经验应当**以何种形式**交付给具体智能体（指令 vs. 清单）。
- **四项实证发现（第4节，TAT-QA 主诊断 + TabFact 复现）**：
  - **组织方式**：在 1024 token 预算下，MemGoG 约 80% 成功率，Graph 68%，Items 65%；
  - **功能单元 + 外层关系**：功能单元保留约 83% 内部依赖（非功能对照组 68%）；加外层关系后跨经验完整支持率从 52% 升至 69%；
  - **组合与呈现耦合**：C1 在"指南"格式下优于 C2（约 82% vs. 76%），在"清单"格式下顺序反转（59% vs. 78%），说明最优组合依赖呈现格式；

- **整体含义**：记忆的组织结构与智能体对记忆的使用方式应**通过执行反馈协同演化**，而非各自独立优化。

## 2. 方法论

### 2.1 核心思想
MACE = **MemGoG 记忆结构** + **MACE Loop 循环**（Need-aware Memory Composer → Adaptive Agent-Memory Coupler → Feedback Co-Evolver）。

### 2.2 MemGoG 构建
- **需求识别**：对每个需要记忆的智能体，从其状态与 token 预算抽取需求描述子 $d_i^t = \text{Need}(s_i^t, b_i^t)$，指定任务、角色、阶段、状态、所需记忆功能与预算。
- **记忆单元（memory graph cell）**：$g_k=(V_k,E_k,\tau_k,f_k,\iota_k,o_k,U_t(g_k),p_k)$，即"条件—动作—输出"子图，含类型、功能、激活条件、提供内容、历史效用与来源记录。构造器产出 episode / mechanism / routine / role projection / source / conflict 等类型单元。
- **图装配**：候选库 $C_t$ 作为外层节点，$G^{cand}_t=(C_t,\bigcup_{r\in R}E^{(r)}_t)$，关系类型 R 包括 support、abstraction、operationalization、role projection、conflict、repair、feedback，即"图的图"（graph of graphs），保留单元内部依赖的同时连接单元。

### 2.3 Need-aware Memory Composer
- **打分**：正面项 $\phi^+_t(g)$（相关性、历史效用、支持）与负面项 $\phi^-_t(g)$（冲突、成本、风险），得分 $S_t(g)=\mathbf{1}_3^\top(\phi^+_t(g)-\phi^-_t(g))$。
- **预算内组合**：过滤冲突/高风险项得可采纳池 $C^{adm}_t$，取 Top-$B_t$ 构成工作图
  $G^{work}_t=(W_t,\ E^D_t\cap(W_t\times R\times W_t))$，即只保留两端都被选中的任务相关关系边。

### 2.4 Adaptive Agent-Memory Coupler
- **记忆-智能体匹配**：构造相关性矩阵 $R_t=[\kappa_t(g_k,d_i^t,s_i^t)]$，行为工作记忆单元、列为参与智能体；按列优先选择并聚合支持/常规链接成智能体专属视图 $G^{view}_{i,t}$（保留来源记录）。
- **自适应补丁**：$P_i^t=(c_i^t,\mu_i^t,\phi_i^t,\delta_i^t,\alpha_i^t,\lambda_i^t,p_i^t)$，分别控制内容、模式（相关案例/成败机制/协作常规/执行约束/修复流程）、格式（清单或输出模式等）、时机、强度（提示或硬性要求）、位置与来源；渲染 $m_i^t=\text{Render}_{b_i^t}(P_i^t)\in L(b_i^t)$ 保证不超 token 预算。

### 2.5 Feedback Co-Evolver
- **三级反馈**：local（当前智能体输出）、downstream（对下游操作的贡献）、team（最终任务结果），轨迹回报 $R_\xi=\sum_{h\in H}r_h(\xi)-\|p_\xi\|_1$，$p_\xi$ 为资源与不当记忆使用的非负惩罚。
- **效用更新**：$u_t^+=u_t+\eta D_\xi(R_\xi\mathbf{1}-u_t)$，$D_\xi$ 为对角掩码，仅更新被使用单元；η 控制单条轨迹贡献。
- **关系与策略更新**：有效组合强化 support 关系，不兼容建议创建/强化 conflict 关系；同时把角色、阶段、配置与结果记录回写，用于后续 patch 模式/格式/时机/强度的选择。

### 2.6 执行流程（Algorithm 1–3 要点）
任务适配 → 检测记忆需求（可判定"无需记忆"）→ 组合与耦合 → 答案生成 → 解析与打分 → 反馈协同演化。**关键不变量：先读后写（read-before-write），图更新仅在打分后提交，防止当前任务金标泄漏到自身预测。**

## 6. 主要结论与发现

- **性能**：MACE 在 8 个基准上全部取得最高分，平均 **81.11%**，超过最强基线 SAGE 的 **78.97%**（+2.14 个百分点），相对 Direct（71.53%）提升 **13.40%**。

- **消融结论**：去掉 Agent-Memory Coupler 下降最大（-5.88），替换 MemGoG 次之（-5.20），去掉 Memory Composer（-3.53），去掉 Feedback Co-Evolver（-1.41），固定 patch 模式影响最小（-0.63）；说明**自适应图结构记忆 + 角色专属耦合**是主要增益来源。
- **效率**：MACE token 成本高于 Direct/MAGMA，但**延迟（1.36 s/query）低于 SAGE（2.41 s/query）**，在最慢子集 LCB v6 上为 3.76 s/query，作者认为开销可接受。
- **鲁棒性**：后端替换下仍保持 79.28–81.11%（均高于 Direct 71.53% 与 SAGE 78.97%）；网络退化到最严重设置仍为 76.92%；记忆单元降至 25% 预算仍有 81.76%；30% 噪声下 70.30%，高于 SAGE 66.95%、MAGMA 56.45%、Direct 55.65%，呈现**平滑退化**。
- **总体论断**：通过执行反馈同步优化记忆组织与智能体使用方式，能更有效地复用协作流程并提升多智能体系统表现。

## 7. 优点

- **动机扎实**：先用 4 组受控诊断实验量化"功能单元保留依赖""外层关系提升跨经验支持""组合×格式相互依赖""联合反馈优于分别评分"，再据此设计方法，方法-动机链条清晰。
- **结构设计合理**：MemGoG 以"图的图"同时保留单元内部依赖与单元间类型化关系（support/conflict/repair 等），比扁平条目或统一图更贴合多智能体协作语义。
- **联合决策机制**：反馈以"所选单元组合 + 呈现格式"配对为单位记录与更新，避免把两个耦合决策拆开评分带来的偏差。
- **交付方式细致**：Coupler 不是简单拼接检索内容，而是按角色去重、标注冲突/陈旧、排序并渲染成带来源与置信提示的补丁，且受 token 预算约束。
- **评估较全面**：8 基准跨 6 领域 + 10 基线 + 5 组消融 + 效率 + 4 轴鲁棒性，并附大量附录（协议、接口契约、伪代码、可复现字段）。
- **实验规范性强**：金标仅由 scorer 使用、先读后写、共享解析器、记录原始 completion，保证了记忆演化场景下的因果隔离与可审计性。
- **成本-性能权衡有说服力**：虽然 token 成本约为 Direct 的 11 倍，但延迟反而低于 SAGE，性价比叙事较完整。

- **呈现空间探索不完整**：组合×格式的耦合证据主要建立在"指南 vs 清单"二值选择上，而 patch 七元组中的时机 $\delta$、强度 $\alpha$、位置 $\lambda$ 等维度未做系统消融，Coupler 的设计空间利用率不明。
- **理论保证缺位**：论文未对记忆图结构的收敛性、联合反馈迭代的稳定性或"联合优于分离"给出任何形式化分析或界，相关论断目前仅为经验观察。
- **安全与隐私维度空白**：协作轨迹中可能包含敏感中间结果、工具返回数据或私有上下文，论文未讨论记忆的访问控制、脱敏、跨任务信息泄漏与合规问题；文中"先读后写"只解决了金标泄漏，不覆盖上述风险。

## 9. 总体评价与启示

- **定位**：MACE 是一个**推理期、免训练**的多智能体记忆框架，其最有价值的贡献不是某个单点模块，而是把"记忆如何组织"与"记忆如何交付给具体智能体"显式建模为一对**耦合决策**，并用执行反馈联合优化——这一视角对任何带持久记忆的 Agent 系统都具迁移性。
- **适用边界**：适合任务可分解、有明确成功信号、历史协作流程可复用、且能容忍约 11 倍于 Direct 的 token 开销而对延迟较敏感的场景；不适合无金标反馈、超低成本约束或需要长程自主演化的开放环境。
- **方法论启示**：诊断先行（4 组受控实验→方法设计）的写作范式值得借鉴；"功能单元 + 外层类型化关系"的图组织方式可作为多智能体记忆的通用表示基线；"组合×格式"作为最小反馈单位的思路，可推广到工具选择×调用参数、检索片段×提示模板等其它耦合决策。
- **后续研究方向**：① 多次重复运行 + 置信区间 + 显著性检验，并统一各基准的采样口径；② 在受控复现条件下重跑 G-MAS 基线；③ 引入记忆衰减、压缩与冲突消解机制，验证长期演化下的稳定性；④ 探索无金标场景下的代理反馈信号；⑤ 补充成本-精度帕累托分析与跨语言、多模态、长程任务评测；⑥ 对 patch 七元组与记忆图关系类型做完整消融与理论刻画。
