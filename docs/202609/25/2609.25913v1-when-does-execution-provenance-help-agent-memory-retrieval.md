## 摘要
语言智能体的执行历史可能超出其上下文窗口，因此其记忆系统需要在严格的 token 预算下检索完整的支撑证据。证据可能跨越多个执行事件，然而传统检索器使用固定的 token 窗口和固定 k 的指标，这些指标奖励单个片段，却无法表明完整的证据集是否能够放入上下文。更小的窗口能减少无关文本，但会将证据分散到不同候选中，而平坦与图结构的比较则可能将候选设计同图传播混为一谈。为解决这些局限，我们将智能体记忆检索形式化为预算约束下的证据补全，并在共享的源坐标中对精确的金标准片段进行评分。我们首先从工具参数与输出中构建源对齐的溯源单元。随后，我们应用零初始化的残差 R-GCN，在带类型的溯源边上对冻结的稠密检索分数进行精化。我们在 1,207 条留出的、基于执行的 ISETrace 轨迹上评估了 2,000 个基于片段的记忆查询。在匹配的 Dense-FT 评分下，溯源单元相比平坦的 512-token 窗口将 Full Support@2048 提升了 19.07 个百分点，并且在四种平坦分块大小上仍比逐指标 oracle 高出 11.96 个百分点；该模式在交叉编码器评分下同样成立。在保持候选与种子分数不变的情况下，图传播使 Full Support@2048 提升 4.55 个百分点（95% CI [2.98, 6.18]）。这一增益集中在金标准证据跨越多个事件时；实体共现扩展未产生可比的收益，而关系与拓扑对照则证实其依赖于带类型的变换以及观测到的图结构。总体而言，源对齐候选解决了主要的粒度权衡，而图条件传播则为分布式证据带来了较小且有针对性收益。

## Abstract
A language agent's execution history can exceed its context window, requiring its memory system to retrieve complete supporting evidence under a hard token budget. Evidence may span multiple execution events, yet conventional retrievers use fixed token windows and fixed-k metrics that reward individual fragments without showing whether the complete evidence set fits in context. Smaller windows reduce irrelevant text but scatter evidence across candidates, while flat-versus-graph comparisons can conflate candidate design with graph propagation. To address these limitations, we formulate agent-memory retrieval as budgeted evidence completion and score exact gold spans in shared source coordinates. We first construct source-aligned provenance units from tool arguments and outputs. We then apply a zero-initialized residual R-GCN to refine frozen dense-retrieval scores over typed provenance edges. We evaluate 2,000 span-grounded memory queries over 1,207 held-out execution-grounded ISETrace trajectories. With matched Dense-FT scoring, provenance units improve Full Support@2048 by 19.07 points over flat 512-token windows and remain 11.96 points above a per-metric oracle over four flat chunk sizes; the pattern also holds with cross-encoder scoring. Holding the candidates and seed scores fixed, graph propagation adds 4.55 points in Full Support@2048 (95% CI [2.98, 6.18]). This gain is concentrated when gold evidence spans multiple events; entity co-occurrence expansion produces no comparable benefit, and relation and topology controls confirm dependence on typed transformations and observed graph structure. Overall, source-aligned candidates address the dominant granularity trade-off, while graph-conditioned propagation adds a smaller, targeted benefit for distributed evidence.

## 1. 核心问题与整体含义

- **研究背景**：语言智能体的执行历史包含消息、工具调用、参数、输出与执行结果，容易超出上下文窗口。记忆系统必须在硬 token 预算下，从长轨迹中检索出足以回答查询的完整证据。
- **核心问题**：传统检索通常使用固定 token 窗口与固定 \(k\) 指标，奖励局部相关片段，却无法回答“完整证据集是否能在预算内全部返回”。证据可能分散在多个执行事件中，单独一个高分片段并不足以支撑答案。
- **关键矛盾**：
  - 窗口越小，无关文本越少，但证据更易被切散到多个候选中；
  - 平坦分块与图结构候选的比较，常把“候选构造差异”和“图传播收益”混在一起，难以判断收益来源。
- **整体含义**：论文将智能体记忆检索重新形式化为 **预算约束下的证据补全**，并试图分离两个效应：源对齐候选视图带来的粒度收益，以及执行溯源图传播带来的关系推理收益。核心结论是：前者是主要收益来源，后者只在证据跨事件分布时提供较小但稳健的定向增益。

## 2. 方法论：EPGM 与预算化证据补全

### 2.1 问题形式化与评估协议

- 轨迹定义为有序事件序列 \(\tau=(e_1,\dots,e_n)\)，每个文本字段可由事件 ID、JSON 指针和字符区间定位。
- 金标准证据是精确源 span 集合 \(G_q=\{s_1,\dots,s_m\}\)，每个检索候选也映射回相同源坐标。
- **Coverage@B**：在 token 预算 \(B\) 下，按排序前缀贪心加入候选直到超出预算，计算已覆盖金标准字符比例。
- **Full Support FS@B**：预算内是否覆盖全部金标准 span，是主指标，因为部分证据通常不足以回答。
- **Budget-AUC**：在 \(\log_2 B\) 轴上计算归一化梯形面积，避免大预算区间被过度加权。
- 辅助诊断指标包括 Recall@k 与 MRR，但论文强调 Recall@k 是源字符覆盖，不是证据项召回。

### 2.2 执行溯源图与源对齐候选

- 对每条轨迹构建查询无关的有向多重图 \(G_\tau=(V,E)\)，节点包括工具调用、工具输出、源支撑的参数/输出单元、被引用工件等。
- 边类型包括：调用返回、内容归属、资源读写、源字段内相邻、精确值复用等。`feeds` 边仅在 URL、绝对路径、文件名、UUID 或哈希唯一匹配时连接早期输出与后续调用参数，表示词法复用而非语义因果。
- **平坦视图**：将消息、推理文本、工具参数和输出渲染为轨迹文档，切成 512 token 窗口，重叠 64 token。
- **溯源单元视图**：将工具参数与输出字段切分为源支撑内容单元，并挂接到图上；该视图排除自由消息，因为金标准仅来自工具参数与输出。

### 2.3 检索与图条件残差

- 基础方法：
  - BM25 对平坦块做词法排序；
  - Dense 使用冻结的 `intfloat/e5-base-v2` 编码查询与候选，按余弦相似度排序；
  - GraphRAG 作为负控制，在实体共现图上传播平坦块分数；
  - Provenance Path 为无训练方法，用冻结稠密编码器取 top-5 锚点，在非时间溯源边上做双向 BFS 扩展。
- **Dense-FT**：微调 E5-base-v2 一个 epoch，学习率 \(2\times10^{-5}\)，batch size 16，正例为源 span 与金标准重叠的候选，负例为随机、BM25 与困难负例。
- **Cross-Encoder-FT**：微调 `BAAI/bge-reranker-base`，联合编码查询-候选对，同样使用精确 span 监督。
- **残差 R-GCN**：
  - 使用匹配的溯源单元 Dense-FT 检查点提供种子分数 \(s_0(q,v)\)；
  - 每个节点冻结的 768 维嵌入与种子分数拼接，投影到 256 维，再经过 3 层关系图卷积；
  - 7 种物理关系按正反方向展开为 14 种关系特定变换；
  - 查询不插入消息传递，但通过种子分数进入每个候选节点表示，使传播查询条件化；
  - 查询条件 MLP 预测残差 \(\Delta_\theta(q,v)\)，最终分数为  
    \[
    s(q,v)=s_0(q,v)+\Delta_\theta(q,v)
    \]
  - 残差输出层零初始化，因此初始模型精确等于 Dense-FT 种子排序；seed passthrough 控制将图深度设为 0，直接返回 \(s_0\)。

## 6. 主要结论与发现

- **源对齐溯源单元是主要收益来源**：
  - 匹配 Dense-FT 下，溯源单元相比 512-token 平坦窗口将 Full Support@2048 提升 **19.07 个百分点**；
  - 相比四种平坦分块大小的逐指标 oracle 仍高 **11.96 个百分点**；
  - 交叉编码器评分下同样成立。
- **图条件残差提供较小但稳健的增益**：
  - 固定候选与 Dense-FT 种子分数后，残差 R-GCN 使 Full Support@2048 提升 **4.55 个百分点**（95% CI [2.98, 6.18]）；
  - Recall@5 提升 7.09，MRR 提升 7.28，Coverage@2048 提升 3.39。
- **增益集中分布**：
  - 直接召回：Full Support@2048 仅 +0.19，区间含零；
  - 链接召回：+4.00；
  - 多事实召回：+11.83。
  - 证据分散在 2 个事件时，残差 Full Support 增益达 10.66；图距离结果非单调，2 跳结构最有效。
- **负控制与消融**：
  - GraphRAG 实体共现扩展相比 BM25 几乎无收益；
  - 同质关系、随机边重连、移除 `feeds` 或执行归属关系会显著削弱或使残差退化到种子排序；
  - 移除工件 I/O 无显著影响，移除 chunk adjacency 反而略升，说明并非所有边族都有用。
- **训练规模与效率**：
  - 残差在 10%–100% 训练子集上均为正，10% 时 Coverage@1024 增益 +14.05，全量时 +2.28，表现为样本高效的结构归纳偏置；
  - 残差 R-GCN 仅增加约 20.06 ms 平均延迟和 11.27 MiB 模型体积。
- **端到端迁移**：
  - 在 315 条链接+多事实人工审计查询上，严格准确率从平坦 Dense-FT 的 71.75% 升至残差 R-GCN 的 77.78%，但差值 95% CI 下界为 0.00，属边界证据；
  - 从“不完整支持”转为“完整支持”的 106 条查询严格准确率提升 26.42 点，说明完整证据到达上下文与答案改善机制一致。

## 7. 优点

- **问题形式化清晰**：将智能体记忆检索定义为预算约束下的证据补全，并用精确源 span 与共享坐标比较不同候选组织，避免固定 \(k\) 指标的误导。
- **有效分离两类效应**：通过匹配 Dense-FT、固定候选与种子分数，把“候选视图收益”与“图传播收益”分开归因，方法学上比简单 flat-vs-graph 对比更严谨。
- **控制实验丰富**：包括 GraphRAG 负控制、随机边重连、关系族消融、同质关系控制、逐指标平坦 oracle、训练规模扫描、预算扫描与人工审计。
- **统计处理稳健**：使用轨迹聚类 bootstrap，考虑同轨迹查询非独立问题；配对种子设计减少训练
