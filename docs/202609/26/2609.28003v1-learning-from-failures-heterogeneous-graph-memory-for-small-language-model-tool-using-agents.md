## 摘要
中小型语言模型为工具使用智能体提供了高性价比的执行器，使其在本地和大规模部署中具有吸引力。然而，在长时程和有状态环境中，它们常犯结构性错误，例如遗漏所需观测、过早执行写入、重复失败的调用以及违反动作前置条件。这些错误可能导致错误的状态更新、策略违规以及代价高昂或不可逆的后果，使可靠的工具执行成为关键部署挑战。现有微调方法需要大量数据和计算，而扁平记忆可能检索到失败动作，却未保留其因果上下文或安全条件。本文提出 FRESH，一种面向经验结构化异构图的失败感知检索框架，将历史成功与失败转化为工具使用智能体的结构化外部经验。通过显式建模任务、动作、错误、修复和执行条件之间的依赖关系，FRESH 帮助冻结的语言模型复用可靠策略、避免重复失败，并在有状态的工具交互中做出更安全的决策。在 τ-Bench 和 AppWorld 上使用多个开源模型进行的实验表明，FRESH 在任务成功率和工具使用可靠性上持续优于无记忆智能体和代表性基于记忆的基线。

## Abstract
Small and medium-sized language models offer cost-effective executors for tool-using agents, making them attractive for local and large-scale deployment. However, in long-horizon and stateful environments, they often make structural errors such as missing required observations, performing premature writes, repeating failed calls, and violating action preconditions. These errors can lead to incorrect state updates, policy violations, and costly or irreversible consequences, making reliable tool execution a critical deployment challenge. Existing fine-tuning approaches require substantial data and computation, while flat memory may retrieve failed actions without preserving their causal context or safety conditions. In this paper, we propose FRESH, a Failure-aware Retrieval framework over Experience-Structured Heterogeneous graphs, which transforms historical successes and failures into structured external experience for tool-using agents. By explicitly modeling the dependencies among tasks, actions, errors, repairs, and execution conditions, FRESH helps frozen language models reuse reliable strategies, avoid recurring failures, and make safer decisions in stateful tool interactions. Experiments on $τ$-Bench and AppWorld with multiple open-source models show that FRESH consistently improves task success and tool-use reliability over no-memory agents and representative memory-based baselines.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体需通过外部工具（搜索、数据库、计算器、代码解释器、软件 API）完成真实任务，在长时程、有状态的多轮环境中，"可靠工具使用"远比生成语法合法的调用困难：智能体必须收集足够证据、维护中间状态、从工具错误中恢复、遵守领域策略，并判断状态变更操作是否安全。
- **痛点对象**：中小规模语言模型（SLM）推理与部署成本低，适合本地或大规模服务，但在长时程有状态环境中更易犯**结构性错误**：
  - 遗漏必需的观测（missing read）
  - 过早执行写入（premature write）
  - 重复失败的调用（repeated call）
  - 违反动作前置条件（precondition violation）
  - 这些错误会导致错误的数据库状态更新、策略违规，甚至不可逆后果。
- **现有方案的两类不足**：
  - **微调路线**：需大量数据与算力，且参数知识难以在新失败模式出现时被检查与更新。
  - **记忆路线（扁平记忆/轨迹回放）**：把历史内容原样保留，但不显式标注"某动作前需要哪些观测""上次为何失败""失败如何修复""写入动作的前置条件"，导致失败动作被当作可复用示例检索到，或成功写入被脱离其生效条件地照搬。
- **核心主张**：可靠的经验复用应捕获"什么成功了、什么失败了、为何失败、如何修复、在何条件下动作是安全的"，并将历史成败组织为**结构化、角色感知的外部经验**，在冻结语言模型的前提下提升执行可靠性。

## 2. 方法论：FRESH 框架

**全称**：FRESH = Failure-aware Retrieval over Experience-Structured Heterogeneous graphs（经验结构化异构图上的失败感知检索）。

**总体思路**：将历史成功/失败轨迹转化为带类型的有向异构图，用带反馈监督的异构图检索器（HG-Retriever）为当前任务检索最有用的经验，压缩成四类操作指引注入冻结执行器，并用轻量策略/前置条件门在写入前把关。图与检索器在评测阶段冻结。

### 2.1 问题设定

- 交互式工具使用任务：给定用户请求 $x$，第 $t$ 步观测历史 $h_t$，选择工具 $a_t=(u_t,z_t)$，环境返回观测 $o_t$ 并可能更新内部状态；轨迹 $\tau=(x,a_1,o_1,\dots,a_T,o_T)$ 获得基准反馈 $F$（任务成功、评测测试、状态检查、工具错误、终止状态）。
- 目标：在不更新执行器参数 $\pi_\theta$ 的前提下提升其表现，执行器条件于检索到的图证据：$\hat a_t \sim \pi_\theta(a\mid h_t, R_G(h_t))$。
- 对需要额外校验的动作，执行门映射为 allow / revise / block / transfer 四种决策。

### 2.2 失败感知经验图归纳

- **经验挖掘器（Experience Miner）**：对工具名、参数、实体、观测做对齐与归一化；基于反馈做**动作级信用分配**——不把整条失败轨迹一律标为错误。
  - 例（Airline）：`GetBooking` 成功读取预订状态 → 保留为"已验证读动作"；`CancelBooking` 在未验证取消资格与用户确认前执行 → 标为"失败写入"。
- **图结构**：$G=(V,E,\tau_V,\tau_E,X)$，节点/边带类型与文本+统计属性。
  - **节点类型**：task、subtask、tool、action、observation、reflection、reasoning_memory、successful_trajectory、failed_trajectory、error、precondition、repair/solution。
  - **关系类型**：contains、calls、requires、guards、verified_by、fails_because、fixed_by、supports、leads_to、similar_to、conflicts_with。
  - 通过把"不安全动作"与"由其派生出的警告、前置条件、修复"分离，既保留失败知识又不鼓励重犯。
- **示例片段**：`Task --contains--> GetBooking`；`GetBooking --verified_by--> SuccessfulRead`；`CancelBooking --fails_because--> EligibilityNotVerified`；`CancelBooking --requires--> CheckCancellationPolicy`；`CheckCancellationPolicy --guards--> CancelBooking`；`EligibilityNotVerified --fixed_by--> ReadCheckConfirmWrite`。

### 2.3 HG-Retriever 训练

1. **查询构造**：$q_i=f_q(x_i,h_i)$，输入包含领域/意图线索、实体与槽位类型、可用工具、策略约束、近期错误信息。
2. **稀疏召回**：先按文本相关性、节点类型、历史效用召回 top-$K_0$ 节点，再并入其 $H$ 跳类型化邻居，得到紧凑候选子图 $G^c_i$，避免对全图做 GNN 编码。
3. **反馈派生监督**：正样本 = 已验证动作、成功推理记忆、有效修复、支撑成功写入的前置条件；负样本 = 失败动作、重复调用、策略违规、无关记忆、不安全模式。要点是"反思（如'退款前先查资格'）视为有用指引，而原始的过早退款动作视为负例"——无需人工相关性标注。
4. **异构图编码**：节点初始表示拼接文本嵌入、节点类型嵌入、历史成败统计、查询匹配特征（式 5）；随后做**关系感知消息传递**（式 6，类似 R-GCN：$h_v^{(\ell+1)}=\sigma(W_0^{(\ell)}h_v^{(\ell)}+\sum_{r\in R}\frac{1}{|N_r(v)|}\sum_{u\in N_r(v)}W_r^{(\ell)}h_u^{(\ell)})$），使动作节点能吸收其关联的工具、观测、前置条件、错误与修复信息。
5. **打分与排序目标**：$s_\phi(q_i,v)=\mathrm{MLP}([h_v^{(L)}\|q_i\|h_v^{(L)}\odot q_i])$；用 **BPR 成对排序损失** $L_{rank}=-\sum_i\log\sigma(s_\phi(q_i,v^+)-s_\phi(q_i,v^-))$；总目标 $L_{HG}=L_{rank}+\lambda_{reg}\|\phi\|_2^2$（算法 2 中另含不安全项 $\lambda_{unsafe}L_{unsafe}$）。**只训练检索器，执行器语言模型全程冻结。**

### 2.4 测试时图条件化执行

- 冻结图与检索器 → 稀疏召回 + GNN 重排 → 取 top-$K$ 节点 → 归类为四类紧凑指引并序列化（式 10）：
  - **Do**：已验证动作/工具使用模式；
  - **Avoid**：失败动作、重复调用、不安全模式；
  - **Check**：必需的观测、校验与策略条件；
  - **Repair**：修正、备用工具、替代执行路径。
- 该记忆表 $M_t$ 是压缩"记忆单"而非完整轨迹，会去除任务特定标识符与无关观测，但保留可操作的依赖关系。
- 冻结执行器生成候选动作；**低风险读动作直接执行**，状态变更/终止/策略敏感动作进入**策略与前置条件门**：$d_t=g(\hat a_t,P_t,O_t,B_t)\in\{\text{Allow, Revise, Block, Transfer}\}$。全部前置条件满足则 Allow；缺读取、参数需修正或需替代序列则 Revise；违反硬约束则 Block；需人工介入则 Transfer。

### 2.5 自演化闭环（仅训练/开发阶段）

- 执行反馈回灌经验挖掘器：成功动作提升其支撑记忆的效用，工具错误、重复调用、状态检查失败、被拦截的写入降低效用，效用更新为 $u_v^{(t+1)}=(1-\beta)u_v^{(t)}+\beta\Delta(F_t,v)$。
- 新发现的失败原因、修复、前置条件插入图中，可生成新的检索器训练对；图构建与检索器训练完成后，最终图与检查点在评测中冻结，防止测试任务信息泄漏。

## 3. 实验设计

- **Benchmark 1：τ-bench**（Yao et al. 2024）
  - 多轮智能体—模拟用户—有状态工具交互，带领域策略；Airline（改签、选座、取消）与 Retail（订单、退货、换货、退款）。
  - 官方 50 个 Airline 任务 + 114 个 Retail 任务，**无官方 train/dev/test 划分**，作者自建固定不重叠划分：留出 20 个 Airline + 40 个 Retail 作评测，其余用于采集训练/开发轨迹、建图与超参选择；测试任务各独立执行 4 次。
  - 指标：pass $k$（$k\in\{1,2,3,4\}$）；仅当最终数据库状态与必要动作通过基准评测器才算成功。
- **Benchmark 2：AppWorld**（Trivedi et al. 2024）
  - 9 个模拟日常应用、457 个 API、约 100 个虚构用户，750 个任务（250 场景 ×3）；官方划分 105 train / 60 dev / 168 Test-N / 417 Test-C。
  - Test-C 要求至少使用一个训练中未见的应用 API，更考验 API 理解与跨应用泛化。
  - 指标：任务级 Pass Rate（PR）、平均执行步数；另有 API-success / read / write 代理指标、prompt token 与平均成本。
- **执行器骨干（均冻结）**：Llama-3.2-1B-Instruct（轻量）、Qwen3-8B（中等）、Gemma-4-26B-A4B（较强）。
