## 摘要
持久记忆使语言模型智能体无需更新模型权重即可改进提示和技能。我们表明，将检索范围与认证范围相匹配，可使这些编辑支持在反复出现的任务族之间进行可靠的重复适应。我们在 ProcStream-RSI（一个12轮代码修复流）上研究冻结模型智能体，使用正交回归控制（ORC）——一种基于执行的持久技能编辑门控。在一项保持提案和门控决策不变的干预中，仅将每个被接受的技能检索用于其来源任务族，使平均隐藏轨迹效用从全局记忆下的0.713提高到0.816，并将有害部署从八次中的六次变为零次。在27个配对随机顺序流中，Scoped-ORC 相较于 Global-ORC 将平均轨迹效用提高0.063 [0.037, 0.094]，接受63次而非12次更新，并在19/27个流中产生多次被接受的更新，有害接受为0/63。全局对照达到0.713，低于静态智能体的0.775，因为局部有效的编辑可能干扰无关任务族。这些结果确立了范围匹配作为持久智能体记忆的一种互补控制：认证决定一项编辑是否得到支持，而检索范围决定该证据在何处授权其使用。

## Abstract
Persistent memory lets language-model agents improve prompts and skills without updating model weights. We show that matching retrieval scope to certification scope enables these edits to support reliable repeated adaptation across recurring task families. We study frozen-model agents on ProcStream-RSI, a 12-round code-repair stream, using Orthogonal Regression Control (ORC), an execution-grounded gate for persistent skill edits. In an intervention that holds proposals and gate decisions fixed, retrieving each accepted skill only for its originating family raises mean hidden trajectory utility from 0.713 under global memory to 0.816 and changes harmful deployments from six of eight to none. In 27 paired randomized-order streams, Scoped-ORC improves mean trajectory utility by 0.063 [0.037, 0.094] over Global-ORC, accepts 63 rather than 12 updates, and produces multiple accepted updates in 19/27 streams, with 0/63 harmful acceptances. The global control reaches 0.713, below the static agent's 0.775, because locally valid edits can interfere with unrelated families. These results establish scope matching as a complementary control for persistent agent memory: certification determines whether an edit is supported, while retrieval scope determines where that evidence authorizes its use.

# 《Scope Before You Persist: Preventing Cross-Family Interference in Agent Memory》论文总结

## 1. 核心问题与整体含义

- **研究背景**：大语言模型智能体可通过持久记忆（编辑提示词、技能策略）在不更新模型权重的情况下持续改进。然而，这种"自我改进"能否在**反复出现的任务族**之间可靠地迁移和复用，仍缺乏系统研究。
- **核心问题**：论文关注一个被忽视的部署问题——**认证范围与检索范围的不匹配**。在单一任务族内收集的证据（局部认证）可能证明某次编辑是有效的，但不足以证明它可以全局部署。
- **关键现象**：全局记忆中的"局部有效编辑"会干扰无关任务族，作者将这种现象命名为**跨族干扰（cross-family interference）**。实验显示全局部署下局部有效编辑使边界族效用提升 0.398，同时使缺失、旋转、平局打破、分块等族分别下降 −0.461、−0.234、−0.148、−0.117。
- **整体含义**：持久记忆需要两个独立决策——**更新是否被支持（认证）** 与**它应在何处生效（检索范围）**。范围匹配是持久智能体记忆的补充性控制手段，可把局部认证转化为可重复的"持续适应（continual adaptation）"。

## 2. 方法论

### 2.1 核心思想

- 冻结的 actor 每轮在发现任务上生成修复程序；同一冻结模型基于程序与可见失败编辑一个 **360 字符的技能策略**；门控（gate）决定是否部署提案。
- 关键干预：**只改变检索范围，保持提案、门控决策、程序与分数不变**，从而隔离"跨族暴露"这一机制。

### 2.2 关键组件

- **ProcStream-RSI 部署框架**：12 轮代码修复流，固定族顺序（boundary → rotation → ordering → normalization → boundary → rotation → nested → missing → prefix → chunk → tie-breaking → ordering），每族有种子派生的不透明协议令牌。
- **Orthogonal Regression Control (ORC) 门控**：
  - 每个任务有三条在线证据通道：4 个公开示例、4 个私有精确输出测试（不在 actor/editor 提示中）、≥6 个无答案的蜕变（metamorphic）检查。
  - 对候选减现任的通过率差值，按"当前族"与每个历史族分组，计算确定性的单侧 95% 配对自助法下界 $L_{g,c}$。
  - 部署条件（$\delta_{new}=0,\ \delta_{reg}=0.02$）：
    - $L_{current,pub} \ge -\delta_{reg}$
    - $L_{current,priv} > \delta_{new}$
    - $L_{current,meta} \ge -\delta_{reg}$
    - $L_{g,c} \ge -\delta_{reg}\ \forall g<t,\ \forall c$
    - 且私有/蜕变通道无"不安全程序"报告。
  - 采用通道级**合取**，防止某一通道的增益平均掉另一通道的退化。
- **Family-scoped 检索（Scoped-ORC）**：
  - 被接受的候选存入当前族的槽位；来自族 $f$ 的任务收到 $K_t(f)=K_t^{(f)}$（若存在已接受槽位），否则回退到初始策略 $K_0$。
  - 活动策略始终恰好 360 字符，仅改变供给哪条策略，不改变提示预算。

### 2.3 门控漂移命题

- 设提案有益概率 $\pi$、有益增益 $G$、有害损失 $L$，门控对有益/有害提案的接受率为 $\alpha$、$\beta$，则期望部署变化为正的条件为 $\pi\alpha G > (1-\pi)\beta L$。
- 在条件独立假设下，AND 门控的有害接受率为 $\prod_j \beta_j$；若各通道假接受事件相同，则增加通道不改变 $\beta$。因此**边际验证器精度不足，通道误差的独立性才是关键**。

## 3. 实验设计

### 3.1 数据集 / 场景与 Benchmark

- **主 Benchmark：ProcStream-RSI v3.1**——12 轮代码修复流，9 个代码契约族，每轮 4 个发现任务 + 4 个探针任务；每流含每族 1 个 checkpoint 与 2 个 final 任务，共 **123 个任务/流**。公开、私有、隐藏输入两两不相交，隐藏案例在线不可见。
- **外部迁移诊断**：固定 SHA-256 排序选出的 **32 个 HumanEval+ 任务**（无反馈评估）。
- **跨 actor 诊断**：GPT-OSS-120B 在每流 **18 任务 sealed final bank** 上评估，2,000 token 上限。
- **随机入口扩展（v4）**：18 个流，每个可能首族 2 个。
- **完全随机顺序扩展**：27 个流，每个首族恰好 3 个，12 轮全程。

### 3.2 对比方法（7 个配对方法）

| 方法 | 说明 |
|---|---|
| **Static** | 从不提案更新 |
| **Frozen-compute** | 做同样调用但不部署 |
| **Latest-only** | 部署每个非空、格式良好的提案 |
| **Self-judge** | actor 自估正确性，取均值更高者 |
| **Replay** | 当前公开增益 + 历史公开非退化 |
| **ORC** | 完整通道级门控 |
| **Batch-ORC** | 累积证据编辑，仅最终提案可部署 |

### 3.3 模型与运行配置

- Actor/editor：**Qwen3-Coder-Next**，Parasail BF16 端点经 OpenRouter，禁用 provider fallback，temperature 0，actor 700 token，editor 500 token。
- Batch-ORC 累积证据编辑器输入为 64,000 字符；其余为 48,000 字符；技能文本统一填充至 360 字符。
- 模型权重从不训练。

## 6. 主要结论与发现

- **全局部署劣于静态**：Global-ORC 平均轨迹效用 0.713，低于 Static 的 0.775；8 次接受中 6 次有害。
- **范围匹配带来核心提升**：固定提案与决策下，Scoped-ORC 平均轨迹效用 **0.816**（vs Global 0.713，Static 0.775），对 Global 配对优势 **0.103 [0.052, 0.151]，p=0.03125**，对 Static **0.041 [0.022, 0.056]，p=0.03125**；8 次局部接受更新**零有害**。
- **27 流扩展验证**：Scoped-ORC 轨迹效用 **0.848**，比 Global-ORC（0.785）高 **0.063 [0.037, 0.094]，p<10⁻⁴**；接受更新 **63 次 vs 12 次**，19/27 流多次接受（Global 仅 2/27），有害接受 **0/63 vs 6/12**。
- **证据通道诊断**：公开通道 AUROC 0.752，私有/蜕变通道 AUROC 0.998；但 8 次 ORC 接受在局部安全，仅 2 次提升下一全局 checkpoint，全局 PPV 从 1.00 降至 0.25。
- **核心原理**：认证决定编辑是否被支持，检索范围决定该证据在何处授权使用；二者匹配才能实现持续适应。

## 7. 优点

- **部署视角新颖**：评估完整部署谱系而非 archive-best checkpoint，更贴近真实持续适应场景。
- **固定输出干预设计干净**：仅改变检索范围，严格隔离"跨族暴露"机制，排除了编辑器/验证器强度差异的混淆。
- **执行接地门控**：结合公开、私有、蜕变三类通道，且采用通道级合取，避免单通道增益掩盖其他通道退化。

- **外部验证多元**：HumanEval+ 迁移 + 跨 actor（GPT-OSS）诊断 + 路由鲁棒性曲线。
