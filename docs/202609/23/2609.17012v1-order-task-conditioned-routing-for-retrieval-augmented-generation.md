## 摘要
检索增强生成（RAG）流水线通常依赖于在预处理阶段确定的固定索引与检索配置。这种一刀切的设计不适合领域专家场景，因为其中的异构查询需要不同的分块粒度、元数据约束和源选择策略。因此，对某一类查询有效的配置在其他查询上往往表现不佳。本文提出 ORDER（Optimal Routing for Dynamic Evidence Retrieval，动态证据检索最优路由），一种以查询为条件的 RAG 框架，可针对传入查询联合调整索引与检索。我们的方法首先在与语料库相关联的给定问题集上发现语义簇，并为每个簇学习一种分块策略以及合适的元数据过滤和重排序配置。在推理时，查询通过最近质心分配被路由到合适的预构建索引。为进一步提升检索效果，我们提出一种监督式查询路由器（QRe），用于预测哪些集合最可能包含相关证据，并结合一种均匀多源采样器（UMS），将检索预算均匀分配到所选来源上。我们在大规模异构历史档案上评估该框架，并表明在复杂专家领域环境中，同时以查询为条件来调节索引与检索，始终优于朴素基线以及强大的当前最优 RAG 系统。

## Abstract
Retrieval-Augmented Generation (RAG) pipelines typically rely on a fixed indexing and retrieval configuration determined at preprocessing time. This one-size-fits-all design is ill-suited to domain-expert settings, where heterogeneous queries require different chunking granularities, metadata constraints, and source-selection strategies. As a result, configurations that are effective for one family of queries often perform poorly for others. In this paper, we introduce ORDER (Optimal Routing for Dynamic Evidence Retrieval), a query-conditioned RAG framework that jointly adapts indexing and retrieval to the incoming query. Our approach first discovers semantic clusters over a given set of questions associated to a corpus and learns, for each cluster, a chunking strategy together with a suited metadata filtering and reranking configuration. At inference time, queries are routed to the appropriate pre-built index through nearest-centroid assignment. To further improve retrieval, we propose a supervised query router (QRe) that predicts which collections are most likely to contain relevant evidence, coupled with a Uniform Multi-source Sampler (UMS) that allocates the retrieval budget evenly across the selected sources. We evaluate our framework on large-scale, heterogeneous historical archives and show that conditioning both indexing and retrieval on the query consistently outperforms both naive baselines and strong state-of-the-art RAG systems in complex expert-domain environments.

- **一刀切 RAG 的困境**：传统检索增强生成（RAG）流水线在预处理阶段就固定了索引与检索配置（分块粒度、元数据约束、来源选择等）。这种“one-size-fits-all”设计在通用基准上表现尚可，但在领域专家场景下失效。
- **专家领域的异构性**：以历史研究为例，历史学家的问题并非可互换的——其意图与主题关切决定了他们寻找证据的方式。同一语料库中，不同问题族需要不同的分块粒度、元数据过滤与来源选择策略；对一类查询有效的配置，对另一类可能表现很差。
- **跨源多跳推理的挑战**：历史问答需要跨异构、严重不均衡的来源进行多跳推理。例如在 HistoriQA-ThirdRepublic 中，`Les Débats`（议会记录）体量是两份报纸总和的 30 倍以上，文档长度也高一个数量级，导致 top-k 余弦排序常常被主导语料“淹没”，无法保证多源证据被同时召回。
- **既有工作的两大弱点**：近期研究虽已开始重新审视索引与分块，但（i）分块与检索彼此独立优化；（ii）两者都独立于查询。图基 RAG（HippoRAGv2、LinearRAG）虽改善了离线索引，但分块仍是固定大小、查询无关，且图构建依赖 LLM 生成 token，成本高昂。
- **核心主张**：优化应沿两条轴拆分——**离线、文档条件化轴**（索引构建、策略发现）与**在线、查询条件化轴**（以极低代价将查询路由到最合适的配置）。ORDER 正是这一立场的操作化实现。

## 2. 方法论：核心思想与关键技术细节

### 2.1 总体框架
ORDER（Optimal Routing for Dynamic Evidence Retrieval）包含三个机制，均遵循“**离线策略发现 + 在线查询条件化路由**”的共同模式：
- **TC-Chunking**（任务条件化分块）
- **TC-Metadata**（任务条件化元数据选择）
- **Structured Retrieval**（结构化检索：QRe + UMS）

### 2.2 任务条件化索引（TC-Chunking / TC-Metadata）
**离线训练阶段**（Algorithm 1）：
1. 将训练问题嵌入，用 UMAP 降至 10 维，用 HDBSCAN 聚类（噪声组 -1 也作为常规簇参与）。
2. 对每个簇 c，在候选策略集 S 中，以 Coverage@3（k₀=3，与评测预算一致）为评分，选出最优策略 s\*(c)。
3. 计算每个簇的质心 μc。

**在线推理阶段**：
1. 将测试查询 q 嵌入，通过 UMAP 变换 T 投影到同一空间 zq。
2. 最近质心分配：`ĉ = argmin_c ‖zq − μc‖₂`。
3. 用该簇的预构建索引 s\*(ĉ) 以预算 k 检索。

**分块策略**：在 `Les Débats`（结构最复杂的集合）上定义 14 种策略，分四组：
- **A 组（基线）**：`10000_hierarchical`（生产基线，全大写标题+递归分割）、`baseline_10k`、`fixed_{500,1k,2k}`。
- **B 组（发言人）**：`S2_atomic`（每个发言轮次一段）、`S3_window3`（3 轮滑动窗口）、`S4_president`（总统介入）。
- **C 组（程序性）**：`S8_vote`（投票决议标记）、`S10_amendment`（修正案生命周期）。
- **D 组（主题）**：`S9_topic`、`S9_topic_noVotes`（去除点名投票名单）、`S11_hybrid`、`S11_hybrid_noVotes`。

**元数据策略**：同样 14 种，分三类：
- **Filter**（布尔谓词预过滤）：`exclude_noisy`（剔除 vote_list、absence_list、fragment 等噪声类型）、`debates_only`、`debates_and_legal`、`min_speakers_2`、`min_length_500`、`exclude_noisy_min_length`。
- **Rerank**（距离加性调整）：`rerank_type_boost`、`rerank_speaker_boost`、`rerank_combined`。
- **Hybrid**（过滤+重排）：`excl_noisy+spk`、`deb+legal+spk`、`deb+legal+cmb`、`triple+cmb`。

### 2.3 结构化检索（QRe + UMS）
每个查询 q 嵌入为 vq，扮演两个角色：(i) 作为监督式路由分类器 fθ 的输入；(ii) 作为集合内余弦排序的查询向量。

- **QRe（查询路由）**：3 类逻辑回归（sklearn 默认超参）预测来源对标签 `ŷq ∈ {G+I, I+D, G+D}`。路由映射 φ 将 ŷq 转为活跃集合 Aq。由于 I+D 和 G+D 映射到同一活跃集 `{G,I,D}`，φ 实际只有两个不同输出，即部署策略退化为**二分类决策“是否需要 Les Débats”**。所有查询都检索两份报纸，路由器只决定议会语料是否加入。
- **UMS（均匀多源采样器）**：针对多跳问题需要多源证据、纯距离排序可能被单一高分集合占满 top-k 的问题，UMS 强制等额配额：
  `qc = ⌊k/|C|⌋ + 1[RANK(c) ≤ k mod |C|]`
  即基础配额均分，余数槽位给全局最相关的集合。最终列表为各集合 TOPK 合并后按距离重排。
- **QRe & UMS 组合**：先在 Aq（而非全 C）上施加 UMS 配额——路由器先剔除无关集合，再在活跃集合间均分预算。两个机制针对**结构上不同的失败模式**：源污染（source contamination）vs. 源饥饿（source starvation）。

### 2.4 评测指标
- **Recall@k**：基于 ID，金标块精确 ID 出现在 top-k 才算命中，每问题得分 ∈ {0, 0.5, 1}。
- **Coverage@k**：基于文本，处理分块粒度不对称。对金标文档 g，若某检索块完全包含 tg 得 1；若检索块是 tg 的子串，则按字符比例累加；否则为 0。对金标文档和问题宏平均。

## 6. 主要结论与发现

### 检索层面（RQ1, RQ2）
- 三种 ORDER 配置在**所有 cutoff、所有问题类型**上均超越全部基线（朴素、词法、图基、索引时自适应）。
- **QRe & UMS 组合**：Recall@3 达 53.7（比 Naive 高 +16.0 个百分点，比 HippoRAGv2 高 +22.0），k=10 时仍领先 +16.9。
- **互补性**：QRe 与 UMS 针对结构上不同的失败模式。跨报纸问题上，Naive 崩溃（16.6@3，被 Débats 淹没），QRe 近乎三倍提升（48.7）；报纸↔Débats 问题上，Naive 已好（48.8），QRe 中性，UMS 带来提升（56.1，保证议会代表）。组合严格占优。
- **图基基线反常**：HippoRAGv2 和 LinearRAG 均低于朴素稠密检索器，尽管索引成本高得多（LLM 索引 pass）。图构建在异构、OCR 噪声语料上脆弱。

### 机制泛化性（RQ3）
- **检索器无关**：将稠密索引换成 BM25，QRe&UMS 仍将 BM25 从 30.7 提升到 57.0 Recall@5（+26.3）。
- **与索引时方法可组合**：Adaptive Chunking 单独仅 37.2 Recall@10（低于朴素基线 56.2），但叠加 ORDER 路由后升至 59.7，说明索引时自适应与检索时路由作用于不同轴。

### 索引条件化（RQ4）
- **TC-Chunking**：在 Naive 检索器下实现 +5.4 Coverage@3、+6.1 Recall@5（p<0.05）；但一旦路由激活，增益消失（≤−0.4 或 +0.2，不显著）。
- **增益消失的机制**：+5.4 的增益完全由“金标仅在报纸”的 36% 问题贡献（+16.2），而金标在 Débats 的问题为 −0.5。TC-Chunking 并非改善 Débats 内部检索，而是让 Débats 块在错误查询上“不那么有竞争力”，腾出槽位给真正的报纸金标（**噪声抑制通道**）。QRe 通过直接过滤 Débats 实现同一效果，因此吸收了这一增益。
- **TC-Metadata**：增益**在 UMS 下持续**（+6.0 Cov@3/Rec@3，p<0.05），因为议会块占据保证配额，过滤噪声文档类型直接受益。在 QRe 下消失（QRe 已预选掉噪声源）。
- **联合 14×14 变体**：匹配但从不严格优于 TC-Metadata（赢家诅咒 + 相关增益通道）。
