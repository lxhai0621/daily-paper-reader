## 摘要
检索增强生成（RAG）系统通常对所有查询采用固定的检索器和生成器配置，尽管查询复杂度和信息需求存在显著差异，这导致计算资源分配低效。虽然检索和生成的适应性已被独立研究，但它们对端到端 RAG 性能的联合影响仍未得到充分探索。我们系统分析了检索器和生成器复杂度在事实型与多跳问答（QA）任务（包括桥接和组合推理任务）中如何相互作用。分析表明，更强的检索通常比增加生成努力带来更大增益，但两者都呈现递减且非单调的回报，表明更高复杂度的配置并非在所有查询上都更优。受这些发现启发，我们提出 DRAG，一个用于选择检索器-生成器配置的查询自适应框架。我们首先提出 DRAG_QPP，一种免训练路由方法，利用查询性能预测（QPP）信号指导检索器选择，并基于检索上下文的困惑度度量指导生成器选择。我们进一步提出 DRAG_SFT，一种监督路由方法，通过微调 LLM 来联合预测检索器-生成器配置。在三个 LLM 系列和四个问答基准上，DRAG_QPP 在性能上与强静态 RAG 基线相当，同时显著降低推理延迟；而 DRAG_SFT 在有效性上持续优于静态和免训练自适应基线。总体而言，DRAG 表明联合自适应检索和生成相比静态 RAG 流程能实现更有利的有效性-效率权衡。

## Abstract
Retrieval-Augmented Generation (RAG) systems typically employ fixed retriever and generator configurations across queries, despite substantial differences in query complexity and information needs, leading to inefficient allocation of computational resources. While retrieval and generation adaptivity have been studied independently, their joint effect on end-to-end RAG performance remains underexplored. We systematically analyze how retriever and generator complexity interacts across factoid and multi-hop question answering (QA), including bridge and composition reasoning tasks. Our analysis shows that stronger retrieval generally yields larger gains than increased generation effort, but both exhibit diminishing and non-monotonic returns, indicating that higher-complexity configurations are not uniformly better across queries. Motivated by these findings, we introduce DRAG, a query-adaptive framework for selecting retriever-generator configurations. We first propose DRAG$_\text{QPP}$, a training-free routing approach that uses Query Performance Prediction (QPP) signals to guide retriever selection and perplexity-based measures over retrieved context to guide generator selection. We further introduce DRAG$_\text{SFT}$, a supervised routing approach that fine-tunes an LLM to jointly predict retriever-generator configurations. Across three LLM families and four QA benchmarks, \qpprag~achieves performance comparable to strong static RAG baselines while substantially reducing inference latency, whereas DRAG$_\text{SFT}$ consistently improves effectiveness over static and training-free adaptive baselines. Overall, DRAG demonstrates that jointly adapting retrieval and generation achieves a more favorable effectiveness-efficiency trade-off than static RAG pipelines.

## 1. 核心问题与研究动机

- **背景**：RAG 系统通过引入外部知识缓解 LLM 参数知识过时/缺失的问题，典型流程由**检索器**（如 BM25、E5 稠密检索）与**生成器**（如 LLaMA、GPT 系列）组成。
- **核心问题**：现有 RAG 系统对**所有查询统一采用固定的检索器-生成器配置**，但查询复杂度差异极大——从可用单文档回答的事实型问题，到需要跨多证据源推理的多跳、时序、数值聚合、多约束问题。
- **动机缺口**：
  - 简单查询用稀疏/稠密检索即可，无需昂贵重排；复杂查询才需要更强检索与推理。
  - 检索自适应与生成自适应此前多被**独立研究**，二者对**端到端 RAG 性能的联合影响尚未被系统探索**。
  - 更强的配置并非普遍更优（存在递减、非单调回报），因此"一刀切"会同时导致**算力浪费与效果次优**。
- **核心主张**：需要**查询自适应地联合选择检索器-生成器配置**，以优化**有效性-效率权衡（EET）**。

## 2. 方法论：DRAG 框架

### 2.1 问题形式化

- 给定查询 $q$、候选检索器集合 $\Theta=\{\theta_i\}$、候选生成器集合 $\Phi=\{\phi_i\}$，目标是选择配置 $(\theta,\phi)\in\Theta\times\Phi$，在满足效果阈值 $\delta$ 的前提下最小化延迟 $L(\theta,\phi)$。
- 由于推理时无真值答案，需构造估计器 $f:(q,\theta,\phi)\mapsto\mathbb{R}$ 预测答案正确性。
- 论文定义了**效率感知 Oracle**：为每个查询分配"能答对且最便宜"的配置（若 EM=1 不满足则用 F1≥0.8 阈值，否则回退到最高复杂度配置）。

### 2.2 DRAG_QPP（免训练路由）

将路由分解为两个顺序预测阶段：

- **检索器性能预测（RPP）**：
  - 使用**检索前（pre-retrieval）QPP 信号**，仅依赖查询文本与语料统计，无需相关性标注。
  - 采用 **Average IDF（Avg-IDF）** 作为信号 $\sigma(q)$：高 IDF（含罕见、高信息量词）表示查询更易检索，走轻量检索器；低分则升级到更强检索管线。
  - 阈值 $\{\tau_j\}$ 由训练集 Avg-IDF 分布的**百分位划分**得到（基百分位 $p$ + 均匀间隔 $\Delta$），实验中用 75/50/25 百分位区分 4 个检索级别。
  - 选择规则：$\theta^*(q)=\theta_i$，其中 $i=\min\{j:\sigma(q)\ge\tau_j\}$。
- **生成器性能预测（GPP）**：
  - 在已选检索器 $\theta^*$ 检索出的上下文上，计算**基础语言模型下的困惑度** $h(\theta^*_k(q)\mid q;\phi_j)$。
  - **低困惑度**表示上下文与模型参数分布一致，可用轻量生成器；**高困惑度**表示上下文噪声大、分布外，需升级到更强推理生成器。
  - 阈值 $\nu_i$ 取训练分布的第 $p$ 百分位（如 20th），推理时从低到高逐级比较，直到满足阈值或默认使用最高复杂度生成器。
- **特点**：完全免训练、轻量，但依赖数据特定的阈值标定。

### 2.3 DRAG_SFT（监督路由）

- 将路由建模为**监督映射** $\hat{P}: q\mapsto(\theta,\phi)$。
- 用 **Qwen3-4B-Instruct** 在构造的训练集 $D_{oracle}$（查询↔Oracle 最优配置标签）上微调。
- 输入为查询 + 指令模板 + 可用配置列表，输出结构化 JSON：`{"retriever": θ, "generator": ϕ}`。
- 推理时单次解码即预测配置，再执行对应检索与生成。
- **优点**：避免顺序路由与阈值标定；**代价**：需要监督数据，且带来额外延迟。

## 6. 主要结论与发现

1. **检索 vs. 生成的贡献不对称**：固定生成器时提升检索复杂度通常带来更大增益（多跳数据集尤为明显），而固定检索器时增加推理努力收益更小且不稳定——**推理无法弥补糟糕的检索**。
2. **回报递减且非单调**：检索复杂度从 High→Extra-High 在多数数据集上饱和甚至下降；高复杂度配置**不是低复杂度配置的严格超集**。
3. **效率代价高昂**：如 HotpotQA（GPT-OSS）上 $\phi_M\to\phi_H$ 仅使 EM 从 49.9 升至 51.6，但延迟从 2.34s 增至 4.36s。
4. **自适应优于静态**：
   - **DRAG_QPP** 在效果上与强静态 RAG 相当，但显著降低延迟（如 HotpotQA 决策开销仅 0.28s，总延迟 2.18s）。
   - **DRAG_SFT** 效果最佳，较 DRAG_QPP 提升约 **2–12%**，延迟增加约 **5–40%**，但仍优于 RAG max，逼近 Oracle。
5. **泛化性**：在 OOD 的 FRAMES 上两种 DRAG 均优于所有基线（含 DRAG AP），但 DRAG_SFT 的提升**并非总是统计显著**，跨数据集路由迁移仍具挑战。
6. **路由误差模式**：主要分为**高估**（简单查询被路由到昂贵配置，引入噪声）、**低估**（复杂查询算力不足导致事实错误）、**错误实体**（配置次优导致证据错误与实体混淆）三类。

## 7. 优点

- **问题定位新颖且有价值**：首次系统研究检索器与生成器复杂度对**端到端 RAG 的联合影响**，填补了此前"分别自适应"的研究空白。
- **双路线互补设计**：DRAG_QPP（免训练、轻量、阈值可解释）与 DRAG_SFT（监督、端到端学习、效果更强）覆盖不同监督与算力约束场景。
- **轻量高效的免训练方案**：仅用 Avg-IDF 与困惑度等**无需相关性标注**的信号，即可接近静态强基线并大幅降延迟，实用性强。
- **实验扎实**：3 个 LLM 家族、4 个基准、全量测试集、含 OOD 与统计显著性检验，并提供延迟分解与逐查询失败分析。
- **框架通用性**：明确声明对检索器/生成器数量与粒度**完全无关**，可扩展到更细/更粗的复杂度空间。
- **可复现**：公开数据集与代码链接。

## 8. 不足与局限

- **算力信息不完整**：未披露 GPU 数量、总训练时长与总计算开销，难以评估成本可复现性。
- **OOD 泛化有限**：仅一个 OOD 数据集（FRAMES），且 DRAG_SFT 在 OOD 上提升不总是显著，跨分布迁移能力仍待验证。
- **DRAG_QPP 依赖数据特定阈值**：阈值基于训练集百分位标定，换语料/换模型需重新校准，泛化性与稳健性受限。
- **DRAG_SFT 引入额外成本**：需构建 Oracle 训练集与微调，且推理延迟更高；监督信号依赖 Oracle 的阈值设定（F1≥0.8 等启发式）。
- **路由误差系统性存在**：高估/低估/错误实体三类失败均源于查询复杂度估计不准，说明查询表示与复杂度建模仍有改进空间。
- **模型覆盖偏窄**：仅评测开源模型（GPT-OSS/Qwen/Gemma），未涉及闭源商用 LLM；固定 $k=5$，未充分探索动态 top-k 与配置的联合优化。
- **未来方向（作者自述）**：需更富表达力的路由策略（更好刻画检索-生成的不可分交互）、更丰富监督信号与强化学习以优化成本-质量权衡。
