## 摘要
智能体记忆正成为长时程 AI 智能体不可或缺的能力，但许多现有系统依赖自回归 LLM 来控制记忆的组织、检索和使用方式，从而将昂贵的生成过程置于记忆操作的关键路径上。我们提出 Jev-Mem，一种受 System-One/System-Two 认知启发的全新智能体记忆架构。System One 负责快速、轻量的决策，而 System Two 则进行更缓慢、审慎的推理。Jev-Mem 通过专用的 System-One 控制平面、结构化的多关系记忆平面以及 System-Two 推理平面，将这种分工引入智能体记忆。System-One 控制器在构建阶段管理记忆类型划分与关系组织，并在检索阶段动态执行查询路由、检索预算分配、图遍历、候选评分和自适应停止。System Two 仅在复杂推理和答案合成时被调用。这种设计同时提升了记忆有效性和系统效率：在 LoCoMo 上，Jev-Mem 取得了 0.777 的 LLM-as-a-Judge 总体得分，相较最强基线相对提升 11.0%，同时将记忆构建时间降至 158 秒，比最快的竞争记忆系统提速 6.6 倍，并将平均查询延迟降至 0.93 秒，减少 36.7%。

## Abstract
Agentic memory is becoming essential for long-horizon AI agents, yet many existing systems rely on autoregressive LLMs to control how memories are organized, retrieved, and used, placing expensive generation on the critical path of memory operations. We introduce \textbf{\method}, a new agentic memory architecture inspired by System-One/System-Two cognition. System One captures fast, lightweight decision-making, whereas System Two performs slower, deliberative reasoning. Jev-Mem brings this division of labor to agentic memory through a dedicated System-One control plane, a structured multi-relational memory plane, and a System-Two reasoning plane. The System-One controller governs memory typing and relational organization during construction, and dynamically performs query routing, retrieval-budget allocation, graph traversal, candidate scoring, and adaptive stopping during retrieval. System Two is invoked only for complex reasoning and answer synthesis. This design improves both memory effectiveness and system efficiency: on LoCoMo Jev-Mem achieves an overall LLM-as-a-Judge score of 0.777, an 11.0\% relative improvement over the strongest baseline, while reducing memory construction time to 158\,s, a 6.6$\times$ speedup over the fastest competing memory system, and lowering average query latency to 0.93\,s, a 36.7\% reduction.

## 2. 方法论

### 2.1 核心思想与总体架构

- 架构由三层构成：**System-One 控制器**（轻量结构化决策）、**共享记忆数据平面**（多关系记忆）、**System-Two 推理模型**（复杂推理与答案合成）。
- 与现有系统不同，**写入与读取路径由同一个控制抽象统一管理**，而非"一套启发式写入 + 另一套启发式检索"。
- System Two 只在最终合成与需要开放式生成/深度推理时才被调用（如被显式升级的合并/摘要操作），**生成是结构化控制决策的可选后果，而非默认机制**。

### 2.2 类型化 System-One 控制接口

- 控制器抽象为 **J(S, Q)**：S 为结构化状态，Q 为一批显式决策问题。
- 输出形式有两种：对**独立命题**输出概率（Noul，值域 [0,1]）；对**互斥备选**输出选项分布（Choice，返回选中标签与选项分布）。
- 与自由文本提示词的关键差异：每个决策暴露**已知的小输出空间**，可直接表示为概率，无需生成中间自然语言再解析；**共享同一状态的多个决策可批量一次调用**。
- 论文明确指出：Jev 返回的分数**不被假定为已校准概率**；"独立性"指问题表述独立，而非统计独立。

### 2.3 记忆表示与写入路径

- 观察表示为 **o_t = (x_t, τ_t, μ_t)**（内容、可选时间戳、来源）；记忆为
  **M_t = ( V_t, {E^g_t}_{g∈G}, I^vec_t, I^lex_t )**，其中 **G = {semantic, temporal, causal, entity}**。
- 所有关系视图**共享同一套规范记忆节点 V_t**；同一对节点可同时存在多条类型化边；向量索引与词法索引提供互补入口——区别于"把同一观察复制到多个记忆库"或"每类关系独立建图"。
- **不设准入过滤**：每条有效非空观察都生成一个规范节点，避免在摄入阶段做出不可逆的"存/弃"决策而永久丢失当下看似无用、未来可能相关的信息；**选择性体现在结构构建与检索阶段**。
- **记忆类型预测**：控制器预测四个**可重叠**的特征分数 **t(v) = (t_episodic, t_semantic, t_procedural, t_preference)**，作为标注而非互斥分类；节点保留原始观察、来源、时间戳、嵌入、实体与类型分数。
- **候选发现与关系判定分离**（控制写入开销）：先用确定性信号（向量相似度、词法重叠、共享实体、时间邻近）取 Top-K_w 候选（实现中最多 10 个），控制器**只评估这些候选对**，避免与全部节点比较导致开销随记忆规模线性增长。
- **关系判定**：对每对 (v,u) 估计语义相关度、方向性因果影响、同事件（episode）归属，必要时做实体等价判定；**可靠结构信息可直接生成关系**（时间戳顺序→时间边；精确共享标识符→实体边），仅在时间顺序隐含时用 Choice 在 before/after/during/contains/overlaps/same_time/unknown 中选择；仅当 **P(g | v,u) ≥ θ_rel（实现取 0.60）** 才插入类型 g 的边。
- **写入路径流程**：**o_t → type → candidates → relations → M_t**。
- **周期性维护**：每 20 次成功写入，在有限邻域内评估冗余、矛盾、过时与新增链接价值；用 Choice 在 keep_separate / merge / promote / uncertain 中选择表示方式。**合并/提升保留原始观察**，只有选中 merge 或 promote 且概率 ≥ 0.85、矛盾分 < 0.85 时，才由外部 System-Two 摘要器生成新表示。

### 2.4 自适应检索（读取路径）

- **查询路由**：预测各关系视图相关度 **p(q) = {p_g(q)}_{g
