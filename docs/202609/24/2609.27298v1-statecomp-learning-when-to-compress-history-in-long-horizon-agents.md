## 摘要
长时程智能体在任务执行过程中会不断累积交互历史，然而过去交互的重要性会随着智能体状态的演化而变化。现有的上下文管理方法大多基于固定窗口、周期性调度或当前相关性来压缩历史，忽略了一个更根本的问题：过去的交互何时才变得可以安全替换？过早压缩可能会移除未来动作仍然需要的信息，而过度保守的保留则会导致大量上下文开销。为解决这一问题，我们提出状态条件压缩（State Conditioned Compression, StateComp），一个根据当前智能体状态判断历史交互何时可以被安全压缩的框架。StateComp 通过两阶段标注过程构建 KEEP 和 READY 监督，并在冻结语言模型的隐藏表示上训练一个不平衡感知路由器。有界状态表示进一步降低了评估长历史的成本，同时在执行过程中将相邻的 READY 交互分组为连续片段，并用紧凑摘要进行替换。在 WorkBuddyBench 上的实验表明，StateComp 在保持任务性能的同时将智能体和摘要总 token 数减少 52.27%，并在表示提取上实现了 12.67 倍加速。

## Abstract
Long-horizon agents continuously accumulate interaction history during task execution, yet the importance of past interactions changes as the agent state evolves. Existing context management methods largely compress history based on fixed windows, periodic schedules, or current relevance, overlooking a more fundamental question: when has a past interaction become safe to replace? Premature compression may remove information still needed for future actions, while overly conservative retention leads to substantial context overhead. To address this, we propose State Conditioned Compression (StateComp), a framework that determines when historical interactions can be safely compressed according to the current agent state. StateComp constructs KEEP and READY supervision through a two-stage annotation procedure and trains an imbalance-aware router on hidden representations from a frozen language model. A bounded state representation further reduces the cost of evaluating long histories, while adjacent READY interactions are grouped into continuous spans and replaced with compact summaries during execution. Experiments on WorkBuddyBench show that StateComp reduces total agent and summarization tokens by 52.27% while maintaining task performance, and achieves a 12.67-fold speedup in representation extraction.

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想
- 以**完整交互** $S_i=(R_i,A_i,O_i)$（推理、动作、观察）为基本单位，保证工具调用与响应成对。
- 标签 $y_{i,k}=0$ 表示 KEEP（需保留原文），$y_{i,k}=1$ 表示 READY（原文可被准确摘要替换）。标签不是 $S_i$ 的固有属性，而是 **"历史交互 × 当前状态" 的联合属性**。
- 为每个交互确定**最早安全压缩点** $t_i^*$：$y_{i,k}=0\ (k<t_i^*)$，$y_{i,k}=1\ (k\ge t_i^*)$；若无支持点则 $t_i^*=\infty$ 全程保留。该单调性只是对已标注轨迹的编码，不是对未来所有轨迹的保证，故在线预测需在有效历史变化后重新计算。

### 2.2 两阶段标注（构建监督）
- **Stage 1（逐检查点独立标注）**：对每个检查点记录任务进展、观察复杂度、下一步子任务需求、目标交互的剩余效用、支持证据位置、初始 KEEP/READY 判断，以及**未来依赖否决项（veto）**。要求正例证据必须已存在于当前前缀 $P_k$ 中；未来交互只能"否决"某次替换，不能用来证明更早的删除是安全的。
- **Stage 2（边界复核）**：汇总同一交互在各检查点的初始判断，复核证据，挑选**最早被支持的压缩边界** $t_i^*$；未解决者保持 KEEP。此设计将"局部证据收集"与"最终边界确定"分离，避免把首次 READY 标签一路传播到后续所有状态。
- **数据规模**：300 条轨迹、7,931 个记录状态、244,526 个交互–状态对（其中 READY 15,633 个，正例率 π≈0.0639）；1,832 个历史交互获得支持边界，6,099 个无支持边界。数据高度不平衡（全判 KEEP 即约 93.61% 准确率）。

### 2.3 路由器与隐藏状态表示
- 使用**冻结语言模型**的隐藏表示：历史交互末 token 向量 $h_i$、当前状态向量 $q_k$（最终 prompt 位置）、以及前缀内聚合历史特征 $r_{i,k}$，拼接为 $x_{i,k}=[h_i;q_k;r_{i,k}]$，输出 $p_{i,k}=\sigma(g_\theta(x_{i,k}))$。
- 理论上论证**因果前缀不变性**：追加 token 不会改变已有前缀隐藏状态，因此状态依赖性必须由 $q_k$ 或"目标+当前上下文"的新构造输入提供。
- **有界表示**：为每个待评估交互构造独立短视图（目标交互 + 当前状态 + 有限有效历史），预算 $M=5{,}120$ token（4,096 基础 + 最多 1,024 目标 token），参考构造为 Recent4。有界化只改变特征计算上下文，不限制被重估的历史交互范围（无近期窗口限制）。
- **不平衡感知训练**：加权 BCE，$w_0=1$、$w_1$ 可调（实验取 10）。理论给出加权分数与真实后验的关系 $\text{logit}\,p^*=\text{logit}\,\eta+\log(w_1/w_0)$，以及代价敏感最优阈值 $\eta_0=C_{unsafe}/(C_{unsafe}+C_{miss})$。强调类别加权改变损失、阈值决定运行点，二者角色不同。
- **在线实现**：冻结 Qwen3.5-9B，取 Layer 32 末 token 读出；路由器输入为 12,288 维（候选交互向量 + 当前检查点向量 + 同前缀 Top4 历史向量均值），单隐层宽 2,048、dropout 0.3。

### 2.4 路由与跨度执行门控（预测与执行解耦）
- 分数 ≥ τ 的交互成为候选；相邻候选合并为极大连续跨度，KEEP 交互或已提交摘要会**打断跨度**。
- 执行条件（公式 2）：$\min_{i\in B}p_{i,k}\ge\tau$、$|B|>\kappa$、$\text{Tokens}(B)\ge B_{min}$，取 τ=0.60、κ=3、$B_{min}$=1,000。即跨度至少含 4 个完整交互、源长度至少 1,000 token。
- 设计动机：小片段摘要的辅助调用成本可能高于节省量；合并相邻交互使摘要源更连贯；延迟小改写可减少 KV 缓存反复失效（论文明确不宣称必然提升缓存命中率或端到端延迟）。

### 2.5 有效历史的状态化更新（闭环）
- 每个合格跨度生成一个摘要（保留事实、约束、位置、已确认结论、失败原因、未决项），**仅当序列化后仍协议合法且确实更短**时才提交替换。
- 提交后，后续动作与路由都基于更新后的有效历史；**不做外部原文检索**。若路由或校验失败，回退到上一个有效历史；摘要失败则保留原跨度。原始轨迹单独留存仅供审计，不参与在线控制。
