## 摘要
当今的智能体常常执行依赖长期记忆和随时间进行上下文回忆的真实世界动作。然而，现有大多数记忆基准都是为对话式问答格式构建的，在这种格式中，问题本身已表明必须检索某个事实，而且往往还指明了是哪一个事实。此外，基准很少要求提交结果在准确率之外达到其他指标，这使得记忆系统能够为获得更高分数而做出不合理的成本/时间权衡。我们提出 DolphinBench，一个通过智能体的任务完成情况直接评估记忆的基准。DolphinBench 包含三个知识工作角色，每个角色约有 50 万 token 的用户消息，并在依赖该历史信息的任务上评估智能体。我们通过在有和没有相关历史的情况下运行智能体来验证每个角色的全部 200 个任务，要求有历史时成功且无历史时失败。最后，我们要求所有评估在报告准确率的同时报告总成本和延迟，这使我们能够全面地评估智能体记忆系统。现有记忆基准都没有同时结合这三点。数据集和评估代码可在 https://dolphinbench.ai 获取。

## Abstract
Agents today often take real-world actions that depend on long-term memory and context recall over time. However, most current memory benchmarks are built for a conversational question-answer format, where the question itself signals that some fact must be retrieved, and often which one. Moreover, benchmarks rarely require anything beyond accuracy from submissions, allowing memory systems to make unreasonable cost/time tradeoffs to achieve higher scores.   We present DolphinBench, a benchmark that evaluates memory directly through an agent's task completion. DolphinBench includes three knowledge-work personas with roughly 500k tokens of user messages per persona and evaluates agents on tasks that depend on information from that history. We verify all 200 tasks per persona by running an agent with and without the relevant history, requiring success with it and failure without it.   Finally, we require all evaluations to report total cost and latency alongside accuracy, which enables us to evaluate agent memory systems holistically. No existing memory benchmark combines all three. The dataset and evaluation code are available at https://dolphinbench.ai.

## 1. 核心问题与整体含义
- **研究动机**：智能体越来越多执行依赖长期记忆的真实任务，但现有记忆基准多采用对话式问答（QA）格式。问题本身已暗示“需要检索某个事实”，甚至点明是哪一个事实，导致评测从“是否意识到要回忆”这一最难步骤之后才开始。
- **另一关键缺陷**：多数基准只要求准确率，不要求成本与延迟，记忆系统可能通过重读全部历史、调用昂贵模型等方式刷高分，做出生产环境不可持续的权衡。
- **有效性风险**：许多合成基准存在答案键错误、证据标注错误、问题不可解等缺陷，且未证明任务确实依赖记忆，可能“无记忆也能通过”。
- **整体含义**：论文提出 **DolphinBench**，通过智能体的任务完成动作直接评测记忆，并要求同时报告准确率、总成本和中位延迟；每个任务还需通过“有相关历史则成功、无相关历史则失败”的验证。目标是绘制智能体记忆系统的帕累托前沿，推动更贴近真实部署的综合评测。

## 2. 方法论
- **核心思想**：不用“问事实—答事实”的 QA 形式，而是让智能体在模拟知识工作场景中执行动作；正确动作依赖其此前摄入的长期历史信息。
- **三个知识工作角色**：
  - Morgan：初创公司 CEO，涉及投资人、招聘、董事会沟通、战略。
  - Alex：基础设施工程师，涉及部署、事故、值班、运维手册。
  - Riley：产品经理，涉及实验、漏斗、留存。
- **构建流程**（文字化算法流程）：
  1. **Personas**：定义角色、关系、工具（日历、邮件、CRM、部署工具等），随历史演进更新。
  2. **History Planning**：LLM 先规划多年叙事，再拆成季度计划、每周事件与对话，明确日期、联系原因、分享/询问内容。
  3. **History Generation**：先更新模拟应用记录，LLM 生成所需工具调用与参数并按时间执行；再基于应用记录、工具输出、周计划、相关事实和先前消息，以角色口吻撰写用户消息。只写用户侧，智能体回复由被测系统生成。
  4. **Test Construction**：LLM 基于历史事实、工具说明、评测日期等提出任务，指定所需事实、预期动作、缺少历史时会缺失或出错之处；再生成用户请求与评分检查。请求提供行动所需信息，但不直接暴露要回忆的细节，避免“我通常那样做”等提示。
  5. **Test Verification**：对每个测试，用 GPT-5.6-Luna 在提供 oracle 历史消息时运行两次，要求全部通过；在不提供相关历史时运行两次，要求全部失败。还需人工检查失败确实源于缺少信息，而非工具错误或测试缺陷。
- **评分与指标**：
  - 评分检查包括 **LLM judge**（GPT-5.6-Sol）判断语义等价，以及 **确定性检查**（工具是否调用、标识符/数字/日期/列表是否匹配等）。
  - 每个要求必须满足；例如邮件必须在同一次发送调用中同时满足收件人和内容要求，两个邮件不能由一次发送冒充。
  - 任务通过条件是所有检查均通过。
  - 必须报告：**准确率**、**总成本**（摄入+测试+记忆处理）、**中位任务延迟**。

## 6. 主要结论与发现
- 最高分配置为 **Hermes + Mem0 + GPT-5.6-Luna**，准确率 **70.67%**，总成本 **$96.21**，中位延迟 **37.69 秒**。
- 更准确不一定更慢：同一 Hermes+GPT-5.6-Luna 下，Mem0 相比内置记忆准确率提高约 5 个百分点，中位延迟从 44.35 秒降至 37.69 秒，但总成本从 $61.48 升至 $96.21。
- 更便宜也不一定更差：Hindsight 成本 $84.65，低于 Honcho 的 $142.85，准确率高 1 个百分点，但延迟更长（55.31 秒 vs 44.66 秒）。
- 记忆系统排名随 harness/模型变化：Mem0 在两个 Hermes 模型中最高，Honcho 在 Claude Code + Claude Sonnet 5 中最高。
- 最贵配置并不最准或最快；Claude Code + Claude Sonnet 5 成本高达 $1,132–$1,830，但准确率仅 26.33%–35.83%。
- 整体结论：应同时比较准确率、成本、延迟，用帕累托前沿视角选择记忆系统配置。

## 7. 优点
- **动作式评测**：移除 QA 中“问题即检索提示”的偏差，要求智能体自行意识到需要记忆。
- **可解性验证严格**：每个测试必须“有相关历史通过、无相关历史失败”，降低错误答案键和无效测试风险。
- **强制成本与延迟报告**：避免记忆系统以不合理成本/时间换准确率，支持生产视角权衡。
- **构建流程系统化**：角色、历史、应用记录、任务、评分检查分层生成，并核对事实来源。
- **只生成用户侧消息**：更贴近智能体参与对话的真实情况，而非让系统阅读固定双人转录。
- **模拟应用可复现**：工具调用和应用状态被模拟，便于重复实验和确定性检查。

## 8. 不足与局限
- **合成数据偏差**：历史由 LLM 生成，可能缺少真实用户的写作风格、语言多样性、交互模式。
- **领域覆盖窄**：仅 3 个知识工作角色，未覆盖法律、医疗、长期客户支持等。
- **模拟环境简化**：应用非真实服务，未完全复现生产系统故障、其他用户并发修改等复杂情况。
- **任务偏短**：每个任务通常 1–4 个独立评分动作，未充分测试跨多步依赖的长流程记忆使用。
- **摄入与测试分离**：智能体先完整处理历史再测试，未评估持续到达的新对话与任务交织场景。
- **评测成本与外部有效性**：成本受 API 定价影响，延迟受服务负载影响；不同 harness/模型混在一起，跨组结论需谨慎。
- **缺少算力与训练细节**：未报告 GPU 型号、数量、训练/推理硬件规模，难以评估可复现性与资源门槛。
- **LLM judge 风险**：部分评分依赖 LLM judge，虽要求语义等价，但仍可能引入判断偏差。
