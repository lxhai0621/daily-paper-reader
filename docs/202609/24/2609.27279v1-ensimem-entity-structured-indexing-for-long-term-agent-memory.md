## 摘要
一个长期与用户交互的智能体必须从不断增长的交互历史中回忆事实、偏好、事件及其变化。现有记忆系统通常将交互压缩为通用摘要，或检索匿名文本片段，使智能体难以识别正确的实体、属性及支撑证据。我们提出 EnSIMem，一种面向智能体的实体结构化长期记忆架构。在离线构建阶段，系统将交互组织为主题连贯的情节，并构建基于对话的索引条目，形式为 [实体][实体类型][属性:值]。每个条目保留其源对话轮次、时间信息以及可用的多模态字段。在线交互期间，智能体的请求被分解为证据需求，其属性与记忆索引对齐。随后，实体-属性查找与自适应检索会收集点式、时序、组合与聚合推理所需的证据。智能体基于保留的源证据而非有损的记忆摘要生成响应。在长期智能体记忆基准上，EnSIMem 在保持紧凑上下文和良好在线效率的同时实现了高回答准确率。这些结果表明，实体结构化索引和情节级溯源为智能体的长期记忆提供了可靠基础。我们模型的代码可在 https://github.com/RamonMeng/EnSIMem 获取。

## Abstract
An agent that interacts with users over long periods must recall facts, preferences, events, and changes from a continuously growing interaction history. Existing memory systems often compress interactions into generic summaries or retrieve anonymous text chunks, making it difficult for an agent to identify the correct entity, property, and supporting evidence. We present EnSIMem, an entity-structured long-term memory architecture for an agent. During offline construction, the system organizes interactions into theme-coherent episodes and builds dialogue-grounded index entries of the form [entity][entity type][property:value]. Each entry preserves its source turns, temporal information, and available multimodal fields. During online interaction, the agent's request is decomposed into evidence requirements whose properties are aligned with the memory index. Entity-property lookup and adaptive retrieval then collect the evidence needed for point, temporal, compositional, and aggregation reasoning. The agent generates its response from the preserved source evidence rather than from lossy memory summaries. On long-term agent-memory benchmarks, EnSIMem achieves high answer accuracy while maintaining compact contexts and favorable online efficiency. These results show that entity-structured indexing and episode-level provenance provide a reliable foundation for long-term memory in agents. The code of our model is available at https://github.com/RamonMeng/EnSIMem.

## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：长期运行的智能体需要从持续增长的交互历史中回忆事实、偏好、事件及其变化。但现有记忆系统存在"可扩展性与特异性"的矛盾：
  - **全量上下文**：证据完整，但上下文膨胀、延迟升高、注意力被稀释（"lost in the middle"）。
  - **摘要压缩**：降低上下文长度，却会丢失细节、时间限定词与溯源信息。
  - **传统 RAG / 向量近邻检索**：返回匿名文本块，无法显式说明"是哪个实体、哪条属性、哪个事件"使该记忆相关。
- **关键难点**：相关信息分散在多次交互中，且表达形式不同（同义改写、代词、相对时间、多模态观察）。例如一次交互说"某人乘直升机去芝加哥"，后续提问只说"如何前往芝加哥"，系统必须能连接二者，同时**不能把事件塌缩为"活动""出行"这类无信息量的泛化类别**。
- **整体含义/设计哲学**：论文把长期对话记忆重新表述为一个**短上下文推理问题**——用结构作为记忆的**寻址系统（address system）**，而不是作为原始交互的有损替代品。索引负责"去哪里找"，原始对话片段负责"如何解释与作答"，从而实现高效访问与证据可溯源性的统一。
- **延伸意义**：论文认为该证据保留式设计可作为向程序性记忆、语义记忆扩展的基础。

## 2. 方法论

### 2.1 总体框架与形式化

- 系统分为**离线、与查询无关的记忆构建**和**在线、依赖查询的记忆访问**两部分：

  - `M = F_memory(D)`（持久、查询无关的记忆表示）
  - `ŷ = G(q, R(q, M))`（检索过程 R + 生成过程 G）
- 与已有方法不同，EnSIMem 把索引记录视为**寻址句柄**，最终答案必须从展开的原始证据生成。
- 无需额外训练或监督，整条流水线由 LLM 提示驱动 + 确定性检索操作组成。

### 2.2 主题连贯的情节化记忆（Theme-Coherent Episodic Memory）

- 将相邻对话轮次划分为**连续、主题连贯的情节（episode）**，而非以单轮或整个会话为检索单元：

  - `Π(Sn) = (en,1, …, en,mn)`，要求**完整覆盖、互不重叠**（∪ en,j = Sn，en,j ∩ en,k = ∅）。
- 分割策略（查询无关、无监督）：
  - 共享实体、事件、目标或未解决的指代时保持同段；
  - 仅当出现**持续性的新话题/新任务**时才切分；
  - **说话人变化本身不触发切分**；
  - 多模态字段始终附着在引入它的轮次上。
- 定位为"单轮"与"整会话"之间的中间粒度：单轮会丢失指代上下文，整会话会混入无关话题与噪声。

### 2.3 对话接地的实体–属性索引

- 对每个情节抽取**显式提及的实体**与显著事件（人、物、地点、活动、命名事件），并关联局部对话支持的属性/关系。
- 记录形式：`r = ⟨x, t, p, v, e, π⟩`（实体、类型、属性、可选具体值、所属情节、溯源链接）。
- 面向检索的索引：`[x][t][p:v] → {episode id}`。
  - 例：`[Caroline][person][research: adoption agencies] → {e}`。
- 值在情节给出具体实现时保留，否则为空。**记录只用于定位，答案仍须回到源情节读取**（保留时间、对话与多模态信息）。

### 2.4 粒度受控的属性对齐

- 核心要求：语料侧与查询侧抽取的属性必须**粒度兼容**。
  - 过窄 → 语义等价表达无法匹配，召回下降；
  - 过宽 → 无法区分（如把 research、上课、踢球都映射为 activity）。
- 做法：属性抽取视为**受控抽象**——属性承载检索所需的语义关系，值保留具体实现；不依赖固定的数据集专属本体，而是按"兼容语义粒度"生成并通过**兼容性而非精确字符串匹配**比较。
- 效果：`took a helicopter to Chicago` 与 `traveled to Chicago` 可共享 travel 类检索属性，同时具体交通方式保留在值中；不相关动作因未被塌缩为通用属性而保持可区分。

### 2.5 需求感知的查询规划

- 将请求分解为原子检索需求集合：`H(q) = {h1, …, hK}`，其中 `hi = (xi, ti, pi, vi, ci, ρi)`（目标实体、类型、中间粒度属性、可选值/条件、证据在回答中扮演的角色）。
- 同时分类推理类型，并据此**在检索开始前确定证据预算**：
  - **点式（point）**：少量相关情节即可；
  - **时序（temporal）**：证据需按时间排序或比较；
  - **组合（compositional）**：需多个相关属性/实体；
  - **聚合/频次（aggregation/frequency）**：必须收集全部相关情节后再计数或比较（如"How often did Sam get health checkups?"不能当作普通 top-k 问题）。

### 2.6 需求覆盖式检索

- 检索公式：`E(q) = Dedup(Structured(I, H(q)) ∪ Dense(T, H(q)))`
  - **结构化路径**：在实体–属性索引上做实体/类型/属性/值/条件匹配，提供精确"地址"；
  - **稠密回退**：在索引文本表示上做语义检索，当结构化路径不完整或措辞不同时保护召回；
  - 两路互补，按情节身份去重合并，并**跟踪哪些需求已被覆盖**。
- **停止条件由证据需求决定，而非固定的相似度阈值**：
  - 点式问题少量证据即可停止；
  - 时序/组合问题持续到比较或推理桥被支持；
  - 聚合/频次问题使用**穷尽式停止条件**。

### 2.7 证据接地的智能体响应

- 检索后把选中情节**展开为源证据**（轮次文本、说话人、时间、可用多模态字段）：`ŷ = G(q, H(q), Γ(E(q)))`。
- 生成阶段只依赖源证据，不依赖索引记录本身：显式事实直接作答，证据不足时承认不确定，时间措辞保持源的精度，聚合跨情节计算。
- 示例：问"What did Caroline research?" → 规划器识别实体 Caroline 与属性 research → 索引指向其自述"researching adoption agencies"的情节 → 展开后回答"adoption agencies"。
- 图像说明、与图像相关的查询或图像 URL 中若含对话文本没有的信息，同样会被保留使用。

### 2.8 离线/在线分离

- 离线：把交互语料转为可复用、带溯源的索引化记忆；
- 在线：按请求选取"需求已覆盖"的情节集合并展开为紧凑证据缓冲；
- 好处：长历史可跨请求复用，每次在线推理上下文聚焦且有据可依，且整条管道可审计（从查询需求 → 实体–属性访问路径 → 支持它的对话轮次与多模态观察）。
