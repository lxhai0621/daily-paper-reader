## 摘要
智能体记忆系统通过复用过往经验来提升未来性能，但大多数现有设计在写入时整理记忆：一旦任务完成，其轨迹就被提炼为固定产物，如反思、工作流、技能或推理策略，之后通过相似度检索。这迫使系统在未知未来查询之前就决定什么值得记住，不可逆地丢弃信息，并产生一个与查询无关的摘要，而该摘要必须服务于许多可能的下游任务。学习这样的写入时整理器也很困难，因为存储决策的价值可能只有在相关查询到来时才会显现，而这可能是在许多任务之后，从而形成长时程的信用分配问题。我们则保留原始轨迹，并将整理推迟到读取时，此时当前任务已知。给定检索到的轨迹和新任务，记忆整理器会合成一个紧凑、任务自适应的载荷，以适应当前需求。由于该载荷在同一任务上被消费，整理器可以直接根据即时任务成功进行训练，避免延迟的效用信号以及人为对相关任务进行分组的需求。在 ALFWorld、WebShop 和 $τ^2$-bench 上，我们的即时记忆（JitMem）持续优于无记忆智能体以及启发式和学习的写入时记忆方法，分别比最强基线提升了 16.2、16.3 和 3.9 个绝对成功率点。值得注意的是，即使未训练的记忆整理器也已能与这些基线相竞争或超越它们，表明任务自适应的读取时整理本身就是主要增益来源；训练整理器则进一步放大了改进。

## Abstract
Agentic memory systems reuse past experience to improve future performance, yet most existing designs curate memory at write time: once a task is completed, its trajectory is distilled into a fixed artifact, such as a reflection, workflow, skill, or reasoning strategy, that is later retrieved by similarity. This forces the system to decide what is worth remembering before the future query is known, irreversibly discarding information and producing a query-independent summary that must serve many possible downstream tasks. Learning such a write-time curator is also difficult because the value of a storage decision may only become apparent when a relevant query arrives, potentially many tasks later, creating a long-horizon credit-assignment problem. We instead retain raw trajectories and defer curation until read time, when the current task is known. Given the retrieved traces and the new task, a memory curator synthesizes a compact, task-adaptive payload tailored to the immediate need. Because this payload is consumed on the same task, the curator can be trained directly from immediate task success, avoiding delayed utility signals and the need to artificially group related tasks. Across ALFWorld, WebShop, and $τ^2$-bench, our Just-in-Time Memory (JitMem) consistently outperforms no-memory agents as well as heuristic and learned write-time memory methods, improving over the strongest baseline by 16.2, 16.3, and 3.9 absolute success-rate points, respectively. Notably, even an untrained curator is already competitive with or surpasses these baselines, showing that task-adaptive read-time curation itself is a major source of the gain; training the curator further compounds the improvement.

# 论文总结：Just-in-Time Memory（JitMem）

## 1. 核心问题与整体含义

- **研究背景**：LLM 智能体越来越多地被期望连续解决一系列随时间展开的任务，而非孤立问题。复用过往轨迹经验是提升未来性能的关键，由此催生了“智能体记忆”研究。
- **核心问题**：现有记忆系统普遍采用**写入时策展（write-time curation）**——任务完成后立即将轨迹蒸馏为固定产物（反思、工作流、技能、推理策略等），未来仅靠相似度检索。这带来两个根本代价：
  - **信息损失过早且不可逆**：写入时丢弃的细节，未来依赖它的任务无法恢复。
  - **单一固定产物需服务多种未来查询**：同一轨迹可能包含多种可用“教训”（如状态转换模式 vs. 物体放置策略），究竟哪种有用取决于下游任务，而写入时未知。
- **学习困难**：写入时策展器的价值可能需等待许多任务后的相关查询才显现，形成**长时程信用分配问题**；已有工作（如 SkillOS）不得不人为分组相关任务来制造延迟学习信号。
- **整体含义**：论文主张从“写入时策展”转向**读取时策展（read-time / just-in-time curation）**，在已知当前任务的时刻再对原始轨迹进行任务自适应蒸馏。

## 2. 方法论

### 核心思想
- **存储与策展分离**：记忆库只存储**原始、未抽象的完整轨迹**（任务描述 + 完整观察-动作序列），写入时不丢弃任何信息。
- **读取时合成任务自适应载荷**：新任务到来时，检索器取出相关轨迹，策展器**联合读取轨迹与当前任务**，合成紧凑的自然语言载荷 $p_t$；同一轨迹对不同任务可产生不同载荷，体现“重构性记忆”的认知科学观点。

### 系统组成与流程（四步）
1. **Retrieve（检索）**：$\hat{\xi}_t = R(x_t, M_t)$，用 BM25 仅基于任务描述取 top-k 原始轨迹。
2. **Curate（策展）**：$p_t = \pi_\phi(x_t, \hat{\xi}_t)$，策展器输出紧凑、任务条件的载荷（识别相关经验、抽取有效策略、给出当前任务的具体指引）。
3. **Execute（执行）**：$(\xi_t, r_t) = \pi_L(x_t, p_t)$，冻结的执行器在上下文中注入载荷并完成任务。
4. **Update（更新）**：$M_{t+1} = \text{UPDATE}(M_t, \xi_t, r_t)$，仅当 LLM-as-judge 判定成功时追加轨迹。载荷 $p_t$ 本身是临时的，不存储。

### 训练细节（GRPO）
- 对每个训练任务采样 G 个候选载荷 $\{p_t^{(i)}\}$，冻结执行器分别尝试任务并返回任务奖励 $r_t^{(i)}$。
- 采用**无标准差归一化**的 GRPO 优势：$\hat{A}_i = r_t^{(i)} - \text{mean}_j r_t^{(j)}$。
- 损失函数：$\mathcal{L}_{\text{GRPO}} = -\frac{1}{G}\sum_i \hat{A}_i \cdot \log \pi_\phi(p_t^{(i)} | x_t, \hat{\xi}_t)$，无价值网络。
- **关键性质**：奖励 $r_t$ 是同一任务载荷 $p_t$ 的直接函数，**策展动作与奖励之间时间间隔为零**，信用分配退化为单步，无需任务分组或延迟回报机制。
- 训练时使用**固定训练库**（用基础执行器跑训练集、以真实标签筛选成功轨迹），保证学习信号稳定；测试时记忆库在线增长。
- 执行器 $\pi_L$ 全程冻结，使系统模块化，一个训练好的策展器可服务多个执行器。

## 3. 实验设计

### 数据集 / 场景与 Benchmark
- **ALFWorld**：文本化具身控制，140 个测试任务。
- **WebShop**：网页商品购买，500 个测试实例；报告 SR 与平均分数。
- **τ²-bench**：对话式工具使用，涵盖航空、零售、电信三个领域（多轮对话 + 工具调用 + 领域政策约束）。

### 对比方法
- **无记忆智能体**：仅冻结执行器。
- **写入时记忆基线**：
  - ReasoningBank：蒸馏可迁移推理策略（启发式）。
  - MemP：多粒度记忆项。
  - SkillOS：用 RL + 复合奖励在分组任务流上训练技能策展器（学习式）。
- 各基线提供 `-base`（同基座模型不训练）与 `-gpt/-gemini`（强提示模型零样本策展）变体。
- **执行器**：Qwen3-8B、Gemini-2.5-Pro、GPT-5.4 三种冻结执行器。
- **JitMem 变体**：`-base`（未训练）、`-gpt/-gemini`（强提示模型）、RL 训练版。

### 训练配置
- 策展器从 Qwen3-8B 初始化（禁用思考模式），GRPO 训练 100 步，学习率 $1\times10^{-6}$，batch size 32，group size 8；训练时用 Qwen3-8B 作执行器。
- 检索 k=3，评测批大小 10（ALFWorld/WebShop）、5（τ²-bench）。

## 4. 资源与算力

## 6. 主要结论与发现

- **读取时策展优于写入时策展**：在三种执行器下，JitMem 较最强基线分别提升 **16.2（ALFWorld）、16.3（WebShop）、3.9（τ²-bench）** 个绝对成功率点。
- **未训练策展器已具竞争力**：即使不训练，读取时策展也常与写入时方法持平或更优（如 WebShop 上 JitMem-gemini 达 61.0 SR vs. SkillOS 41.0），说明**任务自适应读取时策展本身是主要增益来源**；RL 训练进一步叠加提升。
- **弱策展器可胜强策展器**：GPT-5.4 执行器下，用 Qwen3-8B 策展器的 JitMem-base（79.3）超过用 GPT-5.4 的 ReasoningBank（77.9）与 SkillOS-gpt（70.0），证明增益源于策展时机而非模型强度。
- **执行器可迁移**：用 Qwen3-8B 训练一次的策展器迁移到 GPT-5.4 时，与直接训练版仅差 **1.4 SR 点**，说明学到的是通用策展策略而非执行器特定模式。
- **效率更优**：载荷更紧凑，相比写入时方法减少输入 tokens **50.3%–56.3%**、执行步数 **28.4%–31.4%**；相比无记忆仅增加 1.9K 输入 tokens。
- **消融结论**：任务条件化、质量过滤存储、原始轨迹保留三者均独立贡献性能；去掉检索轨迹后 RL 版大幅下降（最高 −15.2 SR），证明 RL 学到的是**蒸馏检索经验**而非单纯调用参数知识；RL 还诱导出环境特定的过程语义（如“先移动到台灯再用它检查碗”）。
- **分阶段刷新与热启动**收益有限，说明静态训练库与空库起步已足够。

## 7. 优点

- **视角新颖且论证清晰**：将“何时策展”作为核心问题，从信息损失与信用分配两个角度系统论证读取时策展的优势。
- **方法简洁有效**：存储原始轨迹 + 读取时任务条件蒸馏，实现同一轨迹对不同任务产生不同载荷（Figure 3 定性佐证）。
- **训练目标直接**：以即时任务奖励单步优化，无需价值网络、复合奖励、任务分组或延迟回报机制，训练稳定（训练曲线验证）。
- **模块化与可迁移**：策展器与执行器解耦，一个策展器服务多执行器，降低部署成本。
- **效率与效果兼得**：不仅提升成功率，还减少输入 tokens 和执行步数。
- **实验严谨**：多执行器、多排序重复、基线复现校准、系统消融，结论可信度较高。
- **定性分析充实**：展示了跨任务差异化载荷与 RL 诱导的过程语义，增强可解释性。

## 8. 不足与局限

- **检索器简单**：使用 BM25 且仅基于任务描述，随记忆库规模增大与多样化可能成为瓶颈；框架虽不限制检索器，但未探索更强检索。
- **额外推理开销**：策展器每个任务增加一次 LLM 调用。
- **载荷格式固定且手工设计**：按 benchmark 分别定制提示，缺乏通用性与自动化格式优化。
- **训练验证不完整**：τ²-bench 无标准训练划分，仅评测免训练变体；RL 训练收益未在该 benchmark 上验证。
- **部分领域增益有限**：τ²-bench 的航空与零售领域，记忆方法相比无记忆未超方差范围，说明读取时策展的价值主要体现于需要综合程序性指引的任务，而非简单事实检索。
- **训练/测试分布偏移**：训练库用基础执行器轨迹、测试库随策展器增强轨迹增长，存在轻度分布偏移（虽有分阶段刷新实验缓解）。
- **基准特定性风险**：环境特定工作流的涌现依赖具体环境，跨环境泛化性未充分讨论。
