## 摘要
检索增强生成（RAG）能够改进知识密集型问答，但第一个设计选择容易被忽视：应如何将源语料库划分为可检索单元？固定大小的分块往往返回长段落，而这些段落与问题的关联只是隐含的。我们提出 EAR，一种用于多项选择问答（MCQA）的实体感知分区方法。EAR 从问题、答案选项和语料库中提取归一化的表层锚点；检索匹配语料锚点周围的局部窗口；并可通过抽取式摘要附加更大的父段落。我们在一个经清洗的、包含 153 个问题的 Massive Multitask Language Understanding（MMLU）风格子集上评估 EAR，该子集由自动语料支持启发式方法选出，并使用去污染的公开教科书文本。在相同协议下，使用 Mistral、Gemma 和 DeepSeek 进行 top-k = 3 与 top-k = 8 的扫描时，EAR 实体窗口相对于分块将检索词数减少 37.5–40.2%。观察到的准确率变化在 top-k = 3 时分别为 +5.2、+1.3 和 -3.9 个百分点，在 top-k = 8 时分别为 +5.9、-3.3 和 -4.6 个百分点；实体窗口的所有差异均不具有统计显著性。范围限定内的贡献是方法学上的：EAR 提供了紧凑且可检查的检索单元，而其基于规则的锚点抽取器仍是领域特定的，在迁移前需要单独验证。

## Abstract
Retrieval-augmented generation (RAG) can improve knowledge-intensive question answering, but the first design choice is easy to overlook: how should the source corpus be partitioned into retrievable units? Fixed-size chunks often return long passages whose relation to the question is only implicit. We introduce EAR, an Entity-Aware Partitioning approach for multiple-choice question answering (MCQA). EAR extracts normalized surface anchors from the question, answer options, and corpus; retrieves local windows around matching corpus anchors; and can attach a larger parent passage through an extractive summary. We evaluate EAR on a cleaned Massive Multitask Language Understanding (MMLU)-style subset of 153 questions selected by an automatic corpus-support heuristic and using decontaminated public textbook text. Across same-protocol top-k = 3 and top-k = 8 sweeps with Mistral, Gemma, and DeepSeek, EAR entity-window reduces retrieved words by 37.5-40.2% relative to chunks. Observed accuracy changes are +5.2, +1.3, and -3.9 points at top-k = 3, and +5.9, -3.3, and -4.6 points at top-k = 8; none of the entity-window differences is statistically significant. The scoped contribution is methodological: EAR provides a compact and inspectable retrieval unit, while its rule-based anchor extractor remains domain-specific and requires separate validation before transfer.

## 1. 核心问题与研究动机

- **背景**：RAG 已被广泛用于知识密集型问答与多项选择问答（MCQA），但系统设计中第一个、也是最容易被忽视的决策是——**如何把源语料切分为"可检索单元"**。
- **现有做法的问题**：主流轻量系统在"看到问题之前"就把文档切分好（固定分块或滑窗分块），检索器只能在这些预先造好的片段上排序。固定分块边界与问题无关，往往返回与问题只有**隐含关联**的长段落。
- **具体痛点**：
  - 通用分块会把答案线索、干扰项和无关叙述混在一起；
  - 更长的上下文提高推理成本，并可能削弱模型对证据的可靠使用（"lost in the middle"现象）；
  - 在 MCQA 中，题干和选项本身常常已经点名了条约、君主、改革、政体、战役、地点或日期——这些信号本可直接指导检索。
- **核心研究问题**：当把通用分块替换为"实体感知窗口"时，**准确率与上下文成本**会呈现怎样的行为？
- **研究定位**：论文自认为贡献是**方法学**层面的——提供一个紧凑、可检查（inspectable）的检索单元，而非宣称普遍的性能优越性；其规则式锚点抽取器仍是领域特定的。

## 2. 方法论：EAR

### 2.1 核心思想
- 用**确定性、基于规则的"表层锚点"（surface anchor）**取代固定长度切分作为检索键：
  - 从问题+选项抽取查询锚点，从语料抽取语料锚点；
  - 命中后返回锚点周围的**局部小窗口（child window）**；
  - 可选地通过抽取式摘要附上**更大的父段落（parent passage）**。
- 强调"entity"是**操作化术语**，指归一化后的文本锚点，**不是**通用 NER 模型的输出；方法不需要本体（ontology）、也不需要学习式链接器或嵌入模型。

### 2.2 锚点抽取与归一化
- 抽取对象：年份、大写短语、以及带后缀的事件类短语（如 `Savaşı`、`Antlaşması`、`Fermanı`）；内容词不超过 6 个的答案选项也被保留为锚点。
- 归一化处理：本地化大小写折叠、标点变体、数字、空白、领域后缀。
- 语料端与查询端**共用同一抽取器**（Algorithm 1 的 Step 3 与 Step 5）。

### 2.3 Algorithm 1：EAR 实体窗口检索
1. 清洗语料页面，删除习题/选择题块；
2. 把每页切分为 **260 词、60 词重叠**的父分块；
3. 从每个父分块抽取归一化语料实体；
4. 为每个锚点存储**前后各最多 80 词**的子窗口；
5. 从问题 q 与选项 O 抽取归一化查询实体；
6. 对子窗口打分：实体匹配 + 词汇重叠，**每个匹配锚点加 3 分，每个匹配年份/日期额外加 1.5 分**；若无查询锚点命中索引，则退化为对全部窗口的词汇打分；
7. 返回 top-k 去重后的窗口作为证据（并列时保持语料索引顺序）。

### 2.4 Algorithm 2：EAR 父段落扩展
1. 先运行 Algorithm 1 得到子窗口；
2. 取每个子窗口所属父分块；
3. 按与问题+选项的重叠度对父分块句子排序；
4. 用最佳句子构建**最多 2 句**的抽取式摘要；
5. 附加子窗口、父摘要与锚点链接日志；
6. 对重复父上下文去重后交给生成器。

### 2.5 设计理据与可审计性
- 每个上下文都可追溯到"查询锚点 → 语料锚点 → 窗口"，因此错误答案可被定位为：Step 5 查询抽取失败、Step 6–7 检索排序失败，或检索正确但生成器未用好证据。
- 架构可替换锚点抽取器，但当前的**大小写、后缀与归一化规则是针对该语料定制的**，迁移需重新设计与验证。

## 3. 实验设计

- **任务**：五选一 MCQA，要求模型输出一个选项标签。
- **数据集与语料**：
  - 基准为 MMLU 风格（土耳其语场景，对应 TurkishMMLU / TR-MMLU 传统）；
  - 先做审计，得到 provisional clean split 与 strict split，**strict 测试集 672 题**；
  - 再用自动"语料支持启发式"（金标选项与题干词在同一保留语料块中重叠足够多）筛出 **153 题 supported split**，支持率 0.2277；
  - 检索语料来自 **4 份公开课程教科书纯文本（9–12 年级）**，去污染步骤删除习题材料与选择题块；
  - 语料审计结果：1108 页、772 页含叙述文本、保留 3955 块、丢弃 4429 块。
- **对比方法**：
  - **no-RAG 直接提示**：zero-shot、few-shot、CoT（共 3 种提示族）；
  - **chunk 基线**：清洗文本切成 220 词、30 词重叠的分块，按与问题+选项的词重叠排序；
  - **EAR entity-window**（主方法）；
  - **EAR parent-expanded**（更宽上下文变体）；
  - **BM25 page**（仅作为 Mistral 诊断用高召回检索器）。
- **模型与协议**：Ollama `mistral:latest`（7.2B，Q4_K_M）、Ollama `gemma:7b-instruct`（9B，Q4_0）、OpenRouter `deepseek/deepseek-v3.2`；**top-k = 3 与 8**；temperature 0、seed 13、选项打乱、每题生成一次；主对比使用 RAG+CoT 提示。
- **指标与统计**：
  - 主指标：supported split 端到端准确率；
  - 次指标：无效答案率、检索词数、检索与生成延迟、配对准确率差；
  - 统计检验：双侧精确 **McNemar 检验** + **2000 次重采样的百分位 bootstrap**（seed 13）95% CI，并对 12 组比较做 Holm / Bonferroni 多重比较校正；
  - 另有检索-only 的窗口半径敏感性扫描（40 / 80 / 120 词）。
- **辅助诊断**：记录金标选项表层形式是否出现在检索上下文中（作为线索诊断，**不等同于证据支持**）。

## 6. 主要结论与发现

- **发现 1：上下文节省稳定，准确率效果方向不定**
  - 检索词数：top-k=3 时 419.6 vs 671.3（**减少 37.5%**）；top-k=8 时 1062.3 vs 1775.6（**减少 40.2%**）。
  - 准确率变化（entity-window 减 chunk）：Mistral +5.2 / +5.9；Gemma +1.3 / −3.3；DeepSeek −3.9 / −4.6（单位：百分点）。
  - **所有 entity-window 的 CI 均跨零**，12 组比较经校正后无一显著。
  - 检索并未改善观测准确率：DeepSeek 直接提示即达 **83.0%**，无任何检索行超过它。
- **发现 2：紧凑窗口改变了成本结构**
  - 在线检索更快：entity 24.4–25.2 ms/题 vs chunk 60.6–62.4 ms/题；
  - 代价是**离线索引更大更慢**（33,228 窗口、6.877 s、143.0 MiB）；
  - 父扩展最慢（约 149 ms），因为它在线排序父句；
  - 端到端生成延迟在 6 组模型-预算运行中全部低于 chunk，降幅 1.8%–31.4%（描述性范围，混合本地与托管请求延迟）；
  - 半径敏感性：40→80 词使 top-k=3 金标表层线索率从 .529 升至 .608；120 词为 .601 但多取 35.5% 文本；top-k=8 时 120 词为 .706 vs 80 词的 .673，但检索词数从 1062.3 增至 1409.8。**80 词处于覆盖率-上下文权衡的中间位置，是工程选择而非按准确率调优的结果**。
- **发现 3：父扩展与表层线索都有局限**
  - 父扩展在 top-k=3 时取得 Mistral/Gemma 最高观测准确率，但在 top-k=8 时反而落后；
  - 未校正 p<.05 下唯一显著差异是 Gemma top-k=8 父扩展 vs chunk：**−8.5 点，95% CI [−15.7, −1.3]，p=.029**，但**未通过多重比较校正**；
  - 表层线索 ≠ 能回答：Mistral top-k=8 诊断中 BM25 page 的金标表层线索率最高（.882 > parent .725 > chunk .706 > entity .673），但其准确率（.431）**低于** entity-window（.444）；
  - 对 entity-window 的四格计数：59 题有线索且答对、9 题无线索答对、44 题有线索却答错、41 题无线索答错——说明可定位失败，但需要人工证据标注才能区分"真支持"与"偶然出现答案字符串"。
- **运行覆盖率**：153 题全部至少抽出一个"问题+选项"锚点；**151 题（98.7%）**至少命中一个精确归一化语料索引键；锚点级别 **676/1331（50.8%）**命中索引。
- **总体定位**：EAR 被支持为一种**紧凑、可检查的检索表示**，但抽取器有效性、语料支持度与跨域迁移仍是开放问题；父扩展不应作为默认选项。

## 7. 优点

- **方法简洁且
