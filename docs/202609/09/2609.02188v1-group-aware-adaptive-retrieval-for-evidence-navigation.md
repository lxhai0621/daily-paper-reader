## 摘要
推理密集型检索处理的是相关性无法通过表面匹配识别、因此需要多步推理的查询。由于相关文档很少出现在初始候选集中，检索系统面临有界召回问题。现有方法在语料库图上以文档级别迭代扩展候选池，孤立地检查每个邻居，并偏向语料库的狭窄区域。为解决此问题，我们提出了组感知自适应检索用于证据导航（GAREN），通过组级扩展来探索语料库图。GAREN根据文档在语料库图中的连接将它们组织成语义连贯且可区分的组。每个组中的信息指示通过扩展该组可以访问的内容，提供了超越单个文档级别信号的指导。在每次迭代中，GAREN使用组级导航器识别有前景的扩展方向，从选定的组中检索文档，并应用文档级重排序器评估更新后的候选集。大量实验表明，GAREN在BRIGHT上比最强基线提升了高达8.0%。源代码可在https://github.com/KJ12124/GAREN获取。

## Abstract
Reasoning-intensive retrieval addresses queries whose relevance cannot be identified by surface-level matching, thereby requiring multi-step reasoning. Because relevant documents rarely appear in the initial candidate set, retrieval systems suffer from the bounded recall problem. Existing methods iteratively expand a candidate pool at the document level over a corpus graph, examining each neighbor in isolation and drifting toward a narrow region of the corpus. To address this problem, we propose Group-Aware Adaptive Retrieval for Evidence Navigation (GAREN), which explores the corpus graph through group-level expansion. GAREN organizes documents into semantically coherent and distinguishable groups based on their connections in the corpus graph. The information in each group indicates what can be accessed by expanding through it, providing guidance beyond individual document-level signals. At each iteration, GAREN uses a group-level navigator to identify promising expansion directions, retrieves documents from the selected groups, and applies a document-level reranker to evaluate the updated candidate set. Extensive experiments show that GAREN achieves up to 8.0% improvement over the strongest baseline on BRIGHT. The source code is available at https://github.com/KJ12124/GAREN

## 论文详细总结

### 1. 核心问题与整体含义（研究动机与背景）

- **问题定义**：面向推理密集型检索（Reasoning-Intensive Retrieval），即查询与文档的相关性不能通过表面词法或语义匹配识别，而需要多步推理才能判定的任务。
- **核心挑战**：由于相关文档与查询之间存在间接相关性，这类文档在初始检索阶段往往不会被召回，导致 **有界召回问题（bounded recall problem）**——即使后续使用更强的重排器，也很难弥补初始候选池中遗失的相关文档。
- **现有方法的不足**：自适应检索方法会在语料库图上迭代扩展候选集，但现有方法（如SlideGAR、RGS、REPAIR）主要基于文档级别的局部信号来判断扩展方向。这种策略存在三点问题：
  1. 当候选文档中没有明显相关文档时（尤其检索早期），文档级信号不可靠或过于微弱，无法提供有效的方向指引；
  2. 孤立地评估每个邻居，缺乏对“扩展该方向后能获得什么信息”的整体感知；
  3. 容易陷入语料库的局部区域，产生漂移，无法到达远处但相关的文档。
- **核心研究问题**：在证据微弱且间接的条件下，如何从弱信号中筛选出通向相关文档的正确扩展方向？

### 2. 方法论：核心思想、技术细节与流程

**总体思想**：将语料库图划分为粗粒度的语义组，将“扩展方向”视为“候选组”，通过组级信息来判断哪些方向值得探索，同时保留文档级重排用于精确评估。引入“先探索、后利用”（explore-then-exploit）的策略来平衡早期不确定性与后期聚焦性。

**方法名称**：GAREN（Group-Aware Adaptive Retrieval for Evidence Navigation，组感知自适应检索用于证据导航）。

**三个核心模块**：

1. **组构建（Group Construction）**
   - 基于预构建的文档语义图（k-NN 图，k=16，使用 Qwen3-Embedding-4B 构建），用 Leiden 社区检测算法进行图划分，最大化模块度（modularity），使组内连接密集、组间连接稀疏。
   - 每个组生成一个 LLM 总结（summary），作为该组“可通过扩展获取的信息”的粗粒度预告，供导航器评估。

2. **组感知自适应检索（Group-Aware Adaptive Retrieval）**
   - 每轮迭代中，以当前窗口文档的图邻居所在组作为候选组集合：`G_cand = {Ω(d') | d' ∈ ∪_{d∈W_t} N_k(d)}`
   - 使用组级导航器（navigator，一个小型重排模型 Qwen3-Reranker-4B）对候选组打分：`G_score = Navigate(q, G_cand)`，评估查询与组总结的相关性，预算为每轮最多 Kg=20 个组。
   - 文档级重排器（reranker，Qwen3-Next-80B-A3B）对当前窗口进行列表式重排。
   - 采用 **探索-利用两阶段扩展策略**：
     - 早期（t ≤ τswitch，默认 τswitch = 4）：**探索阶段（exploration）**，采用广度优先的轮询方式，从多个高分组中取文档，防止早期决策错误导致方向锁定；
     - 后期（t > τswitch）：**利用阶段（exploitation）**，采用深度优先的聚集方式，优先从最高分数组中取文档，利用累积证据聚焦最有效方向。
   - 保留重排后 top-h（h=10）文档，并加入扩展的文档形成下一轮窗口，总共迭代 T 次（总重排预算 100 篇文档）。

3. **组驱动证据传播（Group-Driven Evidence Propagation）**
   - 检索结束后，对观测到的文档进行后处理。将最终 top-10 结果按 RBP（Rank-Biased Precision）方式分配基础权重 b(d) = (1−p)·p^(rank(d)−1)，然后对同一组内的文档加权传播证据：score(d) = b(d) + α·Σ_{Ω(d′)=Ω(d)} b(d′)。
   - 该步骤利用聚类假设，提升与高置信文档同组的潜在相关文档在最终排序中的位置。

**算法主干（文字描述）**：
初始化窗口为初始检索结果的 top-w；对每轮迭代：重排 → 提取候选组 → 导航器打分 → 按探索/利用策略选择扩展文档 → 合成下一窗口；最终对观测文档做证据传播得分重排。

### 3. 实验设计：数据集、基准与对比方法

**数据集/基准**：

**基线方法**：
- BM25（第一阶段检索基线）

### 6. 主要结论与发现

- GAREN 在 BRIGHT 的两种 prompt 设置下均显著优于所有基线：非推理式 setting 下平均 nDCG@10 为 28.3（较最强基线 RGS 26.4 高 7.2%）；推理式 setting 下平均 31.2（较最强基线 RGS 28.9 / REPAIR 28.4 高 8.0% 左右），符合摘要“最高提升 8.0%”的声明。
- 在 R2MED/BEIR 上，GAREN 也取得最佳或并列最佳的性能（R2MED nDCG@10 45.1，BEIR 52.4），证明其泛化性。
- **组级扩展优于文档级扩展**：文档级扩展早期上升快但迅速饱和，组级扩展增速更平稳、后期明显胜出。
- **距离分析**：GAREN 对距离初始候选 4 跳以上的金标文档依然保持可观命中率，而文档级扩展在 7 跳以上几乎失效；组图将金标文档的距离压缩到 3 跳以内，大幅提升可达性。
- 消融实验表明：探索-利用策略、导航器语义打分、证据传播三者均有贡献；移除导航器（连通度启发式）后 nDCG@10 下降 25.1%，R@100 下降 27.7%。
- 效率上，由于导航器规模远小于重排器，几乎不增加延迟，且效果收益主要来自于更大的重排器而非导航器，说明组级方向判断是一个轻量任务。

### 7. 优点与亮点

- **问题定位精准**：直接击中自适应检索在早期阶段信号薄弱的痛点，通过“组”这个中间粒度提供超越文档级的语义预览，思想有创新性。
- **方法设计清晰有效**：组构建（Leiden + LLM summary）、组级导航器、探索-利用两阶段扩展、组驱动证据传播，模块逻辑自洽，各组件消融贡献明确。
- **证据充分**：主实验之外提供大量对比（替换 initial retriever、embedding、reranker backbone、Hierarchical retrieval LATTICE、组构建策略），分析维度丰富（金标距离、失败类型、超参数、token成本、延迟分解）。
- **具有实际部署价值**：导航器较小，可与重排器并行执行，token 成本低，除了 GAREN 的在线成本约 $0.0109 之外在性能上亦强于分层检索方法。
- **开源代码**，可复现性强。
- 统计严谨：5 次运行取平均、查询级配对 t 检验。

### 8. 不足与局限

- **组构建依赖静态图与社区检测**：组质量受 embedding 模型与 Leiden 超参数影响；当文档存在多主题或与查询所需侧面不匹配时，分组和总结可能丢失关键信息（失败分析中 53.3% 的失败源于组构建/总结缺陷）。
- **导航器的判断局限**：即使组内容相关且摘要包含所需知识，导航器仍可能在需要多步推理的查询上打低分（46.7% 的失败源于此）；增加导航器规模带来的精度收益有限且成本过高。
- **固定 τswitch 的启发式**：探索-利用切换时间对所有查询统一，缺乏基于查询复杂度的自适应机制，对极难或极易查询可能不够最优。
- **实验数据集以英文、学术/问答社区为主**，缺少多语言、大规模工业级百万/亿级语料的实测；虽然在 DBpedia 4.6M 上验证了扩展性，但并未报告完整检索性能。
- **公平性微瑕疵**：RGS 使用 DiskANN 图、GAREN 使用 k-NN 图，两者邻域形态不同；虽然遵循原文实现可接受，但底层结构不同可能会给比较带来系统性偏差。
- **未提供“为什么失败”的更多定量归因**，失败案例分析为主观抽样标注，样本有限（120 例），代表性存在一定局限。
- **缺乏与其他基于 hierarchical tree 或 cluster-aware 的 SOTA 检索方法同时在同一数据集上的大范围系统对比**（LATTICE 仅在 token 成本/性能一表中比较，BRIGHT 主表未含 LATTICE）。
- **推理式 prompt 下成本更高**（生成推理链），论文只报告了性能与延迟，但没有给出完整成本表格对照大模型实际使用中的性价比。
