## 摘要
大语言模型（LLM）智能体正从单会话工具演变为长期个人助手，必须在任务、情境和交互中适应个体用户。这一转变使记忆成为个性化的核心需求，因为用户偏好、目标、约束、关系及过往经验是逐步积累的，且常随时间变化。基于图的个性化记忆通过显式关系、时间上下文和证据链接，为建模此类用户信息提供了结构化方式。这种表示不仅能建模智能体对用户的记忆内容，还能建模记忆之间如何连接、修正和检索，以支持个性化决策。然而，现有工作在个性化智能体与通用图记忆框架之间仍然碎片化，难以整体理解设计空间。本综述建立了面向LLM智能体的基于图的个性化记忆的生命周期视角。我们围绕记忆表示、记忆演化、记忆检索和记忆评估组织现有研究，并进一步比较关键设计选择，讨论当前评估实践以及构建可靠长期个性化智能体所面临的开放挑战。本综述旨在阐明基于图的记忆如何支持自适应、可控且以用户为中心的LLM智能体。

## Abstract
Large Language Model (LLM) agents are evolving from single-session tools toward long-term personal assistants that must adapt to individual users across tasks, contexts, and interactions. This shift makes memory a core requirement for personalization, since user preferences, goals, constraints, relationships, and past experiences are accumulated gradually and often change over time. Graph-based personalized memory provides a structured way to model such user information through explicit relations, temporal context, and evidence links. Such representations can model not only what an agent remembers about a user but also how memories are connected, revised, and retrieved to support personalized decisions. However, existing work remains fragmented across personalized agents and generic graph memory frameworks, making it difficult to understand the design space as a whole. This survey develops a lifecycle-oriented view of graph-based personalized memory for LLM agents. We organize existing studies around memory representation, memory evolution, memory retrieval, and memory evaluation. We further compare key design choices, discuss current evaluation practices, and open challenges in building reliable long-term personalized agents. This survey aims to clarify how graph-based memory can support adaptive, controllable, and user-centric LLM agents.

## 2. 论文提出的方法论：核心思想与框架

论文没有提出单一新算法，而是建立了**分析分类框架**和**设计空间图谱**，将现有系统按记忆生命周期划分为四个阶段，并细化了每个阶段的关键机制：

### 2.1 个人记忆的五维表征框架
- **语义**（稳定事实、偏好、目标、约束）
- **时间**（记忆何时成立、如何变化）
- **关系**（与人、地点、任务、物品的关联）
- **经验**（过去事件、结果、例行程序、习惯）
- **情感**（情绪效价与强度）
- 五个维度可重叠，定义了什么信息是图需要表示的对象。

### 2.2 记忆表示（Representation）
- **元素层面**：区分四类功能节点——**证据节点**（原始交互记录）、**事实节点**（抽取的原子断言）、**抽象节点**（如人设、反思等高阶综合）和**领域特定节点**（特定话题/应用实体）；边承担时间、溯源、联想和领域关系等；生命周期元数据（时间戳、有效区间、失效标记）区分活跃状态与历史证据。
- **结构层面**：归纳为五种模式——
  1. **平面图**（无抽象分层，如Mem0g、KGT）
  2. **层次图**（证据到抽象的多层组织，如GAAMA、Bi-Mem、GAM）
  3. **超图**（以超边保持联合上下文，如HingeMem、HyperMem）
  4. **混合图**（图与非图存储互补，如H-Mem、LiCoMemory、MemWeaver）
  5. **多重分离图**（按功能拆分到不同图实例，如DEMENTIA-PLAN）

### 2.3 记忆演化（Evolution）
- 五个操作：
  1. **准入**（Admission）：决定哪些证据进入持久记忆及其功能类型/粒度（如MemGuard按功能角色分类；MemORAI选择性过滤压缩）
  2. **整合**（Integration）：将证据附着到现有图结构，保留溯源（如缓冲附着、语义节点复用）
  3. **冲突消解**（Conflict Resolution）：区分**时间替代**、**用户纠正**与**情境共存**三类冲突，不做简单“新覆盖旧”；处理方式包括版本化保留（ZEP、Kumiho）或不活跃标记（GRAVITY）
  4. **整合巩固**（Consolidation）：完成抽象、去重、重组和归档（如GAM的事件提升、All-Mem的SPLIT/MERGE/UPDATE编辑）
  5. **移除**（Removal）：区分**遗忘**（降低曝光/分辨率，如ScrapMem）与**删除**（改变存储内容/状态，如Kumiho的版本化信念修正）

### 2.4 记忆检索（Retrieval）
- 三种可组合的机制：
  1. **基于相似性的检索**：作为初始候选生成或图锚定
  2. **基于结构的检索**：沿关系/层次/视图扩展证据（如GAM的topic→event两级取用、MAGMA多视图选择、xMemory的互补分组扩展）
  3. **自适应与代理式检索**：按查询意图和中间证据控制图探索、裁剪、路由与压缩（如MRAgent的Cue-Tag-Content迭代剪枝、PRISM的意图感知路径选择、APEX-MEM的检索时冲突消解）

### 2.5 评估体系
- Benchmark分布于长程对话召回、个性化用户建模、图结构与演化等方向
- 评测指标分五组：**答案质量、证据检索、用户状态建模、记忆演化与结构、效率**

## 6. 论文的主要结论与发现

- **图记忆是一种能力使能器而非保证**：图结构本身不等于个性化质量。只有当表示暴露了有意义的关系、演化维护了其有效性、检索能返回相关证据时，图才能真正发挥作用。
- **表示层面**：表示决定了系统保留哪些用户证据以及后续生命周期操作能依赖哪些依赖关系。证据丰富型设计与事实/抽象中心型设计之间存在**可追溯性与紧凑性**的权衡；层次/多存储结构引入跨层一致性代价，生命周期元数据并不自动保证更新传播正确。
- **演化层面**：冲突消解不能简化为“最新即最优”，需区分时间替代/用户纠正/情境共存三种逻辑；抽象化可能复制并固化底层抽取错误；删除源证据未必会正确级联到派生高层的抽象，这是当前系统普遍欠缺的能力。
- **检索层面**：平面top-k检索会返回相关重复片段；结构扩展不可控会引入无关节点和上下文成本；三机制应组合为“相似锚定→结构扩展→自适应压缩/剪枝”的管线。
- **评估层面**：当前评测本质上是**下游任务驱动**的——主要测“答案是否正确”，很少检验“记忆图本身是否正确、状态是否合理、组织是否良好”。针对图原生能力（结构组织、演化、证据派生一致性）的评测仍稀缺。

## 7. 优点与亮点

- **填补视角空缺**：以“个性化”为重心整合了此前彼此分离的图记忆和个性化智能体研究，提供了统一的四阶段生命周期框架。
- **分类细致、多维交叉**：表示层区分元素与结构、演化层划分五类操作、检索层划分三种机制，让零散系统可以被放在精确的设计坐标中比较；表I（记忆五维度）与表II（Benchmark信号矩阵）信息组织清晰。
- **善于暴露设计张力**：几乎对每类设计都给出双向讨论（如层次图的可追溯性vs误差传播；图的高容量vs高一致性成本），避免片面捧高图记忆。
- **引入中立实证视角**：明确引用“记忆是否非图不可”的质疑性研究，显示了综述撰写的克制和公允。
- **现实指向性强**：评估部分按能力族而非论文列表组织，方便后续研究者选取适合自己系统的Benchmark。

## 8. 不足与局限

- **无第一手实验验证**：作为综述，无法回答“何时用哪种图方案更好”的规范性结论，对方法效能只能转述原文。
