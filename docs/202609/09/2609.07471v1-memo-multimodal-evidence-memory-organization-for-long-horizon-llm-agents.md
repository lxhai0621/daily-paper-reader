## 摘要
长时运行的LLM智能体依赖外部记忆来存储和重用超出单一上下文窗口的信息，然而交互轨迹的持续累积与有限的上下文容量之间存在根本性矛盾。因此，智能体记忆的关键挑战不仅在于检索相关记录，还在于在给定预算下选择必要的证据，并以适当的模态组织它们。现有的记忆读出方法主要使用文本或视觉形式。文本能保持高保真度，但其线性token表示使得不同重要性的内容以几乎均匀的单位成本竞争有限的上下文。视觉读出将文本渲染为类文档图像，可以利用二维布局来展现结构并突出关键信息，但在渲染和压缩过程中可能会丢失细粒度细节。为解决这一问题，我们提出了MEMO，一种用于LLM智能体的多模态证据记忆组织方法。MEMO首先使用训练过的证据提取器选择相关的记忆块，并形成带有来源信息和呈现需求的证据单元。一个训练过的、以查询为条件的记忆管理器将每个单元分配给文本、视觉或双通道载体，并选择与证据结构匹配的布局。然后，一个确定性的记忆构建模块生成文本包和视觉页面。记忆管理器通过离线阅读器的反馈进行训练，该阅读器衡量引导式记忆计划的效用，从而使保留和呈现决策与下游使用保持一致。我们在四个基准测试上评估了MEMO，包括HotpotQA、2WikiMultiHopQA、LoCoMo和ALFWorld，并使用了多种阅读器后端。结果表明，MEMO以更少的记忆token更高效地呈现记忆，提升了下游任务性能，并在受限预算下构建了更有效的工作记忆。

## Abstract
Long-running LLM agents rely on external memory to store and reuse information beyond a single context window, yet there is a fundamental tension between the continuous accumulation of interaction trajectories and the limited context capacity. The key challenge in agent memory is therefore not only to retrieve relevant records, but also to select necessary evidence under a given budget and organize it in an appropriate modality. Existing memory readout methods mainly use textual or visual forms. Text preserves high fidelity, but its linear token representation makes contents with different importance compete for the limited context at nearly uniform unit cost. Visual readout renders text into document-like images, which can use two-dimensional layouts to expose structure and emphasize key information, but it may lose fine-grained details during rendering and compression. To address this issue, we propose MEMO, a multimodal evidence memory organization method for LLM agents. MEMO first uses a trained evidence extractor to select relevant memory blocks and form evidence units with source information and presentation requirements. A trained query-conditioned memory manager assigns each unit to a textual, visual, or dual-channel carrier and selects a layout that matches the evidence structure. A deterministic memory construction module then generates the textual package and visual pages. The memory manager is trained with feedback from an offline reader that measures the utility of the guided memory plan, so that retention and presentation decisions align with downstream usage. We evaluate MEMO on four benchmarks, HotpotQA, 2WikiMultiHopQA, LoCoMo, and ALFWorld, with multiple reader backends. The results show that MEMO presents memory more efficiently with fewer memory tokens, improves downstream task performance, and builds more effective working memory under constrained budgets.

- **核心矛盾**：交互轨迹的持续积累与上下文窗口容量有限之间，存在根本性张力。因此，智能体记忆的挑战不仅是"检索到相关记录"（存储与检索），更在于**记忆读出（memory readout）**——即在给定查询、候选记录和上下文预算的条件下，选择任务所需证据，并将其组织为结构化、可高效阅读的工作记忆。
- **现有方法的缺陷**：
  - **文本记忆**：通过分段、压缩、检索构建紧凑上下文，但最终读出为线性token序列，不同重要性的内容以近乎均匀的单位成本竞争上下文空间，无法按重要性分配资源。
  - **视觉记忆**：将文本渲染为文档类图像，利用二维布局暴露结构、突出关键信息（如MemOCR、AgentOCR），有效降低表达同样内容所需token数，但渲染与压缩过程中可能丢失细粒度语义信息。
  - **关键观察**：文本与视觉表征各有适用场景，将全部记忆限定为单一模态，无法同时满足信息保真度、结构表达力和资源效率。
- **研究问题**：能否在**证据单元（evidence unit）粒度**上联合决策"保留什么"与"如何呈现"，使不同证据根据其内容特征被分配到最合适的模态载体，从而在统一资源预算下实现最优的记忆组织？

## 2. 方法论

### 2.1 核心思想

MEMO 的核心在于以"可溯源证据单元"为粒度，将证据选择、呈现模态分配和视觉布局组织纳入**统一的查询条件化工作记忆构建框架**。给定查询 q、记忆记录 R 和总记忆预算 B，MEMO 构建工作记忆 a = (T, V)，其中 T 为文本包、V 为可选的视觉页，并满足统一资源约束 C_text + C_vis ≤ B。整个流程由三个模块协同完成：

1. **证据提取器（Evidence Extractor）**：从原始记忆中定位与查询真正相关的细粒度内容，形成紧凑的证据单元。
2. **记忆管理器（Memory Manager）**：在统一预算下为每个证据单元分配文本、图像、双通道或删除操作，并制定视觉布局方案。
3. **确定性记忆构建模块（Memory Builder）**：根据管理计划生成最终文本包和视觉页面，组装为读者输入。

### 2.2 查询条件化证据提取（Query-Conditioned Evidence Extraction）

- **动机**：已有的基于记忆段落或记忆块级别的证据提取方法过于粗糙——一个段落的绝大部分内容可能是无关背景，整段进入记忆会与关键事实竞争有限空间。
- **方法**：证据提取器 E_φ(q, R, B) 输出与查询相关的源块标识集合 S，以及每个选中源中的字符级关键span集合 H。每个关键span记录其在源块中的起始与结束位置。
- **证据单元的定义**：对于每个选中的记忆块，从原始记录中直接复制对应内容，并保留关键span周围宽度为 w 的局部上下文窗口，形成一个证据单元：
  
  u_i = (id, x_i, h_i, s_i, c_i)
  
  其中 x_i 为证据内容，h_i 为提取器定位的关键span，s_i 记录来源，c_i 为证据保留的优先级规则。该规则取决于内容属于关键span还是关联上下文，可要求以文本形式精确保留语义、允许以视觉形式呈现以满足预算约束、或允许丢弃。因此，后续模块在压缩记忆时可优先保护更关键的语义信息。

- **训练**：基于四个benchmark训练集的证据标注构造监督微调样本，用全参数监督微调训练。对于有原生证据标注的数据集（如HotpotQA和2WikiMultiHopQA的支撑事实sentence id），优先使用；无span标注时使用确定性弱标签（LoCoMo用官方证据轮次，ALFWorld通过状态差分构造）。训练目标为序列生成式交叉熵损失：

  L_ext(ϕ) = −Σ_t log p_ϕ(e⋆_t | e⋆_{<t}, q, R, B)

### 2.3 联合证据选择与呈现（Joint Evidence Selection and Presentation）

- **动作空间**：每个证据单元可选动作 M = {text, image, dual, drop}。
  - **text**：保留紧凑文本锚点于文本包 T 中——保留精确语义信息。
  - **image**：放入视觉页 V 中——保留时间、表格或分组等结构关系；但消耗视觉预算且字符串可恢复性可能下降。
  - **dual**：同时在文本包中保留文本锚点，并把单元加入视觉结构——兼顾精确语义与结构信息；成本同时计入文本与视觉资源。
  - **drop**：从当前工作记忆中省略该单元——节省资源但可能丢失推理所需证据。
- **视觉模板规划**：记忆管理器同时为视觉单元规划模板偏好，控制渲染为卡片、时间线、表格、检查清单或分栏布局等。不同场景匹配不同模板：多跳问答的文档间关系用卡片；长对话中的事件顺序用时间线；具身轨迹用检查清单组织状态变化。
- **联合规划**：由于内容选择、呈现形式与视觉组织竞争同一预算，记忆管理器在单一证据单元级计划中联合决策，输出每个单元的动作与置信度、目标记忆用量和偏好页面模板。**训练时从冻结读者模型的回答质量构建标签**：对同一证据单元尝试不同的反事实呈现，以冻结读者回答质量与记忆用量的权衡确定最优动作标签；模板标签同样由反事实候选的回答质量确定，以有序列表形式存入训练目标。训练同样采用序列生成式交叉熵损失：

  L_sft(θ) = −Σ_t log p_θ(y⋆_t | y⋆_{<t}, q, U, B)

### 2.4 工作记忆构建（Working Memory Building）

- **文本包构造**：被分配为 text 或 dual 的证据单元成为短文本条目，从源记录直接复制关键措辞，保留单元与源标识，按顺序形成文本包 T，计算统一文本token成本 C_text。
- **视觉页构造**：被分配为 image 或 dual 的单元成为视觉块（含标题、来源、内容、信息类型与高亮措辞），由模板偏好排列为时间线、表格、检查清单、卡片或分栏布局。剩余预算决定页面尺寸，同页面尺寸决定视觉成本 C_vis，保证 C_text + C_vis ≤ B。
- **读者输入组装**：文本条目按单元ID标签拼接，视觉页渲染为图像，连同当前查询一并交给冻结读者模型，由其基于该查询特定的工作记忆产生答案。

## 6. 主要结论与发现

- **严格128-token预算下**：MEMO在所有三个读者上取得最佳Overall EM和F1。与最强基线相比：InternVL3.5-8B读者提升7.30 EM与7.22 F1；Qwen3-VL-32B提升2.35 EM与1.84 F1；gpt-5.4-mini提升2.47 EM与2.81 F1。在2Wiki上MEMO对所有读者均排名第一（例如Qwen3-VL-32B读者下F1达73.91，远超Text-only 56.26与Visual-only 35.89），在HotpotQA上保持第一或第二。
- **无token预算下**：MEMO平均仅使用83.93个token，比MemAgent少约50.5–50.7%的token，比Text-only少约66.9%；同时总体回答质量排名第一或第二（最大差距仅0.43点）。即MEMO在上下文充足时不会盲目消耗token，以明显更低的记忆用量保持了近乎最优的回答质量。
- **消融实验**：仅启用证据提取器即将EM提升6.07、F1提升8.85，记忆token从126.22降至70.12（减少44.4%），说明查询相关证据选择大幅改善读者回答并去除大量非必要记忆。进一步加入记忆管理器后EM再提升4.22、F1再提升2.53，记忆使用从70.12适度增至81.07，说明管理器不是简单最小化token，而是在会提升回答质量时多花少量token。完整系统相比双禁用方案提升10.29 EM与11.38 F1，同时减少35.8%的记忆token——两个模块贡献互补。

## 7. 优点

- **研究视角的转换**：将记忆问题从"存储什么、如何检索"推进到"在给定预算下如何在证据单元粒度联合决策保留内容与呈现方式"，提出了更精细、更贴近实际部署的读出观。
- **多模态互补设计合理**：不局限于单一模态，如按单元内容特征灵活选择文本（保真）、视觉（结构）、双通道（两者兼顾），并提供了可操作的机制。通过在图像中兼顾高亮文本与布局组织，减少了单个文本表示的线性token竞争问题。
- **可溯源的证据单元**：保留来源与Id可让记忆具备可验证性，单元内显式编码优先级规则使后续模块在压缩时能对内容分层保真。
- **训练信号来自下游反馈**：用冻结读者模型在反事实候选记忆上的回答质量与记忆开销构造动作标签，比人为标注或纯启发式决策更贴近最终使用场景。
- **采用确定性构建模块**：提取与管理是学习式模块，但最后一步工作记忆构建是确定的、无额外学习参数的构建流程，其成本核算统一规则化，能严格实行C_text+C_vis≤B的预算约束，提高了可验证性与可靠性。
- **实验严谨**：跨多个读者与预算条件，结果包含严格受限与无限制两种场景，既验证了有限预算下的效率优势，也验证了无预算压力下不会浪费token。通过生成式行动管理计划、结果报告细粒度token统计检查等多方提高公平性。

## 8. 不足与局限

- **训练监督来源的渠道**：训练读者为InternVL3.5-4B，而主评测读者包括InternVL3.5-8B、Qwen3-VL-32B、gpt-5.4-mini，训练与推理读者能力差异与偏好差异可能在更广泛部署环境中带来训练信号偏差问题。不同规模的读者偏好可能有系统性差异，单独以单一读者构造反事实标签可能不完全代表不同读者族的最优计划。
- **数据覆盖的局限**：四个benchmark虽然涵盖了多跳QA、长程对话、具身轨迹，但实际问题面更宽（如代码交互、工具调用、网络浏览等）、更长的交互吞吐量、更复杂的层级关系、以及多Agent共享记忆/并发记忆访问等场景未覆盖。
- **证据提取与跨度处理依赖基准的标注设计**：LoCoMo的字符span标注依赖官方证据轮次，ALFWorld用状态差分做确定性弱标注，不同噪声标注条件下跨任务的真实表现与稳定性有待进一步验证。
- **预算与成本核算假设**：论文假定文本token和视觉token可以共用统一预算（C_text+C_vis≤B），但实际多模态模型中不同

**预算与成本核算假设**：论文假定文本token和视觉token可以共用统一预算（C_text+C_vis≤B），但实际多模态模型中不同模态token在推理时的单位计算成本与信息密度并不等价——视觉token通常需经视觉编码器处理并占用更大的解码开销，其"语义载荷"与文本token也不能简单等量齐观。将两者按数量直接相加的核算方式过于理想化，论文缺少对不同模态token实际部署成本的敏感性分析。

- **级联误差与分离式训练的局限**：证据提取器与记忆管理器为两个独立训练的模块，先抽取证据、再规划呈现动作，二者未做端到端联合优化。提取器漏检或错检的关键span将直接限制管理器的决策空间，且误差会沿流水线逐级放大。论文未讨论级联误差对最终工作记忆质量的量化影响。

- **未真正覆盖记忆的动态更新过程**：MEMO处理的是"给定累积历史与当前查询、构建一次性工作记忆"的静态读出问题，没有涉及记忆写入阶段的内容筛选、长期运行中的记忆合并/遗忘/一致性维护，也未支持多轮交互间对已有视觉页的增量更新。对于一个长时程Agent而言，记忆质量随时间推移的衰减与refresh机制仍属空白。

- **评测格式的统一化带来信息损失**：四个benchmark任务类型不同，但都被压缩为统一的EM/F1问答式评估。ALFWorld的下一动作预测本质上是分类决策、LoCoMo涉及长对话中的时序推理，统一指标难以完整刻画不同任务中记忆组织方式对推理质量的具体影响；构造出的"总体分数"虽便于对比，却也掩盖了任务内部的差异性表现。

- **骨干模型规模与真实部署差距**：两个可训练组件均以Qwen2.5-1.5B为骨干，在面对超长对话轨迹或海量候选记忆时，小规模模型的抽取与规划能力可能成为瓶颈，其泛化到训练分布之外的记忆格式或查询类型时是否依然稳健，尚未得到验证。

- **视觉布局与OCR式渲染的质量度量缺失**：论文没有报告视觉页渲染在分辨率下降、字体缩放、复杂表格截断等退化条件下的鲁棒性；也未对"读者模型究竟是从视觉块中读取了布局结构，还是依然在隐式OCR文本"这一机制性问题做诊断分析，视觉模态贡献的内在机理阐释仍不充分。

## 9. 总体评价与展望

综合来看，MEMO是一篇问题意识明确、框架设计完整、实验验证较扎实的工作。其核心贡献可归纳为三点：第一，将长时程LLM智能体的记忆问题重新定义为一种**受统一预算约束的、查询条件化的证据单元级读出问题**，而非单纯的存储与检索问题；第二，提出了文本亲和与视觉亲和证据的**联合模态分配方案**，打破了单模态记忆表达的固有局限；第三，通过"提取器+管理器规划+确定性构建"的解耦流水线，使记忆组织过程既具备学习能力，又保持了成本核算的确定性与透明性。在严格128-token预算下相对最强基线提升7.30 EM/7.22 F1（InternVL3.5-8B读者），无预算限制下以约一半的token用量达到几乎相同的回答质量，这些结果具有较强的说服力。

作为展望，后续工作至少可在四个方向上深化：一是将训练读者从单一模型扩展为读者集成或多读者自适应方案，缓解训练信号对特定后端的依赖；二是将本文"按单元分配模态"的框架迁移至更丰富的交互形态，如代码执行、工具调用、网页浏览与多Agent共享记忆场景；三是从静态读出走向动态记忆管理，与记忆写入、遗忘、合并机制联合设计形成完整的记忆生命周期；四是对视觉模板策略与读者模型的内部利用机制做更细粒度的归因分析，以指导模板库的自动扩展而非手工设计。总体而言，MEMO为多模态记忆组织这一新方向提供了一个结构清晰、具有可扩展性的初始框架。
