## 摘要
检索增强生成（RAG）系统依赖的外部语料库可能包含过时、矛盾、嘈杂或不可靠的文档，从而引入可靠性风险。已有工作利用文档关系来提高RAG的回答可靠性。为了将可靠性信号传播到直接比较的文档对之外，我们提出了TrustPropRAG，它将文档关系构建为图，并通过跨图的多跳传播来估计文档可靠性。TrustPropRAG以有限的文档可靠性人工反馈为锚点，将这些采集成本高昂的基于反馈的可靠性信号传播到整个语料库。具体而言，基于构建的文档关系图，TrustPropRAG通过制定并求解一个联合捕捉成对文档关系与用户反馈的优化问题，为每个文档估计一个信任分数。这些分数随后用于改进可靠文档的选择并支持信任感知的答案生成。评估结果表明，TrustPropRAG在检索质量和精确匹配方面均优于基线，并且在稀疏和嘈杂的反馈下保持鲁棒性。

## Abstract
Retrieval-augmented generation (RAG) systems rely on external corpora that may contain outdated, contradictory, noisy, or unreliable documents, introducing reliability risks. Prior work has leveraged document relations to improve the answer reliability of RAG. To propagate reliability signals beyond directly compared document pairs, we propose TrustPropRAG, which structures document relations as a graph and estimates document reliability through multi-hop propagation across the graph. TrustPropRAG anchors this propagation with a limited set of human feedback on document reliability, extending these costly-to-collect feedback-based reliability signals across the whole corpus. Specifically, based on the constructed document relation graph, TrustPropRAG estimates a trust score for each document by formulating and solving an optimization problem that jointly captures pairwise document relations and user feedback. These scores are then used to improve the selection of reliable documents and support trust-aware answer generation. Evaluation results show that TrustPropRAG improves both retrieval quality and exact match over baselines, and remains robust under sparse and noisy feedback.

## 1. 核心问题与整体含义

- 检索增强生成（RAG）依赖外部语料库，但这些语料可能包含过时、矛盾、嘈杂或恶意误导的内容，从而引入可靠性风险。
- 已有工作虽然利用文档间关系（如文档间的支持或矛盾）提升RAG可靠性，但大多局限于检索到的局部文档子集及其单跳直接关系，缺乏对可靠性信号在全语料范围内的传播。
- 为解决上述问题，论文提出 TrustPropRAG，将文档关系建模为图，利用少量人工反馈（如文档可靠性标注）作为锚点，通过图上的多跳传播估计整个语料库中每个文档的信任分数，并据此改进检索排序与答案生成。
- 整体含义在于：用构建的关系图，将高成本的人类反馈“放大”到未标注文档，使RAG系统在面临不可靠信息时具备全局性的可靠性识别能力。

## 2. 方法论

- **核心思想与框架流程**：TrustPropRAG 分四个阶段：
  1. 构建文档关系图（节点 = 文档，边 = 同源、支持、矛盾）；
  2. 通过优化问题估计所有文档的信任分数（离线）；
  3. 查询时执行信任感知的重排序（rescoring），平衡相关性分数与信任分数；
  4. 信任感知的提示（prompting），使LLM在生成时优先依赖高信任文档、忽略低信任文档。
- **文档关系图构建**：
  - 图 \(G=(C,E)\)，每个节点为文档，边上有关系标签 \(\ell_{ij} \in \{+1, 0, -1\}\)（+1=支持/同源，−1=矛盾，0=无明确关系），以及置信权重 \(w_{ij} \in [0,1]\)。
  - 支持/矛盾关系可由来源元数据或NLI模型（如 nli-deberta-v3-small）推断。
- **信任得分优化**：
  - 保存反馈集合 \(F = F^+ \cup F^-\)，正反馈 y=τ⁺（接近1），负反馈 y=τ⁻（接近0）。
  - 定义两类损失：
    - 成对一致性损失 \(L_{\text{pair}}\)：支持边 \((ℓ=+1)\) 最小化 \((\tau_i-\tau_j)^2\)；矛盾边 \((ℓ=-1)\) 最小化 \((\tau_i+\tau_j-1)^2\)（即两者不应同时得到高信任）。
    - 反馈损失 \(L_{\text{fb}}\)：\(\sum_{d_i \in F}(\tau_i - y_i)^2\)。
  - 联合优化 \(\tau^* = \arg\min_{\tau\in[0,1]^N} L_{\text{pair}} + \lambda_f L_{\text{fb}}\)。
  - 采用投影梯度下降（PGD）求解，利用图的稀疏性，每次迭代只计算有边连接文档对的梯度。初始化基于与邻居边的符号加权聚合。
- **理论分析**：
  - Lemma 1（信任传播）：反馈文档的信任值扰动对其余文档影响随图距离呈指数衰减（因子 \(q^{d_G(i,f)}\)），说明根植于多跳路径的稀疏反馈也能有效散布。
  - Lemma 2（收敛）：PGD 解线性系统 \(Aτ^*=b\)，在固定步长 \(\eta^\star = 2/(\sigma_{\min}+\sigma_{\max})\) 下的误差收缩因子 \(\rho=(\kappa-1)/(\kappa+1)\)，迭代复杂度为 \(O(\kappa\log(1/\epsilon))\)。实验内1000步内收敛。
- **推理时应用**：
  - 信任感知重排序分数 \(r_i = \alpha\tau_i + (1-\alpha)s_i\)（\(s_i\) 为归一化检索相关性分数），取前k篇作为上下文。
  - 信任感知提示将文档及其信任分数一同输入，指令模型优先参考高信任（τ≥0.7）文档、忽略低信任（τ≤0.3）文档。
  - 信任优化在离线阶段完成，计算成本分摊到未来所有查询；查询时仅增加轻量重排序开销。

## 3. 实验设计与 Benchmark

- **数据集**（三个开放域QA基准）：
  - MS MARCO（805份文档），NQ（893份文档），TriviaQA（1037份文档）。每个数据集随机采样300个(回答,问题)实例，半数字段混有仿照PoisonedRAG生成的流利、相关但误导性的矛盾文档。另加入QACC数据（真实自然冲突）评估实际语料鲁棒性。
- **检索器**：BM25（稀疏）、Contriever（稠密）、基于all-MiniLM-L6-v2（稠密）。
- **LLMs**：封闭模型（GPT-4o-mini、GPT-5、Gemini 2.5 Flash、Gemini 2.5 Pro）与开源模型（Llama-3.1-8B-Instruct、Mistral-7B-Instruct）。
- **评价指标**：
  - **EM**（Exact Match）为主要答案质量指标；
  - **FP@k**（Fact Precision@k）评估检索质量 = top-k中事实/正确文档占比。
- **对比的基线**：
  - VanillaRAG（直接使用检索器得分排序）；
  - InstructRAG（用自合成理由指导LLM去噪）；
  - AstuteRAG（利用内部知识与外部证据比对消解冲突）；
  - ReliabilityRAG（基于NLI检测矛盾并选择无矛盾文档子集）；
  - TrustRAG（第一阶段聚类过滤不可靠文档）。
- **默认参数**：k=5，反馈比例FB=30%，α=0.6，λ_f=1.0，τ⁺=0.9，τ⁻=0.1，PGD步长0.01，最多1000轮迭代。

## 6. 主要结论与发现
- TrustPropRAG在所有三个数据集与三个检索器下均取得最佳EM（比最强基线提升0.03–0.11），如MS MARCO BM25上EM达0.47、NQ MiniLM上0.59、TriviaQA Contriever上0.78。
- FP@5 上限大幅提升：从基线38–57%提升到77–96%，证明信任分数可显著提高top-k集合中事实/正确文档的比例；组件消融显示信任优化的不可替代性（仅直接使用反馈EM为0.36 vs 完整框架为0.49）。
- 即使使 Graph 只含 NLI 推导的关系（去掉源组边），框架仍然有效（EM 0.44、FP@5 79%），对图中稀疏且有噪声的 NLI 关系具备鲁棒性。
- 反馈比例不需要太高，10%即接近于较高比例的收益；信任传播的误差因传播过程中在“矛盾边—支持边”上的折中而大幅缓解（即使在40%错误标签下仍相比无反馈有明显提升）。
- 与更强 LLM（GPT-5、Gemini Pro）结合时增益更大，说明提高输入证据可靠性对于强模型持续有效。
- 理论证明给出了传播行为（随图距离衰减）和收敛性保证，为使用迭代式PDG提供了基石。

## 7. 方法/设计亮点
- **解决实际短板**：不再局限于单跳文档比较，而是利用文档关系图的多跳可达性，将昂贵的人类反馈信息扩散至整个语料。
- **模型通用性与集成简易性**：信任分数独立于LLM、检索器，以重排序和提示形式接入即可，可与任意检索器和LLM结合。
- **理论赋能**：利用二次优化、矩阵扰动与衰减界分析，提供了信任传播递减的定量论据（Lemma 1）与迭代收敛保证（Lemma 2），对模型设计提供充分的理论基础。
- **系统清晰的设计**：将反馈、文档一致性约束、信任优化和提示融合在一个整体框架里，对核心信任优化、检索和生成环节各有清晰定位。
- **设置了强实数消融与参数敏感性曲线**：如只保留反馈vs加图传播；去掉源组边只保留NLI；α 扫描等，证明了各组件的贡献与稳定参数范围。
- **鲁棒性验证较为扎实**：针对反馈准确率、反馈比例、边缘错误率以及规则覆盖都做了测试，并且附加QACC自然冲突语料补充生态效度，说明泛化性不只是合成的产物。

## 8. 不足与局限
- **反馈类型为二值**：将人工反馈简化为了可靠/不可靠的二分类标签，未考虑分级信任（如分级评分或不同置信度的反馈），现实世界反馈通常有强度与粒度。
- **不可靠文档的注入方式偏合成**：主实验以PoisonedRAG模拟方式注入矛盾和误导文档，而不是完全源于真实互联网的自然冲突分布（虽然QACC实验弥补了一部分限制性，但规模较小，且QACC样本量有限）。
- **任务覆盖窄**：仅在短答案型开放域QA上（问题—答案对）验证，未拓展到长式生成、多步推理、推荐或对话式等场景，对于生成的可靠性的纵向细节（如信息可能为真但来自低质来源）未做区分。
- **对图的依赖**：图质量（尤其是NLI部分）对整体性能有较大影响，如果语料语义关系极度稀疏或噪声较高，可能影响传播衰减的充分性；虽然NLI-only消融中仍有增益，但需要进一步检验大规模低质量边的鲁棒性。
- **对同构图的假设**：对“同源文档”的真实来源元数据在许多场景下不可得；论文对MS MARCO和NQ使用了**模拟源组**，这属于用于做Source Reliability评估的近似手段，可能与真实源特性存在差异。
- **信任与主题概念的耦合风险**：信任分数的优化以文档为单位，未考虑同一文档在不同问题上可能出现的可靠性差异（例如一份文档在某一主题上是可靠的，在其他主题则过时或有误），因此在更细粒度上有改进空间。
- **理论假设的限制**：引理需要每个连通图至少一个反馈节点等假设，现实语料很难保证这种覆盖率。论文理论分析使用无约束二次函数的解来近似有约束情形的最优解。
- **响应质量仅以短答案EM衡量**：EM容易受表述归一化影响，同时未对答案事实性、流畅性和全面性比如其他可靠性指标（如事实性评分）等做对比。

## 总结
TrustPropRAG 成功利用文档关系图将稀疏、噪声的人类反馈通过多跳传播转译成全语料的文档信任度，并整合到检索排序与生成提示中，在多个数据集/检索器/LLM 组合下显著提升 RAG 可靠性，是“有限反馈+图传播”用于RAG可靠性增强的一项系统而充分验证的工作，但离扩大部署还需要更强的真实数据泛化、多任务覆盖与更丰富的反馈形态。
