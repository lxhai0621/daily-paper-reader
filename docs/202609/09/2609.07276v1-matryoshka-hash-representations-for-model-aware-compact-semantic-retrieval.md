## 摘要
检索增强生成（RAG）依赖于密集检索：每个文档存储为一个学习到的向量，查询通过在该向量空间中找到其最近邻来回答。在语料库规模下，为每个文档保留一个全精度向量是主导的索引成本，因此检索系统用几个字节的短代码替换每个向量——这一步骤称为量化。标准量化器（如乘积量化，PQ）选择最接近重建原始向量的代码。如果单个代码能同时服务于多个字节预算，则更为有用：当其短前缀各自可直接搜索时，部署可以在不重新编码语料库的情况下设置其效率-质量操作点。但在单一目标下训练所有前缀会使早期比特成为各预算之间的折衷——短代码得到改进，而全宽度代码则退化。量化到低比特表示（如二进制代码）进一步加剧了冲突。我们引入了套娃哈希表示（MHR），这是一种将全宽度训练与前缀组织分离的两阶段过程。MHR首先学习一个更长的二进制代码，然后冻结模型并训练额外的零初始化残差代码适配器，用于可直接搜索的前缀。文档以每坐标一位存储，而查询像PQ一样保持连续logits以获得足够的表达力。我们使用FAISS FastScan实现搜索过程。在MS MARCO上训练并零样本迁移到七个BEIR数据集，MHR在32字节时达到.5561 NDCG@10和.6535 Recall@100，超过了同预算的最佳基线。在较低预算下优势更为明显。相同的代码还增强了两条常见流水线：为全精度重排序生成候选名单，以及剪枝低存储图索引（如LEANN）。

## Abstract
Retrieval-augmented generation (RAG) depends on dense retrieval: each document is stored as a learned vector, and a query is answered by finding its nearest neighbors in that vector space. Keeping one full-precision vector per document is the dominant index cost at corpus scale, so retrieval systems replace each vector with a short code of a few bytes---a step called quantization. Standard quantizers such as product quantization (PQ) pick the code that reconstructs the original vector most closely.   A single code is even more useful if it serves several byte budgets at once: when its short prefixes are each directly searchable, a deployment can set its efficiency--quality operating point without re-encoding the corpus. But training all prefixes under one objective makes the early bits a compromise across budgets---short codes improve while the full-width code degrades. Quantization to low-bit representation, such as binary codes, further sharpens the conflict. We introduce Matryoshka Hash Representations (MHR), a two-stage procedure that separates full-width training from prefix organization. MHR first learns a longer binary code, then freezes the model and trains additional zero-initialized residual code adaptors for directly searchable prefixes. Documents are stored at one bit per coordinate, while queries keep continuous logits like PQ to attain sufficient expressivity. We implement the search process with FAISS FastScan. Trained on MS MARCO and zero-shot transferred to seven BEIR datasets, MHR reaches .5561 NDCG@10 and .6535 Recall@100 at 32 bytes, surpassing the best baseline of the same budget. The advantage is more pronounced in lower budgets. The same code also strengthens two common pipelines: shortlisting candidates for full-precision reranking, and pruning a low-storage graph index such as LEANN.

### 1. 核心问题与研究动机
- **背景**：检索增强生成（RAG）系统高度依赖稠密检索，其核心瓶颈在于需要为海量文档存储全精度向量，导致索引成本高昂。
- **现有方案与不足**：
    - **量化技术（PQ等）**：标准量化器是模型无关的，主要优化重建误差，而非最终的检索排序效果。在极低字节预算下，其性能不佳。
    - **嵌套编码（Matryoshka等）**：允许用单一码字的前缀服务多种字节预算，但直接联合训练所有前缀会引发**"全宽-前缀权衡"问题**——优化短码会损害全宽度（最长码）的质量。这种冲突在二进制码（高低比特）的训练中尤为尖锐。
- **研究问题**：如何训练一种二进制码，使其既能提供高质量、可直接搜索的短前缀，又不牺牲全宽度码的性能？

### 2. 方法论：Matryoshka Hash Representations (MHR)
- **核心思想**：采用**两阶段流程**，将“全宽度码训练”与“前缀码组织”解耦，从而避免直接联合训练带来的权衡问题。
- **阶段一：单宽度模型训练（Stage I）**：
    - 基于预训练双编码器（BGE-base），使用LoRA技术进行微调，并添加一个哈希头。
    - 目标是学习一个**强力的、单宽度的256-bit（32字节）二进制码**。
    - 训练损失函数组合了硬文档相关性排序、局部与缓存BGE蒸馏、MiniLM排序和一位平衡（code-balance）正则化。
    - 训练此阶段时已采用**非对称搜索**模式：文档使用硬符号（STE），查询保持连续。
- **阶段二：残差前缀适配（Stage II）**：
    - **冻结阶段一训练好的全部参数**。
    - 在冻结的256维logits之上，级联训练 `R=2` 个**零初始化残差适配器**。
    - 零初始化的关键作用：保证模型在训练的起始点与阶段一的强解完全一致。
    - 通过在前缀上的排序损失和全宽度排序锚定损失（来自阶段一的自蒸馏），将残差容量分配到不同前缀上，使得64-bit（8B）、128-bit（16B）和256-bit（32B）的码都可直接搜索，且互不纠缠。
- **部署与检索**：
    - **非对称检索**：文档硬二值化存储，查询保留连续logits最大程度保持表达力。
    - **高效搜索**：利用解析查找表（analytic LUT）将内积计算转化为查表操作，实现了FAISS FastScan的原生集成，支持平铺扫描和IVF路由搜索。

### 3. 实验设计与基准
- **训练数据与零样本评估**：仅在 **MS MARCO** 段落排序训练集上训练。评估采用**零样本迁移**到7个**BEIR**数据集（Quora, NQ, HotpotQA, DBpedia-Entity, FEVER, TREC-COVID, Climate-FEVER）。
- **对比方法**：
    - **模型无关量化器**：PQ, OPQ, RaBitQ。
    - **哈希/二进制编码方法**：SRP-LSH, Super-Bit, PCA-RR, ITQ。
    - **学习型离散检索器**：JPQ-FT (联合优化PQ), JPQ-Nested (本文的受控嵌套变体)，以及各种直接的嵌套训练baseline。
- **指标**：NDCG@10 和 Recall@100（宏观平均）。

### 4. 资源与算力
- **硬件**：所有训练和评估使用 **1张 NVIDIA A100 80GB GPU**。
- **训练时间**：阶段一约 **29 GPU-小时**，阶段二约 **2 GPU-小时**。（实验在单CPU线程上进行延迟测试。）

### 5. 实验数量与充分性
- 实验非常全面且客观，包含多层次验证：

    - **数据集详细分析**：展示了在每个BEIR数据集上的性能（Quora等），证明宏观优势并非由单一语料驱动。

### 6. 主要结论与发现
- **性能卓越**：在所有量化预算下（8/16/32字节），MHR在宏观NDCG@10和Recall@100上全面领先所有基线。在16字节预算下优势尤甚（NDCG@10达到.502 vs. 最佳基线JPQ-FT的.404）。
- **化解权衡**：MHR成功消除了"全宽-前缀"权衡，其32字节码性能（.556）接近单一宽度的强基线模型，并使短前缀的性能成为可能。
- **下游应用的提升**：MHR作为替换PQ的方案，能显著提升IVF的扫描质量；其8字节码在LEANN-HNSW图剪枝中，在保持几乎无损的精度的同时，比目标拟合的PQ基线平均减少更多距离计算；在粗过滤+全精度重精排实验中，其8字节码过滤K=100候选即达到.561 NDCG@10，优于其自身的32字节压缩码。

### 7. 优点与新颖点

- **严谨的评估体系**：通过标准的零样本BEIR基准、全面的消融研究和下游系统的集成测试，论证了该方法的普适性和强大性。

### 8. 不足之处与局限性
- **训练数据单源性**：MHR仅基于MS MARCO训练，尽管已在多个BEIR数据集上评估，但该单源域的特性可能无法完全代表其他垂直领域（如代码、生物医药）的最佳效果，存在域迁移的上限风险。

- **评估的局限性**：消融实验仅在5个数据集上运行，而非全部7个BEIR数据集；且研究中未报告方法的方差，无法完全排除超参数随机波动带来的种子效应。
