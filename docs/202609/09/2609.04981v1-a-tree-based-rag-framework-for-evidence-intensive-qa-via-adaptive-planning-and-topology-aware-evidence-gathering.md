## 摘要
近期的结构化RAG方法利用基于树或图的推理结构来改进多跳问答。然而，在证据密集型问答中，回答一个问题需要综合分散在数十甚至数百篇文档中的信息，这些方法面临关键限制：结构刚性限制了自适应推理扩展，以及忽视拓扑的证据收集阻碍了跨不同推理节点的有效证据整合。为解决这些问题，我们提出APT-RAG，一个自适应规划与拓扑感知证据收集的RAG框架。自适应规划根据问题依赖和证据需求动态扩展推理结构，而拓扑感知证据收集通过兄弟证据重用、直接检索和子节点证据聚合来提高证据覆盖率。我们进一步引入证据引导的批量答案生成，以减少证据密集型问答中显著的生成开销。在证据密集型问答基准上的实验中，APT-RAG优于现有结构化RAG方法。我们的代码可在https://github.com/hyudsl/APT-RAG获取。

## Abstract
Recent structured RAG methods leverage tree- or graph-based reasoning structures to improve multi-hop QA. However, they face key limitations in evidence-intensive QA, where answering a question requires synthesizing information scattered across dozens or even hundreds of documents: structural rigidity, which limits adaptive reasoning expansion, and topology-ignorant evidence gathering, which prevents effective integration of evidence across different reasoning nodes. To address these issues, we propose APT-RAG, an Adaptive Planning and Topology-aware evidence gathering RAG framework. Adaptive planning dynamically expands the reasoning structure based on question dependencies and evidence requirements, while topology-aware evidence gathering improves evidence coverage through sibling evidence reuse, direct retrieval, and evidence aggregation from child nodes. We further introduce evidence-guided batched answer generation to reduce significant generation overhead in evidence-intensive QA. In the experiments on evidence-intensive QA benchmarks, APT-RAG outperforms existing structured RAG methods. Our code is available at https://github.com/hyudsl/APT-RAG.

## 1. 核心问题与整体含义（研究动机与背景）

- **问题定义**：论文聚焦于 **证据密集型问答（Evidence-Intensive QA）**，即回答一个问题需要从数十甚至数百篇文档中检索并综合分散证据。与仅需少量支撑页面的传统多跳QA（如HotpotQA平均约2.0页）不同，证据密集型QA（如MoNaCo平均需43.3页）对检索和推理的结构提出了更高要求。
- **现有方法的缺陷**：结构化RAG（树/图结构）虽在一定程度上改进了多跳推理，但在证据密集型场景下存在两大关键局限：
  - **结构刚性（Structural Rigidity）**：如Plan*RAG，预先构建固定推理计划，无法根据问题复杂度动态扩展推理结构，导致单一节点被迫处理大量证据（如一次综合19篇文档中13场战争的信息），易失败。
  - **忽视拓扑的证据收集（Topology-ignorant Evidence Gathering）**：如ToQ，虽构建推理树，但仅在根节点收集证据，不利用其他节点子问题的答案，导致子问题可被已有答案直接回答却仍需额外检索，造成证据遗漏（例如图1中q2可由q2,4直接推出，却未聚合）。
- **总体意义**：为解决以上问题，论文提出 **APT-RAG**（Adaptive Planning and Topology-aware evidence gathering），通过递归深度优先遍历动态构建推理树，并以拓扑感知方式跨节点汇聚证据，从而支撑大规模分散文档的问答任务。

## 2. 方法论：核心思想、关键技术细节、算法流程

### 2.1 总体框架（树形递归 + 深度优先遍历）

- 从根问题 Q 出发，采用**递归深度优先遍历**构建推理树；每个节点代表一个子问题。
- 过程分为**前序规划（Pre-order Planning）**与**后序收集与回答（Post-order Gathering & Answering）**。
- 每个节点执行四步：**上下文化（Contextualization）** → **自适应规划（Adaptive Planning)** → **拓扑感知证据收集（Topology-aware Evidence Gathering)** → **答案生成（Answer Generation）**。

### 2.2 节点级处理详解

1. **上下文化**：
   - 处理子问题中的占位符引用 `<Q_j>`，即后续子问题依赖此前兄弟问题答案中的实体/数值/约束。
   - 通过“先前兄弟QA对”对当前问题补全，使其自包含（如图2(c)中，把“每个国家”具体化为国家列表）。

2. **自适应规划**：
   - **可答性检查器（Answerability Checker）**：决定当前问题能否仅凭已有兄弟QA对回答（即“横向可答”），避免不必要的检索/分解。
   - **分解器（Decomposer）**：如果不能横向解决，则判断当前问题是原子问题（直接检索）还是需要拆分为多个子问题（递归垂直展开）。
   - 这一机制使推理树的深度/广度可随问题需求灵活调整，而非固定。

3. **拓扑感知证据收集**——三种策略：
   - **横向收集（Lateral Gathering）**：从**先前兄弟节点的QA对**中提取相关证据 → 对应“可答”分支，避免冗余检索。
   - **外部收集（External Gathering）**：利用改写后的原子检索查询做语义检索（余弦相似度，top-k文档）→ 对应“直接检索”分支。
   - **垂直收集（Vertical Gathering）**：当父问题被分解后，各子节点分别检索/推理生成QA对，再将所有子QA对**聚合回父节点**作为证据 → 实现从叶到根的逐层证据汇总。

4. **答案生成**：
   - 每个节点基于其收集的证据生成子答案；子答案可继续作为上层或兄弟节点的证据。
   - 根节点最终综合其直接子节点的QA对输出最终答案。

### 2.3 证据覆盖范围设计

- 对每个节点而言，推理树中的其他节点被划分为：自身子树（垂直获取）、兄弟子树（横向获取）、祖先及其兄弟子树（由祖先处理）。
- **垂直传播**逐步聚合子答案，而不是一次性吞入整棵子树；**横向复用**避免重复检索；**祖先层**负责更上位的综合——这种分工避免了全树冗余聚合，使各节点可利用本地局部证据。

### 2.4 证据引导的批量答案生成（Evidence-Guided Batched Answer Generation, EC）

- **动机**：许多兄弟子问题（如同一属性跨多个实体）高度共享证据（如在“美洲各国土著比例”问题中，35个子问题里20个可用同一张表回答）。逐个回答将导致大量冗余LLM调用。
- **优化流程**：
  - 当一个父节点分解出多个子问题后，先对所有子节点做规划，选出**不依赖兄弟答案且采用外部收集**的候选子问题执行批处理。
  - **聚类为最少数量的簇**，约束：① 簇内证据两两Jaccard相似度 > τ_S；② 簇内合并后的证据token长度 < τ_L（上下文窗口限制）。
  - 数学建模：将问题形式化为**带约束的聚类优化——最小簇数K**（式1a-1e）。通过**松弛上下文约束**，将其归约为**团划分问题（Clique Covering Problem, CCP）**；再通过互补图把CCP等价转化为**图着色问题**，并用**改进的Welsh-Powell最大优先贪心着色算法**近似求解。算法伪代码见论文Algorithm 3，复杂度O(m + n log n)。
  - 每个簇的多个子问题被放入同一个提示，以合并去重后的文档作为共享证据，一次调用模型生成簇内全部答案（输出JSON字典，键为问题编号）。
- **效果**：显著减少LLM调用次数和输入token数，尤其是长尾高延迟问题。

## 6. 主要结论与发现

- **核心结论**：递归式、拓扑感知的证据收集是处理大规模分散文档问答的有力方向。APT-RAG在两类基准、两种模型规模下均取得了最优或接近最优的答案F1与检索召回。
- 主结果显示（30B设置下）：
  - MoNaCo上：APT-RAG的Answer F1 = 50.84，显著高于Plan*RAG（47.03）、LogicRAG（46.41）、ToQ（46.66）；检索召回达50.79，远超基线（最高Plan*RAG 39.28）。
  - QAMPARI上：APT-RAG F1 = 23.28，优于各基线（ToQ为21.37、NaiveRAG为20.46）。
  - 4B小模型下性能衰减相对更小，说明方法的稳健性。
- **自适应扩展的有效性**：基线检索文档数几乎恒定，而APT-RAG随所需金文档数量递增检索规模、树深度/广度；且证据规模越大，性能下降越平缓（31+页场景中检索召回依然最高）。
- **效率提升**：EC与LG分别减少推理延迟约8.2%和41.4%，在95百分位长尾问题上延迟削减最大；即使高成本基线RT-RAG的推理开销也远大于APT-RAG，且性能并未全面占优。

## 7. 优点（亮点）

- **问题剖析深入**：明确指出两个关键缺陷（结构刚性、忽视拓扑的证据收集）并用图示化失败案例说明，问题定义清晰。
- **自适应性设计**：用可答性检查+按需分解替代固定深度/广度，能随查询复杂度调整搜索空间；消融证明其比固定广度方案在F1与延迟之间取得更好权衡。
- **拓扑感知的三方证据流设计**：横向/外部/垂直三种策略的自然划分，很好地减少了冗余检索并增强跨节点证据汇总，是强于普通树/图RAG的关键机制。
- **理论建模严谨**：批量答案生成的“簇数最小化”问题被规范形式化，并经过松弛、归约到图着色问题、贪心近似与近似界证明，附录E提供了完整的数学推导。
- **效率工程有实际价值**：利用共享证据批量回答子问题，大幅削减LLM调用；而且不改变推理树结构与证据语义，属于“无损”加速的一种形式。
- **实验分析全面**：不仅报告平均F1与召回，还分析了不同证据规模组的性能、LLM成本、延迟分布、聚类质量、显著性检验、双评判器一致性，形成完整证据链。

## 8. 不足与局限

- **方法论局限（作者已声明）**：
  - 证据密集型QA的推理延迟与 token 成本仍较高，虽经EC缓解，但随证据/分支增长仍会增加；树剪枝等控制手段未探索。
  - 规划模块（可答性判定、分解器）由LLM零样本完成，若分解或判定有误，可能导致不必要的推理分支或错误传播；未来需优化规划模块。
- **实验局限**：
  - MoNaCo与QAMPARI都是基于维基百科语料的英文开放域任务；对专业领域（医学、法律）、非英文多语言场景的泛化性未验证。
  - MoNaCo评估依赖GPT-5.4和Gemini-3.5-Flash，这两种LLM评判虽一致但非人工评判，可能存在系统性偏好。
  - 在论文4.1节标注的arXiv编号为“2609.04981v1”（2026年9月，虚拟未来时间），若按实际可用状态其引用DOI等存在有效性疑虑；实验时间无法确认。
  - 由于RT-RAG成本昂贵仅在300例子集比较，基于小样本的对比可能低估同规模下的方差。
- **资源报告不透明**：未给出训练/推理总计算量、GPU运行时长及能源消耗，不利于复现与效率核算。
- **应用性限制**：以RAG框架为核心，但为提升效率引入了较复杂的聚类算法（图着色），实操中用户需额外理解与调节τ_S、τ_L等超参；编码/部署复杂度较高。
