## 摘要
长期记忆是个性化大语言模型代理的核心能力。为了支持这一能力，现有的记忆系统使用多种标准来组织信息，例如主题片段或摘要层级。然而，我们发现了这些设计中的两个主要局限。首先，它们缺乏场景感知：来自不相关生活场景的记忆共享同一检索空间，这扩大了搜索空间并引入了跨场景干扰。其次，它们从单一视角编码每条记忆，使得难以检索同一事件的互补视角。在本文中，我们提出了CreaMem架构，通过将记忆划分为多个生活场景记忆来实现场景感知的记忆组织，以减少检索时的跨场景干扰。为了超越单一视角并实现跨记忆协同，每条条目在每种记忆中都从情景和特质两个视角进行双重编码。我们进一步在检索时设计了一种每记忆平衡采样策略。在两个长期记忆基准上的大量实验表明，CreaMem在所有评估指标上提高了问答准确性，在多跳推理性能上尤其获得了大幅提升，验证了场景感知划分和跨记忆协同的有效性。为了增强可复现性，我们在公共GitHub仓库中发布了代码。

## Abstract
Long-term memory is a core capability for personalized LLM agents. To support it, existing memory systems organize information using various criteria such as topic segments or summary hierarchies. However, we identify two major limitations in these designs. First, they lack scene awareness: memories from unrelated life scenes share the same retrieval space, which inflates the search space and introduces cross-scene interference. Second, they encode each memory from a single perspective, making it difficult to retrieve complementary views of the same event. In this paper, we propose the CreaMem architecture, which enables scene-aware memory organization by partitioning memory into several Life Scene Memories to reduce cross-scene interference at retrieval. To go beyond the single perspective and achieve cross-memory synergy, entries are dual-coded from both episodic and trait-based perspectives within each memory. We further devise a permemory balanced sampling strategy at retrieval time. Extensive experiments on two long-term memory benchmarks show that CreaMem improves QA accuracy across all evaluation metrics, with particularly large gains on multi-hop reasoning performance, validating scene-aware partitioning and cross-memory synergy. To enhance reproducibility, we release our code in a public GitHub repository.

## 1. 论文的核心问题与整体含义

**研究动机与背景：**
- 大型语言模型正在从单会话工具演变为长期个性化代理，长期记忆是支撑跨会话连贯交互的核心能力。
- 现有长期记忆系统尽管在组织方式上有所不同（扁平存储、结构化摘要/知识图谱、按认知功能或时间尺度划分记忆），但普遍存在两个共同缺陷：
  1. **缺乏场景感知**：来自不同生活场景（工作、家庭、兴趣等）的记忆被混在同一检索空间，导致检索空间膨胀并产生跨场景干扰。
  2. **单一视角编码**：每条经验只从一种角度记录，难以支持从互补视角回忆同一事件。
- 作者从认知心理学中找到理论依据：自传体记忆按“人生情境”而非抽象类别组织；情景记忆与语义记忆以互补形式协同编码经验。
- 整体意义在于：记忆组织的“结构性设计”本身是影响长期代理行为连贯性的关键杠杆，而不仅仅是提供更多上下文。

## 2. 论文提出的方法论

**核心思想：**
- 将长期记忆按“生活场景”划分，并把每条经验**双重编码**为情景条目与特质条目，从而减少检索干扰、实现跨记忆协同。

**核心架构（CreaMem）：**
- 由五类记忆组件构成：
  - **Episodic Memory（情景记忆）**：存储带时间戳的具体事件条目，包含事件类型、摘要、细节及其稠密向量，支持时间锚定查询。
  - **Life Scene Memories（生活场景记忆）**：包括 Life（生活）、Work（工作）、Interest（兴趣）三个场景模块，每个条目是“场景条件化的特质推断”，例如“用户周末喜欢家庭户外活动”，并附重要性权重和向量。
  - **Core Memory（核心记忆）**：存储跨场景稳定的用户画像，达到容量阈值后自动压缩。
  - **Meta Memory Manager（元记忆管理器）**：在写入时对输入消息进行场景路由和条目提取，遵循“宽进严滤”的策略，不确定时同时触发多个记忆模块，避免信息遗漏。
- **写入流程**：
  1. Meta Memory Manager 将消息分类到相关场景子集（可能同时命中多个）。
  2. 对每个命中场景使用 LLM 提取出结构化条目（情景条目为事件摘要+细节，场景条目为特质+重要性分数）。
  3. 新条目与已有条目做相似度匹配，LLM 决定合并或新建，条目存储在 SQLite 中。
- **检索流程**：
  1. Planner LLM 针对问题选择要查询的记忆组件并生成 3–6 个检索关键词。
  2. 在每个选中的记忆内部，同时使用 BM25（词项匹配）和余弦相似度（向量匹配）双路检索，各取 top-k 候选。
  3. 合并候选集合，通过**每记忆平衡采样**保证没有一个记忆组件主导检索池。
  4. 全局重排序采用 **Reciprocal Rank Fusion（RRF）**：
     \[
     RRF(c) = \frac{1}{k_0 + rank_{bm}(c)} + \frac{1}{k_0 + rank_{emb}(c)}
     \]
  5. 取 RRF 得分最高的 top-N 条目拼入 prompt，用于生成回答；若判断信息不足，则触发一次小规模补充查询。

**关键技术亮点：**
- 将同一经验同时记录为“情景条目”（具体事件）和“场景特质条目”（抽象偏好），两者在检索时形成互补证据。
- 检索时每个记忆均贡献相同数量候选，保证时间线视角和场景特质视角协同生效。

## 8. 不足与局限

1. **场景分类固定化**：Life/Work/Interest 只是粗糙的、先验设定的分类，并非对所有用户或跨文化、跨领域都最优；论文承认未来需要可配置/自动学习场景划分。
2. **系统延迟与成本**：额外增加了路由、双码提取和 RRF 重排序等开销，使端到端延迟（2.9 秒/查询）高于 A-Mem（1.98 秒/查询），且不排除二次检索导致的额外成本。
3. **评测基准覆盖面有限**：主要基于合成超长对话（LoCoMo）与评估会话记忆的 LongMemEval-S，缺少真实用户长期交互场景，结论的外推性受限。
4. **缺乏对人类偏好/体验的直接评估**：只以自动问答和参考答案匹配为主，未讨论检索到的证据多样性对用户感知、隐私、安全性等方面的影响。
5. **写入成本对比不公允**：论文自己指出各方法在批处理粒度、提取 prompt、存储抽象层上存在差异，难以进行标准化比较，也没有公开每方法写入耗时或 LLM 调用次数。
6. **消融中的“人类标注”样本量少**：三名标注者之间一致性未给出详细统计学报告；场景覆盖率或受标注者主观影响。
7. **失败模式说明了两类残余问题**：不能保证检索到互相链接的隐含证据；即便证据都已出现在上下文中，响应生成端也可能无法将它们组合推理。这说明 CreaMem 在“证据链接”和“显式组合推理”上仍留有改进空间。
