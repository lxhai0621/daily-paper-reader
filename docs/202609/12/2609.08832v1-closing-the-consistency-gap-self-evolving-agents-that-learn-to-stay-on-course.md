## 摘要
由大语言模型（LLM）驱动的智能体平均而言可以很准确，但在实际生产中却不可靠；这一差异虽已被观察到，但在很大程度上仍未得到解决。在 AppWorld 基准上，使用 GPT-4.1 的 ReAct 智能体在五次执行同一任务时，仅 53% 的情况下五次运行全部成功，尽管其单次运行的平均通过率为 77%。我们将这 24 个百分点的差距称为一致性差距，并认为解决这一问题是可信 AI 智能体部署的前提条件。我们提出一种自进化智能体框架，通过识别智能体轨迹中不稳定、低一致性的步骤，并将其转化为智能体在后续运行中可利用的情景记忆，从而缩小这一差距。其核心是一个一致性分析器，用于精确定位轨迹在多次执行中可能发生翻转的位置及原因；以及一个指南生成器，用于将诊断结果转化为有针对性的指南，将其写入记忆，并注入智能体未来在类似任务上的执行过程。在 AppWorld 上使用 ReAct/GPT-4.1 时，我们的框架将五次运行全部成功的任务比例在相同任务评估上提高了 16 个百分点，在相似任务泛化上提高了 13 个百分点。

## Abstract
Large language model (LLM)-powered agents can be accurate on average yet unreliable in production, a discrepancy that has been observed but remains largely unaddressed. When given the same task five times, a ReAct agent on the AppWorld benchmark using GPT-4.1 succeeds in all five runs only 53% of the time, even though its per-run pass rate averages 77%. We call this 24-point shortfall the consistency gap, and we argue that addressing it is a precondition for trustworthy AI agent deployment. We present a self-evolving agent framework that reduces this gap by identifying unstable, low-consistency steps in agent trajectories and converting them into episodic memory the agent can draw on in future runs. At its core is a Consistency Analyzer that pinpoints where and why a trajectory is likely to flip across executions, and a Guideline Generator that converts the diagnosis into targeted guidelines, committed to memory and injected into future agent executions on similar tasks. On AppWorld with ReAct/GPT-4.1, our framework raises the fraction of tasks that succeed in all five runs by +16 points on same-task evaluation and +13 points on similar-task generalization.

## 1. 核心问题与整体含义
- **核心问题**：LLM 智能体常表现出“平均准确率尚可，但重复运行不可靠”的现象。论文将其形式化为**一致性差距（consistency gap）**：同一任务、同一智能体、同一模型多次运行时，结果会在成功与失败之间翻转。
- **关键例证**：在 AppWorld 上，ReAct + GPT-4.1 的 5 次运行平均通过率 `Mean@5 = 77%`，但 5 次全部成功的任务仅 `Pass^5 = 53%`，差距达 `24.4 pp`。
- **整体含义**：论文认为，标准 benchmark 报告的“平均准确率”掩盖了生产部署中的真实风险；缩小一致性差距是可信 AI 智能体部署的前提。
- **作者立场**：一致性不应只被视作准确率的附属属性，而应作为独立的一级目标，需要专门指标、诊断机制和干预机制。

## 2. 方法论
- **核心思想**：将智能体轨迹中“容易翻转”的低一致性步骤识别出来，离线生成自然语言“一致性指南”，写入情景记忆，并在未来相似任务中注入提示词，从而稳定智能体决策。
- **整体流程**：两阶段离线流水线：
  - **Detect（检测）**：黑盒一致性分析器重采样轨迹中的每个推理点，生成步骤级和轨迹级一致性评分。
  - **Generate（生成）**：LLM 指南生成器将易翻转步骤转化为针对性指南，存入记忆并在运行时检索。
- **关键指标定义**：
  - `Pass@k`：k 次中至少成功一次。
  - `Mean@k`：k 次运行的平均通过率。
  - `Pass^k`：k 次全部成功。
  - **一致性差距**：`Gap@k = Mean@k - Pass^k`。
  - **归一化一致性**：`Consistency@k = Pass^k / Mean@k ∈ [0,1]`，用于消除模型自身能力上限对绝对差距的影响。
- **一致性分析器**：
  - 对轨迹 `T = <s1, ..., sn>` 中的每个推理步骤 `si`，向同一 LLM 端点重新发起该步骤记录的 prompt `N` 次，默认 `N=30`，温度 `≤0.5`。
  - 根据响应类型计算步骤一致性 `C(si)`：
    - **自由文本/代码**：用 SBERT 句向量或代码向量的平均成对余弦相似度。
    - **类别型响应**：如工具名、枚举参数，用平均成对 Jaccard 相似度。
    - **结构化响应**：如 JSON，分解字段后按字段类型分别计算，再加权求和。
  - 轨迹级一致性采用均值聚合：`Cmean(T) = (1/n) Σ C(si)`。
  - 黑盒特性：不访问 logits、内部激活或智能体源码，只重新调用 LLM 端点。
- **指南生成器**：
  - 若步骤一致性 `C(si) < θC`，默认 `θC = 0.85`，且该步骤位于决策路径上，则标记为不一致步骤。
  - 将带标记的轨迹和 scorecard 交给 LLM，生成三类指南：
    - **strategy**：固化“猜对了但高波动”的正确模式。
    - **recovery**：绕过与失败相关的高波动步骤。
    - **optimization**：跳过或简化非必要的高波动步骤。
  - 指南进入基于 Fang et al. (2026) 的双索引情景记忆，带类别、优先级、应用上下文、任务类别、来源等元数据；运行时通过余弦相似度或 LLM 选择器检索并注入 prompt。
- **理论直觉**：不一致源于 token 概率分布“平坦”，近并列 token 在平台噪声下容易翻转；仅靠 greedy decoding 不能解决，因为 hosted endpoint 的概率本身会随运行轻微漂移。
