## 摘要
持久记忆正进入面向生产的智能体平台，以帮助长时程智能体跨会话积累经验。然而，仅限于已完成轨迹的任务后策展智能体可能保留错误、过度泛化部分证据或保留过时知识。我们提出环境探测式策展，这是一种与部署兼容的扩展，为现有的异步策展智能体提供最小权限的只读世界工具，以检查、限定范围并刷新候选记忆。它无需模型重训练，且不改变任务智能体、检索器、记忆表示和生产写入权限。在基于其 SDK 构建的类生产 GitHub Copilot (GHCP) 测试框架中，我们在 CLBench 数据库探索和 90 个改编的 APEX 管理咨询任务上比较了无状态执行、完整上下文学习、GHCP + Mem 和 GHCP + Mem（带环境探测）。在 CLBench 上，环境探测将通过率从 39% 提高到 73%，将通过折扣奖励从 8.60 提高到 22.60，同时将每个问题的查询次数从 8.8 降至 4.7，并将任务智能体成本从 $3.38 降至 $1.68。在六个 APEX 世界中，所有 18 项记忆与基线的平均奖励比较均为正，任务智能体工具调用减少 16% 到 75%；在五个世界中，环境探测带来最佳的任务智能体每美元奖励增益。在 Sonnet 4.6 和 Opus 4.7 上，环境探测也比 GHCP + Mem 获得更高的平均奖励，且没有模式漂移。因此，环境探测将现有的智能体记忆策展转变为一种环境知情、可审计的过程，同时保持紧凑的任务时接口。

## Abstract
Persistent memory is entering production-oriented agent platforms to help long-horizon agents accumulate experience across sessions. Yet a post-task curator agent restricted to completed trajectories can preserve errors, overgeneralize partial evidence, or retain stale knowledge. We introduce environment-probing curation, a deployment-compatible extension that gives an existing asynchronous curator agent least-privilege, read-only world tools to check, scope, and refresh candidate memories. It requires no model retraining and leaves the task agent, retriever, memory representation, and production write authority unchanged. In a production-like GitHub Copilot (GHCP) harness built on its SDK, we compare stateless execution, full in-context learning, GHCP + Mem, and GHCP + Mem (w/ Env Probing) on CLBench database exploration and 90 adapted APEX management-consulting tasks. On CLBench, probing raises pass rate from 39% to 73% and pass-discounted reward from 8.60 to 22.60 while reducing queries from 8.8 to 4.7 per question and task-agent cost from \$3.38 to \$1.68. Across six APEX worlds, all 18 memory-versus-baseline mean reward comparisons are positive and task-agent tool calls fall by 16--75%; probing gives the best task-agent reward gain per dollar in five worlds. Probing also attains higher mean reward than GHCP + Mem on both Sonnet 4.6 and Opus 4.7 without schema drift. Environment probing therefore turns existing agent-memory curation into an environment-informed, auditable process while preserving a compact task-time interface.

## 1. 核心问题与整体含义

- **研究动机**：长时程 LLM 智能体正从单次任务执行走向跨会话持续工作（如演化代码库中的功能开发、企业数据分析、客户支持）。成功依赖于积累反馈，尤其是对跨任务共享的**潜在环境结构**的认知。
- **背景问题**：无状态执行会丢弃轨迹、观察和发现，使经验无法改善后续任务；外部持久记忆虽被引入生产平台（如 Claude Managed Agents、Microsoft Copilot Studio、Mem0、Zep），但**仅依赖已完成轨迹的任务后策展**存在根本缺陷。
- **核心诊断**：一条轨迹只是对环境的单一、片面且常含错误的观察。其教训可能：
  - 记住实例答案而非可复用流程；
  - 继承低效路径；
  - 声称无法验证的适用范围；
  - 在未访问区域留下盲点；
  - 随环境漂移而过时。
- **整体含义**：将验证推迟到任务时会迫使任务智能体耗费稀缺工具调用去复核不确定记忆，而非直接解题。论文提出**环境探测式策展（Environment-Probing Curation）**，在不重训模型、不改动任务智能体/检索器/记忆表示/生产写入权限的前提下，提升写入时证据质量。

## 2. 方法论

### 2.1 核心思想

- 在任务结束后，异步策展智能体获得**最小权限、只读的环境世界工具**，用于在写入持久记忆前核验候选记忆、测试其范围、重演流程并刷新过时条目。
- 保持任务智能体、检索器、蒸馏设置、策展智能体、记忆模式和 CRUD 策略不变，仅给策展智能体增加只读探测能力。
- 与认知科学中“情景记忆重构与反事实模拟”及交互学习理念一致。

### 2.2 在线设置与任务智能体

- 任务流 \(S=(S_1,\dots,S_N)\)，环境状态 \(E_i\)，可发生未公告的漂移 \(E_{i+1}\sim\Delta(E_i)\)。
- 任务智能体 \(A_\theta\) 每任务新会话，模型参数固定；拥有环境工具 \(TE_i\) 和只读 `memory_read`，无记忆写权限。
- 轨迹记为 \(\tau_i = A_\theta(S_i; TE_i, R(\cdot, M_{i-1}))\)，终端反馈 \(g_i\) 仅在任务关闭后到达。

### 2.3 任务后记忆策展

- 策展智能体 \(C_\phi\) 是独立 LLM 会话，接收已完成轨迹、终端反馈和相关已有记录，拥有四个记忆工具：`memory_read`、`memory_create`、`memory_update`、`memory_delete`，是唯一可变更 \(M\) 的代理。
- 每条记录包含：类别、置信度、适用范围、简明引理、来源、效用和使用元数据。
- **轨迹蒸馏**：非写入预处理 \(d_i = D_\psi(\tau_i)\)，保留任务、检索记忆、关键观察、流程、未解决假设和答案，但不接收终端反馈、无记忆/环境工具，不能写记忆。
- 策展系统提示要求维护“小而可靠、可迁移、可操作”的记录，存储可复用事实、流程、关系、工具约定和带范围警告，而非任务答案或偶然值。

### 2.4 环境探测式策展（Propose–Probe–Commit）

- 在任务关闭后，给策展智能体安全只读环境工具子集和简短探测指令。
- 流程：
  1. **提出**候选记忆；
  2. 进行**有针对性的只读探测**，调查具体不确定性；
  3. 根据观察**创建、修订、缩小、删除或跳过**记录。
- 可执行的探测类型：
  - 区分偶然答案与可复用关系；
  - 比较观察流程与更短路径；
  - 在另一数据切片上测试声称关系；
  - 检查流程所需前置条件；
  - 检查轨迹遗漏的相关状态；
  - 怀疑漂移时重新查询当前环境。
- **边界**：探测不能改变环境、进入任务轨迹、消耗任务智能体预算，也不能暴露未来任务或标签；无安全只读表面时回退到纯轨迹策展。
- 提示词仅增加两个块：只读工具访问说明和验证提示（插入在 Check 与 Reconcile 之间）。

### 2.5 评价公式

- 通过折扣奖励：
  \[
  r_i = p_i \left(1 - \frac{q_i}{B}\right)
  \]
  其中 \(p_i\in\{0,1\}\) 为严格通过，\(q_i\) 为任务智能体工具调用数，CLBench 中 \(B=15\) SQL 查询，APEX 中 \(B=100\) Archipelago 工具调用。
- 多评分标准任务采用严格通过：所有标准通过才 \(p_i=1\)，否则为 0。

## 6. 主要结论与发现

- **CLBench 主结果**：
  - 通过率从 39% 提升至 73%，总奖励从 8.60 提升至 22.60。
  - 每题 SQL 查询从 8.8 降至 4.7，任务智能体成本从 $3.38 降至 $1.68。
  - 输入 token 从 3.14M 降至 1.69M，优于 Full ICL 的 5.42M。
  - 迁移边界处，探测已领先纯轨迹记忆（累计奖励 0.541 vs 0.486），最终 0.565 vs 0.500；无记忆仅 0.215。
- **无漂移跨模型结果**：
  - Sonnet 4.6：GHCP + Mem 提升 +0.351，探测提升 +0.421，探测均值 0.748。
  - Opus 4.7：GHCP + Mem 提升 +0.252，探测提升 +0.263，探测均值 0.721。
- **APEX 结果**：
  - 所有 18 项记忆 vs 基线平均奖励比较均为正。
  - 任务智能体工具调用从基线均值 30.0–71.6 降至 13.9–28.4，减少 16%–75%。
  - 在 5/6 世界中，探测取得最佳“每美元奖励增益”；最大工具调用减少出现在 941eba66（71.6→17.7–19.3），成本从 $54.30 降至 $7–$9。
- **机制解释**：
  - 记忆摊销环境发现；探测使记录更可操作，将“警告/模糊映射”转化为“可执行流程”。
  - 定性示例：轨迹-only 记录“不要用 AVG(items_g2.prc_usd)”；探测记录“Join items_g2 to taxn_g2 on ref_id；filter cat_lvl=1 和精确 cat_nm；保留 prc>0；再比较 filtered AVG(prc)”。
  - 探测在轨迹留下未解决连接、工作簿位置或流程时最有用；轨迹已支持可操作记录时增益有限。
- **总体结论**：环境探测将现有记忆策展转变为环境知情、可审计的过程，提升正确性同时减少重复环境探索和任务智能体成本，且跨 GPT-5.4、Sonnet 4.6、Opus 4.7 模型家族保持优势。

## 7. 优点

- **部署兼容性强**：无需重训练，不改动任务智能体、检索器、记忆表示和生产写入权限；仅给异步策展智能体增加最小权限只读工具。
- **安全边界清晰**：探测只读、不写环境、不进入任务轨迹、不消耗任务预算、不暴露未来任务或标签；无安全只读表面时自动回退。
- **隔离变量设计精巧**：固定任务时接口和 CRUD 生命周期，使增益可归因于写入时证据质量，而非任务时能力增强。

- **企业集成路径明确**：与 Microsoft Copilot Studio 的 connector/MCP 架构映射，可继承现有认证、授权和审计边界。

  - 方法依赖存在**安全、只读的环境探测表面**；若无可用只读工具，则回退到纯轨迹策展，增益消失。
  - 探测可能引入额外策展阶段成本（论文将其单独追踪，未计入任务智能体成本），总拥有成本需在生产中评估。
  - 只读探测不能验证所有类型的记忆（如涉及写操作或不可查询的隐性知识）。
  - 环境漂移模式在实验中较为结构化（schema 重命名、软删除），真实企业环境的漂移可能更复杂、更不规律。
- **长期效应未知**：论文未评估数百或数千任务流下的记忆膨胀、检索退化或错误累积风险。
- **记忆记录质量评估偏定性**：缺少对记录可执行性、覆盖率和错误率的系统量化指标。
