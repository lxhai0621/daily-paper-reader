## 摘要
准备地方历史与文化遗产课程的教师，所依据的材料难以使用。原始资料是没有文本层的扫描书籍，辅助记录是以电子表格形式发布的行政目录。通用聊天机器人能流畅回答此类问题，但无法提供可验证的来源，而这正是教师最需要的特性。本文提出 HistoRAG，一种问答助手，它基于一个区域性馆藏作答，并为每个事实引用卷和页。HistoRAG 使用视觉语言模型转录每一页，并根据 token 概率保留行级置信度。它从同一馆藏构建三个存储：混合文本索引、关系型目录数据库，以及仅从实体密集段落中抽取的知识图谱。一个轻量级路由器将每个问题发送到所需的存储，因此计数问题进入数据库，关系型问题进入图谱。我们构建了一个包含 516 个问题的基准，覆盖 36 卷扫描书籍以及同一地区的遗产目录，涵盖统计型、事实型、时间型和多跳问题。HistoRAG 正确回答的问题多于段落检索基线以及基于图谱的检索系统，且每个问题的成本远更低。该助手通过聊天界面运行，因此教师可以核对任何陈述所出自的页面。

## Abstract
Teachers who prepare lessons on local history and cultural heritage work from material that is hard to use. The primary sources are scanned books without a text layer, and the supporting records are administrative catalogs released as spreadsheets. A general chatbot answers such questions fluently but without a verifiable source, which is the property a teacher needs most. This paper presents HistoRAG, a question answering assistant that answers from one regional collection and cites a volume and a page for every fact. HistoRAG transcribes each page with a vision language model and keeps a line level confidence from the token probabilities. It builds three stores from the same collection: a hybrid text index, a relational catalog database, and a knowledge graph extracted only from entity dense passages. A lightweight router sends each question to the stores it needs, so that counting questions reach the database and relational questions reach the graph. We build a benchmark of 516 questions over a collection of 36 scanned volumes and the heritage catalogs of the same region, covering statistical, factual, temporal, and multi-hop questions. HistoRAG answers more questions correctly than passage retrieval baselines and than a graph based retrieval system, at a far smaller cost per question. The assistant runs behind a chat interface, so a teacher can check any statement against the page it came from.

  - OCR 错误会传播到检索与生成，低字符错误率也不保证答案可靠。
  - 目录中的计数、过滤问题需要跨多行聚合，不适合普通段落检索。
  - 图检索有利于关系型和多跳问题，但从全馆藏抽取图谱成本高昂。
- **整体含义**：论文提出 **HistoRAG**，面向地方史与遗产档案教学，构建一个**每个事实都附卷页或目录引用**的问答助手，使教师可在课堂使用前核查来源。

## 2. 方法论

- **核心思想**：将同一馆藏组织为三种视图——**混合文本索引、关系型目录数据库、选择性构建的知识图谱**；在线阶段用轻量路由器按问题类型调度，并生成带引用的答案。
- **离线阶段一：置信度携带转录**
  - 使用视觉语言模型逐页转录，提示要求按阅读顺序保留正文、图注和脚注，去除页眉。
  - 每个输出行保留 token 概率，定义行置信度  
    `c(ℓ)=exp((1/n)Σ log p(t_i))`，以及最小 token 置信度 `c_min(ℓ)=min_i p(t_i)`。
  - 纯占位图页面标记为缺失并跳过。
- **离线阶段二：文本索引**
  - 清理页眉、页码、目录项，拼接跨页未结束段落；按约 500 字符切块，保留页范围与块平均置信度。
  - 同时建立稠密向量索引和 BM25 索引；检索时用 RRF 融合，并用块置信度加权：  
    `s(x)=(Σ_r 1/(k+rank_r(x)))·(α+(1−α)\bar c(x)^γ)`。
- **离线阶段三：目录数据库**
  - 将异构遗产目录表映射到统一 schema，处理跨两行表头、区域行、重复发布等问题。
  - 归一化为三张关系表：**不可移动遗址、可移动文物、区域调查**；按名称、城市、县、机构去重。
- **离线阶段四：选择性图构建**
  - 先按规则实体密度排序：  
    `d(x)=100/|x|(n_ne+n_unit+n_date)`，其中 `n_ne` 为人物/地点/组织词，`n_unit` 为单位称谓，`n_date` 为日期模式。
  - 仅将密度最高的前 `ρ` 比例 chunk 送入 LLM 抽取实体与关系；实体类型包括人物、单位、组织、地点、事件、遗址、文档等。
  - 关系包括任职、隶属、参与事件、领导、死亡地、别名等。
- **置信门控实体归一化**
  - 清理表面形式，去除人物敬称；合并别名，但避免把两个独立高频实体误并为别名。
  - 识别变体合并条件：两个同类型、同长度、编辑距离为 1 的表面形式 `u`、`v`，若 `max_{ℓ∈L(u)} c(ℓ)<τ` 且 `f(v)≥κ f(u)`，才将低频 `u` 并入高频 `v`。
  - 额外排除：少于三字名称、单位称谓与文档标题、不同姓氏的人物名。
- **在线阶段：路由与检索**
  - 路由器用 LLM 选择 `R⊆{sql, kg, text}` 并列出问题中的实体名。
  - **数据库路由**：生成只读 SQL；提示中列出源目录和常见保护级别；执行失败可带错误重试一次。
  - **图路由**：实体按精确名、别名、子串匹配链接到图节点，返回 `h` 跳内关系及来源页。
  - **文本路由**：稠密与 BM25 结果 RRF 融合，并按块置信度加权；若选中路由无证据，回退到文本路由。
- **接地生成**
  - 汇总各路由证据并编号，要求每个事实陈述后附引用；来源冲突时分列不同说法；证据不足时明确说明。
  - 输出源列表，包括卷标题与页码，或数据库结果的目录名。

## 3. 实验设计

- **数据集 / 场景**：
  - 一个区域性 20 世纪地方史与文化遗产馆藏。
  - 包含 **36 卷扫描书、13,970 页**，其中 13,601 页有文本，其余为空白占位。
  - 目录部分为不可移动与可移动遗产官方列表，以及人物、事件、纪念物调查。
  - 归一化后数据库含 **1,943 条遗址记录、17,385 条可移动文物记录、984 条调查记录**。
  - 文本 chunk 共 20,554 个；当 `ρ=0.4` 时，8,208 个 chunk 送入图抽取。
- **Benchmark**：
  - 共 **516 题**：统计型 150、事实型 220、时间型 44、多跳型 102。
  - 统计题答案由 SQL 计算；事实/时间题由单个叙事 chunk 生成；多跳题由不同卷中提及同一图实体的两个 chunk 生成。
  - 每题由另一模型调用验证；多跳题仅在单 chunk 不足时保留。
  - 过滤答案出现在问题中、指代源文本而非命名主体、时间答案相对未命名日期等问题。
  - 按问题 ID 哈希划分：开发集 166 题，测试集 350 题；所有设置在开发集调参，报告测试集。
- **对比方法**：
  - 无检索的 LLM。
  - Dense RAG、BM25 RAG、Hybrid RAG，均读取相同转录文本。
  - 图检索基线 **LightRAG**，运行于同一语料的叙事卷。
  - 所有系统使用相同 LLM 做抽取与生成，相同 embedding 模型做稠密检索，以隔离检索设计差异。
- **指标**：
  - 答案正确率由 LLM 对照 gold answer 判定，计数要求 exact match。
  - 另报告字符级 F1、ANLS、有 gold chunk 时的证据召回。
  - 效率：索引构建 LLM token 数、每题平均 token 数与延迟。
