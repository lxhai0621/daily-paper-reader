## 摘要
大语言模型（LLM）智能体日益通过外部工具执行长时程工作流，这使得不可信输出能够影响后续动作并超出用户授权范围。现有防御手段要么隔离注入内容，要么通过预定义计划和静态策略来约束执行，但这些方法在动态工作流下较为脆弱，且难以扩展到可扩展的工具生态系统中。在这项工作中，我们提出 ActGov，一个运行时执行框架，可在每个由LLM提出的工具动作产生外部影响之前对其进行验证。ActGov-Policy 组件构建在授权、动作、运行时上下文和安全约束的统一语义模型之上，从工具规范、良性任务和观测到的失败轨迹中迭代构建策略集，并通过基于SMT的反例检查验证每次更新。在运行时，ActGov-Runtime 将每次工具调用抽象为有限策略记录，并且仅当该调用仍处于任务范围内的授权边界内且满足所有适用策略时才允许执行。这种逐动作执行机制可在长时程、动态分支的工作流中始终保持授权。我们在 AgentDojo 和 AgentDyn 基准上，跨多个模型和攻击配置评估 ActGov。结果表明，ActGov 在保持任务效用性的同时，持续降低间接提示注入攻击的成功率，并显著优于现有防御方法。这些结果表明，ActGov 能够对动态智能体执行实施细粒度授权，而无需依赖底层LLM正确识别恶意指令。

## Abstract
Large language model (LLM) agents increasingly execute long-horizon workflows through external tools, allowing untrusted outputs to influence subsequent actions and exceed user authorization. Existing defenses isolate injected content or constrain execution with predefined plans and static policies, but these approaches are brittle under dynamic workflows and scale poorly across extensible tool ecosystems.   In this work, we present ActGov, a runtime enforcement framework that validates each LLM-proposed tool action before it causes external effects. Built on a unified semantic model of authorization, actions, runtime context, and security constraints, the ActGov-Policy component iteratively constructs a policy set from tool specifications, benign tasks, and observed failure traces, with each update verified through SMT-based counterexample checking. At runtime, ActGov-Runtime abstracts each tool call into finite policy records and permits it only if it remains within the task-scoped authorization boundary and satisfies all applicable policies. This per-action enforcement preserves authorization throughout long-horizon, dynamically branching workflows.   We evaluate ActGov on the AgentDojo and AgentDyn benchmarks across multiple models and attack configurations. It shows that ActGov consistently reduces the success rate of indirect prompt-injection attacks while preserving task utility, significantly outperforming existing defenses. These results demonstrate that ActGov can enforce fine-grained authorization over dynamic agent executions without relying on the underlying LLM to correctly identify malicious instructions.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景转变**：LLM 正从文本生成器演变为可规划、调用工具、观察环境并执行多步动作的自主智能体，可操作邮件、日历、文件系统、代码仓库、金融账户、企业平台等资源。这从根本上改变了安全边界——模型输出可直接触发高影响操作（修改、删除、授权）。
- **核心风险**：不可信的外部内容（如网页、邮件中的注入指令）可被误判为用户意图，导致智能体执行未授权动作，即**间接提示注入（Indirect Prompt Injection, IPI）**。
- **关键挑战**：工具结果与后续动作之间存在动态依赖，因此需要**逐工具调用的授权执行**，而非输入-输出级别的过滤，同时须平衡安全性与任务效用。
- **现有防御的三项局限**：
  - **缺乏统一语义框架**：各防御依赖为特定安全机制定制的表示，可能误判数据与授权来源的关系，把不可信内容当作授权来源。
  - **长时程鲁棒性不足**：预定义计划、预期工具轨迹、静态参数清单等约束，在智能体需持续适应中间输出、动态分支与意外执行状态时，要么过度限制合法自适应行为降低效用，要么在偏离预设假设时失效。
  - **策略构建难以规模化**：手工策略难维护；自动生成的策略/权限缺乏部署前检测遗漏、冲突或非预期权限的严格机制；形式化验证方法（如 VeriGuard）常将策略逻辑与运行时具体状态分离，限制端到端保证。
- **论文定位**：提出 ActGov——一个**形式化验证的授权框架**，把非结构化执行上下文映射到离散二维记录模式，实现可扩展的策略构建与可验证的部署前安全执行。

## 2. 方法论

### 2.1 核心思想
- 将**动作提议（action proposal）与执行授权（execution authority）分离**：智能体可自由提出候选工具调用，但只有在通过 ActGov 验证后才被转发到外部工具接口。
- 把非结构化的运行时上下文抽象为**有限记录空间 R**，让 LLM 仅作为受限的语义解析器（提取布尔/类别值），授权判定则由确定性策略解释器完成，从而严格限制 LLM 幻觉导致的误差空间。

### 2.2 形式化模型
- 将受 ActGov 保护的智能体建模为有限状态机：**M = (H, C, R, P, V, T)**
  - H：执行历史状态空间；C：候选工具调用空间；R：有限记录空间；P：策略集
  - 评估函数 **V : R × P → {allow, deny}**，对抽象记录 rᵢ 与策略集 P 产生确定性判定 vᵢ
  - 状态转移函数 **T : H × C × V → H**，仅当 vᵢ = allow 时外部工具才执行
- 运行时抽象：**rᵢ = α_R(τ, perm, Hᵢ, cᵢ)**

### 2.3 正交二维记录模式
- 记录由**形成层级**与**语义范围**两个正交维度组织，每个记录属于一个层级和一个范围。
- **形成层级（如何产生值）**：
  - **L1 确定性**：直接从显式结构化系统状态计算，无需 NLP
  - **L2 有界语义**：需语义理解从非结构化文本提取，但 LLM 仅作语义解析器，映射到预定义有限值域
  - **L3 组合**：由 L1/L2 值经标准布尔逻辑（AND/OR/NOT）组合，捕捉组合或时序依赖
- **七个语义范围**：action、permission、parameter、history、binding、external、domain，分别刻画候选动作、任务基线权限、参数来源与角色、执行历史、意图与目标的绑定一致性、外部目的地安全属性、当前任务运行阶段。
- 该设计把上下文抽取约束到固定模式和有限值域，防止对抗性指令直接影响最终策略评估。

### 2.4 分层授权策略
- **P = P_TP ∪ P_HI ∪ P_PO**
  - **Task-Permission（P_TP）**：把可信用户任务绑定到最小必需工具与资源，生成基线授权边界 perm，越界动作被阻断。
  - **Hard-Invariant（P_HI）**：编码全局安全属性，如阻止源自不可信注入内容的外发网络动作，与当前任务范围无关。
  - **Procedural-Obligation（P_PO）**：覆盖超出智能体自主处理权限的情形（如目标绑定弱、参数来源不确定），属条件性规则，要求满足特定前置条件或上下文约束才允许执行。

### 2.5 验证门控演化（ActGov-Policy）
- 输入：工具规范（能力与风险约束）、良性任务轨迹（识别过度限制的规则）、观测到的攻击失败（识别缺失的安全条件）。
- LLM 仅作为**策略提议者**起草候选规则；每条更新须经 **Z3 求解器**验证，不得直接修改运行时监视器。
- 对任意预定义安全断言 A_sec，求解器在有限记录域中搜索满足策略语义但违反断言的合法赋值：
  - **∃r, v . Domain_R(r) ∧ P_sem(r, v) ∧ ¬A_sec(r, v)**
  - **SAT** 结果暴露反例（策略缺口或冲突），触发策略精炼；**UNSAT** 才允许部署，从数学上保证更新后的策略保持预定义安全不变量。
- 迭代收敛后，规则提交管理员确认，策略集冻结。
- 将昂贵的 Z3 求解完全置于离线准备阶段，运行时无需引入形式化求解延迟。

### 2.6 运行时执行（ActGov-Runtime）
- 部署在智能体 LLM 与外部工具接口之间，拦截候选调用 cᵢ，按二维模式 R 实例化记录集，动态填充当前执行上下文并评估策略谓词。
- 授权逻辑：先由 P_TP 分配基线边界 perm，再在边界内对 P_HI 与 P_PO 求值；**当且仅当**动作位于 perm 内且不违反任何安全策略时才放行。
- LLM 仅用于特定记录的孤立特征抽取（如参数来源分类），不参与端到端安全判断。

## 3. 实验设计

### 3.1 数据集与基准

- **AgentDyn**：引入含第三方指令的动态开放式任务；合法执行常需从外部观测推导动作目标，同时忽略同一环境中的恶意指令；包含 **60 个用户任务与 28 个注入任务**，组合成 **560 个安全测试用例**。

### 3.2 模型与基线
- **四个 LLM 后端**：Qwen3.6-flash、MiniMax-M2.5、DeepSeek-v4-pro、GPT-4o mini。
- **对比基线**：
  - 无防御基线
  - **CaMeL**：在可信与不可信数据间执行信息流约束
  - **Progent**：基于预定义权限的策略式受护执行
  - **DRIFT**：动态验证与轨迹隔离规则
  - **ACE**：要求智能体先生成抽象计划再映射到具体工具
