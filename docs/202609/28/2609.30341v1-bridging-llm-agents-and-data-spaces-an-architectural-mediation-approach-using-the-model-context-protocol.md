## 摘要
数据空间支持跨组织边界的主权且受治理的数据共享，但其与AI智能体的集成仍具挑战性，原因在于概率性语言模型交互与策略驱动的数据基础设施之间存在不匹配。本文提出一种基于模型上下文协议（MCP）的架构中介方法，并通过Eunomia Agent实现，以实现大语言模型（LLM）智能体与数据空间服务之间的受控交互。所提出的中介层将数据空间能力转换为结构化、模式驱动的工具，AI智能体可发现并调用这些工具，同时保留治理约束。一个原型实现验证了在无需修改现有数据空间组件的情况下，跨目录发现、元数据检索和数据服务调用的端到端交互。结果表明，基于协议的中介能够使AI智能体以可互操作且符合标准的方式集成到数据空间生态系统中。该方法为希望在受治理的数据共享环境中引入AI驱动自动化，同时保持合规性、互操作性和架构关注点分离的组织提供了实践指导。

## Abstract
Data Spaces enable sovereign and governed data sharing across organizational boundaries, but their integration with AI agents remains challenging due to mismatches between probabilistic language model interactions and policy-driven data infrastructures. This article presents an architectural mediation approach based on the Model Context Protocol (MCP), implemented through the Eunomia Agent, to enable controlled interaction between large language model (LLM) agents and data space services. The proposed mediation layer translates data space capabilities into structured, schema-driven tools that AI agents can discover and invoke while preserving governance constraints. A prototype implementation validates end-to-end interaction across catalog discovery, metadata retrieval, and data service invocation without modifying existing data space components. Results demonstrate that protocol-based mediation enables interoperable and standards-aligned integration of AI agents into data space ecosystems. The approach provides practical guidance for organizations seeking to introduce AI-driven automation into governed data-sharing environments while maintaining compliance, interoperability, and architectural separation of concerns.

## 1. 核心问题与整体含义

- **研究动机**：数据空间支持跨组织、主权化、受治理的数据共享，但 LLM 智能体与数据空间基础设施之间存在结构性错配。
- **错配表现**：
  - LLM 智能体倾向于声明式、模式驱动、动态发现和调用工具。
  - 数据空间依赖程序化、协议绑定、多步骤的机器对机器工作流，如目录发布、身份验证、合同谈判、策略执行和受控数据传输。
- **核心风险**：若将数据空间 REST API 直接暴露给 LLM，可能导致脆弱耦合、协议语义误用和治理约束被绕过。
- **整体含义**：论文试图用 Model Context Protocol（MCP）作为中介协议，在**不修改现有数据空间组件**的前提下，让 LLM 智能体以受控、可审计、标准对齐的方式访问数据空间能力。
- **背景**：欧洲数据空间、IDSA、IDS-RAM、Dataspace Protocol、EDC、Eunomia Agent，以及 Data Act / Data Governance Act 等监管背景，使该问题具有现实意义。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：引入一个外部的**架构中介层（Architectural Mediation Layer）**，位于 MCP 客户端与 Eunomia Agent 之间。
- **基本定位**：
  - 中介层不嵌入数据空间业务逻辑。
  - 不复制身份验证、合同谈判、策略执行等治理逻辑。
  - 所有治理权威仍保留在 Eunomia Agent 中。
  - 仅通过公开 HTTP API 与 Eunomia Agent 交互。
- **技术机制**：
  - 使用 MCP 实现工具广告与调用语义。
  - 采用 JSON-RPC over stdio 传输，原型中用于本地实验；生产场景可扩展为 SSE 或 HTTPS 等安全传输。
  - 将数据空间能力抽象为结构化、模式驱动的 MCP 工具。
  - 工具调用时进行输入验证、参数转换、HTTP 请求转发和 MCP 格式响应规范化。
- **暴露的三个 MCP 工具**：
  - `list_datasets()`：目录发现，支持 `query`、`limit`、`offset`，避免大目录导致 LLM 上下文饱和。
  - `get_dataset_metadata`：根据数据集 ID 获取详细元数据，包括关联数据服务信息。
  - `query_data_service`：根据服务 ID 和参数调用数据服务，将结构化参数映射为 HTTP 查询参数。
- **API 映射**：
  - `list_datasets` → `GET /catalogs/{id}/datasets`
  - `get_dataset_metadata` → `GET /datasets/{id}` 与 `GET /datasets/{id}/distributions`
  - `query_data_service` → `GET {service_endpoint}?params`
- **交互流程**：
  1. MCP 客户端连接中介服务器并请求工具发现。
  2. 中介服务器广告工具及其输入/输出模式。
  3. 客户端调用工具。
  4. 中介服务器转换为 Eunomia HTTP API 请求。
  5. Eunomia 返回目录元数据或数据服务信息。
  6. 中介服务器转换为 MCP 响应并返回客户端。
- **设计原则**：
  - 非侵入式集成。
  - 稳定互操作边界。
  - 关注点分离。
  - 中介层可作为治理控制点，支持认证、授权、审计、限流和参数校验。

- **稳定互操作边界**：可隔离快速演进的 AI 工具链与稳定、标准驱动的数据空间基础设施。
- **治理控制点设计**：中介层可集中实施认证、授权、审计、限流、参数校验和策略执行。
