## 摘要
大语言模型（LLMs）和智能体系统在自动化软件开发方面展现出巨大潜力，但由于软件逻辑与物理硬件行为之间的紧密耦合，将其应用于硬件在环（HIL）嵌入式和物联网（IoT）系统仍面临挑战。即使代码能够成功编译，在实际设备上部署时仍可能因时序约束、外设初始化要求或特定硬件行为而失败。为了应对这一挑战，我们引入了一种用于 HIL 嵌入式开发的基于技能的智能体框架，以及 IoT-SkillsBench，这是一个旨在系统评估真实嵌入式编程环境中 AI 智能体的基准测试。IoT-SkillsBench 涵盖了三个具有代表性的嵌入式平台、23 种外设以及三个难度级别的 42 个任务，每个任务都在三种智能体配置（无技能、LLM 生成技能和人类专家技能）下进行评估，并通过真实硬件执行进行验证。通过 378 次硬件验证实验，我们证明了包含结构化专家知识的简洁人类专家技能可以在不同平台上实现近乎完美的成功率。

## Abstract
Large language models (LLMs) and agentic systems have shown promise for automated software development, but applying them to hardware-in-the-loop (HIL) embedded and Internet-of-Things (IoT) systems remains challenging due to the tight coupling between software logic and physical hardware behavior. Code that compiles successfully may still fail when deployed on real devices because of timing constraints, peripheral initialization requirements, or hardware-specific behaviors. To address this challenge, we introduce a skills-based agentic framework for HIL embedded development together with IoT-SkillsBench, a benchmark designed to systematically evaluate AI agents in real embedded programming environments. IoT-SkillsBench spans three representative embedded platforms, 23 peripherals, and 42 tasks across three difficulty levels, where each task is evaluated under three agent configurations (no-skills, LLM-generated skills, and human-expert skills) and validated through real hardware execution. Across 378 hardware validated experiments, we show that concise human-expert skills with structured expert knowledge enable near-perfect success rates across platforms.

传统的 AI 辅助软件开发在纯软件环境（如 Web 或数据科学）中已取得显著进展，但在**嵌入式与物联网（IoT）领域**面临严峻挑战。核心问题在于：
*   **软硬件紧密耦合**：代码编译通过并不代表运行正确，硬件的时序约束、外设初始化顺序和引脚复用等物理特性极易导致系统静默失败。
*   **生态系统碎片化**：不同微控制器（MCU）使用完全不同的工具链、库和实时操作系统（RTOS，如 ESP-IDF, Zephyr）。
*   **模拟器局限性**：现有的硬件模拟器（如 QEMU, Wokwi）无法完全还原真实的传感器-执行器交互和精确的时序行为。
该研究旨在通过引入“结构化技能”来弥合 LLM 的通用编程能力与特定硬件约束之间的鸿沟。

#### 2. 论文提出的方法论
论文提出了一种**基于技能的智能体框架（Skills-based Agentic Framework）**，其核心思想是将复杂的硬件文档和编程范式浓缩为紧凑的“技能卡”。
*   **核心组件**：
    *   **技能（Skills）**：采用 YAML+Markdown 格式，记录特定外设或框架的初始化约束、编程模式和已知失败模式。
    *   **管理节点（Manager Node）**：根据任务需求从技能库中检索并筛选相关技能。
    *   **编码节点（Coder Node）**：结合任务提示词和选定的技能生成固件代码。
    *   **组装节点（Assembler Node）**：负责生成平台相关的脚手架文件（如 CMakeLists.txt, Zephyr 的设备树叠加层 .overlay 等），确保项目可直接编译。
*   **关键技术细节**：该框架不直接向 LLM 喂入海量的 SDK 文档，而是通过专家提炼的“技能”来减少 Token 消耗并提高推理准确性。

#### 3. 实验设计
研究者构建了 **IoT-SkillsBench** 基准测试，具有以下特征：
*   **三大平台**：ATmega2560 (Arduino), ESP32-S3 (ESP-IDF), nRF52840 (Zephyr)，涵盖了从简单抽象到工业级 RTOS 的开发环境。
*   **42 个任务**：分为三个难度等级（L1: 基础 GPIO/ADC；L2: 协议级 I2C/SPI 通信；L3: 中断驱动与多设备集成）。
*   **对比配置**：
    1.  **No-Skills**：仅依赖 LLM 的预训练知识。
    2.  **LLM-generated Skills**：由 Claude 3.5 根据自身知识生成的技能。
    3.  **Human-Expert Skills**：由具备实操经验的嵌入式专家编写的技能。
*   **验证方式**：所有生成的代码均在**真实物理硬件**上进行编译、烧录和行为验证（HIL），而非依赖模拟器。

*   **骨干模型**：实验统一使用 **Claude 3.5 Sonnet** 作为智能体的核心推理引擎。

#### 5. 实验数量与充分性
*   **实验规模**：共进行了 **378 组硬件验证实验**（42 任务 × 3 平台 × 3 技能配置）。为了评估稳定性，每个组合重复运行 5 次，计算 Pass@1 和 Pass@5。
*   **充分性评价**：实验设计非常充分且客观。它不仅覆盖了不同架构的 MCU（AVR, Xtensa, ARM），还对比了不同来源的知识（LLM 自生 vs 专家提炼），并深入分析了 Token 消耗与性能的权衡。

#### 6. 论文的主要结论与发现
*   **专家知识是关键**：使用“人类专家技能”的智能体在所有平台上实现了**接近 100% 的成功率**，显著优于其他配置。
*   **LLM 自生技能的局限**：LLM 生成的技能往往会引入噪声或强化错误的假设，有时甚至会导致性能比“无技能”基准更差，且 Token 消耗最高。
*   **平台差异显著**：LLM 在 Arduino 上表现较好（文档丰富），但在 Zephyr 等工业级框架上表现糟糕，极度依赖外部技能辅助。
*   **硬件失效不可避免**：极少数失败是由物理硬件限制（如电压不匹配）引起的，而非代码逻辑错误。

#### 7. 优点
*   **真实性高**：坚持使用真实硬件验证，避免了模拟器带来的“虚假成功”。
*   **框架解耦**：将硬件知识（Skills）与生成逻辑（Agent）解耦，使得支持新硬件只需编写新的技能卡，无需重新设计智能体。
*   **高效性**：证明了简洁的结构化知识比长篇累牍的原始文档更有效，显著降低了 Token 成本。

#### 8. 不足与局限
*   **专家依赖性**：高质量技能库的构建仍高度依赖人类专家，如何自动化提取高质量硬件技能仍是挑战。
*   **覆盖范围**：虽然涵盖了 23 种外设，但尚未涉及复杂的无线协议栈（如 BLE 组网、Wi-Fi 认证）或低功耗电源管理等更深层的嵌入式课题。
*   **闭源模型依赖**：实验主要基于 Claude 3.5，尚未探讨开源小模型在结合技能库后是否能达到类似效果。
