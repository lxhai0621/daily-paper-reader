## 摘要
当前的 AI 智能体编排方法通常涉及构建多智能体框架，通过代码管理上下文传递、记忆、错误处理和步骤协调。这些框架在复杂的并发系统中表现良好。但对于每一步都需要人工审查输出的顺序工作流，它们引入了问题本身并不需要的工程开销。本文提出了模型工作区协议（Model Workspace Protocol, MWP），这是一种用文件系统结构取代框架级编排的方法。编号文件夹代表不同的阶段。普通的 Markdown 文件承载了提示词和上下文，告知单个 AI 智能体在每个步骤中扮演的角色。本地脚本处理完全不需要 AI 的机械性工作。结果是一个只需单个智能体在正确时刻读取正确文件，即可完成原本需要多智能体框架才能完成的工作的系统。该方法将 Unix 管道设计、模块化分解、多轮编译和文学编程的思想应用于为 AI 智能体构建上下文的特定问题。该协议在 MIT 许可下开源。

## Abstract
Current approaches to AI agent orchestration typically involve building multi-agent frameworks that manage context passing, memory, error handling, and step coordination through code. These frameworks work well for complex, concurrent systems. But for sequential workflows where a human reviews output at each step, they introduce engineering overhead that the problem does not require. This paper presents Model Workspace Protocol (MWP), a method that replaces framework-level orchestration with filesystem structure. Numbered folders represent stages. Plain markdown files carry the prompts and context that tell a single AI agent what role to play at each step. Local scripts handle the mechanical work that does not need AI at all. The result is a system where one agent, reading the right files at the right moment, does the work that would otherwise require a multi-agent framework. This approach applies ideas from Unix pipeline design, modular decomposition, multi-pass compilation, and literate programming to the specific problem of structuring context for AI agents. The protocol is open source under the MIT license.

*   **核心问题**：如何简化 AI 智能体的编排，使其在保持高效的同时，具备高度的可解释性、可干预性和低工程开销？
*   **整体含义**：论文提出了 **ICM（Interpretable Context Methodology）**，主张回归 Unix 哲学，利用**文件系统结构**（文件夹和 Markdown 文件）取代复杂的代码框架。通过这种方式，文件夹结构本身就成为了智能体的“架构”，单个智能体通过在不同阶段读取特定文件来完成多步骤任务。

#### 2. 方法论：核心思想与技术细节
*   **核心思想**：将工作流分解为多个阶段，每个阶段对应一个编号文件夹。利用文件系统的层级关系来管理 AI 的上下文，实现“按需加载”。
*   **五层上下文体系**：
    *   **Layer 0 (全局身份)**：`CLAUDE.md`，定义工作区身份和整体结构。
    *   **Layer 1 (任务路由)**：`CONTEXT.md`，指导如何根据用户需求选择阶段。
    *   **Layer 2 (阶段契约)**：每个阶段文件夹内的 `CONTEXT.md`，明确该步骤的输入、处理逻辑和输出要求。
    *   **Layer 3 (参考资料/工厂)**：稳定的规则、风格指南、领域知识（不随运行次数改变）。
    *   **Layer 4 (工作产物/产品)**：当前运行的中间结果（如上一步的输出），随每次运行而变。
*   **工作流程**：
    1.  **阶段解耦**：每个阶段只做一件事（Unix 原则）。
    2.  **纯文本接口**：阶段间通过 Markdown 或 JSON 传递信息。
    3.  **分层加载**：智能体仅加载当前阶段所需的上下文（通常 2k-8k tokens），避免“信息淹没”。
    4.  **人工审查门控**：每个阶段的输出都是可读、可编辑的文件，人类可以在下一步开始前手动修正。

#### 6 主要结论与发现
*   **U 型干预模式**：人类在第一阶段（设定方向）和最后阶段（对齐与调试）干预最多，中间阶段干预较少。
*   **上下文效率**：通过分层加载，ICM 能将上下文维持在模型表现最佳的区间（<8k tokens），有效避免了长文本导致的“信息丢失（Lost in the Middle）”现象。
*   **低门槛编排**：非技术人员通过编辑 Markdown 文件即可改变智能体行为，无需修改代码。
*   **可观察性是副产品**：由于所有中间状态都是文件，系统天然具备透明度，无需额外的监控仪表盘。

#### 7. 优点
*   **极简主义**：利用现有的文件系统，无需学习复杂的 API 或框架。
*   **高度可解释**：每一个步骤、每一份指令、每一个中间产物都清晰可见、可追溯。
*   **便携性与版本控制**：整个工作区就是一个文件夹，可以轻松通过 Git 进行版本管理或跨设备同步。
*   **人类中心化**：天然支持“人在回路”，允许人类在任何阶段介入修正。

#### 8. 不足与局限
*   **场景限制**：仅适用于顺序、可审查的工作流，不适合需要高频、实时交互的动态多智能体系统。
*   **自动化分支困难**：处理复杂的条件分支逻辑时，可能需要引入脚本，从而增加系统复杂性。
*   **评估缺乏量化指标**：目前主要依赖定性反馈，缺乏针对输出质量、错误率的严谨量化对比。
*   **模型依赖风险**：虽然理论上模型无关，但实际效果可能受限于不同模型对上下文结构的敏感度。
